# Тестбенчи цели SystemVerilog

Тестбенчи для порождённых `taktc -t sv` модулей из `examples/generated/sv/`.
Написаны **руками**: тестбенч — принадлежность проверки, а не продукта, поэтому
`taktc` его не порождает (решение открытого вопроса задачи 0045-07).

| Тестбенч | Модуль под тестом | Сценарий |
|---|---|---|
| `stacker_tb.sv` | `../stacker.sv` | Заявка на забор груза; замкнутая среда ведёт автомат через весь цикл (забор → ячейка → завершение). Проверяет `cmd_ack`, `cmd_fork`, `cmd_done`. |
| `elevator_mini_tb.sv` | `../elevator_mini.sv` | Нажата кнопка кабины «этаж 5»; «физика лифта» довозит кабину. Проверяет `elevator_motor_up`, `door_open`, приезд на этаж. |
| `regulator_tb.sv` | `../regulator.sv` | Регулятор на q(8, 8) самодостаточен (входов нет): сходится к уставке и завершается. Проверяет `ready` и `is_done`. |
| `pid_regulator_tb.sv` | `../pid_regulator.sv` | ПИД с anti-windup, контур замкнут внутри модели. Проверяет сходимость: `ready` и `is_done`. |
| `batch_cycle_tb.sv` | `../batch_cycle.sv` | Технологический цикл на **последовательной** композиции `+`. Проверяет не только `ready`/`is_done`, но и **порядок фаз**: `stage` обязана пройти 1 → 2 → 3, иначе `+` вела бы себя как `\|`. |

Каждый тестбенч делает две вещи:

1. **Проверяет функционирование** — прогоняет модуль на осмысленном сценарии и
   сверяет наблюдаемое поведение `assert`-ами. Провал → `$fatal` → ненулевой код
   выхода → красный предкоммит.
2. **Снимает осциллограмму** `<module>.vcd` (`$dumpvars`) для просмотра в
   [GTKWave](https://gtkwave.sourceforge.net/).

> Потактовую *эквивалентность* RTL и симулятора Takt проверяет отдельная сверка
> (`takt-sim/tests/conformance/conformance_sv_tests.rs`) — она строже: сравнивает значение
> на каждом такте. Тестбенчи здесь проверяют «событие когда-нибудь произошло»
> (устойчиво к сдвигу такта) и служат прежде всего источником осциллограмм.

## Прогон вручную

Из каталога `examples/generated/sv/`:

```sh
verilator --binary --timing --trace --top-module tb \
    tb/stacker_tb.sv stacker.sv -o simtb
(cd tb && ../obj_dir/simtb)     # пишет tb/stacker.vcd
gtkwave tb/stacker.vcd
```

## Автоматический прогон

`scripts/precheck.sh` (гейт тестбенчей цели sv) собирает и запускает **все**
тестбенчи Verilator-ом — по одному на каждый пример из `SV_TRANSLATABLE`;
провал `assert` валит предкоммит. Отсутствие парного тестбенча у обязательного
примера тоже валит гейт. При отсутствии
`verilator` шаг мягко пропускается локально и обязателен в CI
(`SV_GATE_REQUIRED=1`) — как и соседние гейты линта/синтеза.

Осциллограммы (`*.vcd`), каталог сборки (`obj_dir/`) и бинарь (`simtb`) — под
`.gitignore`: это артефакты прогона, а не исходники.
