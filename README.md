# Lam — Язык описания автоматных моделей

**Lam** (Language of Automata Models) — предметно-ориентированный язык (DSL) для моделирования
конечных автоматов (FSM) и компонентных систем. Компилятор реализован на Rust.

## 1. Введение

### Целевая аудитория

Этот документ предназначен для:

- **Разработчиков встраиваемых систем**, которые проектируют управляющую логику на основе
  конечных автоматов и нуждаются в формальном и читаемом способе её описания.
- **Исследователей и инженеров** в области верификации, желающих описывать поведение систем
  на высоком уровне абстракции.
- **Опытных разработчиков** (C/C++/Rust), знакомых с понятиями FSM, которые хотят изучить
  синтаксис и семантику Lam.

### Соглашения по нотации

| Обозначение      | Смысл                              |
|------------------|------------------------------------|
| `ключевое_слово` | Литерал: пишется дословно          |
| `идентификатор`  | Любое имя, выбранное пользователем |
| `[ ... ]`        | Необязательный элемент             |
| `{ ... }`        | Повторение (0 и более раз)         |
| `a \| b`         | Альтернатива                       |

Полная грамматика в формате ISO EBNF — в файле [`Lam.ebnf`](Lam.ebnf).

### Привет, мир!

Минимальная программа — модель со стартовым состоянием:

```lam
model Hello {
    start World;
}

start Main = Hello;
```

Запустить компилятор:

```sh
cargo build --release --bin lamc
./target/release/lamc compile --target c hello.lam -o out/
```

В `out/` появятся `hello.h` и `hello.c`.

## 2. Назначение DSL

### Проблема

Традиционный подход — писать конечные автоматы вручную на C — приводит к рутинному коду,
который сложно верифицировать и сопровождать. Типичная реализация FSM на C требует:
`switch-case` по состояниям, ручного управления флагами входа/выхода, указателей MMIO вместо
типизированных портов.

### Решение

Lam предлагает:

- **Декларативный синтаксис** для FSM вместо `switch-case` на C.
- **Компиляцию в C**: сгенерированный код оптимален и пригоден для встраиваемых систем.
- **Формальную семантику**: типизация, детерминированность переходов, диагностика.
- **Никакого рантайма**: ни сборщика мусора, ни кучи — только стек и порты.

### Парадигма

Lam — **декларативный, ориентированный на состояния** язык:

- **Модели** (`model`) — основные строительные блоки; каждая модель — один FSM.
- **Состояния** (`start`, `state`) — узлы автомата; логика выполняется в их блоках.
- **Переходы** (`ref`, `next`) — рёбра автомата с условиями или безусловные.
- **Параллельная и последовательная композиция** (`|`, `+`) — сборка систем из компонентов.

### «Дзен» языка

| Принцип            | Смысл                                                   |
|--------------------|---------------------------------------------------------|
| **Явность**        | Переходы описаны явно — нет скрытой передачи управления |
| **Локальность**    | Каждая модель инкапсулирует состояния и данные          |
| **Минимализм**     | Язык содержит только необходимые конструкции            |
| **Встраиваемость** | Нет GC, рантайма или кучи — только стек и порты         |

### Сравнение с C

| Концепция          | C (switch-case)        | Lam                      |
|--------------------|------------------------|--------------------------|
| Состояние          | `enum` + переменная    | `state`/`start`          |
| Переход            | `case` с `goto`        | `ref Цель: условие;`     |
| Вход в состояние   | ручная флаг-переменная | `enter { ... }`          |
| Параллелизм        | потоки / ручная логика | `M1 \| M2`               |
| Последовательность | вложенный switch       | `M1 + M2`                |
| Порты              | указатели MMIO         | `in`/`out` внутри модели |
| Типизация          | слабая                 | строгая статическая      |

## 3. Термины и сущности домена

### Глоссарий

| Термин                  | Определение                                                         |
|-------------------------|---------------------------------------------------------------------|
| FSM                     | Конечный автомат (Finite State Machine)                             |
| Модель                  | Объявление конечного автомата (`model M { ... }`)                   |
| Состояние               | Узел автомата (`start` или `state`)                                 |
| Переход                 | Смена активного состояния (`ref` или `next`)                        |
| Условие                 | Булево выражение для `ref`-перехода                                 |
| `cond`                  | Именованное условие — псевдоним для переиспользования               |
| Порт                    | Переменная, отображённая на аппаратный адрес или интерфейс модели   |
| Композиция              | Объединение моделей: последовательная (`+`) или параллельная (`\|`) |
| `enter`/`exit`/`always` | Именованные блоки кода с семантикой жизненного цикла                |
| `next`                  | Безусловный переход в следующее состояние                           |
| DSL                     | Domain-Specific Language — предметно-ориентированный язык           |

### Структура программы

Программа Lam — это последовательность **элементов верхнего уровня**:

| Конструкция          | Описание                                     |
|----------------------|----------------------------------------------|
| `import "file.lam";` | Импорт другого файла                         |
| `type T = ...;`      | Псевдоним типа                               |
| `var x: T := v;`     | Глобальная переменная                        |
| `const C: T := v;`   | Константа                                    |
| `fn f(...) {...}`    | Функция                                      |
| `extern fn f(...);`  | Прототип внешней функции                     |
| `enum E {...}`       | Перечисление                                 |
| `struct S {...}`     | Структура                                    |
| `model M {...}`      | Конечный автомат                             |
| `cond C = ...;`      | Именованное условие                          |
| `start Main = ...;`  | Точка входа (составная модель или псевдоним) |

### Перечисления и структуры

```lam
enum Direction { North, South, East, West }

struct Point { x: u8, y: u8 }
```

## 4. Синтаксис

### Комментарии

```lam
// Однострочный комментарий
```

### Идентификаторы и ключевые слова

**Идентификатор** начинается с буквы Unicode (XID_Start) или `_`, `$`, после чего
допустимы цифры и продолжающие Unicode-символы. Регистрозависимы.

| Группа                    | Ключевые слова                                             |
|---------------------------|------------------------------------------------------------|
| Объявления                | `var`, `const`, `type`, `fn`, `extern`, `enum`, `struct`   |
| Порты                     | `in`, `out`                                                |
| Управление                | `if`, `else`, `loop`, `for`, `break`, `continue`, `return` |
| Состояния                 | `model`, `state`, `start`, `ref`, `next`                   |
| Условия                   | `cond`, `formula`, `assembly`                              |
| Импорт                    | `import`, `as`                                             |
| Литералы                  | `true`, `false`                                            |
| LTL (темпоральная логика) | `LTL`, `Guard`, `X`, `F`, `G`, `U`, `R`                    |

### Операторы и приоритет

| Уровень | Оператор          | Описание                     | Ассоциативность |
|---------|-------------------|------------------------------|-----------------|
| 14      | `:=`              | Присваивание                 | правая          |
| 13      | `\|\|`            | Логическое ИЛИ               | левая           |
| 12      | `&&`              | Логическое И                 | левая           |
| 11      | `=` `!=`          | Равенство                    | левая           |
| 10      | `<` `>` `<=` `>=` | Сравнение                    | левая           |
| 9       | `\|`              | Побитовое ИЛИ                | левая           |
| 8       | `^`               | Побитовое XOR                | левая           |
| 7       | `&` `as`          | Побитовое И; приведение типа | левая           |
| 6       | `<<` `>>`         | Битовые сдвиги               | левая           |
| 5       | `+` `-`           | Сложение, вычитание          | левая           |
| 4       | `*` `/` `%`       | Умножение, деление, остаток  | левая           |
| 3       | `**`              | Возведение в степень         | правая          |
| 2       | `!` `~` `+` `-`   | Унарные операторы            | —               |
| 1       | `num:bit`         | Адресный литерал             | —               |

### Литералы

```lam
// Целые числа

// Числа с плавающей точкой
3.14    1e10    2.5E-3

// Логические

// Строки
```

### Система типов

Lam использует **статическую строгую типизацию** с **выводом типов** из инициализаторов.

| Тип     | Размер     | Описание                                    |
|---------|------------|---------------------------------------------|
| `bit`   | 1 бит      | Одиночный бит                               |
| `bool`  | 1 бит      | Булев тип                                   |
| `float` | переменный | Число с плавающей точкой                    |
| `unit`  | 0          | Пустой тип (возвращаемое значение процедур) |

Массив фиксированной длины: `[ТипЭлемента; Длина]`:

```lam
type u8  = [bit;8];
type u16 = [bit;16];
type u32 = [bit;32];
type u64 = [bit;64];
type Word = [u8;4];
```

Вывод типов из инициализатора:

| Инициализатор     | Выводимый тип |
|-------------------|---------------|
| `0` … `255`       | `[bit;8]`     |
| `256` … `65535`   | `[bit;16]`    |
| `65536` … `2³²−1` | `[bit;32]`    |
| `2³²` … `2⁶⁴−1`   | `[bit;64]`    |
| `true` / `false`  | `bool`        |
| `3.14`, `1e10`    | `float`       |

### Объявление переменных

```lam
var x;               // без типа и значения
var x: u8;           // с явным типом
var x := 100;        // тип выводится
var x: u8 := 50;     // явный тип и значение
const MAX: u8 := 255; // константа
```

### Функции

```lam
fn add(a: u8, b: u8) -> u8 { return a + b; }

fn reset();                    // прототип без тела

extern fn hal_uart_send(data: u8);   // внешняя функция
```

### Импорт

```lam
import "shared.lam";
import "engine.lam" as Motor;
import * as Utils from "lib.lam";
import { TrafficLight, u8 } from "common.lam";
import { OldName as NewName } from "types.lam";
```

### Краткая грамматика EBNF

```ebnf
source_unit   = { model_element } ;

model_element = import_define | type_define | variable_define
              | function_define | enum_define | struct_define
              | model | state_define | condition_define
              | named_block | ";" ;

variable_define
    = "var"   identifier [ ":" type ] [ ":=" expression ] ";"
    | "const" identifier [ ":" type ] ":=" expression ";"
    | "in"    identifier [ ":" type ] [ ":=" expression ] ";"
    | "out"   identifier [ ":" type ] [ ":=" expression ] ";" ;

model        = "model" identifier [ "=" expression ]
               "{" { model_element } "}" ;

state_define = state_kind identifier [ "=" expression ]
               ( "{" { state_element } "}" | ";" ) ;
state_kind   = "start" | "state" ;

state_element
    = named_block
    | "ref"  identifier [ ":" condition ] ";"
    | "next" identifier ";"
    | ";" ;
```

## 5. Семантика

### Присваивание `:=` и сравнение `=`

В Lam присваивание и сравнение разведены по разным знакам (стиль ST/IEC 61131-3,
привычный инженерам АСУ ТП):

| Знак  | Смысл                                   | Где                                        |
|-------|-----------------------------------------|--------------------------------------------|
| `:=`  | Присваивание / инициализация значения   | выражения, тела, инициализаторы `var`/`const`/портов |
| `=`   | Сравнение на равенство                  | выражения **и** условия (`cond`, `ref`)    |
| `<=`  | «Меньше или равно» (реляционный)        | выражения и условия                        |

Оператор `==` из языка **выведен** — равенство всегда пишется `=`. Знак `=`
дополнительно служит связкой в **определениях имён**: `type T = …`,
`enum E { A = 0 }`, `model M = …`, `start Main = …`, `cond C = …` — здесь `=`
вводит определение, а не присваивает значение переменной.

```lam
always { x := 0; }      // := — присваивание значения
if x = 0 { ... }        // = в выражении — сравнение на равенство
cond IsZero = x = 0;    // первое = — связка cond, второе = — сравнение
ref Green: timer = 255; // = в условии перехода — сравнение
var y: u8 := 5;         // := — инициализация переменной
```

### Управляющие конструкции

```lam
// if — без скобок вокруг условия
if x > 0 { x := x - 1; }
else if x = 0 { x := 10; }
else { x := 0; }

// loop — бесконечный или с условием
loop { x := x + 1; if x >= 10 { break; } }
loop x > 0 { x := x - 1; }

// for
for var i := 0; i < 10; i := i + 1 {
    // тело
}
```

> Условие `loop` не может начинаться с `{`. Используйте скобки: `loop ({1,2,3}) { }`.

### Жизненный цикл автомата

Каждое состояние может содержать именованные блоки:

| Блок     | Когда выполняется                          |
|----------|--------------------------------------------|
| `enter`  | Один раз при входе в состояние             |
| `exit`   | Один раз при выходе из состояния           |
| `always` | Каждый такт, пока автомат в этом состоянии |

Порядок выполнения за один такт:

1. **Инициализация**: устанавливается начальное `start`-состояние.
2. **Вход**: выполняются блоки `enter`.
3. **Такт**: выполняются блоки `always`.
4. **Проверка переходов**: вычисляются условия `ref`; при истинности — переход.
5. **Выход**: выполняются блоки `exit` текущего состояния.
6. **Переход**: активируется следующее состояние → шаг 2.

### Переходы

```lam
ref NextState: условие;   // условный переход
next NextState;           // безусловный переход
```

Операторы в условии `ref`:

- `=` — проверка равенства; `&` — И; `|` — ИЛИ; `!` — НЕ
- Сравнения: `<`, `>`, `<=`, `>=`, `!=`

### Именованные условия

```lam
cond IsActive  = x = 1;
cond InRange   = x > 0 & x < 100;
cond Either    = IsActive | InRange;
cond NotActive = !IsActive;
```

### Области видимости

- Переменные модели видны во всех вложенных состояниях.
- Переменные состояния видны только в нём.
- Разрешение: локальная область → состояние → модель → глобальный уровень.
- Затенение: локальное объявление скрывает одноимённое родительское.

## 6. Примеры

### Минимальный конечный автомат

```lam
model Minimal {
    start Idle;
    state Active;
    state Done;
}

start Main = Minimal;
```

### Светофор с таймером

```lam
type u8 = [bit;8];

model TrafficLight {
    var timer: u8 := 0;

    start Red {
        enter  { timer := 0; }
        always { timer := timer + 1; }
        ref Green: timer = 255;
    }

    state Green {
        enter  { timer := 0; }
        always { timer := timer + 1; }
        ref Yellow: timer = 100;
    }

    state Yellow {
        enter  { timer := 0; }
        always { timer := timer + 1; }
        ref Red: timer = 50;
    }
}

start Entry = TrafficLight;
```

### Кнопка и светодиод (направленные порты, внешние функции)

```lam
type u8 = [bit;8];

extern fn debug(msg: u8);

fn toggle(val: u8) -> u8 { return ~val; }

model ButtonLED {
    var state: u8 := 0;

    in  BTN: bit;   // входной порт — кнопка
    out LED: u8;    // выходной порт — светодиод

    start Idle {
        ref Active: BTN = 1;
    }

    state Active {
        enter {
            state := toggle(state);
            LED   := state;
            debug(state);
        }
        next Idle;
    }
}

start M = ButtonLED;
```

### Управление лифтом (параллельная композиция)

```lam
type u8 = [bit;8];

enum Command { Up, Down, Stop }

var command: Command := Stop;

model Motor {
    start Idle {
        ref Up:   command = Up;
        ref Down: command = Down;
        enter { ElevatorMotor_Stop := true; }
    }
    state Up {
        ref Stop: command = Stop | ElevatorMotor_SensorU;
        always   { ElevatorMotor_Up := true; }
    }
    state Down {
        ref Stop: command = Stop | ElevatorMotor_SensorD;
        always   { ElevatorMotor_Down := true; }
    }
    state Stop {
        next Idle;
        always { ElevatorMotor_Stop := true; }
    }

    out ElevatorMotor_Up:    bit;
    out ElevatorMotor_Down:  bit;
    out ElevatorMotor_Stop:  bit;
    in  ElevatorMotor_SensorU: bit;
    in  ElevatorMotor_SensorD: bit;
}

start Main = Cabin | Motor;   // параллельный запуск
```

### Пример с ошибкой и исправлением

```lam
// ОШИБКА: нет начального состояния
model Bad {
    state A;
    state B;
}

// ИСПРАВЛЕНИЕ: добавляем start
model Good {
    start A;   // ← начальное состояние обязательно
    state B;
}
```

### Композиция моделей

```lam
model Init    { start S; }
model Startup { start S; }
model Run     { start S; }
model Halt    { start S; }

start System = (Init + Startup) + (Run | Halt);
```

## 7. Ограничения и ошибки

### Ограничения типов и значений

| Ограничение                           | Код    |
|---------------------------------------|--------|
| Максимальный размер массива: 1024     | SE-038 |
| Циклические псевдонимы запрещены      | SE-039 |
| Поля структуры — уникальные имена     | SE-040 |
| Поля структуры — известные типы       | SE-041 |
| Enum: только объявленные варианты     | SE-043 |
| В модели ровно одно `start`-состояние | SE-011 |
| `next` в состоянии — не более одного  | SE-012 |
| Нет скрытых переходов                 | SE-037 |

| LE-003 | Незакрытый шестнадцатеричный литерал                      |
| LE-004 | Отсутствует цифра после знака числа                       |
| LE-005 | Недопустимый символ в шестнадцатеричном литерале          |
| LE-006 | Нераспознанный токен                                      |
| LE-007 | Отсутствует показатель степени в числе с плавающей точкой |
| LE-008 | Ожидался токен `from`                                     |

### Синтаксические ошибки (SY)

| Код    | Описание                                  |
|--------|-------------------------------------------|
| SY-001 | Недопустимый токен                        |
| SY-002 | Нераспознанный токен                      |
| SY-003 | Лишний токен после завершения конструкции |

### Семантические ошибки (SE)

| Код    | Описание                                                          |
|--------|-------------------------------------------------------------------|
| SE-001 | Модель не найдена                                                 |
| SE-002 | Ссылка на состояние не найдена                                    |
| SE-003 | Переменная не найдена в области видимости                         |
| SE-004 | Неизвестная встроенная функция                                    |
| SE-005 | Переменная с таким именем уже объявлена                           |
| SE-006 | Модель с таким именем уже объявлена                               |
| SE-010 | Нет терминальных состояний                                        |
| SE-011 | Нет начального состояния в модели                                 |
| SE-013 | Файл импорта не найден                                            |
| SE-025 | Неразрешённое условие перехода                                    |
| SE-028 | Индекс массива вне границ                                         |
| SE-037 | Неявное приведение числа к булевому / недетерминированный переход |
| SE-042 | Перекрывающиеся условия переходов                                 |

### Ошибки кодогенерации (CC)

| Код    | Описание                                         |
|--------|--------------------------------------------------|
| CC-001 | BitAccess на порт типа `float` не поддерживается |
| CC-002 | Неразрешённая функция в условии перехода         |
| CC-008 | Начальное состояние модели не определено         |
| CC-010 | Ошибка записи выходного файла (`.h` или `.c`)    |

### Структура сообщения об ошибке

```
Уровень:  Debug | Info | Warning | Error
Тип:      ParserError | SyntaxError | DeclarationError |
          TypeError | CastError | SemanticError | Warning
Позиция:  файл, строка, столбец (начало и конец)
Заметки:  дополнительный контекст
```

### Типичные ошибки пользователей

- Забытое `start` в модели → SE-011.
- Использование `:=` вместо `=` в условии (`if`, `cond`, `ref`) → присваивание
  вместо сравнения (в большинстве позиций условия — ошибка разбора).
- Запись в `in`-порт или чтение из `out`-порта → ошибка направления.
- Перекрывающиеся условия в `ref` → SE-042, недетерминированный переход.

## 8. Интеграция и реализация

### Конвейер компиляции

```
Исходный файл (.lam)
        │
        ▼
┌─────────────────┐
│   Лексер        │  lexer.rs — токены с позиционной информацией
└────────┬────────┘
         ▼
┌─────────────────┐
│   Парсер        │  LALRPOP (LR(1)) — Абстрактное синтаксическое дерево
└────────┬────────┘
         ▼
┌─────────────────┐
│   Семантический │  7 проходов → семантическое дерево + диагностика
│   анализатор    │
└────────┬────────┘
         ▼
┌─────────────────┐
│   Генератор C   │  c_header.rs (.h) + c_source.rs (.c)
└─────────────────┘
```

### Семантические проходы

| № | Проход            | Описание                                               |
|---|-------------------|--------------------------------------------------------|
| 0 | Скелет            | Извлечение имён моделей/состояний, загрузка импортов   |
| 1 | Композиция        | Разрешение составных состояний (`+ M1 M2`, `M1 \| M2`) |
| 2 | Выражения         | Разрешение переменных, вывод типов, порты              |
| 3 | Условия (`cond`)  | Разрешение именованных условий                         |
| 4 | Именованные блоки | Разрешение `enter`/`exit`/`always`                     |
| 5 | Функции           | Разрешение тел функций                                 |
| 6 | Переходы (`ref`)  | Замена `Condition::Unresolved` на разрешённые условия  |

### Запуск компилятора

```sh
# Компиляция в C
lamc compile --target c input.lam -o output/

# Результат:
# output/input.h  — заголовочный файл
# output/input.c  — реализация
```

### Порты ввода-вывода

```lam
model Motor {
    out Enable: bit;   // запись
    out Speed:  u8;
    in  Sensor: bit;   // чтение
    in  Limit:  bit;
}
```

- **`out`-порт**: модель пишет в него; чтение — ошибка.
- **`in`-порт**: модель читает из него; запись — ошибка.

При кодогенерации создаются отдельные enum-типы и типизированные функции для in/out.

### Адресные литералы (MMIO)

```lam
var LED : u8  := 0x00100000;      // привязка к адресу
var BTN : bit := 0x00200000:0;    // адрес:номер_бита
```

### Внешние функции (FFI)

```lam
extern fn hal_uart_send(data: u8);
extern fn hal_gpio_set(pin: u8, val: bit);
```

В сгенерированном C-коде они превращаются в прямые вызовы без обёрток.

### Встроенные функции

| Функция | Назначение                                |
|---------|-------------------------------------------|
| `debug` | Вывод отладочного сообщения               |
| `S`     | Получение начального состояния модели     |
| `min`   | Минимум двух значений                     |
| `max`   | Максимум двух значений                    |
| `abs`   | Абсолютное значение                       |
| `clamp` | Ограничение значения в диапазон `[lo,hi]` |

### LSP-сервер

```sh
cargo build --release --features lsp --bin lam-lsp
cargo install --path grammar --bin lam-lsp --features lsp
```

Поддерживаемые возможности: диагностика, hover, автодополнение, Go to Declaration.

Настройка в Zed:

```json
{
  "lsp": {
    "lam-lsp": {
      "binary": {
        "path": "lam-lsp"
      }
    }
  }
}
```

## 10. Расширение и версии

### Версия

**Версия языка: 0.1.0** (крейт `grammar`). Документ актуален для ветки `v2`.
Список изменений — в файле [`CHANGES.md`](CHANGES.md).

> **Слом совместимости 0.0.x → 0.1.0 (фича 0021):** присваивание записывается
> `:=` (было `=`), сравнение на равенство — `=` (было `==`); оператор `==`
> выведен. Реляционный `<=` без изменений. Старые `.lam` переводятся
> AST-мигратором (см. `docs/development/0021-03-tool/`).

### Композиция моделей

Lam поддерживает два вида сборки систем:

```lam
// Последовательная: Init → Startup (после завершения Init запускается Startup)
start Sequential = Init + Startup;

// Параллельная: Run и Halt работают одновременно
start Parallel = Run | Halt;

// Комбинированная
start System = (Init + Startup) + (Run | Halt);
```

### Формулы и ассемблерные вставки

Для встраивания платформо-зависимого кода или формальных спецификаций:

```lam
assembly "arm" {
    // платформо-зависимый код
}

formula "ltl" {
    always(active())
    eventually(done())
}
```

LTL-аннотации прямо в элементах:

```lam
: [LTL] G(active() -> F done()), X next_state ;
```

### Расширение языка

Добавить новую конструкцию в Lam:

1. Расширить грамматику в `grammar/src/grammar.lalrpop` и `lexer.rs`.
2. Добавить узел AST в `ast.rs`.
3. Реализовать семантический проход в `semantic/tree.rs`.
4. При необходимости — расширить кодогенератор в `generator/c/`.
5. Добавить тесты в `tests/data/valid/` и `tests/data/invalid/`.

Полная грамматика находится в файле [`Lam.ebnf`](Lam.ebnf).
