# BuT — Язык программирования для конечных автоматов

**BuT** (Bus and Transitions) — предметно-ориентированный язык (DSL) для моделирования конечных автоматов и компонентных
систем, реализованный на Rust. Язык ориентирован на описание встраиваемых систем, управление состояниями и аппаратную
абстракцию с доступом к портам ввода-вывода.

## Лексический анализ

Лексер написан вручную на Rust без использования генераторов. Он поддерживает:

- **Идентификаторы** — Unicode XID + символ `$`: `myVar`, `_x`, `$tmp`
- **Числа**:
    - Целые десятичные: `0`, `123`, `1_000_000`
    - Шестнадцатеричные: `0xFF`, `0x1A_BC`
    - Рациональные (float): `3.14`, `1e10`, `2.5E-3`
    - Адресные литералы: `0x00100000:5` (адрес:бит)
- **Строки**: одинарные и двойные кавычки, префикс `unicode`:
  ```
  "hello"    'world'    unicode"текст"    unicode'текст'
  ```
- **Комментарии**:
    - Однострочный: `// комментарий`
    - Документационный: `/// документация`
    - Блочные комментарии (`/* */`) **не поддерживаются**
- **Ключевые слова**: автоматически распознаются через статическую хеш-таблицу (PHF)

### Таблица ключевых слов

| Группа          | Ключевые слова                                             |
|-----------------|------------------------------------------------------------|
| Объявления      | `var`, `const`, `type`, `fn`, `extern`, `port`, `enum`     |
| Управление      | `if`, `else`, `loop`, `for`, `break`, `continue`, `return` |
| Состояния       | `model`, `state`, `start`, `ref`, `next`                   |
| Прочее          | `import`, `as`, `from`, `cond`, `formula`, `assembly`      |
| Литералы        | `true`, `false`                                            |
| Зарезервированы | `template`, `string`, `pragma`                             |

### Модели и состояния

```but
model TrafficLight {
    var timer: u8 = 0;

    start Red {                         // начальное состояние (ровно одно)
        enter  { timer = 0; }           // выполняется при входе в состояние
        always { timer = timer + 1; }  // выполняется каждый цикл
        exit   { }                      // выполняется при выходе из состояния
        ref Yellow: timer > 10;         // условный переход
    }

    state Yellow {
        next Green;                     // безусловный переход
    }

    state Green {
        ref Red: true;
    }
}
```

### Условия (cond)

```but
cond IsActive     = x = 1;           // = означает равенство, не присваивание!
cond InRange      = x > 0 & x < 100;
cond Either       = IsActive | InRange;
cond NotActive    = !IsActive;
```

### Операторы управления потоком

```but
// if — без скобок вокруг условия
if x > 0 {
    x = x - 1;
} else {
    x = 0;
}

// loop с условием (аналог while) — без скобок
loop x > 0 {
    x = x - 1;
}

// бесконечный loop (без условия)
loop {
    x = x + 1;
    if x >= 10 { break; }
}

// for — без скобок вокруг заголовка
for var i = 0; i < 10; i = i + 1 {
    // ...
}
```

## Система типов

### Примитивные типы

| Тип     | Размер     | Значения                  | Описание                                    |
|---------|------------|---------------------------|---------------------------------------------|
| `bit`   | 1 бит      | `0`, `1`, `true`, `false` | Одиночный бит                               |
| `bool`  | 1 бит      | `true`, `false`           | Булев тип                                   |
| `float` | переменный | IEEE                      | Рациональное число                          |
| `unit`  | 0          | —                         | Пустой тип (возвращаемое значение процедур) |

### Составные типы

```but
[bit;8]          // массив из 8 бит (байт)
[u8;16]          // массив из 16 байт
```

### Вывод типов

Компилятор автоматически выводит тип из инициализатора:

| Инициализатор     | Выводимый тип |
|-------------------|---------------|
| `0` … `255`       | `[bit;8]`     |
| `256` … `65535`   | `[bit;16]`    |
| `65536` … `2³²−1` | `[bit;32]`    |
| `2³²` … `2⁶⁴−1`   | `[bit;64]`    |
| `true` / `false`  | `bool`        |
| `3.14`, `1e10`    | `float`       |

### Условия и выражения — разные операторы равенства

Важная особенность: в контексте **условий** (`cond`, `ref`) оператор `=` означает **проверку равенства**, а не
присваивание:

```but
cond IsZero = x = 0;        // x равен 0?
var x = 0;                  // присваивание 0 переменной x
```

В обычных **выражениях** `==` — это сравнение, `=` — присваивание.

## Семантика и модель выполнения

### Жизненный цикл конечного автомата

1. **Начальное состояние**: каждая модель с состояниями должна иметь ровно одно `start`-состояние
2. **Вход в состояние**: выполняются все блоки `enter` в порядке объявления
3. **Активное состояние**: выполняются все блоки `always` каждый цикл
4. **Проверка переходов**: вычисляются условия `ref`; при истинности — переход
5. **Выход из состояния**: выполняются все блоки `exit`

### Переходы

```but
ref NextState: condition;   // условный переход (condition — выражение или cond)
next NextState;             // безусловный переход (всегда срабатывает)
```

### Области видимости

- Переменные модели видны во всех вложенных состояниях
- Переменные состояния видны только в нём и вложенных блоках
- Разрешение имён: локальная область → родительская модель → прародительская и т.д.
- Затенение: локальное объявление скрывает родительское

### Семантические проходы анализатора

| Проход                         | Описание                                                           |
|--------------------------------|--------------------------------------------------------------------|
| 0. Скелет                      | Извлекаются имена моделей/состояний, загружаются импорты           |
| 1. Композиция (`implements`)   | Разрешаются составные состояния (`= M1 + M2`, `= M1 \| M2`)       |
| 2. Выражения переменных        | Разрешаются ссылки на переменные, вывод типов, порты               |
| 3. Именованные условия (`cond`)| Разрешаются объявления `cond` → `Condition`                        |
| 4. Именованные блоки           | Разрешаются блоки `enter`/`exit`/`always`                          |
| 5. Функции                     | Разрешаются тела локальных и внешних функций                       |
| 6. Условия переходов `ref`     | `Condition::Unresolved` заменяется разрешёнными условиями          |
| Валидация                      | Семантические проверки: Се1 (один start), bit-значения, Ce13 (неиспользуемые переменные), Ce14 (детерминированность), NI6 (типобезопасность enum), Ce11 (неявный bool), Ce5 (достижимость) |

### Ссылки на родителя в семантических узлах

Большинство семантических узлов (`VariableNode`, `ConditionNode`, `FunctionNode`, `NamedCodeBlock`) содержат поле
`upper: Option<Rc<RefCell<ModelNode>>>` — ссылку на родительскую модель. Это позволяет:

- получить контекст модели изнутри узла без передачи `model` как отдельного параметра;
- обходить объявленные переменные и условия соседних узлов без обратного прохода по дереву.

Сравнение методом `PartialEq` игнорирует поле `upper` (во избежание рекурсии).

## Модульная система

### Синтаксис импорта

```but
import "path/to/file.but";                        // весь файл
import "path/to/file.but" as Module;              // с переименованием
import * as Module from "path/to/file.but";       // все экспорты
import { TypeA, FnB as FnAlias } from "file.but"; // выборочный импорт
```

### Правила разрешения имён

- Файлы ищутся по списку путей поиска
- Имя модуля выводится из имени файла (camelCase: `my_file.but` → `MyFile`)
- Повторный импорт одного файла идемпотентен
- Выборочный импорт ищет имя в порядке: модели → типы → переменные → условия

## Диагностика и ошибки

### Структура диагностического сообщения

```
Уровень: Debug | Info | Warning | Error
Тип:     ParserError | SyntaxError | DeclarationError |
         TypeError | CastError | SematicError | Warning
Позиция: файл, строка, столбец (начало и конец)
Заметки: дополнительный контекст к ошибке
```

### Категории ошибок

| Категория          | Примеры                                       |
|--------------------|-----------------------------------------------|
| `ParserError`      | Неожиданный токен, неожиданный EOF            |
| `SyntaxError`      | Некорректная конструкция                      |
| `DeclarationError` | Неизвестный идентификатор, дублирование имени |
| `TypeError`        | Несоответствие типов, недопустимое приведение |
| `SematicError`     | Нарушение семантических правил                |
| `Warning`          | Потенциально проблемный код                   |

### Примеры проверок

- Ровно одно `start`-состояние в каждой модели
- Переменная типа `bit` принимает только `0`, `1`, `true`, `false`
- Все использованные переменные/функции/типы должны быть объявлены
- Индексы массивов проверяются при известном типе

### Светофор с таймером

```but
type u8 = [bit;8];

model TrafficLight {
    var timer: u8 = 0;

    start Red {
        enter  { timer = 0; }
        always { timer = timer + 1; }
        ref Green: timer = 255;
    }

    state Green {
        enter  { timer = 0; }
        always { timer = timer + 1; }
        ref Yellow: timer = 100;
    }

    state Yellow {
        enter  { timer = 0; }
        always { timer = timer + 1; }
        ref Red: timer = 50;
    }

```

### Работа с портами и внешними функциями

```but
type u8  = [bit;8];
type u32 = [bit;32];

extern fn debug(msg: u8);

port LED  : u8  = 0x00100000;
port BTN  : bit = 0x00200000:0;

fn toggle(val: u8) -> u8 {
    return ~val;
}

model ButtonLED {
    var state: u8 = 0;

    start Idle {
        ref Active: BTN = 1;
    }

    state Active {
        enter {
            state = toggle(state);
            debug(state);
        }
        next Idle;
    }
}

start M = ButtonLED;
```

```but
model Init    { start S; }
model Startup { start S; }
model Run     { start S; }

start System = (Init + Startup) + (Run | Halt);
```

## Недостатки и проблемные места

### 1. ~~Непоследовательность синтаксиса управляющих конструкций~~ — **Исправлено (С1)**

Реализован вариант A улучшения С1: все управляющие конструкции используют единый стиль без скобок вокруг условия (как в
Rust/Go). `do-while` удалён из языка, добавлен `loop` с опциональным условием:

```but
if x > 0 { }                              // без скобок
loop x > 0 { }                            // loop с условием (аналог while)
loop { break; }                           // бесконечный loop
for var i = 0; i < 10; i = i + 1 { }     // без скобок
```

### 2. Перегрузка символа `=` в условиях и выражениях

В блоках `cond`/`ref` символ `=` означает **проверку равенства**, а в выражениях — **присваивание**. Это серьёзный
источник ошибок при переходе между контекстами:

```but
cond A = x = 0;    // второй = означает сравнение
always { x = 0; } // здесь = означает присваивание
```

### 3. Отсутствие блочных комментариев

Поддерживаются только однострочные `//` и `///`. Блочные комментарии `/* */` недоступны, что затрудняет временное
отключение больших фрагментов кода.

### 4. ~~Переменные запрещены внутри блоков операторов~~ — **Исправлено (С4)**

Реализована полноценная поддержка `var` и `const` внутри блоков операторов (`if`, `loop`, `for`,
именованных блоков `always`/`enter`/`exit`). Переменная видна в последующих операторах того же блока
и скрывается при выходе. Затенение переменных уровня модели поддерживается. `port` внутри блоков
не поддерживается — порты являются аппаратными маппингами и объявляются только на уровне модели.

```but
start S {
    always {
        var local: bit = false;
        local = true;           // OK: local видна в том же блоке
    }
    // local здесь недоступна
}
```

### 5. Минимальный набор встроенных функций

Только `debug` и `S`. Отсутствуют базовые математические функции (`min`, `max`, `abs`), битовые утилиты, работа с
таймерами.

### 6. ~~Отсутствие защиты от циклических импортов~~ — **Исправлено (Се1)**

Реализовано обнаружение циклических импортов. При обнаружении цикла возвращается диагностическая ошибка с полной
цепочкой:

```
Циклический импорт: /src/a.but → /src/b.but → /src/a.but
```

Все три формы импорта (`import "..."`, `import "..." as Name`, `import { A } from "..."`) защищены от циклов.

### 7. ~~Опечатка в имени директории тестов~~ — **Исправлено**

Директория переименована из `tests/data/sematic/` в `tests/data/semantic/`. Все ссылки в тестах
и документации обновлены.

### 8. ~~Активное использование `Rc<RefCell<T>>`~~ — **Частично исправлено (SA8)**

Обратные ссылки на родительскую модель (`upper`) во всех семантических узлах (переменные,
условия, функции, именованные блоки, состояния) преобразованы из `Rc<RefCell<ModelNode>>`
в `Weak<RefCell<ModelNode>>`. Это разрывает все циклы вида `Model → Node.upper → Rc<Model>`
и позволяет дереву корректно освобождаться при удалении корневого `Rc`.

Прямые ссылки (родитель → дочерняя модель через `models: HashMap`) по-прежнему используют
`Rc` — это правильно, поскольку они не образуют циклов. `Rc<RefCell<T>>` в целом остаётся
архитектурной особенностью; полный переход на арены или индексную адресацию возможен в
будущих версиях.

### 9. Отсутствие шаблонов/обобщённых типов

Ключевое слово `template` зарезервировано, но не реализовано. Нет возможности написать параметрические типы или
функции — для встраиваемых систем это ведёт к дублированию кода при работе с разными размерами массивов.

### 10. Нет пользовательских структурных типов

Система типов ограничена массивами фиксированного размера и псевдонимами. Нет аналога `struct` или `enum` с полями — для
встраиваемых систем это существенное ограничение.

### 11. ~~Безусловный переход `next` не проверяется на достижимость~~ — **Исправлено (Се5)**

Функция `transition_completeness_warnings` предупреждает, если состояние содержит `ref`-переходы
совместно с `next` (переходы `ref` в этом случае недостижимы после выполнения `next`).

### 12. ~~Нет проверки полноты переходов~~ — **Исправлено (Се5)**

Функция `transition_completeness_warnings` предупреждает:
- если в модели нет терминальных состояний (автомат не может завершить работу);
- если из конкретного состояния нет пути к терминальному состоянию (BFS по графу переходов).

### 13. ~~Документационные комментарии не включаются в модель~~ — **Исправлено (Се12)**

Реализована привязка `///`-комментариев к семантическому дереву через [`construct_model_with_docs`]. Поля
`ModelNode::doc` и `ModelNode::docs` содержат документацию модели и её элементов.

```but
/// Документация состояния.
start Idle {
    ref Active: btn = 1;
}
```

```rust
let (ast, comments) = parse(src, 0) ?;
let root = construct_model_with_docs( & ast, None, & [], & comments) ?;
root.borrow().element_doc("Idle"); // → ["Документация состояния."]
```

### 14. Отсутствие стандартной библиотеки

Нет встроенного модуля с типовыми алгоритмами, коллекциями или утилитами для встраиваемых систем.

#### Се11. Строгая проверка булевости условий переходов — **Реализовано**

Функция `implicit_bool_warnings(model)` проверяет все условия переходов (`ref`/`next`) и возвращает предупреждения
`Warning` для случаев, когда числовой тип используется без явного сравнения:

```but
ref Next: timer;          // Предупреждение Се11: числовой тип [bit;8] вместо bool
ref Next: timer != 0;     // Явно и безопасно — без предупреждения
```

**Реализация:**

- Модуль `grammar/src/semantic/validate.rs`
- Публичный API: `grammar::semantic::tree::implicit_bool_warnings`
- Условия `ref`-переходов разрешаются на этапе 6 конвейера (`Condition::Unresolved` → `Condition::*`), поэтому
  проверка Се11 работает прежде всего с разрешёнными условиями (`is_boolean_semantic_condition`), а
  `is_boolean_ast_condition` используется только как запасной путь, если условие не было разрешено
- «Булевыми» считаются: `bool`/`bit`-переменная, результат сравнения (`=`, `!=`, `<`, `>`, `<=`, `>=`), логическое НЕ
  (`!`), булев литерал, именованное условие (`cond`), вызов функции (тип неизвестен на этапе анализа), `Condition::None`
- Числовые условия: переменная типа `[bit;N]`, числовые литералы, арифметика (`+`, `-`), побитовые операции (`&`, `|`),
  элементы массива — порождают `Warning`
- Описание ошибочного выражения генерируется лениво (только при наличии нарушения)
- Рекурсивно обходит вложенные модели

**Тесты:**

- 58 unit-тестов в `validate.rs`: полное покрытие всех ветвей `is_boolean_ast_condition` и `ast_condition_summary`
- 30+ интеграционных тестов в `semantic_tests.rs`, в том числе тесты разрешения условий `ref` и тесты ссылок на
  родительскую модель (`upper`)
- 6 файлов примеров: `implicit_bool_warn.but`, `implicit_bool_numeric.but`, `implicit_bool_arithmetic.but`,
  `implicit_bool_named_cond.but`, `ref_cond_resolved.but` (валидный), `ref_cond_arithmetic.but` (вызывает Се11)

#### Се12. Документация как часть семантической модели — **Реализовано**

`///`-комментарии включены в семантическое дерево через новую функцию `construct_model_with_docs`. Каждый `ModelNode`
содержит:

- `doc: Vec<String>` — документация самой модели
- `docs: HashMap<String, Vec<String>>` — документация именованных элементов (состояний, переменных, функций, типов,
  условий)
- `own_doc()` / `element_doc(name)` — методы для удобного доступа

Алгоритм привязки основан на позициях в исходном тексте: `///`-комментарий достаётся тому элементу, ближайшим следующим
для которого он является. Поддерживаются многострочные блоки и вложенные модели.

## Оставшиеся проблемы и открытые задачи

### Известные проблемы

1. **Перегрузка `=` в условиях** — `cond A = x = 0;` неоднозначно; рекомендуется ввести `==` в контексте условий
2. **Отсутствие блочных комментариев** — `/* */` не поддерживаются; затруднено временное отключение блоков кода
3. **Минимальный набор встроенных функций** — только `debug` и `S`; отсутствуют `min`, `max`, `abs`, таймерные утилиты
4. **Нет шаблонов (generics)** — ключевое слово `template` зарезервировано, но не реализовано; дублирование кода неизбежно
5. **Нет структурных типов** — нет `struct`; невозможно сгруппировать связанные поля
6. **Отсутствие стандартной библиотеки** — нет встроенного модуля `std` или `core` (имеющийся `std.but` — тестовый)
7. **Нет LSP/языкового сервера** — есть расширение для Zed, но без поддержки автодополнения и навигации
8. **Ce14 (FE4) проверяет только безусловные переходы** — пересечение условий (`a > 5` и `a > 3`) семантически не анализируется
9. **Генератор C неполон** — нет генерации тела функций перехода, обработчиков `enter`/`exit`/`always`
10. ~~**`enum` в системе типов ограничен**~~ — **Исправлено (NI6)**: добавлена проверка принадлежности числовых значений к вариантам перечисления; добавлено разрешение имён вариантов (например, `North`) в выражениях

### Открытые задачи

#### NI1. Блочные комментарии

Добавить поддержку `/* */` и `/** */` в лексер:

```but
/* Временно отключённый блок кода */
var x = 42;
```

#### NI2. Расширение встроенных функций

Добавить в `builtin.rs`: `min(a, b)`, `max(a, b)`, `abs(x)`, `clamp(x, lo, hi)`.

#### NI3. Структурные типы

Ввести `struct` для группировки полей:

```but
struct Point { x: [bit;16], y: [bit;16] }
var p: Point = Point { x: 10, y: 20 };
```

#### NI4. Улучшение Ce14 — анализ перекрытия условий

Расширить `check_nondeterministic_transitions` для обнаружения пересечений условий на основе символьного анализа интервалов.

#### NI5. Полная генерация C-кода

Завершить `generator/c/mod.rs`: генерация тел функций, FSM-диспетчера (`transition()`), обработчиков именованных блоков (`on_enter`, `on_exit`, `always`).

#### ~~NI6. Типобезопасные операции с `enum`~~ — **Реализовано**

Реализована проверка: при присваивании переменной типа `Direction` числовым литералом, значение должно быть одним из вариантов перечисления. Добавлено разрешение имён вариантов (например, `North`) как выражений.

```but
enum Direction { North, South, East, West }
var dir: Direction = 0;      // OK: 0 — значение варианта North
var dir2: Direction = North; // OK: вариант North разрешается в 0
var dir3: Direction = 99;    // NI6-ошибка: 99 не является вариантом Direction
```

**Реализация:**

- `ModelNode::search_enum_variant(variant_name)` в `semantic/mod.rs` — поиск варианта по имени среди всех доступных перечислений
- Разрешение идентификаторов-вариантов в `semantic/expression.rs` (шаг 4: имя → `Expression::Number(value)`)
- `validate_enum_values(model)` — проверка инициализаторов переменных типа enum в `validate_model`
- `check_enum_type_safety(model)` — расширенная проверка инициализаторов и присваиваний в именованных блоках (`always`, `enter`, `exit`)
- Публичный API: `grammar::enum_type_safety_errors(model)`

**Тесты:**

- 6 unit-тестов в `validate.rs`: корректная инициализация, некорректное значение, явные значения, несколько ошибок, не-enum тип, неизвестный тип
- 2 файла примеров: `ni6_enum_valid_assign.but` (валидный), `ni6_enum_invalid_assign.but` (невалидный)

#### FE1. Грамматический синтаксис для перечислений — **Реализовано**

Добавлена поддержка `enum` в LALRPOP-грамматику и лексер (токен `enum`):

```but
enum Direction { North, South, East, West }
enum Priority { Low = 0, Medium = 5, High = 10 }
```

Реализация: `ast.rs` (EnumDefine, EnumVariant), `lexer.rs` (Token::Enum), `grammar.lalrpop` (правила EnumDefine/EnumVariant), `tree.rs` (построение EnumNode из AST).

#### FE2. Вывод типа из пользовательских псевдонимов — **Реализовано**

Добавлена функция `ast_type_to_node_ctx` с разрешением псевдонимов через `model.borrow().types`:

```but
type u8 = [bit;8];
fn get() -> u8 { return 0; }
var x = get();  // x: [bit;8] (разрешается через псевдоним u8)
```

#### FE3. Диагностика неиспользуемых переменных (Ce13) — **Реализовано**

Новый модуль `semantic/unused.rs`. Публичный API: `grammar::unused_variable_warnings(model)`.

```
Ce13: переменная 'tmp' объявлена, но нигде не используется
```

Порты и константы не предупреждаются — они составляют внешний интерфейс модели.

#### FE4. Проверка детерминированности переходов (Ce14) — **Реализовано**

Функция `check_nondeterministic_transitions` обнаруживает состояния с несколькими безусловными `ref`-переходами. Публичный API: `grammar::nondeterministic_transition_warnings(model)`.

#### FE5. Интеграция генератора C в конвейер — **Реализовано**

CLI-компилятор `grammar/src/bin/butc.rs`:

```sh
butc compile --target c input.but -o output.c
butc compile input.but   # выводит в output.c
```

Публичный API в `lib.rs`: `grammar::compile_to_c(source, output_path)`.

#### FE6. Составные типы в параметрах функций — **Реализовано**

Добавлено правило `ParameterTypeExpr` в `grammar.lalrpop`, разрешающее запись `[T;N]` в параметрах:

```but
fn process(data: [bit;8]) -> bit { return 0; }
```

#### NI6. Типобезопасные операции с `enum` — **Реализовано**

Добавлены проверка допустимости числовых значений при присваивании переменным типа enum и разрешение имён вариантов как выражений.
Публичный API: `grammar::enum_type_safety_errors(model)`.
