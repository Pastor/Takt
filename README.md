# BuT — Язык программирования для конечных автоматов

**BuT** (Bus and Transitions) — предметно-ориентированный язык (DSL) для моделирования конечных автоматов и компонентных систем, реализованный на Rust. Язык ориентирован на описание встраиваемых систем, управление состояниями и аппаратную абстракцию с доступом к портам ввода-вывода.

## Лексический анализ

Лексер написан вручную на Rust без использования генераторов. Он поддерживает:

- **Идентификаторы** — Unicode XID + символ `$`: `myVar`, `_x`, `$tmp`
- **Числа**:
  - Целые десятичные: `0`, `123`, `1_000_000`
  - Шестнадцатеричные: `0xFF`, `0x1A_BC`
  - Рациональные (float): `3.14`, `1e10`, `2.5E-3`
  - Адресные литералы: `0x00100000:5` (адрес:бит)
- **Строки**: одинарные и двойные кавычки, префикс `unicode`:
  ```
  "hello"    'world'    unicode"текст"    unicode'текст'
  ```
- **Комментарии**:
  - Однострочный: `// комментарий`
  - Документационный: `/// документация`
  - Блочные комментарии (`/* */`) **не поддерживаются**
- **Ключевые слова**: автоматически распознаются через статическую хеш-таблицу (PHF)

### Таблица ключевых слов

| Группа | Ключевые слова |
|--------|----------------|
| Объявления | `var`, `const`, `type`, `fn`, `extern`, `port` |
| Управление | `if`, `else`, `loop`, `for`, `break`, `continue`, `return` |
| Состояния | `model`, `state`, `start`, `ref`, `next` |
| Прочее | `import`, `as`, `from`, `cond`, `formula`, `assembly` |
| Литералы | `true`, `false` |
| Зарезервированы | `template`, `string`, `pragma` |

```but

    return a + b;
```

### Модели и состояния

```but
model TrafficLight {
    var timer: u8 = 0;

    start Red {                         // начальное состояние (ровно одно)
        enter  { timer = 0; }           // выполняется при входе в состояние
        always { timer = timer + 1; }  // выполняется каждый цикл
        exit   { }                      // выполняется при выходе из состояния
        ref Yellow: timer > 10;         // условный переход
    }

    state Yellow {
        next Green;                     // безусловный переход
    }

    state Green {
        ref Red: true;
    }
}
```

### Условия (cond)

```but
cond IsActive     = x = 1;           // = означает равенство, не присваивание!
cond InRange      = x > 0 & x < 100;
cond Either       = IsActive | InRange;
cond NotActive    = !IsActive;
```

### Операторы управления потоком

```but
// if — без скобок вокруг условия
if x > 0 {
    x = x - 1;
} else {
    x = 0;
}

// loop с условием (аналог while) — без скобок
loop x > 0 {
    x = x - 1;
}

// бесконечный loop (без условия)
loop {
    x = x + 1;
    if x >= 10 { break; }
}

// for — без скобок вокруг заголовка
for var i = 0; i < 10; i = i + 1 {
    // ...
}
```

| 10 | `<` `>` `<=` `>=` | сравнение | левая |
| 9 | `\|` | побитовое ИЛИ | левая |
| 8 | `^` | побитовое XOR | левая |
| 7 | `&` | побитовое И | левая |
| 6 | `<<` `>>` | битовые сдвиги | левая |
| 5 | `+` `-` | сложение, вычитание | левая |
| 4 | `*` `/` `%` | умножение, деление, остаток | левая |

## Система типов

### Примитивные типы

| Тип | Размер | Значения | Описание |
|-----|--------|----------|----------|
| `bit` | 1 бит | `0`, `1`, `true`, `false` | Одиночный бит |
| `bool` | 1 бит | `true`, `false` | Булев тип |
| `float` | переменный | IEEE | Рациональное число |
| `unit` | 0 | — | Пустой тип (возвращаемое значение процедур) |

### Составные типы

```but
[bit;8]          // массив из 8 бит (байт)
[u8;16]          // массив из 16 байт
```

### Вывод типов

Компилятор автоматически выводит тип из инициализатора:

| Инициализатор | Выводимый тип |
|---------------|---------------|
| `0` … `255` | `[bit;8]` |
| `256` … `65535` | `[bit;16]` |
| `65536` … `2³²−1` | `[bit;32]` |
| `2³²` … `2⁶⁴−1` | `[bit;64]` |
| `true` / `false` | `bool` |
| `3.14`, `1e10` | `float` |

### Условия и выражения — разные операторы равенства

Важная особенность: в контексте **условий** (`cond`, `ref`) оператор `=` означает **проверку равенства**, а не присваивание:

```but
cond IsZero = x = 0;        // x равен 0?
var x = 0;                  // присваивание 0 переменной x
```

В обычных **выражениях** `==` — это сравнение, `=` — присваивание.

## Семантика и модель выполнения

### Жизненный цикл конечного автомата

1. **Начальное состояние**: каждая модель с состояниями должна иметь ровно одно `start`-состояние
2. **Вход в состояние**: выполняются все блоки `enter` в порядке объявления
3. **Активное состояние**: выполняются все блоки `always` каждый цикл
4. **Проверка переходов**: вычисляются условия `ref`; при истинности — переход
5. **Выход из состояния**: выполняются все блоки `exit`

### Переходы

```but
ref NextState: condition;   // условный переход (condition — выражение или cond)
next NextState;             // безусловный переход (всегда срабатывает)
```

### Области видимости

- Переменные модели видны во всех вложенных состояниях
- Переменные состояния видны только в нём и вложенных блоках
- Разрешение имён: локальная область → родительская модель → прародительская и т.д.
- Затенение: локальное объявление скрывает родительское

### Семантические проходы анализатора

| Проход | Описание |
|--------|----------|
| 1. Скелет | Извлекаются имена моделей/состояний, загружаются импорты |
| 2. Типы | Разрешаются псевдонимы типов, адреса портов |
| 3. Выражения | Разрешаются ссылки на переменные, вызовы функций, вывод типов |
| 4. Операторы | Разрешаются операторы в именованных блоках, проверка типов |

## Недостатки и проблемные места

### 1. ~~Непоследовательность синтаксиса управляющих конструкций~~ — **Исправлено (С1)**

Реализован вариант A улучшения С1: все управляющие конструкции используют единый стиль без скобок вокруг условия (как в Rust/Go). `do-while` удалён из языка, добавлен `loop` с опциональным условием:

```but
if x > 0 { }                              // без скобок
loop x > 0 { }                            // loop с условием (аналог while)
loop { break; }                           // бесконечный loop
for var i = 0; i < 10; i = i + 1 { }     // без скобок
```

### 2. Перегрузка символа `=` в условиях и выражениях

В блоках `cond`/`ref` символ `=` означает **проверку равенства**, а в выражениях — **присваивание**. Это серьёзный источник ошибок при переходе между контекстами:

```but
cond A = x = 0;    // второй = означает сравнение
always { x = 0; } // здесь = означает присваивание
```

### 3. Отсутствие блочных комментариев

Поддерживаются только однострочные `//` и `///`. Блочные комментарии `/* */` недоступны, что затрудняет временное отключение больших фрагментов кода.

### 4. Переменные запрещены внутри блоков операторов

`var` и `const` допустимы только на уровне модели/состояния, но не внутри `if`, `loop` или других блоков:

```but
if x > 0 {
    var y = 5;   // ОШИБКА — запрещено
}
```

Это вынуждает объявлять все переменные в начале состояния, нарушая принцип минимальной области видимости.

### 5. Минимальный набор встроенных функций

Только `debug` и `S`. Отсутствуют базовые математические функции (`min`, `max`, `abs`), битовые утилиты, работа с таймерами.

### 6. ~~Отсутствие защиты от циклических импортов~~ — **Исправлено (Се1)**

Реализовано обнаружение циклических импортов. При обнаружении цикла возвращается диагностическая ошибка с полной цепочкой:

```
Циклический импорт: /src/a.but → /src/b.but → /src/a.but
```

Все три формы импорта (`import "..."`, `import "..." as Name`, `import { A } from "..."`) защищены от циклов.

### 7. Опечатка в имени директории тестов

Директория `tests/data/sematic/` содержит опечатку (должно быть `semantic`). Влияет на воспринимаемое качество кода и затрудняет навигацию.

### 8. Активное использование `Rc<RefCell<T>>`

Семантическое дерево построено на `Rc<RefCell<T>>`. Это усложняет граф владения, затрудняет многопоточное использование и потенциально приводит к утечкам памяти при циклических ссылках.

### 9. Отсутствие шаблонов/обобщённых типов

Ключевое слово `template` зарезервировано, но не реализовано. Нет возможности написать параметрические типы или функции — для встраиваемых систем это ведёт к дублированию кода при работе с разными размерами массивов.

### 10. Нет пользовательских структурных типов

Система типов ограничена массивами фиксированного размера и псевдонимами. Нет аналога `struct` или `enum` с полями — для встраиваемых систем это существенное ограничение.

### 11. Безусловный переход `next` не проверяется на достижимость

Если в состоянии есть `ref`-переходы и `next`, анализатор не предупреждает о том, что `next` всегда выполнится, делая предшествующие `ref` потенциально бессмысленными.

### 12. Нет проверки полноты переходов

Анализатор не проверяет, существуют ли пути выхода из каждого состояния. Состояние может оказаться «тупиком» без каких-либо предупреждений.

### 13. Документационные комментарии не включаются в модель

Комментарии `///` распознаются лексером, но не входят в семантическое дерево и никуда не экспортируются. Инструменты не могут использовать их для генерации документации.

### 14. Отсутствие стандартной библиотеки

Нет встроенного модуля с типовыми алгоритмами, коллекциями или утилитами для встраиваемых систем.

## Предложения по улучшению

### Синтаксические улучшения

#### С1. Унификация синтаксиса условий — **Реализовано (вариант A)**

Реализован вариант A: все управляющие конструкции без скобок (стиль Rust/Go). `do-while` удалён, вместо него — `loop` с опциональным условием.

```but
// Все конструкции — без скобок
if x > 0 { }
loop x > 0 { }        // loop с условием (аналог while)
loop { break; }       // бесконечный loop (аналог do-while с break)
for var i = 0; i < 10; i = i + 1 { }
```

#### С2. Единый оператор сравнения в условиях

Ввести `==` в контексте `cond`/`ref` вместо перегрузки `=`:

```but
// Текущее (неоднозначно):
cond A = x = 0;

// Улучшенное:
cond A = x == 0;
```

#### С3. Поддержка блочных комментариев

```but
/* Временно отключённый блок
start Debug {
    always { debug(x); }
}
*/

/** Документация к состоянию */
start Idle { }
```

#### С4. Переменные внутри блоков операторов

```but
start S {
    always {
        var local = compute();   // переменная живёт только в этом блоке
        debug(local);
    }
}
```

#### С5. Тернарный оператор

```but
var x = condition ? value_true : value_false;
```

#### С6. Сокращённые операторы присваивания

```but
x += 1;    // вместо x = x + 1
x -= y;
x <<= 2;
x &= mask;
```

#### С7. Синтаксический сахар для переходов с несколькими условиями

```but
ref Idle when timer > 100;           // альтернативный читаемый синтаксис
ref Idle: timeout | error_occurred;  // явный OR (уже работает через |)
```

### Семантические улучшения

#### Се1. Обнаружение циклических импортов — **Реализовано**

Реализована проверка на основе стека обрабатываемых файлов. При обнаружении цикла возвращается ошибка с полной цепочкой:

```
Циклический импорт: /src/a.but → /src/b.but → /src/a.but
```

Поддерживаются все формы импорта: `import "..."`, `import "..." as Name`, `import { A } from "..."`. Линейные цепочки (без петли) работают корректно.

#### Се2. Реализация шаблонов (generics)

Ввести параметрические модели и функции (ключевое слово `template` уже зарезервировано):

```but
template<N: int>
type array_N = [bit; N];

template<T>
fn identity(x: T) -> T {
    return x;
}
```

#### Се3. Структурные типы

Ввести `struct` для группировки связанных полей:

```but
struct Point {
    x: u8;
    y: u8;
}

var p: Point = Point { x = 0, y = 0 };
```

#### Се4. Перечисления

Ввести `enum` для моделирования конечных наборов значений (особенно органично для DSL конечных автоматов):

```but
enum Color { Red, Green, Blue }

var led: Color = Color::Red;
```

#### Се5. Проверка достижимости и полноты переходов

Статический анализ:
- Предупреждение о состоянии без исходящих переходов («тупик»)
- Предупреждение о переходе после `next` (недостижимый код)
- Предупреждение о нескольких `next` в одном состоянии

```
Предупреждение: состояние 'Done' не имеет исходящих переходов
Предупреждение: блок 'always' в состоянии 'End' после 'next' недостижим
```

#### Се6. Расширенный двунаправленный вывод типов

Выведение типа переменной из контекста её использования, а не только из инициализатора:

```but
fn add(a: u8, b: u8) -> u8 { return a + b; }
var result = add(1, 2);   // result: u8 — выводится из типа возврата функции
```

#### Се7. Стандартная библиотека

Добавить встроенный модуль `std` или `core`:

```but
import std;

fn clamp(val: u8, lo: u8, hi: u8) -> u8;
fn min(a: u8, b: u8) -> u8;
fn max(a: u8, b: u8) -> u8;
fn abs(x: i8) -> u8;
```

#### Се8. Атрибуты состояний и моделей

Добавить аннотации для инструментальной обработки:

```but
#[timeout(100)]
#[priority(high)]
start Critical {
    // ...
}

#[verify(reachable)]
state Done { }
```

#### Се9. История состояний

```but
state Paused {
    ref history;        // возврат в предыдущее состояние
    ref deep_history;   // возврат с восстановлением вложенных состояний
}
```

#### Се10. Явные модификаторы времени жизни переменных состояния

Ввести ключевые слова для явного управления сохранением значения между посещениями:

```but
state S {
    persistent var counter: u8 = 0;  // сохраняется между посещениями
    transient  var temp:    u8 = 0;  // сбрасывается при каждом входе
}
```

#### Се11. Строгая проверка булевости условий переходов

Требовать явного сравнения вместо неявного приведения числа к bool:

```but
ref Next: timer;          // Предупреждение: неявное u8 → bool
ref Next: timer != 0;     // Явно и безопасно
```

#### Се12. Документация как часть семантической модели

Включить `///`-комментарии в семантическое дерево и экспортировать их через публичный API для автоматической генерации документации.
