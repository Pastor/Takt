Используй при проектировании или ревью Rust API, обработке владения, работе с перечислениями и FFI.

## Владение и конструирование

1. Для чтения проверь, хватит ли `&str`, `&[T]` или `&T`. Возвращай владеющее значение, когда результат создаётся внутри и его должен хранить вызывающий. Проверь, может ли потребляющая операция при ошибке вернуть исходное значение.
2. Если borrow checker мешает изменить одно поле при заимствовании другого, работай с полями напрямую или выдели самостоятельные части структуры. Для переноса содержимого при смене варианта `enum` используй `mem::take` или `mem::replace`.
3. Используй `new` для явного конструирования, `Default` при осмысленном значении по умолчанию и Builder при множестве необязательных параметров. Newtype помогает различать доменные значения, скрывать представление и реализовывать трейты в пределах orphan rule. `Deref` оставляй умным указателям и владеющим коллекциям, когда он выражает доступ к содержимому.

## API и реализация

1. Для публичных расширяемых типов оцени `#[non_exhaustive]`. Для внутренних перечислений, где новый вариант обязан учитываться каждым обработчиком, используй исчерпывающий `match` и при необходимости lint против `_`.
2. Предпочитай статическую диспетчеризацию, когда тип известен при компиляции. Для разнородных реализаций используй `dyn Trait`. Если ссылка на выбранную реализацию живёт в пределах функции, проверь, можно ли обойтись без выделения памяти. Перед `move`-замыканием явно привяжи нужные поля или значения.
3. Выбирай паттерн по задаче. Strategy подходит для сменных алгоритмов, Command — для передаваемых действий, Visitor — для отделения обхода от операции, Interpreter — для вычисления по грамматике, Fold — для накопления результата. Используй чистые функции и итераторы, когда они упрощают код.
4. Форматируй сложные строки через `format!`. Резервируй ёмкость в измеренном горячем пути. При делении модуля сохраняй публичные пути импорта через реэкспорт, где от них зависят вызывающие.

## FFI и проверка

1. Локализуй `unsafe` и опиши условия безопасности. Проверь владение и срок жизни указателей и строк. Используй C-совместимое представление на ABI, а `CStr`, `CString`, `Path` или `OsStr` — в подходящих Rust-обёртках. Связывай получение и освобождение ресурса через RAII. Для ошибок используй коды или другой согласованный ABI, учитывай поведение паники.
2. Для примеров API используй компилируемые doctests. Комментируй назначение и инварианты кода. Проверь тесты и lint-правила проекта. Если тестовый профиль собирает только таблицы строк и отладчику нужны локальные переменные, разово запусти `CARGO_PROFILE_TEST_DEBUG=true cargo test --test <цель>`.
