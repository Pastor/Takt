Применяй при написании и ревью Rust-кода. Учитывай соглашения проекта и совместимость публичного API.

- Принимай заимствованные аргументы (`&str`, `&[T]`, `&T`), когда владение не нужно. Если операция принимает значение и при отказе оно остаётся пригодным, предусмотри возможность вернуть его вызывающему коду.
- Ограничивай изменяемость областью, где она нужна. Управляй ресурсами через RAII. Применяй `mem::take` или `mem::replace`, если нужно перенести значение из поля без клонирования.
- Используй типы для выражения инвариантов. Закрывай поля, если конструирование требует проверок. Разбирай варианты внутренних перечислений явно, если новый вариант должен потребовать изменения всех обработчиков.
- Локализуй `unsafe`, документируй условия безопасности и поддерживай их в безопасном интерфейсе. Выражай отказ через контракт FFI и предотвращай выход паники через границу ABI, которая не допускает раскрутку стека.
- Деление модулей определяй по ответственности. Соблюдай лимиты и проверки репозитория. Публичные примеры проверяй как doctests. Настраивай предупреждения в CI и точечными lint-правилами.
