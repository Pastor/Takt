## 2. Кандидаты в фичи

Идеи, ещё не оформленные в карточку `docs/features/XXXX-*.md`.

- **Баг генератора C: нет `typedef struct {Root} {Root};` для одиночной модели**
  (выявлено при 0020-05). Для модели **без под-моделей** заголовок `c` не эмитит
  typedef корня → прототипы `{Root}_init({Root} *)` невалидны как отдельный C
  (нужен тег `struct`). В `c-hal` исправлено локально; для цели `c` — оформить
  фикс (эмитить typedef всегда). Внимание: правка меняет вывод `c` → сверить
  codegen-снапшоты.

- **Пред­существующие сбои тестов на Windows** (выявлены при 0021, не связаны с
  ней; падают и на исходном коде): 5 тестов `lamc` — разбиение `--include-dirs`
  по `:` конфликтует с Windows-путями/буквами дисков; 1 тест `viewport`
  (`simulation`) — путь к ресурсу не найден (ошибка ФС). Оформить фикс/фичу.
- **Семантическая подсветка Lam в IntelliJ через `lam-lsp`** (задел из фичи 0022,
  Option C ADR) — надстройка над лексической подсветкой плагина
  `extensions/intellij-lam` (semantic tokens `lam-lsp`; LSP4IJ/LSP API).
- **Полноценный PSI-парсер плагина IntelliJ** (поверх лексера 0022; надстройка
  над фичей [0023](docs/features/0023-intellij-navigation-include.md)) — то, что
  лёгкий путь 0023 не покрывает: **find usages**, **структура файла**, **rename**,
  инспекции/диагностики, настоящие `PsiReference` для путей `import`,
  кросс-файловое разрешение имён (переход к символу *внутри* импортированного
  файла). Go to Declaration и переход к файлу `import` уже сделаны в 0023.

- **Бэкенд генерации в Structured Text (IEC 61131-3 ST)** — третий целевой язык
  наряду с C и PlantUML (`generator::Language` сейчас = `C` | `PlantUML`).
  Прямо на профиль проекта («промышленные системы управления»): ST — стандартный
  язык ПЛК, куда FSM ложится естественно. Аддитивно (новый вариант `Language`,
  новый `generator/st/`), совместимость не ломает. Оценить на примерах
  `elevator.lam`/`stacker.lam`. **Включает потребителя `AT %…`** для карты
  адресов из фичи [0020](docs/features/0020-port-address-decl.md) (`AddressMap →
  AT %IX…`).

- **`-D`/инъекция define’ов для адресов** (вынесено из [0020](docs/features/0020-port-address-decl.md)) —
  символы `--define NAME=VALUE` в среде констант, потребляемые выражениями адреса
  (`address BTN = BTN_ADDR;`). Тонкий слой поверх `AddressMap`; наборы define’ов
  под платформы. Оформить как анализ после ядра 0020.

- **SVD-подобный экспорт карты адресов** (вынесено из [0020](docs/features/0020-port-address-decl.md)) —
  выгрузка `AddressMap` во внешний формат (`lamc address-map --emit …`) для
  сторонних инструментов (отладчики, генераторы HAL). Требует стабильного
  `AddressMap` из ядра 0020.
- **Юнит-конструкции языка для симуляции (assert/invariant)** — задел на сближение
  крейта `simulation` и верификации: инварианты/ассерты прямо в модели, которые
  симулятор проверяет по шагам, а LTL-верификатор — статически. Требует проработки
  (может пересекаться с 0010); оформить как анализ до карточки.

Остаточные пункты плагина (0022/0023): визуальная `runIde`-проверка в среде с
GUI; юнит-тест CT3 на произвольный неалфавитный символ → `BAD_CHARACTER`.
`verifyPlugin` **настроен и пройден** (фикс [0023-01](docs/fixes/0023-01-verifyplugin-descriptor.md)):
Compatible для IC 2024.3/2025.1/2025.2 — список IDE обновлять по мере выхода
новых релизов. Сборка по-прежнему под 2024.1.x/JDK 17 (расширение на 2024.2+ как
целевой платформы требует JDK 21, но открытый `until-build` уже даёт установку и
подтверждённую совместимость с новыми IDE).
