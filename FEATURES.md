## 2. Кандидаты в фичи

Идеи, ещё не оформленные в карточку `docs/features/XXXX-*.md`.

- **`taktc fmt` печатает синтаксическую ошибку Debug-дампом диагностики.** При
  любом отказе разбора (`SY-001…005`) форматтер выводит `не удалось разобрать
  исходник: [Diagnostic { file: None, loc: Source(0, 6, 7), level: Error, … }]`
  — вместо привычного `путь:строка:колонка: Ошибка компиляции [КОД]: текст`,
  который печатают `compile`, `verify` и `takt-sim`. Причина —
  `FormatError::Parse(format!("{d:?}"))` в `takt-lang/src/format/mod.rs`:
  диагностика превращается в строку **внутри** библиотеки, теряя структуру, и
  восстановить формат вызывающему уже нечем. Вскрыто пробой фичи
  [0156](docs/features/0156-parser-depth-limit.md) (2026-07-31) на её же новой
  диагностике `SY-005`, но класс шире и старше: так печатается **любая**
  ошибка разбора в `fmt`. Смежно с
  [0168](docs/features/0168-generator-warnings-return.md) (диагностику
  возвращают вызывающему, а не печатают/склеивают в библиотеке) — вероятно,
  чинится там же.

- **Цель `st` ТЕРЯЕТ инициализатор переменной типа `[bit;N]` — молча.** Проба
  задачи [0157-05](docs/development/0157-05-literal-u64-representation.md)
  (2026-07-30, вход из четырёх строк): `var small: [bit;8] := 255;` даёт в ST
  `small : USINT;` — **без значения**, тогда как рядом стоящая `var plain: u8 :=
  7;` объявляется как `plain : USINT := 7;`. Симулятор и цель `c` дают 255,
  цель `st` — 0. `taktc` рапортует успех, `iec2c` вывод принимает: расхождение
  наблюдаемо только потактовой сверкой, а сверки `st` по бит-векторам нет.
  Класс — **Tier 1** (молча неверный продукт). Значение литерала здесь ни при
  чём: теряются и узкие (`42`), и широкие. Смежно с
  [0078](docs/features/0078-bit-array-semantics.md) (`[bit;N]` — упакованный
  скаляр) и с остаточным покрытием 0183 (потактовые сверки `st`).

- **Константное выражение в инициализаторе переменной симулятором НЕ
  вычисляется — эталон и цель `c` расходятся МОЛЧА.** Проба стадии архитектуры
  [0157](docs/features/0157-literal-u64-representation.md) (2026-07-30, вход из
  четырёх строк): `var a: u8 := 1 + 2;` — симулятор показывает `a = 0`, цель `c`
  печатает `model->a = 1 + 2;` (то есть `3`). Причина названа в самом коде:
  `takt-sim/src/unit/initial.rs` относит любые унарные и бинарные операции к «не
  константа» с комментарием «свёртка принадлежит семантике», **а семантика её не
  делает** — переменная молча получает значение по умолчанию. Частный случай —
  `var u: u64 := ~0;`: симулятор `0`, цель `c` — все единицы; ещё один —
  `var n: [bit;64] := ~0;` падает `SIM-006` («значение массив нельзя привести к
  типу Integer»), хотя по [0078](docs/features/0078-bit-array-semantics.md)
  `[bit;N≤64]` — упакованный **скаляр**. Класс — **Tier 1** (молча неверный

  уровне состояния (`start A { : [Guard] неизвестное; }`), тогда как
  `invariant Safe = неизвестное;` даёт `SE-025` — потому что десахаризуется в
  `cond`, а `cond` обходится. 0155 сняла лишь глотание ошибок **разрешения** в
  той же ветке (например `SE-062`), причину молчания на имени — нет.
- **Внешний интерфейс модели не выражается: `extern fn` не исполняется
  симулятором, агрегат не может быть аргументом параметра.** Вскрыто фиксом
  [0186-01](docs/fixes/0186-01-example-decomposition.md) (2026-07-30, две пробы)
  при попытке сделать интерфейс памяти внешним — по предложению заказчика.
  Первое: `extern fn mem_read(addr: u8) -> u8;` цель `c` принимает (метод HAL), а
  симулятор останавливает прогон — «внешняя функция не имеет тела». Значит модель
  с внешним интерфейсом **непроверяема эталоном**: сверка поведения невозможна, а
  примеры документа (их гейт исполняет) такой формы содержать не могут. Второе:
  `Memory(prog := {9, 8, 7, 6})` отвергается `SE-083` — константный вычислитель
  агрегат не сворачивает, поэтому «программа как аргумент» не выражается.
  Устранение первого — стенд/заглушка для `extern fn` в симуляторе (это ADR:
  откуда брать значения); второго — агрегатные значения в константном
  вычислителе.

- **Вариант импортированного перечисления не разрешается в образце `match`.**
  Вскрыто фиксом [0186-01](docs/fixes/0186-01-example-decomposition.md)
  (2026-07-30, проба из двух файлов). `import { Op } from "lib.takt";` — и затем
  `match v { Lda => … }` даёт `SE-003` «идентификатор не найден», тогда как
  условие `ref Done: v = Hlt;` **в том же файле** тот же вариант разрешает. То
  есть разрешение вариантов перечисления есть в выражениях и условиях, но путь
  образца `match` смотрит мимо импортированных объявлений. Обход в примерах:
  модели, разбирающие опкод, живут в том же файле, что и `enum`. ⚠️ Корпус класс
  не покрывает: перечисления в нём не пересекают границу импорта.

- **Форматтер выносит комментарий из тела блока наружу.** Вскрыто при разработке
  задачи [0186-04](docs/development/0186-04-book-processor-example.md)
  (2026-07-30). Проба в четыре строки: комментарий, стоящий **первой строкой
  внутри** `always { … }`, после `taktc fmt` оказывается **после** закрывающей
  скобки — то есть привязывается к следующему элементу состояния (`ref`). Текст
  не теряется, теряется **место**: в примерах раздела 20 пояснение к телу стало
  читаться как пояснение к переходу. ⚠️ Это не «синоним, который не
  канонизируется» (`while`/`loop`, `Guard`), а перемещение авторского
  комментария — форматтер обязан сохранять его позицию либо честно отказывать.
  Обход в примерах: комментарий ставится **перед** `always`. Корпус класс не
  ловит: в `examples/` комментарии внутри тел стоят не первой строкой.

- **Массив как общая переменная не переносится в цель `st`; индекс массива —
  только литерал или имя.** Вскрыто пробами задачи
  [0186-01](docs/development/0186-01-book-processor-example.md) (2026-07-30).
  Первое: файл, где под-модели общаются через `var mem: [u8;4]` корня,
  компилируется целью `st`, но `iec2c` его отвергает — «Data type incompatibility
  between parameter 'mem' and value being passed, when invoking FB»; скалярная
  общая переменная при этом работает. То есть цель принимает вход и порождает
  **невалидный** ST — тот же класс, что 0184 (рапорт об успехе при негодном
  выводе), только в другой цели. Второе: грамматика индекса принимает `mem[pc]` и
  `mem[3]`, но **не** `mem[pc + 1]` (`SY-002`, «ожидалось `]`») — выражение в
  индексе не разбирается ни в выражениях, ни в условиях. ⚠️ Корпус ни того, ни
  другого не покрывает: массивы в нём не выходят за пределы одной модели, а
  индекс всюду простой. Устранение первого — работа по цели `st` (передача
  массива в FB либо честный отказ вместо невалидного вывода); второго — правка
  грамматики (кандидат отдельной фичей: индекс-выражение).

- **Симулятор теряет model-level `always` у модели, состояние которой —
  композиция; цель `c` его исполняет.** Вскрыто при разработке задачи
  [0185-07](docs/development/0185-07-model-parameters.md) (2026-07-30, проба):
  файл `var probe: u8 := 0; model Tuner { … } always { probe := probe + 1; }
  start Main = Tuner | Tuner;` даёт в симуляторе `probe = 0` на всех тактах, а в
  порождённом C — `model->probe = model->probe + 1;` в теле такта. То же с
  **именованной** моделью-композицией (`start Main = Tuner | Tuner;` внутри
  `model Root2 { … always { … } }`). У модели со **своими** состояниями
  (`always { … } start S { … }`) блок исполняется верно — то есть дефект в ветви,
  где такт модели уходит в композицию, и тело модели-владельца до исполнения не
  доезжает. Это **расхождение эталона и цели**, причём молчаливое: класс
  [0083](docs/features/0083-model-always-block-c.md) (где тело терялось везде) и
  [0181-01](docs/fixes/0181-01-sim-parallel-always-twice.md) (где оно исполнялось
  дважды). ⚠️ Корпус класс не покрывает: `always` на уровне модели есть только у
  моделей со своими состояниями. Устранение — фикс симулятора + значенческая
  сверка sim ≡ `c` на накапливающем теле (`probe := probe + 1`, иначе
  идемпотентное тело дефект скрывает).

- **Цели `rust` и `sv`: одноимённые константы разных моделей молча сливаются в
  одну.** Вскрыто при разработке задачи
  [0185-06](docs/development/0185-06-model-parameters.md) (2026-07-30, проба):
  `model A { const K: u8 := 2; … } model B { const K: u8 := 3; … } start Main = A | B;`
  даёт в цели `rust` единственный `const K: u8 = 2;`, в цели `sv` —
  единственный `localparam logic [7:0] K = 2;`, и модель `B` **молча** считает с
  чужим значением. Причина одна на две цели: константа печатается **голым
  именем** (`rust_expr::const_name`, `sv_expr::const_signal`), а объявления
  дедуплицируются по нему же, тогда как оба вывода — **одно** пространство имён
  (модуль Rust; уплощённый модуль SV). Цель `c` квалифицирует все константы
  всегда (`CONST_<МОДЕЛЬ>_<ИМЯ>`), цель `st` держит их полями `FUNCTION_BLOCK` —
  там дефекта нет по устройству. Тот же класс, что у ключа карты адресов
  ([0084](docs/features/0084-address-map-qualified-key.md)) и у кандидатов
  именования, найденных при [0182](docs/features/0182-pid-library-and-application.md).
  ⚠️ В 0185-06 квалифицированы **только** константы, выведенные из параметра
  модели: там молчание было бы неверным выводом ради того самого, зачем параметр
  и заводят (две настройки одного имени). Общий случай не тронут сознательно —
  переименование всех констант изменило бы вывод корпуса, а требование R7 фичи
  0185 держит его байт-в-байт. Устранение — отдельная работа: квалифицировать
  константы в `rust`/`sv` как в `c` (вывод корпуса меняется, снапшоты
  обновляются) либо отвергать коллизию диагностикой.

- **`takt-lang/src/semantic/statement.rs` — 999 строк при пределе ~1000.**
  Замер при закрытии 0155 (`scripts/check-module-size.sh` зелёный, но запаса
  нет). Следующая правка модуля обязана начинаться с разделения по образцу
  `semantic/validate/` («директория-подмодуль + `use super::*`», приёмы фичи
  0088), иначе гейт размера её отвергнет. В реестр долга
  `scripts/module-size-baseline.txt` файл **не вносить**: реестр замораживает
  нарушителей, а этот в лимит укладывается.
