## Проект

**Lam** (Language of Automata Models) — DSL для спецификации и синтеза конечных
автоматов (FSM) промышленных систем управления. Цели генерации: `c`/`c-hal`
(прошивка МК), `st`/`st-at` (ПЛК, IEC 61131-3), `rust` (`no_std`), **`sv`**
(синтезируемый SystemVerilog — FPGA/ASIC) и `plantuml` (диаграмма).
Rust-workspace из двух крейтов:

- `grammar` — компилятор (бинарник `lamc`) и LSP-сервер (`lam-lsp`).
- `simulation` — симулятор моделей и GIF-визуализация.

## Команды

```sh
# Сборка
cargo build --bin lamc
cargo build --features lsp --bin lam-lsp

# Канонический форматтер .lam (фича 0024)
cargo run --bin lamc -- fmt examples/          # на месте
cargo run --bin lamc -- fmt --check examples/  # проверка для CI (код ≠ 0 при отличии)

# Тесты (однопоточно — иначе гонки за общие файлы)
cargo test -- --test-threads=1
cargo test --features lsp -- --test-threads=1   # включая тесты LSP
cargo test <имя> -- --test-threads=1            # один тест по имени

# Предкоммит-проверка (fmt + check + clippy + test + сборка примеров)
./scripts/precheck.sh

# Прогон всех симуляций из examples/simulations/
./scripts/run_simulations.sh
```

**Внешние зависимости** (для сборки и тестов `lamc` не нужны — только для
проверки порождённого кода):

- `cmake` + `ninja` + `cc` — гейт цели `c` в `precheck.sh`.
- **MatIEC `iec2c`** — арбитр валидности порождённого Structured Text (фича
  0041): единственный автоматизируемый способ доказать, что ST валиден. Пакетом
  **не поставляется**. Ставить руками не надо — `precheck.sh` вызывает
  `scripts/ensure-iec2c.sh`, который при отсутствии собирает из исходников в
  `~/.local/bin/iec2c` (≈15 с; повторный вызов мгновенный). Скрипт **никогда не
  валит предкоммит**: нет сети/bison/инструментов → мягкий пропуск. Переменные:
  `IEC2C_PREFIX` (`~/.local`), `IEC2C_SRC` (`~/.cache/matiec`), `IEC2C_SKIP=1`.

  ```sh
  ~/.local/bin/iec2c -I ~/.local/share/matiec/lib -T <вывод> файл.st  # 0 = валиден, 1 = нет
  ```

  ⚠ **`-I` обязателен:** `make install` MatIEC ставит только бинарники
  (`install-data-am` пуст), а без `lib/ieclib.txt` iec2c падает на любом входе.
  Скрипт копирует библиотеку в `$PREFIX/share/matiec/lib` сам.

  Сам **гейт** (прогон по порождённым `.st`) в `precheck.sh` **включён и зелён**:
  бэкенд ST дозрел (тела `FUNCTION_BLOCK` эмитятся), `iec2c` принимает **весь**
  корпус `examples/` (8/8 валидны, проверено фичей 0090). Ручные пробы —
  `grammar/tests/data/st/probes/*.st`.

**CI (`.github/workflows/ci.yml`, фича 0090): прогоняет ВЕСЬ `precheck.sh` под
строгим режимом** (`PRECHECK_STRICT=1`) — единый источник истины гейтов, никакой
логики гейтов в самом workflow. Устанавливает инструменты (cmake/ninja/verilator/
yosys/bison/flex + сборка `iec2c`) и делает один вызов `./scripts/precheck.sh`;
под строгим режимом отсутствие инструмента — **ошибка**, а не мягкий пропуск, и
формат **проверяется** (`fmt --check`). Локально без флага поведение прежнее
(мягкие пропуски, `fmt` применяется). Прежде CI видел один живой гейт из семи (sv)
и нёс его **свою** реализацию — источник дрейфа, который фича закрыла.

## Архитектура

Конвейер компиляции: `.lam` → **лексер** (`parser/lexer.rs`) → **парсер**
(LALRPOP LR(1), `grammar.lalrpop`) → AST (`parser/ast.rs`) → **семантика**
(7 проходов, `semantic/`) → **генераторы** C (`generator/c/`) и PlantUML
(`generator/plantuml/`). Верификация свойств — `verification/` (LTL, автоматы Бюхи).

### Семантические проходы (по порядку)

| Проход | Файл | Назначение |
|---|---|---|
| 0 | `tree.rs` | Имена моделей/состояний, загрузка импортов |
| 1 | `tree.rs` | Составные состояния (`M1 + M2`, `M1 \| M2`) |
| 2 | `type_inference.rs` | Переменные, вывод типов, порты |
| 3 | `tree.rs` | Именованные условия (`cond`) |
| 4 | `tree.rs` | Именованные блоки (`enter`/`exit`/`always`) |
| 5 | `tree.rs` | Тела функций |
| 6 | `tree.rs` | Замена `Condition::Unresolved` разрешёнными условиями |

### Критические инварианты (НЕ нарушать)

- **Условия рёбер `ref` не разрешаются.** `ref Next: expr;` хранится как
  `Condition::Unresolved(ast::Condition)`. НЕ добавлять проход
  `resolve_state_references` — ломает `S(Ping) = End`. Охраняется тестом
  `grammar/tests/reference_model_tests.rs::reference_model_compiles_and_translates_state_ref`
  (фича 0075: перевод `S(Ping) = End` в C доказывает, что ссылка пережила
  конвейер; переехал из `lib.rs::syntax_simple`, который стоял на некомпилируемом
  `SRC`). (`semantic/reference.rs` — это структура данных `ReferenceNode`, а НЕ
  запрещённый проход разрешения.)
  **Скобки паттерна `S(Модель) = Состояние` прозрачны** (фича 0074): `(S(Ping)) =
  End`, `S((Ping)) = End`, `S(Ping) = (End)` дают вывод байт-в-байт равный
  бесскобочной форме. Канонизация — в **единой воронке** `condition.rs::
  resolve_condition` (через неё идут ref-рёбра, `cond`, LTL): `canonicalize_state_of`
  снимает обёртки `Parenthesis` в трёх позициях паттерна, `validate`/генераторы
  получают уже каноничный `Function(S,[Model])`. ⚠️ **Снимать `Parenthesis`
  глобально нельзя** — генераторы печатают их как `(…)` (группировка; в `rust`
  приоритеты иначе расходятся с C), поэтому strip только у операндов `S(…)`.
  Правая часть остаётся `Unresolved` (инвариант выше цел). Предикат `is_state_of`
  дублирует `c_expr::condition::state_of_model` — держать в согласии.
- **Разделение `Condition` / `Expression` — намеренное, НЕ унифицировать**
  (фича 0019, `ADR 0019` отверг полное слияние). Это две грамматики с **разной
  семантикой `=`**: в условии — равенство (`Condition::Equal`), в выражении —
  присваивание (`Expression::Assign`). Слияние сломало бы инвариант `=`/`==` и
  все существующие `.lam` (`ref Next: BTN.0 = 1;` стало бы присваиванием).
  Дубликат **`LoopCond`** устранён (0019-01): цепочка приоритетов написана один
  раз как параметризованное правило `Chain<Atom>` и инстанцируется двумя
  атомами — `Expression = Chain14<Precedence1Full>` (с инициализатором `{…}`) и
  `LoopCond = Chain14<Precedence1NoBrace>` (без него; иначе `loop { body }`
  неотличим от `loop {init} { body }`). Ограничение касается только **первого**
  токена, поэтому правый операнд внутри макроса — всегда полная цепочка.
- **Операторы `:=` / `=` (фича 0021, версия языка 0.1.0):** присваивание —
  `:=` (`Expression::Assign`); сравнение на равенство — `=` в выражениях
  (`Expression::Equal`) **и** в условиях (`Condition::Equal`); `==` **выведен**
  из языка (ошибка разбора). Реляционный `<=` без изменений (`LessEqual`). Знак
  `=` также связка в определениях имён (`type`/`enum`/`model`/`state`/`cond`),
  инициализаторы `var`/`const`/портов — через `:=`. AST-узлы прежние — сменилась
  лишь привязка токенов в `grammar.lalrpop` (токен `:=` = `Token::ColonAssign`).
- **Адрес порта (фича 0020, версия языка 0.2.0):** три источника адреса с
  приоритетом **inline `:=` < оператор `address Имя = <адрес>;` < внешняя карта**
  (`--address-map`, `.ld`-подобный формат `address_map/parse.rs`). Слой
  `AddressMap` (`resolve_addresses`, `address_map/resolve.rs`; каталог
  `address_map/` разделён по темам фичей 0069 — `parse`/`env`/`eval`/`resolve`,
  `mod.rs`-реэкспорт держит пути импорта). Диагностики: SE-048 (висячая привязка),
  SE-049 (конфликт inline + `address`), SE-050 (оверлей карты), SE-051 (висячая
  запись карты), SE-052 (used-порт без адреса), AM-001…006 (формат карты).
  **Выражение адреса вычисляется** (фича 0042, закрыта): имена (`--define` →
  `const` модели, рекурсивно, с защитой от циклов) и целочисленная арифметика;
  всё вне подмножества → `SE-055`, неопределённый символ → `SE-054` (ошибка в
  `c-hal`/`st-at`, предупреждение вне). Прежде принимались **только литералы**, и
  символ/арифметика **молча теряли адрес**, давая `SE-052` о следствии.
  ⚠️ Потеря была в **двух** местах: `lower_addr_expr` (оператор) и **фильтр
  инициализатора порта** `tree.rs:476` (inline) — второй срабатывал раньше, на
  этапе 0; снят. `--define NAME=VAL` даёт **среду `AddressEnv`**, видимую
  **только** вычислителю адреса (CLI не должен менять логику автомата); define —
  **не** источник адреса, приоритет не трогает; перекрытие `const` → `SE-053`.
  Арифметика — в **одном** месте (`apply_binary`) для обоих матчеров (сырой АСД у
  оператора, понижённый `ExpressionNode` у inline): разъехавшись, они дали бы
  разный адрес для одного текста.
  Потребление — только цели `-t c-hal` и `-t st-at` (таблица адресов + дефолтный HAL через
  `*(volatile*)`); цель `c` адрес **не эмитит** (порты через HAL-колбэки). Прежний
  инвариант «цель `c` байт-в-байт неизменна» **снят фичей 0033** (она изменила
  тело `_tick`); он описывал 0020, не трогавшую такт. `address` — жёсткое ключевое
  слово.
  **Бит адреса (`0xADDR:бит`) — диапазон [0, 63]; ширина доступа HAL по слову**
  (фикс [0020-01](docs/fixes/0020-01-port-bit-out-of-range.md), фича
  [0098](docs/features/0098-port-bit-range-safe-hal.md), закрыта). Бит вне [0, 63]
  → **`SE-060`** (в `address_map/resolve.rs`, слой `c-hal`/`st-at`; цель `c` не
  задета). Дефолтный HAL (**вынесен в `generator/c/c_hal.rs`** — `c_header.rs`
  упирался в лимит размера) читает бит-порт словом, **минимально содержащим бит**
  (`word_bytes_for_bit`: 1/2/4/8 байт), `read_bit`/`write_bit` — `switch` по
  `b.width`, маска `(uint64_t)1u << s`. ⚠️ **Прежде читался ОДИН байт со сдвигом
  на `b.bit`** → бит 8…31 молча ноль, бит ≥ 32 UB (`int >> 33`); дожило потому,
  что **`c-hal` не компилировалась ни одним гейтом** — теперь есть гейт `cc -c` в
  `precheck.sh`. UB доказан устранённым **исполнением** (значенческий тест
  `grammar/tests/hal_bit_range_tests.rs` через `mmap(MAP_FIXED)` — эмуляция MMIO,
  адрес 16 ТБ: macOS отвергает низкие). ⚠️ **Ширина per-port, а не per-word**
  (C-1 ADR 0098): порты на одном адресе с разными битами получают разную ширину
  доступа — каждый бит извлекается верно, но унификация по адресу за Option B
  (язык выражает ширину слова; смежно 0084). `extend_complex.lam` (бит 33) не
  правлен — обоснован (uint64).
  **Экспорт карты наружу — `lamc address-map --emit map|json`** (фича 0043,
  закрыта). Выгружает **фактически разрешённую** карту (тот же `resolve_addresses`,
  что у `c-hal`): `map` — `.ld`-формат, замыкается через `--address-map` (круговой
  рейс байт-в-байт); `json` — версионированный контракт (тип/направление/адрес/бит/
  источник; мёртвый порт → `"address": null`, **не** `0x0`). `ResolvedAddress`
  обогащён `ty`/`direction` (тем же обходом); мёртвые порты — в
  `AddressResolution::address_less`. Эмиттеры — `address_map/export.rs`, CLI-обвязка
  — `address_map/export_cli.rs`. ⚠️ **CLI вынесен в библиотеку**: `bin/lamc.rs`
  пришпилен к baseline размера (2009) — в бинарнике тонкий диспетчер; туда же уехал
  `split_include_dirs`. CMSIS-SVD не поставляется (`--emit svd` → ошибка). Крейт
  `grammar` — 0.6.0.
  ⚠️ **Ключ `AddressResolution.map` квалифицирован моделью (фича 0084):**
  `qualified_port_key(model_unique, port)` (`address_map/resolve.rs`), а не голое
  имя — иначе одноимённые порты разных под-моделей делили бы запись и адрес
  первого терялся при вставке (латентный дефект ядра 0020; в корпусе замаскирован
  — все адреса на корне). Продюсер (`model_unique_name`, обход `upper`) и
  потребитель (`Name::unique()`) обязаны строить **одну** строку — правя одно,
  правь другое. `ResolvedAddress` несёт голое `name` для публичных форматов.
  Потребители: `c-hal`/`st-at` — lookup по квалиф. ключу; `sv-mmio`/экспорт — по
  `resolved.name`; `SE-051` — голое имя среди значений. ⚠️ **Выгрузка `.ld`/`json`
  остаётся ПЛОСКОЙ** (дедуп по имени, побеждает последний = макс. квалиф. ключ) —
  круговой рейс R4 0043 требует одной записи на имя; квалификация выгрузки (Option
  C) отвергнута. То есть c-hal видит оба одноимённых порта, а плоская выгрузка —
  один. Крейт `grammar` `0.10.0 → 0.11.0` (аддитивное поле `name`).
- **Вход в стартовое состояние не расходует такт (фича 0033, версия 0.3.0).**
  Тело стартового состояния исполняется на **такте 1** — как в симуляторе
  (`enter_initial_state`, 0025-04), — на любой глубине вложенности. Генератор C
  диспетчеризует `INIT` через `if (model->state == {PREFIX}_INIT) { … }` **до**
  `switch`, без `break` (`c_model.rs::generate_model_tick`); инициализация
  вложенных — в `_init` (`generate_start_state_init`, R6: чтение до первого
  `_tick` не UB), блоки `enter` — в такте (поведение). **Контракт для будущих
  бэкендов** (0041 ST, 0045 SV): вход не стоит такта; не воспроизводить чужие
  `INIT`-такты. Потактовая сверка — `conformance_c_tests.rs`
  (`per_tick_trace_*`).
- **Model-level `always` исполняется каждый такт (фича 0083).** Тело `always`
  **вне состояния** (элемент модели) исполняется **каждый такт до диспетчеризации
  состояния**, безусловно по состоянию — в симуляторе (эталон) и во всех целях.
  Прежде молча терялось везде, включая симулятор (`builder.rs` строил
  `executions: HashMap::new()`; наполнен из `model.named_blocks`). Эмиссия — до
  `switch`/`match`/`CASE`/`unique case` (`c_model`/`rust_model`/`st_model`/
  `sv_fsm`); печатники блоков вынесены в `{c,rust,sv}_blocks.rs` (лимит размера).
  ⚠️ **Композитный `always`** (`Root = M { always … }`) работал и раньше — как
  тело синтетического состояния `case ROOT`; дефект был у модели со **своими**
  состояниями. Объём — `always`; model-level `enter`/`exit` **не** реализованы
  (механизм принимает любой `block_name`). Сверка — `conformance_c_tests::
  model_level_always_matches_generated_c` + `grammar/tests/model_always_tests.rs`
  (эмиссия + компиляция rust/st/sv настоящими тулами; корпус конструкции не
  содержит → вывод байт-в-байт неизменен).

## Технические подводные камни

- **Пути** — через `std::path::Path` (не разбивка строк). При генерации C явно
  обрабатывай анонимные/корневые модели (получают имя `Root`) и пустые случаи.
- **Генератор C: порождённый C сегодня не компилируется** (фичи
  [0026](docs/features/0026-c-root-typedef.md),
  [0029](docs/features/0029-c-type-mapping.md), обе в работе). Для модели **без
  под-моделей** не эмитится typedef корня → `cc` даёт 8 ошибок на любой такой
  модели (0026, +2 строки правки). `get_c_type` (`generator/c/mod.rs:150`):
  `Array(size, elem)` → `uint{size}_t`, где `size` — **число элементов**, а не
  разрядность (`[u8; 4]` → невалидный `uint4_t`); `Bit` → `int`; `Rational` →
  `float` (f32), тогда как симулятор считает в f64. **Не используй вывод C как

- **Генератор ST: вывод принимается `iec2c` — гейт зелён** (весь корпус

  `FUNCTION_BLOCK` нет тела → `no body defined in function block declaration`»
  **снята** — тела эмитятся. Остаются в силе **факты MatIEC, снятые пробами**
  (нарушишь — вывод перестанет компилироваться):
  массивы **не вкладываются** (`ARRAY OF ARRAY` отвергается — нужна многомерная
  форма `ARRAY [0..2, 0..1] OF T`); перечислимый `TYPE F : (A := 80)` отвергается

  целым типом + константами `VAR CONSTANT`; `VAR_GLOBAL` вне `CONFIGURATION`

  MatIEC протаскивает квалификатор на следующую секцию, и присваивание падает с
  «Assignment to CONSTANT variables is not allowed». Поэтому `st_func.rs` печатает
  локальный `VAR` **до** `VAR CONSTANT` (сторож — `test_function_var_precedes_var_constant`).
  **Имена делят пространство со стандартной библиотекой не только у POU, но и у
  переменных**: `left`/`right`/`mid` (строковые функции IEC), `limit` (`LIMIT`),
  `step` (ключевое слово SFC) отвергаются — идентификаторы IEC
  **регистронезависимы**, а диагностика обманчива («invalid located variable
  declaration» про `AT %…`, которых в объявлении нет). Оба факта были **латентны

  переменных. Разрядность перечисления считается **по
  диапазону вариантов**, а не берётся `USINT`, как предполагал ADR:
  `enum Action { Idle = 670 }` (`elevator.lam:121`) в байт не влезает.

- **Выражения ST: числа и биты — непересекающиеся миры** (фича 0041,
  `generator/st/st_expr.rs`). `AND`/`OR`/`XOR`/`NOT` в IEC определены **только на
  битовых строках** (`BYTE`/`WORD`/`DWORD`/`LWORD`): `n AND m` при `n : USINT` —
  ошибка. Обратно, **арифметика на битовых строках запрещена** (`y + 1` при
  `y : BYTE` — ошибка). Поэтому переменные числовые, а побитовые операции идут
  через преобразование **в месте операции**: `n & m` →
  `BYTE_TO_USINT(USINT_TO_BYTE(n) AND USINT_TO_BYTE(m))`. Отсюда трансляция
  **типозависима**: без типа операнда имя функции не построить → `ST-011`, а не
  догадка. **Битового доступа `x.0` в MatIEC нет вовсе** (ни `x.0`, ни `%X0`) —
  разворачивается в маску `(USINT_TO_BYTE(x) AND 16#01) <> 16#00`. Оператора
  `<<` нет — только `SHL`/`SHR` над битовой строкой. ⚠ Вопреки плану `b := 0;`
  для `BOOL` **компилируется** (не проходит лишь `b := 2;`); `FALSE`/`TRUE`
  печатаются ради стандартности, а не потому, что иначе не собирается.

  `st_expr::coerce_to` — как в `rust`/`sv`): `BOOL`/`bit` + `0`/`1` → `FALSE`/
  `TRUE`, перечисление + число → имя константы (`command := 2` → `Command_Stop`,
  совпадает с объявлением `st_decl::enum_constants`). Зовётся на присваивании
  (покрывает `enter`/`exit`/`always` — они идут через тот же `print_statement`) и
  на инициализаторе объявления; `print_expression` типа НЕ видит и не менялась.
  Значение без варианта → **число** (не догадываться). ⚠️ `state := N`
  (синтетический регистр, тип `USINT`, не Lam-enum) остаётся числом. Прежде `st`
  была **единственной** целью, чей вывод противоречил сам себе (объявляла
  `Command_Stop` и тут же его не использовала).

- **Fixed-point `q(m, n)`: арифметика ПОБИТОВО едина у симулятора и всех целей**
  (фича [0061](docs/features/0061-fixed-point-type.md), закрыта). Эталон —
  `simulation/src/eval/fixed.rs` (`Value::Fixed { repr, m, n }`); нормативные
  правила ADR 0061: `+`/`−` — repr-арифметика с wraparound к `W = m + n`; `*` —
  произведение `2W`, сдвиг на `n` вправо, **floor к −∞**; `/` — расширение `2W`,
  сдвиг влево, деление к нулю. Детектор формата во всех целях — общий слой
  `semantic::type_inference::extract_type` (`SE-059` гарантирует единый формат
  операндов). Q-логика вынесена: `c_expr/fixed.rs`, `rust_fixed.rs`,
  `st_fixed.rs`, `sv_fixed.rs`. Сверка — `conformance_{c,rust,st,sv}_tests`
  (наблюдение repr: `c` — поле структуры, `rust`/`st` — `as float` через порт
  (repr·2⁻ⁿ точно в f64/LREAL), `sv` — `$signed(dut.<сигнал>)`).

  **implementation-defined**. Floor эмитится **не** сдвигом, а хелпером
  `lam_q_floordiv` (floor-деление `/`/`%`, стандартно-определены); в порождённом
  C `>>` над знаковым **отсутствует вовсе** (сторож `generated_c_fixed_has_no_right_shift`

  отдельно). ⚠️ **Цель `st`: сдвигов над числами в IEC нет** (`SHL`/`SHR` только

  эмитируемую `FUNCTION LAM_Q_FLOORDIV`; промежуток `LINT`, `W > 32` → `ST-013`.
  ⚠️ **Цель `rust`: `x := x * y` над `q` НЕ сворачивается в `x *= y`** (дало бы
  умножение представлений без сдвига — молча неверно + паника в debug); `as iN <<`
  требует скобок `(x as iN)` (иначе Rust парсит `iN<...>` как generic). ⚠️ **Цель

  потребителя (`lib.rs::scoped_formula`), **не** в сборщике
  `ltl_check::model_ltl_formulas` (тот отдаёт `LtlSite { formula, loc, state }`
  с **авторской** формулой): второй потребитель сборщика — диагностики, и
  SE-056 обязан ругаться на атом, который написал автор. Печатается
  **проверенная** формула, а не авторская.
  **Область проверки — свой файл** (фича 0051, закрыта): `--scope file`
  (умолчание) / `all`. Импорт **неотличим** от локальной вложенной модели своими
  силами (проход 0 кладёт обе в один `models`, `Location::file_no` везде **0**),
  поэтому заведён признак `ModelNode::origin` (`ModelOrigin::{Local,Imported}`),
  ставится `tree.rs::mark_imported` в трёх формах импорта. ⚠ `Rename`
  (`import { A as B }`) — ловушка: узел приходит `Rc::clone`-ом чужого дерева и
  несёт `Local`; метит импортёр при вставке. Отсечение — **поддеревом целиком**
  (поузловая проверка признака не работает: вложенные модели чужого файла
  локальны для него). Пропущенное **перечисляется** (`VerifyOutcome.skipped`).
  `SE-055` **остался** (текст указывает на `lamc verify`): `lamc compile` LTL
  по-прежнему не проверяет. Вывод C неизменен.
- **Верификация свойств над данными — абстракция по формуле** (фича 0068,
  закрыта; `verification/data_kripke.rs`). Атом LTL теперь не только имя
  состояния, но и **предикат над данными**: именованное `cond` или булев
  `var`/`const`. Вершина Крипке становится парой `(состояние, оценка
  отслеживаемых переменных)`; отслеживаются **только** переменные, встречающиеся
  в φ (`comprehensive` + `cond Overheated = temperature >= MAX_TEMP` → 4 × 256 =
  **1024** вершины). Домен из типа: `bit`/`bool` → 2, целое `{bits}` → 2^bits,
  `enum` → число вариантов; `float`/`q`, порт, арифметика/функция в предикате,
  превышение **потолка** (`VERTEX_LIMIT = 1_000_000`, считается ДО построения) →
  честный `Verdict::Unsupported`. Если атомы — **только** имена состояний, путь
  прежний (0049) байт-в-байт (критерий A7). `build_buchi`/`product`/`emptiness`
  не тронуты — меняется лишь построение Крипке.
  ⚠️ **Консервативное ядро (решение заказчика):** ход данных **полностью
  недетерминирован** — отслеживаемая переменная на каждом такте вольна принять
  любое значение домена. Это **максимальная сверх-аппроксимация**: `Holds`
  надёжен (реальный прогон присутствует с точными метками; эталон позиции 0 —
  init-значения, «до первого `_tick`», R6 0033), но свойство над меняющимися
  данными почти всегда даёт **`Violated` (возможно, ложный)**; доказуемы лишь
  тавтологии над доменом (`G (temp <= 255)` для `u8`) и управляющие свойства.
  Прецизионное вычисление хода данных (Option D в полном объёме — доказывающее
  `G (temp <= 100)`, когда логика ограничивает `temp`) **не** реализовано: тот же
  класс риска, что стоил проекту года (неверный ход данных сломал бы `Holds`).
  Направление ошибки — сторож `abstracted_source_yields_extra_run_not_missed`:
  мутация правила 3 (заморозить данные) обязана дать **ложный `Holds`** и
  завалить тест.
  ⚠️ **Наивный explicit-state по данным НЕОСУЩЕСТВИМ** (замер при проработке 0068,
  обоснование абстракции по формуле):
  |состояний × Π доменов| даёт `stacker` — **1.1 × 10²²** (19 × 256⁸ × 2⁵),
  `comprehensive` — 3.6 × 10¹⁷. Решающее — **входные порты**: `in`-порт есть среда,
  вольная выбрать любое значение **каждый такт**, поэтому у `elevator` (21 входной
  `u8`) **3.7 × 10⁵⁰ преемников у ОДНОЙ вершины**. Конвейер работает на **явном**
  графе и таких объектов не представит — «просто поменять разметку вершин»
  **нельзя**.
  ⚠️ **Капкан, стоивший дефекта** ([фикс 0010-01](docs/fixes/0010-01-buchi-acceptance.md)):
  `build_buchi` с фичи 0010 принимал **любой** бесконечный прогон (`F p`
  принимал слово без `p`) — в `expand` в `Old` клались только литералы, из-за
  чего условие прогресса `Until` вырождалось в истину. Прожило в зелёном CI,
  потому что тесты `buchi.rs` проверяли **структуру** («states не пусто»), а не
  язык, а потребителя у затравки не было. Тесты верификации пиши **на вердикт**
  (`Holds`/`Violated` на эталонных парах модель×φ), а не на форму автомата.
  Инвариант GPVW: `Old := Old ∪ {η}` во **всех** ветках `expand` — не декорация,
  а вход условия принятия.

## Форматтер

Ядро печати — `grammar/src/format/` (`format_source`), потребители: `lamc fmt`
(`--check`/`--stdin`) и LSP `textDocument/formatting`. **Добавляешь узел АСД —
добавь и его печать**, иначе `format_source` начнёт отказывать (по замыслу: молча
потерять кусок исходника хуже). `grammar/tests/format_tests.rs` гоняет форматтер
по **всему корпусу** `.lam` и валит сборку при новом непокрытом узле.
`precheck.sh` проверяет канон `examples/` (фикстуры `tests/data/` намеренно не
нормализованы — тесты завязаны на их позиции).

**Синонимы не канонизируются:** `while`/`loop` и `: [Guard] x;`/`: x;` — АСД
хранит выбор автора (`ast::LoopKeyword`, `Guard::explicit`); семантика эти
признаки игнорирует.
