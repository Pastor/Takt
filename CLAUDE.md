## Проект

**Takt** (Typed, Automata, Known Timing) — DSL для спецификации и синтеза конечных
автоматов (FSM) промышленных систем управления. Цели генерации: `c`/`c-hal`
(прошивка МК), `st`/`st-at` (ПЛК, IEC 61131-3), `rust` (`no_std`), **`sv`**
(синтезируемый SystemVerilog — FPGA/ASIC) и `plantuml` (диаграмма).
Rust-workspace из двух крейтов:

- `takt-lang` — компилятор (бинарник `taktc`) и LSP-сервер (`takt-lsp`).
- `takt-sim` — симулятор моделей и GIF-визуализация.

## Команды

```sh
# Сборка
cargo build --bin taktc
cargo build --features lsp --bin takt-lsp

# Канонический форматтер .takt (фича 0024)
cargo run --bin taktc -- fmt examples/          # на месте
cargo run --bin taktc -- fmt --check examples/  # проверка для CI (код ≠ 0 при отличии)

# Тесты (параллельно — фича 0190 сняла `--test-threads=1`)
cargo test
cargo test --all-features                       # включая тесты LSP
cargo test <имя>                                # один тест по имени

# Предкоммит-проверка (fmt + check + clippy + test + сборка примеров), ~230 с
./scripts/precheck.sh

# Прогон всех симуляций из examples/simulations/
./scripts/run_simulations.sh
```

**Толчейн и CI** описаны один раз — в разделе «Документ и процесс»: пин
`rust-toolchain.toml` (стабильный `1.97.1`) и прогон всего `precheck.sh` под
`PRECHECK_STRICT=1`. Здесь только то, чего там нет: `Cargo.lock` **отслеживается**
(workspace даёт бинарники, а `lalrpop` берётся из git — без lock состав
зависимостей плавает), `resolver = "3"`, MSRV `rust-version = "1.97"` в обоих
манифестах (нижняя граница не измерялась).

**Внешние зависимости** (для сборки и тестов `taktc` не нужны — только для
проверки порождённого кода):

- `cmake` + `ninja` + `cc` — гейт цели `c` в `precheck.sh`.
- **MatIEC `iec2c`** — арбитр валидности порождённого ST (фича 0041):
  единственный автоматизируемый способ доказать, что ST валиден. Пакетом не
  поставляется, ставить руками не надо — `precheck.sh` зовёт
  `scripts/ensure-iec2c.sh` (собирает при отсутствии, ≈15 с) и **никогда не
  валит предкоммит**: нет сети/bison → мягкий пропуск. Переменные:
  `IEC2C_PREFIX`, `IEC2C_SRC`, `IEC2C_SKIP=1`.

  ```sh
  ~/.local/bin/iec2c -I ~/.local/share/matiec/lib -T <вывод> файл.st  # 0 = валиден
  ```

  ⚠ **`-I` обязателен:** `make install` MatIEC ставит только бинарники, а без
  `lib/ieclib.txt` `iec2c` падает на любом входе; скрипт копирует библиотеку
  сам. Ручные пробы — `takt-lang/tests/data/st/probes/*.st`.
## Архитектура

Конвейер компиляции: `.takt` → **лексер** (`parser/lexer.rs`) → **парсер**
(LALRPOP LR(1), `grammar.lalrpop`) → AST (`parser/ast.rs`) → **семантика**
(7 проходов, `semantic/`) → **генераторы** C (`generator/c/`) и PlantUML
(`generator/plantuml/`). Верификация свойств — `verification/` (LTL, автоматы Бюхи).

### Семантические проходы (по порядку)

| Проход | Файл | Назначение |
|---|---|---|
| 0 | `tree.rs` | Имена моделей/состояний, загрузка импортов |
| 1 | `tree.rs` | Составные состояния (`M1 + M2`, `M1 \| M2`) |
| 2 | `type_inference.rs` | Переменные, вывод типов, порты |
| 3 | `tree.rs` | Именованные условия (`cond`) |
| 4 | `tree.rs` | Именованные блоки (`enter`/`exit`/`always`) |
| 5 | `tree.rs` | Тела функций |
| 6 | `tree.rs` | Замена `Condition::Unresolved` разрешёнными условиями |

### Критические инварианты (НЕ нарушать)

Чек-лист перед правкой ядра. Каждый пункт подробно разобран ниже, в
«Технических подводных камнях», — здесь только имя инварианта, чтобы шесть самых
дорогих были видны вместе.

⚠️ **Связь двусторонняя и сторожится машиной**
([0289](docs/features/0289-claude-md-invariant-checklist-gate.md)): подробный
пункт несёт метку `` `[критический инвариант N]` ``, и
`scripts/check-claude-md.py` требует, чтобы номера чек-листа и метки совпадали
**в обе стороны**. Прежде запись надо было внести дважды, а забытую половину
никто не ловил — класс 0084/0193/0195, только списки не в коде, а в контексте.

1. **Условия рёбер `ref` не разрешаются** — прохода `resolve_state_references`
   не заводить (раздел «Семантика и диагностика»).
2. **`Condition` и `Expression` не унифицировать** — у них разная семантика `=`
   (там же).
3. **Присваивание `:=`, сравнение `=`, `==` из языка выведено** (там же).
4. **Адрес порта: inline `:=` < оператор `address` < внешняя карта** — вместе с
   квалификацией ключа, диапазоном бита и экспортом (раздел «Цели генерации»).
5. **Вход в стартовое состояние не расходует такт** — контракт для всех
   бэкендов (там же).
6. **Model-level `always` исполняется каждый такт** до диспетчеризации
   состояния (там же).

### Общее

- **Пути** — через `std::path::Path`, не разбивкой строк. При генерации C явно
  обрабатывай анонимные/корневые модели (получают имя `Root`) и пустые случаи.
- **Новые тесты** — сперва зонд для захвата реального вывода, затем проверки
  против захваченного. Не угадывать строки, адреса и позиции.
- **Сторож фикстуры проверяет её ОБЕЩАНИЕ, а не факт разбора**
  ([0288](docs/features/0288-fixture-guards-audit.md)). Замер 2026-08-20: из 62
  тестов на `tests/data/**/valid/` **28** только констатировали построение —
  такой тест зелен и в мире, где обещанное не работает (так было с выводом типа
  по ссылке до 0204; класс фикса 0010-01). Ратчет — `scripts/check-fixture-guards.py`
  плюс реестр `scripts/fixture-guard-baseline.txt`: новая констатация (`F1`) и
  протухшая запись (`F2`) роняют предкоммит. ⚠️ **Проверять «в дереве нет
  `Unresolved`» нельзя**: условия рёбер `ref` остаются неразрешёнными по
  инварианту — смотреть надо тело блока. ⚠️ Искать узел надо **там, где он
  написан**: индексация — в инициализаторах объявлений, перечисление — во
  вложенной модели (первая редакция сторожей искала не там и падала).
- **Параметр функции виден и при ИНДЕКСАЦИИ**
  ([0346](docs/features/0346-array-param-index.md)). Ветвь `ArraySubscript`
  спрашивала только `model.search_var`, и `fn first(a: [u8;2]) -> u8 { return
  a[0]; }` давал `SE-003` «Переменная 'a' не найдена» — параметр был виден
  всюду, кроме индексации. ⚠️ **Дефектов два:** параметры не передавались и в
  разбор **индекса** (рекурсивный вызов шёл с `vec![]`), поэтому `a[i]` с
  параметром-индексом ломался так же; срез (`ArraySlice`) — та же позиция.
  ⚠️ Отказ приходил из **семантики**, то есть одинаково у эталона и всех восьми
  целей: `probe.sh` пишет в таком случае «поведение цели НЕ измерено» — эта
  строка и указывает на предмет. ⚠️ Контроли обязательны: неизвестное имя
  остаётся `SE-003`, индексация не массива — `SE-030`. ⚠️ Имя `at` в пробе
  брать нельзя — это ключевое слово (адрес порта), отказ придёт от парсера
  (класс имени `ln`, 0342).
- **Разрешение переменных** проверяй в обоих путях — верхнеуровневый и вложенный
  доступ к модели (включая `tick`/`init`): починка одного пути часто ломает другой.
- **Поведение цели сверяется потактово, а не только компилируется.** Сверки —
  `takt-sim/tests/conformance_{c,sv,rust,st}_tests.rs`. ⚠️ Гейт целевого языка
  (rustc/clippy, verilator/yosys, iec2c) доказывает, что вывод **компилируется**,
  но не что он **верен**: молча неверная трансляция компилируется тоже. Правило:
  **сверку заводить вместе с бэкендом** — у [0045](docs/features/0045-sv-backend.md)
  дефект приняли молча оба инструмента SV, у [0050](docs/features/0050-rust-backend.md)
  сверки не было вовсе при зелёном гейте.
- **Тесты идут ПАРАЛЛЕЛЬНО; временный каталог теста уникален по тесту**
  ([0190](docs/features/0190-precheck-selective-gates.md)). Прежде предкоммит
  гонял `--test-threads=1` «из-за гонок за общие файлы»; замер показал, что
  гонок было **две**, обе в `st_tests`: каталог строился по фикстуре
  (`types_all`, `enum_struct` — их берут по 2–3 теста) и по имени входного
  файла (одно имя на два теста), а каждый помощник начинает с `remove_dir_all`.
  Ключ уникальности — имя потока (`std::thread::current().name()`: харнесс
  Rust называет поток именем теста); в однопоточном режиме имени нет, и ключом
  остаётся фикстура. Замер: 146 с → 95–127 с при 12 ядрах, а `cargo test` был
  тогда **84 % времени предкоммита** (сегодня — **65.6 %**, замер ADR 0242).
  ⚠️ Покраснел параллельный прогон — чини **каталог теста**, а не возвращай
  флаг: возврат прячет гонку и возвращает всю стоимость разом.
- **Интеграционные тесты — ОДНА цель на тему, набор внутри остаётся файлом**
  ([0244](docs/features/0244-test-target-build-cost.md),
  [0271](docs/features/0271-test-target-gate.md)). Тем семь (`semantic`,
  `targets`, `syntax`, `lsp`, `verify`, `conformance`, `sim`); файл темы —
  `tests/<тема>/main.rs`, он только объявляет `mod`. ⚠️ Причина — **замер**:
  первый запуск свежесобранного тестового бинарника стоит **0.60 с при загрузке
  ЦП 2 %**, повторный — 0.033 с, а бинарников было 147. ⚠️ **Новый набор
  кладётся в тему и объявляется в её `main.rs`**; сторож
  `check-test-targets.py` ловит `.rs` в `tests/` верхнего уровня (`T1`), набор
  без `mod` (`T2` — не собирается вовсе, а `cargo test` рапортует об успехе) и
  тему без `main.rs` (`T3`). ⚠️ **Имя потока несёт `::`** — временный каталог
  теста обязан вычищать двоеточие (инвариант 0190).
- **Генерация детерминирована** ([0048](docs/features/0048-deterministic-codegen.md)).
  Порядок эмиссии задаётся **типом контейнера** (`BTreeMap`/`BTreeSet`), а не
  сортировкой на выходе: локальная сортировка не спасает, если внешний цикл
  недетерминирован. Сторож — жёсткий гейт в `precheck.sh` (два прогона × все цели
  → `diff -r`). Следствие: дифф `examples/generated/` несёт смысл, снапшоты возможны.
- **Размер модуля** — ≤ ~1000 строк вместе с тестами (правило в `docs/CODE.md`,
  фича [0091](docs/features/0091-module-size-rule-in-code-md.md)). Проверяет
  `scripts/check-module-size.sh`; с [0261](docs/features/0261-module-size-warning-zone.md)
  он печатает **жёлтую зону** (`970…1000` строк, список с остатком запаса) —
  предупреждение **не влияет на код возврата**, иначе прогон падал бы за 30
  строк до предела в чужой правке. ⚠️ Порог выбран замером: при 950 в зоне 15
  файлов, при 900 — 23, при 970 — восемь; сегодня ближайший
  `generator/sv/sv_expr.rs` — 1000 строк, **запас 0**. ⚠️ Самопроверки у гейта
  не было с 0027 — теперь есть `scripts/test-module-size.sh` (мутация на
  временном дереве через `MS_ROOT`); реестр `scripts/module-size-baseline.txt` —
  **узаконенный долг** (3 файла), запись оттуда не имеет права расти, а уложившийся
  в лимит обязан быть удалён. ⚠️ Правя большой файл, готовься к отказу «вырос»:
  это замысел — выносить новое в отдельный модуль.
- **Генератор фич `scripts/new-feature.sh` идемпотентен**
  ([0094](docs/features/0094-new-feature-script-fixes.md)): повторный `--register`
  не дублирует строки реестров. Добор стадии — `--stage NAME`, подзадача —
  `--stage dev --subtask NN`. Регресс — `scripts/test-new-feature.sh` в предкоммите.

### Семантика и диагностика

- **Параметр модели — поле экземпляра, а под `--parameters=specialize` —
  константа копии** ([0185](docs/features/0185-model-parameters.md), версия
  языка 0.8.0). `parameter Y: u8 := 100;` живёт в `variables` обычным
  `VariableNode::Simple`; отличие — в `ModelNode::parameters` (имя, позиция,
  **порядок** — по нему строится ключ дедупликации). Аргумент вычислен и понижен
  в литерал: за границей семантики выражения аргумента не существует. ⚠️ Флаг
  меняет **форму** вывода, не поведение — сторож сверяет **четыре** трассы.
  ⚠️ Проход константности стоит **после специализации и до стадии 2**: позже
  пришлось бы править оба представления переменной (засада 0096) и опоздать к
  `after` и адресу порта; анализ идёт по **именам** — затенение ошибается в
  безопасную сторону. ⚠️ Параметр там, где нужна величина сборки — **`SE-088`,
  называющий режим**. ⚠️ Равенство `ParameterArgument` **игнорирует позицию**.
- **Ошибка разрешения оператора не зависит от глубины вложенности**
  ([0155](docs/features/0155-semantic-nested-statement-resolution.md)).
  `semantic/statement/mod.rs` пробрасывает ошибку `?` во **всех** телах (`if`/`else`,
  `while`/`loop`, `for`, inline-`Guard`). ⚠️ Возвращать
  `.unwrap_or_else(|_| Unresolved(…))` нельзя: цель `c` печатает `Unresolved`
  **пустотой**, симулятор пропускает — терялась не диагностика, а **сам оператор**.
  Сторож — `takt-lang/tests/semantic/nested_statement_resolution_tests.rs`.
- **Глубина вложенности ограничена** `MAX_NESTING_DEPTH = 32`, превышение →
  `SE-062` ([0129](docs/features/0129-semantic-deep-nesting.md)). Сторожа стоят в
  `construct_expression`, `resolve_condition`, `resolve_ast_statement`. Без предела
  инструменты падали `SIGABRT` без диагностики. ⚠️ Счётчик меряет глубину **узлов
  дерева**, а не скобок.
- **Второй предел — на разборе: `MAX_PARSE_DEPTH = 96`, превышение → `SY-005`**
  ([0156](docs/features/0156-parser-depth-limit.md)). Проверка стоит в **единой
  точке** `takt_lang::parse`, поэтому дерево глубже предела наружу не выходит и
  рекурсивные потребители (печать, `Clone`, `Drop`, `Debug`, `serde`) безопасны
  **по построению**. Прежде `taktc fmt` падал `SIGABRT` уже на ≈ 200 уровнях —
  семантику этот путь не зовёт, `SE-062` его не прикрывал. ⚠️ **Предел разбора
  обязан быть выше семантического с запасом**: счёт по узлам, и один уровень

  ⚠️ **Вычислитель отвечает ДВУМЯ родами сообщений** («значение неизвестно»
  против ошибки записи): свёртка проглатывала любую ошибку, и первый `SE-121` в
  ней растворился. ⚠️ **Дробное, длительность и агрегаты остаются эталону** —
  их правила завязаны на `Value`.
- **Приведение `as` вычисляется при компиляции, ПОКА оно тождественно**
  ([0286](docs/features/0286-sv-const-initializer-expression.md)). `const_eval`
  берёт `Cast`, если значение целое, целевой тип целочисленный и значение в него
  **помещается** (границы — у единственного носителя `literal_range::type_range`);
  прочее отвергает с названной причиной. ⚠️ **Правила изменения значения
  принадлежат ЭТАЛОНУ**, и копии их в `takt-lang` быть не должно: две реализации
  одного правила разошлись бы **значениями**. Отсюда узость — `300 as u8`
  невычислимо, хотя эталон его исполняет (кандидат). ⚠️ Прежде цель `sv` судила
  инициализатор **по виду узла**: `var v := 5 as u16;` отвергался, а
  `var v: u16 := 2 + 3;` принимался — разницу делала свёртка, приведения не
  берущая. ⚠️ **`ast_type_to_node_ctx` не разрешает `u8`…`i64`** — имя
  встроенного типа спрашивается у `builtin_type_by_name`, иначе ветвь молча не
  срабатывает ни на одном целочисленном типе.
- **Вычисленный инициализатор НОРМИРУЕТСЯ по типу объявления, литерал автора —
  нет** ([0207](docs/features/0207-bitwise-not-unsigned-literal.md), версия
  языка 0.9.0). Беззнаковое — обёртка `mod 2ⁿ` (правило 0127), знаковое —
  ошибка `SE-089`. Цена прежнего устройства: свёртка (0192) считала `~0` в
  `i128` и давала `-1`, проверка диапазона (0157) его отвергала — и `~0` был
  законен **в теле** (255 у эталона, `c`, `rust`) и запрещён в объявлении.
  ⚠️ После свёртки вычисленное значение **неотличимо** от написанного автором,
  поэтому разделяет их свёртка — существующим `is_literal` (он же защищает
  понижение `q`, 0096); `var u: u8 := 300;` остаётся ошибкой, а
  `var u: u8 := 200 + 100;` даёт `44`, как та же запись в теле. ⚠️ Границы —
  у **одного** носителя (`validate::literal_range::type_range`): своя копия
  разошлась бы с `SE-089`.
- **Инициализатор `var`/`const` доезжает до потребителей ЛИТЕРАЛОМ**
  ([0192](docs/features/0192-const-init-fold.md)). Свёртку делает существующий
  `semantic/const_eval/`: за границей семантики выражения не существует, и
  расходиться потребителям **не по чему**. Прежде `var a: u8 := 1 + 2;` означало
  **пять разных** вещей. Имя в инициализаторе значит **начальное значение** и
  ссылается только назад по тексту (решение заказчика). ⚠️ **Порядок трёх шагов
  обязателен**: разрешить → вывести типы → **свернуть**; свернув раньше вывода,
  получишь `bool` вместо `bit`. ⚠️ **Литерал не подменяется** (дробный уже
  понижен в q-представление), но **значение запоминается всегда** — иначе
  ссылка на соседнюю переменную молча даст `0`. ⚠️ Послабление «имя вычислимо»
  живёт в наполнении `const_eval::Locals`, а **не** в `resolve_name`: тот же
  вычислитель обслуживает `after`, параметры и порты, где «значение известно
  только в такте» — верное правило.
- **Операция константного вычисления живёт в ОДНОЙ таблице — `int_ops`**
  ([0208](docs/features/0208-const-evaluators-unification.md),
  [0407](docs/features/0407-const-power-fold.md)). Знак, которого в ней нет,
  свёртка не считает, и узел доезжает до потребителей неразвёрнутым: `const
  SPAN: u16 := 2 ** 8;` не давал `256` **никто** — эталон `0` молча,
  `c` — `CC-023`, `st` **теряла инициализатор молча** (`iec2c` файл принимает),
  `rust` — вывод, отвергаемый `rustc` (`E0689`), `sv` — `SV-002`.
  ⚠️ **Семантика операции берётся у того, кто её уже задал** (степень — 0328):
  своя ветвь со своим `pow` разошлась бы с эталоном и адресом. ⚠️ Показатель
  вне `u32` — `ExponentOutOfRange`, то есть запись остаётся **невычисленной**,
  а не получает новый отказ. ⚠️ Язык **адресов** знак не наследует: матчер
  `address_map/eval.rs` форму `Power` не разбирает — граница названа и
  проверена прогоном. ⚠️ Сторож класса — **тождественность** вывода выводу для
  готового литерала (приём 0143), а не сверка трасс на одном входе.
- **Обходы по числу состояний — итеративные, не рекурсивные**
  ([0052](docs/features/0052-verify-iterative-traversal.md)): рекурсия роняла
  инструмент `SIGABRT` без диагностики. Сторож — `deep_model_tests.rs` (2 МБ стека
  в потоке теста). ⚠️ `expand` в `buchi.rs` рекурсивен **осознанно**; `outer_dfs`
  делает работу **после** потомков — нарушение постпорядка даёт **неверный вердикт**.

### Типы и представление

- **Носитель числового значения — `i128`; граница приёма литерала — ТИПЫ языка**
  ([0157](docs/features/0157-literal-u64-representation.md)). `Token::Number` →
  АСД → `ExpressionNode`/`ConditionNode` → `eval::Value::Number` несут `i128`;
  приём — `[i64::MIN, u64::MAX]` (объединение диапазонов самого широкого
  знакового и самого широкого беззнакового типа), вне — `LE-009`. Границы и
  восстановление после отказа — `parser/literal_range.rs`. ⚠️ Носитель шире
  приёма **намеренно**: промежуточный результат константного вычисления не
  должен переполняться там, где итог по типу законен. ⚠️ Значение варианта
  перечисления — тот же `i128`: второй носитель числа завёл бы границу между
  ними. ⚠️ Обёртка `u64` работает через **общий** путь `coerce_integer` —
  спецслучая «bits >= 64» больше нет (он и давал `SIM-004` вместо обещанной
  0127 обёртки). ⚠️ Адрес порта остался `i64`: литерал шире сужается **явным**
  отказом `SE-055`, а не `as i64`.
- **Литерал вне диапазона типа приёмника — `SE-089`**
  ([0157](docs/features/0157-literal-u64-representation.md),
  `semantic/validate/literal_range.rs`). Проверяются позиции с **объявленным**
  типом (инициализатор `var`/`const`, присваивание переменной); проверка
  накопительная. ⚠️ `bit`/`bool` пропущены намеренно — их значения проверяет
  `validate_bit_values`, иначе две диагностики об одной причине. ⚠️ Проверяется
  **литерал**, не значение выражения: свёртки констант в семантике нет.
- **Печать широкого литерала зависит от цели**
  ([0157](docs/features/0157-literal-u64-representation.md)). `c` — суффикс
  `ULL` выше `LLONG_MAX` (`generator/c/c_literal.rs`), иначе
  `-Wimplicitly-unsigned-literal` под `-Werror`; `sv` — размерная форма
  `<W>'d<value>` по ширине **приёмника** (`sv_type::sized_literal`), иначе
  `WIDTHEXPAND` **уже с 33 бит**; `st`/`rust`/`plantuml` — как есть (доказано
  гейтами `iec2c` и `rustc -D warnings`). ⚠️ Особая форма печатается **только**
  по нужде — иначе поехали бы снапшоты `examples/generated/`. Сторож —
  `takt-lang/tests/targets/wide_literal_tests.rs` (эмиссия + настоящие гейты).
- **`[bit;N]` — упакованный вектор** ([0078](docs/features/0078-bit-array-semantics.md)):
  скаляр при N ≤ 64, массив `uint64_t[⌈N/64⌉]` при N > 64. Правило — в едином слое
  `semantic::bit_vector`.
- **Разряд за ОБЪЯВЛЕННОЙ шириной — `SE-125`**
  ([0394](docs/features/0394-bit-beyond-declared-width.md), решение
  заказчика). `w.100` при `[bit;96]` эталон, `c` и `rust` писали молча
  (значение занимает два слова, 0078), `verilator` вывод `sv` **отвергал**
  (`SELRANGE`) при нулевом коде возврата, `st` отказывала. Ширина — контракт;
  раскладка по словам деталь представления. ⚠️ Проверка живёт в **существующем**
  обходе доступа к члену (`member_access.rs`): доступ по имени и по номеру —
  один узел (урок 0203); стоит в **обеих** ветвях, выражений и условий (0359).
  ⚠️ **Границы «переменный индекс» не существует** — `w.idx` есть доступ к полю
  `idx`; пропускается выражение, **чей тип не выводится** (результат вызова), и
  там остаётся `SIM-011`.
- **`q(m, n)` В ПАРАМЕТРЕ функции опознаёт СЕМАНТИКА, а не грамматика**
  ([0380](docs/features/0380-fixed-point-parameter.md)). Тип параметра
  грамматика хранит **выражением**, и `q(8, 8)` приходит туда **вызовом** (`q`
  — обычный идентификатор, решение 0061): семантика такую форму не разбирала и
  отвечала **`SE-119`** — отказом о дефекте компилятора — у всех девяти
  потребителей. Правило `Type` в позицию параметра не подставить: оно даёт
  конфликт LR(1) с вызовом. ⚠️ Непохожая форма получает **`SE-034`** с
  названным ожиданием, а не воронку внутренних инвариантов. ⚠️ **Вторым слоем
  вскрылся дефект цели `st`:** Q-хелперы вставлялись перед первым
  `FUNCTION_BLOCK`, тогда как пользовательские `FUNCTION` печатаются **до**
  него, — вызов шёл раньше объявления (`iec2c`: «')' missing at the end of
  function invocation»), а комментарий кода обещал «перед первым POU» (класс
  0292). ⚠️ Границы: `q(m, n) sat` в параметре невыразим (`SY-002`), арифметику
  над параметром-`q` три цели не переводят — вынесено кандидатом.
- **Fixed-point `q(m, n)`: арифметика ПОБИТОВО едина** у симулятора и всех
  целей ([0061](docs/features/0061-fixed-point-type.md),
  [0061-01](docs/fixes/0061-01-q-wrap-storage-width.md)). Эталон —
  `takt-sim/src/eval/fixed.rs`; `*` — floor к −∞, `/` — к нулю. ⚠️ У `c` floor
  эмитится **не сдвигом**, а хелпером: `>>` знакового отрицательного в C
  implementation-defined; сторож — греп «в порождённом C нет `>>`». ⚠️ У `st`
  сдвигов над числами в IEC нет вовсе; у `rust` `x := x * y` над `q` **не**
  сворачивается в `x *= y`. ⚠️ **Перенос идёт к `W = m + n`, а НЕ к ширине
  хранения**: три цели выражали границу типом хранения и на `q(6, 6)` давали
  38.0 против −26.0 у эталона; дожило из-за дыры в **покрытии** (корпус состоит
  из `q(8, 8)` и `q(4, 4)`, где границы совпадают). Перенос эмитится **только
  при `W ≠ S`**, при `W ≥ 63` цель `st` отказывает `ST-021`.
- **Насыщение — свойство ТИПА: `q(m, n) sat` прижимает, `q(m, n)` переносит**
  ([0170](docs/features/0170-fixed-point-saturation.md)). Признак — поле
  `TypeNode::Fixed { …, sat }` и зеркальное `Value::Fixed`, то есть часть
  **формата**: смешение запрещает существующий `SE-059` (два места, обязанные
  давать один вердикт), явное `as q(m, n) sat` законно. Развилка одна на
  реализацию, хелпер эмитится по факту вызова. ⚠️ Слово после формата, отличное
  от `sat`, — **`SE-104`**: без отказа опечатка вернула бы молчаливый перенос.
  ⚠️ **Прижатие идёт до сужения** (у `sv` промежуток считается в `2W`): иначе
  сравнение с границами идёт по уже обёрнутому значению, и оба инструмента такой
  вывод принимают молча. ⚠️ Насыщение эмитится **всегда**, в отличие от
  переноса: границы формата типу хранения неизвестны. Сторожа — сверки на
  `q(6, 6)`, включая край `−(−2^(W−1))`; каждая проверена мутацией.
- **q-ЛИТЕРАЛ понижается в представление ВЕЗДЕ, где известен приёмник**
  ([0381](docs/features/0381-fixed-literal-in-body.md),
  [0382](docs/features/0382-fixed-literal-in-place.md)). Правило 0061 работало
  только в объявлении: `gain := 2.0;` цель `c` печатала значением **2** вместо
  512, а сравнение на ребре срабатывало там, где эталон перехода не делает —
  другой автомат при нулевом коде возврата. Позиции приёмника: присваивание,
  сравнение, аргумент, возврат, локальное объявление и условие ребра.
  ⚠️ **Приёмник — МЕСТО, а не имя**: поле структуры и элемент массива тоже; тип
  места даёт общий носитель `semantic::validate::base_type` (0358), своего
  разбора в проходе нет (сторож — греп-тест). ⚠️ **Путь условий ОДИН**: правило
  «условия рёбер не разрешаются» верно для **одной формы** — паттерна
  `S(Модель) = Состояние`; обход сырого АСД снят как не срабатывавший ни разу.
  ⚠️ **Арифметика в объём не входит** (`SE-059`), и проход стоит **после стадии
  6**: раньше приёмник неизвестен.
- **Прозрачный `float` через глобальную Q-точность**
  ([0096](docs/features/0096-fixed-point-native-float.md)): автор пишет `float`,
  представление выбирают флаги `--float-as-q=m.n` / `--float-embedded`. ⚠️ Это
  **осознанное исключение** из принципа «CLI не меняет логику автомата» (0042) —
  оба режима документированы и сверяются. ⚠️ **Главная засада:** `VariableNode`
  живёт в **двух** представлениях (owned в `model.variables` и за `Rc<RefCell>` в
  теле) — проход обязан мутировать **оба** `ty`, иначе объявление `q`, а арифметика
  `float`. Сторож — `variable_cell_in_body_is_retyped`. ⚠️ Литерал понижается
  **только** в инициализаторе объявления, не в телах; проход **идемпотентен** по
  гейту «исходный тип был `Rational`».
- **Именованное условие в ТЕЛЕ печатается тем же печатником, что на ребре**
  ([0331](docs/features/0331-named-condition-in-body.md)). Замер 2026-08-20:
  `if ready { … }` давал **пять** ответов — `SIM-014` у эталона **в такте**,
  `if (COND_…)` у цели `c` (идентификатор **нигде не определён**, файл не
  собирается при нулевом коде возврата), `ST-011`/`RS-011`/`SV-002` у прочих,
  приём у `plantuml`. ⚠️ Своего разбора условия не заводится ни у кого — второе
  знание разошлось бы с первым. ⚠️ У цели `rust` понадобилась **вторая**
  правка: `expression_type` не знал `Condition`, и приведение к `bool` отвечало
  «тип не выводится». ⚠️ Мёртвая `condition_macro_name` снята (урок 0278).
- **Присваивание АГРЕГАТА печатается поэлементно у `st` и `sv`**
  ([0330](docs/features/0330-aggregate-assignment.md)). `a := {1, 2};` в теле
  исполняли эталон, `c`, `rust` и `plantuml`, а `st`/`st-at` отвечали `ST-011`
  (текст обещал «часть 2 задачи 0041-04» — работу, которой нет),
  `sv`/`sv-mmio` — `SV-002`. ⚠️ **Агрегатная форма не годится:** в IEC её нет
  вовсе, а шаблон `'{…}` у `sv` работает лишь в ветви сброса (0309) — в
  `always_comb` его пришлось бы согласовывать по ширине. ⚠️ **Класс найден
  чтением ТЕКСТОВ отказов**, а не пробой наугад: два из них обещали задачи,
  которые давно закрыты. ⚠️ Сверка берёт **разные** значения по элементам и
  меняет их по тактам — иначе перестановка и потеря присваивания незаметны.
- **Операнды степени у цели `rust` печатаются С ОГЛЯДКОЙ НА ПРИЁМНИК**
  ([0415](docs/features/0415-rust-power-operands.md)). Замер 2026-08-23: из
  четырёх форм записи гейт цели проходила **одна** — `2 ** 8` давало `E0689`
  (метод на неоднозначном типе), `b ** 8` и `b ** n` при `n: u32` —
  `clippy::unnecessary_cast`, всё при нулевом коде возврата. База-литерал
  получает **суффикс** (`2u32`), приведение показателя печатается по нужде
  (классы 0263 и 0361). ⚠️ Тип доезжает **полем контекста**
  `Scope::power_target` (образец `return_type`, 0336): своего печатника
  арифметики нет — она идёт обёрткой `wrapping_add`, и второй разошёлся бы.
  ⚠️ **Разворот в умножения отвергнут семантикой:** `2 * 2 * 2` в debug
  паникует, `wrapping_pow` обёртывает. ⚠️ Отказ из предиката свёртки
  `x := x + 1` приходил **раньше** приёмника — печать операнда там есть вопрос,
  а не вывод. ⚠️ Корпус класс не покрывает: степеней в `examples/` нет.
- **Целую степень переводят ВСЕ восемь целей**
  ([0329](docs/features/0329-power-in-rust-sv.md)). `rust` печатает
  `wrapping_pow` — он даёт **ровно** семантику эталона, тогда как обычный `pow`
  **паникует** при переполнении в отладке; `sv` разворачивает степень в
  умножения при литеральном показателе. ⚠️ Текст прежнего отказа `rust`
  ссылался на `f64::powf` — вещественную степень, которой в этой позиции нет.
  ⚠️ Расширение цели **ломает чужие сторожа**: тест 0308 брал `**` как пример
  непереводимой конструкции и покраснел — это правильное поведение, он
  зафиксировал утверждение, переставшее быть верным.
- **Целая степень `**` считается ЦЕЛЫМИ**
  ([0328](docs/features/0328-integer-power.md)). Цель `c` печатала
  `pow((double)…)`, и на `3 ** 40` это давало **12157665459056928768** против
  **12157665459056928801** у эталона (53 разряда мантиссы `double`) — прогон
  харнесса, не рассуждение; цель `st` печатала оператор IEC, определённый над
  **вещественным**, и `iec2c` отвергал файл при нулевом коде возврата.
  ⚠️ У `c` — хелпер `takt_ipow` (умножение в `uint64_t`, обёртка по 0127),
  эмиссия **по факту вызова**, как у Q-хелперов; у `st` — разворот в умножения,
  переменный показатель отвергается. ⚠️ **Широкий тип в сверке обязателен:** на
  `u8` `double` точен. ⚠️ Класс всплыл при проверке **описания** кода `RS-011`
  — проба подтверждала утверждение об отказе `rust` и показала, что делают
  остальные. ⚠️ `rust` и `sv` степень по-прежнему не переводят (кандидат).
- **Сдвиг на ширину типа цель `rust` печатает НАСЫЩЕННЫМ**
  ([0326](docs/features/0326-rust-shift-width.md)). `self.a >> 8` для `i8`
  **не компилируется** (`rustc`: «attempt to shift right … would overflow») при
  нулевом коде возврата `taktc`, тогда как эталон и семь остальных потребителей
  дают −1 (знаковый) и 0 (беззнаковый). Печатается `>> (ширина − 1)` для
  знакового и `0` для беззнакового. ⚠️ **`wrapping_shr` не годится:** он
  маскирует величину (`8 % 8 = 0`) и даёт −8. ⚠️ **Переменная величина не
  трогается** — названная граница (кандидат). ⚠️ Гейт цели класс не видит:
  он гоняет корпус, а таких сдвигов там нет.
- **Приведение к ТОМУ ЖЕ типу не печатается, и «тот же» решает НАПЕЧАТАННЫЙ
  тип** ([0361](docs/features/0361-same-type-cast.md),
  [0374](docs/features/0374-mapped-type-cast.md)). `q := r as u16;` при `r: u16`
  — законная запись — печаталась буквально, и вывод цели `rust` **не собирался**
  под флагами её же гейта (`clippy::unnecessary_cast`) при нулевом коде
  возврата. ⚠️ **Правится у трёх целей, хотя отказ был у одной**: разное
  поведение на одной записи — то, из чего вырастают классы 0084/0193/0195.
  ⚠️ Признак — **именованное значение** (носитель 0359): у литерала и выражения
  тип печатнику неизвестен. ⚠️ Сравниваются **напечатанные** типы, и признак
  живёт у каждой цели свой — список «эквивалентных пар» разъехался бы с
  отображением. ⚠️ Ветвь `q(m, n)` стоит **раньше**: там приведение
  масштабирует. ⚠️ Контрпримеров два — расширение и **сужение**.
- **Значение печатается в типе ПРИЁМНИКА, и приводятся операнды**
  ([0360](docs/features/0360-mixed-sign-arithmetic.md)). `r := a + b;` при
  `a, b: u8` и `r: u16` — обычное накопление — не переводили три цели: `rust`
  отвечал `E0308`, `st` — отказом `iec2c`, `sv` — четырьмя `WIDTHEXPAND` (гейт
  считает предупреждение ошибкой), тогда как эталон и `c` (продвижение до
  `int`) считают верно. ⚠️ **Приводятся ОПЕРАНДЫ, а не результат:**
  `(a + b) as u16` считало бы в восьми битах и обёртывало **до** расширения —
  300 стало бы 44; компиляция обе формы принимает, разницу видит только сверка
  значений. ⚠️ **Класс про тип приёмника, а не про знаковость** — это показал
  контрольный вход `u8 + u8 → u16`, где знаки совпадают; правило покрывает и
  простое присваивание (`rr := r;`). ⚠️ Признак узкий: оба операнда —
  **именованные значения** целого типа; литерал не в счёт (у него типа нет,
  приведение литерала — `clippy::unnecessary_cast`), выражение тоже (его
  промежуточный тип печатнику неизвестен). ⚠️ Цель `c` не трогается — иначе
  изменился бы вывод всего корпуса.
- **Сравнение знакового с беззнаковым приводит операнды к общему типу**
  ([0359](docs/features/0359-mixed-sign-comparison.md)). На `s < u` (`i8`/`u8`)
  было **пять** ответов: эталон и `c` — истина, `rust` — `E0308`, `st` — отказ
  `iec2c`, `sv` — **ложь молча** (SV приводит смешанное сравнение к
  беззнаковому). Правило — носитель `generator/mixed_sign.rs`: `Widen` либо
  `SignGuard` (когда общего типа нет — `u64`). ⚠️ **У цели `c` дефект зависит от
  ШИРИНЫ**: на 8/16/32 операнды продвигаются до `int`, на 64 — нет
  (`-Wsign-compare`). ⚠️ **Тип берётся только у ИМЕНОВАННОГО значения**: у
  литерала знаковости нет, а `3 as i32` — `clippy::unnecessary_cast`.
  ⚠️ **Печатников у каждой цели ДВА** (условий и выражений) — правка одного
  чинит половину входов. ⚠️ Формы выбраны **пробой** инструментов, а сверка
  обязана менять ответ по ходу трассы: на постоянном ошибка неотличима.
- **Сдвиг вправо знакового — АРИФМЕТИЧЕСКИЙ (округление к −∞)**
  ([0324](docs/features/0324-arithmetic-shift-right.md)). ⚠️ Прежняя запись
  здесь утверждала, что операторов `<<`/`>>` в языке **нет**; проба 2026-08-20
  это **опровергла** — они разбираются, исполняются эталоном и переводятся
  всеми восемью целями (класс 0292 наоборот: проза отрицала то, что код
  делает). Семантика задана этой фичей. Замер: `-7 >> 1` давало **−4** у
  эталона, `c` и `rust`, но **124** у `st` (`SHR` над битовой строкой) и `sv`
  (`>>` там **логический даже над `logic signed`** — проверено прогоном
  verilator). ⚠️ Цель `sv` печатает `>>>`, цель `st` — floor-деление
  `SEL(a < 0, a / 2ⁿ, (a − (2ⁿ − 1)) / 2ⁿ)`: деление в IEC усекает **к нулю**,
  и на нечётном отрицательном это другое число. ⚠️ Величина сдвига у `st`
  обязана быть **литералом** (иначе `2ⁿ` считался бы `EXPT`, возвращающей
  вещественное). ⚠️ Сверка обязана брать **нечётное** значение: на чётном floor
  и усечение совпадают. ⚠️ Левый сдвиг у всех целей совпадает и не менялся.
- **Знак и ширина перечисления считаются общим слоем** `semantic::enum_facts`
  ([0060](docs/features/0060-enum-width-shared-layer.md)); цель `c` даёт
  `int{bits}_t` при `signed`. Прежде знак терялся молча.
- **У структуры обязано быть хотя бы одно поле — `SE-115`**
  ([0284](docs/features/0284-empty-struct-semantics.md)). Замер: `struct S { }`
  язык принимал, а вывод не принимали **чужие** инструменты — цель `c` печатала
  расширение GNU (C11 6.7.2.1; `cc -pedantic` даёт `-Wgnu-empty-struct`), а
  порождённый ST отвергал `iec2c` («no structure element declared»). Эталон при
  этом исполнял. ⚠️ **Гейт класс не видел по устройству**: он гоняет `cc`
  **без** `-pedantic`, а в корпусе пустых структур нет ни одной. ⚠️ Контроль
  обязателен и он же отделил причину: **непустая** структура проходит оба
  инструмента. ⚠️ Квантификатор грамматики (`Comma<StructField>`) оставлен
  намеренно — правило языка не должно быть свойством LR-разбора (урок 0172).
  ⚠️ Цели `rust` и `sv` в замер **не входят**: они не переводят структуры
  вовсе (`RS-014` на любой, висячая ссылка на необъявленный тип у `sv`) —
  соседний класс, вынесенный кандидатом.
- **У перечисления обязан быть хотя бы один вариант — `SE-105`, и судит
  СЕМАНТИКА** ([0172](docs/features/0172-empty-enum-semantics.md)). Прежде
  `enum E { }` отвергала **грамматика** (`CommaOne<EnumVariant>`), то есть
  правило языка было свойством квантификатора, а текст — внутренностью
  LR-разбора; смена квантификатора изменила бы язык молча. ⚠️ Отказ стоит на
  **объявлении**: при использовании сообщение вырождалось в `SE-043`
  «…(допустимые варианты: )» — про пустой список не говорилось ничего.
  ⚠️ `None`-ветви `enum_facts` у четырёх целей **сохранены** (`c`/`st`/`rust` →
  8 бит без знака, `sv` → `SV-004`): изменилась причина их недостижимости.
  ⚠️ Мутация опровергла комментарий «проверка стоит раньше соседней намеренно» —
  порядок сообщений задаёт `diagnostics::normalize` по позиции в тексте, а не
  порядок проверок в `validate_model_all`.
- **Структуры переводят ВСЕ цели, и форма агрегата у каждой своя**
  ([0293](docs/features/0293-struct-in-st-rust.md)). `c` — `struct`, `st` —
  `TYPE … STRUCT` с инициализатором `(поле := значение, …)`, `sv` — `typedef
  struct packed` с конкатенацией, `rust` — литерал структуры. Прежде три цели не
  шли дальше объявления: `st` **молча теряла** инициализатор (и `iec2c` это
  принимал), `sv` ссылалась на необъявленный тип, `rust` отказывал.
  ⚠️ **Именованную форму агрегата SV отвергает yosys**, тогда как verilator её
  принимает — форма выбирается по тому, что принимают **оба**; безразмерные
  литералы внутри `{…}` дают `WIDTHCONCAT`. ⚠️ **`Eq` не выводится**: у поля
  `float` его нет, и корпус перестал бы компилироваться. ⚠️ **Запись в поле
  делает переменную изменяемой** (`let mut`), иначе `E0594`. ⚠️ Порядок полей
  значим: он берётся у **объявления**, а не у карты.
- **СРЕЗ массива печатается поэлементно, и пригодность операндов решает
  носитель** ([0355](docs/features/0355-array-slice-in-targets.md)). Правило —
  `semantic/slice/`: `bounds` (полуинтервал `[l, r)`, пропущенная граница —
  край) и `elementwise_len` (пригоден ли тип). Прежде эталон срез исполнял, а
  **семь** целей отказывали: у языка была конструкция, существовавшая только в
  прогоне. Форма одна на четыре цели, потому что другой нет (массив в C не
  присваивается, в IEC нечем, в SV `{…}` — склейка разрядов, в Rust срез не
  `Sized`). ⚠️ **Границы — литералы**, поэтому длина известна при компиляции;
  выход за край отвергает `SE-029` — второй проверки в генераторе быть не
  должно. ⚠️ **Пригодны ОБА операнда** — срез бит-вектора и срез в скалярный
  приёмник давали невалидный вывод; **поймали это ЧУЖИЕ тесты**. ⚠️ Непригодный
  вход отдаётся прежнему пути: координату отказу даёт `site::at`, свой отказ
  пришёл бы с позицией объявления (класс 0264).
- **Срез в АРГУМЕНТЕ вызова разворачивается в семантике**
  ([0400](docs/features/0400-slice-in-call-argument.md)). `first(src[1:3])`
  эталон исполнял, а **ни одна цель не переводила**; теперь проход
  `semantic/slice/argument.rs` заводит перед оператором `var takt_slice_N: [T;
  L];` и присваивание — печатники целей о форме не знают. ⚠️ **Форма выбрана
  замером:** объявление **с инициализатором** (как предлагала ADR) не
  переводит никто, а присваивание переводят все (0355). ⚠️ **Имя обязано быть
  идентификатором ЦЕЛЕВЫХ языков и проверяться на занятость** — редакция с `#`
  дала «expected identifier» у `cc`. ⚠️ Носитель границ переехал в
  `semantic/slice/`: свойство языка, и звать его должна семантика.
  ⚠️ Разворот открыл три самостоятельных дефекта (0409, 0410, 0411) — все
  нашлись прогоном инструментов целей.
- **ВЛОЖЕННЫЙ агрегат раскрывается ДО ЛИСТЬЕВ одним носителем, а форму
  адресации собирает ЦЕЛЬ** ([0366](docs/features/0366-nested-aggregate-carrier.md)).
  `aggregate::places` отвечал на «один уровень», и рекурсию писала каждая цель —
  написали **две из четырёх**, а `st` и `sv` отвергали вход, который исполняют
  эталон, `rust` и `c`. Теперь раскрытие — общий `aggregate::leaves`, отдающий
  **путь шагами** (`Index`/`Field`), а форму печатает цель. ⚠️ **Готовую строку
  носитель вернуть не может** — формы адресации у целей разные; поиск полей
  принимается **замыканием** (объявления цели хранят по-разному).
  ⚠️ **У цели `sv` поле структуры внутри массива ОТВЕРГАЕТСЯ** (`SV-002` с
  причиной): yosys принимает шаблон только для массива целиком, а частичную
  запись объявляет защёлкой — печатать её значило бы заменить громкий отказ
  молчаливым несинтезом. ⚠️ Бит-вектор `[bit;N≤64]` — **лист**, не агрегат.
- **Присваивание АГРЕГАТА печатается поэлементно, и место записи выбирает один
  носитель** ([0330](docs/features/0330-aggregate-assignment.md),
  [0340](docs/features/0340-aggregate-assign-place.md)). Правило —
  `generator/aggregate.rs`: массив по индексу, структура по **имени поля**, в
  порядке **объявления**. Носитель принимает **поля**, а не модель (`sv` держит
  снимок карты). ⚠️ Прежде `body := {3, 4};` не переводила ни одна цель, кроме
  `rust`: `c` печатала форму, которой в C нет, `st` и `sv` адресовали структуру
  **как массив** — всё при нулевом коде возврата. ⚠️ **Массив в C не
  присваивается** даже составным литералом, и разворот живёт в печатнике
  **операторов**. ⚠️ Комментарий 0330 утверждал о чужом коде неверно —
  утверждение проверяется прогоном, а не чтением (класс 0292).
  ⚠️ **Позиций агрегата ЧЕТЫРЕ**: присваивание, инициализация переменной,
  элемент массива структур (0343), локальное объявление (0345); ветвь, не
  позвавшая носитель, давала отказ на записи с верным поведением.
- **Константа-АГРЕГАТ печатается тем же путём, что переменная**
  ([0347](docs/features/0347-const-aggregate.md)). `const BASE: Cell := {3,
  4};` цель `rust` печатала `[3, 4]` в поле типа `Cell` (`E0308`), цель `sv` —

  `rust` и `reset_value` у `sv` — те же носители, что у переменных. ⚠️ **У цели
  `sv` дефектов было два:** правка обнажила второй — типы печатались **после**

  инициализатора (0343) и локального объявления (0345).
- **Умолчание значения у цели `rust` строит ОДИН носитель, а `derive(Default)`

- **Структуры печатаются в порядке ЗАВИСИМОСТЕЙ, и это один носитель**

  `st` и `sv`. Прежде порядок был **алфавитным** (`structs` — `BTreeMap`), и

  specification in structure element declaration» у `iec2c` и «Reference to
  'point_t' before declaration» у verilator — при **нулевом** коде возврата
  `taktc`. ⚠️ **Алфавитная сортировка на ВЫХОДЕ у `st` снята**: она разрушала
  собранный порядок; детерминированность держит обход по `BTreeMap` (0048).
  ⚠️ **Цикл структур носитель переживает, но не диагностирует** — это вопрос
  семантики (кандидат). ⚠️ У цели `rust` тем же входом ломалось другое:
  `expression_type` считал **любой** доступ через точку логическим, и

  транслируются»), хотя цель переводит их с 0293 — класс 0191.
- **Структурные типы**: объявленный **порядок полей значим** (не `BTreeMap`),

  Доступ к члену — общий `eval/access.rs::read_member`, запись — `eval/place.rs::update`
  (лист приводится к **типу поля**). Сравнение структур — `TypeMismatch`: C
  запрещает `==`, и симулятор «умнее» эталона врал бы. Доступ к несуществующему
  полю — компайл-тайм `SE-061`.
- **Массивы `[T;N]` исполняются симулятором** ([0076](docs/features/0076-sim-arrays.md)):
  запись элемента и запись поля структуры — **единый** сегментный механизм «места».
  Границы/вид → `SIM-010`.
- **Константная выдержка `after` вычисляется на СЕМАНТИКЕ и до целей не доезжает**
  ([0143](docs/features/0143-after-const-duration.md)). `after 3m`, `after DWELL`,
  `after (BASE + 30s)` дают один узел `ConditionNode::After(нс)` — за этой границей
  формы не существует, поэтому шесть целей не могут по ней разойтись. Вычислитель
  — `semantic/condition/after_const.rs` (литералы, константы `duration`, цепочки,
  `+`/`-`, предел глубины 32); всё прочее → `SE-072` с **названной** причиной.
  ⚠️ Аргумент живёт в грамматике **условий**: `*`, `/` и `as` там отсутствуют, а
  составное выражение обязано быть в скобках (`after` связывает крепче арифметики,
  поэтому `after A + 1s` = `(after A) + 1s`) — скобки хранятся в дереве, иначе
  печать форматтера изменила бы смысл. Сторож — не «собралось», а
  **тождественность вывода** литеральной форме во всех целях
  (`takt-lang/tests/semantic/after_const_duration_tests.rs`).
- **Тип `duration` в целях — целое в МИЛЛИСЕКУНДАХ; выдержка бывает вычисляемой**
  ([0183](docs/features/0183-duration-type-in-targets.md),
  [0215](docs/features/0215-duration-per-tick-conformance-st-sv.md)).
  `uint32_t` / `u32` / `UDINT` / `logic [31:0]`; единица та же, что у приведения
  `as`, поэтому граница «длительность ↔ число» **не порождает арифметики** —
  сторож проверяет это **текстом**. Пересчёт — только
  `semantic::duration::value_millis`. ⚠️ Тип `TIME` у `st` не выбран: арифметика
  над ним в MatIEC ограничена. ⚠️ **Вычисляемая выдержка** требует множителя
  `hertz / 1000` («такты»; нецелый — `SE-073`), у `st` в профиле «часы» —
  `ST-016`. ⚠️ **Ширина счётчика поднимается до 32 бит**, иначе `rust` не
  компилируется, а `c`/`sv` молча усекают. ⚠️ Четыре обхода по `ConditionNode`
  кончаются `_ =>` и компилятором **не** охраняются (в `unused.rs` таких
  сборщиков два) — пропуск даёт ложное «не используется» либо `RS-011`.
### Цели генерации

- **САМОПЕРЕХОД не сбрасывает отсчёт времени в состоянии**
  ([0393](docs/features/0393-every-on-self-transition.md), решение заказчика).
  Признак входа один у эталона и целей — **смена состояния** (`state !=
  prev_state` в порождённом C). Прежде эталон сбрасывал при любом сработавшем
  переходе, и один вход давал **другой автомат**: тело `every 3ms` не
  срабатывало никогда, а `ref Done: after 3ms;` не уводил в `Done`, тогда как
  цель `c` уходила на 4-м такте. ⚠️ **Класс охватывал ОБА** — `every` и
  `after`: они завязаны на одно «время с входа», и правка одна.
  ⚠️ `enter`/`exit` при самопереходе **исполняются** — «вход» для них и для
  отсчёта понимается по-разному; названо словами в `book/src/12-time/`.
  ⚠️ Сторож — сверка, наблюдающая оба следствия сразу; время в ней ведёт
  прогон (`set_time_ns`), как в 0134-09.
- **Вход в стартовое состояние не расходует такт** `[критический инвариант 5]`
  ([0033](docs/features/0033-init-tick-alignment.md), версия языка 0.3.0). Тело
  стартового состояния исполняется на **такте 1** на любой глубине. **Контракт для
  будущих бэкендов:** не воспроизводить чужие `INIT`-такты. Сверка —
  `conformance_c_tests::per_tick_trace_*`.
- **Model-level `always` исполняется каждый такт** до диспетчеризации состояния `[критический инвариант 6]`
  ([0083](docs/features/0083-model-always-block-c.md),
  [0194](docs/features/0194-sim-composition-model-always.md)) — в эталоне и во
  всех целях, **включая модель, чьё состояние есть композиция**. Прежде молча
  терялось везде, а у композиции — только в эталоне. ⚠️ Механизм исполнения был
  **на месте**: не наполнялось **поле** `executions`, оттого дефект пережил 0083
  и фикс 0181-01. Компиляция блоков — одна на обоих строителей, контекст
  владельца строится **один раз** (две ячейки = молча неработающая починка).
  ⚠️ Сторожа обязаны стоять на **накапливающем** теле (`n := n + 1`): на
  идемпотентном пропуск и двойное исполнение неразличимы. ⚠️ Model-level
  `enter`/`exit` **не** реализованы, `every` уровня модели грамматикой не
  принимается вовсе.
- **Генератор C: вывод компилируется, отображение типов доверено**
  ([0026](docs/features/0026-c-root-typedef.md),
  [0029](docs/features/0029-c-type-mapping.md)). `map_c_type`: `Bit` →
  `uint8_t`, `Rational` → `double`/`float`, `[bit;N]` — через `bit_vector`,
  прочие массивы → `CC-014`/`CC-015`. `conformance_c_tests` — **основной
  потактовый эталон** проекта. ⚠️ Неиспользуемая переменная в структуру не
  попадает (штатный фильтр). ⚠️ **Оба гейта идут под `-Wall -Wextra
  -Wno-unused-parameter -Werror`** (0171, 0220) и **в двух режимах** — отладка и
  `-DNDEBUG` (0312): прошивки собирают релизом, и `assert` там исчезает, поэтому
  харнессы **запускаются**, а не только собираются. ⚠️ Исключён ровно один класс
  предупреждений, и он назван; снять исключение — убрать флаг в **двух** местах.
  ⚠️ Флаги живут **в гейте**, не в `CMakeLists` примера: `-Werror` навязал бы
  строгость всякому, кто скопирует вывод.
- **ВЛОЖЕННЫЙ массив у цели `c`: объявитель, инициализация и присваивание —
  одно правило** ([0364](docs/features/0364-c-nested-array.md)). Тип массива в C
  неотделим от имени, поэтому массив печатает только объявитель, а он звал
  `map_c_type` для элемента — и на `[[u8; 2]; 2]` получал `CC-015`, хотя
  `uint8_t grid[2][2]` выразим. ⚠️ **Отказ был закреплён юнит-тестом** (класс
  0191): починка начинается со снятия утверждения. ⚠️ **Дефектов три, и каждый
  прятался за предыдущим**: снятие отказа открыло форму, которой в C нет, в
  инициализации, а её починка — ту же форму в присваивании **в теле**; печатники
  разные (урок 0359). ⚠️ Спуск по размерностям останавливается на `[bit;N≤64]`.
  ⚠️ **Фикстура сверки обязана иметь СТОРОНЫ РАЗНОЙ ДЛИНЫ и обе позиции
  записи**: на квадрате 2 × 2 две мутации из трёх не роняли её.
- **Переменная БЕЗ инициализатора получает ноль и у цели `c`**
  ([0353](docs/features/0353-c-default-init.md)). `<Root>_init` ставил только
  поле `state`, и переменная читалась как **мусор стека** — UB в прошивке при
  нулевом коде возврата и молчащем `cc -Werror`, тогда как эталон и остальные
  цели дают ноль. Раскладка — `c_zero_init.rs`, и она зависит от типа, потому
  что в C **не всё присваивается**: скаляр присваиванием, массив по элементам,
  бит-вектор `N > 64` — **по словам** (проверка стоит РАНЬШЕ массива, иначе
  `[bit;128]` дал бы 128 присваиваний по несуществующим индексам), структура по
  полям. ⚠️ **`memset` не годится**: `_init` служит и сбросом, а указатели HAL
  привязываются до него. ⚠️ **Неиспользуемую переменную обнулять нельзя** —
  штатный фильтр выбрасывает её из структуры. ⚠️ Класс невидим инструментам и
  корпусу: мутация упала **только** на потактовой сверке.
- **Указатель на состояние печатается ПО НУЖДЕ, а гейты идут БЕЗ исключений**
  ([0260](docs/features/0260-c-unused-struct-parameter.md),
  [0396](docs/features/0396-c-struct-parameter-on-demand.md)). Протокол вызова
  цели `c` единообразен (`main`, `model`, `m`), и класс был отключён флагом
  `-Wno-unused-parameter` — то есть не сторожил ничего; 0260 завела заглушку
  `(void)параметр;`, 0396 — снятие самого параметра. ⚠️ **Признак общий с целью
  `rust`** (`c_needs` спрашивает `rust_needs::function_needs`): своё знание
  разошлось бы. ⚠️ **Пустой список печатается `void`** — `f()` в C значит
  «список неизвестен», и `-Wstrict-prototypes` это отвергает. ⚠️ **Порт требует
  `main` ВСЕГДА**, даже свой: колбэки HAL живут у корня (пропуск поймал чужой
  сторож 0184). ⚠️ Признак считается на **модель**, не на функцию — 30 заглушек
  осталось, вынесено кандидатом. ⚠️ `assert` использованием не считается: под
  `-DNDEBUG` он исчезает.
- **`SE-036` видит и ЛОКАЛЬНЫЕ объявления тел, а у объявления есть позиция**
  ([0386](docs/features/0386-unused-local-warning.md),
  [0387](docs/features/0387-write-only-local.md)). Проверка спускается по телам
  (блоки модели и состояний, тела функций, вложенные блоки); признак —
  `semantic::unused::unused_locals_of_block`, `generator::local_stub` стал его
  обёрткой. ⚠️ **Позиция — часть предмета**: `StatementNode::Variable` получил
  поле `Location`, иначе координатой было бы `1:1` — ложь вместо отсутствия
  (класс 0264). ⚠️ **Признак спрашивает ЧТЕНИЯ, а не упоминания**: запись без
  чтения — мёртвая переменная, и вывод **пяти** целей отвергали их же
  инструменты. Режим задан флагом `UsageSet::reads_only`, а не вторым обходом;
  фильтры печати целей его не включают — там вопрос «нужно ли имя в выводе».
  ⚠️ У `sv` сужение меняет ошибку на `ALWCOMBORDER`: поглотитель печатается
  **после** тела.
- **Неиспользуемая ЛОКАЛЬНАЯ переменная тела гасится заглушкой у `c` и `rust`**
  ([0376](docs/features/0376-unused-local-stub.md)). Замер 2026-08-21:
  `var spare: u8 := n + 5;` без обращений даёт `cc -Werror`
  «unused variable» и `rustc -D warnings` «unused variable», тогда как эталон
  исполняет, а `st` и `sv` переводят; `taktc` возвращает **ноль**. Идиома
  принадлежит цели (`(void)x;`, `let _ = x;`), а признак общий —
  `generator::local_stub::unused_locals`. ⚠️ **Вопрос задаётся ДЕРЕВУ, а не
  напечатанному тексту** (в отличие от 0260/0337): объявление печатается
  **до** своего блока, спрашивать нечего; сборщик имён общий с целью `st`
  (`usage_from_stmt`). ⚠️ Спрашивается **блок объявления**: область видимости
  локальной — он, и это ровно ответ компилятора. ⚠️ Заглушка печатается в
  **конце блока** — там переменная ещё видима. ⚠️ Граница: «записана, но не
  прочитана» признак считает использованием. ⚠️ Смежно: `SE-036` локальных
  объявлений не видит вовсе — вынесено кандидатом.
- **Неиспользуемый параметр функции гасится ЗАГЛУШКОЙ у трёх целей**
  ([0260](docs/features/0260-c-unused-struct-parameter.md),
  [0337](docs/features/0337-unused-function-parameter.md)). Признак один —
  «упоминается ли параметр в **напечатанном** тексте тела» (границы
  идентификатора обязательны: `value` содержит `v`), идиома принадлежит целевому
  языку: `(void)v;`, `let _ = v;`, редукция у `sv`. ⚠️ Прежде объявленный
  автором параметр не гасил никто, и функция, не пользующаяся им, давала отказ
  **чужого** инструмента при нулевом коде возврата. ⚠️ **Имя параметра в
  сигнатуре не менять**: форма `_v` предупреждение гасит, но сигнатуру читает
  человек. ⚠️ **`lint_off` запрещён** (0169): в форме `sv` параметр честно
  используется, а константа в редукции даёт ноль — синтезатор выбрасывает логику
  сам. ⚠️ Корпус класс не покрывает.
- **Неразрешённый узел в цели `c` — отказ `CC-023` с позицией, а не пустота**
  ([0236](docs/features/0236-c-unresolved-condition-refusal.md)). Условие,
  выражение и оператор зовут **одну** воронку `c_unresolved::refuse(loc, вид)`
  (образец `FM-001`). Прежде условие печаталось пустой строкой, оператор
  исчезал, а **ребро с неразрешённым условием считалось безусловным** — валидный
  C, другой автомат. ⚠️ **Не всякий `Unresolved` — дефект**: правая часть
  `S(Модель) = Состояние` приходит неразрешённой по инварианту и разбирается
  **до** воронки; проход «в дереве не бывает `Unresolved`» отвергнут — он завёл
  бы второе знание о форме паттерна (класс 0203). ⚠️ Отказ **недостижим** из
  корректной программы: вход отсекает семантика, то есть недостижимость держит
  другая фича. Сторож — перечисление видов узла, падает **списком**.
- **Что считать БЕЗУСЛОВНЫМ ребром, решает ОДИН предикат** —
  `ConditionNode::is_unconditional()`
  ([0291](docs/features/0291-rust-sv-unresolved-condition.md)). Прежде решение
  принимали **восемь** потребителей порознь, и они разошлись: `rust` и `sv`
  считали безусловным ещё и `Unresolved` — условное ребро срабатывало всегда,
  вывод валиден, автомат другой. ⚠️ **Неразрешённое условие значит «имя не
  найдено», а не «условия нет»**, и такой вход отсекает `SE-025` до генерации:
  подмена автомата сегодня **недостижима**, а недостижимость держит **другая**
  фича — ровно поэтому ветвь и снята, ловушка дешевле правила. ⚠️ Паттерн
  `S(Модель) = Состояние` под предикат **не подпадает**. ⚠️ Сторож грепает
  **оба** крейта и падает списком; на первом прогоне нашёл **три** места сверх
  известных двух. Границу он называет сам: обход не через `matches!` ему
  невидим.
- **Безусловное ребро ЗАВЕРШАЕТ цепочку — одинаково у всех четырёх целей**
  ([0213](docs/features/0213-c-redundant-break.md)). После `ref T;` без условия
  печать рёбер прекращается: дальше недостижимо, и своего `break;` у такого
  ребра в цели `c` нет. Прежде отставала одна цель — `c` печатала и `break;`
  (пара `break; break;`, 7 мест корпуса), и хвост рёбер. ⚠️ Инструменты класс
  **не видят**: `-Wunreachable-code` молчит и о прежнем выводе, и о
  половинчатой правке. Сторожа двое: греп по порождённому C всего корпуса и
  **потактовая** сверка — половинчатая правка даёт `[1, 9, 9, 9]` против
  `[1, 0, 0, 0]` и компилируется без замечаний. ⚠️ Условное ребро не трогать:
  его `break;` выходит из `switch` изнутри блока `if`. ⚠️ Записи «ребро после
  безусловного» в корпусе нет — класс держат фикстуры.
- **Отказ цели `c` НЕСЁТ КОД, и воронок две: `CC-022` и `CC-023`**
  ([0212](docs/features/0212-c-diagnostic-without-code.md)). `CC-022` —
  «конструкция в языке есть, цель её не умеет», `CC-023` — «узел не прошёл
  понижение» (дефект инструмента). Прежде **девятнадцать** мест строили отказ
  строкой: код печатался `[?]`, текст нёс имя варианта Rust (класс 0231), а
  позиция — «начало первого файла». ⚠️ **Гейт кодов класс не видит по
  устройству**: он сверяет коды с реестром, а диагностику **без** кода искать
  нечем — сторож греп-тест, падающий списком. ⚠️ **Позиция выражения — одно
  знание** (`ExpressionNode::loc()` в `semantic/`). ⚠️ **Путь файла ставит ТИП,
  а не вызов**: `parse_and_construct` отдаёт `pipeline::Compilation`, штампует
  её метод `emit` — иначе координата теряется на печати (класс 0228). Имя
  входного файла подставлять нельзя: смещения принадлежат своему файлу.
- **Генератор ST: вывод принимается `iec2c`, гейт зелён** (8/8 корпуса,
  [0041](docs/features/0041-st-backend.md), [0090](docs/features/0090-ci-precheck.md)).
  Факты MatIEC, снятые пробами (нарушишь — вывод перестанет компилироваться):
  массивы **не вкладываются**; перечислимый тип с явными значениями отвергается →
  целый тип + `VAR CONSTANT`; `VAR_GLOBAL` вне `CONFIGURATION` недопустим; массиву
  нельзя дать скалярный инициализатор; **порядок секций в `FUNCTION` значим** —
  локальный `VAR` печатается **до** `VAR CONSTANT` (сторож
  `test_function_var_precedes_var_constant`); идентификаторы IEC
  **регистронезависимы** и делят пространство со стандартной библиотекой —
  `left`/`right`/`mid`/`limit`/`step` отвергаются, диагностика при этом обманчива.
- **Цель `st`: вход в стартовое состояние печатается `IF state = 0` ПЕРЕД
  `CASE`** ([0191](docs/features/0191-st-per-tick-conformance.md)). Ветвью
  `CASE` его выразить нельзя: `CASE` в IEC **не проваливается**, поэтому
  `0: (* INIT *) state := 1;` заканчивал скан, ничего не исполнив, — по
  холостому скану на каждый уровень вложенности (замер трассы: `0 0 8 8 8 …`
  против `8 …` у эталона и цели `c`). Сторож — **потактовая** сверка
  `takt-sim/tests/conformance/conformance_st_per_tick_tests.rs`, а не факт компиляции:
  `iec2c` принимал и сдвинутый вывод. ⚠️ Дефект дожил потому, что был **закреплён
  тестами**: сверки шли «с поправкой на INIT-сдвиг»; поправки сняты.
  ⚠️ Инициализатор `[bit;N≤64]` глушить **нельзя** — это упакованный скаляр
  ([0078](docs/features/0078-bit-array-semantics.md)), а не массив; признак
  берётся из `semantic::bit_vector`, тем же слоем, что и печать типа.
- **Инициализатор массива у цели `st`: скаляры — формой `[…]`, структуры —
  первым сканом** ([0343](docs/features/0343-array-initializer.md)). Прежде он
  терялся **молча** для любого массива, и расходились **значения**: прогон
  порождённого ST дал `o = 0` против `3` у эталона при нулевом коде возврата
  `taktc`. Форма `ARRAY [0..1] OF USINT := [1, 2]` выбрана **пробой** `iec2c`;
  массив структур та же проба отвергла в **трёх** видах, поэтому его значения
  кладутся операторами первого скана (`st_model::emit_deferred_inits`) — до
  входа в стартовое состояние. ⚠️ **Агрегат массива в аргументе ПАРАМЕТРА
  остаётся `ST-017`**: в объявлении переменной форма законна, а в
  инициализаторе экземпляра `FUNCTION_BLOCK` `iec2c` её не принимает —
  первая редакция правки сняла отказ и породила невалидный файл, поймал это
  тест-граница фичи 0209. ⚠️ Тем же входом `c` печатала `model->cells[0] = {1,
  2};` (формы нет в C), а `rust` — `[[1, 2], …]` вместо литералов структуры.
- **Массив в параметре ST объявляется ИМЕНОВАННЫМ типом; индекс — выражение**
  ([0210](docs/features/0210-st-array-shared-and-index.md)). MatIEC не принимает
  анонимный `ARRAY […] OF T` в `VAR_IN_OUT` («Data type incompatibility … when
  invoking FB»), и цель порождала невалидный ST при рапорте об успехе (класс
  0184). ⚠️ Именованным обязано быть **и параметр, и переменная владельца**:
  половинчатая правка даёт ту же ошибку — сторож проверяет **счёт** объявлений.
  ⚠️ Имя строит одна функция `st_type::shared_array_type_name`, квалифицированная
  корнем (пространство имён IEC регистронезависимо). ⚠️ `[bit; N ≤ 64]` —
  упакованный **скаляр** (0078), ему именованный тип не нужен.
  ⚠️ **Индекс массива — произвольное выражение** (правка только грамматики:
  печатники целей, симулятор, форматтер и `semantic/usages` уже рекурсивны), а
  переменная-индекс **считается использованной** — сборщиков в `unused.rs`
  четыре, и все игнорировали индекс. Цена прежнего умолчания: цель `rust`
  печатала `self.i` для переменной, не попавшей в общую структуру, — невалидный
  Rust (`E0609`), закреплённый текстовым тестом печатника (класс 0191).
- **МНОГОМЕРНЫЙ массив у цели `st`: объявление, индексация и инициализатор —
  одно правило** ([0363](docs/features/0363-st-multidim-subscript.md)). В IEC
  массивы не вкладываются, `[[u8; 2]; 2]` печатается `ARRAY [0..1, 0..1] OF
  USINT` — и **всё остальное обязано следовать объявлению**. Дефектов на одном
  входе было три: индексация формой C, вложенный инициализатор (`iec2c`
  **принимает** и молча теряет вторую строку) и уплощение **сквозь** упакованный
  `[bit;N≤64]`. ⚠️ **Второй дефект видит только потактовая сверка**: вывод
  валиден, значения другие — фикстура обязана держать по индексам **разные**
  значения и менять их по тактам. ⚠️ Формы выбраны **прогоном** `iec2c` + `cc`,
  а не чтением стандарта. ⚠️ Печатников индексации **два** (выражения и
  условия) — правка одного чинит половину входов. ⚠️ Цепочка обрывается на
  чужом узле: `ps[1].x[0]` — два разных массива.
- **Массив в параметре `FUNCTION` — ИМЕНОВАННАЯ форма через `VAR_IN_OUT`, и у
  переменной ТОЖЕ** ([0348](docs/features/0348-st-array-parameter.md),
  [0409](docs/features/0409-st-local-array-argument.md)). Имя строится по
  **форме** (`TAKT_ARR_2_USINT`), а не по владельцу, как в 0210: функция
  вызывается с разными массивами, и типы аргумента с параметром обязаны
  совпадать буквально. ⚠️ **Форму выбрал полный цикл `iec2c` → `cc`**:
  `VAR_INPUT` с массивом инструмент **разбирает**, но порождает C, который не
  компилируется, — форма, принятая разбором, не годна, пока не собран её
  вывод. ⚠️ **Порядок аргументов следует СЕКЦИЯМ**: параметры-массивы объявлены
  в `VAR_IN_OUT`, и позиционный вызов IEC идёт по порядку объявления.
  ⚠️ **Локальные объявления тел подчиняются тому же правилу** (0409) — обе
  точки печати зовут `st_type::local_declaration_type`; прежде переменная
  модели ему подчинялась, локальная нет, и `iec2c` отвергал вывод при нулевом
  коде возврата. ⚠️ Именуются **только** формы из параметров: иначе правка
  задела бы каждый массив вывода.
- **Внутри `FUNCTION` цели `st` видно только объявленное в ней самой**
  ([0030](docs/features/0030-comprehensive-example-fix.md),
  [0338](docs/features/0338-enum-in-function.md)). IEC 61131-3 делает функцию
  замкнутой единицей, поэтому туда **дублируются** и константы модели (0030), и
  константы перечислений (0338) — иначе `iec2c` отвечает «Ambiguous enumerate
  value or Variable not declared in this scope» при **нулевом** коде возврата
  `taktc`. ⚠️ Дублируются **упомянутые телом**, а не все, и отбор идёт по
  **тексту** напечатанного тела: имя константы строит печатник
  (`st_expr::coerce_to`), и второй способ его узнать разошёлся бы с первым
  (класс 0084/0193/0195). ⚠️ Тем же входом цель `sv` печатала `res = 0;` для
  переменной перечислимого типа — verilator отвечает **ошибкой** `ENUMVALUE`;
  корень общий: **вариант приходит печатнику числом**, узла варианта у
  `ExpressionNode` нет вовсе. ⚠️ Кандидат, из которого выросла 0338, был
  **ошибочен** (приписывал отказ перечислению в параметре, а срабатывал
  досрочный возврат `SV-002`) — посторонняя причина не была снята, правило 30.
- **Имя переменной не может совпасть с именем ТИПА: `ST-023`**
  ([0378](docs/features/0378-st-name-type-clash.md)). Идентификаторы IEC
  регистронезависимы и делят пространство, поэтому `var pair: Pair;` для MatIEC
  — два объявления одного имени; шесть потребителей вход исполняют, `iec2c`
  отвергает, `taktc` возвращает **ноль**, а ответ инструмента **обманчив** (он
  указывает на `AT %…`, которых нет). ⚠️ **Отказ, а не переименование за
  автора**: переименование потребовало бы одного носителя имени для объявления
  и всех обращений. ⚠️ **Заняты имена, которые цель ПЕЧАТАЕТ** — только
  структуры (фикс 0378-01): первая редакция отвергала вход, который `iec2c`
  принимает, а ложный отказ хуже пропуска. ⚠️ Проверка стоит **после** фильтра
  использования: неиспользуемую переменную цель не эмитит.
- **Список зарезервированных имён IEC ПРОВЕРЯЕТСЯ ПРОГОНОМ `iec2c`**
  ([0342](docs/features/0342-st-reserved-names.md)). Он собирался чтением
  стандарта и отстал на **двадцать** имён (`ln`, `log`, `exp`, тригонометрия,
  `trunc`, `mod`, `and`, `or`, `xor`, `not`, `add`, `sub`, `mul`, `div`,
  `move`): `var ln: u8;` давал невалидный ST при **нулевом** коде возврата
  `taktc`. ⚠️ Сторож (`takt-lang/tests/targets/st_reserved_names_tests.rs`)
  гоняет инструмент по каждой записи и требует **контрольного** имени, которое
  тот принимает, — иначе тест доказывал бы лишь, что `iec2c` ругается на любой
  вход. ⚠️ **На первом прогоне сторож опроверг сам замер:** `adr`, `size`,
  `bcd_to_int`, `int_to_bcd` инструмент **принимает**, и в список они не вошли —
  ложный отказ цели хуже пропуска. ⚠️ **Полноту он не доказывает** (словаря
  имён MatIEC нет), только обоснованность записей. ⚠️ Список берётся **из
  исходника** цели, а не повторяется в тесте (класс 0084/0193/0195).
- **Функции цели `st` печатаются в порядке ВЫЗОВОВ**
  ([0344](docs/features/0344-st-call-order.md)). Опережающих ссылок в IEC
  61131-3 нет, и алфавитный порядок давал `iec2c` «';' missing at the end of
  statement» — диагностику о **синтаксисе в строке вызова**, по которой причину
  не опознать; код возврата `taktc` был нулевым. Носитель —
  `generator/call_order.rs` (обход в глубину, порядок детерминирован).
  ⚠️ **Граф ацикличен по построению**: рекурсию запрещает `SE-053`. ⚠️ Дефект
  зависел от **алфавита** — вывод собрался бы при других именах, и корпус его
  не покрывает по той же причине; в фикстуре имена подобраны так, что алфавит
  противоречит вызову. ⚠️ Разбор тела **не** исчерпывающий: пропущенная форма
  даёт прежний алфавитный порядок, а не порчу вывода.
- **Имена моделей делят пространство со стандартной библиотекой IEC**: модель
  `Concat` → `invalid function block name`. Имя корневой модели берётся **из имени
  файла**, поэтому ловушка срабатывает и на `concat.takt`. Ловится гейтом, не тестами.
- **Тип операнда у цели `st` знает и ПОЛЕ СТРУКТУРЫ**
  ([0349](docs/features/0349-duration-field.md)). Имя функции преобразования
  IEC строится из **обоих** типов (`<ИЗ>_TO_<В>`), и `t.hold as u32` при
  `struct Timing { hold: duration }` отвергалось `ST-011` «тип операнда не
  определяется статически» — хотя тип поля объявлен рядом. Граница была
  свойством **сигнатуры** (функция не принимала модель), а не существа дела:
  теперь есть `inner_expr_type_in(expr, model)`, и живут оба варианта в
  `st_operand_type.rs`. ⚠️ Тем же входом ломалась цель `sv`: размерная форма
  внутри `{…}` применялась только к `Number`, а литерал длительности приходит
  узлом `Duration` — verilator отвечал `WIDTHCONCAT`, что гейт цели считает
  **ошибкой**. Признак теперь берётся у **напечатанного** текста (все ли
  символы цифры): он уже приведён к миллисекундам, и второе знание о единицах
  разошлось бы с первым.
- **Выражения ST: числа и биты — непересекающиеся миры**
  ([0041](docs/features/0041-st-backend.md)). `AND`/`OR`/`XOR` определены только на
  битовых строках, арифметика на них запрещена → побитовые операции идут через
  преобразование **в месте операции**, отсюда трансляция **типозависима** (без типа
  операнда → `ST-011`, а не догадка). Битового доступа `x.0` в MatIEC **нет вовсе**.
  Литералы в телах печатаются по целевому типу
  ([0066](docs/features/0066-st-bool-literals.md)).
- **Имя константы КВАЛИФИЦИРОВАНО владельцем во всех целях**
  ([0193](docs/features/0193-shared-const-qualified.md)). Модуль `rust` один на
  программу, модуль `sv` уплощён — **одно** пространство имён, и голое имя
  означало, что одноимённые константы двух моделей дают одно объявление: вторая
  молча считала чужим значением (расходились **цели между собой**). Печать и
  дедупликация обязаны идти **одной** функцией на цель. ⚠️ Ключ «константа
  используется» (`const_key`, пара владелец + имя) строится **из `upper` узла**,
  а не из «модели, которую печатаем»: неиспользуемая `const` в Rust под
  `-D warnings` — **отказ** сборки. ⚠️ Потребителей ключа **шесть**, и `st`
  среди них — заводя новый, ищи по имени поля, а не по форме `usage()`.
  ⚠️ Сторож — потактовая сверка, не гейт: `clippy`, `verilator` и `yosys`
  дефектный вывод **принимали**.
- **`[bit; N > 64]` — МАССИВ СЛОВ во всём выводе `c` и `rust`, а не только в
  типе** ([0262](docs/features/0262-wide-bit-vector-c-rust.md)). Обе цели звали
  слой `semantic::bit_vector` лишь при печати типа, а операции печатали как для
  скаляра: `cc -Werror` давал четыре ошибки, `rustc` — четыре, всё при **нулевом
  коде возврата**. Разряд адресуется через `bit_vector::bit_slot` (общий
  носитель с эталоном), инициализация и копирование идут по словам.
  ⚠️ **Маска ломала и СКАЛЯРНЫЙ случай** — печаталась литералом `1u`: класс
  шире того, что называл кандидат, найден **контрольным входом**.
  ⚠️ **Операция над словами отвергается своей диагностикой** (`CC-022`,
  `RS-011`): её не умеет и эталон, а печать означала бы в C арифметику
  указателя. ⚠️ Корпус класс не покрывает — сторожа фикстурные, с прогоном
  настоящих `cc`/`clippy-driver` и потактовой сверкой на разрядах в **разных**
  словах.
- **Позиция отказа цели — у ОПЕРАТОРА, и носитель её один на все цели**
  ([0277](docs/features/0277-expression-usage-position.md),
  [0308](docs/features/0308-target-refusal-position.md)). У `ExpressionNode`
  позиции **употребления** нет (решение 0056), поэтому печатник операторов
  объявляет место (`site::enter`), а конструктор отказа спрашивает его
  (`site::at`). Замер 2026-08-20: цель `c` указывала строку оператора, а
  `rust`, `st` и `sv` печатали отказ **без координаты вовсе** —
  `Location::Codegen` идёт без префикса. ⚠️ Носитель **потоковый**: у трёх
  целей конструкторы отказов — свободные функции без доступа к контексту, и
  протаскивать карту через полсотни вызовов значило бы менять сигнатуры ради
  координаты. ⚠️ **`site::reset()` в диспетчере обязателен** — состояние
  переживает вызов, и следующая генерация в том же потоке начиналась бы с
  координаты чужого файла (класс 0264). ⚠️ Вне операторов координата остаётся
  **своей** — на это стоит контрольный тест.
- **Генератор Rust: приоритеты C и Rust расходятся МОЛЧА**
  ([0050](docs/features/0050-rust-backend.md)). `a == b | c` даёт в C `1`, в
  Rust `false`, поэтому печатник скобит **каждый** бинарный узел — **на целых
  дефект был бы тихим**. Прочее цели: `#![no_std]` в модуле не эмитится;
  перечисление в присваивании приходит числом; общие переменные под-моделей
  свёрнуты в `<Root>Shared` (0059); функции получают состояние параметрами
  (`hal` — последним, иначе E0499); политика линтов `-D warnings`.
  ⚠️ `pub enum` с неконструируемым вариантом гейт **проходит**: публичность
  заглушила бы сторожа. ⚠️ **`bit` — это `bool`** (0148-01). ⚠️ **Мёртвое
  начальное значение не печатается** (0216): ошибка в сторону «мёртв» громкая,
  в сторону «жив» тихая. ⚠️ Открыт фикс
  [0148-02](docs/fixes/0148-02-rust-port-to-port-borrow.md) (E0499 на `led :=
  btn;`). ⚠️ Гейт цели гоняет **только корпус**.
- **Объявление БЕЗ инициализатора у цели `rust` сворачивается и `mut` не
  печатает** ([0410](docs/features/0410-rust-deferred-let-mut.md)). Первое
  присваивание — инициализация, а не изменение: прежде печаталось
  `let mut x: T;` **безусловно**, и `rustc -D warnings` отвечал «variable does
  not need to be mutable» при нулевом коде возврата `taktc`. ⚠️ **Слоёв было
  два**: снятие `mut` открыло `clippy::needless_late_init`, и его снимает
  свёртка — оба механизма (`deferred_needs_mut`, `fold_assignment`) взяты у
  соседней ветви мёртвого инициализатора (0216), второго знания не заводится.
  ⚠️ **Срез из свёртки исключён**: он печатается поэлементно (0355), выражения
  у него нет — свёрнутая форма дала бы `RS-011`. ⚠️ Отложенный **массив** так
  не лечится (`E0381`: Rust требует инициализации целиком до записи по
  индексу) — вынесено кандидатом.
- **Вариант перечисления восстанавливается И в сравнении, а не только в
  присваивании** ([0281](docs/features/0281-rust-enum-compare-literal.md)).
  У `enum` в Rust числового представления в выражении нет, поэтому
  `ref Done: c = 1;` печаталось `self.c == 1` — `E0308` **при нулевом коде
  возврата** `taktc`, тогда как `c := Go;` печаталось верно. Имя варианта
  строит **один** носитель `rust_expr::enum_variant_literal`, его зовут
  `coerce_to` и ветвь `enum_comparison` печатника условий. ⚠️ Тот же класс, что
  фикс 0148-01 (`bit` в сравнении): знание жило в одном месте из двух, и пути
  разошлись **молча**. ⚠️ Сравнение с ИМЕНЕМ варианта идёт другим узлом
  (`ConditionNode::EnumVariant`) и всегда печаталось верно — контрольный тест
  сторожит именно это. ⚠️ Гейт цели класс не видел: сравнения перечисления с
  числом в корпусе нет.
- **Сдвиг за ширину типа насыщается у `rust` и `c`, а ПОРОГ у каждого свой**

- **Ширина ВЫВЕДЕННОГО типа берётся у РЕЗУЛЬТАТА, а не у операндов**
  ([0285](docs/features/0285-inferred-width-from-result.md)). Тип выводится до
  свёртки, поэтому `const K := 1 + 255;` получал `[bit;8]` от левого литерала, а
  нормирование (0207) заворачивало 256 в **ноль** — молча и одинаково у всех
  девяти потребителей. ⚠️ Дело **не в сдвиге**, как считал кандидат: `2 * 128`
  и `200 + 200` (давало `144`) — тот же случай; `300 - 44` работало **случайно**
  — там левый операнд уже не влезал в восемь бит. ⚠️ **Расширяется только
  превышение ВЕРХНЕЙ границы у объявления БЕЗ явного типа** — три границы, и
  каждая ловила перебор чужим тестом: явный тип не трогать (`var u: u8 := 200 +
  100;` = `44`, правило 0207), тип из сигнатуры функции не трогать (вычислитель
  сворачивает вызов, и первая редакция дала `[bit;8]` вместо `[bit;32]`),
  отрицательное не расширять (`~0` = `255` — домен 0207). ⚠️ Границы берутся у
  единственного носителя `validate::literal_range::type_range`: своя копия
  разошлась бы с `SE-089`.
- **ТИП выведенного объявления берётся у ОБЪЯВЛЕННОГО операнда, а не у
  литерала** ([0287](docs/features/0287-wider-type-array-literal.md)). Таблица
  `wider_type` не знала `TypeNode::Integer` ни в одной паре, а литерал получает
  `[bit;N]` — тип литерала перехватывался ветвями `Array` и побеждал
  написанное автором. Исхода три, два тихих: вывод, отвергаемый чужим
  инструментом при нулевом коде возврата; отказ четырёх целей на вычислимой
  записи; **потеря знака** (`213` вместо `−299`) одинаково у всех девяти.
  Правило: ширина наибольшая, знак — знаковый, если знаков хотя бы один.
  ⚠️ **Ветви стоят ПОСЛЕ `Enum`/`Rational` и ДО `Array`**: выше перебьют
  соседей, ниже их перехватит тип литерала. ⚠️ Вектор **шире** объявленного
  целого отдан прежним ветвям: правило уточняет тип, а не подменяет.
  ⚠️ Сторож границы **был декоративен** — годен вход, где результат влезает в
  **оба** типа.
- **Тип операнда приведения знает ПОЛЕ структуры, и ядро спуска ОДНО**
  ([0371](docs/features/0371-fixed-cast-from-field.md),
  [0399](docs/features/0399-operand-type-single-carrier.md)). `one := g.kp as
  u8;` при поле `q(8, 8)` давал у эталона `1`, а у `c`, `rust`, `sv` и `st` —
  **128**: приведение печаталось без деления на 2ⁿ, молча и при нулевом коде
  возврата (ни линт, ни синтез, ни `cc` этого не видят — вердикт даёт
  потактовая сверка). ⚠️ **Класс был у ЧЕТЫРЁХ целей**, потому что цепочку
  `переменная(.поле | [индекс])*` каждая разбирала сама; теперь её разбирает
  `validate::base_type_with` (замыкание на структуры — приём 0366), и `st`/`sv`
  зовут его. ⚠️ **Полностью носители НЕ сводятся, и это замер**: на литерале,
  разряде, сравнении и арифметике они обязаны отвечать по-разному — цель
  `rust` оставлена со своим. ⚠️ Контроль обязателен: та же запись **над
  переменной** печаталась верно — тип терялся именно у поля.
- **Понижение q-литерала доходит и до ПОЛЕЙ структуры**
  ([0370](docs/features/0370-struct-field-fixed.md)). `var g: Gains := {1.5,
  2.5};` при `struct Gains { kp: q(8, 8), … }` исполнял эталон, а вывод
  **всех** целей, кроме диаграммы, отвергали их инструменты (`cc`, `iec2c`,
  `rustc`) либо сама цель (`SV-002`). ⚠️ **Границу создавала сигнатура
  помощника, а не устройство:** модель у слоя свёртки была всё это время, и
  снятие заняло один параметр — а названа граница была фичей 0368 как
  «структуры сюда не входят». ⚠️ Массив структур покрыт **рекурсией** ветви
  массива. ⚠️ **Сверка обязана смотреть на q-ЗНАЧЕНИЯ, а не на результат
  приведения `as`:** приведение из поля цель `c` печатает без деления на 2ⁿ
  (`(uint8_t)(g.kp + g.ki)` вместо `takt_q_floordiv`), и первая редакция теста
  падала не из-за понижения — соседний класс вынесен кандидатом.
- **Элемент агрегата несёт ТИП ЭЛЕМЕНТА — и при понижении, и при печати**
  ([0368](docs/features/0368-aggregate-element-type.md)). `[q(8, 8); 2] := {1.5,
  2.5}` доезжало до целей **дробным** литералом (`cc -Werror`, `E0308`,
  `SV-002`), а массив перечислений давал у `rust` числа в поле типа `[Mode; 2]`.
  ⚠️ **Скалярный аналог работает у всех девяти** — тип терял именно элемент
  агрегата; корней три (понижение смотрело на скалярный тип, печать `rust` знала
  лишь элемент-структуру, `sv_stmt::target_type` отдавал `None`). ⚠️ **Место
  понижения — СВЁРТКА инициализаторов, а не вывод типов**: правка в выводе
  выполнялась и **терялась**, потому что свёртка подменяет значение из сырого
  АСД; показал это отладочный прогон, а не чтение. ⚠️ Бит-вектор `[bit;N≤64]`
  исключён; до полей структуры понижение не доходит — граница названа.
- **Дробная арифметика в инициализаторе: ТОЧНОЕ считается, округляемое —
  `SE-114`** ([0300](docs/features/0300-fractional-init-arithmetic.md)).
  `+`, `-`, `*` над десятичными литералами сворачиваются **точно**
  (`const_eval/decimal.rs`), деление отвергается. ⚠️ Прежний общий отказ был
  верен **наполовину**: довод про округление `q` — про округление, а `1.0 + 2.0`
  есть ровно `3.0` в любом представлении; цена умолчания — **три** значения на
  одном входе. ⚠️ **Свёрнутый литерал обязан быть ПОНИЖЕН тем же носителем**,
  что авторский: понижение идёт при выводе типов, то есть **до** свёртки.
  ⚠️ **Отказ узкий — только арифметика**: первая редакция отвергала вход, где
  эталон и цель уже согласны, и поймали это сторожа чужой фичи. ⚠️ Сторож —
  сверка плюс **контрольная пара** «свёрнутое = написанное»: без неё «стороны
  сошлись» значит лишь «ошибаются одинаково».
- **Инициализатор объявления не читает НЕОПРЕДЕЛЁННУЮ память: `SE-099` (ячейка)
  и `SE-113` (порт)** ([0189](docs/features/0189-anonymous-ports.md),
  [0266](docs/features/0266-port-in-declaration-initializer.md)). Правило одно —
  инициализатор вычисляется до первого такта, — поэтому обход **один**, а кодов
  два: разный обход в тексте. Цена молчания на порте: **три** поведения у
  принимающих целей и два отказа у остальных, причём при нулевом входе ноль и
  чтение совпадают случайно. ⚠️ **Нормировать эту форму нечем**: ветвь сброса
  `sv` выражений не вычисляет, а у эталона до первого такта входа нет — общего
  поведения не существует. ⚠️ Порт узнаётся по **виду объявления**, а не по
  имени: вид проставлен при объявлении и от вывода типов не зависит.
  ⚠️ Замеряя поведение `c-hal`, **дай порту адрес**: без него приходит `SE-052`
  и прячет настоящий ответ.
- **Инициализатор не зовёт функцию, которую компилятор исполнить НЕ МОЖЕТ, и
  причина называется** ([0306](docs/features/0306-unfoldable-call-in-initializer.md)).
  Вычислитель констант знает, что мешает (чтение переменной, порт, `extern`,
  бюджет), а свёртка выбрасывала его диагностику конструкцией `let Ok(…) else`,
  у которой ошибки **нет по типу**. Цена: эталон давал `0` **молча**, `st`
  теряла инициализатор при коде 0, прочие отказывали четырьмя разными кодами.
  ⚠️ Признак **синтаксический** — «в записи есть вызов»: неразрешённое имя судит
  `SE-004` ниже по конвейеру. ⚠️ **Вычислимый вызов законен**, и это контроль,
  без которого правило означало бы «любой вызов запрещён». ⚠️ **Место эмиссии
  одно**: ветвь 0305 в свёртке была **мертва** (спрашивала `External`, а на
  стадии 2 лежит `Unresolved`), и копия в `validate` снята — сторож
  `initializer_refusal_lives_in_a_single_place`.
- **Инициализатор не зовёт ВНЕШНЮЮ функцию: `SE-084`**
  ([0305](docs/features/0305-extern-call-in-initializer.md)). Значение `extern`
  при компиляции неизвестно по определению, а начальное значение выставляется до
  первого такта. Замер 2026-08-20: эталон давал ноль **молча**, `st`/`st-at`
  печатали объявление **без** `:=` при нулевом коде возврата, `c`/`c-hal`,
  `rust` и `sv` отказывали — три ответа на один вход. ⚠️ Проверка стоит в **том
  же** обходе, что `SE-099` и `SE-113` (правило одно — обход один, урок 0203).
  ⚠️ **Форм внешней функции в ячейке ДВЕ:** на стадии 2 лежит
  `Unresolved(FunctionDefine { external: true, … })`, а не `External` — проверка
  только второй не ловит ничего. ⚠️ Вызов **локальной** функции вычисляется и
  законен; `extern` **в теле** — штатный путь. ⚠️ Следствие: причина вердикта
  `InitialValueUnknown` (0258) осталась без достижимых входов и помечена
  защитной.
- **Обращение к ячейке без имени — `#АДРЕС`**
  ([0189](docs/features/0189-anonymous-ports.md)). `#A:B as T` — поле
  разрядности `T` с бита `B`; `#A.B` — один бит; `#A` без ширины — **`SE-097`**
  (ширина доступа к MMIO угадыванию не подлежит). Свёртка форм в тройку
  `{адрес, бит, тип}` — воронка `semantic/anon_port.rs`, та же, которой живут
  `c-hal` и `sv-mmio`. Запись → **`SE-096`**, обращение в инициализаторе →
  **`SE-099`** (до первого такта содержимое неизвестно). ⚠️ Поддерживают **три**
  цели (`c-hal`, `st-at`, `sv-mmio`); `c`, `rust`, `st`, `sv` **отказывают с
  причиной** — молчать им нельзя. ⚠️ Имя ячейки строит компилятор и оно
  **общее** у эталона, `st-at` и `sv-mmio`: разойдясь на символ, сверка трасс
  сравнивала бы разные величины. ⚠️ Эталон моделирует ячейку синтетическим
  портом, поэтому `#A as u8` и `#A as u32` для него — **разные** ячейки.
- **Оператором-выражением может быть только форма с эффектом**
  ([0189](docs/features/0189-anonymous-ports.md), решение 6A): присваивание и
  вызов функции; `x + 1;` и `#0x100.4;` → **`SY-007`** от парсера. Прежде язык
  принимал любое выражение, а отказ приходил от **чужого** инструмента на
  порождённом файле (`cc -Wall -Werror`: `-Wunused-value`).
  ⚠️ Голый адресный литерал в выражении → **`SY-008`**: адрес есть свойство
  размещения (`at`, оператор `address`, карта). Прежде `x := 0x105:0;`
  принималось и давало молчаливое расхождение — симулятор считал адрес числом,
  а цель `c` **теряла оператор целиком**. Корень потери устранён там же:
  печатник операторов цели `c` глотал **любую** ошибку (`Err(_) => {}`), теперь
  пропускается только вызов встроенной функции.
- **Экспорт карты — `taktc address-map --emit map|json`**
  ([0043](docs/features/0043-address-map-export.md)): выгружает **фактически
  разрешённую** карту тем же `resolve_addresses`, что у `c-hal`; `map` замыкается
  круговым рейсом. Мёртвый порт → `"address": null`, не `0x0`.

### Симулятор

- **Семантика вычислений живёт только в `takt-sim/src/eval/`**
  ([0025](docs/features/0025-simulator-expression-eval.md)). Адаптеры семантики
  не содержат; тела исполняет один интерпретатор `unit/statement.rs`. Модуль
  `eval` и второй вычислитель (`unit/initial.rs`, начальные значения) — под
  `deny(clippy::wildcard_enum_match_arm)`, гейт `check-exhaustive-nodes.sh`
  сторожит **оба** и ищет атрибут **с начала строки** (иначе его находил
  док-комментарий). ⚠️ Правило названо для трёх узлов языка: ветки по
  `TypeNode`/`StateNode`/`Extend` в `builder.rs` им не покрыты. ⚠️ Тесты
  симуляции пиши **на значения** (`Unit::variable`), а не на факт перехода:
  отсутствие этого слоя дало восемь дефектов при зелёных тестах.
  ⚠️ **Второй вычислитель — не «только литералы»** (0205): он зовёт тот же
  `eval::cast_to_type` и читает константу **из таблицы объявлений**, а не из
  ячейки (в ячейке снимок с непонижённым АСД, урок 0204). Своей арифметики
  приведения здесь заводить нельзя — разойдётся с тактом.
- **Проверка состояния под-модели исполняется ЭТАЛОНОМ, и адресуется по имени
  модели** ([0245](docs/features/0245-sim-state-of-model.md)). `S(Модель) =
  Состояние` вычисляется через реестр состояний в контексте-корне: узел
  публикует своё состояние при постройке, переходе и восстановлении из снимка.
  Прежде эталон отвечал `SIM-013` на записи, которую цель `c` переводит с 0075.
  ⚠️ Публикация стоит **после** смены поля `state`: наблюдатель обязан увидеть
  переход соседа **на том же такте**; мутация «публиковать до» валит сверку.
  ⚠️ Модель, не запущенная в прогоне, даёт **`SIM-036`**, а не «условие ложно»:
  молчаливое `false` развело бы трассу с прошивкой. ⚠️ Проверка состояния —
  **условие**: её место — ребро, `cond`, формула. ⚠️ Форму паттерна разбирает
  **одна** функция на проект — её зовут судья условий, цель `c` и эталон.
- **Разряд — ЧИСЛО 0/1, а правило S8 остаётся в силе**
  ([0356](docs/features/0356-sim-bit-in-arithmetic.md)). `read_bit` отдавал
  `Value::Boolean`, и правило S8 («логическое не смешивается с числом молча»,
  решение 0025) било по записям, которые переводят **все восемь** целей: замер
  2026-08-21 дал `SIM-005` **в такте** на `arith := src.7 + 1;` и на типичной
  записи ребра `ref Done: src.7 = 1;`. ⚠️ **Эталон противоречил сам себе:**
  `bit`-ПЕРЕМЕННАЯ в той же арифметике (`var f: bit := 1; f + 1`) исполнялась —
  она хранится числом; различал поведение источник значения, а не тип.
  ⚠️ **Правку легко сделать не там:** первая редакция меняла `as_num`, то есть
  **отменяла S8** для всех значений — упал его собственный юнит-тест, и это
  верное поведение сторожа. Верное место — источник (`eval/access.rs`).
  ⚠️ Контрпример «S8 в силе» стоит рядом с изменённым тестом: без него правка
  читается как отмена правила. ⚠️ Условия не затронуты (`to_bool` принимает
  число), но проверено это прогоном. ⚠️ Наблюдаемое отличие одно: трассы
  печатают разряд числом, а не `true`/`false`.
- **Отказ доступа к разряду называет разрядность ЗНАЧЕНИЯ**
  ([0307](docs/features/0307-sim-bit-range-text.md)). `SIM-011` печатал «вне
  диапазона 0..64» литералом — и на `[bit;96]` это была **ложь**: разряд 70 тот
  же эталон исполняет. Теперь ширина в ошибке: 64 у целого (носитель), `1` у
  логического, `слов × 64` у бит-вектора (раскладка 0078). ⚠️ Граница
  печатается **включительно** (`0..127`), иначе читается как допустимая.
  ⚠️ Ширина берётся у значения, **не** у объявления: в `eval/` типа уже нет, а
  разряд 100 в `[bit;96]` принимают эталон, `c`, `rust` и `sv` — обещание
  отказа по объявленной ширине было бы второй ложью (класс вынесен кандидатом).
  ⚠️ Сторожа **сквозные** (`takt-sim/tests/sim/bit_range_text_tests.rs`): модуль
  `eval` крейта приватен, и проверять надо текст, который видит пользователь.
- **Умолчание типа у эталона строит ОДИН носитель, и вид значения — часть
  типа** ([0354](docs/features/0354-sim-duration-default.md)).
  `unit/builder.rs::default_field` разбирает `Bool`, `Rational`, `Fixed`,
  `Array`, `Struct`, прочее сводит к `Value::Number(0)` — для `Integer`, `Enum`,
  `Bit` верно, для `duration` нет: у неё **свой** вид значения (наносекунды).
  Прежде `var d: duration;` плюс `d := d + 1s;` давало `SIM-005` **в такте**,
  тогда как все восемь целей вход переводят. ⚠️ Носитель обслуживает и поля
  структуры, и элементы массива. ⚠️ **Расширять арифметику вместо этого
  нельзя**: смешение числа и длительности отвергает `SE-065`, и «умный» эталон
  врал бы (класс 0034). ⚠️ Сторож — потактовая **сверка**, а не «отказа больше
  нет»: значение обязано совпасть, а единицы у сторон разные.
- **Значение `extern`-функции задаёт СЦЕНАРИЙ**
  ([0209](docs/features/0209-model-external-interface.md)). Секция `extern` шага:
  одно значение на такт либо таблица по **первому** аргументу («память»).
  ⚠️ Умолчания нет: не задали — прежний `SIM-019`. Ноль сделал бы сверку трасс
  зелёной при расхождении эталона с прошивкой — класс, ради которого сверки и
  заведены. ⚠️ Стенд принадлежит **шагу** и ставится перед тактом, как модельное
  время; доехать он обязан до **всех** областей видимости (`BlockScope`,
  `FunctionScope`, `Unit` в роли контекста) — умолчание трейта в любой из трёх
  означает «стенда нет», и подмена молча не срабатывает.
- **Единый источник истины по значениям — `ModelNodeContext`**
  ([0032](docs/features/0032-state-io-variables.md)): писать только через
  `Context::set_value`, читать через `get_value`/`dump`.
- **Узел языка в симуляторе разбирают ТРИ места, и они расходятся**
  (фикс [0134-02](docs/fixes/0134-02-duration-literal-in-body.md)): адаптер
  условий (`predicate.rs`), адаптер выражений (`expression.rs`) и вычислитель
  начальных значений (`unit/initial.rs`). Литерал длительности жил в двух из трёх:
  в теле блока `left := left - 1s;` отвечал `SIM-007`, хотя документ обещает
  арифметику, а инициализатор объявления работал. ⚠️ **Гейт исчерпаемости этот
  класс не ловит по устройству:** узел разобран, ветвь есть — она просто отвечает
  отказом «до будущей задачи», и отказ переживает саму задачу. Сторож — только
  проверка **поведения**; заводя ветвь-заглушку, заводи и тест, который её
  снимет. ⚠️ Тест на арифметику существовал и дефект **не ловил**: складывал две
  переменные, а падал литерал.
- **Реализация МОДЕЛИ (`model M = A | B { … }`) разворачивается в состояние**
  ([0199](docs/features/0199-model-implements-brace-form.md)). Форма — синоним
  записи `model M { start Имя = A | B; }`, и разворот делает
  `extend::expand_model_implement` на построении дерева: за этой границей формы
  не существует, и пяти потребителям не по чему разойтись (приём 0143/0187/0192).
  ⚠️ Прежде `ModelNode::implements` не разрешался **никогда** — разрешались
  только реализации состояний: эталон давал пустую трассу, а все четыре цели
  искали состояние с пустым именем. ⚠️ **Разрешить `implements` в поле мало**:
  карта (`semantic::minimap`) строит состояния из `model.states`, и от такой
  правки чинится **только эталон** (проверено). ⚠️ Модель с реализацией **и**
  собственным состоянием — `SE-101`: прежде такая запись работала, **молча
  теряя** реализацию. Коллизии имени синтетического состояния нет по построению
  — других состояний у модели с реализацией не бывает.
- **У состояния-композиции ЕСТЬ собственные рёбра, и цели их печатают**
  ([0303](docs/features/0303-composition-state-conditional-edge.md)). По
  завершении реализации проверяются переходы: сначала `ref` в порядке
  объявления, затем `next`; `END` подставляется **только** состоянию без
  переходов. Прежде все восемь целей печатали лишь `next`, и вход с условным
  ребром давал другой автомат — в целевое состояние не шёл никто. ⚠️ **Правки
  целей было мало**: `minimap::visit_state` клал в обход только `next`, и
  состояние, достижимое по ребру, в карту не попадало — цель `rust` не знала о
  нём вовсе. ⚠️ Класс **невидим инструментам**: прежний вывод принимали `cc`,
  `verilator`, `yosys` и `iec2c`; вердикт дают только потактовые сверки.
  ⚠️ Найден **контрольным входом чужой фичи**: «то же самое, но без предмета» —
  единственное, что отличает «стороны сошлись» от «ошибаются одинаково».
- **Реализация состояния — дочерний юнит узла с ОБЩИМ контекстом**
  ([0181](docs/features/0181-sim-state-implementation-tick.md), закрытие фикса
  [0057-01](docs/fixes/0057-01-sim-composition-next.md)). `state P = A + B { … }`
  живёт в `UnitKind::Node::state_impls`; такт тикает её **до** проверки переходов
  и берёт переход только по завершении — на том же такте (эталон — цель `c`,
  `generate_extend_transition` в ветви `is_done`). Повторный вход композицию
  **не** перезапускает — тоже контракт цели `c`. ⚠️ `next` живёт **отдельным
  полем** `StateNode::Implement::next`, а не среди `references`: заводя новую
  форму перехода, проверь, что `build_transitions` её видит — иначе состояние
  застрянет молча. ⚠️ Шаги `+` обязаны делить родительский контекст (общий
  `shared_context` с `Parallel`), иначе значение шага A шагу B не видно. Сторожа
  — тройная сверка sim≡C≡SV в `conformance_sv_tests` и
  `takt-sim/tests/sim/sequential_composition_tests.rs`.
- **`Unit::execution` в дочерние юниты НЕ спускается** — фикс
  [0181-01](docs/fixes/0181-01-sim-parallel-always-twice.md). Ребёнок исполняет
  свои блоки сам, в собственном `tick_body`; вернуть спуск значит исполнить
  `always` под-модели композиции **дважды** за такт (симулятор давал 2, цель
  `c` — 1; било и по `|`, и по `+`). ⚠️ Дефект был **невидим для всего
  покрытия**: тела корпуса идемпотентны (`x := <выражение>`), и лишнее
  исполнение в них неразличимо. Сторож — значенческие тесты на **накапливающем**
  теле (`n := n + 1`) в `takt-sim/tests/sim/sequential_composition_tests.rs`.
- **Порты под-моделей композиции драйвятся**
  ([0079](docs/features/0079-sim-composition-ports.md)): `PortNames::from_model`
  обходит `model.models` рекурсивно. ⚠️ Правки требовало **перечисление**, а не
  чтение/запись — те адресуют все ветви.
- **Порт адресуется квалифицированно** `Модель::порт`
  ([0135](docs/features/0135-sim-qualified-port-names.md)); голое имя работает как
  прежде. ⚠️ Квалификатор — **имя модели, а не путь**: две под-модели с одинаковым
  именем неразличимы.
- **Сценарий пишется именами портов**
  ([0132](docs/features/0132-sim-named-port-scenarios.md),
  [0150](docs/features/0150-sim-positional-scenario-deprecation.md)): неизвестное
  имя → `SIM-030`, двусмысленное → `SIM-031`. ⚠️ Позиционная форма **устарела и
  об этом говорит** (`SIM-037`, **один раз за прогон**): индекс — место имени в
  **алфавитном** списке, и добавление порта молча сдвигает массив. Форма
  принимается (сценарии живут и вне репозитория), а репозиторий держит гейт
  `check-positional-scenarios.py` с ратчетом. ⚠️ **Код диагностики обязан быть
  отдельным литералом**: гейт кодов ищет `"XX-NNN"`, и код, вплавленный в текст,
  ему невидим — так `SIM-030`…`SIM-032` прожили вне реестра до
  [0255](docs/features/0255-sim-diagnostic-codes-registry.md). ⚠️ Значения
  портов удерживаются между тактами: явный ноль после единицы есть сброс.
- **Инварианты проверяются** ([0044](docs/features/0044-sim-assert-invariant.md)):
  `invariant Имя = C;` — сахар над `cond` + `Formula::Guard`; нарушение →
  `TickResult::Failed` + `SIM-025`. Мягкий режим (`--invariant-soft`) **записывает**
  нарушение и продолжает такт. ⚠️ Ошибка **вычисления** условия — `Failed` в обоих
  режимах; в сверке с C мягкий режим не участвует.
- **Сценарии примеров проверяются прогоном** (`examples_scenario_tests.rs`): у
  каждого `examples/*.takt` обязан быть либо контракт (цепочка + бюджет +
  завершение), либо исключение **с причиной**.

### Верификация

- **Абстракция управляющего графа** ([0049](docs/features/0049-model-checking-ltl.md)):
  атом = имя состояния, условия рёбер абстрагированы. «Держится» надёжно,
  «нарушено» может быть ложным. ⚠️ **Самопетля — не только у тупика:** её получает
  всякое состояние без **безусловного** `ref`. Первая редакция ставила петлю лишь
  вершине без рёбер → Крипке была **недо**-аппроксимацией → ложный `Holds`.
  Правило: ошибаться только в сторону **лишних** прогонов.
  ⚠️ **Капкан, стоивший дефекта** ([фикс 0010-01](docs/fixes/0010-01-buchi-acceptance.md)):
  `build_buchi` принимал любой бесконечный прогон, потому что тесты проверяли
  **структуру** автомата, а не язык. Тесты верификации пиши **на вердикт**.
  Область формулы — по месту объявления; область проверки — свой файл
  ([0051](docs/features/0051-verify-scope.md)).
- **Свойства над данными — абстракция по формуле**
  ([0068](docs/features/0068-verify-data-properties.md)): отслеживаются **только**
  переменные из φ. Ход данных **полностью недетерминирован** — максимальная
  сверх-аппроксимация: `Holds` надёжен, `Violated` над меняющимися данными почти
  всегда возможно ложный. ⚠️ Наивный explicit-state **неосуществим**: у `elevator`
  одна вершина имеет 3.7·10⁵⁰ преемников (входной порт волен принять любое значение
  каждый такт). Сторож направления — `abstracted_source_yields_extra_run_not_missed`.
- **Потолок верификации по данным считается по РЁБРАМ**
  ([0145](docs/features/0145-verify-vertex-budget.md)): `EDGE_LIMIT = 1_000_000`
  против `max(E_упр, V_упр) × D²`, где `D` — произведение доменов
  отслеживаемых переменных. Работа (произведение с Бюхи + nested DFS) идёт **по
  рёбрам**, а рёбра растут квадратично по `D`. ⚠️ Метрику выбрал **замер**: два
  входа с одинаковым числом **вершин** различаются по времени в 2000 раз, с
  одинаковым числом **рёбер** — совпадают. Прежний `VERTEX_LIMIT` пропускал
  вход, не завершавшийся за 60 с при 81-кратном запасе. ⚠️ Потолок **один**:
  новая величина мажорирует прежнюю, и `max` в формуле делает это свойством
  кода, а не рассуждения. ⚠️ Сторож на взрыв рёбер при регрессе **виснет, а не
  падает** — быстрый сигнал даёт второй тест на ту же формулу; удалять его как
  «дублирующий» нельзя. ⚠️ Корпус класс не покрывает: формул `[LTL]` в
  `examples/` нет.
- **Вердикт-отказ НАЗЫВАЕТ причину, и носитель текста один**
  ([0258](docs/features/0258-verify-unsupported-reason.md)).
  `Verdict::Unsupported { atoms, reason }`; `UnsupportedReason` различает пять
  случаев, текст даёт `UnsupportedReason::text()` — его берут и CLI, и экспорт
  графа. Прежде вердикт нёс только имена атомов, CLI печатал **все** причины
  разом, а экспорт утверждал своё — на входе за потолком это была ложь.
  ⚠️ **Ветвь `DomainNotEnumerable` недостижима, и это замер**: `float`, `q`,
  массив и структура отсекаются подмножеством предикатов шагом раньше. Ветвь
  оставлена защитной: расширится подмножество — она окажется на переднем крае.
  ⚠️ Текст сообщения проверяется **прогоном инструмента**: продолжение строки в
  `match` дало десятки пробелов подряд, чего тесты на тип не видят.
### Документ и процесс

- **Версия языка — единственный источник истины в коде**:
  `takt_lang::LANGUAGE_VERSION`, **сейчас `0.13.0`**
  ([0085](docs/features/0085-language-version-constant.md)). Гейт
  `scripts/check-language-version.sh` сверяет **три** источника — константа,
  README и живой контекст. ⚠️ Меняя версию языка (правило 22 — накапливается по
  циклам), правь все три синхронно. Это **не** версия крейта `takt-lang` (`CARGO_PKG_VERSION`, сейчас `0.55.0`).
- **Релиз и тег выпускает АВТОМАТИКА при подъёме минорной версии языка**
  ([0302](docs/features/0302-release-on-language-minor.md)). Решение принимает
  `scripts/release-check.sh` (одна строка: `release <версия>` либо `skip
  <причина>`), тело собирает `scripts/release-notes.sh`, `.github/workflows/release.yml` —
  обёртка **без логики**. ⚠️ Устройство подчинено тому, что **CI не
  исполняется**: задания Actions не стартуют (блокировка аккаунта по биллингу —
  замер 2026-08-19, фича 0175), поэтому YAML непроверяем, и всё проверяемое
  обязано лежать в скриптах; их гоняет сторож
  `scripts/test-release-check.sh` в предкоммите. ⚠️ **Автоматика — страховка,
  а не замена правила 22:** тег, поставленный человеком, останавливает её
  (`skip`), а гейт 0162 при отсутствии локального тега первой подсказкой
  предлагает `git fetch --tags`. ⚠️ **Тело релиза берётся из ИСТОРИИ, а не из
  журнала:** в `CHANGES.md` заголовок `## ` один на весь файл (выпуски не
  размечали ни разу), и раздел «Не выпущено» дал бы 9765 строк.
- **Подъём версии языка помечается тегом, и у правила есть сторож**
  ([0162](docs/features/0162-git-tag-v040.md)). `scripts/check-version-tag.sh`:
  у **закоммиченной** версии есть **аннотированный** тег `v<версия>`, достижимый
  из `HEAD`. Замер: из восьми версий тегов не имели две — правило 22 без команды
  исполнялось через раз. ⚠️ **Гейт обязан молчать в момент подъёма**: тег
  ставится **на** коммит, а предкоммит идёт **до** него, и наивная проверка
  падала бы у каждой фичи, исполняющей правило **верно**; признак — расхождение
  версии в рабочем дереве и в `HEAD`. ⚠️ **Прошлые пропуски сторож не ищет** —
  перечня версий в дереве нет. ⚠️ **Замеряя теги, разыменовывай `^{commit}`**: у
  аннотированного тега `rev-parse` отдаёт объект **тега**, и наивное сравнение
  объявляет «тег указывает не туда» у всех сразу. ⚠️ CI получил `fetch-depth: 0`,
  но **прогоном не проверен** — Actions заблокированы.
- **Замер расхождения снимается КОМАНДОЙ, и проба проверяется**
  ([0301](docs/features/0301-probe-checklist.md),
  [0362](docs/features/0362-probe-target-tools.md), правило 30).
  `scripts/probe.sh [-n ШАГОВ] МОДЕЛЬ.takt` сводит эталон и все восемь целей в
  одну таблицу и проверяет **саму пробу**: неиспользуемое объявление, имя файла
  = имя типа, отказ **общей** диагностикой раньше цели («поведение НЕ
  измерено»). ⚠️ **КОД ВОЗВРАТА `taktc` — НЕ ВЕРДИКТ О ВАЛИДНОСТИ**: последний
  раздел гоняет **инструменты целей** флагами гейтов; у `st` шагов два
  (`iec2c`, затем сборка его вывода). ⚠️ Нет арбитра — печатается «пропуск»,
  никогда «принял». ⚠️ **Скрипт не судит**: контрольный вход, снятие
  посторонних причин и дата замера — на человеке. ⚠️ Каталог бинарников — у
  носителя `scripts/target-dir.sh`.
- **Реестр стадии СВЕРЯЕТСЯ с диском, и пропуск в нём слепит соседний гейт**

> печать в `takt-lang/src/format/`, иначе `format_source` начнёт **отказывать** на

> ⚠️ **«Весь корпус» — это три каталога** (`examples`, `takt-lang/tests/data`,
> `takt-sim/tests/data`), и пропавший каталог **валит тест** (фича
> [0230](docs/features/0230-format-corpus-sentinel.md)). Прежде обход звал два
> каталога, переименованных ещё 0100, и при ошибке чтения молча возвращался:
> тест рапортовал о корпусе, видя 158 файлов из 308. Цена измерена в дефектах —
> в невидимой половине жила запись `model M = A | B { … }`, у которой форматтер
> **терял реализацию**, и форма `model M = A { }`, которую он печатал
> неразбираемой (фикс [0199-01](docs/fixes/0199-01-fmt-drops-model-implement.md)).
> ⚠️ Список исключений `KNOWN_GAPS` — **с ратчетом**: запись, которой на корпусе
> не соответствует ни один отказ, валит тест (образец —
> `scripts/module-size-baseline.txt`). Сегодня он пуст.
> ⚠️ **Отказ строит одна функция** `format::unsupported(loc, вид)` — диагностика
> **`FM-001`** с позицией узла (фича
> [0229](docs/features/0229-format-unsupported-position.md)). Прежде отказ нёс
> строку: место не называлось вовсе, а на операторе печатался `Debug`-дамп узла
> (класс 0202 в ветви, до которой та фича не дошла). Позицию оператора даёт
> **`ast::Statement::loc()`**, имя вида — `kind_name()`; оба разбора
> исчерпывающи, и копий у них быть не должно — до 0229 `statement_loc` жил в
> двух местах (счётчик глубины, константный вычислитель).
> ⚠️ У `Type::Function` позиции в АСД **нет**, и это осознанно: узел грамматикой
> не строится (как `Expression::CodeBlock`/`NamedFunction` — мёртвые узлы, класс
> 0201). Появится правило — вместе с ним появится и `loc`.

> **Слой использований (фича 0131).** Новый узел АСД **валит сборку**
> `semantic/usages/walk.rs`: модуль объявляет `deny(clippy::wildcard_enum_match_arm)`,
> то есть `_ =>` по узлу языка там не соберётся. Это замысел: пропущенное
> вхождение — испорченный переименованием исходник, а не «неполный ответ».
> Добавил узел — разбери его в обходе (третий пункт списка сопровождения после
> форматтера и `eval/` симулятора).

> **Слой стиля — канон именования (фича [0226](docs/features/0226-naming-convention-warning.md)).**
> Новая форма **объявления** обязана попасть в обход `takt-lang/src/style/naming.rs`,
> иначе её имя каноном не проверяется — а сказать об этом машине нечем: обход
> кончается `_ => {}` **осознанно** (канон описывает объявления, а не всякий узел
> АСД), поэтому `deny(clippy::wildcard_enum_match_arm)` здесь неприменим. Сторож —
> `takt-lang/tests/syntax/style_naming_fmt_tests.rs::every_declaration_kind_of_the_canon_is_reported`:
> он перечисляет **все** виды объявлений и падает, когда обход теряет ветвь, но о
> **новом** виде, которого в его таблице нет, промолчит. ⚠️ Проверка живёт вне
> семантики намеренно: `taktc fmt` семантику не запускает (ADR 0024), и это его
> свойство. ⚠️ Предупреждение `CS-001` на код возврата `fmt --check` **не влияет**
> (решение заказчика), поэтому корпус от него сторожит тест
> `corpus_has_no_style_warnings`, а не гейт предкоммита.
> ⚠️ **Обход спускается в ТЕЛО СОСТОЯНИЯ** (фикс
> [0197-01](docs/fixes/0197-01-kr-else-cond-case-enum-lines.md)): `invariant`
> объявляется в двух местах — элементом модели и элементом состояния, — и без
> спуска канон действовал бы через раз. `collect_state_element` разбирает
> `StateElement` **исчерпывающе, без `_`**: новый вид элемента обязан заставить
> принять решение. ⚠️ Прочие элементы тела (`next`, `ref`, `every`, именованные
> блоки) имён не объявляют, а **ссылаются** на чужие — переименовывать их канон
> не вправе; контр-пример на это стоит рядом с положительным сторожем.
> ⚠️ **`CS-001` отдаётся во ВСЕХ ветвях возврата `lsp/diagnostics.rs::collect_diagnostics_at`,
> где АСД разобран** (фича [0227](docs/features/0227-lsp-style-warning-with-errors.md)):
> рядом с ошибкой построения дерева, рядом с ошибкой `validate` и на успешном
> пути. Это **исключение** из политики «предупреждения о смысле при ошибках не
> показываем» — канон именования смотрит на текст и от ошибок не портится;
> прочие предупреждения (`SE-036`, `SE-037`) остаются только на успешном пути.
> Прежде предупреждение исчезало от любой ошибки, а `fmt` его печатал — один
> вход, два ответа. ⚠️ Сторожа на **новую** ветвь возврата нет и быть не может
> (ветвь — не тип): заводя её, отдай стиль и там, иначе он потеряется молча.

> **Запуск инструментов из IntelliJ: логика — вне GUI** (фича
> [0158](docs/features/0158-intellij-run-configurations.md)). Конфигурации
> «Compile»/«Simulate» строят командную строку **чистой функцией**
> `run/TaktCommandLine.kt` (без `Project`/`Editor`/сервисов) — только она и
> проверяется Gradle-тестами, потому что плагин вне `precheck.sh`. ⚠️ **Колонка
> диагностики — в СИМВОЛАХ**, а документ IDEA адресуется кодовыми единицами
> UTF-16: на символе вне BMP (эмодзи в комментарии) наивное «колонка − 1»
> уводит ссылку не туда — пересчёт делает `TaktOutputFilter.charColumnToOffset`,
> и мутация это ловит. ⚠️ Каталоги импортов подставляются **повторяемым** `-I`:
> разделитель списка у компилятора платформозависим (`:` против `;`), и второе
> знание о нём в плагине заводить нельзя. ⚠️ Формат позиции задан ядром
> (`diagnostics::position_prefix`), а разбирает его плагин — при смене формата
> тесты плагина об этом не узнают (кандидат).

> **Переименование в IntelliJ делает СЕРВЕР, и держится это на отсутствии
> `PsiNamedElement`** ([0154](docs/features/0154-intellij-server-rename.md)).
> `LSPRenameHandler` из LSP4IJ зарегистрирован `order="first"`, но **уступает**
> любому доступному нативному обработчику: его предикат требует, чтобы других не
> было (либо чтобы все были `VariableInplaceRenameHandler`) — разбор байткода в
> ADR. Поэтому пока `TaktNameDecl` объявлял `PsiNameIdentifierOwner`, серверный
> `rename` не включался **никогда**, а работала эвристика «первая одноимённая
> декларация файла» без областей видимости. ⚠️ Вернёте `PsiNamedElement` —
> переименование молча уедет обратно в эвристику; сторож
> `TaktRenameTest::testDeclarationIsNotRenamableNatively` это ловит (проверено
> мутацией). ⚠️ Сторож на **пустоту** `RenameHandlerRegistry.getRenameHandlers`
> строить нельзя: зонд 0154 показал, что в синтетическом `DataContext` теста
> `PsiElementRenameHandler` доступен даже для `.txt` — он предлагает
> переименовать **файл**. ⚠️ Цена: без `takt-lsp` переименования в IntelliJ нет
> вовсе (навигация и подсветка остаются) — названо в `README` плагина.

> **Редакторский слой — правило 29 свода (фича 0178).** Изменение лексики,
> синтаксиса или семантики **обязано** проверить LSP (`takt-lang/src/lsp/`) и
> плагины (`extensions/`); ответ «не нужно» фиксируется тоже. Часть держит

> исчерпывающ, `deny(clippy::wildcard_enum_match_arm)` не даёт вернуть `_`

> держится и без clippy). Список автодополнения `lsp/keywords.rs::TAKT_KEYWORDS`
> — **данные**, исчерпываемостью не защищаются: их сторожит тест вложения
> `KEYWORDS ⊆ TAKT_KEYWORDS ∪ COMPLETION_EXCLUDED` (перечисление лексера —
> `parser::lexer::all_keywords()`). ⚠️ Проверять **равенство** нельзя: в списке
> законно живут `enter`/`exit`/`always` — имена блоков, а не ключевые слова.
> ⚠️ Плагин **IntelliJ** машиной **не защищён**: его сторож
> `TaktKeywordSyncTest` живёт в Gradle-сборке, которая вне `precheck.sh`/CI
> (пусковой JDK 17…26 — измеренный диапазон фичи
> [0224](docs/features/0224-intellij-kotlin-upgrade.md)), — там работает только
> дисциплина правила 29. Плагин
> **Zed** своих списков не ведёт (`language_servers = ["takt-lsp"]`) и правок не
> требует, но и наследует все дефекты сервера.

> **`from` — КОНТЕКСТНОЕ ключевое слово, и оно не единственное**
> ([0385](docs/features/0385-contextual-from.md), версия языка 0.12.0). Слово
> встречается в языке ровно в одной форме — директиве импорта, — но было
> жёстким: `struct Line { from: u8, to: u8 }` давал `SY-002` прямо на
> объявлении поля. Приём тот же, что у семи слов LTL: продукция в правиле
> `Identifier`; лексема и терминал сохранены (изымать надо терминал, а не
> лексему — урок 0201). ⚠️ **Сплошной замер (2026-08-22):** из 47 слов лексера
> контекстны **восемь**, прочие 39 жёсткие — их список в анализе фичи.
> ⚠️ **Расширение языка ОТКРЫЛО дыру у цели `st`:** в IEC `FROM` и `TO` —
> ключевые слова диапазона, и вывод отвергался `iec2c` при нулевом коде
> возврата; заведён список `IEC_RESERVED_FIELD` и проверка имени **поля**.
> ⚠️ **Список полей СВОЙ, и это замер:** из 79 имён `IEC_RESERVED` поле
> принимает **52** (стандартные функции внутри `STRUCT` ни с чем не
> сталкиваются) — общий список дал бы ложные отказы (урок 0378-01).
> ⚠️ Дыра была шире фичи: `var to: u8;` ломал вывод `st` и до неё.
> ⚠️ Гейт лексики сам назвал **два** места документа (раздел «Лексика» и
> приложение «Грамматика») — ради этого 0160/0298 и заведены.

> **Лексема без правила — дефект, и его ловит машина** (фича
> [0201](docs/features/0201-dead-lexemes.md)). Слово в `KEYWORDS`, которого нет
> в extern-блоке грамматики, даёт `SY-002` при употреблении, **обещая**
> конструкцию из шести списков, что по `KEYWORDS` выравниваются. Так жили
> `string` и `template`, а `pragma` — на уровень глубже (вариант `Token` без
> слова в таблице: недостижим и он, и его механизм). Сторож —
> `takt-lang/tests/syntax/dead_lexeme_tests.rs`, сверка идёт **в обе стороны**: слово
> без терминала (класс A) и терминал без правила (класс B).
> ⚠️ **Имя типа ключевым словом быть не обязано** — `bit`, `bool`, `u8`, `q` им
> не являются, типы в грамматике суть `Type: Alias(Identifier)`. Поэтому
> `var bit: u8 := 1;` законен, а строковый тип, если понадобится, вводится
> одной строкой в `builtin_type_by_name` (как `duration` в 0134): держать слово
> ключевым ради будущего типа **не нужно**.
> ⚠️ **Неиспользуемый терминал — не «надгробие» изъятой конструкции.** Замер
> 0201 на двух редакциях грамматики: текст диагностики от объявления **не
> зависит** (байт-в-байт), зато объявление добавляет вторую, **каскадную**
> ошибку. Изымая оператор, оставляй **лексему** (иначе `==` распадётся на `=` и
> `=` — сообщение о следствии), но **не** терминал.

## Форматтер

Ядро печати — `takt-lang/src/format/` (`format_source`), потребители: `taktc fmt`
(`--check`/`--stdin`) и LSP `textDocument/formatting`. `precheck.sh` проверяет
канон `examples/` (фикстуры `tests/data/` намеренно не нормализованы — тесты
завязаны на их позиции). Правило «добавил узел АСД — добавь его печать» и устройство
сторожа корпуса — во врезке раздела «Добавление конструкции языка».

⚠️ **Канон описан словами** — раздел «Стиль кода» документа (фича
[0197](docs/features/0197-language-code-style.md)). Машинной сверки «текст ↔
форматтер» нет и построить её в общем виде нельзя, поэтому фича, меняющая
поведение `taktc fmt`, **обязана** проверить этот раздел: разошедшись, он станет
обещанием, которого инструмент не исполняет. Примеры раздела прогоняет гейт
документа (0133), но правила словами — на человеке. Цена измерена фиксом
[0197-01](docs/fixes/0197-01-kr-else-cond-case-enum-lines.md): смена трёх правил
затронула **пять** записей канона — печать `format/`, слой `style/naming.rs`,
свод в `book/src/21-code-style/`, описание `CS-001` в приложении об ошибках и
таблицу отступлений в карточке 0197.

**Раскладка — K&R** (фикс 0197-01): `} else {`, цепочка **плоская**
(`} else if c {`). Склейку строк делает `Out::join` — снимает уже поставленный
`'\n'` и взводит `glued`, из-за которого следующая `line` идёт без отступа.
⚠️ Флаг нужен потому, что заголовок звена печатает **рекурсивный** `stmt::print`,
не знающий, что его позвали из ветки `else`; `blank` при взведённом флаге
подавлена, иначе восстановление пустой строки разорвало бы `} else `.

**Перечисление и структура печатаются по элементу на строке** (`print_enum` —
фикс 0197-01, `print_struct` — фикс
[0198-01](docs/fixes/0198-01-struct-comment-placement.md); устройство у них
одно). ⚠️ **Висячей запятой быть не должно**: грамматика — `CommaOne<EnumVariant>`
и `Comma<StructField>`, и напечатанная запятая делает файл неразбираемым (класс
0199-01 — `fmt` пишет на месте). ⚠️ Заголовок печатается `line`, закрывающая
скобка — `node_line(&loc, "}")`, а варианты/поля — `node_line_within(…, brace)`
с границей по байту самой `}`: `loc` записи покрывает её **целиком**, поэтому в
однострочной форме хвостовой комментарий стоит на той же строке, что и каждый
вариант, и без границы его забрал бы первый — а печать перестала бы быть
идемпотентной.

⚠️ **`out.line` в печати элемента модели — сам по себе дефект привязки.**
Комментарии выдают только `node_line`/`node_line_within`/`comments_before`;
ведущие комментарии самой записи спасает общий вход `print_element`, поэтому
обход виден не сразу — страдает то, что живёт **внутри** записи и на строке `}`.
Так дефект и пережил фичу 0198 (она шла по печати **операторов**) и фикс 0197-01
(он переписал соседнюю ветку `Enum`).

**Ведущие комментарии оператора выдаёт ОДНА точка — `stmt::print`** (фича
[0406](docs/features/0406-format-comment-before-block.md)). Прежде их выдавал
только `Out::node_line`, а он печатает **неблочные** операторы: у блочных
заголовок идёт через `line`, и комментарий, написанный перед `if`/`while`/
`match`/`assembly`/`formula`, всплывал первой строкой ТЕЛА — менял хозяина, а
пустая строка перед оператором терялась. Теперь `print` = `blank_before` +
`leading_for` + `print_inner`. ⚠️ **`node_line` для заголовка не годится:** он
берёт и хвостовой комментарий по концу позиции, а она у блочного оператора
покрывает весь оператор **вместе с телом**. ⚠️ **Ветвь `else` зовёт
`print_inner`:** там строка ждёт продолжения (`} else `), и выдача в неё рвёт
K&R (`} else // комментарий`); сторож на это добавлен **после** мутации —
первая редакция её не ловила, потому что в цепочке без комментариев выдавать
нечего. ⚠️ Комментарий между `}` и `else` остаётся внутри тела ветки —
названная граница: своей строки у ветки в каноне нет. ⚠️ Четвёртое место
класса (0198, 0197-01, 0198-01, 0295); вывод корпуса не изменился —
комментариев в этой позиции в `examples/` не было.

**Закрывающая скобка тела печатается ОДНОЙ функцией `close_body`** (фича
[0295](docs/features/0295-format-element-comment-binding.md)): она выдаёт
хвостовые комментарии и печатает `}` через `node_line`. Комментарий последней
строкой тела принадлежит **этому** телу; без явной выдачи его подхватывает
`leading()` следующего элемента, а при отсутствии следующего — всплывает в
конец файла. ⚠️ Класс правился **трижды и каждый раз в своей ветке** (0198 —
операторы, 0197-01 — перечисление, 0198-01 — структура), и замер 2026-08-19
нашёл его живым ещё в двух: состояние и вложенная модель. ⚠️ Сторож
двухслойный (`takt-lang/tests/syntax/format_comment_binding_tests.rs`):
поведение — по **отступу** комментария (проверка порядка строк дефект **не
ловит**: уезжая, комментарии сохраняют взаимный порядок), устройство — греп по
`format/mod.rs`, падающий списком мест. ⚠️ Корпус класс не покрывает —
комментариев внутри таких записей там ноль.

**Синонимы не канонизируются:** `while`/`loop` и `: [Guard] x;`/`: x;` — АСД
хранит выбор автора (`ast::LoopKeyword`, `Guard::explicit`); семантика эти
признаки игнорирует.
