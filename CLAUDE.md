Живой контекст проекта для сессий Claude Code (claude.ai/code) и других
AI-инструментов. Здесь — **только контекст** (что за проект, архитектура,
ключевые файлы, инварианты, состояние), без правил процесса.

- **Правила работы — эталон:** [`docs/RULE.md`](docs/RULE.md). Процесс = жизненный
  цикл фич; `FEATURES.md` — витрина незакрытых фич, карточки фич — в
  `docs/features/`. Плоских списков задач (`TASKS.md`/`STATUS.md`) нет.
- **Правила написания Rust-кода:** [`docs/CODE.md`](docs/CODE.md).
- **Журнал изменений:** [`CHANGES.md`](CHANGES.md) (формат Keep a Changelog).
- **Описание языка (для пользователя):** [`book/`](book/) — **Typst** → PDF (шрифт
  Fira Code), сборка `make -C book build` → `book/book/pdf/takt-language.pdf`
  (нужен только `typst` ≥ 0.13; сборка — шаг `precheck.sh`, фича 0240). Содержит **только язык** (синтаксис/семантику/примеры), без
  деталей реализации, номеров фич и процесса (**правило 24**). Каждая языковая фича
  проходит стадию «Документирование»; каждый новый раздел — отдельная фича. Фича
  0101 завела инфраструктуру + seed «Обзор»; разделы 2–15 — фичи-преемники.

> **Завершение фичи → коммит + пуш (стойкое разрешение проекта).** Закончив
> работу над фичей (стадия закрытия: статус `ГОТОВО`, документы обновлены,
> `./scripts/precheck.sh` зелёный), **закоммить и запушь** изменения без
> дополнительного запроса. Это переопределяет дефолт AI-инструмента «коммить и

## Проект

**Takt** (Typed, Automata, Known Timing) — DSL для спецификации и синтеза конечных
автоматов (FSM) промышленных систем управления. Цели генерации: `c`/`c-hal`
(прошивка МК), `st`/`st-at` (ПЛК, IEC 61131-3), `rust` (`no_std`), **`sv`**
(синтезируемый SystemVerilog — FPGA/ASIC) и `plantuml` (диаграмма).
Rust-workspace из двух крейтов:

- `takt-lang` — компилятор (бинарник `taktc`) и LSP-сервер (`takt-lsp`).
- `takt-sim` — симулятор моделей и GIF-визуализация.

## Команды

```sh
# Сборка
cargo build --bin taktc
cargo build --features lsp --bin takt-lsp

# Канонический форматтер .takt (фича 0024)
cargo run --bin taktc -- fmt examples/          # на месте
cargo run --bin taktc -- fmt --check examples/  # проверка для CI (код ≠ 0 при отличии)

# Тесты (параллельно — фича 0190 сняла `--test-threads=1`)
cargo test
cargo test --all-features                       # включая тесты LSP
cargo test <имя>                                # один тест по имени

# Предкоммит-проверка (fmt + check + clippy + test + сборка примеров), ~230 с
./scripts/precheck.sh

# Прогон всех симуляций из examples/simulations/
./scripts/run_simulations.sh
```

**Толчейн и CI** описаны один раз — в разделе «Документ и процесс»: пин
`rust-toolchain.toml` (стабильный `1.97.1`) и прогон всего `precheck.sh` под
`PRECHECK_STRICT=1`. Здесь только то, чего там нет: `Cargo.lock` **отслеживается**
(workspace даёт бинарники, а `lalrpop` берётся из git — без lock состав
зависимостей плавает), `resolver = "3"`, MSRV `rust-version = "1.97"` в обоих
манифестах (нижняя граница не измерялась).

**Внешние зависимости** (для сборки и тестов `taktc` не нужны — только для
проверки порождённого кода):

- `cmake` + `ninja` + `cc` — гейт цели `c` в `precheck.sh`.
- **MatIEC `iec2c`** — арбитр валидности порождённого ST (фича 0041):
  единственный автоматизируемый способ доказать, что ST валиден. Пакетом **не
  поставляется**; ставить руками не надо — `precheck.sh` зовёт
  `scripts/ensure-iec2c.sh`, который при отсутствии собирает из исходников в
  `~/.local/bin/iec2c` (≈15 с). Скрипт **никогда не валит предкоммит**: нет
  сети/bison → мягкий пропуск. Переменные: `IEC2C_PREFIX` (`~/.local`),
  `IEC2C_SRC` (`~/.cache/matiec`), `IEC2C_SKIP=1`.

  ```sh
  ~/.local/bin/iec2c -I ~/.local/share/matiec/lib -T <вывод> файл.st  # 0 = валиден
  ```

  ⚠ **`-I` обязателен:** `make install` MatIEC ставит только бинарники
  (`install-data-am` пуст), а без `lib/ieclib.txt` `iec2c` падает на любом входе.
  Скрипт копирует библиотеку в `$PREFIX/share/matiec/lib` сам. Гейт по
  порождённым `.st` включён и зелён (8/8 корпуса); ручные пробы —
  `takt-lang/tests/data/st/probes/*.st`.

## Архитектура

Конвейер компиляции: `.takt` → **лексер** (`parser/lexer.rs`) → **парсер**
(LALRPOP LR(1), `grammar.lalrpop`) → AST (`parser/ast.rs`) → **семантика**
(7 проходов, `semantic/`) → **генераторы** C (`generator/c/`) и PlantUML
(`generator/plantuml/`). Верификация свойств — `verification/` (LTL, автоматы Бюхи).

### Семантические проходы (по порядку)

| Проход | Файл | Назначение |
|---|---|---|
| 0 | `tree.rs` | Имена моделей/состояний, загрузка импортов |
| 1 | `tree.rs` | Составные состояния (`M1 + M2`, `M1 \| M2`) |
| 2 | `type_inference.rs` | Переменные, вывод типов, порты |
| 3 | `tree.rs` | Именованные условия (`cond`) |
| 4 | `tree.rs` | Именованные блоки (`enter`/`exit`/`always`) |
| 5 | `tree.rs` | Тела функций |
| 6 | `tree.rs` | Замена `Condition::Unresolved` разрешёнными условиями |

### Критические инварианты (НЕ нарушать)

Чек-лист перед правкой ядра. Каждый пункт подробно разобран ниже, в
«Технических подводных камнях», — здесь только имя инварианта, чтобы шесть самых
дорогих были видны вместе.

⚠️ **Связь двусторонняя и сторожится машиной**
([0289](docs/features/0289-claude-md-invariant-checklist-gate.md)): подробный
пункт несёт метку `` `[критический инвариант N]` ``, и
`scripts/check-claude-md.py` требует, чтобы номера чек-листа и метки совпадали
**в обе стороны**. Прежде запись надо было внести дважды, а забытую половину
никто не ловил — класс 0084/0193/0195, только списки не в коде, а в контексте.

1. **Условия рёбер `ref` не разрешаются** — прохода `resolve_state_references`
   не заводить (раздел «Семантика и диагностика»).
2. **`Condition` и `Expression` не унифицировать** — у них разная семантика `=`
   (там же).
3. **Присваивание `:=`, сравнение `=`, `==` из языка выведено** (там же).
4. **Адрес порта: inline `:=` < оператор `address` < внешняя карта** — вместе с
   квалификацией ключа, диапазоном бита и экспортом (раздел «Цели генерации»).
5. **Вход в стартовое состояние не расходует такт** — контракт для всех
   бэкендов (там же).
6. **Model-level `always` исполняется каждый такт** до диспетчеризации
   состояния (там же).

### Общее

- **Пути** — через `std::path::Path`, не разбивкой строк. При генерации C явно
  обрабатывай анонимные/корневые модели (получают имя `Root`) и пустые случаи.
- **Новые тесты** — сперва зонд для захвата реального вывода, затем проверки
  против захваченного. Не угадывать строки, адреса и позиции.
- **Сторож фикстуры проверяет её ОБЕЩАНИЕ, а не факт разбора**
  ([0288](docs/features/0288-fixture-guards-audit.md)). Замер 2026-08-20: из 62
  тестов на `tests/data/**/valid/` **28** только констатировали построение —
  такой тест зелен и в мире, где обещанное не работает (так было с выводом типа
  по ссылке до 0204; класс фикса 0010-01). Ратчет — `scripts/check-fixture-guards.py`
  плюс реестр `scripts/fixture-guard-baseline.txt`: новая констатация (`F1`) и
  протухшая запись (`F2`) роняют предкоммит. ⚠️ **Проверять «в дереве нет
  `Unresolved`» нельзя**: условия рёбер `ref` остаются неразрешёнными по
  инварианту — смотреть надо тело блока. ⚠️ Искать узел надо **там, где он
  написан**: индексация — в инициализаторах объявлений, перечисление — во
  вложенной модели (первая редакция сторожей искала не там и падала).
- **Разрешение переменных** проверяй в обоих путях — верхнеуровневый и вложенный
  доступ к модели (включая `tick`/`init`): починка одного пути часто ломает другой.
- **Поведение цели сверяется потактово, а не только компилируется.** Сверки —
  `takt-sim/tests/conformance_{c,sv,rust,st}_tests.rs`. ⚠️ Гейт целевого языка
  (rustc/clippy, verilator/yosys, iec2c) доказывает, что вывод **компилируется**,
  но не что он **верен**: молча неверная трансляция компилируется тоже. Правило:
  **сверку заводить вместе с бэкендом** — у [0045](docs/features/0045-sv-backend.md)
  дефект приняли молча оба инструмента SV, у [0050](docs/features/0050-rust-backend.md)
  сверки не было вовсе при зелёном гейте.
- **Тесты идут ПАРАЛЛЕЛЬНО; временный каталог теста уникален по тесту**
  ([0190](docs/features/0190-precheck-selective-gates.md)). Прежде предкоммит
  гонял `--test-threads=1` «из-за гонок за общие файлы»; замер показал, что
  гонок было **две**, обе в `st_tests`: каталог строился по фикстуре
  (`types_all`, `enum_struct` — их берут по 2–3 теста) и по имени входного
  файла (одно имя на два теста), а каждый помощник начинает с `remove_dir_all`.
  Ключ уникальности — имя потока (`std::thread::current().name()`: харнесс
  Rust называет поток именем теста); в однопоточном режиме имени нет, и ключом
  остаётся фикстура. Замер: 146 с → 95–127 с при 12 ядрах, а `cargo test` был
  тогда **84 % времени предкоммита** (сегодня — **65.6 %**, замер ADR 0242).
  ⚠️ Покраснел параллельный прогон — чини **каталог теста**, а не возвращай
  флаг: возврат прячет гонку и возвращает всю стоимость разом.
- **Интеграционные тесты — ОДНА цель на тему, набор внутри остаётся файлом**
  ([0244](docs/features/0244-test-target-build-cost.md)). Тем семь:
  `takt-lang` — `semantic` (51 набор), `targets` (26), `syntax` (13), `lsp`
  (12), `verify` (2); `takt-sim` — `conformance` (27), `sim` (20). Файл темы —
  `tests/<тема>/main.rs`, он только объявляет `mod`; сами наборы лежат рядом
  своими файлами, поэтому правило размера модуля не задевается, а имя теста
  несёт префикс набора (`cargo test --test targets c_stub_tests::`).
  ⚠️ Причина — **замер**, а не порядок: первый запуск свежесобранного тестового
  бинарника стоит **0.60 с при загрузке ЦП 2 %** (проверка кода ядром, чтение с
  диска, работа динамического загрузчика), повторный — 0.033 с; бинарников было
  **147**, и в гейте каждый запускается впервые. ⚠️ **Новый набор кладётся в
  тему и объявляется в её `main.rs`** — файл, положенный в `tests/` верхнего
  уровня, снова станет отдельной целью и вернёт свою долю стоимости молча.
  ⚠️ **Это сторожит машина** ([0271](docs/features/0271-test-target-gate.md)):
  `scripts/check-test-targets.py` ловит `.rs` в `tests/` верхнего уровня (`T1`),
  набор темы **без `mod`** в её `main.rs` (`T2` — такой набор не собирается и не
  запускается вовсе, а `cargo test` рапортует об успехе; кандидат этого класса
  не называл) и тему без `main.rs` (`T3`).
  ⚠️ **Имя потока теперь несёт `::`** — набор, строящий по нему временный
  каталог (инвариант 0190), обязан вычищать двоеточие: `.replace(':', "_")`.
  ⚠️ Пути в `include_str!` внутри набора отсчитываются от его файла и стали на
  уровень глубже — это ловит компилятор, молча не уедет.
- **Генерация детерминирована** ([0048](docs/features/0048-deterministic-codegen.md)).
  Порядок эмиссии задаётся **типом контейнера** (`BTreeMap`/`BTreeSet`), а не
  сортировкой на выходе: локальная сортировка не спасает, если внешний цикл
  недетерминирован. Сторож — жёсткий гейт в `precheck.sh` (два прогона × все цели
  → `diff -r`). Следствие: дифф `examples/generated/` несёт смысл, снапшоты возможны.
- **Размер модуля** — ≤ ~1000 строк вместе с тестами (правило в `docs/CODE.md`,
  фича [0091](docs/features/0091-module-size-rule-in-code-md.md)). Проверяет
  `scripts/check-module-size.sh`; с [0261](docs/features/0261-module-size-warning-zone.md)
  он печатает **жёлтую зону** (`970…1000` строк, список с остатком запаса) —
  предупреждение **не влияет на код возврата**, иначе прогон падал бы за 30
  строк до предела в чужой правке. ⚠️ Порог выбран замером: при 950 в зоне 15
  файлов, при 900 — 23, при 970 — восемь; сегодня ближайший
  `generator/sv/sv_expr.rs` — 1000 строк, **запас 0**. ⚠️ Самопроверки у гейта
  не было с 0027 — теперь есть `scripts/test-module-size.sh` (мутация на
  временном дереве через `MS_ROOT`); реестр `scripts/module-size-baseline.txt` —
  **узаконенный долг** (3 файла), запись оттуда не имеет права расти, а уложившийся
  в лимит обязан быть удалён. ⚠️ Правя большой файл, готовься к отказу «вырос»:
  это замысел — выносить новое в отдельный модуль.
- **Генератор фич `scripts/new-feature.sh` идемпотентен**
  ([0094](docs/features/0094-new-feature-script-fixes.md)): повторный `--register`
  не дублирует строки реестров. Добор стадии — `--stage NAME`, подзадача —
  `--stage dev --subtask NN`. Регресс — `scripts/test-new-feature.sh` в предкоммите.

### Семантика и диагностика

- **Параметр модели — поле экземпляра, а под `--parameters=specialize` —
  константа копии** ([0185](docs/features/0185-model-parameters.md), версия языка
  0.8.0). `parameter Y: u8 := 100;` живёт в `variables` обычным
  `VariableNode::Simple` (потребитель, ничего не знающий о параметрах, обращается
  с ним верно); отличие — в `ModelNode::parameters` (имя, позиция, **порядок** —
  по нему строится ключ дедупликации). Аргумент `M(Y := выражение)` **вычислен**
  (`semantic/const_eval/`) и понижен в литерал: за границей семантики выражения
  аргумента не существует. ⚠️ Флаг меняет **форму** вывода, не поведение — сторож
  R11 сверяет **четыре** трассы (симулятор и цель `c` в обоих режимах,
  `takt-sim/tests/conformance/conformance_param_modes_tests.rs`); гейт предкоммита требует
  «флаг не наблюдаем» от примеров **без** параметров и «специализация
  детерминирована» от параметризованных. ⚠️ Проход константности
  (`semantic/parameter_const.rs`) стоит **после специализации и до стадии 2**:
  позже пришлось бы править оба представления переменной (засада 0096) и опоздать
  к `after` (0143) и адресу порта (0042); анализ изменяемости идёт по **именам**
  — затенение делает параметр «изменяемым», то есть ошибка только в безопасную
  сторону. ⚠️ Параметр там, где нужна величина сборки, под `assign` — **`SE-088`,
  называющий режим**; прежде `after PARAM` молча становился вычисляемой
  выдержкой. ⚠️ Специализация модели с вложенными моделями — `SE-087`; равенство
  `ParameterArgument` **игнорирует позицию** (иначе `SV-016` отвергал одинаковые
  наборы).

- **Ошибка разрешения оператора не зависит от глубины вложенности**
  ([0155](docs/features/0155-semantic-nested-statement-resolution.md)).
  `semantic/statement/mod.rs` пробрасывает ошибку `?` во **всех** телах (`if`/`else`,
  `while`/`loop`, `for`, inline-`Guard`). ⚠️ Возвращать
  `.unwrap_or_else(|_| Unresolved(…))` нельзя: цель `c` печатает `Unresolved`
  **пустотой**, симулятор пропускает — терялась не диагностика, а **сам оператор**.
  Сторож — `takt-lang/tests/semantic/nested_statement_resolution_tests.rs`.
- **Глубина вложенности ограничена** `MAX_NESTING_DEPTH = 32`, превышение →
  `SE-062` ([0129](docs/features/0129-semantic-deep-nesting.md)). Сторожа стоят в

  нет** ([0207](docs/features/0207-bitwise-not-unsigned-literal.md), версия
  языка 0.9.0). Беззнаковое — обёртка `mod 2ⁿ` (правило 0127), знаковое —
  ошибка `SE-089`. Цена прежнего устройства: свёртка (0192) считала `~0` в
  `i128` и давала `-1`, проверка диапазона (0157) его отвергала — и `~0` был
  законен **в теле** (255 у эталона, `c`, `rust`) и запрещён в объявлении.
  ⚠️ После свёртки вычисленное значение **неотличимо** от написанного автором,
  поэтому разделяет их свёртка — существующим `is_literal` (он же защищает
  понижение `q`, 0096); `var u: u8 := 300;` остаётся ошибкой, а
  `var u: u8 := 200 + 100;` даёт `44`, как та же запись в теле. ⚠️ Границы —
  у **одного** носителя (`validate::literal_range::type_range`): своя копия
  разошлась бы с `SE-089`.
- **Инициализатор `var`/`const` доезжает до потребителей ЛИТЕРАЛОМ**
  ([0192](docs/features/0192-const-init-fold.md)). Свёртку делает существующий
  `semantic/const_eval/` (0185) — тем же приёмом, каким 0187 свернула начальное
  значение порта, а 0143 — константную выдержку: за границей семантики выражения
  не существует, и расходиться потребителям **не по чему**. Цена прежнего
  устройства: `var a: u8 := 1 + 2;` означало **пять разных** вещей — эталон `0`
  (арифметика была «не константа»), `c`/`rust` `3`, `st` теряла значение молча,
  `sv` отказывала. Имя переменной в инициализаторе значит её **начальное
  значение** и ссылается только **назад по тексту** (решение заказчика).
  ⚠️ **Порядок трёх шагов обязателен** и собран в одном месте
  (`declaration::prepare_variables`): разрешить → вывести типы → **свернуть**.
  Свернув раньше вывода типов, получишь `bool` вместо `bit` (значение верное,
  тип нет). ⚠️ **Литерал не подменяется** — дробный к этому моменту уже понижен
  в q-представление (0096), и «свёртка» вернула бы его в дробный вид; но
  **значение его запоминается всегда**, иначе `var base := 5; var probe := base
  + 1;` молча даст `0`. ⚠️ Послабление «имя вычислимо» живёт в наполнении
  `const_eval::Locals`, а **не** в `resolve_name`: тот же вычислитель обслуживает
  `after` (0143), параметры (0185) и порты (0187), где «значение известно только
  в такте» — верное правило. Сторожа — значенческие
  `takt-lang/tests/semantic/const_init_fold_tests.rs` и потактовые сверки Q-арифметики
  (поймали обе перестановки; чтение кода не поймало ни одной).
- **Обходы по числу состояний — итеративные, не рекурсивные**
  ([0052](docs/features/0052-verify-iterative-traversal.md)): рекурсия роняла
  инструмент `SIGABRT` без диагностики. Сторож — `deep_model_tests.rs` (2 МБ стека
  в потоке теста). ⚠️ `expand` в `buchi.rs` рекурсивен **осознанно**; `outer_dfs`
  делает работу **после** потомков — нарушение постпорядка даёт **неверный вердикт**.

### Типы и представление

- **Носитель числового значения — `i128`; граница приёма литерала — ТИПЫ языка**
  ([0157](docs/features/0157-literal-u64-representation.md)). `Token::Number` →
  АСД → `ExpressionNode`/`ConditionNode` → `eval::Value::Number` несут `i128`;
  приём — `[i64::MIN, u64::MAX]` (объединение диапазонов самого широкого
  знакового и самого широкого беззнакового типа), вне — `LE-009`. Границы и
  восстановление после отказа — `parser/literal_range.rs`. ⚠️ Носитель шире
  приёма **намеренно**: промежуточный результат константного вычисления не
  должен переполняться там, где итог по типу законен. ⚠️ Значение варианта
  перечисления — тот же `i128`: второй носитель числа завёл бы границу между
  ними. ⚠️ Обёртка `u64` работает через **общий** путь `coerce_integer` —
  спецслучая «bits >= 64» больше нет (он и давал `SIM-004` вместо обещанной
  0127 обёртки). ⚠️ Адрес порта остался `i64`: литерал шире сужается **явным**
  отказом `SE-055`, а не `as i64`.
- **Литерал вне диапазона типа приёмника — `SE-089`**
  ([0157](docs/features/0157-literal-u64-representation.md),
  `semantic/validate/literal_range.rs`). Проверяются позиции с **объявленным**
  типом (инициализатор `var`/`const`, присваивание переменной); проверка
  накопительная. ⚠️ `bit`/`bool` пропущены намеренно — их значения проверяет
  `validate_bit_values`, иначе две диагностики об одной причине. ⚠️ Проверяется
  **литерал**, не значение выражения: свёртки констант в семантике нет.
- **Печать широкого литерала зависит от цели**
  ([0157](docs/features/0157-literal-u64-representation.md)). `c` — суффикс
  `ULL` выше `LLONG_MAX` (`generator/c/c_literal.rs`), иначе
  `-Wimplicitly-unsigned-literal` под `-Werror`; `sv` — размерная форма
  `<W>'d<value>` по ширине **приёмника** (`sv_type::sized_literal`), иначе
  `WIDTHEXPAND` **уже с 33 бит**; `st`/`rust`/`plantuml` — как есть (доказано
  гейтами `iec2c` и `rustc -D warnings`). ⚠️ Особая форма печатается **только**
  по нужде — иначе поехали бы снапшоты `examples/generated/`. Сторож —
  `takt-lang/tests/targets/wide_literal_tests.rs` (эмиссия + настоящие гейты).
- **`[bit;N]` — упакованный вектор** ([0078](docs/features/0078-bit-array-semantics.md)):
  скаляр при N ≤ 64, массив `uint64_t[⌈N/64⌉]` при N > 64. Правило — в едином слое
  `semantic::bit_vector`.
- **Fixed-point `q(m, n)`: арифметика ПОБИТОВО едина** у симулятора и всех целей
  ([0061](docs/features/0061-fixed-point-type.md)). Эталон — `takt-sim/src/eval/fixed.rs`;
  `*` — floor к −∞, `/` — к нулю. ⚠️ Цель `c`: floor эмитится **не сдвигом**, а
  хелпером `lam_q_floordiv` — `>>` знакового отрицательного в C
  implementation-defined (C11 6.5.7p5); сторож — греп «в порождённом C нет `>>`».
  ⚠️ Цель `st`: сдвигов над числами в IEC нет вовсе. ⚠️ Цель `rust`: `x := x * y`
  над `q` НЕ сворачивается в `x *= y`. Сверки — `conformance_{c,rust,st,sv}_tests`.
  ⚠️ **Перенос идёт к `W = m + n`, а НЕ к ширине хранения**
  ([0061-01](docs/fixes/0061-01-q-wrap-storage-width.md)). Тип хранения
  округляется вверх до 8/16/32/64 (в C нет `int12_t`), и три цели выражали им
  границу переноса: на `q(6, 6)` эталон давал −26.0, а `c`/`rust`/`st` — 38.0
  (цель `sv` была права: `logic signed [W-1:0]`). Дожило из-за дыры в
  **покрытии** — корпус и фикстуры состоят из `q(8, 8)` и `q(4, 4)`, где обе
  границы совпадают. Теперь перенос эмитится явно и **только при `W ≠ S`**
  (иначе поехал бы вывод корпуса): `lam_q_wrap` в C, пара сдвигов в Rust,
  `LAM_Q_WRAP` на `MOD` в ST; при `W ≥ 63` цель `st` отказывает `ST-021` —
  модуль `2^W` в `LINT` непредставим. ⚠️ Дефект достижим и через
  `--float-as-q=m.n` (0096): флаг принимает любые `m`/`n`.
- **Насыщение — свойство ТИПА: `q(m, n) sat` прижимает, `q(m, n)` переносит**
  ([0170](docs/features/0170-fixed-point-saturation.md)). Признак — поле
  `TypeNode::Fixed { m, n, sat }` и зеркальное `Value::Fixed`, то есть часть
  **формата**: смешение `sat` и не-`sat` запрещает существующий `SE-059`
  (отдельный код заводить не стали — два места, обязанные давать один вердикт),
  явное `as q(m, n) sat` законно. Развилка одна на реализацию (`make` эталона,
  `open_wrap`/`close_wrap` у `c`, `wrap_to` у `rust`, `wrap_lint` у `st`,
  `saturate_sv` у `sv`); хелпер эмитится по факту вызова, поэтому вывод корпуса
  не изменился. ⚠️ Слово после формата, отличное от `sat`, — **`SE-104`**: без
  отказа опечатка (`q(8,8) sta`) вернула бы молчаливый перенос вместо
  запрошенного насыщения. ⚠️ **Прижатие идёт до сужения**: у `st` — в `LINT`
  перед `LINT_TO_{S}`, у `sv` промежуток считается в `2W` (в `W` места нет);
  иначе сравнение с границами идёт по уже обёрнутому значению, и оба
  инструмента такой вывод принимают молча. ⚠️ Насыщение эмитится **всегда**, а
  не только при `W ≠ S` (в отличие от переноса): границы формата типу хранения
  неизвестны. Сторожа — сверки значений на `q(6, 6)`, включая край
  `−(−2^(W−1))` (единственная **унарная** операция, где семантики расходятся);
  каждая проверена мутацией.
- **Прозрачный `float` через глобальную Q-точность**
  ([0096](docs/features/0096-fixed-point-native-float.md)): автор пишет `float`,
  представление выбирают флаги `--float-as-q=m.n` / `--float-embedded`. ⚠️ Это
  **осознанное исключение** из принципа «CLI не меняет логику автомата» (0042) —
  оба режима документированы и сверяются. ⚠️ **Главная засада:** `VariableNode`
  живёт в **двух** представлениях (owned в `model.variables` и за `Rc<RefCell>` в
  теле) — проход обязан мутировать **оба** `ty`, иначе объявление `q`, а арифметика
  `float`. Сторож — `variable_cell_in_body_is_retyped`. ⚠️ Литерал понижается
  **только** в инициализаторе объявления, не в телах; проход **идемпотентен** по
  гейту «исходный тип был `Rational`».
- **Сдвиг `>>` определён в целях по-разному.** В C знакового отрицательного —
  implementation-defined; в Rust арифметический; в ST сдвига над числами **нет**;
  в SV определён. Операторов `<<`/`>>` в языке Takt **нет** — фича, которая их
  введёт, обязана задать семантику **нормативно**.
- **Знак и ширина перечисления считаются общим слоем** `semantic::enum_facts`
  ([0060](docs/features/0060-enum-width-shared-layer.md)); цель `c` даёт
  `int{bits}_t` при `signed`. Прежде знак терялся молча.
- **У структуры обязано быть хотя бы одно поле — `SE-115`**
  ([0284](docs/features/0284-empty-struct-semantics.md)). Замер: `struct S { }`
  язык принимал, а вывод не принимали **чужие** инструменты — цель `c` печатала
  расширение GNU (C11 6.7.2.1; `cc -pedantic` даёт `-Wgnu-empty-struct`), а
  порождённый ST отвергал `iec2c` («no structure element declared»). Эталон при
  этом исполнял. ⚠️ **Гейт класс не видел по устройству**: он гоняет `cc`
  **без** `-pedantic`, а в корпусе пустых структур нет ни одной. ⚠️ Контроль
  обязателен и он же отделил причину: **непустая** структура проходит оба
  инструмента. ⚠️ Квантификатор грамматики (`Comma<StructField>`) оставлен
  намеренно — правило языка не должно быть свойством LR-разбора (урок 0172).
  ⚠️ Цели `rust` и `sv` в замер **не входят**: они не переводят структуры
  вовсе (`RS-014` на любой, висячая ссылка на необъявленный тип у `sv`) —
  соседний класс, вынесенный кандидатом.
- **У перечисления обязан быть хотя бы один вариант — `SE-105`, и судит
  СЕМАНТИКА** ([0172](docs/features/0172-empty-enum-semantics.md)). Прежде
  `enum E { }` отвергала **грамматика** (`CommaOne<EnumVariant>`), то есть
  правило языка было свойством квантификатора, а текст — внутренностью
  LR-разбора; смена квантификатора изменила бы язык молча. ⚠️ Отказ стоит на
  **объявлении**: при использовании сообщение вырождалось в `SE-043`
  «…(допустимые варианты: )» — про пустой список не говорилось ничего.
  ⚠️ `None`-ветви `enum_facts` у четырёх целей **сохранены** (`c`/`st`/`rust` →
  8 бит без знака, `sv` → `SV-004`): изменилась причина их недостижимости.
  ⚠️ Мутация опровергла комментарий «проверка стоит раньше соседней намеренно» —
  порядок сообщений задаёт `diagnostics::normalize` по позиции в тексте, а не
  порядок проверок в `validate_model_all`.
- **Структуры переводят ВСЕ цели, и форма агрегата у каждой своя**
  ([0293](docs/features/0293-struct-in-st-rust.md)). `c` — `struct`, `st` —
  `TYPE … STRUCT` с инициализатором `(поле := значение, …)`, `sv` —
  `typedef struct packed` с конкатенацией `{8'd2, 8'd3}`, `rust` — `pub struct`
  с литералом `Gains { kp: 2, ki: 3 }`. Прежде три цели не шли дальше
  объявления: `st` **молча теряла** инициализатор (в корпусе — коэффициенты
  `pid_heater`, и `iec2c` это принимал), `sv` печатала ссылку на необъявленный
  тип при нулевом коде возврата, `rust` отказывал `RS-011`. ⚠️ **Именованную
  форму агрегата SV отвергает yosys** (`syntax error, unexpected ':'`), тогда
  как verilator её принимает — форма выбирается по тому, что принимают **оба**
  (урок 0235); безразмерные литералы внутри `{…}` дают `WIDTHCONCAT`.
  ⚠️ **`Eq` для структуры не выводится**: у поля `float` (`f64`) его нет, и
  корпус перестал бы компилироваться. ⚠️ **Запись в поле делает переменную
  изменяемой** (`let mut`) — `collect_assigned` учитывает `r.output := …`, иначе
  `rustc` даёт `E0594`. ⚠️ Порядок полей значим у `sv` (разряды `packed`) и у
  всех агрегатов: он берётся у **объявления**, а не у карты.
- **Структурные типы**: объявленный **порядок полей значим** (не `BTreeMap`),
  инициализатор `{…}` позиционный ([0034](docs/features/0034-sim-struct-types.md)).
  Доступ к члену — общий `eval/access.rs::read_member`, запись — `eval/place.rs::update`
  (лист приводится к **типу поля**). Сравнение структур — `TypeMismatch`: C
  запрещает `==`, и симулятор «умнее» эталона врал бы. Доступ к несуществующему
  полю — компайл-тайм `SE-061`.
- **Массивы `[T;N]` исполняются симулятором** ([0076](docs/features/0076-sim-arrays.md)):
  запись элемента и запись поля структуры — **единый** сегментный механизм «места».
  Границы/вид → `SIM-010`.
- **Константная выдержка `after` вычисляется на СЕМАНТИКЕ и до целей не доезжает**
  ([0143](docs/features/0143-after-const-duration.md)). `after 3m`, `after DWELL`,
  `after (BASE + 30s)` дают один узел `ConditionNode::After(нс)` — за этой границей
  формы не существует, поэтому шесть целей не могут по ней разойтись. Вычислитель
  — `semantic/condition/after_const.rs` (литералы, константы `duration`, цепочки,
  `+`/`-`, предел глубины 32); всё прочее → `SE-072` с **названной** причиной.
  ⚠️ Аргумент живёт в грамматике **условий**: `*`, `/` и `as` там отсутствуют, а
  составное выражение обязано быть в скобках (`after` связывает крепче арифметики,
  поэтому `after A + 1s` = `(after A) + 1s`) — скобки хранятся в дереве, иначе
  печать форматтера изменила бы смысл. Сторож — не «собралось», а
  **тождественность вывода** литеральной форме во всех целях
  (`takt-lang/tests/semantic/after_const_duration_tests.rs`).
- **Тип `duration` в целях — целое в МИЛЛИСЕКУНДАХ; выдержка бывает вычисляемой**
  ([0183](docs/features/0183-duration-type-in-targets.md), в разработке;
  значения сверяются с эталоном у **четырёх** целей —
  [0215](docs/features/0215-duration-per-tick-conformance-st-sv.md) добавила
  `st` и `sv` к `c` и `rust`; ⚠️ фикстура `sv` **своя**: приведение `as` цель не
  транслирует, и значение зажимается сравнениями, включая **равенство**.
  ⚠️ Ценность сверок измерена мутацией: порча пересчёта в мс даёт вывод,
  который `iec2c` и `verilator` принимают **с кодом 0**).
  `uint32_t` / `u32` / `UDINT` / `logic [31:0]`; единица та же, что у приведения
  `as` (0134), поэтому граница «длительность ↔ число» **не порождает арифметики**
  — сторож проверяет это **текстом** вывода. Пересчёт — только
  `semantic::duration::value_millis` (`SE-063` при некратности мс, `SE-064` за
  32 бита). ⚠️ Тип `TIME` в цели `st` **не** выбран: арифметика над ним в MatIEC
  ограничена. ⚠️ **Вычисляемая выдержка** (`after (v + 1s)`, узел
  `ConditionNode::AfterExpr`) требует множителя `hertz / 1000` в профиле «такты»
  — частота, при которой он не цел, отвергается `SE-073`; в профиле «часы» цель
  `st` отказывает `ST-016` (переменный `PT` у `TON`). ⚠️ **Ширина счётчика
  выдержки поднимается до 32 бит**, если выдержка вычисляемая: иначе `rust` не
  компилируется (`u8 >= u32`), а `c`/`sv` **молча** усекают. ⚠️ Четыре обхода по
  `ConditionNode` кончаются `_ =>` и компилятором **не** охраняются: два в
  `time_ast`, `unused::collect_from_condition` (пропуск даёт ложное «переменная
  нигде не используется») и `rust_cond::condition_type` (пропуск даёт `RS-011`
  на готовом булевом выражении). В `unused.rs` таких сборщиков **два**.

### Цели генерации

- **Вход в стартовое состояние не расходует такт** `[критический инвариант 5]`
  ([0033](docs/features/0033-init-tick-alignment.md), версия языка 0.3.0). Тело
  стартового состояния исполняется на **такте 1** на любой глубине. **Контракт для

- **Генератор Rust: приоритеты C и Rust расходятся МОЛЧА**
  ([0050](docs/features/0050-rust-backend.md)). `a == b | c` даёт в C `1`, в Rust
  `false`. Поэтому печатник заключает в скобки **каждый** бинарный узел, а лишние
  внешние снимает `unwrap_outer`. Не «стиль»: **на целых дефект был бы тихим**.
  Прочие ловушки цели: `#![no_std]` в модуле не эмитится (доказывает гейт);
  перечисление в присваивании приходит **числом** (вариант восстанавливается по
  целевому типу); под-модель не получает указатель на корень — общие переменные
  свёрнуты в `<Root>Shared` ([0059](docs/features/0059-rust-shared-struct.md));
  функции получают состояние **параметрами** (`hal` — последним, иначе E0499);

  через `||`. Политика линтов — `-D warnings`: не эмитить недостижимое.
  ⚠️ `pub enum` с неконструируемым вариантом гейт **проходит** — сделать state-enum
  публичным значит заглушить сторожа видимостью. Не делать.

  сравнение `bit`-операнда с литералом сводится к самому операнду (`x = 1` → `x`,
  `x = 0` → `(!x)`), иначе получается `bool == 1` (`E0308`) либо `bool == true`
  (валит `clippy::bool_comparison`). Присваивание коэрцию делало всегда —
  разошлись два пути одной идеи.
  ⚠️ **Мёртвое начальное значение локальной переменной не печатается**
  ([0216](docs/features/0216-rust-live-printer-coverage.md)): `let mut t: u8 :=
  0;` перед записью во все ветки — это `unused_assignments`, то есть отказ
  гейта. Перезаписью считаются безусловное присваивание, `if/else` с записью в
  обе ветки, **исчерпывающий `match`** (есть ветвь `_`) и **`init` цикла
  `for`**; последние два до 0216 вердикта не давали вовсе и печатали
  невалидный по линту код при нулевом коде возврата `taktc`. ⚠️ Признать
  перезапись **мало**: отложенная форма `let t: u8;` перед `if/else` — это
  `clippy::needless_late_init`, поэтому `match` **сворачивается** в цепочку
  сравнений (`Folded::Chain`), а `for` — нет (проба: перед блоком линт её
  принимает). ⚠️ Ошибка анализа в сторону «мёртв» громкая (ошибка компиляции
  порождённого кода), в сторону «жив» — тихая; отсюда консервативность:
  `match` без `_`, `if` без `else` и цикл значение оставляют. Сторож —
  `takt-lang/tests/targets/rust_live_tests.rs` (текст вывода **и** настоящий
  `clippy -D warnings`; корпус класс не покрывает).

- **ТИП выведенного объявления берётся у ОБЪЯВЛЕННОГО операнда, а не у
  литерала** ([0287](docs/features/0287-wider-type-array-literal.md)). Таблица
  `wider_type` (`semantic/type_inference.rs`) не знала `TypeNode::Integer`
  (`u8`…`i64`) **ни в одной паре**, а литерал получает `[bit;N]`
  (`infer_int_type`) — поэтому тип литерала перехватывался ветвями `Array` и
  побеждал написанное автором. Три исхода одной причины, и два тихих: цели
  `rust`/`st`/`sv` порождали вывод, отвергаемый **чужим** инструментом
  (`E0308`, `iec2c`, `WIDTHEXPAND`) **при нулевом коде возврата** `taktc`;
  `u16 + u8` давало `Unsupported` и отказ четырёх целей на вычислимой записи;
  `const A: i16 := -300; const D := A + 1;` теряло **знак** и давало `213`
  вместо `−299` — одинаково у всех девяти. Правило: ширина — наибольшая, знак —
  знаковый, если знаков хотя бы один. ⚠️ **Ветви стоят ПОСЛЕ `Enum`/`Rational`
  и ДО `Array`**: выше — перебьют соседей, ниже — их перехватит тип литерала.
  ⚠️ **Вектор ШИРЕ объявленного целого (`n > bits`) отдан прежним ветвям**:
  правило уточняет тип источника, а не подменяет; случай «результат не влезает
  в наибольшую ширину» лечит 0285, второго знания о границах не заводится.
  ⚠️ Кандидат называл **ложную `SE-089`** — её снял 0285, но лишь как следствие
  (расширение при превышении верхней границы), и корень пережил закрытие:
  замер обязателен заново (правило 30). ⚠️ Сторож границы **был декоративен**:
  первая редакция теста брала вход, где 0285 расширяет тип независимо от
  проверяемого условия, и мутацию не ловила — годный вход тот, где результат
  влезает в **оба** типа.

  `+`, `-`, `*` над десятичными литералами (в том числе смешанные с целым)
  сворачиваются **точно** (`semantic/const_eval/decimal.rs`), и свёрнутый
  литерал идёт дальше тем же путём, что написанный автором; деление отвергается.
  ⚠️ Прежний общий отказ вычислителя был верен **наполовину**: довод
  «представление выбирают флаги, округление q задано эталоном» — про
  **округление**, а `1.0 + 2.0` есть ровно `3.0` в любом представлении. Цена
  умолчания измерена: один вход давал **три** значения — `0.0` у эталона, `3.0`
  у `c`/`rust`, молчаливую **потерю** инициализатора у `st`, а на `q(4, 4)`
  цель `c` печатала выражение в поле `int8_t`, то есть `0.1875` вместо `3.0`.
  ⚠️ **Свёрнутый дробный литерал обязан быть ПОНИЖЕН в q-представление тем же
  носителем** (`lower_fixed_literal`), что и авторский: понижение литералов идёт
  при выводе типов, то есть **до** свёртки, и `1.0 + 2.0` проходит мимо него.
  ⚠️ **Отказ узкий — только арифметика.** Первая редакция была шире и отвергала
  `var v := 3 as q(4, 4);` — вход, где эталон и цель **уже согласны** (работа
  0205); поймали это сторожа той фичи, а не чтение кода. ⚠️ Сторож — сверка
  эталона с целью `c` плюс **контрольная пара** «свёрнутое = написанное»: без
  неё «стороны сошлись» значило бы лишь, что они ошибаются одинаково.
- **Инициализатор объявления не читает НЕОПРЕДЕЛЁННУЮ память: `SE-099` (ячейка)
  и `SE-113` (порт)** ([0189](docs/features/0189-anonymous-ports.md),
  [0266](docs/features/0266-port-in-declaration-initializer.md)). Правило одно —
  инициализатор вычисляется до первого такта, а значения ни у ячейки, ни у порта
  в этот момент нет, — поэтому обход инициализаторов **один**
  (`semantic/validate/init_undefined_read.rs`), а кодов два: разный обход в
  тексте. Цена прежнего молчания измерена на порте: **три** поведения у
  принимающих потребителей и **два** отказа у остальных — ноль у эталона, чтение
  HAL-колбэка у `c`, чтение **регистра железа** у `c-hal`, молчаливая **потеря**
  инициализатора у `st`/`st-at`, `RS-022` у `rust`, `SV-002` у `sv`; при нулевом
  входе ноль и чтение совпадают случайно. ⚠️ **Нормировать эту форму нечем:**
  ветвь сброса цели `sv` выражений не вычисляет (свойство синтеза), а у эталона
  до первого такта входа нет — общего поведения не существует, отсюда запрет.
  ⚠️ Порт узнаётся по **виду объявления** (`VariableNode::Port`), а не по
  имени: вид проставлен при объявлении и от вывода типов не зависит, поэтому
  снимок в ячейке ссылки (засада 0204) здесь достоверен. ⚠️ Замеряя поведение
  `c-hal`, **дай порту адрес**: без него приходит `SE-052` и прячет настоящий
  ответ — на этом едва не перевернулся вывод фичи.
- **Инициализатор не зовёт функцию, которую компилятор исполнить НЕ МОЖЕТ, и
  причина называется** ([0306](docs/features/0306-unfoldable-call-in-initializer.md)).
  Вычислитель констант (0185) знает, что мешает — чтение переменной, порт,
  `extern`, неподдержанный оператор, исчерпанный бюджет, — а свёртка (0192)
  выбрасывала его диагностику конструкцией `let Ok(…) else`, у которой ошибки
  **нет по типу**. Замер 2026-08-20 на теле, читающем переменную модели: эталон
  `scale = 0` **молча**, `st`/`st-at` — код 0 и **потерянный** инициализатор,
  `c`/`c-hal` — `CC-023` (код дефекта инструмента), `rust` — `RS-011`, `sv` —
  `SV-002`, `plantuml` принимал. ⚠️ Признак **синтаксический** — «в записи есть
  вызов»: неразрешённое имя судит `SE-004` ниже по конвейеру. ⚠️ **Вычислимый
  вызов законен** (`var x := seed();` — на нём все девять согласны), и это
  контроль, без которого правило означало бы «любой вызов запрещён».
  ⚠️ **Место эмиссии одно:** ветвь 0305 в свёртке была **мертва** (спрашивала
  `External`, а на стадии 2 лежит `Unresolved(FunctionDefine { external })`);
  починка сделала мёртвой копию в `validate`, и та снята — сторож
  `initializer_refusal_lives_in_a_single_place`.
- **Инициализатор не зовёт ВНЕШНЮЮ функцию: `SE-084`**
  ([0305](docs/features/0305-extern-call-in-initializer.md)). Значение `extern`
  при компиляции неизвестно по определению, а начальное значение выставляется до
  первого такта. Замер 2026-08-20: эталон давал ноль **молча**, `st`/`st-at`
  печатали объявление **без** `:=` при нулевом коде возврата, `c`/`c-hal`,
  `rust` и `sv` отказывали — три ответа на один вход. ⚠️ Проверка стоит в **том
  же** обходе, что `SE-099` и `SE-113` (правило одно — обход один, урок 0203).
  ⚠️ **Форм внешней функции в ячейке ДВЕ:** на стадии 2 лежит
  `Unresolved(FunctionDefine { external: true, … })`, а не `External` — проверка
  только второй не ловит ничего. ⚠️ Вызов **локальной** функции вычисляется и
  законен; `extern` **в теле** — штатный путь. ⚠️ Следствие: причина вердикта
  `InitialValueUnknown` (0258) осталась без достижимых входов и помечена
  защитной.
- **Обращение к ячейке без имени — `#АДРЕС`** ([0189](docs/features/0189-anonymous-ports.md)).
  `#A:B as T` — поле разрядности `T` с бита `B`; `#A.B` — один бит; `#A` без
  ширины — **`SE-097`** (ширина доступа к MMIO угадыванию не подлежит, класс
  0029). Свёртка форм (`as`, `.N`) в тройку `{адрес, бит, тип}` — **в единой
  воронке** `semantic/anon_port.rs`: та же тройка, которой уже оперируют
  дефолтный HAL `c-hal` и регистровый файл `sv-mmio`; собственного
  представления фича не заводит. Запись → предупреждение **`SE-096`**, текст
  называет способ снять (объявить порт с тем же адресом); чтение молчит.
  Обращение в инициализаторе объявления → **`SE-099`**: содержимое памяти до
  первого такта неизвестно, и эталон с целью разошлись бы молча.
  ⚠️ Поддерживают **три** цели: `c-hal` (`*(volatile uintN_t*)`), `st-at`
  (размещённая глобальная `AT %M…`), `sv-mmio` (регистр файла); `c`, `rust`,
  `st`, `sv` **отказывают с причиной** (`CC-021`, `ST-018`, `SV-017`) — молчать
  им нельзя. ⚠️ Имя ячейки строит компилятор (`synthetic_name`) и оно **общее**
  у эталона, `st-at` и `sv-mmio`: разойдясь на символ, сверка трасс сравнивала
  бы разные величины. ⚠️ Эталон моделирует ячейку синтетическим портом, поэтому
  `#A as u8` и `#A as u32` для него — **разные** ячейки (перекрытие полей не
  моделируется); на плате это одна память. Сторож — потактовая сверка
  `takt-sim/tests/conformance/conformance_anon_tests.rs` (настоящая память через `mmap`).
- **Оператором-выражением может быть только форма с эффектом**
  ([0189](docs/features/0189-anonymous-ports.md), решение 6A): присваивание и
  вызов функции; `x + 1;` и `#0x100.4;` → **`SY-007`** от парсера. Прежде язык
  принимал любое выражение, а отказ приходил от **чужого** инструмента на
  порождённом файле (`cc -Wall -Werror`: `-Wunused-value`).
  ⚠️ Голый адресный литерал в выражении → **`SY-008`**: адрес есть свойство
  размещения (`at`, оператор `address`, карта). Прежде `x := 0x105:0;`
  принималось и давало молчаливое расхождение — симулятор считал адрес числом,
  а цель `c` **теряла оператор целиком**. Корень потери устранён там же:
  печатник операторов цели `c` глотал **любую** ошибку (`Err(_) => {}`), теперь
  пропускается только вызов встроенной функции.
- **Экспорт карты — `taktc address-map --emit map|json`**
  ([0043](docs/features/0043-address-map-export.md)): выгружает **фактически
  разрешённую** карту тем же `resolve_addresses`, что у `c-hal`; `map` замыкается
  круговым рейсом. Мёртвый порт → `"address": null`, не `0x0`.

### Симулятор

- **Семантика вычислений живёт только в `takt-sim/src/eval/`**
  ([0025](docs/features/0025-simulator-expression-eval.md)). Адаптеры семантики
  **не содержат**; тела блоков и функций исполняет один интерпретатор
  `unit/statement.rs::exec_statement`. Модуль `eval` под
  `deny(clippy::wildcard_enum_match_arm)`: ветка `_` по узлу языка завалит сборку —
  так задумано ([0093](docs/features/0093-wildcard-match-rule.md), гейт
  `scripts/check-exhaustive-nodes.sh`). **Второй вычислитель** (начальные значения,
  `unit/initial.rs`) под тем же `deny` с фичи
  [0163](docs/features/0163-builder-eval-exhaustive.md); гейт сторожит **оба**
  модуля и ищет атрибут **с начала строки** — иначе его находил док-комментарий,
  и модуль без атрибута проверку проходил. ⚠️ Правило названо для трёх узлов
  языка: подстановочные ветки по `TypeNode`/`StateNode`/`Extend` в `builder.rs`
  им **не** покрыты и осмысленны.
  ⚠️ Тесты симуляции пиши **на значения** (`Unit::variable`), а не на факт
  перехода: именно отсутствие этого слоя дало восемь дефектов при зелёных тестах.
  ⚠️ **Второй вычислитель — не «только литералы»**
  ([0205](docs/features/0205-as-in-declaration-initializer.md)): он считает
  приведение `as` (зовя **тот же** `eval::cast_to_type`, что и такт) и читает
  константу по ссылке — **из таблицы объявлений** (`search_var`), а не из ячейки:
  в ячейке снимок с ещё не понижённым АСД (урок 0204). Цена прежнего устройства
  измерена: из восьми форм приведения **шесть** давали эталону ноль при верном
  значении у цели `c` (`5 as u16` → 0 против 5), две падали `SIM-006` в такте.
  ⚠️ Своей арифметики приведения здесь заводить нельзя — разойдётся с тактом;
  свёртка `as` в семантике отвергнута по той же причине, по какой `const_eval`
  не считает дробных: округление `q` задано эталоном. Предел `MAX_REF_DEPTH`
  нужен из-за взаимных констант (`const A := B; const B := A;`).
- **Проверка состояния под-модели исполняется ЭТАЛОНОМ, и адресуется по имени
  модели** ([0245](docs/features/0245-sim-state-of-model.md)). `S(Модель) =
  Состояние` и краткая `Модель = Состояние` вычисляются через реестр состояний
  в контексте-корне: узел публикует своё состояние при постройке, при переходе
  и при восстановлении из снимка, а условие читает через `Context::model_state`.
  Прежде эталон отвечал `SIM-013` («пока не поддерживается») на записи, которую
  цель `c` переводит с 0075, — расходились эталон и прошивка. ⚠️ Публикация
  стоит **после** смены поля `state`: наблюдатель обязан увидеть переход соседа
  **на том же такте**, как в порождённом C (под-модели тикаются по очереди);
  мутация «публиковать до» валит потактовую сверку. ⚠️ Модель, не запущенная в
  прогоне, даёт **`SIM-036`**, а не «условие ложно»: цель `c` на ней отказывает
  `CC-012`, и молчаливое `false` развело бы трассу с прошивкой. ⚠️ Проверка
  состояния — **условие**: её место — ребро `ref`, `cond`, формула/`invariant`;
  в теле блока запись отвергает семантика (`SE-003`). ⚠️ Тёзки под-моделей
  неразличимы — тот же компромисс, что у квалифицированного порта (0135).
  ⚠️ Форму паттерна разбирает **одна** функция на проект
  (`semantic::condition::state_of`, публичная с 0245): её зовут судья условий,
  цель `c` и симулятор.
- **Отказ доступа к разряду называет разрядность ЗНАЧЕНИЯ**
  ([0307](docs/features/0307-sim-bit-range-text.md)). `SIM-011` печатал «вне
  диапазона 0..64» литералом — и на `[bit;96]` это была **ложь**: разряд 70 тот
  же эталон исполняет. Теперь ширина в ошибке: 64 у целого (носитель), `1` у
  логического, `слов × 64` у бит-вектора (раскладка 0078). ⚠️ Граница
  печатается **включительно** (`0..127`), иначе читается как допустимая.
  ⚠️ Ширина берётся у значения, **не** у объявления: в `eval/` типа уже нет, а
  разряд 100 в `[bit;96]` принимают эталон, `c`, `rust` и `sv` — обещание
  отказа по объявленной ширине было бы второй ложью (класс вынесен кандидатом).
  ⚠️ Сторожа **сквозные** (`takt-sim/tests/sim/bit_range_text_tests.rs`): модуль
  `eval` крейта приватен, и проверять надо текст, который видит пользователь.
- **Значение `extern`-функции задаёт СЦЕНАРИЙ**
  ([0209](docs/features/0209-model-external-interface.md)). Секция `extern` шага:
  одно значение на такт либо таблица по **первому** аргументу («память»).
  ⚠️ Умолчания нет: не задали — прежний `SIM-019`. Ноль сделал бы сверку трасс
  зелёной при расхождении эталона с прошивкой — класс, ради которого сверки и
  заведены. ⚠️ Стенд принадлежит **шагу** и ставится перед тактом, как модельное
  время; доехать он обязан до **всех** областей видимости (`BlockScope`,
  `FunctionScope`, `Unit` в роли контекста) — умолчание трейта в любой из трёх
  означает «стенда нет», и подмена молча не срабатывает.
- **Единый источник истины по значениям — `ModelNodeContext`**
  ([0032](docs/features/0032-state-io-variables.md)): писать только через
  `Context::set_value`, читать через `get_value`/`dump`.
- **Узел языка в симуляторе разбирают ТРИ места, и они расходятся**
  (фикс [0134-02](docs/fixes/0134-02-duration-literal-in-body.md)): адаптер
  условий (`predicate.rs`), адаптер выражений (`expression.rs`) и вычислитель
  начальных значений (`unit/initial.rs`). Литерал длительности жил в двух из трёх:
  в теле блока `left := left - 1s;` отвечал `SIM-007`, хотя документ обещает
  арифметику, а инициализатор объявления работал. ⚠️ **Гейт исчерпаемости этот
  класс не ловит по устройству:** узел разобран, ветвь есть — она просто отвечает
  отказом «до будущей задачи», и отказ переживает саму задачу. Сторож — только
  проверка **поведения**; заводя ветвь-заглушку, заводи и тест, который её
  снимет. ⚠️ Тест на арифметику существовал и дефект **не ловил**: складывал две
  переменные, а падал литерал.
- **Реализация МОДЕЛИ (`model M = A | B { … }`) разворачивается в состояние**
  ([0199](docs/features/0199-model-implements-brace-form.md)). Форма — синоним
  записи `model M { start Имя = A | B; }`, и разворот делает
  `extend::expand_model_implement` на построении дерева: за этой границей формы
  не существует, и пяти потребителям не по чему разойтись (приём 0143/0187/0192).
  ⚠️ Прежде `ModelNode::implements` не разрешался **никогда** — разрешались
  только реализации состояний: эталон давал пустую трассу, а все четыре цели
  искали состояние с пустым именем. ⚠️ **Разрешить `implements` в поле мало**:
  карта (`semantic::minimap`) строит состояния из `model.states`, и от такой
  правки чинится **только эталон** (проверено). ⚠️ Модель с реализацией **и**
  собственным состоянием — `SE-101`: прежде такая запись работала, **молча
  теряя** реализацию. Коллизии имени синтетического состояния нет по построению
  — других состояний у модели с реализацией не бывает.
- **У состояния-композиции ЕСТЬ собственные рёбра, и цели их печатают**
  ([0303](docs/features/0303-composition-state-conditional-edge.md)). По
  завершении реализации проверяются переходы состояния: сначала `ref` в порядке
  объявления, затем `next` (порядок эталона — `build_transitions`); `END`
  подставляется **только** состоянию без переходов, иначе узел **остаётся** в
  состоянии. Прежде все восемь целей печатали лишь `next`: вход
  `state S = A | B { ref T: cond; }` давал другой автомат — в `T` не шёл никто,
  а при ложном условии цель завершалась там, где эталон ждёт. ⚠️ **Правки целей
  было мало:** `minimap::visit_state` в ветви `Implement` клал в обход только
  `next`, и состояние, достижимое по ребру, в карту не попадало — цель `rust` не
  знала о нём вовсе (ни варианта перечисления, ни ветви `match`). ⚠️ Класс
  **невидим инструментам**: прежний вывод принимали `cc -Wall -Wextra -Werror`,
  `verilator`, `yosys` и `iec2c`; вердикт дают только потактовые сверки
  (`conformance_composition_edge_tests`, два входа — сработавшее и несработавшее
  ребро). ⚠️ Найден **контрольным входом чужой фичи** (0267), а не плановой
  работой: «то же самое, но без предмета» — единственное, что отличает «стороны
  сошлись» от «ошибаются одинаково» (правило 30).
- **Реализация состояния — дочерний юнит узла с ОБЩИМ контекстом**
  ([0181](docs/features/0181-sim-state-implementation-tick.md), закрытие фикса
  [0057-01](docs/fixes/0057-01-sim-composition-next.md)). `state P = A + B { … }`
  живёт в `UnitKind::Node::state_impls`; такт тикает её **до** проверки переходов
  и берёт переход только по завершении — на том же такте (эталон — цель `c`,
  `generate_extend_transition` в ветви `is_done`). Повторный вход композицию
  **не** перезапускает — тоже контракт цели `c`. ⚠️ `next` живёт **отдельным
  полем** `StateNode::Implement::next`, а не среди `references`: заводя новую
  форму перехода, проверь, что `build_transitions` её видит — иначе состояние
  застрянет молча. ⚠️ Шаги `+` обязаны делить родительский контекст (общий
  `shared_context` с `Parallel`), иначе значение шага A шагу B не видно. Сторожа
  — тройная сверка sim≡C≡SV в `conformance_sv_tests` и
  `takt-sim/tests/sim/sequential_composition_tests.rs`.
- **`Unit::execution` в дочерние юниты НЕ спускается** — фикс
  [0181-01](docs/fixes/0181-01-sim-parallel-always-twice.md). Ребёнок исполняет
  свои блоки сам, в собственном `tick_body`; вернуть спуск значит исполнить
  `always` под-модели композиции **дважды** за такт (симулятор давал 2, цель
  `c` — 1; било и по `|`, и по `+`). ⚠️ Дефект был **невидим для всего
  покрытия**: тела корпуса идемпотентны (`x := <выражение>`), и лишнее
  исполнение в них неразличимо. Сторож — значенческие тесты на **накапливающем**
  теле (`n := n + 1`) в `takt-sim/tests/sim/sequential_composition_tests.rs`.
- **Порты под-моделей композиции драйвятся**
  ([0079](docs/features/0079-sim-composition-ports.md)): `PortNames::from_model`
  обходит `model.models` рекурсивно. ⚠️ Правки требовало **перечисление**, а не
  чтение/запись — те адресуют все ветви.
- **Порт адресуется квалифицированно** `Модель::порт`
  ([0135](docs/features/0135-sim-qualified-port-names.md)); голое имя работает как
  прежде. ⚠️ Квалификатор — **имя модели, а не путь**: две под-модели с одинаковым
  именем неразличимы.
- **Сценарий пишется именами портов**
  ([0132](docs/features/0132-sim-named-port-scenarios.md)); неизвестное имя →
  `SIM-030`, двусмысленное → `SIM-031`. ⚠️ Позиционная форма **устарела и об
  этом говорит** ([0150](docs/features/0150-sim-positional-scenario-deprecation.md)):
  индекс — место имени в **алфавитном** списке, поэтому добавление порта молча
  сдвигает весь массив; теперь такой сценарий даёт `SIM-037` — **один раз за
  прогон** (на каждый шаг было бы стеной повторов, глушащей следующее
  предупреждение). Форма по-прежнему принимается: сценарий живёт и вне
  репозитория, и отказ сломал бы чужое. Репозиторий держит гейт
  `scripts/check-positional-scenarios.py` — с самопроверкой и **ратчетом**
  (устаревшая запись исключения валит его). ⚠️ Гейт оправдал себя сразу: ручной
  обход дал «один позиционный файл», гейт нашёл **второй** — пример в `book/`.
  ⚠️ **Код диагностики обязан быть отдельным литералом** (`const CODE: &str =
  "SIM-037"`): `check-diagnostic-codes.sh` ищет коды как `"XX-NNN"`, и код,
  вплавленный в текст сообщения, ему невидим. Так `SIM-030`…`SIM-032` прожили
  вне реестра от 0132 до
  [0255](docs/features/0255-sim-diagnostic-codes-registry.md), которая их
  вернула и завела **условие 5** гейта: скобочная форма `[XX-NNN]` без своего
  литерала роняет прогон списком мест. ⚠️ Условием **отказа**, а не
  предупреждением, его сделал замер: скобочная форма встречается у шести
  кодов, три законны (комментарий и `assert!` внутри `src`, литералы есть).
  ⚠️ Тогда же у гейта появилась **первая самопроверка**
  (`scripts/test-diagnostic-codes.sh`, `DC_ROOT` для temp-дерева) — четыре
  условия прожили без неё, и дырявым оказалось то, которое никто не пробовал
  сломать. ⚠️ Значения портов удерживаются между тактами: явный ноль после
  единицы есть сброс.
- **Инварианты проверяются** ([0044](docs/features/0044-sim-assert-invariant.md)):
  `invariant Имя = C;` — сахар над `cond` + `Formula::Guard`; нарушение →
  `TickResult::Failed` + `SIM-025`. Мягкий режим (`--invariant-soft`) **записывает**
  нарушение и продолжает такт. ⚠️ Ошибка **вычисления** условия — `Failed` в обоих
  режимах; в сверке с C мягкий режим не участвует.
- **Сценарии примеров проверяются прогоном** (`examples_scenario_tests.rs`): у
  каждого `examples/*.takt` обязан быть либо контракт (цепочка + бюджет +
  завершение), либо исключение **с причиной**.

### Верификация

- **Абстракция управляющего графа** ([0049](docs/features/0049-model-checking-ltl.md)):
  атом = имя состояния, условия рёбер абстрагированы. «Держится» надёжно,
  «нарушено» может быть ложным. ⚠️ **Самопетля — не только у тупика:** её получает
  всякое состояние без **безусловного** `ref`. Первая редакция ставила петлю лишь
  вершине без рёбер → Крипке была **недо**-аппроксимацией → ложный `Holds`.
  Правило: ошибаться только в сторону **лишних** прогонов.
  ⚠️ **Капкан, стоивший дефекта** ([фикс 0010-01](docs/fixes/0010-01-buchi-acceptance.md)):
  `build_buchi` принимал любой бесконечный прогон, потому что тесты проверяли
  **структуру** автомата, а не язык. Тесты верификации пиши **на вердикт**.
  Область формулы — по месту объявления; область проверки — свой файл
  ([0051](docs/features/0051-verify-scope.md)).
- **Свойства над данными — абстракция по формуле**
  ([0068](docs/features/0068-verify-data-properties.md)): отслеживаются **только**
  переменные из φ. Ход данных **полностью недетерминирован** — максимальная
  сверх-аппроксимация: `Holds` надёжен, `Violated` над меняющимися данными почти
  всегда возможно ложный. ⚠️ Наивный explicit-state **неосуществим**: у `elevator`
  одна вершина имеет 3.7·10⁵⁰ преемников (входной порт волен принять любое значение
  каждый такт). Сторож направления — `abstracted_source_yields_extra_run_not_missed`.
- **Потолок верификации по данным считается по РЁБРАМ**
  ([0145](docs/features/0145-verify-vertex-budget.md)): `EDGE_LIMIT = 1_000_000`
  против `max(E_упр, V_упр) × D²`, где `D` — произведение доменов
  отслеживаемых переменных. Вершин `V = V_упр × D` (линейно по `D`), рёбер
  `E = E_упр × D²` (квадратично — ход данных недетерминирован, каждое
  управляющее ребро скрещивается с каждой оценкой), а работа
  (произведение с Бюхи + nested DFS) идёт **по рёбрам**. Цена прежней метрики
  (`VERTEX_LIMIT` по вершинам) измерена: вход «3 состояния и 12 `bit`» — 12 288
  вершин, **в 81 раз ниже** потолка, — не завершался за 60 с; два `u8` (замер
  0136) — за 90 с. То есть защита была, а от практически достижимого входа не
  спасала. ⚠️ Метрику выбрал **замер, а не рассуждение**: два входа с
  одинаковым числом **вершин** различаются по времени в 2000 раз (0.03 с
  против > 60 с), два входа с одинаковым числом **рёбер** дают одинаковое
  время (1.22 с и 0.98 с при 786 432 рёбрах). ⚠️ Потолок **один**: новая
  величина мажорирует прежнюю (у состояния валидной модели всегда есть
  преемник, `may_stutter` — значит `E_упр ≥ V_упр`), поэтому `VERTEX_LIMIT`
  удалён; `max` в формуле делает это свойством кода, а не рассуждения.
  ⚠️ Сторож `low_vertex_count_but_edge_explosion_is_unsupported` при регрессе
  **не падает, а виснет** — быстрый сигнал даёт `ceiling_counts_edges_not_vertices`
  (та же формула, но падением); удалять второй как «дублирующий» нельзя.
  ⚠️ Корпус класс **не покрывает**: формул `[LTL]` в `examples/` нет ни одной
  (они есть только в `book/`), поэтому сторожа — юнит-тесты и тема `verify`.
- **Вердикт-отказ НАЗЫВАЕТ причину, и носитель текста один**
  ([0258](docs/features/0258-verify-unsupported-reason.md)).
  `Verdict::Unsupported { atoms, reason }`; `UnsupportedReason` различает пять
  случаев (атом не связан, предикат вне подмножества, домен не перечислим,
  размер за потолком, начальное значение неизвестно), текст даёт
  `UnsupportedReason::text()` — его берут и CLI, и экспорт графа. Прежде
  вердикт нёс только имена атомов, CLI печатал **все** причины разом, а
  `dot.rs` утверждал своё («не имя состояния и не отслеживаемый предикат») —
  на входе за потолком это ложь, ровно та, что 0145 сняла обезличиванием.
  ⚠️ **Ветвь `DomainNotEnumerable` недостижима, и это замер**: `float`, `q`,
  массив и структура отсекаются **подмножеством предикатов** (`collect_tracked`,
  шаг 2), а проверка домена стоит шагом позже — проверено на четырёх входах.
  Ветвь оставлена защитной: расширится подмножество — она окажется на переднем
  крае, и молчаливая подмена причины была бы ложью. ⚠️ Текст сообщения
  проверяется **прогоном инструмента**: первая редакция использовала
  продолжение строки в `match`, и в вывод пошли десятки пробелов подряд —
  тесты на тип этого не видят.

### Документ и процесс

- **Версия языка — единственный источник истины в коде**:
  `takt_lang::LANGUAGE_VERSION`, **сейчас `0.10.0`**
  ([0085](docs/features/0085-language-version-constant.md)). Гейт
  `scripts/check-language-version.sh` сверяет **три** источника — константа,
  README и живой контекст. ⚠️ Меняя версию языка (правило 22 — накапливается по
  циклам), правь все три синхронно. Это **не** версия крейта `takt-lang` (`CARGO_PKG_VERSION`, сейчас `0.52.0`).
- **Релиз и тег выпускает АВТОМАТИКА при подъёме минорной версии языка**
  ([0302](docs/features/0302-release-on-language-minor.md)). Решение принимает
  `scripts/release-check.sh` (одна строка: `release <версия>` либо `skip
  <причина>`), тело собирает `scripts/release-notes.sh`, `.github/workflows/release.yml` —
  обёртка **без логики**. ⚠️ Устройство подчинено тому, что **CI не
  исполняется**: задания Actions не стартуют (блокировка аккаунта по биллингу —
  замер 2026-08-19, фича 0175), поэтому YAML непроверяем, и всё проверяемое
  обязано лежать в скриптах; их гоняет сторож
  `scripts/test-release-check.sh` в предкоммите. ⚠️ **Автоматика — страховка,
  а не замена правила 22:** тег, поставленный человеком, останавливает её
  (`skip`), а гейт 0162 при отсутствии локального тега первой подсказкой
  предлагает `git fetch --tags`. ⚠️ **Тело релиза берётся из ИСТОРИИ, а не из
  журнала:** в `CHANGES.md` заголовок `## ` один на весь файл (выпуски не
  размечали ни разу), и раздел «Не выпущено» дал бы 9765 строк.
- **Подъём версии языка помечается тегом, и у правила есть сторож**
  ([0162](docs/features/0162-git-tag-v040.md)). `scripts/check-version-tag.sh`
  (шаг предкоммита): у **закоммиченной** версии есть **аннотированный** тег
  `v<версия>`, достижимый из `HEAD`. Замер: из восьми версий тегов не имели
  две, и последний пропуск сделан накануне — правило 22 без команды
  исполнялось через раз (тот же довод, что у ADR 0085 про саму константу).
  ⚠️ **Гейт обязан молчать в момент подъёма**, иначе он вреден: тег ставится
  **на** коммит, а предкоммит идёт **до** коммита, и наивная проверка падала бы
  у каждой фичи, исполняющей правило **верно**. Признак — расхождение
  `LANGUAGE_VERSION` в рабочем дереве и в `HEAD`; тогда печатается пропуск с
  подсказкой команды. ⚠️ **Прошлые пропуски сторож не ищет** — перечня версий в
  дереве нет (README документирует два перехода из восьми); прошлое размечено
  один раз, этой фичей. ⚠️ **Замеряя теги, разыменовывай `^{commit}`**: у
  аннотированного тега `git rev-parse v0.5.0` отдаёт объект **тега**, и наивное
  сравнение хешей объявляет «тег указывает не туда» у всех аннотированных
  сразу. ⚠️ CI получил `fetch-depth: 0` (иначе клон без тегов), но **прогоном
  не проверен** — Actions заблокированы по биллингу.
- **Замер расхождения снимается КОМАНДОЙ, и проба проверяется**
  ([0301](docs/features/0301-probe-checklist.md), правило 30).
  `scripts/probe.sh [-n ШАГОВ] МОДЕЛЬ.takt` прогоняет эталон и **все восемь**
  целей в одну таблицу и проверяет **саму пробу** на три ловушки: объявление не
  используется (штатный фильтр выбрасывает его из вывода целей — замер покажет
  «расхождения нет»), имя файла совпало с объявленным типом (класс 0195), отказ
  **общей** диагностикой (`SE-`/`SY-`/`LE-`) пришёл раньше цели — её поведение
  **не измерено**. Повод: подряд у четырёх фич (0266, 0284, 0291, 0300) проба
  была негодной, и каждый раз ошибка вела в сторону «дефекта нет».
  ⚠️ **Скрипт не судит** — сводит ответы, сравнивает человек; подменять им
  потактовые сверки нельзя. ⚠️ Машине недоступны **контрольный вход** (без него
  «стороны сошлись» значит лишь «ошибаются одинаково»), скобки в спорных
  приоритетах, снятие посторонних причин по одной и датирование замера — это
  правило 30. ⚠️ Каталог бинарников — у одного носителя
  (`scripts/target-dir.sh`): копия в `run_simulations.sh` сломалась в день фичи
  0251 и не была замечена, потому что скрипт никто не запускает.
- **Реестр стадии СВЕРЯЕТСЯ с диском, и пропуск в нём слепит соседний гейт**
  ([0164](docs/features/0164-registry-rebuild-gate.md)).
  `scripts/check-registries.py` (шаг предкоммита) сверяет множество файлов
  папки-стадии с множеством ссылок её `README.md` **в обе стороны**: `R1` —
  файл без записи, `R2` — запись без файла, `R0` — пустая стадия. Замер
  2026-08-20: **42** артефакта не значились в реестрах. ⚠️ Кандидат называл
  битую ссылку — таких **ноль** (их ловит `check-links.py`); живое расхождение
  обратное. ⚠️ Главное следствие: `check-registry-verdicts.py` проверяет
  **строки**, поэтому шесть тест-планов и двенадцать отчётов не проверялись
  вовсе — гейт, чью проверку обходит отсутствие записи, не гейт. ⚠️ Пересборка
  реестра скриптом отвергнута: в строке живёт написанный человеком текст
  (заголовок, статус, вердикт со ссылкой), и гейт сверяет **состав**, а не
  содержание.
- **Запись реестра диагностик НАЗЫВАЕТ СМЫСЛ**
  ([0311](docs/features/0311-diagnostic-descriptions.md)). Разбор с примером
  есть у **83 кодов из 229**, поэтому для остальных реестр
  `docs/diagnostics/README.md` — единственное объяснение; замер 2026-08-20
  нашёл **десять** записей вида «ошибка»/«предупреждение» или имени
  конструкции. Гейт `scripts/check-diagnostic-descriptions.py` (шаг
  предкоммита, со сторожем на копии дерева): **D1** — служебное слово, **без
  исключений**; **D2** — описание короче 25 символов вне узаконенного долга
  (`scripts/diagnostic-description-baseline.txt`, 15 записей); **D3** —
  протухшая запись долга. ⚠️ Служебное слово **долгом не покрывается**, и это
  отдельное условие сторожа: первая редакция гейта проверяла D1 после долга.
  ⚠️ «Разобрать все коды» — **не** предмет проверки: какие заслуживают разбора,
  решает польза, а не согласованность (вывод 0290; остаток вынесен кандидатом).
- **Живой контекст проверяется машиной**
  ([0149](docs/features/0149-claude-md-consistency-gate.md)):
  `scripts/check-claude-md.py` сверяет статусы упомянутых фич с реестром, пути — с
  деревом, версии крейтов — с манифестами, **запрещает** ссылки вида
  `файл.rs:NNN` (строка остаётся, символ уезжает) и сверяет чек-лист критических
  инвариантов с метками подробных пунктов
  ([0289](docs/features/0289-claude-md-invariant-checklist-gate.md)).
  ⚠️ **Разбор идёт ПО АБЗАЦУ** ([0297](docs/features/0297-check-claude-md-line-blindness.md)):
  построчный поиск слеп к переносу, и сверка версий крейтов не срабатывала
  **никогда** — фикс 0202-01 снял факт, но не причину. ⚠️ Тогда же снята
  бутафория самопроверки: она требовала «нашлось хоть что-то», а проверка
  чек-листа даёт находку на любом коротком образце — все случаи проходили
  независимо от своего класса. ⚠️ Граница: перенос **внутри** одного токена в
  обратных кавычках сшивкой не лечится. ⚠️ Гейт проверяет форму, не
  смысл: истинность утверждений о поведении — на человеке (правило 4).
- **В сообщениях коммитов нет `Co-Authored-By`** (правило 31, решение

> печать в `takt-lang/src/format/`, иначе `format_source` начнёт **отказывать** на

> `takt-lang/tests/syntax/format_tests.rs` прогоняет форматтер по всему корпусу `.takt` и
> валит сборку при появлении **нового** непокрытого узла.
> ⚠️ **«Весь корпус» — это три каталога** (`examples`, `takt-lang/tests/data`,
> `takt-sim/tests/data`), и пропавший каталог **валит тест** (фича
> [0230](docs/features/0230-format-corpus-sentinel.md)). Прежде обход звал два
> каталога, переименованных ещё 0100, и при ошибке чтения молча возвращался:
> тест рапортовал о корпусе, видя 158 файлов из 308. Цена измерена в дефектах —
> в невидимой половине жила запись `model M = A | B { … }`, у которой форматтер
> **терял реализацию**, и форма `model M = A { }`, которую он печатал
> неразбираемой (фикс [0199-01](docs/fixes/0199-01-fmt-drops-model-implement.md)).
> ⚠️ Список исключений `KNOWN_GAPS` — **с ратчетом**: запись, которой на корпусе
> не соответствует ни один отказ, валит тест (образец —
> `scripts/module-size-baseline.txt`). Сегодня он пуст.
> ⚠️ **Отказ строит одна функция** `format::unsupported(loc, вид)` — диагностика
> **`FM-001`** с позицией узла (фича
> [0229](docs/features/0229-format-unsupported-position.md)). Прежде отказ нёс
> строку: место не называлось вовсе, а на операторе печатался `Debug`-дамп узла
> (класс 0202 в ветви, до которой та фича не дошла). Позицию оператора даёт
> **`ast::Statement::loc()`**, имя вида — `kind_name()`; оба разбора
> исчерпывающи, и копий у них быть не должно — до 0229 `statement_loc` жил в
> двух местах (счётчик глубины, константный вычислитель).

> не строится (как `Expression::CodeBlock`/`NamedFunction` — мёртвые узлы, класс

> **Слой использований (фича 0131).** Новый узел АСД **валит сборку**
> `semantic/usages/walk.rs`: модуль объявляет `deny(clippy::wildcard_enum_match_arm)`,
> то есть `_ =>` по узлу языка там не соберётся. Это замысел: пропущенное
> вхождение — испорченный переименованием исходник, а не «неполный ответ».
> Добавил узел — разбери его в обходе (третий пункт списка сопровождения после
> форматтера и `eval/` симулятора).

> **Слой стиля — канон именования (фича [0226](docs/features/0226-naming-convention-warning.md)).**
> Новая форма **объявления** обязана попасть в обход `takt-lang/src/style/naming.rs`,
> иначе её имя каноном не проверяется — а сказать об этом машине нечем: обход
> кончается `_ => {}` **осознанно** (канон описывает объявления, а не всякий узел
> АСД), поэтому `deny(clippy::wildcard_enum_match_arm)` здесь неприменим. Сторож —
> `takt-lang/tests/syntax/style_naming_fmt_tests.rs::every_declaration_kind_of_the_canon_is_reported`:
> он перечисляет **все** виды объявлений и падает, когда обход теряет ветвь, но о
> **новом** виде, которого в его таблице нет, промолчит. ⚠️ Проверка живёт вне
> семантики намеренно: `taktc fmt` семантику не запускает (ADR 0024), и это его
> свойство. ⚠️ Предупреждение `CS-001` на код возврата `fmt --check` **не влияет**
> (решение заказчика), поэтому корпус от него сторожит тест
> `corpus_has_no_style_warnings`, а не гейт предкоммита.
> ⚠️ **Обход спускается в ТЕЛО СОСТОЯНИЯ** (фикс
> [0197-01](docs/fixes/0197-01-kr-else-cond-case-enum-lines.md)): `invariant`
> объявляется в двух местах — элементом модели и элементом состояния, — и без
> спуска канон действовал бы через раз. `collect_state_element` разбирает
> `StateElement` **исчерпывающе, без `_`**: новый вид элемента обязан заставить
> принять решение. ⚠️ Прочие элементы тела (`next`, `ref`, `every`, именованные
> блоки) имён не объявляют, а **ссылаются** на чужие — переименовывать их канон
> не вправе; контр-пример на это стоит рядом с положительным сторожем.
> ⚠️ **`CS-001` отдаётся во ВСЕХ ветвях возврата `lsp/diagnostics.rs::collect_diagnostics_at`,
> где АСД разобран** (фича [0227](docs/features/0227-lsp-style-warning-with-errors.md)):
> рядом с ошибкой построения дерева, рядом с ошибкой `validate` и на успешном
> пути. Это **исключение** из политики «предупреждения о смысле при ошибках не
> показываем» — канон именования смотрит на текст и от ошибок не портится;
> прочие предупреждения (`SE-036`, `SE-037`) остаются только на успешном пути.
> Прежде предупреждение исчезало от любой ошибки, а `fmt` его печатал — один
> вход, два ответа. ⚠️ Сторожа на **новую** ветвь возврата нет и быть не может
> (ветвь — не тип): заводя её, отдай стиль и там, иначе он потеряется молча.

> **Запуск инструментов из IntelliJ: логика — вне GUI** (фича
> [0158](docs/features/0158-intellij-run-configurations.md)). Конфигурации
> «Compile»/«Simulate» строят командную строку **чистой функцией**
> `run/TaktCommandLine.kt` (без `Project`/`Editor`/сервисов) — только она и
> проверяется Gradle-тестами, потому что плагин вне `precheck.sh`. ⚠️ **Колонка
> диагностики — в СИМВОЛАХ**, а документ IDEA адресуется кодовыми единицами
> UTF-16: на символе вне BMP (эмодзи в комментарии) наивное «колонка − 1»
> уводит ссылку не туда — пересчёт делает `TaktOutputFilter.charColumnToOffset`,
> и мутация это ловит. ⚠️ Каталоги импортов подставляются **повторяемым** `-I`:
> разделитель списка у компилятора платформозависим (`:` против `;`), и второе
> знание о нём в плагине заводить нельзя. ⚠️ Формат позиции задан ядром
> (`diagnostics::position_prefix`), а разбирает его плагин — при смене формата
> тесты плагина об этом не узнают (кандидат).

> **Переименование в IntelliJ делает СЕРВЕР, и держится это на отсутствии
> `PsiNamedElement`** ([0154](docs/features/0154-intellij-server-rename.md)).
> `LSPRenameHandler` из LSP4IJ зарегистрирован `order="first"`, но **уступает**
> любому доступному нативному обработчику: его предикат требует, чтобы других не
> было (либо чтобы все были `VariableInplaceRenameHandler`) — разбор байткода в
> ADR. Поэтому пока `TaktNameDecl` объявлял `PsiNameIdentifierOwner`, серверный
> `rename` не включался **никогда**, а работала эвристика «первая одноимённая
> декларация файла» без областей видимости. ⚠️ Вернёте `PsiNamedElement` —
> переименование молча уедет обратно в эвристику; сторож
> `TaktRenameTest::testDeclarationIsNotRenamableNatively` это ловит (проверено
> мутацией). ⚠️ Сторож на **пустоту** `RenameHandlerRegistry.getRenameHandlers`
> строить нельзя: зонд 0154 показал, что в синтетическом `DataContext` теста
> `PsiElementRenameHandler` доступен даже для `.txt` — он предлагает
> переименовать **файл**. ⚠️ Цена: без `takt-lsp` переименования в IntelliJ нет
> вовсе (навигация и подсветка остаются) — названо в `README` плагина.

> **Редакторский слой — правило 29 свода (фича 0178).** Изменение лексики,
> синтаксиса или семантики **обязано** проверить LSP (`takt-lang/src/lsp/`) и
> плагины (`extensions/`); ответ «не нужно» фиксируется тоже. Часть держит
> машина: **новый токен валит сборку** `lsp/semantic_tokens.rs` — разбор
> исчерпывающ, `deny(clippy::wildcard_enum_match_arm)` не даёт вернуть `_`
> (мутация показала, что отказ даёт **сам rustc**: `E0004`, то есть инвариант
> держится и без clippy). Список автодополнения `lsp/keywords.rs::TAKT_KEYWORDS`
> — **данные**, исчерпываемостью не защищаются: их сторожит тест вложения
> `KEYWORDS ⊆ TAKT_KEYWORDS ∪ COMPLETION_EXCLUDED` (перечисление лексера —
> `parser::lexer::all_keywords()`). ⚠️ Проверять **равенство** нельзя: в списке
> законно живут `enter`/`exit`/`always` — имена блоков, а не ключевые слова.
> ⚠️ Плагин **IntelliJ** машиной **не защищён**: его сторож
> `TaktKeywordSyncTest` живёт в Gradle-сборке, которая вне `precheck.sh`/CI
> (пусковой JDK 17…26 — измеренный диапазон фичи
> [0224](docs/features/0224-intellij-kotlin-upgrade.md)), — там работает только
> дисциплина правила 29. Плагин
> **Zed** своих списков не ведёт (`language_servers = ["takt-lsp"]`) и правок не
> требует, но и наследует все дефекты сервера.

> **Лексема без правила — дефект, и его ловит машина** (фича
> [0201](docs/features/0201-dead-lexemes.md)). Слово в `KEYWORDS`, которого нет
> в extern-блоке грамматики, даёт `SY-002` при употреблении, **обещая**
> конструкцию из шести списков, что по `KEYWORDS` выравниваются. Так жили
> `string` и `template`, а `pragma` — на уровень глубже (вариант `Token` без
> слова в таблице: недостижим и он, и его механизм). Сторож —
> `takt-lang/tests/syntax/dead_lexeme_tests.rs`, сверка идёт **в обе стороны**: слово
> без терминала (класс A) и терминал без правила (класс B).
> ⚠️ **Имя типа ключевым словом быть не обязано** — `bit`, `bool`, `u8`, `q` им
> не являются, типы в грамматике суть `Type: Alias(Identifier)`. Поэтому
> `var bit: u8 := 1;` законен, а строковый тип, если понадобится, вводится
> одной строкой в `builtin_type_by_name` (как `duration` в 0134): держать слово
> ключевым ради будущего типа **не нужно**.
> ⚠️ **Неиспользуемый терминал — не «надгробие» изъятой конструкции.** Замер
> 0201 на двух редакциях грамматики: текст диагностики от объявления **не
> зависит** (байт-в-байт), зато объявление добавляет вторую, **каскадную**
> ошибку. Изымая оператор, оставляй **лексему** (иначе `==` распадётся на `=` и
> `=` — сообщение о следствии), но **не** терминал.

> **Плагин IntelliJ (фича 0067).** PSI плагина `extensions/intellij-takt` —

## Форматтер

Ядро печати — `takt-lang/src/format/` (`format_source`), потребители: `taktc fmt`
(`--check`/`--stdin`) и LSP `textDocument/formatting`. `precheck.sh` проверяет
канон `examples/` (фикстуры `tests/data/` намеренно не нормализованы — тесты
завязаны на их позиции). Правило «добавил узел АСД — добавь его печать» и устройство
сторожа корпуса — во врезке раздела «Добавление конструкции языка».

⚠️ **Канон описан словами** — раздел «Стиль кода» документа (фича
[0197](docs/features/0197-language-code-style.md)). Машинной сверки «текст ↔
форматтер» нет и построить её в общем виде нельзя, поэтому фича, меняющая
поведение `taktc fmt`, **обязана** проверить этот раздел: разошедшись, он станет
обещанием, которого инструмент не исполняет. Примеры раздела прогоняет гейт
документа (0133), но правила словами — на человеке. Цена измерена фиксом
[0197-01](docs/fixes/0197-01-kr-else-cond-case-enum-lines.md): смена трёх правил
затронула **пять** записей канона — печать `format/`, слой `style/naming.rs`,
свод в `book/src/21-code-style/`, описание `CS-001` в приложении об ошибках и
таблицу отступлений в карточке 0197.

**Раскладка — K&R** (фикс 0197-01): `} else {`, цепочка **плоская**
(`} else if c {`). Склейку строк делает `Out::join` — снимает уже поставленный
`'\n'` и взводит `glued`, из-за которого следующая `line` идёт без отступа.
⚠️ Флаг нужен потому, что заголовок звена печатает **рекурсивный** `stmt::print`,
не знающий, что его позвали из ветки `else`; `blank` при взведённом флаге
подавлена, иначе восстановление пустой строки разорвало бы `} else `.

**Перечисление и структура печатаются по элементу на строке** (`print_enum` —
фикс 0197-01, `print_struct` — фикс
[0198-01](docs/fixes/0198-01-struct-comment-placement.md); устройство у них
одно). ⚠️ **Висячей запятой быть не должно**: грамматика — `CommaOne<EnumVariant>`
и `Comma<StructField>`, и напечатанная запятая делает файл неразбираемым (класс
0199-01 — `fmt` пишет на месте). ⚠️ Заголовок печатается `line`, закрывающая
скобка — `node_line(&loc, "}")`, а варианты/поля — `node_line_within(…, brace)`
с границей по байту самой `}`: `loc` записи покрывает её **целиком**, поэтому в
однострочной форме хвостовой комментарий стоит на той же строке, что и каждый
вариант, и без границы его забрал бы первый — а печать перестала бы быть
идемпотентной.

⚠️ **`out.line` в печати элемента модели — сам по себе дефект привязки.**
Комментарии выдают только `node_line`/`node_line_within`/`comments_before`;
ведущие комментарии самой записи спасает общий вход `print_element`, поэтому
обход виден не сразу — страдает то, что живёт **внутри** записи и на строке `}`.
Так дефект и пережил фичу 0198 (она шла по печати **операторов**) и фикс 0197-01
(он переписал соседнюю ветку `Enum`).

**Закрывающая скобка тела печатается ОДНОЙ функцией `close_body`** (фича
[0295](docs/features/0295-format-element-comment-binding.md)): она выдаёт
хвостовые комментарии и печатает `}` через `node_line`. Комментарий последней
строкой тела принадлежит **этому** телу; без явной выдачи его подхватывает
`leading()` следующего элемента, а при отсутствии следующего — всплывает в
конец файла. ⚠️ Класс правился **трижды и каждый раз в своей ветке** (0198 —
операторы, 0197-01 — перечисление, 0198-01 — структура), и замер 2026-08-19
нашёл его живым ещё в двух: состояние и вложенная модель. ⚠️ Сторож
двухслойный (`takt-lang/tests/syntax/format_comment_binding_tests.rs`):
поведение — по **отступу** комментария (проверка порядка строк дефект **не
ловит**: уезжая, комментарии сохраняют взаимный порядок), устройство — греп по
`format/mod.rs`, падающий списком мест. ⚠️ Корпус класс не покрывает —
комментариев внутри таких записей там ноль.

**Синонимы не канонизируются:** `while`/`loop` и `: [Guard] x;`/`: x;` — АСД
хранит выбор автора (`ast::LoopKeyword`, `Guard::explicit`); семантика эти
признаки игнорирует.
