AI-инструментов. Здесь — **только контекст** (что за проект, архитектура,

  цикл фич; `FEATURES.md` — витрина незакрытых фич, карточки фич — в

- **Правила написания Rust-кода:** [`docs/CODE.md`](docs/CODE.md).
- **Журнал изменений:** [`CHANGES.md`](CHANGES.md) (формат Keep a Changelog).
- **Описание языка (для пользователя):** [`book/`](book/) — mdBook → PDF (шрифт
  Fira Code), сборка `make -C book build` → `book/book/pdf/takt-language.pdf`
  (нужны `mdbook`+`mdbook-pandoc`+`xelatex`, вне `precheck.sh`). Содержит **только язык** (синтаксис/семантику/примеры), без
  деталей реализации, номеров фич и процесса (**правило 24**). Каждая языковая фича

  0101 завела инфраструктуру + seed «Обзор»; разделы 2–15 — фичи-преемники.

## Проект

**Takt** (Typed, Automata, Known Timing) — DSL для спецификации и синтеза конечных
автоматов (FSM) промышленных систем управления. Цели генерации: `c`/`c-hal`
(прошивка МК), `st`/`st-at` (ПЛК, IEC 61131-3), `rust` (`no_std`), **`sv`**
(синтезируемый SystemVerilog — FPGA/ASIC) и `plantuml` (диаграмма).
Rust-workspace из двух крейтов:

- `takt-lang` — компилятор (бинарник `taktc`) и LSP-сервер (`takt-lsp`).
- `takt-sim` — симулятор моделей и GIF-визуализация.

## Команды

```sh
# Сборка
cargo build --bin taktc
cargo build --features lsp --bin takt-lsp

# Канонический форматтер .takt (фича 0024)
cargo run --bin taktc -- fmt examples/          # на месте
cargo run --bin taktc -- fmt --check examples/  # проверка для CI (код ≠ 0 при отличии)

# Тесты (параллельно — фича 0190 сняла `--test-threads=1`)
cargo test
cargo test --all-features                       # включая тесты LSP
cargo test <имя>                                # один тест по имени

# Предкоммит-проверка (fmt + check + clippy + test + сборка примеров), ~230 с
./scripts/precheck.sh

# Прогон всех симуляций из examples/simulations/
./scripts/run_simulations.sh
```

**Толчейн и CI** описаны один раз — в разделе «Документ и процесс»: пин
`rust-toolchain.toml` (стабильный `1.97.1`) и прогон всего `precheck.sh` под
`PRECHECK_STRICT=1`. Здесь только то, чего там нет: `Cargo.lock` **отслеживается**
(workspace даёт бинарники, а `lalrpop` берётся из git — без lock состав
зависимостей плавает), `resolver = "3"`, MSRV `rust-version = "1.97"` в обоих
манифестах (нижняя граница не измерялась).

**Внешние зависимости** (для сборки и тестов `taktc` не нужны — только для
проверки порождённого кода):

- `cmake` + `ninja` + `cc` — гейт цели `c` в `precheck.sh`.
- **MatIEC `iec2c`** — арбитр валидности порождённого ST (фича 0041):
  единственный автоматизируемый способ доказать, что ST валиден. Пакетом **не
  поставляется**; ставить руками не надо — `precheck.sh` зовёт
  `scripts/ensure-iec2c.sh`, который при отсутствии собирает из исходников в
  `~/.local/bin/iec2c` (≈15 с). Скрипт **никогда не валит предкоммит**: нет
  сети/bison → мягкий пропуск. Переменные: `IEC2C_PREFIX` (`~/.local`),
  `IEC2C_SRC` (`~/.cache/matiec`), `IEC2C_SKIP=1`.

  ```sh
  ~/.local/bin/iec2c -I ~/.local/share/matiec/lib -T <вывод> файл.st  # 0 = валиден
  ```

  ⚠ **`-I` обязателен:** `make install` MatIEC ставит только бинарники
  (`install-data-am` пуст), а без `lib/ieclib.txt` `iec2c` падает на любом входе.
  Скрипт копирует библиотеку в `$PREFIX/share/matiec/lib` сам. Гейт по
  порождённым `.st` включён и зелён (8/8 корпуса); ручные пробы —
  `takt-lang/tests/data/st/probes/*.st`.

## Архитектура

Конвейер компиляции: `.takt` → **лексер** (`parser/lexer.rs`) → **парсер**
(LALRPOP LR(1), `grammar.lalrpop`) → AST (`parser/ast.rs`) → **семантика**
(7 проходов, `semantic/`) → **генераторы** C (`generator/c/`) и PlantUML
(`generator/plantuml/`). Верификация свойств — `verification/` (LTL, автоматы Бюхи).

### Семантические проходы (по порядку)

| Проход | Файл | Назначение |
|---|---|---|
| 0 | `tree.rs` | Имена моделей/состояний, загрузка импортов |
| 1 | `tree.rs` | Составные состояния (`M1 + M2`, `M1 \| M2`) |
| 2 | `type_inference.rs` | Переменные, вывод типов, порты |
| 3 | `tree.rs` | Именованные условия (`cond`) |
| 4 | `tree.rs` | Именованные блоки (`enter`/`exit`/`always`) |
| 5 | `tree.rs` | Тела функций |
| 6 | `tree.rs` | Замена `Condition::Unresolved` разрешёнными условиями |

### Критические инварианты (НЕ нарушать)

Чек-лист перед правкой ядра. Каждый пункт подробно разобран ниже, в
«Технических подводных камнях», — здесь только имя инварианта, чтобы шесть самых
дорогих были видны вместе.

1. **Условия рёбер `ref` не разрешаются** — прохода `resolve_state_references`
   не заводить (раздел «Семантика и диагностика»).
2. **`Condition` и `Expression` не унифицировать** — у них разная семантика `=`
   (там же).
3. **Присваивание `:=`, сравнение `=`, `==` из языка выведено** (там же).
4. **Адрес порта: inline `:=` < оператор `address` < внешняя карта** — вместе с
   квалификацией ключа, диапазоном бита и экспортом (раздел «Цели генерации»).
5. **Вход в стартовое состояние не расходует такт** — контракт для всех
   бэкендов (там же).
6. **Model-level `always` исполняется каждый такт** до диспетчеризации
   состояния (там же).

### Общее

- **Пути** — через `std::path::Path`, не разбивкой строк. При генерации C явно
  обрабатывай анонимные/корневые модели (получают имя `Root`) и пустые случаи.
- **Новые тесты** — сперва зонд для захвата реального вывода, затем проверки
  против захваченного. Не угадывать строки, адреса и позиции.
- **Разрешение переменных** проверяй в обоих путях — верхнеуровневый и вложенный
  доступ к модели (включая `tick`/`init`): починка одного пути часто ломает другой.
- **Поведение цели сверяется потактово, а не только компилируется.** Сверки —
  `takt-sim/tests/conformance_{c,sv,rust,st}_tests.rs`. ⚠️ Гейт целевого языка
  (rustc/clippy, verilator/yosys, iec2c) доказывает, что вывод **компилируется**,
  но не что он **верен**: молча неверная трансляция компилируется тоже. Правило:
  **сверку заводить вместе с бэкендом** — у [0045](docs/features/0045-sv-backend.md)
  дефект приняли молча оба инструмента SV, у [0050](docs/features/0050-rust-backend.md)
  сверки не было вовсе при зелёном гейте.
- **Тесты идут ПАРАЛЛЕЛЬНО; временный каталог теста уникален по тесту**
  ([0190](docs/features/0190-precheck-selective-gates.md)). Прежде предкоммит
  гонял `--test-threads=1` «из-за гонок за общие файлы»; замер показал, что
  гонок было **две**, обе в `st_tests`: каталог строился по фикстуре
  (`types_all`, `enum_struct` — их берут по 2–3 теста) и по имени входного
  файла (одно имя на два теста), а каждый помощник начинает с `remove_dir_all`.
  Ключ уникальности — имя потока (`std::thread::current().name()`: харнесс
  Rust называет поток именем теста); в однопоточном режиме имени нет, и ключом
  остаётся фикстура. Замер: 146 с → 95–127 с при 12 ядрах, а `cargo test` —
  **84 % времени предкоммита**. ⚠️ Покраснел параллельный прогон — чини
  **каталог теста**, а не возвращай флаг: возврат прячет гонку и возвращает всю
  стоимость разом.
- **Генерация детерминирована** ([0048](docs/features/0048-deterministic-codegen.md)).
  Порядок эмиссии задаётся **типом контейнера** (`BTreeMap`/`BTreeSet`), а не
  сортировкой на выходе: локальная сортировка не спасает, если внешний цикл
  недетерминирован. Сторож — жёсткий гейт в `precheck.sh` (два прогона × все цели
  → `diff -r`). Следствие: дифф `examples/generated/` несёт смысл, снапшоты возможны.
- **Размер модуля** — ≤ ~1000 строк вместе с тестами (правило в `docs/CODE.md`,
  фича [0091](docs/features/0091-module-size-rule-in-code-md.md)). Проверяет
  `scripts/check-module-size.sh`; реестр `scripts/module-size-baseline.txt` —
  **узаконенный долг** (4 файла), запись оттуда не имеет права расти, а уложившийся
  в лимит обязан быть удалён. ⚠️ Правя большой файл, готовься к отказу «вырос»:
  это замысел — выносить новое в отдельный модуль.
- **Генератор фич `scripts/new-feature.sh` идемпотентен**
  ([0094](docs/features/0094-new-feature-script-fixes.md)): повторный `--register`
  не дублирует строки реестров. Добор стадии — `--stage NAME`, подзадача —
  `--stage dev --subtask NN`. Регресс — `scripts/test-new-feature.sh` в предкоммите.

### Семантика и диагностика

- **Параметр модели — поле экземпляра, а под `--parameters=specialize` —
  константа копии** ([0185](docs/features/0185-model-parameters.md), версия языка
  0.8.0). `parameter Y: u8 := 100;` живёт в `variables` обычным
  `VariableNode::Simple` (потребитель, ничего не знающий о параметрах, обращается
  с ним верно); отличие — в `ModelNode::parameters` (имя, позиция, **порядок** —
  по нему строится ключ дедупликации). Аргумент `M(Y := выражение)` **вычислен**
  (`semantic/const_eval/`) и понижен в литерал: за границей семантики выражения
  аргумента не существует. ⚠️ Флаг меняет **форму** вывода, не поведение — сторож
  R11 сверяет **четыре** трассы (симулятор и цель `c` в обоих режимах,
  `takt-sim/tests/conformance_param_modes_tests.rs`); гейт предкоммита требует
  «флаг не наблюдаем» от примеров **без** параметров и «специализация
  детерминирована» от параметризованных. ⚠️ Проход константности
  (`semantic/parameter_const.rs`) стоит **после специализации и до стадии 2**:
  позже пришлось бы править оба представления переменной (засада 0096) и опоздать
  к `after` (0143) и адресу порта (0042); анализ изменяемости идёт по **именам**
  — затенение делает параметр «изменяемым», то есть ошибка только в безопасную
  сторону. ⚠️ Параметр там, где нужна величина сборки, под `assign` — **`SE-088`,
  называющий режим**; прежде `after PARAM` молча становился вычисляемой
  выдержкой. ⚠️ Специализация модели с вложенными моделями — `SE-087`; равенство
  `ParameterArgument` **игнорирует позицию** (иначе `SV-016` отвергал одинаковые
  наборы).

- **Ошибка разрешения оператора не зависит от глубины вложенности**
  ([0155](docs/features/0155-semantic-nested-statement-resolution.md)).
  `semantic/statement.rs` пробрасывает ошибку `?` во **всех** телах (`if`/`else`,
  `while`/`loop`, `for`, inline-`Guard`). ⚠️ Возвращать
  `.unwrap_or_else(|_| Unresolved(…))` нельзя: цель `c` печатает `Unresolved`
  **пустотой**, симулятор пропускает — терялась не диагностика, а **сам оператор**.
  Сторож — `takt-lang/tests/nested_statement_resolution_tests.rs`.
- **Глубина вложенности ограничена** `MAX_NESTING_DEPTH = 32`, превышение →
  `SE-062` ([0129](docs/features/0129-semantic-deep-nesting.md)). Сторожа стоят в
  `construct_expression`, `resolve_condition`, `resolve_ast_statement`. Без предела
  инструменты падали `SIGABRT` без диагностики. ⚠️ Счётчик меряет глубину **узлов
  дерева**, а не скобок.
- **Второй предел — на разборе: `MAX_PARSE_DEPTH = 96`, превышение → `SY-005`**
  ([0156](docs/features/0156-parser-depth-limit.md)). Проверка стоит в **единой
  точке** `takt_lang::parse`, через которую идут все инструменты, поэтому дерево
  глубже предела наружу не выходит и рекурсивные потребители (печать форматтера,
  `Clone`, `Drop`, `Debug`, `serde`) безопасны **по построению** — их сторожить
  по отдельности не нужно. Цена отсутствия: `taktc fmt` и форматирование в
  редакторе падали `SIGABRT` уже на ≈ 200 уровнях в потоке 2 МиБ (семантику этот
  путь не зовёт, `SE-062` его не прикрывал). Сторож —
  `takt-lang/tests/parse_depth_tests.rs` (прогон в потоке 2 МиБ).
  ⚠️ **Предел разбора обязан быть выше семантического с запасом**: счёт по узлам,
  а один уровень текста ≠ один узел (вложенный `if` = `If` + `Block`), поэтому
  семантической глубине 32 отвечает ≈ 70. Инвариант держит `const _: () =
  assert!(…)` в `parser/depth/mod.rs`, а не тест. ⚠️ **Отвергнутое дерево
  утилизируется итеративно** (`parser/depth/dismantle.rs`): производный `Drop`
  роняет процесс на ≈ 18 750 узлах, то есть отказ убивал бы инструмент в момент
  возврата диагностики. ⚠️ Оба обхода — под `deny(clippy::wildcard_enum_match_arm)`
  и в гейте `scripts/check-exhaustive-nodes.sh`: узел, выпавший из счёта, не
  измеряется, выпавший из утилизации — уничтожается рекурсивно.
- **Ошибок за прогон — несколько** ([0130](docs/features/0130-diagnostics-batch.md),
  [0151](docs/features/0151-diagnostics-batch-within-check.md)).
  Вход `collect_compile_diagnostics` общий у CLI и LSP. Стадии **построения дерева**
  терминальны (после ошибки дерево неполно), проверки `validate` — накапливаются.
  ⚠️ Заводя диагностику, **ставь позицию** (`Diagnostic::error(loc, …)`): в пачке
  сообщений координата `1:1` бесполезна.
  ⚠️ **Правило накопления внутри проверки — «одна диагностика на элемент, все
  элементы высказываются»** (0151). Элемент — объявление, ребро перехода,
  именованное условие, оператор `address`; **внутри одного выражения** ранний
  выход сохранён (дальше идут следствия первой ошибки). Все проверки
  `validate_model_all` отдают `Vec<Diagnostic>`; вернуть `Result<(), Diagnostic>`
  значит вернуть потерю. ⚠️ Один код диагностики ≠ одно место эмиссии: `SE-025`
  рождается и на ребре, и в объявлении `cond` — тест, покрывающий одно место,
  молча оставляет второе (мутация 0151 это показала).
- **В тексте диагностики нет внутреннего представления**
  ([0231](docs/features/0231-diagnostic-text-no-debug.md)). `Debug`-дамп узла
  вместо сообщения — класс, правленный **трижды** (0202 — отказ форматтера,
  0229 — печать узла, 0231 — `SE-025` и ещё девять мест) и каждый раз найденный
  глазами. Сторож — `takt-lang/tests/diagnostic_text_tests.rs`: прогоняет
  диагностики на фикстурах **и на списке проб**, проверяя сами тексты.
  ⚠️ Пробы обязательны: одни фикстуры дают 98 сообщений и `SE-025` **не
  порождают** — без проб сторож декоративен (доказано мутацией). ⚠️ Гейт грепом
  по исходнику отвергнут замером: `:?}` встречается в `src/` 147 раз, и почти
  всё законно (тесты, `panic!`, ключи). ⚠️ Цитата записи автора берётся у
  **форматтера** (`format::condition_text`); узел, который он печатать не умеет,
  оставляет сообщение **без цитаты** — подставлять `Debug` нельзя.
- **Диагностика несёт путь файла** ([0053](docs/features/0053-diagnostics-file-id.md)).
  `taktc` и `takt-sim` печатают позицию **одной** функцией
  `diagnostics::position_prefix` — формат есть свойство диагностики, а не бинарника
  (копия разошлась бы). ⚠️ Создавая `Diagnostic` литералом, указывай `file: None`.
  Колонка — в **символах** (в `.takt` есть кириллица).
- **Предупреждения `taktc compile` идут через одну точку** —
  `semantic::warnings::collect_model_warnings`
  ([0081](docs/features/0081-lamc-print-warnings.md)). ⚠️ Новое предупреждение
  доезжает до пользователя, **только если добавлено туда**. Цена нарушения
  измерена ([0232](docs/features/0232-implicit-bool-warning-delivery.md)):
  проверка неявной булевости (`SE-037`, Ce11) с юнит-тестами и публичной
  обёрткой не была подключена — считалась и выбрасывалась. ⚠️ **LSP зовёт ту же
  точку** (0232): прежде у него был свой список из **двух** проверок вместо
  восьми, и редактор молча не показывал `SE-044`, `SE-045`, `SE-046`, `SE-047`,
  `SE-096` и предупреждения LTL. Два списка одного набора расходятся — класс
  0084/0193/0195.
- **Что считать булевым условием, решает ОДНО правило** —
  `is_boolean_semantic_condition` (`semantic/validate/implicit_bool.rs`, фича
  [0233](docs/features/0233-single-boolean-predicate.md)). Булевы: сравнения,
  `!`, переменные `bit`/`bool`, именованные `cond`, **`&`/`|` над булевыми

  неразрешённое условие (молчим). ⚠️ `&`/`|` булевы не по доброте: логических
  `&&`/`||` условная грамматика **не принимает вовсе**, это единственная форма
  конъюнкции условий. ⚠️ Прежде правил было **два** (второе — по «сырому» АСД,
  для `Unresolved`), и они разошлись на `after`: цена — 51 ложное срабатывание

  Второе удалено по замеру: 433 проверки, `Unresolved` — ноль, и быть не может
  (неразрешённое условие есть `SE-025`, а предупреждения считаются только при
  отсутствии ошибок). ⚠️ Заводя ветвь «на всякий случай», помни этот счёт:
  недостижимый код нельзя ни проверить, ни удержать от расхождения.

- **Разделение `Condition` / `Expression` — намеренное, НЕ унифицировать**

- **Операторы `:=` / `=`** ([0021](docs/features/0021-swap-assign-compare.md)):

- **Позиция использования — свойство ссылки; индекс LSP адресует `(file_no, offset)`**

- **Импортированное объявление — объявление ИМПОРТЁРА**
  ([0184](docs/features/0184-imported-shared-variables.md)). `import` строит дерево

  спрашивают владельца **у ячейки** и печатали доступ «как к своей» (невалидный

  правы случайно, симулятор шёл по цепочке моделей и падал `SIM-009` — пять
  потребителей на одном входе. Лечит слой `semantic/import/adopt.rs`
  («усыновление»). ⚠️ Перепривязывать надо **оба** представления `VariableNode`
  (карта + `Rc`-ячейки тел; засада 0096) и **только внутри** ветки импорта — пока

  значений `takt-sim/tests/conformance_c_import_tests.rs` (трасса возможна лишь

  ⚠️ **Импорт переносит УСТРОЙСТВО типа, а не имя** (фикс

  `types`, поля и варианты — в `structs`/`enums`. Перенос одного имени давал
  цели `c` тип без `typedef`, а вариант перечисления не разрешался вовсе
  (`SE-003`). ⚠️ **Корпус класс не покрывает** — в `examples/` перечисления
  границу импорта не пересекают, поэтому сторожа фикстурные и стоят с **обеих**
  сторон: номера ветвей `match` в порождённом C и трасса эталона
  (`{takt-lang,takt-sim}/tests/import_enum_match_tests.rs`, фича
  [0206](docs/features/0206-imported-enum-variant-in-match.md)).
- **Импорт ищется рядом с импортирующим файлом**
  ([0055](docs/features/0055-lsp-multifile.md)) — каталог импортёра добавляется

- **`documentSymbol`: `selection_range` — диапазон ИМЕНИ, `range` — всего
  объявления** ([0147](docs/features/0147-lsp-document-symbol-tests.md)). По

  символа, бери имя как соседние ветви — через `match … { Some => …, None =>
  continue }`, а не `unwrap`: `IdentifierOrError` кладёт `None`, когда имя не
  разобралось, и это паника сервера во время набора. ⚠️ Сегодня путь

- **Семантика переполнения целых нормирована**
  ([0127](docs/features/0127-int-overflow-semantics.md)). Беззнаковое — обёртка
  `mod 2ⁿ` у эталона и всех целей; знаковое — **ошибка программы** (`SIM-003`).
  ⚠️ Цель `rust` печатает `wrapping_*`, и свёртка в `x += 1` для таких узлов
  **отключена**: `+=` паникует в debug.
- **Тип выводится и через ССЫЛКУ на другое объявление**
  ([0204](docs/features/0204-const-ref-type-inference.md)). Вывод спрашивает
  **таблицу объявлений** по имени, а не ячейку ссылки: `ExpressionNode::Variable`
  несёт `Rc::new(RefCell::new(var.clone()))` — снимок, снятый при разрешении
  имени, то есть **до** вывода типов, и в нём навсегда `Inference`. Проходы
  идут до неподвижной точки (таблица — `BTreeMap`, обход алфавитный: цепочка
  `Z → A` иначе не сходится); понижение `q(m, n)` остаётся на **первом**
  проходе. Цена прежнего устройства: `var y := x;` отвергали **все пять**
  потребителей (`CC-015`, `RS-014`, `ST-002`, `SV-002`, `SIM-007` **в такте**),
  а сторож фикстуры проверял, что файл разбирается. ⚠️ «Свернуть инициализаторы
  до вывода типов» — напрашивающееся и **неверное** решение: даёт `bool` вместо
  `bit` (порядок трёх шагов, 0192); контр-пример — в
  `takt-lang/tests/type_inference_chain_tests.rs`. ⚠️ `wider_type` знает пару
  `(Duration, Duration)`; смешение длительности с числом до неё не доходит —
  его отвергает `SE-065`. ⚠️ Правило `(_, Array(n, t))` берёт тип **литерала**,
  из-за чего `const A: u16 := 300; const B := A + 1;` даёт `[bit;8]` и ложную
  `SE-089` — этот класс фича не лечит, он вынесен кандидатом в `FEATURES.md`.
- **Вычисленный инициализатор НОРМИРУЕТСЯ по типу объявления, литерал автора —
  нет** ([0207](docs/features/0207-bitwise-not-unsigned-literal.md), версия
  языка 0.9.0). Беззнаковое — обёртка `mod 2ⁿ` (правило 0127), знаковое —
  ошибка `SE-089`. Цена прежнего устройства: свёртка (0192) считала `~0` в
  `i128` и давала `-1`, проверка диапазона (0157) его отвергала — и `~0` был
  законен **в теле** (255 у эталона, `c`, `rust`) и запрещён в объявлении.
  ⚠️ После свёртки вычисленное значение **неотличимо** от написанного автором,
  поэтому разделяет их свёртка — существующим `is_literal` (он же защищает
  понижение `q`, 0096); `var u: u8 := 300;` остаётся ошибкой, а
  `var u: u8 := 200 + 100;` даёт `44`, как та же запись в теле. ⚠️ Границы —
  у **одного** носителя (`validate::literal_range::type_range`): своя копия
  разошлась бы с `SE-089`.
- **Инициализатор `var`/`const` доезжает до потребителей ЛИТЕРАЛОМ**
  ([0192](docs/features/0192-const-init-fold.md)). Свёртку делает существующий
  `semantic/const_eval/` (0185) — тем же приёмом, каким 0187 свернула начальное
  значение порта, а 0143 — константную выдержку: за границей семантики выражения
  не существует, и расходиться потребителям **не по чему**. Цена прежнего
  устройства: `var a: u8 := 1 + 2;` означало **пять разных** вещей — эталон `0`
  (арифметика была «не константа»), `c`/`rust` `3`, `st` теряла значение молча,
  `sv` отказывала. Имя переменной в инициализаторе значит её **начальное
  значение** и ссылается только **назад по тексту** (решение заказчика).
  ⚠️ **Порядок трёх шагов обязателен** и собран в одном месте
  (`declaration::prepare_variables`): разрешить → вывести типы → **свернуть**.
  Свернув раньше вывода типов, получишь `bool` вместо `bit` (значение верное,
  тип нет). ⚠️ **Литерал не подменяется** — дробный к этому моменту уже понижен

  **значение его запоминается всегда**, иначе `var base := 5; var probe := base
  + 1;` молча даст `0`. ⚠️ Послабление «имя вычислимо» живёт в наполнении
  `const_eval::Locals`, а **не** в `resolve_name`: тот же вычислитель обслуживает
  `after` (0143), параметры (0185) и порты (0187), где «значение известно только
  в такте» — верное правило. Сторожа — значенческие
  `takt-lang/tests/const_init_fold_tests.rs` и потактовые сверки Q-арифметики
  (поймали обе перестановки; чтение кода не поймало ни одной).
- **Обходы по числу состояний — итеративные, не рекурсивные**
  ([0052](docs/features/0052-verify-iterative-traversal.md)): рекурсия роняла

### Типы и представление

- **Носитель числового значения — `i128`; граница приёма литерала — ТИПЫ языка**
  ([0157](docs/features/0157-literal-u64-representation.md)). `Token::Number` →
  АСД → `ExpressionNode`/`ConditionNode` → `eval::Value::Number` несут `i128`;
  приём — `[i64::MIN, u64::MAX]` (объединение диапазонов самого широкого
  знакового и самого широкого беззнакового типа), вне — `LE-009`. Границы и
  восстановление после отказа — `parser/literal_range.rs`. ⚠️ Носитель шире
  приёма **намеренно**: промежуточный результат константного вычисления не
  должен переполняться там, где итог по типу законен. ⚠️ Значение варианта
  перечисления — тот же `i128`: второй носитель числа завёл бы границу между
  ними. ⚠️ Обёртка `u64` работает через **общий** путь `coerce_integer` —
  спецслучая «bits >= 64» больше нет (он и давал `SIM-004` вместо обещанной
  0127 обёртки). ⚠️ Адрес порта остался `i64`: литерал шире сужается **явным**
  отказом `SE-055`, а не `as i64`.
- **Литерал вне диапазона типа приёмника — `SE-089`**
  ([0157](docs/features/0157-literal-u64-representation.md),
  `semantic/validate/literal_range.rs`). Проверяются позиции с **объявленным**
  типом (инициализатор `var`/`const`, присваивание переменной); проверка
  накопительная. ⚠️ `bit`/`bool` пропущены намеренно — их значения проверяет
  `validate_bit_values`, иначе две диагностики об одной причине. ⚠️ Проверяется
  **литерал**, не значение выражения: свёртки констант в семантике нет.
- **Печать широкого литерала зависит от цели**
  ([0157](docs/features/0157-literal-u64-representation.md)). `c` — суффикс
  `ULL` выше `LLONG_MAX` (`generator/c/c_literal.rs`), иначе
  `-Wimplicitly-unsigned-literal` под `-Werror`; `sv` — размерная форма
  `<W>'d<value>` по ширине **приёмника** (`sv_type::sized_literal`), иначе
  `WIDTHEXPAND` **уже с 33 бит**; `st`/`rust`/`plantuml` — как есть (доказано
  гейтами `iec2c` и `rustc -D warnings`). ⚠️ Особая форма печатается **только**
  по нужде — иначе поехали бы снапшоты `examples/generated/`. Сторож —
  `takt-lang/tests/wide_literal_tests.rs` (эмиссия + настоящие гейты).
- **`[bit;N]` — упакованный вектор** ([0078](docs/features/0078-bit-array-semantics.md)):
  скаляр при N ≤ 64, массив `uint64_t[⌈N/64⌉]` при N > 64. Правило — в едином слое
  `semantic::bit_vector`.
- **Fixed-point `q(m, n)`: арифметика ПОБИТОВО едина** у симулятора и всех целей
  ([0061](docs/features/0061-fixed-point-type.md)). Эталон — `takt-sim/src/eval/fixed.rs`;
  `*` — floor к −∞, `/` — к нулю. ⚠️ Цель `c`: floor эмитится **не сдвигом**, а
  хелпером `lam_q_floordiv` — `>>` знакового отрицательного в C
  implementation-defined (C11 6.5.7p5); сторож — греп «в порождённом C нет `>>`».
  ⚠️ Цель `st`: сдвигов над числами в IEC нет вовсе. ⚠️ Цель `rust`: `x := x * y`
  над `q` НЕ сворачивается в `x *= y`. Сверки — `conformance_{c,rust,st,sv}_tests`.
  ⚠️ **Перенос идёт к `W = m + n`, а НЕ к ширине хранения**
  ([0061-01](docs/fixes/0061-01-q-wrap-storage-width.md)). Тип хранения
  округляется вверх до 8/16/32/64 (в C нет `int12_t`), и три цели выражали им
  границу переноса: на `q(6, 6)` эталон давал −26.0, а `c`/`rust`/`st` — 38.0
  (цель `sv` была права: `logic signed [W-1:0]`). Дожило из-за дыры в
  **покрытии** — корпус и фикстуры состоят из `q(8, 8)` и `q(4, 4)`, где обе
  границы совпадают. Теперь перенос эмитится явно и **только при `W ≠ S`**
  (иначе поехал бы вывод корпуса): `lam_q_wrap` в C, пара сдвигов в Rust,
  `LAM_Q_WRAP` на `MOD` в ST; при `W ≥ 63` цель `st` отказывает `ST-021` —
  модуль `2^W` в `LINT` непредставим. ⚠️ Дефект достижим и через
  `--float-as-q=m.n` (0096): флаг принимает любые `m`/`n`.
- **Насыщение — свойство ТИПА: `q(m, n) sat` прижимает, `q(m, n)` переносит**
  ([0170](docs/features/0170-fixed-point-saturation.md)). Признак — поле
  `TypeNode::Fixed { m, n, sat }` и зеркальное `Value::Fixed`, то есть часть
  **формата**: смешение `sat` и не-`sat` запрещает существующий `SE-059`
  (отдельный код заводить не стали — два места, обязанные давать один вердикт),
  явное `as q(m, n) sat` законно. Развилка одна на реализацию (`make` эталона,
  `open_wrap`/`close_wrap` у `c`, `wrap_to` у `rust`, `wrap_lint` у `st`,
  `saturate_sv` у `sv`); хелпер эмитится по факту вызова, поэтому вывод корпуса
  не изменился. ⚠️ Слово после формата, отличное от `sat`, — **`SE-104`**: без
  отказа опечатка (`q(8,8) sta`) вернула бы молчаливый перенос вместо
  запрошенного насыщения. ⚠️ **Прижатие идёт до сужения**: у `st` — в `LINT`
  перед `LINT_TO_{S}`, у `sv` промежуток считается в `2W` (в `W` места нет);
  иначе сравнение с границами идёт по уже обёрнутому значению, и оба
  инструмента такой вывод принимают молча. ⚠️ Насыщение эмитится **всегда**, а
  не только при `W ≠ S` (в отличие от переноса): границы формата типу хранения
  неизвестны. Сторожа — сверки значений на `q(6, 6)`, включая край
  `−(−2^(W−1))` (единственная **унарная** операция, где семантики расходятся);
  каждая проверена мутацией.
- **Прозрачный `float` через глобальную Q-точность**
  ([0096](docs/features/0096-fixed-point-native-float.md)): автор пишет `float`,
  представление выбирают флаги `--float-as-q=m.n` / `--float-embedded`. ⚠️ Это
  **осознанное исключение** из принципа «CLI не меняет логику автомата» (0042) —
  оба режима документированы и сверяются. ⚠️ **Главная засада:** `VariableNode`
  живёт в **двух** представлениях (owned в `model.variables` и за `Rc<RefCell>` в
  теле) — проход обязан мутировать **оба** `ty`, иначе объявление `q`, а арифметика
  `float`. Сторож — `variable_cell_in_body_is_retyped`. ⚠️ Литерал понижается
  **только** в инициализаторе объявления, не в телах; проход **идемпотентен** по
  гейту «исходный тип был `Rational`».
- **Сдвиг `>>` определён в целях по-разному.** В C знакового отрицательного —
  implementation-defined; в Rust арифметический; в ST сдвига над числами **нет**;
  в SV определён. Операторов `<<`/`>>` в языке Takt **нет** — фича, которая их
  введёт, обязана задать семантику **нормативно**.
- **Знак и ширина перечисления считаются общим слоем** `semantic::enum_facts`
  ([0060](docs/features/0060-enum-width-shared-layer.md)); цель `c` даёт
  `int{bits}_t` при `signed`. Прежде знак терялся молча.
- **Структурные типы**: объявленный **порядок полей значим** (не `BTreeMap`),
  инициализатор `{…}` позиционный ([0034](docs/features/0034-sim-struct-types.md)).
  Доступ к члену — общий `eval/access.rs::read_member`, запись — `eval/place.rs::update`
  (лист приводится к **типу поля**). Сравнение структур — `TypeMismatch`: C
  запрещает `==`, и симулятор «умнее» эталона врал бы. Доступ к несуществующему
  полю — компайл-тайм `SE-061`.
- **Массивы `[T;N]` исполняются симулятором** ([0076](docs/features/0076-sim-arrays.md)):
  запись элемента и запись поля структуры — **единый** сегментный механизм «места».
  Границы/вид → `SIM-010`.
- **Константная выдержка `after` вычисляется на СЕМАНТИКЕ и до целей не доезжает**
  ([0143](docs/features/0143-after-const-duration.md)). `after 3m`, `after DWELL`,
  `after (BASE + 30s)` дают один узел `ConditionNode::After(нс)` — за этой границей
  формы не существует, поэтому шесть целей не могут по ней разойтись. Вычислитель
  — `semantic/condition/after_const.rs` (литералы, константы `duration`, цепочки,
  `+`/`-`, предел глубины 32); всё прочее → `SE-072` с **названной** причиной.
  ⚠️ Аргумент живёт в грамматике **условий**: `*`, `/` и `as` там отсутствуют, а
  составное выражение обязано быть в скобках (`after` связывает крепче арифметики,
  поэтому `after A + 1s` = `(after A) + 1s`) — скобки хранятся в дереве, иначе
  печать форматтера изменила бы смысл. Сторож — не «собралось», а
  **тождественность вывода** литеральной форме во всех целях
  (`takt-lang/tests/after_const_duration_tests.rs`).
- **Тип `duration` в целях — целое в МИЛЛИСЕКУНДАХ; выдержка бывает вычисляемой**
  ([0183](docs/features/0183-duration-type-in-targets.md), в разработке).
  `uint32_t` / `u32` / `UDINT` / `logic [31:0]`; единица та же, что у приведения
  `as` (0134), поэтому граница «длительность ↔ число» **не порождает арифметики**
  — сторож проверяет это **текстом** вывода. Пересчёт — только
  `semantic::duration::value_millis` (`SE-063` при некратности мс, `SE-064` за
  32 бита). ⚠️ Тип `TIME` в цели `st` **не** выбран: арифметика над ним в MatIEC
  ограничена. ⚠️ **Вычисляемая выдержка** (`after (v + 1s)`, узел
  `ConditionNode::AfterExpr`) требует множителя `hertz / 1000` в профиле «такты»
  — частота, при которой он не цел, отвергается `SE-073`; в профиле «часы» цель
  `st` отказывает `ST-016` (переменный `PT` у `TON`). ⚠️ **Ширина счётчика
  выдержки поднимается до 32 бит**, если выдержка вычисляемая: иначе `rust` не
  компилируется (`u8 >= u32`), а `c`/`sv` **молча** усекают. ⚠️ Четыре обхода по
  `ConditionNode` кончаются `_ =>` и компилятором **не** охраняются: два в
  `time_ast`, `unused::collect_from_condition` (пропуск даёт ложное «переменная
  нигде не используется») и `rust_cond::condition_type` (пропуск даёт `RS-011`
  на готовом булевом выражении). В `unused.rs` таких сборщиков **два**.

### Цели генерации

- **Вход в стартовое состояние не расходует такт**
  ([0033](docs/features/0033-init-tick-alignment.md), версия языка 0.3.0). Тело
  стартового состояния исполняется на **такте 1** на любой глубине. **Контракт для
  будущих бэкендов:** не воспроизводить чужие `INIT`-такты. Сверка —
  `conformance_c_tests::per_tick_trace_*`.
- **Model-level `always` исполняется каждый такт** до диспетчеризации состояния
  ([0083](docs/features/0083-model-always-block-c.md)) — в симуляторе и во всех
  целях, **включая модель, чьё состояние есть композиция**
  ([0194](docs/features/0194-sim-composition-model-always.md)). Прежде молча
  терялось везде, а у композиции — только в эталоне (цели соблюдали контракт
  вчетвером). ⚠️ Механизм исполнения был **на месте**: `tick_body` зовёт
  `execution("always")` для любого вида юнита, а `Unit::execution` читает
  `executions` и у `Parallel`, и у `Sequential` — не наполнялось **поле**, и
  потому дефект пережил 0083 и фикс 0181-01. Компиляция блоков — одна на обоих
  строителей (`unit/blocks.rs`); контекст владельца строится **один раз** и
  отдаётся и ветвям, и телу (две ячейки = молча неработающая починка).
  ⚠️ Сторожа обязаны стоять на **накапливающем** теле (`n := n + 1`): на
  идемпотентном пропуск и двойное исполнение (дефект-близнец 0181-01)
  неразличимы. Model-level `enter`/`exit` **не** реализованы — одинаково у
  композиции и обычной модели (замер 0194); `every` уровня модели грамматикой не
  принимается вовсе.
- **Генератор C: вывод компилируется, отображение типов доверено**
  ([0026](docs/features/0026-c-root-typedef.md),
  [0029](docs/features/0029-c-type-mapping.md)). `map_c_type`: `Bit` → `uint8_t`,
  `Rational` → `double`/`float` по `FloatWidth`, `[bit;N]` → через `bit_vector`,
  прочие массивы → **диагностика** `CC-014`/`CC-015`. Корпус компилируется гейтом
  `cc`/`cmake`, `conformance_c_tests` — **основной потактовый эталон** проекта.
  ⚠️ Эталонный `SRC` (`lib.rs::parse_simple`) целью `c` не компилируется **по
  замыслу** — он покрывает парсер; компилируемость доказывает
  `reference_model_tests::SYNTH_SRC`. ⚠️ Неиспользуемая переменная не попадает в
  структуру — штатный фильтр `c_header.rs::generate_model_header`.
  ⚠️ **Оба гейта цели `c` идут под `-Wall -Werror`**
  ([0171](docs/features/0171-c-gate-werror.md)): корпус через `cmake`, `c-hal`
  через `cc -c`. Прежде флагов не было вовсе, и гейт принял тождественно ложное
  `if (model->lv == -5)` при `uint8_t lv` — `cc` об этом **говорил**, а гейт не
  слушал. Замер перед включением: корпус под `-Wall` даёт **0** предупреждений;
  `-Wextra` добавил бы 38 одного класса (`-Wunused-parameter`) — кандидат.
  ⚠️ Флаги живут **в гейте**, а не в `CMakeLists` примера: `-Werror` в
  поставляемом файле навязал бы строгость всякому, кто скопирует
  `examples/generated/c`. ⚠️ Помощник `<Root>_bind_default_hal` эмитится
  `static inline`, а не `static`: он в заголовке и зовётся не всякой единицей
  трансляции — у голого `static` это `-Wunused-function` в сборке пользователя.
- **Неразрешённый узел в цели `c` — отказ `CC-023` с позицией, а не пустота**
  ([0236](docs/features/0236-c-unresolved-condition-refusal.md)). Условие,
  выражение и оператор зовут **одну** воронку `c_unresolved::refuse(loc, вид)`
  (образец `FM-001` фичи 0229: один код, вид назван словом, позиция — у
  АСД-узла). Цена прежнего устройства: условие печаталось пустой строкой
  (`assert( < 3);` — отказ давал `cc`), оператор исчезал, а **ребро с
  неразрешённым условием считалось безусловным** (`None | Unresolved` в одной
  ветви) — валидный C, другой автомат; проба:
  `case PROBE_RUN: { model->state = PROBE_DONE; break; break; }`.
  ⚠️ **Не всякий `Unresolved` — дефект:** правая часть `S(Модель) = Состояние`
  приходит неразрешённой по инварианту и разбирается **до** воронки; поэтому
  проход «в дереве не бывает `Unresolved`» отвергнут — он завёл бы второе знание
  о форме паттерна (класс 0203). ⚠️ Отказ **недостижим** из корректной
  программы: вход отсекает семантика (`SE-025`/`SE-003`), то есть недостижимость
  держит другая фича. Сторож — перечисление видов узла в
  `takt-lang/src/generator/c/c_unresolved.rs`, падает **списком**.
- **Генератор ST: вывод принимается `iec2c`, гейт зелён** (8/8 корпуса,
  [0041](docs/features/0041-st-backend.md), [0090](docs/features/0090-ci-precheck.md)).
  Факты MatIEC, снятые пробами (нарушишь — вывод перестанет компилироваться):
  массивы **не вкладываются**; перечислимый тип с явными значениями отвергается →
  целый тип + `VAR CONSTANT`; `VAR_GLOBAL` вне `CONFIGURATION` недопустим; массиву
  нельзя дать скалярный инициализатор; **порядок секций в `FUNCTION` значим** —
  локальный `VAR` печатается **до** `VAR CONSTANT` (сторож
  `test_function_var_precedes_var_constant`); идентификаторы IEC
  **регистронезависимы** и делят пространство со стандартной библиотекой —
  `left`/`right`/`mid`/`limit`/`step` отвергаются, диагностика при этом обманчива.
- **Цель `st`: вход в стартовое состояние печатается `IF state = 0` ПЕРЕД
  `CASE`** ([0191](docs/features/0191-st-per-tick-conformance.md)). Ветвью
  `CASE` его выразить нельзя: `CASE` в IEC **не проваливается**, поэтому
  `0: (* INIT *) state := 1;` заканчивал скан, ничего не исполнив, — по
  холостому скану на каждый уровень вложенности (замер трассы: `0 0 8 8 8 …`
  против `8 …` у эталона и цели `c`). Сторож — **потактовая** сверка
  `takt-sim/tests/conformance_st_per_tick_tests.rs`, а не факт компиляции:
  `iec2c` принимал и сдвинутый вывод. ⚠️ Дефект дожил потому, что был **закреплён
  тестами**: сверки шли «с поправкой на INIT-сдвиг»; поправки сняты.
  ⚠️ Инициализатор `[bit;N≤64]` глушить **нельзя** — это упакованный скаляр
  ([0078](docs/features/0078-bit-array-semantics.md)), а не массив; признак
  берётся из `semantic::bit_vector`, тем же слоем, что и печать типа.
- **Имена моделей делят пространство со стандартной библиотекой IEC**: модель
  `Concat` → `invalid function block name`. Имя корневой модели берётся **из имени
  файла**, поэтому ловушка срабатывает и на `concat.takt`. Ловится гейтом, не тестами.
- **Выражения ST: числа и биты — непересекающиеся миры**
  ([0041](docs/features/0041-st-backend.md)). `AND`/`OR`/`XOR` определены только на
  битовых строках, арифметика на них запрещена → побитовые операции идут через
  преобразование **в месте операции**, отсюда трансляция **типозависима** (без типа
  операнда → `ST-011`, а не догадка). Битового доступа `x.0` в MatIEC **нет вовсе**.
  Литералы в телах печатаются по целевому типу
  ([0066](docs/features/0066-st-bool-literals.md)).
- **Имя константы КВАЛИФИЦИРОВАНО владельцем во всех целях**
  ([0193](docs/features/0193-shared-const-qualified.md)). Модуль цели `rust` один
  на программу, модуль цели `sv` уплощён — это **одно** пространство имён, и
  голое имя означало, что `model A { const K := 2 }` и `model B { const K := 3 }`
  дают одно объявление: вторая модель молча считала чужим значением (эталон и
  цель `c` тот же вход переводили верно — расходились **цели между собой**).
  Печать и дедупликация обязаны идти **одной** функцией на цель
  (`rust_expr::const_ident`, `sv_expr::const_signal`); разъехавшись, они дают
  либо потерянное объявление, либо ссылку в пустоту. ⚠️ Ключ «константа
  используется» (`semantic::unused::const_key`, пара владелец + имя — образец
  `qualified_port_key` 0084) обязан согласоваться с печатаемым именем и
  строиться **из `upper` узла**, а не из «модели, которую печатаем»: по голому
  ключу неиспользуемая тёзка печаталась бы вслед за используемой, а
  неиспользуемая `const` в Rust под `-D warnings` — это **отказ** сборки.
  ⚠️ Потребителей ключа **шесть**, и цель `st` среди них (свои константы,
  унаследованные от предков, константы функции) — заводя новый, ищи по имени
  поля, а не по форме `usage()`. Сторож — потактовая сверка
  `takt-sim/tests/conformance_shared_const_tests.rs`, а не гейт: `clippy`,
  `verilator` и `yosys` дефектный вывод **принимали**.
- **Генератор Rust: приоритеты C и Rust расходятся МОЛЧА**
  ([0050](docs/features/0050-rust-backend.md)). `a == b | c` даёт в C `1`, в Rust
  `false`. Поэтому печатник заключает в скобки **каждый** бинарный узел, а лишние
  внешние снимает `unwrap_outer`. Не «стиль»: **на целых дефект был бы тихим**.
  Прочие ловушки цели: `#![no_std]` в модуле не эмитится (доказывает гейт);
  перечисление в присваивании приходит **числом** (вариант восстанавливается по
  целевому типу); под-модель не получает указатель на корень — общие переменные
  свёрнуты в `<Root>Shared` ([0059](docs/features/0059-rust-shared-struct.md));
  функции получают состояние **параметрами** (`hal` — последним, иначе E0499);
  мёртвый инициализатор не эмитится; соседние рёбра в одно состояние сливаются
  через `||`. Политика линтов — `-D warnings`: не эмитить недостижимое.
  ⚠️ `pub enum` с неконструируемым вариантом гейт **проходит** — сделать state-enum
  публичным значит заглушить сторожа видимостью. Не делать.
  ⚠️ **`bit` в цели — это `bool`** ([0148-01](docs/fixes/0148-01-rust-bit-compare.md)):
  сравнение `bit`-операнда с литералом сводится к самому операнду (`x = 1` → `x`,
  `x = 0` → `(!x)`), иначе получается `bool == 1` (`E0308`) либо `bool == true`
  (валит `clippy::bool_comparison`). Присваивание коэрцию делало всегда —
  разошлись два пути одной идеи. ⚠️ **Открыт фикс
  [0148-02](docs/fixes/0148-02-rust-port-to-port-borrow.md):** `led := btn;`
  даёт `hal.write_bit(P, hal.read_bit(Q))` → **E0499**; проводка «вход на выход»
  целью `rust` не транслируется. Два чтения в одном выражении при этом законны.
  ⚠️ Гейт цели гоняет **только корпус**, и оба дефекта дожили именно поэтому:
  ветви печатников сверяет `takt-lang/tests/rust_printers_tests.rs` (фича 0148) —
  **текстом**, а не фактом сборки.
- **Конструктор без аргументов идёт в паре с `impl Default`**

  `is_root && !uses_hal`, буквально то же, при котором срабатывает
  `clippy::new_without_default`. ⚠️ При `new(hal: H)` печатать `Default`

  `takt-lang/tests/rust_default_impl_tests.rs` (эмиссия + прогон настоящего

- **Генератор SV: гейт доказывает валидность, но НЕ верность**
  ([0045](docs/features/0045-sv-backend.md)). Такт ≡ `posedge clk`; автомат

  ([0235](docs/features/0235-guard-formula-in-st-sv.md)). `c` печатает
  `assert(…)`, `rust` — `assert!(…)` с именем инварианта, **`sv` — `assert (…);`**,
  **`st` — предупреждение `ST-022`** и продолжает трансляцию (в IEC 61131-3
  конструкции `assert` нет вовсе, а придумывать замену бэкенд не вправе). Прежде
  `st` и `sv` теряли формулу **молча** — прошивка шла без объявленной охраны.
  ⚠️ **Форма для `sv` — без `else`:** `assert (…) else $error("…")` verilator
  **принимает**, а yosys отвергает (`unexpected TOK_ELSE`), то есть добавленное

  переносится по устройству синтезатора. ⚠️ Место — `always_comb`, **до**
  присваиваний уровня (умолчание `name_next = name` уже выполнено), как `assert`
  в начале `_tick` цели `c`; синтез не дорожает (ячейка `$check`).
  ⚠️ Предупреждение `ST-022` выдаётся на **каждую** формулу — счёт сторожит тест:
  одно на модель означало бы молчаливую потерю второй. ⚠️ **Корпус класс не
  покрывает** (в `examples/` формул ноль) — сторож только фикстурный:
  `takt-lang/tests/guard_targets_tests.rs`.

  ([0166](docs/features/0166-sv-example-sequential-composition.md)). Прежде
  `SV_TRANSLATABLE` состоял из моделей на `|`, и синтез на `+` прогонялся

- **Имя перечислителя порта несёт сегмент `PORT_`; имя поля печатается той же

  ⚠️ Отдельно: поле под-модели объявляется `local_lowercase_snakecase()`, и

- **Адрес порта: три источника с приоритетом** inline `:=` < оператор `address` <

  ([0208](docs/features/0208-const-evaluators-unification.md)): таблица

  и `const_eval::int_op` — тонкие переводчики её ошибок в свои диагностики. У
  адреса остаётся **своё**: носитель (сужение `as i64` равносильно обёртке по 64
  битам — сторож в юнит-тестах), запрет операнда `адрес:бит` и набор допустимых
  форм (сравнения отсекает **матчер**, а не таблица). ⚠️ Вычислитель выдержки
  (0143) в эту таблицу **не сводится**: он считает наносекунды `checked_*` — иной
  домен и иная семантика переполнения. ⚠️ `--define` даёт среду, видимую **только**
  вычислителю адреса — CLI не меняет логику автомата. ⚠️ Потребляют адрес только
  цели `c-hal` и `st-at`; цель `c` его **не эмитит** (порты идут через
  HAL-колбэки). `address` — жёсткое ключевое слово.
- **Ключ карты адресов квалифицирован моделью**

- **Направление порта проверяется во ВСЕХ позициях**
  ([0188](docs/features/0188-port-direction-everywhere.md)). Запись в `in` —
  `SE-026`, чтение из `out` — `SE-027`; правило действует в условиях, телах

  **молча**, и шесть потребителей расходились — `rust` отказывал (`RS-018`),
  `c`/`st`/симулятор исполняли, `sv` печатал присваивание входу модуля

  ⚠️ Судья один — `validate/common.rs::validate_expression`; проход
  `validate/bodies.rs` только **доставляет** ему выражения. Заводя новую
  позицию в языке, добавляй её в обход, а не пиши второе правило.
  ⚠️ Левая часть присваивания — **место записи, а не чтение**: исключение
  покрывает обе формы (`led := 1` и `led.0 := 1`), иначе законная запись в выход

  память» — через переменную); смягчение обсуждается осью 3B фичи

- **Присваивание — оператор, а не выражение; доступ к порту нормирован**
  ([0187](docs/features/0187-port-io-redesign.md), ось 4, вариант 4B).
  Позиций записи **три** — выражение-оператор тела, шаг `for` и именованный
  аргумент вызова (`Pid(kp := 0.25)`, форма 0185). Первые две держит
  **грамматика** (**`SY-006`**, фикс
  [0187-01](docs/fixes/0187-01-assignment-is-statement-in-grammar.md)), третью —
  семантика (**`SE-095`**, `validate/assignment_position.rs`): на уровне АСД
  вызов функции и инстанцирование модели неразличимы. Цена
  прежнего молчания: `seen := (value := 3) + 1;` язык принимал, а не умел
  **никто** — `c` печатал `void + int`, `rust` — `() + {integer}`, `st` —
  невалидный ST (отказ давал чужой инструмент на порождённом файле), `sv`
  отвечал `SV-002`, симулятор — `SIM-014` **в такте**. ⚠️ На переменных было
  хуже, чем на портах: `(a := 3) + 1` цель `c` печатала **валидным** C и
  считала, тогда как эталон ту же модель не исполнял вовсе. ⚠️ Судьи (`SE-026`/
  `SE-027` и `SE-095`) делят **один** обход тел — `validate/bodies.rs`; он же
  знает позицию выражения, потому что судья её не выводит, а принимает.
  ⚠️ Форма доступа целей зафиксирована **таблицей и сторожем**

  контракт, а не образец.
- **Позиция бита однобитного порта нормируется в слое адресов**

### Симулятор

- **Семантика вычислений живёт только в `takt-sim/src/eval/`**
  ([0025](docs/features/0025-simulator-expression-eval.md)). Адаптеры семантики
  **не содержат**; тела блоков и функций исполняет один интерпретатор
  `unit/statement.rs::exec_statement`. Модуль `eval` под
  `deny(clippy::wildcard_enum_match_arm)`: ветка `_` по узлу языка завалит сборку —
  так задумано ([0093](docs/features/0093-wildcard-match-rule.md), гейт
  `scripts/check-exhaustive-nodes.sh`). **Второй вычислитель** (начальные значения,
  `unit/initial.rs`) под тем же `deny` с фичи
  [0163](docs/features/0163-builder-eval-exhaustive.md); гейт сторожит **оба**
  модуля и ищет атрибут **с начала строки** — иначе его находил док-комментарий,
  и модуль без атрибута проверку проходил. ⚠️ Правило названо для трёх узлов
  языка: подстановочные ветки по `TypeNode`/`StateNode`/`Extend` в `builder.rs`
  им **не** покрыты и осмысленны.
  ⚠️ Тесты симуляции пиши **на значения** (`Unit::variable`), а не на факт
  перехода: именно отсутствие этого слоя дало восемь дефектов при зелёных тестах.
  ⚠️ **Второй вычислитель — не «только литералы»**
  ([0205](docs/features/0205-as-in-declaration-initializer.md)): он считает
  приведение `as` (зовя **тот же** `eval::cast_to_type`, что и такт) и читает
  константу по ссылке — **из таблицы объявлений** (`search_var`), а не из ячейки:
  в ячейке снимок с ещё не понижённым АСД (урок 0204). Цена прежнего устройства
  измерена: из восьми форм приведения **шесть** давали эталону ноль при верном
  значении у цели `c` (`5 as u16` → 0 против 5), две падали `SIM-006` в такте.
  ⚠️ Своей арифметики приведения здесь заводить нельзя — разойдётся с тактом;
  свёртка `as` в семантике отвергнута по той же причине, по какой `const_eval`
  не считает дробных: округление `q` задано эталоном. Предел `MAX_REF_DEPTH`
  нужен из-за взаимных констант (`const A := B; const B := A;`).
- **Значение `extern`-функции задаёт СЦЕНАРИЙ**
  ([0209](docs/features/0209-model-external-interface.md)). Секция `extern` шага:
  одно значение на такт либо таблица по **первому** аргументу («память»).
  ⚠️ Умолчания нет: не задали — прежний `SIM-019`. Ноль сделал бы сверку трасс
  зелёной при расхождении эталона с прошивкой — класс, ради которого сверки и
  заведены. ⚠️ Стенд принадлежит **шагу** и ставится перед тактом, как модельное
  время; доехать он обязан до **всех** областей видимости (`BlockScope`,
  `FunctionScope`, `Unit` в роли контекста) — умолчание трейта в любой из трёх
  означает «стенда нет», и подмена молча не срабатывает.
- **Единый источник истины по значениям — `ModelNodeContext`**
  ([0032](docs/features/0032-state-io-variables.md)): писать только через
  `Context::set_value`, читать через `get_value`/`dump`.
- **Узел языка в симуляторе разбирают ТРИ места, и они расходятся**
  (фикс [0134-02](docs/fixes/0134-02-duration-literal-in-body.md)): адаптер
  условий (`predicate.rs`), адаптер выражений (`expression.rs`) и вычислитель
  начальных значений (`unit/initial.rs`). Литерал длительности жил в двух из трёх:
  в теле блока `left := left - 1s;` отвечал `SIM-007`, хотя документ обещает
  арифметику, а инициализатор объявления работал. ⚠️ **Гейт исчерпаемости этот
  класс не ловит по устройству:** узел разобран, ветвь есть — она просто отвечает
  отказом «до будущей задачи», и отказ переживает саму задачу. Сторож — только
  проверка **поведения**; заводя ветвь-заглушку, заводи и тест, который её
  снимет. ⚠️ Тест на арифметику существовал и дефект **не ловил**: складывал две
  переменные, а падал литерал.
- **Реализация МОДЕЛИ (`model M = A | B { … }`) разворачивается в состояние**
  ([0199](docs/features/0199-model-implements-brace-form.md)). Форма — синоним
  записи `model M { start Имя = A | B; }`, и разворот делает
  `extend::expand_model_implement` на построении дерева: за этой границей формы
  не существует, и пяти потребителям не по чему разойтись (приём 0143/0187/0192).
  ⚠️ Прежде `ModelNode::implements` не разрешался **никогда** — разрешались
  только реализации состояний: эталон давал пустую трассу, а все четыре цели
  искали состояние с пустым именем. ⚠️ **Разрешить `implements` в поле мало**:
  карта (`semantic::minimap`) строит состояния из `model.states`, и от такой
  правки чинится **только эталон** (проверено). ⚠️ Модель с реализацией **и**
  собственным состоянием — `SE-101`: прежде такая запись работала, **молча
  теряя** реализацию. Коллизии имени синтетического состояния нет по построению
  — других состояний у модели с реализацией не бывает.
- **Реализация состояния — дочерний юнит узла с ОБЩИМ контекстом**
  ([0181](docs/features/0181-sim-state-implementation-tick.md), закрытие фикса
  [0057-01](docs/fixes/0057-01-sim-composition-next.md)). `state P = A + B { … }`
  живёт в `UnitKind::Node::state_impls`; такт тикает её **до** проверки переходов
  и берёт переход только по завершении — на том же такте (эталон — цель `c`,
  `generate_extend_transition` в ветви `is_done`). Повторный вход композицию
  **не** перезапускает — тоже контракт цели `c`. ⚠️ `next` живёт **отдельным
  полем** `StateNode::Implement::next`, а не среди `references`: заводя новую
  форму перехода, проверь, что `build_transitions` её видит — иначе состояние
  застрянет молча. ⚠️ Шаги `+` обязаны делить родительский контекст (общий
  `shared_context` с `Parallel`), иначе значение шага A шагу B не видно. Сторожа
  — тройная сверка sim≡C≡SV в `conformance_sv_tests` и
  `takt-sim/tests/sequential_composition_tests.rs`.
- **`Unit::execution` в дочерние юниты НЕ спускается** — фикс
  [0181-01](docs/fixes/0181-01-sim-parallel-always-twice.md). Ребёнок исполняет
  свои блоки сам, в собственном `tick_body`; вернуть спуск значит исполнить
  `always` под-модели композиции **дважды** за такт (симулятор давал 2, цель
  `c` — 1; било и по `|`, и по `+`). ⚠️ Дефект был **невидим для всего
  покрытия**: тела корпуса идемпотентны (`x := <выражение>`), и лишнее
  исполнение в них неразличимо. Сторож — значенческие тесты на **накапливающем**
  теле (`n := n + 1`) в `takt-sim/tests/sequential_composition_tests.rs`.
- **Порты под-моделей композиции драйвятся**
  ([0079](docs/features/0079-sim-composition-ports.md)): `PortNames::from_model`
  обходит `model.models` рекурсивно. ⚠️ Правки требовало **перечисление**, а не
  чтение/запись — те адресуют все ветви.
- **Порт адресуется квалифицированно** `Модель::порт`
  ([0135](docs/features/0135-sim-qualified-port-names.md)); голое имя работает как
  прежде. ⚠️ Квалификатор — **имя модели, а не путь**: две под-модели с одинаковым
  именем неразличимы.
- **Сценарий пишется именами портов**
  ([0132](docs/features/0132-sim-named-port-scenarios.md)); неизвестное имя →
  `SIM-030`, двусмысленное → `SIM-031`. ⚠️ Позиционная форма **опасна**: индекс —
  место имени в **алфавитном** списке, поэтому добавление порта молча сдвигает
  весь массив. ⚠️ Значения портов удерживаются между тактами: явный ноль после
  единицы есть сброс.
- **Инварианты проверяются** ([0044](docs/features/0044-sim-assert-invariant.md)):
  `invariant Имя = C;` — сахар над `cond` + `Formula::Guard`; нарушение →
  `TickResult::Failed` + `SIM-025`. Мягкий режим (`--invariant-soft`) **записывает**
  нарушение и продолжает такт. ⚠️ Ошибка **вычисления** условия — `Failed` в обоих
  режимах; в сверке с C мягкий режим не участвует.
- **Сценарии примеров проверяются прогоном** (`examples_scenario_tests.rs`): у
  каждого `examples/*.takt` обязан быть либо контракт (цепочка + бюджет +
  завершение), либо исключение **с причиной**.

### Верификация

- **Абстракция управляющего графа** ([0049](docs/features/0049-model-checking-ltl.md)):
  атом = имя состояния, условия рёбер абстрагированы. «Держится» надёжно,
  «нарушено» может быть ложным. ⚠️ **Самопетля — не только у тупика:** её получает
  всякое состояние без **безусловного** `ref`. Первая редакция ставила петлю лишь
  вершине без рёбер → Крипке была **недо**-аппроксимацией → ложный `Holds`.
  Правило: ошибаться только в сторону **лишних** прогонов.
  ⚠️ **Капкан, стоивший дефекта** ([фикс 0010-01](docs/fixes/0010-01-buchi-acceptance.md)):
  `build_buchi` принимал любой бесконечный прогон, потому что тесты проверяли
  **структуру** автомата, а не язык. Тесты верификации пиши **на вердикт**.
  Область формулы — по месту объявления; область проверки — свой файл
  ([0051](docs/features/0051-verify-scope.md)).
- **Свойства над данными — абстракция по формуле**
  ([0068](docs/features/0068-verify-data-properties.md)): отслеживаются **только**
  переменные из φ. Ход данных **полностью недетерминирован** — максимальная
  сверх-аппроксимация: `Holds` надёжен, `Violated` над меняющимися данными почти
  всегда возможно ложный. ⚠️ Наивный explicit-state **неосуществим**: у `elevator`
  одна вершина имеет 3.7·10⁵⁰ преемников (входной порт волен принять любое значение
  каждый такт). Сторож направления — `abstracted_source_yields_extra_run_not_missed`.

- **Живой контекст проверяется машиной**
  ([0149](docs/features/0149-claude-md-consistency-gate.md)):
  `scripts/check-claude-md.py` сверяет статусы упомянутых фич с реестром, пути — с
  деревом, версии крейтов — с манифестами и **запрещает** ссылки вида
  `файл.rs:NNN` (строка остаётся, символ уезжает). ⚠️ Гейт проверяет форму, не
  смысл: истинность утверждений о поведении — на человеке (правило 4).
- **Библиотека отдаёт применению ТИП и ПРОТОКОЛ, объявленные ею же**
  ([0182](docs/features/0182-pid-library-and-application.md), фикс
  [0182-01](docs/fixes/0182-01-pid-law-as-type-and-functions.md)). Образец —
  `examples/pid_law.takt` (`struct PidState` + `pid_init`/`pid_compute`/
  `pid_reset` + `target`/`meas`/`ctrl` наружу) и `examples/pid_heater.takt`
  (объект + замыкание контура). ⚠️ Регулятор — **тип данных, а не автомат**: у
  автомата он один на программу (состояние в переменных модели), у типа
  контуров столько, сколько объявлено переменных.
  ⚠️ Объект **отдельной библиотекой не выражается**: подключение двух файлов
  строит два независимых дерева, общей переменной между ними не возникает.
  ⚠️ **Функции импортируются** ([0182-04](docs/fixes/0182-04-import-functions.md)):
  прежде категории `functions` в переносе не было вовсе. Владелец функции
  **перепривязывается к импортёру** — цель `c` строит её имя из владельца
  (`<Модель>_<функция>`) и вызов ищет там же. ⚠️ Строитель дерева вливает
  функции `extend`-ом: присваивание целиком затирало вклад импорта, и вызов
  отвечал `SE-004`. ⚠️ `import "файл";` целиком переносит к импортёру и типы с
  устройством, и функции — иначе они остаются у корня библиотеки, ставшего
  промежуточной моделью, а обращение к её объявлениям цели не выражают.
  ⚠️ **Файл без единого состояния — библиотека, а не ошибка**
  ([0182-02](docs/fixes/0182-02-library-file-without-start.md)): как вход
  исполнения отвергается `SE-102` (**одно** правило `validate_entry_model` на
  цели и симулятор), через `import` работает. Признак — отсутствие состояний
  **вовсе**; состояния без стартового остаются `SE-011`. Языковой сервер
  проверку **не зовёт**: библиотеку открывают и правят.
  ⚠️ **Импорт переносит УСТРОЙСТВО типа, а не имя**
  ([0182-03](docs/fixes/0182-03-imported-type-definition.md)): имя лежит в
  `types`, поля — в `structs`/`enums`, и перенос одного лишь имени давал цели
  `c` тип без `typedef` (файл не компилировался), а симулятору — `SIM-012`, при
  рапорте об успехе. Дожило потому, что **ни один пример корпуса структуру не
  импортировал**.
  ⚠️ **Имя типа делит пространство со стандартной библиотекой IEC**: `TYPE Pid`
  MatIEC отвергает — там есть `FUNCTION_BLOCK PID`, а идентификаторы IEC
  регистронезависимы. Прежде ловушка была известна для имён **моделей**
  (`Concat`); структура `PidState` названа так по этой причине.
  ⚠️ Подбор имён примера вскрыл три дефекта именования в кодогене (порт =
  состояние; состояние = корневая модель из составного имени файла; корневая
  модель = под-модель) — все записаны кандидатами в `FEATURES.md`, обойдены
  выбором имён, причины **не устранены**.

> ⚠️ Список исключений `KNOWN_GAPS` — **с ратчетом**: запись, которой на корпусе

> вхождение — испорченный переименованием исходник, а не «неполный ответ».
> Добавил узел — разбери его в обходе (третий пункт списка сопровождения после
> форматтера и `eval/` симулятора).

> **Слой стиля — канон именования (фича [0226](docs/features/0226-naming-convention-warning.md)).**
> Новая форма **объявления** обязана попасть в обход `takt-lang/src/style/naming.rs`,
> иначе её имя каноном не проверяется — а сказать об этом машине нечем: обход
> кончается `_ => {}` **осознанно** (канон описывает объявления, а не всякий узел
> АСД), поэтому `deny(clippy::wildcard_enum_match_arm)` здесь неприменим. Сторож —
> `takt-lang/tests/style_naming_fmt_tests.rs::every_declaration_kind_of_the_canon_is_reported`:
> он перечисляет **все** виды объявлений и падает, когда обход теряет ветвь, но о
> **новом** виде, которого в его таблице нет, промолчит. ⚠️ Проверка живёт вне
> семантики намеренно: `taktc fmt` семантику не запускает (ADR 0024), и это его
> свойство. ⚠️ Предупреждение `CS-001` на код возврата `fmt --check` **не влияет**
> (решение заказчика), поэтому корпус от него сторожит тест
> `corpus_has_no_style_warnings`, а не гейт предкоммита.
> ⚠️ **Обход спускается в ТЕЛО СОСТОЯНИЯ** (фикс
> [0197-01](docs/fixes/0197-01-kr-else-cond-case-enum-lines.md)): `invariant`
> объявляется в двух местах — элементом модели и элементом состояния, — и без
> спуска канон действовал бы через раз. `collect_state_element` разбирает
> `StateElement` **исчерпывающе, без `_`**: новый вид элемента обязан заставить
> принять решение. ⚠️ Прочие элементы тела (`next`, `ref`, `every`, именованные
> блоки) имён не объявляют, а **ссылаются** на чужие — переименовывать их канон
> не вправе; контр-пример на это стоит рядом с положительным сторожем.
> ⚠️ **`CS-001` отдаётся во ВСЕХ ветвях возврата `lsp/diagnostics.rs::collect_diagnostics_at`,
> где АСД разобран** (фича [0227](docs/features/0227-lsp-style-warning-with-errors.md)):
> рядом с ошибкой построения дерева, рядом с ошибкой `validate` и на успешном
> пути. Это **исключение** из политики «предупреждения о смысле при ошибках не
> показываем» — канон именования смотрит на текст и от ошибок не портится;
> прочие предупреждения (`SE-036`, `SE-037`) остаются только на успешном пути.
> Прежде предупреждение исчезало от любой ошибки, а `fmt` его печатал — один
> вход, два ответа. ⚠️ Сторожа на **новую** ветвь возврата нет и быть не может
> (ветвь — не тип): заводя её, отдай стиль и там, иначе он потеряется молча.

> **Редакторский слой — правило 29 свода (фича 0178).** Изменение лексики,
> синтаксиса или семантики **обязано** проверить LSP (`takt-lang/src/lsp/`) и
> плагины (`extensions/`); ответ «не нужно» фиксируется тоже. Часть держит
> машина: **новый токен валит сборку** `lsp/semantic_tokens.rs` — разбор
> исчерпывающ, `deny(clippy::wildcard_enum_match_arm)` не даёт вернуть `_`
> (мутация показала, что отказ даёт **сам rustc**: `E0004`, то есть инвариант
> держится и без clippy). Список автодополнения `lsp/keywords.rs::BUT_KEYWORDS`
> — **данные**, исчерпываемостью не защищаются: их сторожит тест вложения
> `KEYWORDS ⊆ BUT_KEYWORDS ∪ COMPLETION_EXCLUDED` (перечисление лексера —
> `parser::lexer::all_keywords()`). ⚠️ Проверять **равенство** нельзя: в списке
> законно живут `enter`/`exit`/`always` — имена блоков, а не ключевые слова.
> ⚠️ Плагин **IntelliJ** машиной **не защищён**: его сторож
> `TaktKeywordSyncTest` живёт в Gradle-сборке, которая вне `precheck.sh`/CI
> (нужен JDK 21, фича 0159), — там работает только дисциплина правила 29. Плагин
> **Zed** своих списков не ведёт (`language_servers = ["takt-lsp"]`) и правок не
> требует, но и наследует все дефекты сервера.

> **Лексема без правила — дефект, и его ловит машина** (фича
> [0201](docs/features/0201-dead-lexemes.md)). Слово в `KEYWORDS`, которого нет
> в extern-блоке грамматики, даёт `SY-002` при употреблении, **обещая**
> конструкцию из шести списков, что по `KEYWORDS` выравниваются. Так жили
> `string` и `template`, а `pragma` — на уровень глубже (вариант `Token` без
> слова в таблице: недостижим и он, и его механизм). Сторож —
> `takt-lang/tests/dead_lexeme_tests.rs`, сверка идёт **в обе стороны**: слово
> без терминала (класс A) и терминал без правила (класс B).
> ⚠️ **Имя типа ключевым словом быть не обязано** — `bit`, `bool`, `u8`, `q` им
> не являются, типы в грамматике суть `Type: Alias(Identifier)`. Поэтому
> `var bit: u8 := 1;` законен, а строковый тип, если понадобится, вводится
> одной строкой в `builtin_type_by_name` (как `duration` в 0134): держать слово
> ключевым ради будущего типа **не нужно**.
> ⚠️ **Неиспользуемый терминал — не «надгробие» изъятой конструкции.** Замер
> 0201 на двух редакциях грамматики: текст диагностики от объявления **не

> ошибку. Изымая оператор, оставляй **лексему** (иначе `==` распадётся на `=` и
> `=` — сообщение о следствии), но **не** терминал.

## Форматтер

Ядро печати — `takt-lang/src/format/` (`format_source`), потребители: `taktc fmt`
(`--check`/`--stdin`) и LSP `textDocument/formatting`. `precheck.sh` проверяет
канон `examples/` (фикстуры `tests/data/` намеренно не нормализованы — тесты
завязаны на их позиции). Правило «добавил узел АСД — добавь его печать» и устройство
сторожа корпуса — во врезке раздела «Добавление конструкции языка».

⚠️ **Канон описан словами** — раздел «Стиль кода» документа (фича
[0197](docs/features/0197-language-code-style.md)). Машинной сверки «текст ↔
форматтер» нет и построить её в общем виде нельзя, поэтому фича, меняющая
поведение `taktc fmt`, **обязана** проверить этот раздел: разошедшись, он станет
обещанием, которого инструмент не исполняет. Примеры раздела прогоняет гейт
документа (0133), но правила словами — на человеке. Цена измерена фиксом
[0197-01](docs/fixes/0197-01-kr-else-cond-case-enum-lines.md): смена трёх правил
затронула **пять** записей канона — печать `format/`, слой `style/naming.rs`,
свод в `book/src/21-code-style/`, описание `CS-001` в приложении об ошибках и
таблицу отступлений в карточке 0197.

**Раскладка — K&R** (фикс 0197-01): `} else {`, цепочка **плоская**
(`} else if c {`). Склейку строк делает `Out::join` — снимает уже поставленный
`'\n'` и взводит `glued`, из-за которого следующая `line` идёт без отступа.
⚠️ Флаг нужен потому, что заголовок звена печатает **рекурсивный** `stmt::print`,
не знающий, что его позвали из ветки `else`; `blank` при взведённом флаге
подавлена, иначе восстановление пустой строки разорвало бы `} else `.

**Перечисление и структура печатаются по элементу на строке** (`print_enum` —
фикс 0197-01, `print_struct` — фикс
[0198-01](docs/fixes/0198-01-struct-comment-placement.md); устройство у них
одно). ⚠️ **Висячей запятой быть не должно**: грамматика — `CommaOne<EnumVariant>`
и `Comma<StructField>`, и напечатанная запятая делает файл неразбираемым (класс
0199-01 — `fmt` пишет на месте). ⚠️ Заголовок печатается `line`, закрывающая
скобка — `node_line(&loc, "}")`, а варианты/поля — `node_line_within(…, brace)`
с границей по байту самой `}`: `loc` записи покрывает её **целиком**, поэтому в
однострочной форме хвостовой комментарий стоит на той же строке, что и каждый
вариант, и без границы его забрал бы первый — а печать перестала бы быть
идемпотентной.

⚠️ **`out.line` в печати элемента модели — сам по себе дефект привязки.**
Комментарии выдают только `node_line`/`node_line_within`/`comments_before`;
ведущие комментарии самой записи спасает общий вход `print_element`, поэтому
обход виден не сразу — страдает то, что живёт **внутри** записи и на строке `}`.
Так дефект и пережил фичу 0198 (она шла по печати **операторов**) и фикс 0197-01
(он переписал соседнюю ветку `Enum`).

**Синонимы не канонизируются:** `while`/`loop` и `: [Guard] x;`/`: x;` — АСД
хранит выбор автора (`ast::LoopKeyword`, `Guard::explicit`); семантика эти
признаки игнорирует.
