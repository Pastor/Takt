# Исправление: литерал длительности в теле блока давал `SIM-007`

> Фича: [../features/0134-language-time-model.md](../features/0134-language-time-model.md) · вскрыт при проработке фичи [тип `duration` в целях генерации и вычисляемая выдержка](../features/0183-duration-type-in-targets.md) (тип `duration` в целях), 2026-07-29

## Симптом

Раздел документа о времени обещает арифметику длительностей и даёт пример
`left := pause + 750ms;`. В теле блока это **не работало**:

```takt
model M {
    var left: duration := 2s;
    start Wait { always { left := left - 1s; } }
}
```

```text
ОШИБКА вычисления на шаге 1: тип duration не поддерживается симулятором (SIM-007)
Симуляция остановлена: результат недостоверен.
```

Падало **любое** выражение с литералом длительности в теле: `left - 1s`,
`3s - 1s`, `left + 1s`, `(left > 1s) ? 1 : 0`. При этом работали:

- `left := DWELL;` (константа без литерала в теле);
- `ms := left as u32;` (приведение);
- `var left: duration := 1m30s;` (литерал **в инициализаторе объявления**).

## Причина

Узел `ExpressionNode::Duration` разбирают **три** места, и одно разошлось с двумя:

| Место | Что делало |
|---|---|
| `takt-sim/src/predicate.rs` (адаптер условий) | `Ok(Value::Duration(нс))` |
| `takt-sim/src/unit/initial.rs` (начальные значения) | `Some(Value::Duration(нс))` |
| **`takt-sim/src/expression.rs` (адаптер выражений)** | **`Err(UnsupportedType)`** |

Заглушка в третьем месте была поставлена **до** подзадачи с честным
комментарием «значение времени вводит 0134-03», но саму 0134-03 пережила: та
завела ядро `eval/duration.rs` и подключила его к условиям и начальным значениям,
а тело блока осталось с отказом.

**Почему не поймали тесты.** Тест
`duration_tests::duration_addition_and_subtraction_stay_duration` арифметику
проверяет — но складывает **две переменные** (`sum := a + b;`). Падал именно
**литерал**, и ни один тест не ставил его в тело. Проверка исчерпаемости
здесь тоже бессилен: узел **разобран**, ветвь есть — она просто отвечает отказом.
Контролем такого класса может быть только проверка **поведения**.

Проверка примеров `book/`  тоже не помог: пример раздела времени
(`fan.takt`) арифметики длительностей не содержит — обещание документа живёт в
прозе и фрагментах, а не в проверяемом примере.

## Исправление

`takt-sim/src/expression.rs`: ветвь `ExpressionNode::Duration(ns)` возвращает
`Ok(Value::Duration(*ns))` — то же, что делают два соседних места. Наносекунды —
каноническое представление языка; профиль времени («часы»/«такты») есть свойство
генерации, а не модели.

Смешение с числом при этом **не открылось**: `bad := pause + 1;` по-прежнему
отвергается семантикой (`SE-065`) до симулятора.

## Проверка

- `takt-sim/tests/sim/duration_tests.rs::duration_literal_inside_body_is_a_value` —
  литерал в **каждой** позиции: справа от операции, слева, в сравнении и как
  самостоятельное значение;
- `takt-sim/tests/sim/duration_tests.rs::duration_literal_mixed_with_number_still_refused`
  — контроль направления: `SE-065` на месте;
- пробы, с которых начался разбор: три выражения выше дают значения
  (`left=0ms`, `left=2s`, `ready=1`), а не `SIM-007`.

## Tier

**Tier 2.** Молчаливого расхождения не было — симулятор отказывал громко, — но
**обещанная документом** конструкция языка не работала, а причина классическая:
один узел разбирают три места, и одно отстало. Тот же класс, что исправление
(два списка встроенных типов) и фича (второй вычислитель вне правила
исчерпаемости).
