## Краткое описание

Раздел документа `book/` про **инструментарий** языка: назначение и работа
`taktc` (генерация, форматирование, верификация, карта адресов), `takt-sim`
(симуляция и визуализация) и `takt-lsp` (сервер языка); команды, примеры вызова и
**реального** вывода. Раздел — **прикладной**: по решению заказчика
свод дополнено исключением, разрешающим показывать команды и вывод
инструментов в выделенных прикладных разделах; языковые разделы остаются tool-free.

Документ `book/` по своду описывает **только язык** и исключает детали
инструментов (компилятор, симулятор, генераторы), команды и вывод — они живут в
`README.md`. Заказчик запросил (2026-07-24) добавить в **сам документ** раздел про
инструментарий: описание работы, команды, примеры вызова и вывода. Это прямо
противоречит своду, поэтому нужно решение о размещении и о судьбе правила.

### Decision Drivers

1. **Запрос заказчика.** Раздел про инструменты должен быть в документе (PDF),
   рядом с описанием языка, а не только в README.
2. **Целостность своду.** Языковые разделы должны остаться свободными от
   деталей инструментов — иначе документ теряет фокус «описание языка».
3. **Единый источник.** Дублирование команд в README и book рискует рассинхроном.

### Considered Options

#### Option A. Раздел «Инструментарий» в book/ + точечное исключение из свод **Pros:**
- Даёт заказчику запрошенное — раздел в PDF.
- Исключение **выделенное**: послабление только для прикладных разделов
  («Инструментарий», «Развёрнутый пример»), языковые разделы свод защищает
  по-прежнему.

**Cons:**
- свод усложняется оговоркой.

#### Option B. Только в README.md (свод не трогать)

**Pros:**
- свод остаётся чистым.

**Cons:**
- Не выполняет запрос: раздела в документе/PDF нет.

#### Option C. Дублировать в book/ и README

**Pros:**
- Максимальное покрытие.

**Cons:**
- Два источника истины по командам — рассинхрон (драйвер 3).

### Decision

Принимается **Option A**. В `book/` заводится раздел «Инструментарий»; свод дополняется **точечным исключением** для прикладных разделов. Языковые разделы
остаются tool-free. **Номера фич/задач, ссылки на артефакты процесса и сведения о
процессе** не попадают в документ нигде (это ограничение свод сохраняется
полностью, в т. ч. в прикладных разделах).

## Анализ

### Цель и контекст

Раздел документа `book/` про инструментарий языка. Язык **не меняется** (Tier 3).
Ключевое решение — исключение из своду: прикладной раздел
вправе показывать команды и вывод инструментов.

### Инвентаризация поверхности CLI (источник истины — сами инструменты)

Собрана прогонами на рабочей машине (не из памяти):

- **`taktc --help`** — подкоманды `compile`/`fmt`/`verify`/`address-map`; флаги
  `-t/--target`, `-o`, `-I`, `-v`, `-q`, `--guard-enable/-disable`,
  `--address-map`, `-D`, `--float-width`, `--float-as-q`, `--float-embedded`.
  Цели: `c`, `c-hal`, `st`, `st-at`, `rust`, `sv`, `sv-mmio`, `plantuml`.
- **`takt-sim --help`** — аргумент `<файл.takt>`; опции `-I`, `-n/--steps`,
  `-o/--output` (GIF/SVG), `-s/--sim-file`, `--load-state`, `--save-state`,
  `--graphics-config`, `--invariant-soft`.
- **`takt-lsp`** — сервер LSP; пути импорта из `initializationOptions.searchPaths`.

### Захваченный реальный вывод (для примеров раздела)

- `compile` (успех): `Скомпилировано: <in> → <out>/ (путей поиска: 0)`.
- `fmt --check` (расхождение): `требуется форматирование: <файл>` +
  `Не отформатировано файлов: 1 из 1`.
- `verify` (держится): `СВОЙСТВО ДЕРЖИТСЯ: F Start` + `Проверено свойств: 1;
  все держатся`.
- `verify` (нарушено): `СВОЙСТВО НАРУШЕНО: …` + `контрпример: [ … ]*`.

### Ограничения

В раздел **не** попадают номера фич/задач и сведения о процессе — из справки
`taktc` номера фич («(фича NNNN)») вычищены при переносе в текст.
