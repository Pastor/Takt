# Исправление 0539-04: правка схемы пропадает после сохранения

> Фича: [графическое представление модели — раскладка состояний и рёбер в отдельном файле](../features/0539-model-layout-ui.md)

## Проблема

Автор расставляет узлы, ведёт изломы рёбер, сохраняет проект — и после
перезагрузки схема снова разложена по ярусам: изгибов нет, правка визуальной
части пропала целиком. Замечено заказчиком 2026-09-10.

## Причина

Раскладка пишется своим файлом `.takt-ui` рядом с моделью, и запись шла без
ревизии. Сервер принимает запись без ревизии только для нового файла, а правку
существующего отвергает конфликтом: «файл уже есть: правка требует ревизии».
Первое сохранение заводило файл и проходило, а каждое следующее падало; отказ
показывался предупреждением и тонул среди сообщений об успешной записи модели.
Ревизия у протокола — проектная, одна на все файлы: модель и сценарий её
передавали, раскладка — нет.

## Решение

Запись раскладки в существующий файл несёт текущую ревизию проекта — ту, что
вернула запись модели и сценария, — и запоминает ответную. Новый файл по-прежнему
пишется без ревизии.

## Проверки

Замер на сервере: запись в существующий `ports16.takt-ui` без ревизии — `409
revision_conflict`. Тест страницы требует, чтобы запись раскладки несла ревизию
проекта. Прогон страницы: узел перенесён и сохранён дважды подряд — файл несёт
обе правки, после перезагрузки схема та же.
