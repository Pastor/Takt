# Исправление: `clippy` отвергал обёртку «выхода ещё не было»

> Фича: [../features/0446-inline-early-return.md](../features/0446-inline-early-return.md) · ADR: [../features/0446-inline-early-return.md#архитектура-adr](../features/0446-inline-early-return.md#архитектура-adr)

## Что было

Подстановка тела с ранним возвратом ставит операторы после возможного выхода
под условие «выхода ещё не было». Первая редакция вкладывала оператор в
обёртку как есть:

```rust
if !takt_inline_1_done {
    if doubled > 6 {
        takt_inline_1_ret = 50;
    }
}
```

Замер-31 (`probe.sh` по фикстуре сверки): `rustc` такой модуль
принимает, а `clippy` под `-D warnings` — **нет**:

```text
error: this `if` statement can be collapsed
```

То есть цель `rust` клала на диск файл, который её собственный проверка отвергает.

## Почему это не поймали

Прогон инструментов у фичи шёл по пробе **без** раннего возврата: обёртки
там не возникает вовсе. Проверка цели `rust` в предкоммите гоняет только корпус, а
в корпусе подстановки нет — умолчание `--inline=off`. Класс жил
ровно в той части вывода, которую ни один прогон не смотрел.

## Что сделано

1. **Обёртка сливается с условным оператором:** `if !done { if c { … } }`
   печатается как `if !done && c { … }`. Форма проверена прогоном — её
   принимают все восемь целей и оба инструмента SV.
2. Блок из одного оператора перед слиянием разворачивается: тело цикла
   приходит блоком, и без этого слияние не срабатывало бы.
3. **Прогон инструментов получил вторую пробу** — с ранним возвратом и
   возвратом из цикла (`function_inline_tests::EARLY_PROBE`): `clippy` и
   `verilator` гоняются теперь по ней.

## Урок

Проба, на которой гоняются инструменты целей, обязана содержать **ту самую**
форму, ради которой заведена фича. Проба «вообще про подстановку» не покрывает
подстановку с ветвлением — как корпус не покрывает то, что по умолчанию
выключено.
