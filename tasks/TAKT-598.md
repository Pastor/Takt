# Исправление: сервер не умеет назвать свою версию

- **Фича:** [lSP-сервер lam-lsp](../features/0011-lsp-server.md) — LSP-сервер
- **Статус:** ГОТОВО
- **Дата:** 2026-08-23
- **Повод:** отчёт заказчика — «в LSP ошибка: `source` не найден»

## Что наблюдалось

Заказчик сообщил об отказе редактора на записи, которую компилятор принимает:

```takt
fn total_of(source: [u8; 4]) -> u8 {
    var sum: u8 := 0;
    for var i: u8 := 0; i < 4; i := i + 1 {
        sum := sum + source[i];
    }
    return sum;
}
```

## Замер

`taktc compile -t c` — **код 0**, вывод собирается. `collect_diagnostics`
текущего дерева — **ноль** диагностик. То есть в коде дефекта нет.

Прогон **установленного** сервера по протоколу (зонд на `initialize` +
`didOpen`, чтение `publishDiagnostics`):

| Сервер | Ответ |
|---|---|
| `~/.local/bin/takt-lsp` (сборка **2026-08-17**) | `SE-003 \| Переменная 'source' не найдена` |
| свежий из дерева | диагностик нет |

Класс закрыт исправлением [индексация параметра-массива внутри функции](../features/0346-array-param-index.md) — «параметр
функции виден и при индексации», лёгшим **2026-08-21**, то есть на четыре дня
**позже** сборки установленного сервера.

## Настоящий предмет

Расхождение — не дефект языка, а **невозможность его опознать**: узнать версию
установленного сервера было **нечем**. Аргументы командной строки `takt-lsp` не
разбирал вовсе, поэтому

```
$ takt-lsp --version
Error: ProtocolError("disconnected channel", true)
```

— флаг уходил в протокол, и процесс падал. Пользователь не мог отличить
«дефект компилятора» от «сервер устарел», и класс возвращался разработчику как
ложный отчёт о дефекте языка. Версия при этом **есть** в `serverInfo`
рукопожатия, но она видна только в логе редактора, а не пользователю.

## Что сделано

- `takt_lang::version` — печать обобщена: `version_text_for(tool)` и
  `run_version_subcommand_for(tool)`. Своей строки у сервера нет: форма
  вывода — одно знание на проект.
- `handle_server_args` и `server_help_text` — там же, **в библиотеке**, а не в
  бинарнике: образец `address-map`  — так проверяется вывод, а не
  факт вызова.
- `takt-lsp` разбирает аргументы **до** открытия stdio: `--version`/`-V`/
  `version`, `--help`/`-h`/`help`.
- README: команда в разделе «LSP-сервер» (её прогоняет проверка) и объяснение,
  зачем сверять версии. Попутно исправлена ложная ссылка на каталог расширения
  Zed — `extensions/zed-lam` не существует с переименования 0100.

**Неизвестный аргумент по-прежнему игнорируется, а не отвергается.** Сервер
запускает редактор, состав аргументов задаёт его конфигурация, и отказ сломал
бы чужую настройку ради флага, которого она не просила. Граница названа в
заголовке функции, и на неё стоит контрольный тест.

## Проверки

| № | Условие | Результат |
|---|---|---|
| F1 | `takt-lsp --version` | `takt-lsp 0.55.0` + `язык Takt 0.13.0`, код 0 |
| F2 | `takt-lsp --help` | справка, код 0 |
| F3 | Формы `-V`, `version`, `-h`, `help` | останавливают запуск сервера |
| F4 | **Контроль:** без аргументов и с неизвестным аргументом | сервер запускается |
| F5 | Мутация `_ => Some(2)` | `other_arguments_start_the_server` падает |
| F6 | Проверка команд README | прогнан, зелёный |
| F7 | `./scripts/precheck.sh` | код 0 |

Контроля — `takt-lang/src/version.rs` (модуль тестов): вывод, а не факт вызова.

## Что осталось заказчику

Установленный сервер надо переустановить — иначе редактор продолжит показывать
диагностики четырёхдневной давности:

```sh
scripts/install.sh
```

После этого `takt-lsp --version` обязан назвать ту же версию, что и
`taktc --version`.
