## Краткое описание

Четвёртый целевой язык генерации наряду с C, PlantUML и (прорабатываемым
параллельно) Structured Text: `generator::Language` сегодня имеет ровно два
варианта — `C` и `PlantUML`
([`generator/mod.rs:14`](../../takt-lang/src/generator/mod.rs)). Фича добавляет
вариант `SV` и модуль `grammar/src/generator/sv/`, транслирующий семантическое
дерево модели в **синтезируемый SystemVerilog (IEEE 1800)** — язык описания
аппаратуры для FPGA/ASIC.

Автоматная модель Lam ложится на синтезируемый RTL-автомат естественнее, чем на
любую другую цель (FSM — каноническая форма RTL), но это **принципиально иная
модель исполнения**: у C и ST такт — итерация цикла сканирования, у RTL — **фронт
тактового сигнала**. Ключевые решения ([ADR](0045-sv-backend.md#архитектура-adr)):

- **Время:** такт Lam ≡ `posedge clk`; `clk`/`rst_n` — неявные служебные порты
  модуля (в языке Lam их нет), имена зарезервированы. Язык **не меняется**.
- **Сброс:** синхронный, активный низкий `rst_n`; ветвь сброса устанавливает
  стартовое состояние и исполняет его `enter`. Синтетического `INIT`-состояния
  **нет** → **сдвиг = 0 на любой глубине**: контракт
  [ADR](0033-init-tick-alignment.md#архитектура-adr) выполняется **конструктивно** (в
  C его требуется *убирать* правкой, здесь его просто нет).
- **Автомат:** two-process — `always_comb` (тело состояния, блокирующие
  присваивания → порядок операторов как в C) + `always_ff` (латч + сброс).
- **Композиция:** один модуль на корневую модель; регистры состояний под-моделей
  независимы, логика инлайнится в общий `always_comb` в порядке вызова `_tick`
  C-генератором (иначе `stacker.lam` даёт **комбинационную петлю** — проверено).
- **Типы:** `bit` → `logic` (**идеальное** соответствие; в C — `int`); `Rational` → **ошибка `SV-003`**: в синтезируемом RTL плавающей точки не
  существует.
- **Порты:** `in`/`out` → `input`/`output logic` — **самое естественное
  соответствие из всех целей**. Карта адресов [адрес порта — размещение и потребление (карта адресов)](0020-port-address-decl.md)
  **не потребляется**: адрес MMIO для RTL бессмыслен.

Изменение **аддитивно**: `Language` помечен `#[non_exhaustive]`
([`generator/mod.rs:13`](../../takt-lang/src/generator/mod.rs)), существующие цели
`c`/`c-hal`/`plantuml` байт-в-байт не меняются, `.lam` не тронут.

> Фича зарегистрирована **по прямому запросу заказчика**; далее проходит
> жизненный цикл по своду.

установлены (`brew install verilator yosys`) и опробованы:

| Проба | Verilator 5.050 `--lint-only -Wall` | yosys 0.67 `synth` |
|---|---|---|
| Целевой модуль `LiftController` (написан от руки по решению ADR) | **чисто, код 0** | **синтезирован, 22 ячейки** |
| Контрпример `real` в `always_ff` | **принял молча, код 0** | **`ERROR: TOK_REAL`, код 1** |
| Контрпример: комбинационная петля | **`UNOPTFLAT`, код 1** | **синтезировал молча, код 0** |
| Тестбенч (`verilator --binary --timing`) | **собран и прогнан**; трасса подтверждает сдвиг = 0 | — |

**Главная находка:** инструменты ловят **непересекающиеся** классы дефектов —
Verilator пропускает `real` (то есть расхожее «`--lint-only` = проверка синтеза»
**неверно**), yosys молча синтезирует комбинационную петлю (центральный риск
отображения `M1 | M2`). Поэтому проверок **два**, и они обязательны оба. Подробно —
[анализ 0045-02](0045-sv-backend.md#анализ).

## Ключевые ограничения (документируются)

- **`extern fn` не транслируется** (`SV-005`) → `elevator.lam` (8 шт.),
  `comprehensive.lam` (2), `extend_complex.lam` (1) для цели `sv` **недоступны**.
  Флагманский пример цели — **`stacker.lam`** (0 `extern fn`, 0 `float`, 13
  `bit`-портов, три параллельные модели — витрина преимущества RTL).
- **`float` запрещён** (`SV-003`): в синтезируемом RTL плавающей точки нет.
  Fixed-point Q(m.n) — кандидат (требует расширения **языка**, а не генератора).
- **`inout` запрещён** (`SV-006`): требует сигнала `oe`, которого Lam не выражает.
- **Уплощение иерархии:** один SV-модуль на корневую модель — плата за точную
  семантику `|`.
- Один тактовый домен; CDC, множественные домены, SDC/XDC, потолок частоты — вне
  объёма.

Цена всех запретов на сегодня — **нулевая** (корпус их не использует, проверено
`grep`), но границы обязаны быть в документации.

#### Какую проблему решаем

свод объявляет целью проекта «язык задания и **синтеза** автоматных моделей
промышленных систем управления». Слово «синтез» в отрасли имеет два смысла, и
проект сегодня закрывает только первый:

1. **Синтез программы** — `c`/`c-hal` (прошивка МК), `st` (ПЛК).
2. **Синтез аппаратуры** — RTL → FPGA/ASIC. **Не покрыт ничем.**

Второй контур — не экзотика для профиля: жёсткое реальное время (реакция за
единицы наносекунд), аппаратные блокировки безопасности (safety interlock),
которые обязаны работать независимо от процессора и его зависаний, и
высокоскоростные контуры управления (приводы, силовая электроника). Ровно там,
где ПЛК со своим скан-циклом в миллисекунды не успевает, ставят FPGA.

**Автоматная модель Lam ложится на синтезируемый RTL-автомат естественнее, чем на
любую из существующих целей**: FSM — это и есть каноническая форма RTL. Но модель
исполнения **принципиально иная**, и в этом вся соль проработки: у C/ST такт —
итерация цикла сканирования (программа сама решает, когда сделать шаг), у RTL
такт — **фронт тактового сигнала**, физическое событие, которого в языке Lam нет
вообще. Ни `clk`, ни `rst` в `.lam` не выразимы.

> **Источник фичи.** Заведена **по прямому запросу заказчика**, а не из блока
> кандидатов `FEATURES.md` (в отличие от 0041, вынесенной заделом фичи).

### Decision Drivers

1. **Профиль проекта.** Аппаратный контур промышленного управления
   не покрыт ни одной целью. SV — вход в него.
2. **Модель исполнения RTL ≠ модель исполнения C/ST.** Такт задаёт железо, а не
   программа. Решение обязано честно ответить, откуда берутся `clk`/`rst`, и не
   делать вид, что RTL — это «C с другим синтаксисом».
3. **Синтезируемость — бинарный критерий.** Код, который не проходит синтез, —
   не RTL, а текст. Всё, что не синтезируется (`real`, рекурсия, комбинационные
   петли), обязано отвергаться **диагностикой**, а не эмитироваться в надежде.
4. **Не повторить дефекты отображения типов C**. `get_c_type`
   (`generator/c/mod.rs:150`): `Array(size, elem)` → `uint{size}_t` (число
   элементов путается с разрядностью), `Bit` → `int`, `Rational` → `float`, а
   переменная-массив **молча исчезает** из структуры **без диагностики**.
   SV-генератор пишется с нуля и обязан **никогда не терять узел молча** (класс
   «тихий пропуск»: фичи; та же логика, что у форматтера 0024).
5. **Контракт моментности уже принят — его надо соблюсти, а не изобрести.**
   ADR постановил: вход в стартовое состояние **не стоит такта**, эталон
   моментности — модель, сдвиг обязан быть нулевым на **любой** глубине. Для RTL
   это не абстракция, а прямая аппаратная конструкция — состояние сброса.
6. **Проверяемость.** Проект дважды обжигался на непроверяемом выводе (тихие
   пропуски 0025/0028/0029; невозможность CI-проверки плагина 0022/0023). Новый
   генератор без автоматизируемого проверки повторил бы ошибку в третий раз.
7. **Аддитивность.** `Language` уже `#[non_exhaustive]`; добавление
   варианта не должно менять ни байта вывода `c`/`c-hal`/`plantuml` и не должно
   трогать `.lam`. Версия языка не растёт.

### Вопрос 1. Модель времени: откуда берутся `clk` и `rst`

Ядро решения. В языке Lam тактового сигнала нет: `tick` — это шаг модели, а не
фронт. В RTL без `clk` не существует ни одного регистра.

#### Option A. Такт Lam ≡ `posedge clk`; `clk`/`rst_n` синтезируются неявно

Генератор добавляет к модулю служебные порты `clk`/`rst_n`, которых нет в `.lam`.
Автомат живёт в `always_ff @(posedge clk)`. Имена — зарезервированы; коллизия с
портом модели → диагностика.

**Pros:**
- **`.lam` не меняется** → фича аддитивна, версия языка не растёт (драйвер 7). Одна и та же модель компилируется в C, ST и SV без правок — это и
  есть заявленная ценность языка-источника («одна модель — много платформ»).
- **Такт Lam уже абстрактен.** Модель не утверждает, *чем* порождён шаг: в C это
  вызов `_tick`, в ST — скан ПЛК, в RTL — фронт `clk`. Отображение шага на фронт
  — самое прямое из трёх: в C/ST шаг ещё надо кому-то инициировать, в RTL он
  происходит сам, физически.
- `clk`/`rst_n` — универсальное соглашение синхронного RTL; инженер получает
  модуль ровно той формы, которую ожидает вставить в свой проект.
- Не требует ни одного нового понятия в языке.

**Cons:**
- Имена `clk`/`rst_n` становятся **зарезервированными** для цели `sv`: модель с
  портом `clk` не транслируется. Смягчение: диагностика `SV-007`, а не тихое
  переименование. Сегодня цена нулевая — ни один `.lam` корпуса не объявляет
  порт `clk`/`rst_n` (проверено `grep` по `examples/`).
- Тактовая частота, домены тактирования, CDC (пересечение тактовых доменов) —
  вне модели. Для одного домена (текущий объём) это не ограничение, для
  многодоменного дизайна — да. Фиксируется как граница фичи.

#### Option B. Объявление `clk`/`rst` в модели (новый синтаксис)

Ввести в язык конструкцию тактового домена: `clock clk; reset rst_n;` либо
атрибут модели.

**Pros:**
- Такт становится **специфицированным** в языке, а не соглашением генератора.
- Открывает дорогу многодоменным дизайнам и CDC — то, чего Option A не может.
- Явное лучше неявного: автор видит, откуда берётся время.

**Cons:**
- **Меняет язык** → версия языка растёт, фича перестаёт быть
  аддитивной; заказчик языковой конструкции не запрашивал — запрошен генератор.
- **Ломает переносимость модели.** `clock` бессмысленен для целей `c`/`st`: что
  делать со счётчиком тактов на ПЛК? Либо игнорировать (тогда конструкция —
  ложь для трёх целей из четырёх), либо вводить платформенные секции в `.lam` —
  вендор-специфика в языке-источнике, ровно то, чего избегал ADR.
- Требует пройти всю цепочку: грамматика, АСД, 7 проходов, форматтер 0024, LSP,
  плагин IntelliJ — ради того, что Option A даёт соглашением об именах.
- **Повторяет ошибку, от которой отказался ADR** (его Option C: «явная
  модель такта запуска в семантике языка» отвергнута как преждевременная —
  «риск спроектировать конструкцию в пустоту: реальных требований пока не
  собрано»). Здесь ровно та же ситуация: требований к многодоменности нет.

#### Option C. Такт по разрешению: `clk` + `en` (clock enable)

Как Option A, плюс служебный вход `en`: шаг модели происходит на фронте `clk`
**при `en == 1`**.

**Pros:**
- Точнее соответствует скан-циклу C/ST: шаг делается, когда потребитель разрешил
  → сверка с симулятором и с C становится буквальной (тик = такт с `en`).
- Позволяет тактировать автомат медленнее системного `clk` без второго домена —
  штатный приём (например, автомат на 1 кГц в дизайне на 100 МГц).
- Синтезируется тривиально: `if (en) begin … end` внутри `always_ff`.

**Cons:**
- Ещё один служебный порт, которого нет в модели → расширяет зону
  зарезервированных имён.
- **Не нужен по умолчанию:** `en`, тождественно равный `1`, покрывает основной
  случай, а тот, кому нужен делитель, добавит его снаружи — это одна строка в
  модуле верхнего уровня. Вводить порт ради частного случая — усложнение
  интерфейса без запроса.
- Усложняет тестбенч и сверку (нужно ещё дёргать `en`).

#### Decision (вопрос 1)

Принимается **Option A**: такт Lam ≡ `posedge clk`; `clk` и `rst_n` —
**неявные служебные порты модуля**, добавляемые генератором; имена
зарезервированы, коллизия → диагностика **`SV-007`**.

Обоснование:

1. **Единственная опция, сохраняющая аддитивность** (драйвер 7). Option B меняет
   язык ради генератора — прямая инверсия отношений: язык-источник не должен знать
   про целевую платформу (тот же довод, по которому ADR отверг вендорские
   локации в `.lam`, а ADR — синтаксис `AT %`).
2. **Отображение «шаг → фронт» честно, потому что шаг Lam уже абстрактен.** Мы
   не приписываем модели новой семантики: мы выбираем исполнителя шага. В C им
   был вызывающий код, в RTL — генератор тактов.
3. **Option C отклонён как преждевременный, но не как неверный.** `en` —
   аддитивное расширение поверх A (порт с умолчанием `1'b1` не ломает никого):
   если потребность возникнет, заводится отдельной фичей. Выносится в кандидаты.
4. Option B не отвергнут навсегда: если появятся требования к многодоменности и
   CDC, язык придётся расширять — но тогда это будет фича **по требованию**, а не
   догадка. Ровно логика ADR в отношении его Option C.

**Граница фичи (фиксируется явно):** один тактовый домен, один сброс. CDC,
множественные домены, тактовые ограничения (SDC/XDC), gated clocks — **вне
объёма**; выносятся в кандидаты.

### Вопрос 2. Сброс: вид, полярность и связь с фичей

Здесь вопрос «стоит ли вход в стартовое состояние такта» получает прямой
аппаратный смысл: **состояние сброса — это и есть стартовое состояние автомата**.

#### Что постановил ADR (читать как контракт, а не как контекст)

ADR разобрал расхождение симулятора и C: генератор C заводит синтетическое
состояние `{PREFIX}_INIT` **на каждый уровень иерархии**, и `case INIT`
завершается `break` — то есть **вход в стартовое состояние стоит такта**, а сдвиг
относительно симулятора равен **глубине вложенности** (проверено пробами: 1 / 2 /
3 уровня → сдвиг 1 / 2 / 3 такта).

Принят **Option B**: генератор C перестаёт тратить такт на `INIT`; эталон
моментности — **модель**, сдвиг обязан быть **нулевым на любой глубине**.
Решающий довод (драйвер 3 ADR) — **композируемость**: если обёртка
`model Mid { start S = Inner; }` молча съедает такт, потактовые свойства модели
не композируемы и рассуждать о времени в языке нельзя.

Прямая цитата следствий ADR: «Будущие генераторы (0041 ST) получают **контракт**
“вход в стартовое состояние не стоит такта”, а не прецедент чужой бухгалтерии».
**Фича — первый генератор, пишущийся уже под этот контракт**, и обязана его
реализовать **конструктивно**, а не «починить потом».

#### Option A. Синхронный сброс, активный низкий `rst_n`; ветвь сброса несёт `enter` стартового состояния

```systemverilog
always_ff @(posedge clk) begin
    if (!rst_n) begin
        state    <= LIFT_IDLE;   // стартовое состояние — напрямую
        cmd_fork <= 1'b0;        // enter { cmd_fork := 0; } — инлайн в сброс
    end else begin
        state <= state_next;
        // …
    end
end
```

Синтетического состояния `INIT` **нет вообще**.

**Pros:**
- **Контракт 0033 выполняется конструктивно, а не соблюдается усилием.** Регистр
  состояния физически не может «побыть в INIT»: после снятия `rst_n` первый же
  фронт исполняет тело стартового состояния. **Сдвиг = 0 по построению.**
- **Сдвиг = 0 на любой глубине — бесплатно** (
