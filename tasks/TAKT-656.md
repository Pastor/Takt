# Исправление 0531-02: прогон со сценарием обрывается на его последнем шаге

> Фича: [онлайн-редактор Takt: подсветка, LSP, генерация, симуляция, обмен ссылками](../features/0531-web-playground.md)

## Проблема

Автор ставит 196 шагов, выбирает сценарий и запускает прогон — прогон кончается на
втором такте с сообщением, что число шагов достигнуто. Замечено заказчиком
2026-09-10.

## Причина

Сценарий был из двух шагов, а длину прогона страница эталону не передавала: число
шагов служило только бюджетом воркера, то есть пределом, после которого страница
перестаёт просить такты. Эталон, не получив длины, брал её у сценария — правило
CLI без ключа `-n`. У CLI это законно: длину там называет автор, либо её нет. У
страницы длина названа всегда, но оставалась на стороне страницы, и правило
[длину прогона задаёт `-n`, а не длина сценария](../features/0523-sim-scenario-run-length.md)
до браузера не доехало.

## Решение

Число шагов страницы доезжает до эталона полем `steps` запроса открытия прогона —
ключом `-n`: сценарий задаёт входы, после его последнего шага значения
удерживаются, и прогон идёт до названной длины. Длина входит в ключ сессии
воркера: сессия, открытая под другое число шагов, остановилась бы не там, где
просит автор. Шаг по одному такту получает ту же длину.

## Проверки

`takt-wasm`: `scenario_shorter_than_run_keeps_inputs` — сценарий из двух шагов при
длине пять даёт пять строк, и на пятой вход удерживает значение второго шага.
Страница: тест моста «прогон: длину задаёт число шагов страницы, а сценарий -
входы» — 196 строк при сценарии из двух шагов. Без правки оба дают две строки.
