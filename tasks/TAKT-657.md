# Исправление: комментарии новых файлов не прошли проверку

> Фича: [../features/0536-gate-empty-selection.md](../features/0536-gate-empty-selection.md)

## Проблема

Коммит фичи не проходит собственный предкоммит: `scripts/check-comments.py` на нём
находит семь нарушений в трёх файлах, заведённых этой же фичей, —
`scripts/gatelib.mjs`, `scripts/gatelib.sh`, `scripts/test-registry-verdicts.sh`
(классы `C2` и `C10` — номер работы в комментарии).

Обнаружено при разработке соседней фичи: та же проверка на рабочем дереве стала
красной сразу, как только новые файлы попали в индекс.

## Причина

`check-comments.py` берёт список файлов из `git ls-files`, то есть судит
**отслеживаемые** файлы. Предкоммит гонялся до `git add`, и трёх новых файлов в
выборке не было — проверка их не видела и отвечала успехом. После добавления в
индекс те же файлы дали находки.

Класс тот же, что закрывала фича: выборка проверки не совпала с предметом
проверки. Граница входа здесь не помогает — улов не пуст, просто неполон.

## Решение

Комментарии приведены к правилу: номер работы из первой строки помощников и из
пояснения к контрольной пробе убран, смысл сохранён — что делает файл, а не
какой фичей заведён.

## Проверки

- `scripts/check-comments.py` — зелёный на дереве, где новые файлы отслеживаются
  (1689 файлов, нарушений нет).
- `./scripts/precheck.sh` — зелёный целиком.

Правило, из которого следует порядок работы: предкоммит доказывает состояние
дерева **с учётом индекса**. Отдельной записью заведён кандидат: проверки,
берущие список из индекса, обязаны говорить об этом, либо предкоммит обязан
падать на неотслеживаемых файлах, которые он судить не может.
