## [Не выпущено]

### Добавлено

- **Зарегистрирована фича 0025 «Починка вычислителя выражений симулятора»
  (стадия 1, `СОЗДАНА`).** Обзор проекта выявил, что крейт `simulation`
  вычисляет модели неверно и **бесшумно**: `eval_expression_rt`
  (`unit/builder.rs:135`) покрывает ~6 из ~30 вариантов `ExpressionNode`, а
  невычислимое выражение приводит к тихому пропуску присваивания
  (`unit/builder.rs:220`, без ветки `else`). Следствия подтверждены на
  собственных примерах: `examples/comprehensive.lam` навсегда висит в `Idle`
  (`ref Heating: temperature > 10` не срабатывает, т.к. `temperature` не
  инкрементируется), в `examples/stacker.lam` `eta=0` на каждом шаге
  (`eta := travel_time(…)` — вызов функции, значение отбрасывается). В состав
  фичи также вошли: паника `unimplemented!()` на вызове функции в условии
  перехода (`predicate.rs:111`), потеря операторов-вызовов
  (`compile_expression`, только `Assign`) и неисполнение `enter` стартового
  состояния (`unit/mod.rs:185`). Тесты дефект не ловят (прогон зелёный: 1484
  passed) — проверяют факт переходов, но не вычисленные значения. Заведены
  карточка `docs/features/0025-…`, заготовки ADR/анализа, строки в реестрах;
  фича поставлена **первой** в витрине `FEATURES.md` по правилу 19 (критерий 4
  «необходимость», с обоснованием) — впереди 0019 и 0024.
- **Фича 0025: принят ADR (стадия 2, статус `СОЗДАНА` → `АРХИТЕКТУРА`).**
  Разбор `predicate.rs` на архитектурной стадии выявил **ещё три дефекта**, все
  воспроизведены: Д6 — смешанная арифметика `int`+`real` в условии роняет
  симулятор (`unwrap()` на `None`, `predicate.rs:130`); Д7 — `Parenthesis`
  возвращает внутренний узел **невычисленным** (`Ok(*cond.clone())` вместо
  `flat(cond, context)`), из-за чего `(t + 1) > 2` при `t=5` ложно; Д8 —
  `EnumVariant`/`State`/`Model`/`ArraySubscript` → `Err`, из-за чего
  `mode = Manual` при `mode=Manual` ложно, а `S(Ping) = End` в симуляторе не
  работает. Д7/Д8 молчаливы вдвойне: `create_predicate` сводит `Err` и
  невычислимый результат к `false`, поэтому ошибка вычисления **неотличима** от
  честно ложного условия. Итого инвентарь фичи — Д1–Д8.
  **Принят Option B**: общее ядро вычисления над `Value` (единственное место
  семантики) + два тонких адаптера `ConditionNode`/`ExpressionNode` с
  **исчерпывающим `match` без `_`**, возвращающих `Result<Value, Diagnostic>`;
  новый вариант узла ломает сборку вместо тихого `None`. Отвергнуты: Option A
  (точечная починка — оставляет причину: `_ => None`, `Option` вместо `Result`,
  AST в роли значения) и Option C (понижение `ConditionNode → ExpressionNode` —
  лоссиво для `Model`/`State`/`EnumVariant` и наступает на решение, уже
  отвергнутое ADR 0019). Зафиксированы: принцип числовой семантики (совпадение с
  синтезированным C для определённого поведения, диагностика — для UB),
  трактовка `extern fn`, декомпозиция на `0025-01…05` и 9 критериев приёмки.
  Правило 18 соблюдено: диаграммы активности «как есть» и целевого потока.
- **Бэклог кандидатов `FEATURES.md` пополнен находками обзора** (правило 7):
  размер `validate.rs` (3648 строк против лимита ~1000), эмиссия заглушек
  `//FIXME`/`//TODO` в генерируемый C (`c_model.rs:769`, `:316`), тихая потеря
  LTL в блоках кода (`statement.rs:266`), предупреждения `private_interfaces` в
  `simulation`.

### Изменено

- **Версия языка 0.1.0 → 0.2.0; фича 0020 закрыта (ГОТОВО).** Подсистема адресов
  портов реализована полностью (0020-01…05). Расширение **аддитивное** (инлайн-адрес
  работает как прежде) → минорный бамп по SemVer (правило 22): `grammar` 0.1.0 →
  0.2.0. Обновлены `grammar/Cargo.toml`, `README.md` (раздел «Версия»), `CLAUDE.md`
  (инвариант адреса порта), карточка `docs/features/0020-…` (раздел «Итог»,
  статус ГОТОВО), реестр `docs/features/README.md`; фича удалена из витрины
  `FEATURES.md`.

- **Фича 0020 (пересмотр архитектуры): «Адрес порта — размещение + потребление
  (карта адресов)».** По запросу заказчика решение 0020 пересмотрено на стадии
  «Архитектура». Триггер — находка в коде: числовой адрес порта **не эмитится в
  генерируемый C** (порт → enum, чтение/запись через HAL-колбэки,
  `generator/c/c_expr.rs:261`), то есть был мёртвыми метаданными. Проведён обзор
  других языков (Ada `for X'Address use`/аспект `with Address`; IEC 61131-3
  `AT %IX`; внешние файлы SVD/device-tree/`.ld` с оверлеями; препроцессор `-D`).
  Принят **гибрид** на базе единого внутреннего слоя `AddressMap: PortId →
  Address`: источники (по возрастанию приоритета) — инлайн `:=` (сахар) → оператор
  `address NAME = <expr>;` (**жёсткое** ключевое слово) → внешняя **`.ld`-подобная**
  карта (`--address-map`, оверлей + warning при перекрытии); потребитель ядра — C
  (таблица адресов + дефолтный HAL через `*(volatile*)`). Правила: двойное
  задание в одной области → ошибка; висячая привязка → ошибка; адрес обязателен
  только для портов, **достижимых** кодогенерацией (опора на `unused.rs`), мёртвые
  — не в счёт. Вынесены в отдельные фичи/кандидаты: `-D`/инъекция define’ов,
  SVD-экспорт, ST `AT %` (в рамках ST-бэкенда). Переписаны `docs/adr/…`,
  `docs/analyze/…`, карточка `docs/features/0020-…`, обновлены `FEATURES.md` и
  реестр `docs/features/README.md`. Кода нет; язык расширяется → версия языка
  повышается при реализации (правило 22).

### Добавлено

- **Фича 0020-05 (разработка): потребление адреса в C — цель `c-hal`.**
  Завершает подсистему адресов (фича [0020](docs/features/0020-port-address-decl.md)):
  адрес порта становится реально потребляемым артефактом. Новая цель `lamc compile
  -t c-hal` генерирует обычный C **плюс** таблицу адресов портов и дефолтную
  реализацию HAL. `address_map.rs`: `resolve_addresses` строит консолидированный
  `AddressMap` (приоритет inline < `address` < внешняя карта), понижает адрес в
  `(addr,bit)`, даёт SE-052 (used-порт без адреса → ошибка), SE-050/051.
  `GenerateOptions`: поля `hal`/`address_map`. `lib.rs`: `compile_to_c_hal`
  (карта участвует в резолве; SE-052 → ошибка; возвращает предупреждения).
  `generator/c/c_header.rs`: в режиме hal — `{Root}_PortBinding`, таблицы
  `{Enum}__ADDR[]`, дефолтные `read_*`/`write_*` через `*(volatile T*)addr`,
  `bind_default_hal`, а также `typedef struct {Root} {Root};` для одиночной
  модели. CLI: `-t c-hal` + протяжка `--address-map`, справка. Цель `c` —
  **байт-в-байт как прежде** (регресс = 0). Сгенерированный `c-hal`-вывод
  **компилируется** `cc -std=c99 -Wall`. Тесты: резолвер (6), codegen c-hal (4),
  CLI. fmt/clippy чисты. Документ `docs/development/0020-05-c-consumption.md`.

- **Фича 0020-04 (разработка): полнота адресов по достижимости.** Проверка, что
  порт, попадающий в кодогенерацию, имеет адрес (фича
  [0020](docs/features/0020-port-address-decl.md), стадия «Разработка»).
  `semantic/validate.rs`: `check_port_address_completeness(model, external_ports)`
  — достижимость порта из `unused::compute_usage`; используемый порт без адреса
  (ни inline, ни оператором `address`, ни во внешней карте) → предупреждение
  **SE-052**; мёртвые порты не предупреждаются; результат детерминирован
  (сортировка по позиции), обход рекурсивный. `lib.rs`: публичная обёртка
  `port_address_completeness_warnings(model, external_ports)`. Функция
  **аналитическая** — не в конвейере `validate_model`/`compile_to_c` по умолчанию
  (в текущей C-модели адрес не эмитится, примеры объявляют порты без адресов);
  эскалацию в ошибку «по цели» подключает адрес-потребляющий C-режим (0020-05).
  Тесты `port_address_completeness_tests.rs` (используемый без адреса → SE-052;
  мёртвый → тихо; inline/оператор/внешняя карта → тихо). fmt/clippy чисты.
  Документ разработки `docs/development/0020-04-completeness.md`.

- **Фича 0020-03 (разработка): внешняя `.ld`-подобная карта адресов.** Адреса
  портов можно держать в отдельном файле-карте и накладывать оверлеем под
  платформу (фича [0020](docs/features/0020-port-address-decl.md), стадия
  «Разработка»). Новый модуль `grammar/src/address_map.rs`: `parse_address_map`
  — свой построчный парсер формата `NAME = 0xADDR[:bit];` (комментарии `//`,
  hex/десятичные, устойчивость к ошибкам с восстановлением до `;`), коды
  **AM-001…006**; `address_map_overlay_warnings` — наложение на модель с
  предупреждениями **SE-050** (карта переопределяет адрес, заданный в модели) и
  **SE-051** (запись для несуществующего порта). Реэкспорт из `lib.rs`
  (`parse_address_map`, `address_map_overlay_warnings`, `AddressMapEntry`). CLI:
  флаг `--address-map <файл>` (`lamc`) — карта читается, разбирается (ошибки
  формата → выход), затем печатаются оверлей-предупреждения; справка дополнена.
  Тесты: юнит-тесты парсера (форматы + AM-коды + восстановление),
  `address_map_tests.rs` (оверлей SE-050/051), CLI-разбор флага. Границы: приоритет
  выражен предупреждением, фактическое переопределение значения и консолидированный
  `AddressMap` для генерации — 0020-05; вложенные модели оверлей пока не покрывает.
  Все тесты зелёные; fmt/clippy чисты. Документ разработки
