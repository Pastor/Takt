## TAKT-715. Заголовки MatIEC в драйверах conformance

В 27 C-драйверах из 23 файлов `takt-sim/tests/conformance/` заголовок
`accessor.h` подключается сразу после `iec_std_lib.h` и до `POUS.h`.
Так макросы MatIEC уже определены к моменту, когда `POUS.h` включает
`iec_std_FB.h`. На базе `144aacc3` сборка драйверов давала 28 отказов.
Ожидаемые трассы сохранены.

Полный прогон на MatIEC 0.1 (`c316fe57`), Apple Clang 21.0.0,
Rust 1.97.1 и Verilator 5.055 devel (`2d6aba6ed`) завершился
с результатом 308/308, без пропусков и расхождений трасс. Четыре теста
ищут MatIEC по стандартному пути `~/.local`. На время прогона этот
путь указывал на ту же установку.

```bash
export IEC2C_PREFIX=/private/tmp/takt-matiec.MDxe4h/install
export CARGO_TARGET_DIR=/private/tmp/takt-715-target
export PATH="/private/tmp/takt-oss-cad.kWvgCT/oss-cad-suite/bin:$IEC2C_PREFIX/bin:$PATH"
CC=/usr/bin/clang cargo test --locked -p takt-sim --test conformance -- --nocapture
cargo fmt --check -p takt-sim
git diff --check
```

Строгая проверка ST из `scripts/precheck.sh` запущена отдельно с
`PRECHECK_STRICT=1`. После `cargo build --locked -p takt-lang --bin taktc`
все 11 корневых примеров пересобраны командой `taktc compile … -t st -o …`
во временный каталог. `iec2c -I "$IEC2C_PREFIX/share/matiec/lib" -T …`
принял все 11 файлов. Журналы: `/private/tmp/takt-715-conformance-full.log`
и `/private/tmp/takt-715-st-gate.log`.

У `scripts/probe.sh` отдельный способ сборки C. На `examples/regulator.takt`
конфигурационная единица цели `st-at` собирается. Для `st` вызов с
`-include POUS.h` падает в `iec_std_FB.h`. Этот путь находится вне
драйверов conformance. Журнал: `/private/tmp/takt-715-probe.log`.

## TAKT-714. Архив WASM при Docker-выкатке

Разработка начата от `origin/v2` (`02b9ef92`), интеграция выполнена с
локальным TAKT-713 (`151bdcd8`). Эти два изменения предназначены для одной
выкатки.

Под замком `stand-hook.py` скрипт `stand.sh up` переносит каталог `wasm`
из прежнего контейнера во временный каталог. После `down` архив берётся
из локального тега последнего образа. Новый образ собирается под временным
тегом. `merge-wasm.py` проверяет структуру индексов, размер и SHA-256 модулей
по описям и отклоняет новые байты для занятого URL. Эту же проверку вызывает
`deploy-web.sh`. Прежние каталоги версий копируются целиком, включая описи и
предсжатые файлы. Последней индекс объявляет версию новой сборки.

Проверенный архив добавляется слоем к новому образу до переключения Compose.
Ошибка подготовки оставляет старый контейнер обслуживающим запросы.
После смены контейнера скрипт ждёт `/health` и сверяет `wasm/index.json` с
подготовленным индексом. При отказе он возвращает прежний образ через
Compose и проверяет прежний индекс и `/health`. Отказ новой выкатки
сохраняется в статусе hook даже при успешном откате.

### Сверка выкатчиком

Перед выкаткой сохраните три опубликованных файла для сравнения. После
штатной выкатки обоих коммитов повторите запросы и сверьте байты и индекс.

```bash
base=https://pastor.axatel.ru/takt
before=$(mktemp -d)
for file in takt.wasm takt-export.wasm manifest.json; do
  curl -fsS "$base/wasm/0.62.2/$file" -o "$before/$file" || exit 1
done
shasum -a 256 "$before/"*.wasm
# Здесь выкатчик выполняет штатную выкатку.
after=$(mktemp -d)
curl -fsS "$base/health" || exit 1
curl -fsS "$base/wasm/index.json" | python3 -c '
import json, sys
data = json.load(sys.stdin)
assert data["latest"] == "0.62.3"
assert {"0.62.2", "0.62.3"} <= set(data["versions"])
' || exit 1
for version in 0.62.2 0.62.3; do
  mkdir -p "$after/$version"
  for file in takt.wasm takt-export.wasm manifest.json; do
    curl -fsS -D "$after/headers" "$base/wasm/$version/$file" \
      -o "$after/$version/$file" || exit 1
    grep -qi '^cache-control: .*immutable' "$after/headers" || exit 1
  done
  shasum -a 256 "$after/$version/"*.wasm
done
for file in takt.wasm takt-export.wasm manifest.json; do
  cmp "$before/$file" "$after/0.62.2/$file" || exit 1
done
```

Затем откройте проект, сохранённый с версией 0.62.2, и скачайте его архив
с целью C. В архиве должны быть файлы C в `generated/`. Сервер выбирает
ядро по `takt_lang` проекта. Браузерный редактор загружает текущий модуль
из `version.json`.

## TAKT-595. Запись прогона и редактор сценария

Ветка `codex/TAKT-595` создана от `5d39c551`, вершина `origin/v2`
сверена с GitHub. В браузере запись собирается из завершённых тактов
эталона. Она сохраняет исходные `extern`, `guard` и время из сценария,
подставляет ручные значения на их тактах и удерживает пустые шаги.
Файл открывается из проекта и скачивается. Для явной частоты CLI
принимает `takt-sim --tick-hz`. Формат сценария остался прежним.

Редактор даёт перемещаться по шагам и менять `in_ports`, `guard`,
`extern` и `_step`. Он сохраняет исходный текст остальных полей и точные

## Панель схемы IntelliJ (TAKT-540)

В окне Takt Scheme общий холст загружается из ресурсов плагина в JCEF.
Панель слушает смену активного редактора, правки текста, каретку и тему IDE.
Отложенные ответы графа сверяются с редакцией документа. Сообщения холста
привязаны к открытому файлу.

При наличии LSP4IJ панель запрашивает `takt/graph` у сервера, к которому
подключён выбранный документ. Перед запросом LSP4IJ отправляет ожидающие
`didChange`. Без LSP4IJ панель передаёт снимок текста редактора в
`takt-lsp --graph` через временный файл. Оба ответа проходят общий разбор
JSON. Соседний `.takt-ui` читается и записывается через VFS. Обновление
с диска отражается на холсте, а запись из холста сохраняет его историю
отмены. Инструкция по панели добавлена в главу «Инструментарий».
