## TAKT-699. Экспорт схемы в IntelliJ

Ветка `codex/TAKT-699` создана от `a97bcf00`, вершина `origin/v2`
сверена с GitHub. Кнопка «Экспорт» берётся из общей разметки холста.
Холст передаёт только событие и номер сессии. Панель сверяет его
с активным локальным редактором и сохраняет документы перед запуском.
Режим `EXPORT` в `TaktCommandLine` собирает вызов настроенного
`takt-sim export` с каталогами импортов. Процесс работает в фоне
и поддерживает отмену через индикатор IDE. По умолчанию CLI строит SVG
всех листов открытой модели. Панель задаёт соседний каталог `export/`
и сообщает об исходе запуска. Сборка ресурсов также подхватила
разметку, стили и словари текущей веб-страницы на базе TAKT-595.

## TAKT-595. Запись прогона и редактор сценария

Ветка `codex/TAKT-595` создана от `5d39c551`, вершина `origin/v2`
сверена с GitHub. В браузере запись собирается из завершённых тактов
эталона. Она сохраняет исходные `extern`, `guard` и время из сценария,
подставляет ручные значения на их тактах и удерживает пустые шаги.
Файл открывается из проекта и скачивается. Для явной частоты CLI
принимает `takt-sim --tick-hz`. Формат сценария остался прежним.

целые числа. Эталон принимает обновлённые будущие шаги той же сессии.
Сдвиг шагов в уже пройденной части применяется после сброса.
Черновик файла сценария хранится с собственной прочитанной ревизией.
Запись в проект использует прежние права и проверку ревизии.

## TAKT-596. Последовательная цепочка внутри параллельной

Ветка `v2` на `afaa4383` совпадала с вершиной на GitHub. В ней уже есть
коммит `3cc4fc95`, который добавил поддержку `(A + B) | C`

прошёл без пропусков (3 теста). Эталонный симулятор и модули, собранные

в порт с четвёртого. Существующие тесты обнаруживают как потерю
цепочки в C, так и преждевременный запуск B в Rust.

Отдельная сверка `parallel_step_inside_concatenation_matches_generated_c`
тоже прошла. `precheck.sh` остановился на битых ссылках в карточках

## TAKT-615. Запись в выходной порт из другого порта в Rust

На `v2` (`21b5d777`) уже присутствует исправление `237f7d5b`.
При чтении HAL в правой части генератор вычисляет значение во временной
переменной `takt_value` до вызова записи. Это разводит изменяемые
заимствования HAL и сохраняет порядок операторов модели.

- Буквальный пример из карточки завершается с `SE-102`: в файле нет
  стартового состояния верхнего уровня. С теми же портами и состояниями
  на верхнем уровне `taktc compile -t rust` генерирует рабочий код,
  который принимает `rustc -D warnings`. Возврат вложенного вызова чтения
  в копии сгенерированного файла воспроизводит `E0499`.
- `cargo test --offline -p takt-lang --test targets rust_port_read_in_write_tests -- --nocapture`:
  три теста. Прямое присваивание `bit` и выражение с чтением `u8` в аргументе
  функции компилируются в `rustc` и `clippy-driver` с `-D warnings`.
  Проверена форма вывода для обеих записей и обычный аргумент для записи
  без чтения HAL.
- `cargo test --offline -p takt-sim --test conformance conformance_port_read_in_write_tests -- --nocapture`:
  один тест. Порождённый Rust и эталонный симулятор после трёх тактов дают
  одинаковые значения `(o_sum, o_bit, o_plain) = (21, 1, 3)`. Фикстура
  читает двунаправленный порт после записи в него в том же такте.

### TAKT-707. Ссылки в перенесённых карточках

В aNaL сверены все ключи `TAKT-1`–`TAKT-706`. R80 и умение № 45
подключены. Коммит переноса `db98c93f` входит в историю `main` и `v2`.
Рабочая база итоговой проверки — `89ba0195` (`origin/v2`).

Все 5150 ошибок относятся к 661 Markdown-файлу в `tasks/`. Выгрузка
`351f9179` содержит 709 файлов OKF. Для каждой из 5150 ссылок нашлась
цель в дереве `3c154a13`, если разрешать путь от исходной карточки.
Например, `0049-model-checking-ltl.md` из TAKT-10 теперь разрешается
в отсутствующий `tasks/0049-model-checking-ltl.md`. В архиве цель лежит
рядом с исходной карточкой.
[Ссылка на цель в архиве](https://github.com/Pastor/Takt/blob/3c154a13d979b18312a1250ebfbe3db2fa5247d3/docs/features/0049-model-checking-ltl.md).

GitHub открывает ссылки относительно Markdown-файла текущей ветки.
В aNaL тот же путь присутствует в теле TAKT-10 (MCP id 1064).
В источниках aNaL на `8190da95` функция `TaskFile.tail` записывает
тело задачи в OKF. В интерфейсе `TaskCard.svelte` передаёт тело
в `descriptionNode`, а `design/book/js/markdown.js` сохраняет
относительный путь в `href`. Браузер разрешает его от страницы aNaL.
Архивный путь в строке «Источник» даёт доступ к оригиналу отдельно.
[Правила относительных ссылок GitHub](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#relative-links).

Один вариант исправления — обновить тексты через aNaL и повторить
выгрузку. Для унаследованных целей можно построить постоянные URL
на коммит архива из пути оригинала. При преобразовании надо сохранить
фрагменты ссылок и сверить пути с деревом архива. Так адреса будут
одинаковыми в карточке и в Git. Преобразование только при экспорте
решит проблему в Git, а карточкам потребуется отдельная правка.
Ручная правка экспортированных файлов расходится с телом в aNaL и
затрагивает контрольные суммы OKF.
Массовое исправление вынесено в [TAKT-710](https://pastor.axatel.ru/anal/#task/1840).

Эксперимент с проверкой архивного пути дал 5225 проверенных ссылок
и устранил остановку на проверке ссылок. Адреса перехода остались прежними,
поэтому изменение проверки снято. Следующий блокер эксперимента —
C1 в `check-comments.py`. Отчёт совпал с чистой базой `ed53482b`.
Отдельный прогон перечислил 211 находок C1 в выгрузке и одну в
`takt-sim/tests/conformance/conformance_time_implementation_tests.rs`.
Итоговый `precheck.sh` останавливается на 5150 ссылках. Перенос и сверка
полноты завершены. Ошибка ссылок учтена в TAKT-710, сбой C1 остаётся
отдельным результатом проверки.

## Восстановление реализаций состояний

В `TAKT-702` воспроизведён сбой через `--save-state` и `--load-state`.
После загрузки условие `S(Feeder) = Done` не срабатывало, хотя до
сохранения вложенная модель уже перешла в `Done`. Снимок теперь хранит
дерево реализаций по именам состояний, а загрузка восстанавливает дерево
и заново публикует его в реестре. Старые снимки читаются без поля

## Панель схемы IntelliJ (TAKT-540)

В окне Takt Scheme общий холст загружается из ресурсов плагина в JCEF.
Панель слушает смену активного редактора, правки текста, каретку и тему IDE.
Отложенные ответы графа сверяются с редакцией документа. Сообщения холста
привязаны к открытому файлу.

При наличии LSP4IJ панель запрашивает `takt/graph` у сервера, к которому
подключён выбранный документ. Перед запросом LSP4IJ отправляет ожидающие
`didChange`. Без LSP4IJ панель передаёт снимок текста редактора в
`takt-lsp --graph` через временный файл. Оба ответа проходят общий разбор
JSON. Соседний `.takt-ui` читается и записывается через VFS. Обновление
с диска отражается на холсте, а запись из холста сохраняет его историю
отмены. Инструкция по панели добавлена в главу «Инструментарий».

Проверки на базе `ac49d140` включали 177 LSP-тестов, сверку WASM с CLI,
154 веб-теста, проверку 20 ресурсов панели, сборку книги и проверки её
примеров. В проверке компиляции примеров пропущены цели ST и SystemVerilog
из-за отсутствия `iec2c` и `verilator`. `./scripts/precheck.sh`
остановился на первой проверке ссылок. Все 5150 ошибок относятся к
неизменённым карточкам `tasks/`.

На JBR 21 из SDK IntelliJ 2024.2.5 прошли `./gradlew test buildPlugin
verifyPluginStructure` и все 100 тестов. Верификатор оставил предупреждение
об историческом ID плагина `org.takt.intellij`. Указали JBR явно и отключили
автозагрузку JDK, поскольку при автоподборе Gradle 9.7.0 завершался ошибкой
`IBM_SEMERU`. `runIde` запустил пробный проект в изолированной песочнице.
Инструмент управления окном не смог подключиться к процессу песочницы,
поэтому сценарии с холстом в IDE остались без ручной проверки.
