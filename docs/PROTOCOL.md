# Протокол Takt

## TAKT-706. Пример в главе «Диагностики»

После раздела о тихом режиме добавлена модель лампы с двумя выносками.
Разбор показывает предупреждение `SE-036` при успешной генерации и
ошибку `SE-003` при опечатке в имени входа.

`taktc 0.62.2` (язык 0.19.0) принял формат примера и сгенерировал C,
Rust, ST и SystemVerilog с предупреждением. С `--quiet` предупреждение
скрылось, а ошибка в позиции 8:20 сохранилась и оставила каталог вывода
пустым. После исправления имени и удаления лишней переменной компиляция
прошла без диагностики. Симуляция подтвердила выход 0 → 1 → 0 за три такта.

`make -C book pdf` собрала 183 страницы. Пример целиком виден на
печатной странице 84. Прошли проверки шрифта, лексики, подсветки, кодов
диагностик, стиля документов и примеров глав. База ветки сверена с
`origin/v2` (`afaa4383`).

## TAKT-704. Тип результата `unit`

В главе «Типы данных» описан `unit`, в главе «Функции» добавлена ссылка
на описание. Явное `-> unit` и опущенная аннотация задают один тип
результата. Вызов выполняет действие, функция завершается в конце тела
или по `return;`.

`make -C book pdf` собрала 180 страниц. Прошли проверки символов шрифта,
лексики, подсветки, кодов диагностик и стиля документов с самопроверками.
Пробная модель с обеими формами объявления прошла генерацию для C, Rust,
SystemVerilog и ST установленным `taktc 0.62.2` (язык 0.19.0).
`takt-sim` выполнил 10 тактов. База ветки сверена с `origin/v2` (ac49d140).

## Очистка после сборки

В рамках `TAKT-708` скрипты предкоммита, установки и проверки веб-сервера
очищают свои каталоги на выходе. Готовые бинарники остаются на месте.
Сверка WASM собирает модули во временном каталоге и переносит готовые
файлы после проверки.

После очистки `target/precheck` сократился с 5,4 ГБ до 87 МБ,
`target/web-server` освободил 2,7 ГБ. Проверены готовые бинарники, сборка
и сверка WASM, режим установки и сохранение кода ошибки при очистке.

## TAKT-703. Повтор образца внутри ветви `match`

`SE-131` сообщает о дубле в списке образцов и указывает на ветвь.
Для повторов между ветвями сохраняется прежняя диагностика.

До исправления тест `1, 1 => { … }` получил ноль предупреждений.
После исправления прошли 828 семантических тестов, 37 тестов диагностик
и 8 тестов генерации ветвей. Прошли fmt, Clippy, проверки реестра,
качества диагностик, размеров модулей и сборка книги. Проверка
Markdown-ссылок дала тот же список из 5150 ошибок, что и на чистой `v2`.

## Восстановление реализаций состояний

В `TAKT-702` воспроизведён сбой через `--save-state` и `--load-state`.
После загрузки условие `S(Feeder) = Done` не срабатывало, хотя до
сохранения вложенная модель уже перешла в `Done`. Снимок теперь хранит
дерево реализаций по именам состояний, а загрузка восстанавливает дерево
и заново публикует его в реестре. Старые снимки читаются без поля
`state_impls`. Регрессия проверяет переход по условию на первом такте
после загрузки.

`cargo test --locked -p takt-sim` — 737 тестов прошли, один
документационный тест пропущен. Форматирование, Clippy для `takt-sim`
и проверка стиля документации прошли. `./scripts/precheck.sh`
остановился на 5150 битых ссылках. Список совпал с исходной `v2`.

## Сверка времени в реализации состояния

В `TAKT-701` на существующих фикстурах `time_in_implementation.takt` и
`every_in_implementation.takt` добавлена потактовая сверка Rust с эталоном
по двум выходам с шагом 1 мс. Сверки C используют те же фикстуры и эталон.

ST прогнан через MatIEC и драйвер со временем ПЛК, SystemVerilog — через
Verilator с внешним `time_ms`. Трассы и ограничения инструментов записаны
в карточке `TAKT-701`.

`scripts/precheck.sh` остановился на проверке Markdown. На чистой базе
`ac49d140` проверка выдаёт тот же список из 5 150 битых ссылок.
