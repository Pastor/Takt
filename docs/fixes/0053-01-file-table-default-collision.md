# Исправление 0053-01: `FileTable::default()` сталкивает первый импорт с корнем

> Фича: [../features/0053-diagnostics-file-id.md](../features/0053-diagnostics-file-id.md) · обнаружено при проработке [фичи 0056](../features/0056-lsp-goto-exact-file.md)

- **Статус:** ЗАВЕДЁН (проработан, не исправлен)
- **Блокирует:** задачу [0056-01](../development/0056-01-file-aware-index.md) —
  файлоосознанный индекс без верных номеров файлов не различит файлы.

## Проблема

`FileTable::add` нумерует файлы позицией в векторе:

```rust
pub fn add(&mut self, path: &str) -> u64 {
    if let Some(i) = self.paths.iter().position(|p| p == path) {
        return i as u64;
    }
    self.paths.push(path.to_string());
    (self.paths.len() - 1) as u64
}
```

`FileTable::new(root)` кладёт корень в слот `0`, поэтому первый импорт получает
`1` — верно. Но `FileTable::default()` создаёт **пустой** реестр, и первый
импорт получает **`0`** — тот же номер, что корень у `new`.

Итог: в дереве, построенном через `construct_model` (обёртка с
реестром-однодневкой), диагностика и позиция из **импортированного** файла
неотличимы от корневых — ровно тот дефект, который фича 0053 закрывала.

## Как обнаружено

Зондом при проработке 0056 (не тестами):

```text
УЗЕЛ: name=speed kind=Variable loc=Source(0, 19, 37)
```

`speed` объявлена в `helper.lam` — импортированном файле, — но несёт `file_no=0`.
Ожидалось `1`.

## Почему не поймали тесты 0053

Тесты фичи 0053 проверяют путь `compile_to_*`, а он использует
`FileTable::new(filename)` — корень в слоте `0`, коллизии нет. Ветка с
`Default` осталась **без потребителя, читающего `file_no`**: `construct_model`
зовут 183 места, но ни одно из них номер файла не читает.

Тот же класс, что дефект затравки [0010-01](0010-01-buchi-acceptance.md): код без
потребителя молча гниёт. Разница в том, что здесь потребитель **появится** —
задача 0056-01.

## Влияние (сегодня — латентное)

| Путь | Реестр | Коллизия |
|---|---|---|
| `compile_to_*` → `parse_and_construct` | `new(filename)` | нет |
| `lsp::collect_diagnostics_at` | `new(path)` | нет |
| `simulation` | `new(lam_file)` | нет |
| `construct_model` (обёртка, 183 вызова) | `default()` | **есть** |

Единственный сегодняшний читатель `file_no` из этой ветки —
`goto_declaration_with_paths`, а его не зовёт никто, кроме тестов (с пустыми
путями). Поэтому дефект **латентен** — но 0056 его активирует.

## Предлагаемое исправление

Слот `0` обязан быть **зарезервирован всегда**: номер `0` означает «корень»,
и раздавать его импорту нельзя ни при каком способе создания реестра.

Варианты:

1. **`Default` резервирует слот `0` пустым путём**, `path()` возвращает `None`
   для пустой строки. Дёшево; `path(0)` честно говорит «корень неизвестен».
2. **Нумерация с `1`, когда корень неизвестен.** Явнее, но `paths` перестаёт
   быть простым вектором-индексом.

Предпочтителен вариант 1: он сохраняет инвариант «индекс = номер» и делает
неизвестный корень выразимым.

## Проверка

Тест-сторож (в объёме 0056-01):

```rust
// Импорт НИКОГДА не получает номер корня — при любом способе создания реестра.
let mut files = FileTable::default();
assert_ne!(files.add("lib.lam"), 0);
```

Плюс сторож против регресса зонда: узел под курсором принадлежит текущему файлу
(критерий A3 ADR 0056).
