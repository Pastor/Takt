# ADR 0081: `lamc compile` печатает предупреждения компилятора

- **Status:** Accepted
- **Date:** 2026-07-20
- **Authors:** Архитектор + Лид разработки
- **Related issues:** [Фича 0081](../features/0081-lamc-print-warnings.md); выявлено при [0035](../features/0035-ltl-in-blocks.md)

## Context

`unused_variable_warnings` (`SE-036`), `nondeterministic_transition_warnings`
(`SE-037`/`SE-042`), `unreachable_state_warnings`, `constant_condition_warnings`,
`ltl_warnings`, `stray_semicolon_warnings`, `unknown_named_block_warnings` — часть
**публичного API** (`lib.rs`), но из CLI **не вызывались**. `lamc compile` печатал
только **два** адрес-специфичных предупреждения (`address_expr`,
`address_map_overlay`, фичи 0042) и **лишь для не-адрес-потребляющих** целей.

Следствие: пользователь `lamc` **не видел** ни `Ce13` (неиспользуемая
переменная), ни `Ce14` (недетерминизм переходов), ни любого нового предупреждения
(`SE-053`/`SE-054` фич 0035/0042). Диагностика, которую никто не печатает,
равносильна её отсутствию.

**Замер корпуса (проба 2026-07-20):** после подключения всех предупреждений
корпус даёт **одно** — `examples/elevator.lam`: переменная `action` объявлена, но
не используется (`SE-036`). Это **реальная находка**, не ложное срабатывание;
прочие категории на корпусе молчат.

## Decision Drivers

1. **Новое предупреждение обязано доезжать до всех целей автоматически.** Дефект
   в том, что доставка была частичной (две категории, часть целей).
2. **Единообразие с ошибкой.** Пользователь читает ошибку и предупреждение одним
   взглядом — тот же формат (позиция `файл:строка:колонка` + код).
3. **Не менять код возврата.** Предупреждение — не ошибка: корпус целью `c`
   собирается успешно (rc=0), и это должно сохраниться.
4. **`--quiet` уважается** — как для существующих адрес-предупреждений.

## Considered Options

### Option A (принято). Единая точка сбора; печать для всех целей

Функция `semantic::warnings::collect_model_warnings(ast, model)` собирает все
предупреждения публичного API над **построенной** моделью; CLI печатает их
форматом, **общим с ошибкой** (`position_prefix` + код), для **любой** цели,
уважая `--quiet`. Адрес-специфичные предупреждения добавляются отдельно у
вызывающего — они зависят от цели (у `c-hal`/`st-at` те же ситуации дают
**ошибки** `SE-052`/`SE-054`, а не предупреждения).

⚠️ `collect_model_warnings` живёт в `grammar/src/semantic/warnings.rs`, а **не** в
`bin/lamc.rs` или `lib.rs`: оба пришпилены к лимиту размера модуля, добавление в
них отвергается гейтом. Печать — inline в CLI (отдельная функция превысила бы
лимит `bin/lamc.rs`).

**Pros:**
- Новое предупреждение API доезжает **сразу до всех целей** (драйвер 1) — одна
  точка правки.
- Формат общий с ошибкой (драйвер 2); `--quiet` работает (драйвер 4).
- Уровень — предупреждение, rc не меняется (драйвер 3): корпус собирается прежним
  кодом.

**Cons:**
- Модель строится **повторно** ради предупреждений (парсинг + семантика). Для CLI
  (не горячий путь) цена пренебрежима; уже так делалось для адрес-предупреждений.

### Option B. Печатать только `Ce13`/`Ce14` (буква находки)

**Cons:** оставляет `unreachable`/`constant_condition`/`ltl`/`stray_semicolon`/
`unknown_named_block` непечатаемыми — дефект «предупреждения не доезжают» решён
частично; следующий добавленный код снова потребует правки CLI (нарушен драйвер 1).

### Option C. Вернуть предупреждения из `compile_to_*` вместе с генерацией

**Cons:** меняет сигнатуры всех `compile_to_*` (7 целей) и их 36+ вызовов в
тестах — несоразмерно объёму; предупреждения не зависят от цели, им незачем течь
через генератор.

## Decision

Принимается **Option A**.

**Нормативные правила:**

1. **Единая точка** `semantic::warnings::collect_model_warnings(ast, model)` — все
   предупреждения публичного API над построенной моделью. Новый код диагностики,
   попав в эту функцию, доезжает до всех целей.
2. **Печать inline** форматом, общим с `print_compile_error` (позиция + код +
   текст).
3. **Для всех целей**; `--quiet` глушит.
4. **Уровень — предупреждение**, rc не меняется.
5. **Адрес-специфичные предупреждения** (`address_expr`/`address_map_overlay`) —
   только для целей, адрес **не** потребляющих (у `c-hal`/`st-at` — ошибки).
6. Язык **не меняется** → версия не растёт (правило 22).

## Consequences

### Положительные

- Предупреждения `Ce13`/`Ce14` и все прочие видны пользователю впервые.
- Любое новое предупреждение доезжает автоматически.
- **Находка:** `examples/elevator.lam` содержит неиспользуемую `action` — кандидат
  на чистку (вне объёма 0081).

### Отрицательные / Action items

- **A-1. Двойное построение модели** в CLI (ради предупреждений + при генерации).
  Приемлемо для CLI; оптимизация — при необходимости.
- **A-2. Чистка `elevator.lam`** (unused `action`) — кандидат, вне объёма.

### Acceptance criteria

1. **A1.** `lamc compile` на файле с неиспользуемой переменной печатает `SE-036`.
2. **A2.** На недетерминированных переходах печатает `SE-037`.
3. **A3.** `--quiet` глушит предупреждения.
4. **A4.** Чистый файл предупреждений не даёт.
5. **A5.** Код возврата не изменился (корпус собирается, `precheck.sh` зелёный).
6. **A6.** Язык не изменился; версия не поднята.
