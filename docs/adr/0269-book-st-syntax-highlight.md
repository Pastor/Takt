# ADR 0269: Подсветка блоков `st` и `ebnf` в документе

- **Status:** Accepted
- **Date:** 2026-08-20
- **Authors:** Архитектор + Аналитик
- **Related issues:** [Фича 0269](../features/0269-book-st-syntax-highlight.md); [фича 0240](../features/0240-book-typst.md) (переход на Typst, где класс и возник), [фича 0160](../features/0160-takt-ebnf-sync.md) (приложение «Грамматика» — восемь блоков EBNF), [фича 0146](../features/0146-book-glyph-gate.md) (образец: сборка документа класс не ловит)

## Context

Подсветку блоков кода в Typst делает **syntect**. Его встроенных определений
хватает не на всё: Structured Text среди них нет, EBNF тоже.

**Замер 2026-08-20** (кандидат перепроверен, правило 30) — рендер пробной
страницы в PNG:

| Блок | Результат |
|---|---|
| ```c | подсвечен (ключевые слова, комментарий) |
| ```st | **чёрный текст** |
| ```ebnf | **чёрный текст** |

Состав документа: `takt` — 237 блоков, `text` — 109, `bash` — 19, **`ebnf` — 8**,
`c` — 7, `systemverilog`/`sh`/`rust`/`json` — по 2, **`st` — 1**.

Уточнения к кандидату: он называл «два блока `st` и `pascal`» — сегодня
`pascal` в документе нет вовсе, зато есть **восемь** блоков `ebnf`, которых
кандидат не упоминал. То есть непокрытых блоков девять, а не два.

⚠️ **Класс невидим сборке:** `typst compile` на неизвестном языке блока даёт
**код 0** и ни слова. Замечает только глаз, и то на цветной странице — ровно
как с символами вне шрифта (фича 0146).

## Decision Drivers

1. **Документ показывает вывод целей рядом.** Блок `c` цветной, блок `st`
   чёрный — читатель видит разницу, которой нет причины.
2. **Приложение «Грамматика» — восемь блоков подряд** без выделения терминалов;
   именно терминалы там несут смысл.
3. **Молчание сборки** делает класс невидимым: без гейта следующий язык
   заведут так же тихо.

## Considered Options

### Option A. Переразметить блоки под встроенные языки

Писать ```pascal вместо ```st (прежний конвейер так и делал).

**Pros:** ноль своих файлов.
**Cons:** метка языка перестаёт быть правдой — блок содержит **не** Pascal;
у EBNF подходящего суррогата нет вовсе.

### Option B. Свои определения `.sublime-syntax` рядом с документом

Тем же способом, каким заведена подсветка Takt (фича 0240): файл подключается в
`book/src/template.typ`.

**Pros:** метка честная; форма проверена — Typst принимает **список**
синтаксисов; правила описывают ровно то, что стоит в документе.
**Cons:** два файла на сопровождении; полнота по стандарту не гарантируется.

### Option C. Оставить как есть

**Pros:** ноль работы.
**Cons:** документ показывает вывод одной цели хуже другой без причины.

## Decision

Принимается **Option B**, и вместе с ним — **гейт**:

1. `book/st.sublime-syntax` — Structured Text: объявления POU и секций,
   управляющие конструкции, словесные операторы (`AND`/`OR`/`XOR`/`MOD`),
   элементарные типы, литералы (типизированный, с основанием, длительность),
   локации `%MB512`, комментарии `(* … *)`. Правила **нечувствительны к
   регистру**: идентификаторы IEC регистронезависимы, цель печатает верхним, а
   рукописный пример может быть строчным.
2. `book/ebnf.sublime-syntax` — терминалы в кавычках, `::=`/`=`, `|`, `{}`,
   `[]`, `()`, `;`, нетерминалы, комментарии `(* … *)`.
3. `scripts/check-book-code-langs.py` (шаг предкоммита со своей самопроверкой):
   язык блока обязан быть **объявлен** — либо как встроенный в syntect, либо
   как свой, с существующим файлом, **подключённым** в шаблоне. Четыре класса
   находок: не объявлен (C1), нет файла (C2), файл не подключён (C3), объявлен
   впустую (C4).

⚠️ Полнота по стандарту IEC 61131-3 **не требуется**: требуется покрыть то, что
печатают цели `st`/`st-at` и что написано в документе. Сверять список слов с
кодом проекта нечем — он задан чужим стандартом, а не лексером Takt.

## Consequences

### Положительные

- Девять блоков документа получают подсветку; вывод целей выглядит одинаково.
- Новый язык блока обязан объявить, откуда берётся его подсветка, — иначе
  предкоммит красный.
- Класс C3 (файл есть, но не подключён) сторожится отдельно: это самая тихая
  поломка — определение мёртвое, ошибки нет.

### Отрицательные / Action items

- Два файла подсветки на сопровождении; при расширении вывода цели `st` их
  придётся дополнять (гейт этого не заметит — он проверяет объявленность, а не
  полноту).
- Цвет проверяется человеком по рендеру страницы: машине он недоступен.

### Acceptance criteria

1. Блоки `st` и `ebnf` в документе выходят цветными (рендер страницы).
2. Гейт ловит все четыре класса — доказано самопроверкой.
3. **Контроль:** согласованное дерево гейт не роняет.
4. Документ собирается, символы новых файлов проходят гейт шрифта.
5. `./scripts/precheck.sh` — код 0.
