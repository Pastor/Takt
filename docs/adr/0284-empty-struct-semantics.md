# ADR 0284: Структура без полей

- **Status:** Accepted
- **Date:** 2026-08-18
- **Authors:** Архитектор + аналитик + разработчик
- **Related issues:** [Фича 0284](../features/0284-empty-struct-semantics.md); прямой образец — [ADR 0172](0172-empty-enum-semantics.md) (`SE-105`, перечисление без вариантов)

## Context

Правило `StructDefine` использует `Comma<StructField>` («ноль или более»),
поэтому `struct S { }` язык принимает. Карточка сообщала, что цель `c` печатает
расширение GNU, и просила **перед решением замерить остальные цели**.

**Замер 2026-08-18** на `struct Empty { }` с используемой переменной:

| Потребитель | Что происходило |
|---|---|
| эталон | исполняет: переменная получает `Empty{}` |
| `c`, `c-hal` | `typedef struct Empty { } Empty;` — компилируется, но `cc -std=c11 -pedantic` даёт `warning: empty struct is a GNU extension [-Wgnu-empty-struct]` (C11 6.7.2.1 требует непустой список объявлений) |
| `st`, `st-at` | `Empty : STRUCT END_STRUCT;` — **`iec2c` отвергает**: `error: no structure element declared in structure type declaration` |
| `rust` | отказ `RS-014` «значение по умолчанию для типа 'Empty' не строится» |
| `sv`, `sv-mmio` | `empty_t used_e;` — ссылка на **необъявленный** тип; `verilator`: `Can't find typedef/interface: 'empty_t'` |

⚠️ **Контрольный замер отделил причину от следствия.** Непустая структура
`struct Pt { a: u8, b: u8 }` проходит и `cc -std=c11 -pedantic`, и `iec2c`
(POUS.c порождён, ошибок нет). Значит ломается **пустота**, а не структурный тип.

⚠️ **Но тот же контроль сузил объём фичи.** Отказ `RS-014` и висячий тип у `sv`
воспроизводятся и на **непустой** структуре: эти две цели не переводят
структуры **вовсе**. К пустоте они отношения не имеют — это соседний класс
(кандидат «структуры не транслируются целями `st` и `rust` дальше объявления»,
который замер расширяет на `sv`).

⚠️ **Гейт проекта класс не видел по устройству:** он гоняет `cc` **без**
`-pedantic` (там пустая структура законна как расширение), гейт `st` пропускает
файл через `iec2c` только для корпуса, а пустых структур в `examples/` нет ни
одной.

## Decision Drivers

1. **Решение уже принято — для перечисления.** ADR 0172 постановил: у
   перечисления обязан быть хотя бы один вариант, и говорит это **семантика**,
   на объявлении. Структура — та же форма («агрегатное объявление без
   элементов»), и разное отношение к ней есть дефект правила.
2. **Отвечает чужой инструмент, и только под флагом.** Сегодня о пустой
   структуре говорит `cc -pedantic` (которого в гейте нет) и `iec2c` — на
   **порождённом** файле, то есть автор узнаёт о своей ошибке из чужого
   сообщения о чужом языке.
3. **Пустая структура ничего не выражает.** Значения у неё одно, полей нет,
   прочитать нечего: запрет не отнимает выразительности.
4. **Квантификатор грамматики — не место для правила языка** (урок 0172): смена
   `Comma` на `CommaOne` изменила бы язык молча, а текст отказа стал бы
   внутренностью LR-разбора.

## Considered Options

### Option A. Оставить как есть

**Pros:** ноль правок.

**Cons:** порождённый ST **не компилируется**, а C держится на расширении
компилятора. Автор узнаёт об этом от чужого инструмента или не узнаёт вовсе.

### Option B. Сузить грамматику до `CommaOne<StructField>`

**Pros:** одна строка.

**Cons:** правило языка становится свойством квантификатора, а сообщение —
`SY-002` «нераспознанный токен `}`». Ровно то устройство, которое ADR 0172
признал негодным и заменил.

### Option C. Оставить запись законной и научить цели её переводить

**Pros:** язык не сужается.

**Cons:** переводить нечего: в C стандартного представления пустой структуры
нет, в ST — тоже. Пришлось бы подставлять фиктивное поле, то есть печатать не
то, что написал автор.

### Option D. Отказ семантики — `SE-115` на объявлении

**Pros:**
- Ответ одинаков у всех девяти потребителей и приходит **до** генерации.
- Симметрия с `SE-105`: одна форма — одно устройство отказа.
- Текст называет требование и выход, а не пересказывает чужую ошибку.

**Cons:**
- Формально ломающее. ⚠️ Замер: в `examples/` и фикстурах пустых структур нет
  ни одной, ни один тест такую запись не закреплял — предкоммит зелёный без
  правок корпуса.

## Decision

Принимается **Option D**.

1. Структура без полей — ошибка **`SE-115`**, на **объявлении**, накопительно
   (правило 0151: две пустые структуры — две диагностики).
2. Проверка живёт в `semantic/validate/structs.rs`, рядом с прочими правилами о
   структурах.
3. Грамматика **не трогается**: `Comma<StructField>` остаётся, правило языка
   выражает семантика.
4. Коды `SE-105` и `SE-115` остаются **разными**: форма одна, причины разные —
   у перечисления выбирать нечего, у структуры вывод не принимают чужие
   инструменты. Подмена размыла бы обе.

## Consequences

### Положительные

- Порождённый ST перестал быть невалидным на этом классе; C перестал зависеть
  от расширения компилятора.
- Автор получает сообщение на **своём** языке и на своей строке.
- Правило про агрегаты стало симметричным.

### Отрицательные / Action items

- Запись, которую язык принимал, стала ошибкой. Выход назван в тексте.
- ⚠️ **Цели `rust` и `sv` не переводят структуры вовсе** — этой фичей не
  затронуто и ею не лечится: класс шире и вынесен кандидатом (замер расширил
  его на `sv`, где вывод ссылается на необъявленный тип).

### Acceptance criteria

1. `struct S { }` даёт `SE-115` на объявлении, с названным выходом (A1).
2. Две пустые структуры дают две диагностики (A2).
3. Непустая структура остаётся законной (A3).
4. Пустое перечисление по-прежнему судит `SE-105` (A4).
5. `./scripts/precheck.sh` зелён без правок корпуса (A5).
