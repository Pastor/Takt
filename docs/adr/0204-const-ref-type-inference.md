# ADR 0204: Вывод типов не протягивает тип через ссылку константа-константа

- **Status:** Accepted (Option C)
- **Date:** 2026-08-16
- **Authors:** Архитектор
- **Related issues:** [Фича 0204](../features/0204-const-ref-type-inference.md); замер при разработке [0143](../features/0143-after-const-duration.md); смежно с [ADR 0192](0192-const-init-fold.md) (свёртка инициализатора идёт ПОСЛЕ вывода типов), [ADR 0096](0096-fixed-point-native-float.md) (две редакции `VariableNode`)

## Context

Документ обещает вывод типа **из выражения**: «Если у объявления есть
инициализатор, тип можно не указывать — компилятор выведет его из выражения»
(раздел «Типы», подраздел «Вывод типов»). Обещание исполняется только для
литералов.

### Замер 1: что получают объявления сегодня (2026-08-16)

| Запись | Тип сегодня | Ожидаемо |
|---|---|---|
| `const BASE := 2s;` | `Duration` | ✅ |
| `const DWELL := BASE;` | **`Inference`** | `Duration` |
| `const S := 2s + 1s;` | **`Unsupported`** | `Duration` |
| `const Z := 5; const A := Z;` | **`Inference`** у `A` | `[bit;8]` |
| `var a := 5; var b := a;` | **`Inference`** у `b` | `[bit;8]` |
| цепочка `A → B → C` | `Inference` у `B` и `C` | `[bit;8]` |
| `const A: u16 := 5; const B := A;` | `u16` ✅ | работает — у источника **явный** тип |

### Замер 2: причин **две**, и они независимы

**П1 — снимок ячейки.** `ExpressionNode::Variable` несёт
`Rc<RefCell<VariableNode>>`, который `expression::construct_expression` создаёт
как `Rc::new(RefCell::new(var.clone()))` — то есть **копию на момент разрешения
имени**. Разрешение идёт **до** вывода типов (`declaration::prepare_variables`:
разрешить → вывести → свернуть), поэтому в ячейке навсегда остаётся `Inference`.
Обновить ячейку нельзя: копий у переменной столько, сколько упоминаний. Отсюда и
работающий случай «источник с явным типом»: там снимок сделан уже с типом.

**П2 — `wider_type` не знает длительностей.** Правила `(Duration, Duration)` нет
вовсе, поэтому `const S := 2s + 1s;` — **без единой ссылки** — даёт
`Unsupported`. Смешение длительности с числом до этой ветви не доходит: его
отвергает `SE-065` (проба).

⚠️ Числовая арифметика через ссылку (`const B := A + 1;`) работает **случайно**:
`wider_type(Inference, Array(8,Bit))` попадает в правило `(_, Array(n, t))` и
берёт тип **литерала**. То есть «работает» и «выведено верно» здесь — разные
вещи.

### Замер 3: цена — форма не исполняется никем

`var x := 42; var y := x;` — запись, которую фикстура
`takt-lang/tests/data/semantic/valid/ce6_type_inference_chain.takt` объявляет
образцом («тип `y` выводится из переменной `x`; ожидается: типы выведены
корректно»):

| Потребитель | Ответ |
|---|---|
| цель `c` | `CC-015` «тип не представим в C» |
| цель `rust` | `RS-014` «тип `_` не представим» |
| цель `st` | `ST-002` «вывод типов не завершён» |
| цель `sv` | `SV-002` «внутренний либо неразрешённый тип» |
| симулятор | `SIM-007` **в такте**, шаг 1 |

То есть дефект **не** «тип недоопределён, но безвреден» (так его описывал
кандидат): язык принимает программу, а исполнить её не может **ни один** из пяти
потребителей.

⚠️ **Сторож был декоративен.** Тест фикстуры (`semantic_tests/part4.rs`)
проверяет, что файл **разбирается без ошибок**, — и проходил всё это время,
пока обещанный им вывод типа не работал. Класс знаком проекту: тесты на
структуру вместо теста на язык (фикс 0010-01).

### Замер 4: корпус

226 файлов корпуса строят дерево; объявлений без выведенного типа — **одно**, и
это та самая фикстура. То есть исправление не может изменить вывод корпуса.

## Decision Drivers

1. **Обещание документа обязано исполняться.** Раздел «Вывод типов» говорит «из
   выражения», а не «из литерала».
2. **Пять потребителей отказывают на законной записи** — цена измерена, а не
   предположена.
3. **Порядок «разрешить → вывести → свернуть» трогать нельзя** (ADR 0192):
   свёртка раньше вывода даёт `bool` вместо `bit` — значение верное, тип нет.
4. **Ячейка ссылки — снимок, и это неисправимо дёшево**: обновлять пришлось бы
   все копии, а их столько, сколько упоминаний.
5. **Порядок объявлений произволен.** Таблица переменных — `BTreeMap`, то есть
   обход **алфавитный**: `const Z := 5; const A := Z;` требует, чтобы решение
   работало независимо от того, в каком порядке имена попались.

## Considered Options

### Option A. Свернуть инициализаторы до вывода типов

Тогда `const DWELL := BASE;` пришёл бы в вывод уже литералом.

**Pros:** одна перестановка, ноль нового кода.

**Cons:** **прямо отвергнуто ADR 0192** и проверено пробой: `var b: bit := false;
var a := b;` даст `a` тип `bool` вместо `bit`. Порядок трёх шагов — инвариант,
за который проект уже заплатил.

### Option B. Обновлять ячейки после вывода типов

Пройти по выражениям и записать выведенный тип в каждый `Rc<RefCell<…>>`.

**Pros:** ссылка начинает отвечать правду всем потребителям, а не только выводу.

**Cons:** обход **всех** выражений модели ради типа, который потребители и так
берут из таблицы; ячеек у переменной столько, сколько упоминаний — пропущенная
даёт молча разный тип у двух копий одного имени (класс 0096, где ровно это и
случилось). Цена несопоставима с предметом.

### Option C. Спрашивать таблицу объявлений, а не снимок + неподвижная точка

`extract_type` получает необязательную ссылку на таблицу в том состоянии, в
каком её видит вывод; на `Variable` со значением `Inference` тип берётся **по
имени** из таблицы. Проходы повторяются, пока хоть одно объявление получает тип
(число `Inference` строго убывает — завершение по построению). Плюс правило
`(Duration, Duration) → Duration` в `wider_type`.

**Pros:**
- лечит обе причины и не трогает порядок 0192;
- работает при любом порядке имён — цепочка `A → B → C` и обратная
  `Z → A` сходятся одинаково;
- цикл (`const A := B; const B := A;`) не зацикливает: прохода без прогресса
  достаточно для выхода, оба останутся `Inference`;
- внешние вызовы `extract_type` (генераторы, `validate`) не меняются — им
  передаётся `None`.

**Cons:**
- у функции появляется второй вход (`extract_type_known`), и рекурсивные вызовы
  обязаны тащить таблицу — забытый аргумент вернёт прежнее поведение молча;
- вывод перестаёт быть однопроходным (на корпусе — второй проход впустую).

### Option D. Топологический порядок объявлений

Отсортировать объявления по зависимостям инициализаторов и выводить в нём.

**Pros:** один проход.

**Cons:** без Option C бесполезен — снимок ячейки остаётся устаревшим при любом
порядке. То есть это оптимизация поверх C, а не альтернатива.

## Decision

Принимается **Option C**.

- `extract_type_known(expr, model, known)` — тип с оглядкой на таблицу
  объявлений; `extract_type(expr, model)` остаётся тонкой обёрткой с `None` для
  внешних вызовов.
- На `ExpressionNode::Variable` тип берётся из снимка, а если тот `Inference` —
  **по имени из таблицы**.
- `type_inference` крутит проходы до неподвижной точки; понижение `q(m, n)`
  (0061) остаётся на **первом** проходе, чтобы поведение однопроходного случая
  не изменилось.
- `wider_type` получает правило `(Duration, Duration) → Duration`.

**Вне объёма (граница названа):** `wider_type(Integer, Array)` берёт тип
**литерала**, из-за чего `const A: u16 := 300; const B := A + 1;` даёт `[bit;8]`
и **ложную** диагностику `SE-089` («литерал 301 не помещается в `[bit;8]`»).
Механизм другой (не ссылка, а правило расширения), и лечение требует решения о
знаковости и ширине — заведено кандидатом.

## Consequences

### Положительные

- Форма `var y := x;` и цепочки любой длины переводятся всеми целями и
  исполняются эталоном.
- `const S := 2s + 1s;` получает `Duration` — вычислитель выдержки (0143)
  перестаёт быть единственным, кто понимает такую запись.
- Обещание документа исполняется без правки документа.

### Отрицательные / Action items

- **Совместимость:** вывод корпуса обязан остаться байт-в-байт (замер 4 говорит,
  что задет один файл фикстур, и там тип раньше отсутствовал вовсе).
- **Декоративный сторож обязан быть заменён**: тест фикстуры проверяет разбор,
  а не вывод типа. Иначе фича закроется, оставив после себя ту же дыру.
- Диагностика на записи, которая **не** выводится (цикл `A := B; B := A;`),
  остаётся прежней — типа не будет, и о нём скажут цели. Заведение
  специального кода — отдельное решение, здесь не принимается.
- Язык **не меняется**: раздел «Вывод типов» уже обещает это поведение, версия
  языка не поднимается (правило 22). В документ добавляется пример ссылки —
  ровно то, что теперь работает.

### Acceptance criteria

1. `const DWELL := BASE;`, `var b := a;` и цепочка из трёх получают тип
   источника — при любом порядке имён.
2. `const S := 2s + 1s;` получает `Duration`.
3. Форма `var x := 42; var y := x;` переводится целями `c`/`rust`/`st`/`sv` и
   исполняется симулятором.
4. Сторож фикстуры проверяет **тип**, а не факт разбора.
5. Вывод корпуса `examples/generated/` байт-в-байт неизменен.
6. `./scripts/precheck.sh` зелёный.
