# ADR 0135: Квалифицированные имена портов в симуляторе

- **Status:** Accepted
- **Date:** 2026-07-27
- **Authors:** Системный аналитик, архитектор
- **Related issues:** [Фича 0135](../features/0135-sim-qualified-port-names.md)

## Context

Пространство имён значений симулятора было **плоским**. `Unit::get_value`
спускалось по ветвям композиции и возвращало **первое** найденное совпадение,
`set_value` рассылало запись **всем** ветвям. Пока имена под-моделей уникальны,
это незаметно; при совпадении — половина состояния модели становится
недоступной.

Проба (две под-модели с одноимёнными портами, `Left::val = 1`,
`Right::val = 2`): симулятор печатал `out:val=1`. Значение `Right::val`
существовало (в снимке `--save-state` видны обе ветви), но **адресовать его было
нечем**. Симметрично: задать вход отдельной под-модели тоже нечем — голое имя
уходит в обе.

Смежное решение в проекте уже есть: фича [0084](0084-address-map-qualified-key.md)
квалифицировала ключ **карты адресов** (`model_unique::port`) — там тот же дефект
проявлялся потерей адреса. Значения симулятора остались неквалифицированными:
это разные слои, и второй не был исправлен.

В корпусе дефект замаскирован — одноимённых портов у под-моделей нет.

## Decision Drivers

1. **Молчание хуже отказа.** Сегодня модель с одноимёнными портами выглядит
   работающей, хотя часть её состояния не наблюдается и не управляется.
2. **Аддитивность (правило 11).** Голые имена используются везде: сценарии JSON
   (позиционные), `--load-state`, `Unit::variable` в десятках тестов,
   потактовые сверки. Ломать их нельзя.
3. **Одна форма записи на две подсистемы.** Разделитель обязан совпасть с уже
   принятым в карте адресов, иначе пользователю придётся помнить две формы.
4. **Границы объёма.** Формат сценариев (позиционные массивы) — территория фичи
   [0132](../features/0132-sim-named-port-scenarios.md), которая от этой зависит.

## Considered Options

### Option A. Квалифицированное имя + голое как прежде + видимая двусмысленность

`Модель::порт` адресует одну ветвь (чтение и запись). Голое имя работает
по-прежнему. Двусмысленные имена **называются**: предупреждение при запуске и
квалифицированные формы в потактовом выводе.

**Pros:**
- Полностью аддитивно: ни один существующий сценарий, снимок или тест не
  затронут.
- Дефект перестаёт быть молчаливым — пользователь видит и проблему, и способ
  адресовать точно.
- Разделитель `::` совпадает с ключом карты адресов (0084).

**Cons:**
- Голое имя остаётся двусмысленным (первая ветвь при чтении, все — при записи).
  Это осознанный компромисс ради совместимости; двусмысленность теперь видна.

### Option B. Только квалифицированные имена

**Pros:**
- Никакой двусмысленности вовсе.

**Cons:**
- **Ломающее**: позиционные сценарии, снимки состояния, `Unit::variable` во всех
  тестах и потактовых сверках. Цена несоизмерима с задачей.

### Option C. Диагностика вместо чтения при двусмысленности

Голое имя при совпадении — ошибка.

**Pros:**
- Двусмысленность невозможна незаметно.

**Cons:**
- `get_value` возвращает `Option<Value>` и канала для диагностики не имеет;
  вводить его пришлось бы во всём дереве вызовов.
- Ломает те же места, что Option B, только не сразу, а на первой модели с
  совпадением.

## Decision

Принимается **Option A**.

- Узел дерева симуляции получает **имя своей модели** (`UnitKind::Node.model_name`
  из `ModelNode::name`); без него квалифицировать нечем.
- `get_value`/`set_value` распознают форму `Модель::порт` (разделитель `::`, как
  у карты адресов) и адресуют **ровно одну** ветвь; неизвестный квалификатор не
  адресует ничего — опечатка не должна писать «куда-нибудь».
- `PortNames` вычисляет **двусмысленные** имена (объявленные более чем одной
  моделью) и их квалифицированные формы; `takt-sim` печатает предупреждение при
  запуске, а потактовый вывод показывает такие значения квалифицированно.
- Публичный `Unit::set_port` — симметрия к `Unit::variable`: раньше запись
  требовала тащить внутренний трейт `Context` в вызывающий код.

**Вне объёма:** формат сценариев остаётся позиционным (драйв по голому имени
по-прежнему рассылается всем ветвям) — это фича 0132, зависящая от этой.

## Consequences

### Положительные

- Значения одноимённых портов различимы: `Left::val` и `Right::val` читаются и
  пишутся независимо.
- Двусмысленность **видна**: предупреждение называет обе модели и показывает,
  как адресовать точно; потактовый вывод больше не скрывает половину состояния.
- Совместимость полная: сценарии, снимки и тесты на голых именах не тронуты.

### Отрицательные / Action items

- **Голое имя остаётся двусмысленным** при совпадении (первая ветвь / все ветви).
  Устранение — за фичей 0132 (именованные порты в сценариях) и, при
  необходимости, отдельным решением о запрете голого имени.
- **Квалификатор — имя модели, а не путь.** Две под-модели с одинаковым **именем
  модели** в разных ветвях по-прежнему неразличимы; полный путь (`Root::Left::val`)
  не вводится — в языке нет синтаксиса пути, и в карте адресов 0084 принят тот же
  однокомпонентный ключ.
- **Анонимная модель не адресуема квалифицированно** (у неё нет имени) — голое
  имя работает как прежде.

### Acceptance criteria

1. `Модель::порт` читается и пишется, адресуя одну ветвь.
2. Неизвестный квалификатор не пишет ничего и читает `None`.
3. Голое имя ведёт себя как прежде (совместимость).
4. Двусмысленные имена перечисляются и попадают в предупреждение и вывод.
5. Корпус `examples/` предупреждений не даёт (в нём совпадений нет).
6. `./scripts/precheck.sh` зелёный.

> Диаграмма по правилу 18 **не требуется**: язык не меняется — меняется
> адресация значений в инструменте.
