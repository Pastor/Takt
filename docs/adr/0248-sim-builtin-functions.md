# ADR 0248: Встроенные функции min/max/abs/clamp/debug не исполняются эталоном

- **Status:** Accepted
- **Date:** 2026-08-17
- **Authors:** Архитектор + аналитик
- **Related issues:** [Фича 0248](../features/0248-sim-builtin-functions.md);
  находка гейта — [ADR 0217](0217-stub-branch-gate.md);
  правило «семантика вычислений живёт в `eval/`» — [ADR 0025](0025-simulator-expression-eval.md);
  уроки сверок — [ADR 0045](0045-sv-backend.md), [ADR 0050](0050-rust-backend.md)

## Context

Встроенные функции языка объявлены в `takt-lang/src/semantic/builtin.rs`:
`debug`, `S`, `min`, `max`, `abs`, `clamp`. Цели их переводят, **эталон — нет**:
ветвь `FunctionDefinitionNode::Builtin` в `takt-sim/src/unit/statement.rs`
отвечает `SIM-020` «пока не поддерживается» и останавливает прогон.

Найдено гейтом ветвей-заглушек (фича 0217) в первый же его прогон: запись
номера задачи у этой ветви не было вовсе.

### Что показала проба

**1. Расхождение эталона и цели — не теоретическое.** Вход
`m := min(n, 3);`:

| Потребитель | Результат |
|---|---|
| эталон | `ОШИБКА вычисления на шаге 1: встроенная функция 'min' пока не поддерживается симулятором (SIM-020)`, прогон остановлен |
| цель `c` | `model->m = (((model->n) < (3)) ? (model->n) : (3));` — верно |
| цель `rust` | `n.min(3)` |
| цель `sv` | `((a < b) ? a : b)` |

То есть сверить эталон с целью на модели со встроенной функцией **нечем** —
ровно класс, ради которого заведены потактовые сверки (0045, 0050).

**2. Формы перевода у целей совпадают по смыслу и опираются на сравнение.**
Цель `c` (и `sv`) раскрывает `min`/`max`/`abs`/`clamp` тернарником над теми же
операциями сравнения и унарного минуса, что и операторы языка. Проба на `q(8, 8)`:
`r := min(x, y);` → `(((model->x) < (model->y)) ? (model->x) : (model->y))`,
`clamp` → вложенный тернарник. Значит эталону не нужна **своя** арифметика: те
же операции у него уже есть (`eval::ops::apply_binary`/`apply_unary`), причём с
нормировкой q, насыщением и обёрткой (0061, 0127, 0170).

**3. `debug` устроен иначе.** Его аргумент — строковый литерал
(`TypeNode::BuiltinString`), а `Value` симулятора строк **не представляет**
(`ExpressionNode::String` → «строки не поддерживаются»). Значит вычислить
аргумент и передать в общий путь нельзя: `debug` перехватывается **до**
вычисления аргументов. Цели ведут себя по-разному и это уже принято: `rust`
печатает через HAL-метод, `c` вызова не порождает вовсе (решение 0189), `sv`
отказывает `SV-002`.

**4. `S(M)` в позиции выражения не поддержана НИКЕМ:** `c` — `CC-022`,
`rust` — отказ «вне условия `S(Модель) = Состояние`», `sv` — `SV-002`. В
условии её исполняет фича 0245 (паттерн `S(Модель) = Состояние`).

## Decision Drivers

1. **Эталон обязан считать то, что считают цели.** Иначе сверка невозможна, а
   именно она — единственное доказательство, что цель не разошлась со
   спецификацией.
2. **Своей арифметики заводить нельзя.** Правило проекта: семантика вычислений
   живёт только в `takt-sim/src/eval/` (0025). Второй экземпляр правил
   сравнения/минуса разъехался бы с первым — класс, стоивший проекту фиксов
   0061-01 и 0148-01.
3. **Формы обязаны совпадать с целями побитово,** включая q: `min` — выбор по
   `<`, `abs` — унарный минус, у которого уже нормированы перенос и насыщение.
4. **Отказ, который остаётся, обязан назвать причину** и получить держателя в
   реестре заглушек (0217), а не остаться «пока».

## Considered Options

### Option A. Реализовать все шесть встроенных, включая `S` в выражении

**Pros:**
- Ни одной заглушки не остаётся.

**Cons:**
- `S(M)` как **значение** не переводит ни одна цель: эталон стал бы «умнее»
  целей, и сверка на такой модели была бы невозможна в другую сторону
  (симулятор считает, цель отказывает). Это ровно та ошибка, которую проект уже
  разбирал на сравнении структур (0034, драйвер 3).

### Option B. Реализовать `min`/`max`/`abs`/`clamp`/`debug`; `S` в выражении оставить отказом

**Pros:**
- Закрывает измеренное расхождение: все функции, которые цели **считают**,
  считает и эталон.
- `S` остаётся отказом ровно там, где отказывают все цели, — эталон не обгоняет
  их и не отстаёт.
- Отказ для `S` получает причину и держателя (фича 0247, тема состояний).

**Cons:**
- Одна заглушка остаётся — но объявленная, с держателем и названной причиной.

### Option C. Реализовать только `min`/`max`/`abs`/`clamp`, `debug` не трогать

**Pros:**
- Меньше правки: не нужен перехват до вычисления аргументов.

**Cons:**
- `debug` — самая частая отладочная конструкция; модель с ней осталась бы
  неисполнимой в эталоне, то есть непроверяемой сверкой целиком.

## Decision

Принимается **Option B**.

1. `min`, `max`, `abs`, `clamp` вычисляются в `call_function` **через
   существующий слой** `eval::ops`: `min(a, b)` = `if apply_binary(Less, a, b)
   { a } else { b }`, `abs(x)` = `if x < 0 { apply_unary(Minus, x) } else { x }`,
   `clamp(x, lo, hi)` = как у цели `c` — сначала нижняя граница, потом верхняя.
   Своей арифметики не появляется; q, длительности и насыщение работают тем же
   кодом, что и операторы языка.
2. `debug(строка)` перехватывается в вычислителе выражений **до** вычисления
   аргументов (иначе строковый литерал упадёт как «строки не поддерживаются») и
   печатает текст в **stderr** с пометкой такта. Поток выбран так, чтобы не
   смешиваться с трассой прогона в stdout, которую читают сверки.
3. `S(M)` в позиции выражения остаётся отказом, но текст называет причину («вне
   условия `S(Модель) = Состояние`» — как у цели `rust`), а запись реестра
   заглушек переводится на держателя **0247**.
4. Верность доказывается **потактовой сверкой** эталона с целью `c` на модели
   со всеми четырьмя вычислимыми встроенными, включая q-формат, а не фактом
   «симулятор больше не падает».

## Consequences

### Положительные

- Модель со встроенными функциями снова сверяема: эталон считает, цель считает,
  трассы сравниваются.
- Реализация не заводит второго носителя семантики: `min` над `q(8, 8)`
  наследует нормировку от общих операций автоматически.
- `debug` перестаёт делать модель неисполнимой; отладочный вывод виден в
  stderr.

### Отрицательные / Action items

- Одна заглушка (`S` в выражении) остаётся: объявлена в реестре 0217 с
  держателем 0247.
- Поведение `debug` у эталона и целей различается по **побочному эффекту**
  (печать/HAL/ничего) — это принято ещё решением 0189 и на значения переменных
  не влияет; сверка трасс его не видит.
- Диагностика `SIM-020` сохраняет код, но меняет смысл: теперь она о `S`, а не
  о «встроенных вообще».

### Acceptance criteria

1. `min`, `max`, `abs`, `clamp` исполняются эталоном; значения совпадают с
   целью `c` **потактово**, в том числе на `q(m, n)`.
2. `debug("текст")` не останавливает прогон; текст виден в stderr.
3. `S(M)` в выражении отвечает отказом с названной причиной; запись реестра
   заглушек переведена на держателя 0247, гейт 0217 зелёный.
4. Реализация не содержит собственной арифметики: вызовы идут в `eval::ops`.
5. `./scripts/precheck.sh` — код 0; сверка добавлена в набор `conformance`.
