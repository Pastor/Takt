# ADR 0139: Удаление мёртвой конфигурации `.travis.yml`

- **Status:** Accepted
- **Date:** 2026-07-27
- **Authors:** Системный аналитик, лид разработки
- **Related issues:** [Фича 0139](../features/0139-remove-travis-config.md)

## Context

В корне репозитория лежит `.travis.yml`:

```yaml
language: rust
script:
  - rustup component add clippy
  - cargo clippy
  - cargo test --verbose
```

Действующий CI — [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml):
единственный вызов `./scripts/precheck.sh` под строгим режимом
(`PRECHECK_STRICT=1`), где полтора десятка гейтов — компиляция порождённого кода
настоящими инструментами (`cc`/`cmake`, `rustc`+`clippy -D warnings`,
`verilator`+`yosys`, `iec2c`), детерминизм генерации, размер модулей, версия
языка, реестр диагностик. Этот контракт установила фича
[0090](0090-ci-precheck.md), явно устранившая **дрейф**: прежде CI нёс
собственную реализацию гейтов, и она разошлась с локальной.

Travis CI не подключён к репозиторию: прогонов нет, бейджа нет, в документации
файл не упоминается. То есть перед нами **описание другого, более слабого набора
проверок**, которое читатель может принять за действующий контракт — ровно тот
класс вреда, который фича 0090 устраняла.

## Decision Drivers

1. **Один источник истины гейтов** (принцип фичи 0090): любая вторая
   конфигурация проверок — источник дрейфа.
2. **Витрина не должна врать.** Файл в корне читается как часть контракта
   проекта; неисполняемый файл вводит в заблуждение сильнее, чем его отсутствие
   (тот же довод, что для устаревших кандидатов в `FEATURES.md`).

## Considered Options

### Option A. Удалить файл

**Pros:**
- Устраняет второй, более слабый набор проверок.
- Ноль поддержки в дальнейшем.

**Cons:**
- Если Travis когда-нибудь понадобится, конфигурацию придётся писать заново —
  впрочем, из `ci.yml` она выводится за минуты.

### Option B. Оставить, но привести в соответствие с `precheck.sh`

**Pros:**
- Запасной CI на случай отказа GitHub Actions (учитывая, что прогоны Actions
  были заблокированы по биллингу — см. кандидат «Дожать CI-верификацию 0090»).

**Cons:**
- **Два места, где описаны гейты** — ровно то, что фича 0090 признала дефектом
  процесса; разойдутся при первой же правке.
- Travis не подключён: конфигурация всё равно не исполняется, то есть её
  «соответствие» никем не проверяется.

### Option C. Оставить как есть

**Pros:**
- Ничего не делать.

**Cons:**
- Сохраняется ложный контракт: читатель видит `cargo clippy` + `cargo test` и
  делает вывод, что этого достаточно для коммита.

## Decision

Принимается **Option A** — удалить. Аргумент Option B (запасной CI) не
выдерживает проверки: запасной CI, который никем не исполняется и ни с чем не
сверяется, не является запасным. Если понадобится второй провайдер CI, он
должен звать **тот же** `precheck.sh`, а не свой набор команд, — и заводиться
отдельной фичей с проверкой живым прогоном.

## Consequences

### Положительные

- В репозитории остаётся единственное описание гейтов — `scripts/precheck.sh`,
  вызываемый из `ci.yml`.
- Снята ловушка «прочитал `.travis.yml`, решил, что гейты — это clippy и tests».

### Отрицательные / Action items

- Если Actions останутся недоступны (биллинг), вопрос запасного провайдера
  придётся решать заново — **отдельной фичей**, с требованием звать
  `precheck.sh`.

### Acceptance criteria

1. Файла `.travis.yml` в репозитории нет.
2. Упоминаний Travis в `README.md`, `docs/`, `CLAUDE.md` нет (кроме истории в
   `CHANGES.md` и артефактов этой фичи).
3. `./scripts/precheck.sh` зелёный.

> Диаграмма по правилу 18 **не требуется**: ADR не меняет ни синтаксиса, ни
> семантики языка.
