# ADR 0062: Цель `sv-mmio` — адреса портов как регистровый файл

- **Status:** Accepted
- **Date:** 2026-07-17
- **Authors:** Архитектор + Дизайнер языка
- **Related issues:** [Фича 0062](../features/0062-sv-mmio-target.md); исполняет отложенное решение [ADR 0045](./0045-sv-backend.md) (вопрос 5, **Option B вынесен в кандидаты**); вскрыт [фикс 0020-01](../fixes/0020-01-port-bit-out-of-range.md)

## Context

ADR 0045 (вопрос 5) принял **Option A**: цель `sv` адрес **не потребляет** —
«у RTL-модуля процессора нет; спрашивать, по какому адресу лежит `cmd_fork`,
так же бессмысленно, как спрашивать адрес ножки микросхемы». **Option B**
(`sv-mmio`: адрес → регистровый файл на шине) признан **ценным**, но вынесен в
кандидаты с двумя возражениями:

1. «**Требует выбрать шину** (APB? AXI-Lite? Wishbone?) — решение, для которого в
   требованиях нет **никакого** основания. Выбор произволен, а цена ошибки
   высока.»
2. «Резко расширяет объём: шинный автомат, декодер адреса, семантика
   чтения/записи, **тестбенч уровня шины (BFM)**.»

Оба возражения — про **шину**, а не про регистровый файл. Это и есть ключ к
решению (см. Decision).

### Замер: что адреса корпуса говорят о себе (2026-07-17)

| Файл | Адреса | Похоже на |
|---|---|---|
| `stacker.lam` | `0x100`…`0x601`, сгруппированы по назначению (`0x1xx` задание, `0x2xx` позиция, `0x3xx` датчики, `0x4xx` цели, `0x5xx` вилы, `0x6xx` подтверждения) | **готовую карту регистров** — смещения, а не физические адреса |
| `elevator.lam` | `0x10000000`…`0x10000009` | **плоский физический MMIO** (база + смещение) |
| `extend_complex.lam` | `0x44533932`, биты `1`, `2`, **`33`** | одно слово, **три порта, разных направлений** |

То есть корпус пользуется адресами **двумя разными способами**, и цель обязана
работать с обоими.

### Находка проработки: одно слово несёт порты РАЗНЫХ направлений

`extend_complex.lam`: `out IDLE :1`, `out WORK :2`, `in WAIT :33` — **один**
адрес. Для регистрового файла это значит: регистр **не бывает** просто
read-only или write-only — направление принадлежит **биту**, а не слову.
Это ограничение дизайна, а не деталь.

### Находка проработки: бит адреса не проверяется вовсе → [фикс 0020-01](../fixes/0020-01-port-bit-out-of-range.md)

Греп по всему `grammar/src` не находит **ни одной** проверки диапазона бита;
`bit: Option<i64>` допускает и отрицательный. Цель `c-hal` на бите 8…31 читает
**всегда 0** (загружен один байт), на бите ≥ 32 — **UB** (`int >> 33`, C11
6.5.7p3); `cc -Wall` молчит, потому что бит — значение времени выполнения.
Дожило потому, что **`c-hal` не компилируется ни одним гейтом** (в `precheck.sh`
она только в гейте **детерминизма**).

**Следствие для 0062:** язык **не выражает ширину адресуемого слова** — есть
только адрес и бит. Пока это не решено, `sv-mmio` не может знать, какой ширины
регистр порождать для `0x44533932:33`.

## Decision Drivers

1. **Произвольный выбор нельзя маскировать под архитектуру.** Возражение ADR 0045
   верно: основания выбрать APB/AXI-Lite/Wishbone в требованиях **нет**.
2. **Ценность — в карте регистров, а не в шине.** Адреса `stacker` уже **являются**
   картой регистров; шина — способ до них дотянуться.
3. **Проверяемость.** Тестбенч уровня шины (BFM) — половина объёма Option B и
   источник ошибок, не относящихся к Lam.
4. **Две половины одной шины.** Ценность, названная ADR 0045: один адрес значит
   одно и то же для `c-hal` (сторона процессора) и `sv-mmio` (сторона периферии).
   Она достижима **без** выбора протокола.

## Considered Options

### Option A. Выбрать APB (или AXI-Lite, или Wishbone) и породить готовый шинный блок

**Pros:**
- «Воткнул и работает» на конкретной платформе.

**Cons:**
- **Ровно то, что запретил ADR 0045** (драйвер 1): выбор произволен. AXI-Lite —
  экосистема AMD/Xilinx; APB — ARM; Wishbone — открытые ядра. Требований нет →
  выбор был бы вкусовым, а зафиксировался бы в выводе компилятора.
- Тянет BFM в тест-план (драйвер 3).
- Выбрав неверно, платим дважды: второй протокол придётся добавлять рядом.

### Option B. Шинно-агностичный регистровый файл; адаптеры — отдельные фичи

Модуль получает **простой синхронный регистровый интерфейс** (адрес, данные
записи, данные чтения, строб записи/чтения) — без протокола. Адаптер
APB/AXI-Lite/Wishbone пишется поверх (обычно десятки строк) и заводится
**отдельной фичей, когда появится требование**.

**Pros:**
- **Снимает оба возражения ADR 0045**: выбирать шину не нужно (драйвер 1); BFM не
  нужен — регистровый интерфейс дёргается в тестбенче напрямую (драйвер 3).
- Даёт **всю** содержательную ценность: карта регистров из `.lam`, «две половины
  одной шины» (драйверы 2, 4).
- Адаптер — тонкий шим, и он **платформенный**, то есть ему и место снаружи.
- Объём соразмерен: декодер + регистры, без шинного автомата.

**Cons:**
- Не «готовый блок»: интеграция требует шим. Смягчение: шим тривиален и всё равно
  платформенно-зависим.
- Появляется свой интерфейс — его форму надо задать (правило 3 ниже).

### Option C. Атрибуты/комментарии с адресами в выводе `sv`

**Pros:** дёшево.

**Cons:** ADR 0045 уже отверг это для 0045 («комментарий с претензией»; создаёт
**ложное впечатление**, что адрес учтён). Довод не изменился.

### Option D. Не делать (статус-кво)

**Pros:** ноль работы; `-t sv` честно игнорирует адрес.

**Cons:** отложенное решение 0045 остаётся отложенным; адреса модели для
аппаратной цели — мёртвые метаданные.

## Decision

Принимается **Option B** — **шинно-агностичный регистровый файл**.

Возражения ADR 0045 против Option B оба относятся к **шине**, а не к
регистровому файлу; убрав протокол из объёма, мы снимаем оба и сохраняем всю
ценность. Выбор протокола — **требование**, и его должен принести заказчик, а не
угадать архитектор; до тех пор компилятор не обязан вставать на чью-то сторону.

**Нормативные правила:**

1. **Новая цель** `-t sv-mmio`, парная к `sv` — как `c-hal` парная к `c`
   (прецедент 0020-05, на который прямо ссылается ADR 0045). Цель `sv`
   **не меняется**: адрес по-прежнему не потребляет.
2. **Порты с адресом** становятся битами регистров; порты **без** адреса остаются
   портами модуля. Смешение допустимо.
3. **Интерфейс** (форма — задача 0062-01): адрес, данные записи, данные чтения,
   стробы; синхронный, без протокола; ширина адреса выводится из **максимального**
   адреса модели.
4. **Направление принадлежит биту, а не слову** (находка выше): регистр может
   нести и читаемые, и записываемые биты. Бит `in` — записывается шиной, читается
   автоматом; бит `out` — пишется автоматом, читается шиной.
5. **Запись в бит `out` со стороны шины игнорируется**; чтение бита `in` шиной
   возвращает записанное. Иное — конфликт драйверов.
6. **Ширина регистра** берётся из решения по [фиксу 0020-01](../fixes/0020-01-port-bit-out-of-range.md).
   ⚠️ Пока фикс не закрыт, `sv-mmio` **обязана отказать** (диагностика) на бите вне
   поддержанного диапазона — **не угадывать**. Угадать ширину — значит повторить
   ошибку, за которую ADR 0045 отверг fixed-point (см. [0061](./0061-fixed-point-type.md)).
7. **`--address-map` работает** с `-t sv-mmio` — то есть проверку
   `bin/lamc.rs:532` (сегодня пропускает внешнюю карту только для `c-hal`)
   придётся расширить. Это **единственная** правка вне новой цели.
8. **Язык не меняется** → версия не растёт (правило 22).

## Consequences

### Положительные

- Адреса модели становятся осмысленными для аппаратной цели; «две половины одной
  шины» (`c-hal` + `sv-mmio`) — замыкание фичи 0020.
- Выбор протокола **отложен до появления требования**, а не принят вслепую.
- Тестируется без BFM.

### Отрицательные / Action items

- **A-1. Зависимость от фикса 0020-01** (правило 6). Пока ширина адресуемого слова
  языком не выражена, `sv-mmio` не знает, что такое `0x44533932:33`. Фича обязана
  **отказывать**, а не угадывать. Это делает 0020-01 **блокирующим** для полного
  объёма (частичный — только биты 0…7 — возможен, но бессмыслен: `extend_complex`
  корпуса им не покрывается).
- **A-2. Адаптеры шин — отдельные фичи** (APB / AXI-Lite / Wishbone), каждая по
  требованию. Кандидат.
- **A-3. Сверка обязательна и заводится вместе с целью** (уроки 0045/0050). У
  `sv` дефект «`always_comb` читает регистр вместо `_next`» приняли **оба**
  инструмента. Наблюдение для `sv-mmio` берётся **со стороны шины** (чтение
  регистра), а не иерархической ссылкой: именно так его видит потребитель.
- **A-4. `c-hal` не компилируется гейтом** — кандидат; без этого «две половины
  одной шины» проверяются только с одной стороны.

### Acceptance criteria

1. **A1.** `-t sv-mmio` порождает модуль с регистровым интерфейсом; `stacker.lam`
   (17 адресов, `0x100`…`0x601`) даёт карту регистров, совпадающую с адресами
   модели.
2. **A2.** Модуль **синтезируется**: гейт **обоими** инструментами (verilator
   **и** yosys — ловят непересекающиеся классы, проверено 4 раза при 0045).
3. **A3.** Цель `sv` **не изменилась**: вывод `examples/generated/sv` побайтово
   прежний (опора — детерминизм закрытой [0048](./0048-deterministic-codegen.md)).
4. **A4.** Потактовая сверка: трасса `sv-mmio` (наблюдение **через регистры**) =
   трасса симулятора на каждом такте.
5. **A5.** Слово со **смешанными** направлениями (`extend_complex`: `out :1`,
   `out :2`, `in :33`) обрабатывается по правилам 4–5 либо **отвергается**
   диагностикой (пока 0020-01 не закрыт) — но **не угадывается**.
6. **A6.** Запись шиной в бит `out` игнорируется; чтение бита `in` возвращает
   записанное.
7. **A7.** Порт **без** адреса остаётся портом модуля (правило 2).
8. **A8.** `--address-map` принимается целью `sv-mmio` (правило 7); приоритет
   источников адреса — прежний (inline < `address` < карта), фича 0020 не тронута.
9. **A9.** Язык не изменился; версия не поднята.
