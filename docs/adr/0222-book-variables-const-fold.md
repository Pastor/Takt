# ADR 0222: Раздел документа не отражает свёртку инициализатора

- **Status:** Accepted
- **Date:** 2026-08-17
- **Authors:** Архитектор + Системный аналитик
- **Related issues:** [Фича 0222](../features/0222-book-variables-const-fold.md);
  свёртка — [0192](../features/0192-const-init-fold.md); нормировка вычисленного —
  [0207](../features/0207-bitwise-not-unsigned-literal.md); диагностика ссылки
  вперёд — [0246](../features/0246-init-forward-reference.md).

## Context

Фича 0192 сделала инициализатор объявления **вычисляемым при сборке** и ввела
правило «имя в инициализаторе значит начальное значение и ссылается только
назад по тексту». Документ об этом молчал: раздел «Типы данных» описывал лишь
вывод типа из инициализатора.

Часть предмета всё же описана — фича 0207 добавила в раздел «Выражения и
условия» абзац о **нормировке вычисленного** значения (`~0` даёт 255 при `u8`)
против литерала автора (`SE-089`). Значит недостающее — именно **свёртка**:
что значение известно до запуска, что имя даёт начальное значение и что
порядок объявлений значим.

**Проба при взятии фичи вскрыла дефект** (2026-08-17): ссылка **вперёд**
принималась молча и давала `0` у эталона против `1` в прошивке. Описывать
правило, которое инструменты не соблюдают, нельзя, поэтому диагностику завела
отдельная фича [0246](../features/0246-init-forward-reference.md) (решение
заказчика: «сначала диагностика, потом документ»).

## Decision Drivers

1. **Документ обязан описывать язык, каким он есть.** Свёртка меняет
   наблюдаемое поведение объявления — читатель обязан о ней знать.
2. **Правило 25.** Подробности нормировки уже живут в «Выражениях»; дублировать
   их в «Типах» нельзя — только сослаться.
3. **Правило 27(д).** Числа в разделе обязаны браться из прогона, а не из
   рассуждения.
4. **Соразмерность.** Предмет — свойство объявления; заводить ради него новый
   раздел (правило 24 — отдельная фича) несоразмерно.

## Considered Options

### Option A. Подраздел в «Типах данных» рядом с «Выводом типов»

**Pros:**
- предмет — свойство **объявления**, а объявления и вывод типа описаны там же;
- читатель встречает правило в том месте, где узнаёт про инициализатор;
- ссылка на «Выражения» покрывает нормировку без дублирования (правило 25).

**Cons:**
- раздел «Типы данных» и без того велик.

### Option B. Дописать в раздел «Выражения и условия»

**Pros:**
- там уже описана нормировка вычисленного — предмет рядом.

**Cons:**
- «Выражения» описывают **формы записи**, а свёртка — свойство объявления;
- правило «ссылка только назад» касается порядка **объявлений**, о котором
  раздел выражений не говорит вовсе.

### Option C. Новый раздел «Объявления»

**Pros:**
- предмет виден в оглавлении.

**Cons:**
- правило 24: новый раздел — отдельная фича с полным циклом;
- объявления описаны по частям в «Типах», «Моделях» и «Портах» — перенос их в
  новый раздел выходит далеко за объём этой фичи.

## Decision

Принимается **Option A**.

Состав правки:

1. Подраздел **«Инициализатор вычисляется при сборке»** в
   `book/src/03-types/index.typ` после «Вывода типов»: значение известно до
   запуска; имя значит **начальное** значение (пример со снимком переменной,
   которая позже растёт); ссылка только **назад** по тексту, иначе `SE-109`;
   у констант порядок не важен; невычислимое (порт, `extern`) остаётся как
   есть; нормировка — ссылкой на «Выражения» (правило 25).
2. Блок «Частые ошибки» раздела дополняется `SE-109`.
3. Все числа примеров берутся из прогона симулятора.

## Consequences

### Положительные

- Поведение, которым автор пользуется в каждом объявлении, описано.
- Правило «только назад» получает в документе то же звучание, что в
  компиляторе, — и подкреплено кодом диагностики.

### Отрицательные / Action items

1. Раздел «Типы данных» растёт примерно на полстраницы.
2. Примеры подраздела — инлайн-блоки, а не отдельный файл: они иллюстрируют
   **правило**, а не устройство, и гейт примеров (0133) их не прогоняет.
   Числа проверены прогоном при разработке и приведены в отчёте.

### Acceptance criteria

1. Подраздел существует, описывает: вычисление при сборке, «имя = начальное
   значение», «ссылка только назад» с `SE-109`, порядок у констант,
   невычислимые инициализаторы.
2. Нормировка не дублируется — стоит ссылка на «Выражения».
3. «Частые ошибки» дополнены `SE-109`.
4. Все числа примеров подтверждены прогоном.
5. `./scripts/precheck.sh` зелёный.
