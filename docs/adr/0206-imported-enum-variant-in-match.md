# ADR 0206: Вариант импортированного перечисления не разрешается в образце match

- **Status:** Accepted (Option B — дефект вылечен ранее, фича закрывается сторожем)
- **Date:** 2026-08-16
- **Authors:** Архитектор
- **Related issues:** [Фича 0206](../features/0206-imported-enum-variant-in-match.md); находка фикса [0186-01](../fixes/0186-01-example-decomposition.md); вылечено фиксом [0182-03](../fixes/0182-03-imported-type-definition.md)

## Context

Карточка описывала дефект: `import { Op } from "lib.takt";`, затем
`match v { Lda => … }` → `SE-003` «идентификатор не найден», тогда как условие
`ref Done: v = Hlt;` в том же файле тот же вариант разрешает.

### Замер 1: сегодня дефект НЕ воспроизводится (2026-08-16)

Вход — библиотека с `enum Op { Lda, Hlt }` и применение с `match` по её
вариантам:

| Проверка | Результат |
|---|---|
| `import {Op} from "library.takt"` + `match` | **компилируется** |
| `import "library.takt"` (целым файлом) + `match` | **компилируется** |
| транзитивный импорт (`app → mid → lib`) | **компилируется** |
| порождённый C | `case 0:` и `case 1:` — варианты разошлись по номерам |
| эталон (симулятор) | выбирает ветвь по варианту; трасса `1, 2, 2` |
| цели `rust`, `st`, `plantuml` | транслируют |
| цель `sv` | `SV-002` — **`match` не транслируется вовсе**, независимо от импорта (проверено на локальном перечислении) |

### Замер 2: чем вылечено — установлено запуском, а не догадкой

Тот же вход прогнан на состоянии репозитория **до** фикса
[0182-03](../fixes/0182-03-imported-type-definition.md) (`git worktree` на
`c5dc70db~1`):

```text
app.takt:3:14: Ошибка компиляции [SE-003]: Идентификатор 'Lda' не найден в области видимости
```

То есть класс закрыл фикс 0182-03 («импорт переносит **устройство** типа, а не
имя»): имя перечисления лежит в карте `types`, а его варианты — в `enums`, и
переносилось прежде только первое.

⚠️ **Асимметрия, записанная в карточке, на этом входе не воспроизводится.** На
состоянии до фикса падают **обе** формы — и `match`, и условие ребра, причём
раньше них падает само объявление `var v: Op;` (`SE-034` «Локальный тип не
найден»). Исходная проба 0186-01 имела другую раскладку файлов, восстановить её
дословно нечем; вывод «путь образца смотрит мимо импортированных объявлений»
следует считать **неподтверждённым**.

### Замер 3: покрытия у класса нет

- В `examples/` перечисления **не пересекают** границу импорта — гейты корпуса
  класс не трогают.
- Тест фикса 0182-03 (`import_type_definition_tests.rs`) проверяет
  импортированное перечисление только в **инициализаторе объявления**
  (`var m: Mode := Auto;`) и только по наличию имени в заголовке.
- Путь **образца `match`** не проверяет никто.

## Decision Drivers

1. **Чинить нечего** — дефект вылечен (замеры 1–2).
2. **Но и закрыть молча нельзя:** вылеченный класс не имеет ни одного сторожа
   (замер 3), а корпус его не покрывает. Регресс вернулся бы незамеченным — ровно
   так класс и дожил до 0182-03.
3. **Отмена — решение заказчика** (правило 17); аналитик вправе лишь предложить.
   Предлагать её здесь нечего: работа по фиче есть, она просто иная.
4. **Сторож обязан проверять номера вариантов и трассу**, а не факт компиляции:
   вариант, разрешённый не в тот номер, компилируется и исполняется — молча
   выбирая чужую ветвь.

## Considered Options

### Option A. Отмена (`ОТМЕНА`): дефект вылечен другой фичей

**Pros:** формально честно — предмет фичи исчез.

**Cons:** оставляет класс **без сторожа**. Карточка сама указывает, что корпус
его не покрывает; отмена закрепила бы это положение. К тому же отмена —
решение заказчика, а не аналитика.

### Option B. Закрыть фичу сторожем

Фича меняет не код, а **покрытие**: пара тестов пришпиливает путь образца
`match` по импортированному варианту — со стороны цели (номера ветвей в
порождённом C) и со стороны эталона (трасса значений), плюс контр-пример на
несуществующий вариант.

**Pros:**
- Класс перестаёт быть невидимым: регресс упадёт тестом, а не всплывёт в
  примере через месяц.
- Мутация проверяема: сторож прогнан на состоянии до 0182-03 — краснеет.
- Стоимость мала, а корпус трогать не нужно.

**Cons:**
- Фича закрывается без единой правки кода — по журналу выглядит «пустой», если
  не прочесть отчёт.

### Option C. Завести перечисление через границу импорта в корпус `examples/`

**Pros:** класс попал бы под все гейты сразу.

**Cons:** корпус — набор **примеров языка**, а не полигон; пример заводится
ради демонстрации конструкции, и добавлять его ради покрытия значит смешивать
роли (правило 27 требует от примера функциональной осмысленности). Дешёвый и
точный ответ — тест, а не пример.

## Decision

Принимается **Option B**: кода фича не меняет, класс закрывается **сторожем**.

- `takt-lang/tests/import_enum_match_tests.rs` — сторона цели: обе формы импорта
  (выборочная и целым файлом), номера ветвей в порождённом C, условие ребра на
  том же варианте, контр-пример «несуществующий вариант отвергнут».
- `takt-sim/tests/import_enum_match_tests.rs` + фикстуры `tests/data/eval/` —
  сторона эталона: трасса `seen` = `1, 2, 2`, то есть ветвь выбрана **по
  варианту**, а не наугад.

В карточке фиксируется: дефект вылечен фиксом 0182-03, что доказано прогоном на
состоянии до него; асимметрия «условие работает, образец нет» —
**неподтверждена**.

## Consequences

### Положительные

- Путь «перечисление пересекает границу импорта → образец `match`» получает
  сторожа с обеих сторон (цель и эталон).
- Мутация выполнена буквально: сторож прогнан на дефектном состоянии и краснеет
  всеми четырьмя проверками.

### Отрицательные / Action items

- ⚠️ Контр-пример на дефектном состоянии падает **по другой причине** (там нет и
  самого типа) — как свидетельство мутации он слабее прочих; это названо в
  отчёте.
- Цель `sv` `match` не транслирует вовсе — ограничение цели, к импорту
  отношения не имеющее; в объём фичи не входит.

### Acceptance criteria

1. Обе формы импорта дают в порождённом C **разные** номера ветвей.
2. Эталон выбирает ветвь по варианту (трасса значений).
3. Несуществующий вариант по-прежнему отвергается с именем в тексте.
4. Сторож краснеет на состоянии до фикса 0182-03.
5. `./scripts/precheck.sh` зелёный.
