# ADR 0147: Тесты textDocument/documentSymbol

- **Status:** Accepted
- **Date:** 2026-07-29
- **Authors:** Архитектор + Аналитик
- **Related issues:** [Фича 0147](../features/0147-lsp-document-symbol-tests.md); замер покрытия — [0138](../features/0138-coverage-measurement.md); смежно с [ADR 0178](0178-editor-layer-language-sync.md) (редакторский слой)

## Context

`document_symbol_provider` **объявлен** клиенту в `ServerCapabilities`, то есть
редактор шлёт запрос при каждом открытии файла. Тестов на него не было ни
одного: замер покрытия (фича 0138, 2026-07-27) дал по
`takt-lang/src/lsp/symbols.rs` **0 %** при 183 строках, и ноль перепроверен
грепом — артефактом учёта он не был.

Класс — «объявленный контракт без единого свидетеля». Отвечает сервер вслепую:
любая правка обхода АСД меняет панель структуры у пользователя, и узнать об этом
проекту неоткуда.

⚠️ Уточнение к постановке: покрытие требуется не ради процента, а потому что
`documentSymbol` — единственная возможность LSP, чей ответ **структурен**
(дерево, диапазоны, виды символов). Ошибка в нём не даёт ни отказа, ни
диагностики — панель просто показывает не то.

## Decision Drivers

1. **Проверять надо три разных свойства.** Состав (что стало символом),
   вложенность (дерево, а не плоский список) и диапазоны (`selection_range` —
   имя). Ломаются они независимо, и тест на одно не ловит два других.
2. **Ожидания снимаются зондом, а не выводятся из кода.** Правило проекта:
   позиции, номера строк и виды символов не угадывать.
3. **Тесты не должны пришпиливать дефекты.** Если зонд показал неверное
   поведение, сперва правится код, потом пишется тест, — иначе набор
   консервирует ошибку (урок 0181: два теста требовали лишнего такта).

## Considered Options

### Option A. Один файл тестов на все три свойства, ожидания с зонда

**Pros:**
- контракт `documentSymbol` описан в одном месте и читается целиком;
- зондовые ожидания невозможно «подогнать»: они сняты с фактического вывода.

**Cons:**
- пиннинг состава (`syms.len()`) требует правки теста при добавлении вида
  символа — но это и есть замысел: состав панели меняться молча не должен.

### Option B. Только snapshot-тест (сравнение с эталонным деревом целиком)

**Pros:**
- дёшево написать, ловит любое изменение.

**Cons:**
- **не объясняет, что сломалось**: дифф дерева на 20 узлов не отличает
  «перепутан вид символа» от «сдвинулся диапазон»;
- snapshot принимают обновлением файла, то есть регресс чинится нажатием
  кнопки — сторож перестаёт быть сторожем.

### Option C. Юнит-тесты внутри `symbols.rs`

**Pros:**
- ближе к коду.

**Cons:**
- модуль уже 183 строки и растёт; тесты LSP в проекте живут отдельными файлами
  под `#[cfg(feature = "lsp")]` (образцы — `lsp_references_tests`,
  `lsp_rename_tests`), и расхождение с этим порядком ничем не оправдано.

## Decision

Принимается **Option A**: `takt-lang/tests/lsp/lsp_document_symbol_tests.rs`, три
группы проверок (состав, вложенность, диапазоны) плюс границы (неразбираемый
вход, объявленность возможности).

### Два дефекта, найденных зондом, исправлены — не пришпилены

Зонд по файлу со всеми видами объявлений показал, что ветвь
`ModelElement::Struct` выбивается из общего правила **дважды**:

1. **`selection_range` указывал на всё объявление**, а не на имя. У всех прочих
   символов — на имя. По `selection_range` редактор переходит из панели
   структуры, то есть переход к структуре выделял её целиком;
2. **`def.name.clone().unwrap()`** вместо пропуска безымянного элемента, как во
   всех соседних ветвях. `IdentifierOrError` кладёт `None`, когда имя не
   разобралось, — то есть это паника сервера прямо во время набора текста.

⚠️ Второй путь **сегодня недостижим**: при ошибке разбора `parse` возвращает
`Err`, и `document_symbols` выходит раньше (проверено четырьмя формами
испорченного входа). Но недостижимость обеспечена **парсером**, а не этим
модулем, и открытая фича
[0152](../features/0152-semantic-recovery-element-boundary.md) (восстановление
на границе элемента) ровно это свойство и меняет. Оставлять мину, зная про фичу,
которая её взведёт, — хуже, чем снять её одной строкой.

Обе правки — приведение ветви к поведению **соседних**, а не новая логика.

### Что сознательно НЕ взято в объём

Инвариант **состояния** (`invariant Sane = …;` внутри `state`) символом не
становится, тогда как инвариант **модели** становится. Это асимметрия, но её
исправление — изменение **состава** панели структуры, то есть вопрос к
аналитику, а не побочная правка тестовой фичи. Текущее поведение **пришпилено
тестом с явным комментарием**, чтобы его изменение было осознанным; разбор
записан находкой в `FEATURES.md`.

## Consequences

### Положительные

- объявленный контракт получает свидетелей: 13 тестов на состав, вложенность,
  диапазоны и границы;
- две ветви-исключения в `symbols.rs` приведены к общему правилу;
- взведённость набора доказана мутациями (см. критерии).

### Отрицательные / Action items

- пиннинг состава (`syms.len()`) придётся править при добавлении нового вида
  символа. Это замысел, а не издержка: состав панели структуры не должен
  меняться молча;
- ⚠️ тесты идут под `#[cfg(feature = "lsp")]` — обычная `cargo test` их **не
  видит**. Гоняет `cargo test --all-features` в `precheck.sh` (фича 0178).

### Acceptance criteria

1. Каждое именованное объявление верхнего уровня становится символом своего вида.
2. Вложенность: под-модель → элементы, состояние → блоки, перечисление →
   варианты, структура → поля.
3. `selection_range` покрывает имя и содержится внутри `range`; `range`
   начинается с ключевого слова объявления.
4. Неразбираемый вход даёт пустой список, а не панику.
5. Набор **взведён** — доказано мутациями `symbols.rs`.
6. `./scripts/precheck.sh` зелёный.
