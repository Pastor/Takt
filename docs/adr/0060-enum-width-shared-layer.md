# ADR 0060: Диапазон и знак перечисления — один расчёт на все цели

- **Status:** Accepted
- **Date:** 2026-07-17
- **Authors:** Архитектор + Лид разработки
- **Related issues:** [Фича 0060](../features/0060-enum-width-shared-layer.md); вскрыт [фикс 0005-01](../fixes/0005-01-c-enum-signedness.md) (Tier 1, молчаливо неверный вывод цели `c`)

## Context

Кандидат заявлял: «верный расчёт — по диапазону значений — сегодня реализован в
каждом бэкенде отдельно (`rust_type::enum_repr`, `sv_type::enum_width`); вынести в
`semantic/`, чтобы четвёртый бэкенд не наступил на то же».

**Проработка уточнила заявку дважды, и оба уточнения меняют решение.**

### Уточнение 1: копий не две, а четыре

| Цель | Функция | Что возвращает | Знак |
|---|---|---|---|
| `c` | `get_c_type`, ветка `Enum` (`c/mod.rs:218`) | `uint{8,16,32,64}_t` | **не проверяет вовсе** |
| `st` | `st_type::enum_type` + `variants_range` | `SINT`/`USINT`/… через `integer_type(bits, signed)` | `min < 0` |
| `rust` | `rust_type::enum_repr` | `"u8"`/`"i16"`/… | `any(v < 0)` |
| `sv` | `sv_type::enum_width` | `(биты, знак)` — **точная** ширина | `any(v < 0)` |

Четыре независимых извлечения диапазона (`variants.iter().map(…).min()/max()`) —
проверено грепом.

### Уточнение 2: «четвёртый бэкенд наступит на то же» — уже наступил, и это **первый**

Цель `c` **теряет знак молча**. Проба на `enum Level { Low = -5, Mid = 0, High = 5 }`:
C даёт `uint8_t lv;` и `model->lv = -5;`, а условие `if (model->lv == -5)`
**тождественно ложно** — проверено живым `cc`: `lv = 251`, `(lv == -5) = 0`.
**Автомат, верный в симуляторе и в трёх других целях, в C молча стоит.** Подробности
и критерии — [фикс 0005-01](../fixes/0005-01-c-enum-signedness.md).

То есть дублирование — не «долг на будущее», а **действующий дефект Tier 1** в
**эталонной** цели.

### Уточнение 3: цели задают РАЗНЫЕ вопросы

Общей «ширины перечисления» не существует:

- `sv` нужна **точная** ширина (`670` → **10** бит);
- `rust`/`st`/`c` нужна **машинная** ширина из {8,16,32,64} (`670` → 16);
- `rust` нужно **имя типа** (`i16`), `st` — своё (`INT`), `c` — своё (`int16_t`).

Значит выносить надо **не «ширину»**, а **факт**: диапазон и знак. Отображение
факта в тип цели обязано остаться в цели.

### Расхождение, которое уже есть (пустое перечисление)

| Цель | `enum E { }` |
|---|---|
| `c` | `uint8_t` (`unwrap_or_default`) |
| `st` | `USINT` (`unwrap_or(0)`) |
| `rust` | `u8` (`unwrap_or(0)`) |
| `sv` | **`SV-004`** (ошибка) |

Один вход — четыре ответа, из них три молчат.

## Decision Drivers

1. **Тихо неверный вывод — худший класс дефекта** (Tier 1). Правило проекта:
   ошибаться в сторону **громкого** отказа. Сейчас C ошибается тихо.
2. **Эталон обязан быть эталоном.** `CLAUDE.md` объявляет `Enum` доверенным при
   сверке с C — проба это опровергает.
3. **Дублирование — механизм расхождения, а не стиль.** Четыре копии уже дали
   четыре ответа на пустое перечисление и два — на знак.
4. **Не всё общее.** Отображение «диапазон → тип цели» **target-специфично** и
   должно остаться в цели: слияние его в общий слой породило бы `match` по целям в
   `semantic/` — то есть ту же связность, только централизованную.

## Considered Options

### Option A. Общий слой считает ФАКТ (диапазон + знак + минимальная ширина); цели отображают

`semantic/` получает описание перечисления: `min`, `max`, `signed`, минимальная
ширина в битах; `sv` берёт ширину напрямую, `rust`/`st`/`c` округляют до машинной
и печатают своё имя типа.

**Pros:**
- Убивает все четыре извлечения диапазона — источник расхождений (драйвер 3).
- **Чинит 0005-01 как следствие**: C, спросив общий слой про знак, не может его
  потерять (драйверы 1, 2).
- Оставляет в цели ровно то, что целевое (драйвер 4).
- Диапазон — свойство **семантического узла** `EnumNode`, а не цели: место
  естественное.

**Cons:**
- Требует миграции **четырёх** целей за раз, иначе смысла нет.
- Поведение цели `c` меняется (это и есть фикс) — нужна новая сверка.

### Option B. Вынести целиком «ширину», включая имя типа

**Pros:**
- Ещё меньше кода в целях.

**Cons:**
- Общий слой начнёт знать про `uint8_t`/`USINT`/`u8`/`logic [9:0]` — то есть про
  все цели сразу (нарушен драйвер 4). Каждая новая цель правила бы `semantic/`.

### Option C. Оставить как есть; чинить только C

**Pros:**
- Минимальная правка; фикс 0005-01 закрывается.

**Cons:**
- Четыре копии остаются (драйвер 3) — расхождение на пустом перечислении живёт,
  пятая цель повторит путь. Кандидат заведён ровно против этого.

### Option D. Общий слой + унифицировать пустое перечисление в диагностику

**Pros:**
- Снимает и четвёртое расхождение.

**Cons:**
- Меняет поведение `c`/`st`/`rust` (сегодня молча `u8`) — это **вопрос семантики
  языка** («допустимо ли `enum E { }`»), а не кодогенерации. Решать его в ADR про
  вынос расчёта — превышение полномочий (прецедент: 0029 сознательно не решала
  семантику `[bit;N]`).

## Decision

Принимается **Option A**.

Общий слой считает **факт** (диапазон, знак, минимальную ширину), цели —
**отображение**. Фикс [0005-01](../fixes/0005-01-c-enum-signedness.md) закрывается
**в объёме этой фичи**: миграция цели `c` на общий расчёт делает знак верным как
**следствие**, а не отдельной заплатой. Прецедент такого совмещения —
[0056](./0056-lsp-goto-exact-file.md), закрывшая попутно фикс 0053-01.

Option D отклонена как выход за полномочия: пустое перечисление — вопрос
**семантики**, выносится кандидатом. Общий слой обязан вернуть «пусто» честно
(`Option`), а каждая цель сохраняет **сегодняшнее** поведение — чтобы 0060 не
протащила незаявленного изменения.

**Нормативные правила:**

1. Общий слой живёт в `semantic/` рядом с `EnumNode` и **не знает ни одной цели**
   (никаких `uint8_t`/`USINT`/`u8`).
2. Он отдаёт: `min`, `max`, `signed = min < 0`, `min_bits` (точная ширина; для
   знакового — дополнительный код).
3. Пустое перечисление → **`None`**; трактовку выбирает цель, и она **остаётся
   сегодняшней** (`c`/`st`/`rust` — 8 бит без знака, `sv` — `SV-004`).
4. Отображение «факт → имя типа цели» остаётся **в цели**.
5. Извлечений диапазона (`variants.iter()…min()/max()`) в `generator/` не остаётся
   **ни одного**.

**Язык не меняется** → версия не растёт (правило 22). Изменение поведения цели `c`
— это **исправление** (фикс 0005-01), а не смена контракта: сегодняшнее поведение
не является контрактом, оно является дефектом.

## Consequences

### Положительные

- Тихий Tier 1 в эталонной цели устранён.
- Расчёт один; пятая цель получает его готовым.
- Расхождение на пустом перечислении становится **видимым** (зафиксировано, а не
  размазано по четырём файлам).

### Отрицательные / Action items

- **A-1. Нужна сверка на отрицательном перечислении.** Гейт `c` (cmake+ninja, без
  `-Werror`) дефект **принимает**: `cc` даёт лишь предупреждение
  `-Wtautological-constant-out-of-range-compare`. Правило (уроки 0045/0050):
  **сверку заводить вместе с правкой**. `conformance_c_tests` пополняется моделью
  с отрицательным перечислением.
- **A-2. Поправить `CLAUDE.md`.** Там записано «сверка — только
  `Integer`/`Enum`/`Bool`», то есть `Enum` объявлен доверенным. Проба опровергает:
  доверять можно лишь **неотрицательным**. Формулировка правится вместе с фиксом —
  иначе следующий читатель снова поверит.
- **A-3. Корпус не докажет фикс.** Ни одно перечисление корпуса не имеет
  отрицательных вариантов, поэтому вывод корпуса обязан остаться **побайтово
  прежним**, а фикс доказывается **новой фикстурой**. Это делает A2 (неизменность
  корпуса) сильным сторожем «рефакторинг не задел ничего лишнего».
- **A-4. Пустое перечисление — кандидат.** Вопрос семантики (`enum E { }` —
  ошибка или `u8`?) выносится, а не решается здесь.
- **A-5. Гейт `c` без `-Werror`** — отдельная находка: сторож существует, но
  выключен. Кандидат.

### Acceptance criteria

1. **A1.** `enum Level { Low = -5, … }` → цель `c` даёт **`int8_t`**; переход
   `ref Done: lv = Low;` **срабатывает** (сегодня — никогда).
2. **A2.** Вывод **всех** целей на корпусе — **побайтово прежний** (в корпусе нет
   отрицательных перечислений; опора — детерминизм закрытой
   [0048](./0048-deterministic-codegen.md)).
3. **A3.** Потактовая сверка `conformance_c_tests` на **новой** модели с
   отрицательным перечислением — зелёная.
4. **A4.** `grep` по `generator/`: извлечений диапазона вариантов
   (`variants.iter()…min()/max()`) — **ноль**.
5. **A5.** Общий слой не содержит ни одного имени типа цели
   (`grep "uint\|USINT\|u8\|logic"` по новому модулю — пусто).
6. **A6.** Поведение на **пустом** перечислении у каждой цели — **как сегодня**
   (`c`/`st`/`rust` → 8 бит без знака; `sv` → `SV-004`).
7. **A7.** Сохранены известные факты: `670` → `rust` `u16`, `st` `UINT`, `c`
   `uint16_t`, `sv` **10 бит** (тесты `enum_repr_670_is_u16_not_u8`,
   `enum_width_670_needs_ten_bits_not_one` — зелёные).
8. **A8.** `cc` не выдаёт `-Wtautological-constant-out-of-range-compare` на
   порождённом коде фикстуры.
9. **A9.** Гейты всех целей (`c`, `st`/`iec2c`, `rust`, `sv`) — зелёные.
