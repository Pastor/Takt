# ADR 0209: Внешний интерфейс модели — extern fn в симуляторе и агрегат как аргумент

- **Status:** Accepted (стенд из сценария — решение заказчика 2026-08-16)
- **Date:** 2026-08-16
- **Authors:** Архитектор
- **Related issues:** [Фича 0209](../features/0209-model-external-interface.md); находка фикса [0186-01](../fixes/0186-01-example-decomposition.md); смежно с [ADR 0185](0185-model-parameters.md) (параметры моделей), [0134](0134-language-time-model.md) (время ставит `runner`)

## Context

Фича состоит из **двух независимых** частей; проба (2026-08-16) подтвердила обе.

### Замер 1: `extern fn` со значением останавливает прогон

| Форма | Цель `c` | Эталон |
|---|---|---|
| `extern fn led(on: bit);` (без возврата) | колбэк HAL | **исполняется** (пустое действие) |
| `extern fn mem_read(addr: u8) -> u8;` | колбэк HAL | **`SIM-019` в такте**, прогон остановлен |

Следствие названо в карточке: модель с внешним интерфейсом **непроверяема
эталоном** — сверка поведения невозможна, а примеры документа (их гейт
исполняет) такой формы содержать не могут.

### Замер 2: агрегат как аргумент параметра не вычислялся

`Memory(prog := {9, 8, 7, 6})` → `SE-083`: общий константный вычислитель
агрегат не сворачивал. То есть «программа как аргумент» не выражалась.

⚠️ **Снятие отказа обнажило неготовность цели `c`** (проба после правки):
она печатала `model->main.prog = {9, 8, 7, 6};` — не выражение, а инициализатор
объявления, и `cc` отвечал «expected expression». Дефект был **недостижим**,
пока семантика отвергала форму раньше. Цель `rust` ту же форму печатала верно
(`self.main.prog = [9, 8, 7, 6];`, `rustc` принял), цели `st` и `sv` отвечают
своими отказами (`ST-017`, `SV-002`).

## Decision Drivers

1. **Эталон обязан быть проверяемым.** Всё, что цель `c` умеет, эталон должен
   уметь прогнать — иначе сверок поведения не существует.
2. **Молчаливое умолчание недопустимо.** Ноль вместо значения внешней функции
   означал бы зелёный прогон при расхождении эталона и прошивки — тот самый
   класс, ради которого заведены потактовые сверки.
3. **Вход прогона уже есть.** Сценарий подаёт значения входных портов по тактам;
   внешняя функция — тот же вход, только вызываемый.
4. **Агрегат — значение сборки.** Параметр задаётся при инстанцировании, и
   значение его аргумента обязано доезжать до целей литералом (образец 0185).

## Considered Options (часть 1: откуда брать значения `extern fn`)

### Option A. Из сценария, таблицей по аргументу — **принято**

Секция `extern` в шаге: одно значение на такт (`"mem_read": 42`) либо таблица по
первому аргументу (`"mem_read": {"0": 9, "1": 8}`).

**Pros:**
- значения приходят оттуда же, откуда входы портов, — новых входов инструмента
  не заводится;
- «память» описывается естественно: адрес → содержимое;
- умолчания нет: не задали — прежний отказ `SIM-019`.

**Cons:**
- таблица ищет по **первому** аргументу; вызов без аргументов таблицей не
  покрывается (для него есть форма «одно значение») — названная граница.

### Option B. Тело-заглушка на языке Takt

Отдельный файл-дубль с телами тех же функций, подключаемый флагом.

**Pros:** заглушка может считать, а не только отдавать таблицу.

**Cons:** новый вход инструмента, своё разрешение имён и вопрос «что если
заглушка разошлась с прошивкой» — работа, несопоставимая с предметом.

### Option C. Значение по умолчанию + предупреждение

**Cons:** прямо противоречит драйверу 2: эталон считал бы ноль, прошивка —
настоящее значение, и сверка трасс была бы зелёной.

### Option D. Оставить отказ

**Cons:** оставляет модель с внешним интерфейсом непроверяемой — то есть не
решает предмет фичи.

## Decision

**Часть 1** — Option A (решение заказчика 2026-08-16): стенд задаётся сценарием.
Значения ставятся перед тактом тем же приёмом, что и модельное время
(`set_time_ns`), и живут **шагом**, а не прогоном.

**Часть 2** — агрегат вычисляется общим константным вычислителем
(`ConstValue::List`) и печатается целями:
- `c` — **поэлементно** (`p.prog[0] = 9;`), потому что агрегат в C не
  присваивается;
- `rust` — как есть (уже работало);
- `st`/`sv` — прежние отказы `ST-017`/`SV-002`: границы названы, а не молчат.

## Consequences

### Положительные

- Модель с внешним интерфейсом становится **проверяемой эталоном**: сверка
  поведения и примеры документа с `extern fn` возможны.
- «Программа как аргумент» выражается: `Memory(prog := {9, 8, 7, 6})`.
- Формат сценария расширен **аддитивно**: поле необязательно, старые сценарии
  читаются без правки.

### Отрицательные / Action items

- Таблица ищет по **первому** аргументу — для функций с несколькими значащими
  аргументами этого мало; названо границей, расширение — отдельная фича.
- Цели `st` и `sv` агрегатный аргумент не печатают; отказы пришпилены тестом,
  чтобы «научится» не прошло молча.
- ⚠️ Стенд обязан доезжать **до всех областей видимости**: тело блока и тело
  функции исполняются в своих контекстах, а такт — с `Unit` в роли контекста.
  Пропусти одну — подмена молча не сработает (так и случилось при первой сборке).

### Acceptance criteria

1. Таблица по аргументу кормит последовательные чтения разными значениями.
2. Форма «одно значение» отвечает на любой вызов такта.
3. Без стенда — прежний отказ `SIM-019` (контр-пример).
4. Стенд принадлежит **шагу**, а не прогону (контр-пример).
5. Нечисловой ключ таблицы — ошибка сценария с именем функции.
6. Агрегат в аргументе вычисляется; эталон видит заданные значения.
7. Цель `c` печатает агрегат поэлементно, и `cc` принимает вывод.
8. Неконстантный элемент агрегата по-прежнему отвергается.
9. `./scripts/precheck.sh` зелёный, вывод корпуса неизменен.
