# ADR 0225: Модуль semantic/statement.rs — 999 строк при пределе 1000

- **Status:** Accepted
- **Date:** 2026-08-17
- **Authors:** Архитектор + аналитик
- **Related issues:** [Фича 0225](../features/0225-statement-module-size.md);
  правило размера — [ADR 0027](0027-module-size-split.md), приём деления —
  [ADR 0088](0088-module-size-remaining.md), образец выноса тестов —
  [ADR 0129](0129-semantic-deep-nesting.md)

## Context

Правило проекта: модуль — не больше ~1000 строк вместе с тестами
(`docs/CODE.md`), сторож — `scripts/check-module-size.sh` (храповик: новый
нарушитель, рост записи долга, незакрытая запись и запись на несуществующий файл
дают отказ). Кандидат, из которого заведена фича, записал: «`statement.rs` — 999
строк при пределе ~1000… следующая правка модуля **обязана** начинаться с
разделения, иначе гейт её отвергнет».

### Что показала проба (замер кандидата перепроверен)

**1. Числа устарели.** Сегодня файл — **976** строк, не 999. История размера
(`git show <коммит>:./takt-lang/src/semantic/statement.rs | wc -l`):

| Коммит | Фича | Строк |
|---|---|---|
| `04f09cc2` | 0129 | 977 |
| `3d11a2a0` | 0155 | **999** ← замер кандидата |
| `584647c5` | 0185 | 971 |
| `de185cbd` | 0189 | 976 |
| `7d2174e0` | 0243 | 976 |

**2. Утверждение «следующая правка будет отвергнута» опровергнуто историей.**
После замера модуль правили **трижды** (0185, 0189, 0243), разделения не
делали, и гейт ни разу не отказал: запас в 24 строки есть, а две из трёх правок
файл даже сократили. То есть проблема не «гейт блокирует работу», а «запаса
мало» — риск, а не отказ.

**3. Файл не самый близкий к пределу.** Замер по всем модулям и тестам
(`wc -l`, порог 950):

| Строк | Файл |
|---|---|
| 998 | `takt-lang/src/generator/sv/sv_fsm.rs` |
| 994 | `takt-sim/tests/conformance/conformance_st_tests.rs` |
| 994 | `takt-lang/src/generator/sv/sv_expr.rs` |
| 994 | `takt-lang/src/generator/c/c_header.rs` |
| 981 | `takt-sim/tests/conformance/conformance_c_tests.rs` |
| 976 | `takt-lang/tests/semantic/semantic_tests.rs` |
| **976** | **`takt-lang/src/semantic/statement.rs`** |
| 974 | `takt-lang/src/generator/rust/rust_model.rs` |
| 973 | `takt-sim/tests/conformance/conformance_sv_tests.rs` |

`statement.rs` — седьмой, а не первый: класс «модуль вплотную к пределу» шире
одного файла (девять записей ≥ 970). Реестр долга при этом содержит **три**
файла, и `statement.rs` в нём справедливо нет.

**4. Естественный шов виден сразу.** Состав файла:

| Строки | Что |
|---|---|
| 1–58 | док-шапка модуля и `use` |
| 59–90 | `resolve_statement` |
| 91–316 | `resolve_ast_statement` |
| 317–377 | область видимости локальных (`register_local_var`, `unregister_local_vars`) |
| **378–976** | **`#[cfg(test)] mod tests`** — 599 строк, **61 %** файла |

То есть шесть из десяти строк модуля — тесты. Приём выноса в проекте уже есть и
проверен: фича 0129 так поступила с `semantic/expression.rs` (директория
`expression/` = `mod.rs` + `tests.rs`), приём деления описан ADR 0088
(«директория-подмодуль + `use super::*`»).

## Decision Drivers

1. **Работа делается по замеру, а не по записи кандидата.** Запись отстала:
   и в числах, и в выводе о блокировке.
2. **Запас важнее разовой правки.** Модуль ядра семантики правят регулярно
   (три фичи за три недели); 24 строки запаса означают, что четвёртая правка
   начнётся с рефакторинга под давлением, а это худшее время для него.
3. **Приём деления уже выбран проектом** (ADR 0088/0129) — заводить второй
   способ для той же задачи не нужно.
4. **Поведение обязано остаться прежним.** Это рефакторинг: ни одной
   диагностики, ни одного узла, ни одной ветви не меняется.

## Considered Options

### Option A. Вынести тесты в `semantic/statement/tests.rs`

**Pros:**
- Снимает 599 строк из 976 → модуль ≈ 378 строк, запас более чем двукратный.
- Ровно тот приём, которым проект уже решал ту же задачу (0129 для
  `expression.rs`), — читателю не нужно узнавать новую раскладку.
- Риск минимален: `mod tests` переезжает целиком, `use super::*` сохраняет
  видимость приватных функций.

**Cons:**
- Логика самого модуля не становится меньше: `resolve_ast_statement` (226
  строк) остаётся как есть.

### Option B. Разделить логику по видам операторов (`statement/{control,decl,…}.rs`)

**Pros:**
- Уменьшает и код, не только тесты.

**Cons:**
- `resolve_ast_statement` — **один** `match` по `ast::Statement`; разрезание
  его по файлам разносит ветви одного разбора, а исчерпывающий `match` — это
  ровно то, чем проект защищает язык от пропущенных узлов (правило
  `wildcard_enum_match_arm`). Читаемость упадёт, выгода — 226 строк.
- Больше правки → больше риск регресса в ядре семантики ради задачи «дать
  запас», которую полностью решает A.

### Option C. Ничего не делать (закрыть фичу отменой)

**Pros:**
- Ноль работы; запас в 24 строки формально есть, гейт зелёный.

**Cons:**
- Запас исчезает от одной средней правки: 0155 добавила к файлу 22 строки.
- Рефакторинг под давлением («правка не проходит гейт — срочно делим») — тот
  самый случай, ради которого храповик и заведён.

### Option D. A + предупреждение гейта о приближении к лимиту («жёлтая зона»)

**Pros:**
- Класс виден заранее у всех девяти файлов, а не в момент отказа.

**Cons:**
- Это **другая** задача (правка сторожа и его политики), у неё свои решения:
  где порог, ронять ли предкоммит, как не превратить предупреждение в шум.
  Смешивать её с рефакторингом одного модуля — расширять объём фичи.

## Decision

Принимается **Option A**: `takt-lang/src/semantic/statement.rs` превращается в
директорию `takt-lang/src/semantic/statement/` с `mod.rs` (логика) и `tests.rs`
(вынесенный `mod tests`), по образцу `semantic/expression/`.

Логика (`resolve_ast_statement` и соседи) **не переписывается** — Option B
отвергнут: он разносит ветви одного исчерпывающего `match` по файлам.

Предложение D (предупреждение о приближении к лимиту) выносится **кандидатом** в
`FEATURES.md`: замер этой фичи показал девять файлов в зоне ≥ 970 строк, то есть
предмет реальный, но самостоятельный.

## Consequences

### Положительные

- Модуль ядра семантики получает двукратный запас; следующая правка не начнётся
  с вынужденного рефакторинга.
- Раскладка совпадает с `semantic/expression/` — один приём на две одинаковые
  задачи.
- Замер кандидата заменён верным: и число, и вывод «гейт отвергнет правку».

### Отрицательные / Action items

- Пути `include_str!`/относительные ссылки внутри перенесённых тестов, если бы
  они были, сместились бы на уровень (в этом файле их нет — проверено).
- Остальные восемь файлов зоны ≥ 970 строк фича не трогает; класс вынесен
  кандидатом.

### Acceptance criteria

1. `takt-lang/src/semantic/statement.rs` больше нет; есть
   `semantic/statement/mod.rs` и `semantic/statement/tests.rs`.
2. Оба файла — заметно ниже лимита (`wc -l`), в реестр долга ничего не
   добавлено.
3. `scripts/check-module-size.sh` зелёный.
4. Состав и число тестов не изменились: те же имена тестов проходят.
5. `./scripts/precheck.sh` — код 0 (в том числе `clippy -D warnings` и все
   3000+ тестов).
6. Поведение компилятора неизменно: `examples/generated/` после прогона чист.
