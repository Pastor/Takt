# ADR 0174: Цель rust: корневая модель без портов (clippy::new_without_default)

- **Status:** Accepted
- **Date:** 2026-07-29
- **Authors:** Архитектор + Аналитик
- **Related issues:** [Фича 0174](../features/0174-rust-new-without-default.md); наследует [ADR 0050](0050-rust-backend.md) (политика линтов R9); класс тот же, что у [0026](0026-c-root-typedef.md)

## Context

Корневая модель, которой транзитивно не нужен HAL, даёт
`pub fn new() -> Self` **без аргументов**. Линт `clippy::new_without_default`
на такой конструктор ругается, а гейт цели `rust` в `precheck.sh` гоняет
`clippy -D warnings` — то есть на подобном входе он **красный**. Следствие шире
гейта: пользователь со своей политикой `-D warnings` не собрал бы порождённый
код вовсе.

Проба 2026-07-29 (модель `var n: u8; model Counter { … } start Main = Counter;`):

```
error: you should consider adding a `Default` implementation for `Noports`
  --> noports.rs:97:5
   | pub fn new() -> Self {
   = note: `-D clippy::new-without-default` implied by `-D warnings`
```

⚠️ `rustc` при этом **молчит** — синтаксис и типы верны. Дефект видит только
clippy.

### Почему корпус слеп

Карточка фичи предполагала причину «у каждого примера есть порты». Замер её
**уточнил**: у `comprehensive.takt` портов **ноль**, и гейт всё равно зелёный —
пример зовёт `extern fn`, поэтому получает `new(hal: H)`, аргумент у
конструктора есть и линт молчит.

Настоящий признак — предикат `needs_hal` (транзитивный по портам **и**
`extern fn`). Слепым корпус делает то, что **ни один** пример не обходится разом
без портов и без `extern fn`. Контрольный замер: перегенерация всего корпуса
после правки даёт **пустой дифф** — то есть исправление ни одного примера не
касается, и без отдельного сторожа регресс вернулся бы незамеченным.

## Decision Drivers

1. **Гейт обязан быть зелёным на простейшем входе.** Модель без ввода-вывода —
   самый простой класс моделей, и именно на нём цель отказывает.
2. **Политика линтов R9 фичи 0050: «не эмитить то, на что линт ругается».**
   Точечные `#[allow]` глушат сторожа: заглушив линт, мы спрячем и будущие его
   срабатывания.
3. **Правка не должна касаться корпуса.** Порождённый код существующих примеров
   обязан остаться байт-в-байт прежним — иначе фича вышла бы за свои границы.
4. **Сторож обязателен.** Без него корпус остаётся слеп, и дефект вернётся с
   первой же правкой генератора.

## Considered Options

### Option A. Эмитить `impl Default` рядом с `new()` без аргументов

**Pros:**
- ровно то, что предлагает сам clippy, и идиоматичный Rust: тип, строящийся без
  параметров, обязан быть `Default`;
- **аддитивно**: добавляется новый элемент вывода, существующий не меняется;
- условие эмиссии буквально совпадает с условием срабатывания линта
  (конструктор публичен и без аргументов), поэтому «разъехаться» им негде.

**Cons:**
- нужен точный предикат: при `new(hal: H)` печатать `Default` **нельзя** —
  значение `H` взять неоткуда, вывод не скомпилируется. То есть ошибка в условии
  ломает весь корпус, а не молчит.

### Option B. Сделать `new()` приватным

**Pros:**
- линт срабатывает только на публичных конструкторах — замолчит.

**Cons:**
- **уничтожает публичный API**: модель станет непостроимой снаружи крейта, то
  есть порождённый модуль перестанет быть пригодным для использования;
- лечит симптом (видимость), а не причину.

### Option C. `#[allow(clippy::new_without_default)]` у конструктора

**Pros:**
- одна строка.

**Cons:**
- прямо противоречит политике R9 фичи 0050: атрибут глушит сторожа навсегда,
  включая будущие, ещё не появившиеся срабатывания;
- переносит проблему на пользователя: он получает код с чужим `allow` в своём
  крейте.

## Decision

Принимается **Option A**.

Условие эмиссии — `is_root && !uses_hal`, то есть буквально то же, при котором
срабатывает линт: конструктор **публичен** (публичен только корневой) и
аргументов не имеет (аргумент появляется ровно тогда, когда модели транзитивно
нужен HAL).

### Сторож: фикстура, а не корпусный пример

Карточка предлагала завести **корпусный пример** без портов. Отвергнуто:

- модель без единого порта и без `extern fn` — **замкнутая система**, ничего не
  наблюдающая и ни на что не влияющая. В `examples/` такой файл был бы
  документацией (правила 15, 16) о том, как писать бесполезную модель;
- сторож ставится там же, где стоят прочие сторожа порождённого кода, — в
  тестах на **фикстурах** (прецедент: `conformance_rust_tests` собирает
  порождённый Rust настоящим `rustc` на своих фикстурах, а не на корпусе).

Сторож — **двухслойный**, и оба слоя нужны:

1. **эмиссия** — быстрый текстовый тест: `impl Default` есть при конструкторе
   без аргументов и **отсутствует** при `new(hal: H)`;
2. **гейт** — тот же `clippy -D warnings`, что в `precheck.sh`, применённый к
   фикстуре. Первый слой ловит регресс дёшево и точно, второй доказывает, что
   ловится **настоящее** правило линта, а не наше представление о нём.

## Consequences

### Положительные

- цель `rust` перестаёт отказывать на простейшем классе моделей;
- порождённый модуль получает идиоматичный `Default` — польза, а не заглушка;
- корпус впервые получает сторожа на класс «модель без HAL».

### Отрицательные / Action items

- ⚠️ предикат `uses_hal` становится **условием компилируемости** вывода в ещё
  одном месте: ошибка в нём теперь ломает не только `-D warnings`, но и сборку
  (`Default` при `new(hal: H)` не скомпилируется). Это цена Option A, и она
  покрыта контрпримером в тестах;
- обоснование «порт нужен цели `rust`» в комментариях `regulator.takt`,
  `float_regulator.takt` и `pid_regulator.takt` **устарело**. Правка их
  комментариев в объём не берётся: она косметическая и тронула бы три файла
  корпуса ради одной фразы — записано находкой в `FEATURES.md`.

### Acceptance criteria

1. Модель без портов и без `extern fn` даёт `impl Default` рядом с `new()`.
2. Модель с портом (или `extern fn`) `impl Default` **не** получает.
3. Порождённый модуль первой модели принимается `clippy -D warnings`.
4. `examples/generated/rust/**` не изменился.
5. Оба слоя сторожа **взведены** — доказано мутацией генератора.
6. `./scripts/precheck.sh` зелёный.
