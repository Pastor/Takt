# ADR 0223: Три примера объясняют выходной порт устаревшей нуждой цели rust

- **Status:** Accepted
- **Date:** 2026-08-17
- **Authors:** Архитектор + аналитик
- **Related issues:** [Фича 0223](../features/0223-examples-port-rationale-stale.md);
  повод находки — [ADR 0174](0174-rust-new-without-default.md) (цель `rust` даёт
  `impl Default` модели без портов)

## Context

Примеры корпуса `examples/` объясняют свои конструкции комментариями: пример —
это не только вход гейтов, но и **учебный текст**, который читают и по которому
пишут следующие примеры. Комментарий, объясняющий конструкцию **неверной**
причиной, хуже отсутствующего: следующий автор либо воспроизведёт причину в
новом примере, либо снимет конструкцию, поверив, что нужды в ней больше нет.

Четыре примера объясняют свой выходной порт `ready` нуждой цели `rust`:

```
// Выходной порт `ready` нужен и цели `rust` (модель без портов →
// clippy::new_without_default).
```

После фичи [0174](../features/0174-rust-new-without-default.md) модель без
портов получает `impl Default` рядом с `new()`, и линт молчит — то есть порт по
названной причине больше не нужен. Объяснение устарело.

### Что показала проба (замер кандидата перепроверен)

Карточка фичи требует перепроверки замера кандидата (урок 0195). Проба
2026-08-17, `taktc` из рабочего дерева:

| Пример | `impl Default` в выводе `-t rust` без порта | `clippy-driver -D warnings` |
|---|---|---|
| `regulator` | есть | принял |
| `float_regulator` | есть | принял |
| `pid_regulator` | есть | принял |
| `batch_cycle` | есть | принял |

Контр-проба (мутация вывода — блок `impl Default` вырезан вручную):
`error: you should consider adding a Default implementation for RegulatorNoport`.
То есть проба содержательна: линт на этом входе жив, и молчит он **именно
благодаря** 0174.

**Замер кандидата занижен: файлов ЧЕТЫРЕ, а не три.** Кандидат (2026-07-29)
называет `regulator.takt`, `float_regulator.takt`, `pid_regulator.takt`;
`batch_cycle.takt` несёт то же объяснение в собственной формулировке
(«Выходной порт `ready` нужен ещё и цели `rust`: модель без портов даёт
`clippy::new_without_default`») и потому под греп кандидата не попал. История
объясняет, как так вышло: `batch_cycle` заведён фичей 0166 в коммите `92c3379c`
(2026-07-29 15:30), а 0174 закрыта коммитом `728100a2` того же дня в 15:51 —
четвёртая копия объяснения написана **по образцу трёх старших за двадцать минут
до того, как объяснение перестало быть верным**. Это тот же класс, что «четвёртая
копия `report` заведётся по образцу трёх» (0168): устаревшая формулировка в
корпусе воспроизводится, пока её не снимут.

### Чем порт удерживается на самом деле

Порты снимать не предлагается — но, чтобы назвать причину, её надо знать.
Проверено чтением гейтов и тестбенчей:

| Пример | Что держит порт `ready` сегодня |
|---|---|
| `regulator` | тестбенч SV (`saw_ready`, `$error` при отсутствии) **и** гейт `sv-mmio`: это единственный пример со всеми **выходными** портами (фича 0214) |
| `pid_regulator` | тестбенч SV (`saw_ready`) |
| `batch_cycle` | тестбенч SV (`saw_ready` + порядок фаз) |
| `float_regulator` | **ничем не удерживается**: в `SV_TRANSLATABLE` его нет (без `--float-as-q` цель `sv` отвечает `SV-003`, а `FLOAT_AS_Q_EXAMPLES` содержит только `pid_regulator`), тестбенча у него нет, контракт сценария проверяет цепочку состояний, а не порт |

## Decision Drivers

1. **Комментарий примера — учебный текст.** Неверная причина воспроизводится
   следующим примером (что и произошло с `batch_cycle` через двадцать минут
   после закрытия 0174).
2. **Причина обязана быть проверяемой.** Названная причина должна либо
   опираться на живой гейт, либо честно сообщать, что гейта нет, — иначе она
   устареет так же молча, как нынешняя.
3. **Ни одного порта не снимать.** У трёх примеров на `ready` смотрят
   тестбенчи SV; снятие уронило бы гейт.
4. **Цена правки нулевая для поведения.** Меняются только комментарии; вывод
   всех целей обязан остаться байт-в-байт прежним.

## Considered Options

### Option A. Просто удалить устаревшую фразу

**Pros:**
- Минимальная правка; неверного утверждения в корпусе не остаётся.

**Cons:**
- Порт остаётся **без объяснения вовсе**, и следующий редактор вправе счесть
  его лишним — а у трёх примеров на нём висит тестбенч SV. Отсутствующая
  причина здесь опаснее устаревшей: она приглашает снять порт.

### Option B. Заменить фактической причиной (по каждому примеру своей)

**Pros:**
- Комментарий снова объясняет то, что есть: у трёх примеров — тестбенч SV
  (у `regulator` дополнительно гейт `sv-mmio` фичи 0214), у `float_regulator` —
  честное «гейтом не удерживается, стоит ради паритета с `regulator.takt`».
- Причина у трёх из четырёх **проверяется исполнением**: тестбенч завершается
  `$error`, если `ready` не поднялся, — устареть молча она не может.
- Правка захватывает **все четыре** файла, а не три названных кандидатом.

**Cons:**
- Причины разные, общей формулировки нет — текст в каждом файле свой.

### Option C. Option B + греп-сторож «в корпусе нет `new_without_default`»

**Pros:**
- Формулировка не вернётся третьим заходом.

**Cons:**
- Сторож проверяет **отсутствие строки**, а не верность объяснений: класс
  («комментарий примера отстал от кода») он не покрывает и создаёт ложное
  чувство защиты. Замер: в корпусе это единственная строка такого рода, то есть
  сторож охраняет запись, которой после правки не будет ни одной.
- Пример, которому линт **действительно** понадобится упомянуть (скажем,
  разбор политики `-D warnings`), уронил бы гейт без вины.

## Decision

Принимается **Option B**. В каждом из **четырёх** файлов устаревшая фраза
заменяется фактической причиной существования порта `ready`; у
`float_regulator.takt` причина называется честно — гейтом порт не удерживается.
Порты и любой порождаемый код не трогаются.

Греп-сторож (Option C) отвергнут: он сторожит строку, а не свойство. Причина
верности комментария у трёх примеров и так исполняется гейтом SV — тестбенч
падает `$error`, если `ready` не поднялся; это лучший сторож, чем греп по тексту.

## Consequences

### Положительные

- Корпус перестаёт обещать нужду, которой нет, и перестаёт быть образцом для
  пятой копии объяснения.
- Причина порта названа там, где её ищут, — рядом с портом.
- Снят кандидат блока 2 `FEATURES.md` (правило 28).

### Отрицательные / Action items

- Комментарий `float_regulator.takt` называет **отсутствие** гейта; если пример
  когда-нибудь войдёт в `FLOAT_AS_Q_EXAMPLES`/`SV_TRANSLATABLE`, запись
  придётся обновить. Это свойство честной формулировки, а не её дефект.
- Правка косметическая — **машинного** сторожа у неё нет и не заводится
  (см. Option C). Актуальность комментариев корпуса остаётся на ревью
  (правило 4).

### Acceptance criteria

1. Строки `new_without_default` в `examples/` не остаётся ни одной
   (`grep -rn new_without_default examples/` пуст).
2. Каждый из четырёх примеров называет причину порта `ready`, соответствующую
   проверенной таблице «чем порт удерживается на самом деле».
3. Вывод всех целей по корпусу **не изменился**: `git status` по
   `examples/generated/` чист после прогона `precheck.sh`.
4. `./scripts/precheck.sh` зелёный (в том числе гейты `sv`, `sv-mmio`, `rust` и
   канон `taktc fmt` по `examples/`).
