# ADR 0371: Приведение q из поля структуры масштабируется

- **Status:** Accepted
- **Date:** 2026-08-21
- **Authors:** Архитектор + лид разработки
- **Related issues:** [Фича 0371](../features/0371-fixed-cast-from-field.md);
  связь с [ADR 0061](0061-fixed-point-type.md) (правила q),
  [ADR 0349](0349-duration-field.md) (тип операнда знает поле — у цели `st`),
  [ADR 0370](0370-struct-field-fixed.md) (понижение литерала в полях)

## Context

Масштабирование при приведении `q → целое` цель применяет, **только когда
знает**, что тип операнда — `q(m, n)`. Вывод этого типа у каждой цели свой:
`c` зовёт семантический `extract_type`, `rust` и `sv` — собственные
`expression_type`/`fixed_format`, `st` — `inner_expr_type`.

Ни один из них не выводил тип **поля структуры**: `extract_type` отвечал на
`BitAccess` `Unsupported`, у `rust` поле давало `None` (граница названа фичей
0341), у `sv` ветви поля не было вовсе, а `st` знал поле только в
`inner_expr_type_in` (0349) — и та функция в q-пути не звалась.

## Decision Drivers

1. **Молчаливое расхождение значений — самый дорогой класс.** Здесь оно у
   четырёх целей сразу.
2. **Тип поля объявлен рядом** — догадываться не о чем.
3. **Правила округления не трогаются:** носитель прежний (0061), правится
   только вывод типа операнда.

## Considered Options

### Option A. Научить типу поля семантический `extract_type` и вывод каждой цели

**Pros:**
- Цель `c` чинится сразу (она зовёт семантику).
- У остальных правка сводится к «спросить тип с оглядкой на модель», а
  объявления структур у них уже есть (`Scope.model` у `rust`,
  `Scope.structs` у `sv`, `ModelNode` у `st`).

**Cons:**
- Правка в четырёх местах плюс семантика.

### Option B. Только семантика

**Pros:** одно место.

**Cons:** `rust`, `sv` и `st` семантический вывод не зовут — правка их не
починит. Проверено прогоном.

### Option C. Отказ целей на приведении из поля

**Pros:** громче молчания.

**Cons:** запись исполняет эталон и переводят все цели — отказ сузил бы язык
без нужды.

## Decision

Принимается **Option A**:

- `semantic::type_inference::extract_type` выводит тип **поля структуры**
  (`BitAccess` с `Member::Identifier`); доступ к разряду не трогается — его
  тип есть вопрос правила 0356;
- `rust_fixed::fixed_format_in(expr, model)` и
  `sv_fixed::fixed_format_in(expr, structs)` — вывод с оглядкой на объявления;
- у цели `st` `fixed_format` принимает модель и спрашивает
  `inner_expr_type_in` (0349) вместо `inner_expr_type`.

## Consequences

### Положительные

- Приведение из поля, из выражения над полями и из поля элемента массива
  масштабируется у всех четырёх целей.
- Побочно: цель `st` перестала отказывать `ST-011` на выражении над полями.

### Отрицательные / Action items

- Вывод типа поля появился в **четырёх** местах (по одному на цель) плюс
  семантика: это следствие того, что у каждой цели свой вывод типа операнда.
  Сведение к одному носителю — отдельная работа, вынесена кандидатом.

### Acceptance criteria

1. Инструменты всех целей принимают вывод.
2. Потактовая сверка с целью `c` совпадает на трёх формах: поле, выражение над
   полями, поле элемента массива.
3. Мутация «семантика без типа поля» роняет сверку.
4. Предкоммит зелёный; вывод корпуса не изменился.
