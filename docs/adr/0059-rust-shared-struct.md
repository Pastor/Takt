# ADR 0059: Общие переменные корня — структура `Shared` вместо параметров по одной

- **Status:** Accepted
- **Date:** 2026-07-17
- **Authors:** Архитектор + Лид разработки
- **Related issues:** [Фича 0059](../features/0059-rust-shared-struct.md); исполняет политику линтов [ADR 0050](./0050-rust-backend.md) (вариант (а)) там, где она сегодня **нарушена**

## Context

Цель `-t rust` передаёт под-модели переменные родительской модели **по одной**,
`&mut`-параметрами. Так решено в [ADR 0050](./0050-rust-backend.md) осознанно:
указатель на корень (`self.cabin.tick(&mut self)`) даёт **двойное заимствование**
(E0499), поэтому «как в C» (`Model *model`) сделать нельзя, и переменные пошли
параметрами — «как `VAR_IN_OUT` у ST».

Следствие — арность. Порог `clippy::too_many_arguments` — **7**, и `self` в него
**входит**. При превышении генератор **эмитит заглушку линта**:

```rust
// rust_model.rs:918
if 1 + shared.len() + usize::from(needs_hal_param) > 7 {
    p.ident("#[allow(clippy::too_many_arguments)]").nl();
}
```

**Замер по корпусу (2026-07-17, чтение порождённых `.rs`):**

| Под-модель | `shared` | Параметров (со `self` и `hal`) | Заглушка |
|---|---|---|---|
| `Stacker::CommandReceiver` | 6 | 8 | **да** |
| `Stacker::MovementController` | **8** | **10** | **да** |
| `Stacker::LiftController` | 3 | 5 | нет |
| `Elevator::Engine` | 3 | 5 | нет |
| `ElevatorMini::*` | 1–3 | 3–5 | нет |
| `ExtendComplex::*` | 0–2 | 1–4 | нет |
| `Comprehensive::*` | 0 | 2 | нет |

То есть заглушка сегодня стоит **у двух под-моделей одного примера**, а
`rust_model.rs:920` — **единственное место во всём генераторе, которое эмитит
`#[allow]` в порождаемый код**. Это и есть суть проблемы: **единственное
исключение из принятой политики (а)** ADR 0050 («не эмитить то, на что линт
ругается, вместо `#[allow]`; сторож должен остаться живым»).

⚠️ **Уточнение факта, записанного в кандидате и в самом коде.** И кандидат («у
`MovementController` их девять»), и комментарий генератора (`rust_model.rs:911`:
«`MovementController` разделяет с корнем девять переменных») **ошибаются на
единицу**. Замер: в `stacker.lam` **девять** переменных корня
(`tgt_stack`, `tgt_row`, `tgt_section`, `tgt_type`, `busy`, `eta`,
`lift_request`, `lift_op`, `lift_done`), а `MovementController` разделяет
**восемь** — все, кроме `eta`. Девять — это размер **корня**, а не нужд
под-модели. Заявка кандидата «такт получает 10 параметров» при этом **верна**
(`self` + `hal` + 8). Отсюда важное для решения наблюдение: **`shared` считается
по каждой под-модели отдельно** (минимум по нуждам), а не «все переменные корня».

## Decision Drivers

1. **Политика (а) не должна иметь исключений.** ADR 0050 выбрал «не эмитить то, на
   что линт ругается» и прямо запретил глушить сторожей (прецедент: `pub enum`
   глушит `dead_code` видимостью — «не делать»). Одно исключение делает политику
   договорной.
2. **Арность диктует модель, а не стиль.** Это верно — и потому лечить нужно
   **форму передачи**, а не линт: сама по себе заглушка не становится честнее от
   того, что арность обоснована.
3. **Масштабируемость.** 8 общих переменных дают 10 параметров; 20 дали бы 22.
   Предела нет — растёт вместе с моделью пользователя.
4. **Не потерять то, что今 работает.** `no_std`, отсутствие `unsafe`, потактовая
   сверка и контракт 0033 обязаны остаться в силе; заимствования не должны дать
   E0499 (ровно та причина, по которой 0050 не передала указатель на корень).

## Considered Options

### Option A. Одна структура `Shared` на композирующую модель; поле корня; `&mut Shared` параметром

`Shared` = **объединение нужд под-моделей** (не «все переменные корня»: переменная,
которой не нужен никто, общей не является и остаётся прямым полем).

```rust
struct Shared { busy: bool, eta: u8, lift_done: bool, /* … */ }

pub struct Stacker<H: Hal> { shared: Shared, state: StackerState, /* … */ hal: H }

impl Stacker<H> {
    pub fn tick(&mut self) {
        self.movement.tick(&mut self.hal, &mut self.shared);   // ← поля НЕПЕРЕСЕКАЮЩИЕСЯ
    }
}
```

**Pros:**
- Заглушка исчезает **по построению**: параметров всегда `self` + `hal` +
  `&mut Shared` = 3 ≤ 7 (драйверы 1, 3).
- **Двойного заимствования нет** (драйвер 4): `&mut self.hal` и `&mut self.shared`
  — раздельные поля, а не `&mut self`; именно это отличает `Shared` от
  отвергнутого 0050 указателя на корень.
- Ближе к эталону: у цели `c` под-модель получает `Model *model` — то же самое,
  минус заимствования.
- Одна форма вывода — один путь кода.

**Cons:**
- **Теряется минимальность интерфейса:** сегодня сигнатура показывает, какие
  именно переменные читает под-модель (`LiftController` — ровно три); с `Shared`
  каждая под-модель видит всё объединение.
- Корпус меняется шире дефекта: правятся **все** композиции, а не только две
  под-модели `stacker`.

### Option B. Структура ссылок на под-модель (`MovementControllerShared<'a>`)

**Pros:**
- Минимальность сохраняется: у каждой под-модели своя структура ровно из её нужд.
- Заглушка исчезает.

**Cons:**
- **Тип на каждую под-модель** + время жизни; объём вывода растёт.
- Место вызова становится **многословнее сегодняшнего**
  (`&mut MovementControllerShared { busy: &mut self.busy, … }`), то есть проблема
  «девять имён в строке» переезжает из сигнатуры в вызов, а не решается.

### Option C. Оставить как есть (точечная заглушка)

**Pros:**
- Ноль правок; арность действительно диктуется моделью (драйвер 2 — верен).

**Cons:**
- **Нарушает политику (а)** и оставляет её единственное исключение (драйвер 1).
- Не масштабируется (драйвер 3).
- Заглушка на методе скрывает и **будущие** срабатывания линта на нём.

### Option D. `Shared` только там, где порог превышен

**Pros:**
- Минимальный дифф корпуса: меняются ровно две под-модели `stacker`.

**Cons:**
- **Форму вывода начинает определять порог линта** — две формы одного и того же,
  два пути кода, две поверхности дефектов.
- Порог clippy — величина внешняя и может измениться; вывод генератора не должен
  от неё зависеть.

## Decision

Принимается **Option A**.

Она устраняет **единственное исключение** из политики (а) по построению, а не
заглушкой, и снимает потолок роста (драйвер 3). Ключ к ней — наблюдение, которого
не было у 0050: **двойное заимствование даёт `&mut self`, а не «структура»**;
`&mut self.hal` + `&mut self.shared` — непересекающиеся поля, и E0499 не возникает.
То есть довод, по которому 0050 отвергла «указатель на корень», к `Shared` **не
применим**.

Option D отклонена как порождающая две формы вывода ради экономии диффа: дифф —
одноразовая цена, две формы — постоянная. Option B сохраняет минимальность, но
переносит многословность в место вызова и множит типы. Option C оставляет политику
с исключением.

**Нормативные правила:**

1. `Shared` эмитится **только** у модели, у которой есть под-модели, нуждающиеся
   хотя бы в одной её переменной. Нет нужд — нет типа (иначе `dead_code`).
2. `Shared` = **объединение** нужд под-моделей. Переменная модели, не нужная ни
   одной под-модели, в `Shared` **не входит** и остаётся прямым полем: иначе имя
   типа лгало бы.
3. `Shared` **приватна** (как перечисления состояний): публичность заглушила бы
   `dead_code`-сторожа видимостью — прямой запрет ADR 0050.
4. Уровни вложенности: правило 1 применяется **к каждой** композирующей модели
   независимо — у промежуточной модели свой `Shared` (в корпусе такой случай есть:
   `extend_complex`).
5. `hal` в `Shared` **не входит** — он остаётся отдельным параметром и **последним**
   (инвариант 0050: иначе `f(&mut hal, hal.read_u8(…))` даёт E0499).

**Язык не меняется** → версия языка не растёт (правило 22).

## Consequences

### Положительные

- `#[allow]` в порождаемом коде **исчезает полностью**; политика (а) становится
  безысключительной, а `rust_model.rs:920` — удаляется.
- Арность такта перестаёт зависеть от размера модели (драйвер 3).
- Форма вывода одна.

### Отрицательные / Action items

- **A-1. Минимальность интерфейса теряется** — осознанная цена. Сегодня сигнатура
  `LiftController::tick(…, lift_done, lift_op, lift_request)` документирует
  связность; с `Shared` она видна только в `rust_needs`. Смягчение: `Shared`
  строится **по объединению нужд** (правило 2), а не «все переменные корня», то
  есть связность модели по-прежнему ограничивает содержимое типа.
- **A-2. Дифф корпуса будет широким** — меняются `stacker`, `elevator`,
  `elevator_mini`, `extend_complex` (у `comprehensive` общих переменных нет).
  Это **не** нарушение правила 11: наружный контракт (публичный API, порты, HAL,
  поведение) неизменен, меняется внутренняя форма. Дифф **осмыслен и проверяем**
  благодаря детерминизму (закрытая [0048](./0048-deterministic-codegen.md)).
- **A-3. Исправить неверный комментарий генератора.** `rust_model.rs:911` утверждает,
  что `MovementController` разделяет с корнем **девять** переменных; замер —
  **восемь** (девять — размер корня). Комментарий переживёт правку кода, поэтому
  чинится вместе с ней (задача 0059-01).
- **A-4. Проверить сверку, а не только гейт.** `Shared` меняет **способ доступа** к
  переменным (`busy` → `shared.busy`), то есть ровно тот класс, где ошибка тихая
  (урок 0045: `always_comb` читал регистр вместо `_next`, и **оба** гейта приняли).
  Обязателен прогон `conformance_rust_tests`.

### Acceptance criteria

1. **A1.** `grep -rn "allow(clippy::too_many_arguments)" examples/generated/rust/`
   — **пусто**; `rust_model.rs:920` (эмиссия заглушки) удалена.
2. **A2.** `grep -rn "p.ident(\"#\[allow" grammar/src/generator/rust/` — **пусто**:
   генератор не эмитит заглушек линтов вовсе (политика (а) без исключений).
3. **A3.** Гейт цели `rust` (rustc + clippy `-D warnings`) зелёный на **всём**
   корпусе.
4. **A4.** `conformance_rust_tests` — вердикты **не изменились** (A-4).
5. **A5.** Такт под-модели имеет ровно `self` + `hal?` + `&mut Shared?` — не более
   трёх параметров, независимо от числа общих переменных.
6. **A6.** Модель **без** общих переменных (`comprehensive`) типа `Shared` **не
   получает** (правило 1): `grep "struct Shared" comprehensive.rs` — пусто.
7. **A7.** Переменная модели, не нужная ни одной под-модели, в `Shared` **не
   входит** (правило 2) — проверяется фикстурой.
8. **A8.** `Shared` **приватна** (правило 3) — `grep "pub struct Shared"` пусто.
9. **A9.** Многоуровневая композиция (`extend_complex`) даёт `Shared` **на каждом**
   композирующем уровне (правило 4), гейт зелёный.
10. **A10.** `unsafe` в выводе отсутствует; `no_std` держится (инварианты 0050).
