# ADR 0348: Массив в параметре функции у цели `st`

- **Статус:** Accepted
- **Дата:** 2026-08-20
- **Фича:** [../features/0348-st-array-parameter.md](../features/0348-st-array-parameter.md)

## Контекст

Замер 2026-08-20: `first(arr)` при `fn first(a: [u8;2])` давал `iec2c` «Data
type incompatibility for value passed in position 1» — при **нулевом** коде
возврата `taktc`; эталон, `c`, `rust` и `sv` вход исполняли.

Пробы MatIEC (по одной причине за раз):

| Форма параметра | `iec2c` | `cc` на его выводе |
|---|---|---|
| `a : ARRAY [0..1] OF USINT` (аноним) | **отказ** | — |
| `a : U8Arr2` в `VAR_INPUT` | принимает | **не собирается**: «operand of type '__ARRAY_OF_USINT_2' where arithmetic or pointer type is required» |
| `a : U8Arr2` в `VAR_IN_OUT` | принимает | собирается, значение верное |

То есть форму выбрал **полный цикл** `iec2c` → `cc`: одна трансляция сказала бы,
что `VAR_INPUT` годится.

Кроме того, типы аргумента и параметра обязаны **совпадать**: анонимный
`ARRAY […]` против именованного MatIEC не принимает (проба).

## Решение

- Имя типа строится по **форме** массива — `TAKT_ARR_<размер>_<ЭЛЕМЕНТ>`
  (`st_type::array_form_name`), а не по владельцу: все переменные и параметры
  одной формы получают один тип. Этим он отличается от именованных типов фичи
  0210, где речь о **конкретной** переменной, разделяемой с под-моделью.
- Параметры-массивы объявляются в `VAR_IN_OUT`; аргументы вызова
  переупорядочиваются под секции (`reorder_by_sections`), потому что
  позиционный вызов IEC следует порядку **объявления**.
- Именованную форму получают **только** массивы, чья форма встречается в
  параметрах функций: список считается один раз и общий у продюсера типов и у
  каждого объявления (урок ADR 0195).

## Границы

- **Массив по значению не передать:** `VAR_IN_OUT` — ссылка, и функция,
  меняющая параметр, изменит массив вызывающего. Сегодня язык такой записи не
  порождает (аргумент — переменная модели), но это названное свойство формы.
- **Литерал-агрегат аргументом** по-прежнему отвергается (`ST-017`, фича 0343).

## Отвергнутые варианты

1. **`VAR_INPUT` с именованным типом.** Принимается разбором и даёт невалидный
   C — худший исход: отказ приходит от `cc` на выводе `iec2c`.
2. **Имя типа по владельцу (как 0210).** Функция вызывается с разными
   массивами; тип обязан зависеть от формы, а не от места объявления.

## Последствия

- Вывод корпуса не изменился: массивов, передаваемых в функции, в `examples/`
  нет, а прочие остаются анонимными.
