# ADR 0088: Остальные нарушители лимита размера модуля — объём и стратегия

- **Status:** Accepted
- **Date:** 2026-07-23
- **Authors:** Архитектор + Системный аналитик
- **Related issues:** [Фича 0088](../features/0088-module-size-remaining.md);
  продолжение [ADR 0027](0027-module-size-split.md) (правило размера + храповик
  `check-module-size.sh`); образцы разделения — `semantic/validate/`, `lsp/`,
  `generator/c/c_expr/`, `semantic/index/`, `address_map/` (ADR 0069).

## Context

Фича [0027](0027-module-size-split.md) взяла в объём **три** худших модуля и
**заморозила** остальные храповиком `scripts/check-module-size.sh` (реестр
`scripts/module-size-baseline.txt` — узаконенный долг). На сегодня в реестре
**18 файлов** (суммарное превышение — тысячи строк):

| Класс | Файлы (строк) |
|---|---|
| Тесты | `semantic_tests` 5015, `parser_tests` 1892, `codegen_tests` 1393, `lsp_tests` 1266, `lexer_tests` 1081 |
| Генераторы | `rust_model` 1345, `c_source` 1169, `rust_expr` 1112, `c_model` 1073 |
| Парсер | `ast` 1204, `lexer` 1154 |
| Симуляция | `unit/viewport` 1455 |
| **Ядро семантики** | `semantic/tree` 1842, `semantic/mod` 1747, `semantic/expression` 1360, `type_inference` 1191 |
| **Пришпиленные к baseline** | `bin/lamc` 1993, `lib` 1402 |

Классы **сильно различаются риском**. Тесты и генераторы делятся механически и
проверяются быстро (`cargo test` таргета, codegen-снапшоты, детерминизм-гейт).
**Ядро семантики** — сердце компилятора: `mod.rs`/`tree.rs`/`expression.rs`
несут перекрёстные зависимости AST-узлов и проходов; их дробление — крупная
перетряска с реальным риском тонкого регресса. **`lamc.rs`/`lib.rs`** прошлые
фичи (0043, 0075, 0085, 0062) **намеренно** держали большими как «тонкий
диспетчер / публичный API, пришпиленный к baseline» — их дробление противоречит
принятым решениям и требует их пересмотра.

Правило (свод `docs/CODE.md`, 0027): «дели по логике; реестр — долг, а не
разрешение». Оно не запрещает разбить всё, но объём и риск полного захода
несоразмерны Tier-3 характеру работы (качество, не багфикс).

## Decision Drivers

1. **Разный риск по классам.** Механический вынос тестов/генераторов ≠ перетряска
   ядра компилятора. Один объём для всех — либо слишком рискованно, либо слишком
   мало.
2. **Отсутствие регресса — обязательно.** Вынос — **чистое перемещение** кода;
   вывод генераторов байт-в-байт неизменен (детерминизм-гейт 0048), поведение —
   тоже. `mod.rs`-реэкспорт держит пути импорта (правило 11).
3. **Соразмерность.** Быстрее всего сокращает реестр устранение записей у самой
   границы (файл −N строк уходит из реестра целиком).
4. **Пересмотр прежних решений — отдельно.** `lamc.rs`/`lib.rs` пришпилены
   осознанно; трогать их — значит перерешать 0043/0085 — это не механика.

## Considered Options

### Option A. Вынести все 18 файлов за одну фичу

**Pros:** реестр обнуляется (или почти); правило соблюдено полностью.

**Cons:** максимальный риск (ядро) + пересмотр пришпиленных решений в одной
корзине с механикой; много прогонов `precheck.sh`; несоразмерно Tier 3; высокая
вероятность тонкого регресса в `semantic/`.

### Option B. Безопасная часть сейчас, ядро и пришпиленные — отдельно (принята)

Объём 0088 — **12 чисто-делимых файлов**: тесты (5) + генераторы (4) + парсер
(2: `ast`, `lexer`) + симуляция (1: `viewport`). **Ядро семантики** (`tree`,
`mod`, `expression`, `type_inference`) и **пришпиленные** (`lamc`, `lib`) —
**вынесены из объёма** в отдельную фичу (высокий риск / пересмотр прежних ADR).

**Pros:** сокращает реестр **18 → 6** при низком риске; вся работа —
механическое перемещение под зелёным `precheck.sh`; ядро дробится осознанно и
отдельно, а не заодно.

**Cons:** реестр не обнуляется — остаётся 6 записей (заведены новой фичей).

### Option C. Только быстрые победы (файлы у границы)

Вынести лишь `c_model`/`lexer_tests`/`rust_expr`/`ast`… минимальной правкой.

**Pros:** максимально дёшево и безопасно; быстро уменьшает **число** нарушителей.

**Cons:** оставляет крупные безопасно-делимые файлы (`semantic_tests` 5015 —
худший в проекте) нетронутыми; половинчато.

## Decision

Принимается **Option B** (решение заказчика): объём фичи 0088 — **безопасная
часть, 12 файлов**; ядро семантики и пришпиленные `lamc`/`lib` — **новая фича**
(заводится при закрытии 0088; см. Consequences).

Стратегия дробления по классам:

- **Тесты** (`tests/X.rs` — отдельный бинарник): переводятся в
  **директория-подмодуль** — `tests/X.rs` становится тонким файлом с `mod`-
  объявлениями, тела едут в `tests/X/<тема>.rs`. Один тест-бинарник сохраняется
  (быстрее N бинарников), каждый файл ≤ 1000. Границы — по теме проверок (Ce/SE,
  enum, address, struct, verify, …), а не по строкам.
- **Генераторы** (`rust_model`/`rust_expr`/`c_model`/`c_source`): по печатникам,
  образец — уже существующие `{c,rust,sv}_blocks.rs`; новые подмодули
  реэкспортируются, вывод байт-в-байт неизменен (детерминизм-гейт).
- **Парсер** (`ast`, `lexer`): по категориям узлов/токенов.
- **Симуляция** (`viewport`): по ответственности (геометрия/рендер/раскладка).

**Порядок разработки** — по возрастанию превышения (быстрее уходят записи из
реестра), но крупный `semantic_tests` (5015) берётся отдельной подзадачей ввиду
объёма. Каждый вынос: переместить → обновить `module-size-baseline.txt` (удалить
уложившиеся, уменьшить оставшиеся) → зелёный целевой тест → зелёный `precheck.sh`
→ коммит.

**Гарантия отсутствия регресса:** вынос — чистое перемещение; публичные пути
держит `mod.rs`-реэкспорт (правило 11); вывод генераторов сверяется детерминизм-
гейтом и codegen-снапшотами; поведение — существующими тестами. Ни один тест не
меняет **утверждений** — только адрес.

## Consequences

### Положительные

- Реестр `module-size-baseline.txt` сокращается **18 → 6** без риска для ядра.
- Худший файл проекта (`semantic_tests` 5015) перестаёт быть монолитом.
- Устанавливается **воспроизводимый приём** дробления тестов (директория-
  подмодуль) для будущих фич.

### Отрицательные / Action items

- **Реестр не обнуляется:** 6 записей (`semantic/{tree,mod,expression,type_inference}`,
  `lamc`, `lib`) остаются. При закрытии 0088 — **завести новую фичу** «Дробление
  ядра семантики и пересмотр пришпиленных `lamc`/`lib`» (внесёт их в свой объём;
  пересмотр 0043/0085 — её ADR).
- **Тест-бинарники:** директория-подмодуль сохраняет один бинарник на группу —
  время компиляции тестов не растёт кратно.
- **`viewport`** формально в `simulation`, не в ядре семантики — включён как
  безопасный (рендер, не язык); если дробление окажется нетривиальным, переносится
  в отложенную фичу (решение в анализе).

### Acceptance criteria

1. Из реестра `module-size-baseline.txt` **удалены** все 12 файлов безопасной
   части (каждый ≤ 1000 либо разбит на подмодули ≤ 1000); остаются ровно 6
   отложенных записей.
2. `./scripts/precheck.sh` **зелёный** (в т.ч. `check-module-size.sh`,
   детерминизм-гейт, все тесты) на каждом коммите-выносе.
3. Вывод генераторов (`c`/`rust`/`st`/`sv`/`plantuml`) **байт-в-байт неизменен**;
   ни одно тест-утверждение не изменено (только расположение).
4. Пути импорта потребителей не изменились (`mod.rs`-реэкспорт).
5. При закрытии заведена фича-преемник на 6 отложенных файлов.
