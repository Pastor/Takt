# ADR 0119: Приложения документа + приложение «Ошибки»

- **Status:** Accepted
- **Date:** 2026-07-24
- **Authors:** Архитектор, лид документации
- **Related issues:** [Фича 0119](../features/0119-book-appendices.md); правило 25; источник таблицы — [реестр диагностик](../diagnostics/README.md) (ADR 0077)

## Context

Часть справочного материала (полная таблица кодов диагностик — 170+ записей)
необходима в документе, но в основном тексте **перегружала** бы изложение.
Заказчик запросил: механизм **приложений** для такого материала; первым
приложением — «Ошибки» (сводная таблица + разбор каждой ошибки с примером кода и
вывода); и **правило**: в основном тексте на ошибку ставить **ссылку** на
приложение, а не раскрывать её на месте.

## Decision Drivers

1. **Читаемость основного текста.** Длинные справочники не должны его раздувать.
2. **Единый источник кодов.** Таблица кодов уже ведётся в `docs/diagnostics/`
   (ADR 0077) — приложение не должно заводить второй источник истины.
3. **Правило 24.** Номера фич/процесс — в документ нигде.

## Considered Options

### Источник таблицы кодов

- **(A) Генерировать из `docs/diagnostics/README.md`** (единый реестр, ADR 0077):
  извлечь `Код`+`Значение`, отбросить столбец «Источник» (файл:строка — деталь
  реализации) и упоминания фич. **Выбрано.**
- **(B) Писать таблицу в книге вручную** — второй источник, отстанет (та же
  проблема, что решала 0077).

### Полнота разбора

- **(A) Полная сводная таблица (все коды) + подробный разбор представительного
  набора** пользовательских ошибок (пример кода + реальный вывод), структура
  расширяема. **Выбрано** как первый объём.
- **(B) Подробный разбор всех 170** — большой объём; многие коды target-специфичны
  и трудновоспроизводимы. Дорабатывается по мере надобности.

## Decision

Заводится часть «Приложения» с механизмом (правило 25): справочный материал,
перегружающий основной текст, идёт в приложение `book/src/appendix-*/`; в тексте —
ссылка. Первое приложение — «Ошибки и предупреждения»: сводная таблица **всех**
кодов (сгенерирована из реестра диагностик, без «Источника» и номеров фич) +
подробный разбор основных ошибок (пример кода + реальный вывод). Правило 25
внесено в `docs/RULE.md`.

## Consequences

### Положительные

- Основной текст не раздувается; полная справка — в приложении.
- Таблица кодов — производная от единого реестра (ADR 0077), не второй источник.

### Отрицательные / Action items

- При изменении реестра диагностик таблицу приложения нужно **перегенерировать**
  (кандидат: скрипт синхронизации).
- Подробный разбор пока покрывает основной набор ошибок; расширяется по надобности.

### Acceptance criteria

1. Приложение `book/src/appendix-errors/index.md`: префиксы, сводная таблица всех
   кодов, подробный разбор основных ошибок с примерами и выводом.
2. Правило 25 в `docs/RULE.md` (приложения + ссылки на них).
3. Сборка PDF (`xelatex`) чистая; `precheck.sh` зелёный.
