# ADR 0128: Диагностика вместо паники на числовом литерале больше `i64::MAX`

- **Status:** Accepted
- **Date:** 2026-07-27
- **Authors:** Системный аналитик, архитектор, дизайнер языка
- **Related issues:** [Фича 0128](../features/0128-lexer-literal-overflow.md)

## Context

Лексер разбирал числовой литерал через `unwrap()` — в двух местах:

- шестнадцатеричный: `i64::from_str_radix(&hex, 16).unwrap()`;
- десятичный: `i64::from_str(&n_clean).unwrap()`.

Литерал шире `i64` **ронял компилятор**: пользователь получал трассу паники
Rust (`rc = 101`) вместо диагностики. Это не экзотический ввод: полная маска для
типа **`[bit;64]`** — официально поддержанного упакованного вектора (фича
[0078](0078-bit-array-semantics.md)) — записывается ровно так:
`0xFFFFFFFFFFFFFFFF`. То есть у поддержанного типа есть значение, при попытке
записать которое инструмент падает.

Причина глубже лексера: значение литерала хранится в токене как
`Token::Number(i64)`, и **представление чисел в языке** просто не вмещает
беззнаковый 64-битный диапазон.

## Decision Drivers

1. **Инструмент не падает на пользовательском вводе.** Паника — отказ
   инструмента, а не сообщение об ошибке; для библиотеки (её же зовёт LSP) это
   вдобавок обрушивает редактор.
2. **Граница языка должна быть названа.** Молчаливое усечение хуже отказа:
   прецедент — фича [0061](0061-fixed-point-type.md), где непредставимый литерал
   `q(8,8) := 0.001` даёт **ошибку `SE-058`**, а не тихое округление.
3. **Не догадываться за автора.** Если значение не представимо — сказать это, а
   не подставлять «похожее».

## Considered Options

### Option A. Диагностика на выходе за диапазон `i64`; представление не меняем

Новый код `LE-009`; оба `unwrap()` заменяются возвратом ошибки с позицией и
текстом литерала. Граница диапазона документируется в приложении «Ошибки» и в
разделе «Лексика».

**Pros:**
- Устраняет отказ инструмента — цель фичи достигнута полностью.
- Минимальная и полностью проверяемая правка: два места в лексере, ноль влияния
  на АСД, семантику и генераторы.
- Граница становится **названной**: сегодня она существует де-факто, но
  проявляется падением.

**Cons:**
- У типа `[bit;64]` остаётся незаписуемое значение (полная маска). Ограничение
  документируется, но не снимается.

### Option B. Расширить представление числа до `i128`

**Pros:**
- Все 64-битные беззнаковые значения записываются.

**Cons:**
- Правка **сквозная**: токен → узлы АСД → семантика → **пять генераторов**, у
  каждого своя печать чисел. Риск тихого расхождения целей несоизмерим с
  задачей «убрать панику».
- Не отвечает на вопрос о границе: `i128` тоже конечен, и та же паника
  воспроизведётся на литерале шире 128 бит — то есть диагностика всё равно нужна.

### Option C. Для шестнадцатеричных литералов принимать беззнаковое значение и хранить битовый шаблон в `i64`

**Pros:**
- `0xFFFFFFFFFFFFFFFF` записывается; для масок семантика «битовый шаблон»
  выглядит естественной.

**Cons:**
- **Меняет наблюдаемое поведение молча:** `0xFFFFFFFFFFFFFFFF` стало бы `-1`, и
  печать в целях (`c`, `rust`, `sv`, `st`) пошла бы как `-1` — для `uint64_t`
  это тот же битовый шаблон, а для знакового типа или для `st` (где нет
  беззнаковой печати такого литерала) — уже другое число.
- Разводит смысл шестнадцатеричной и десятичной записи: одно и то же значение
  становится то допустимым, то нет — в зависимости от формы записи.
- Требует проверки во всех целях, то есть по объёму приближается к Option B, но
  без его выигрыша.

## Decision

Принимается **Option A**.

Задача фичи — устранить **отказ инструмента**, и Option A решает её полностью и
проверяемо. Расширение диапазона чисел — **отдельный вопрос языка** (какое
представление у числового литерала и как его печатают пять целей), и решать его
попутно, в фиксе паники, значило бы протащить сквозную правку без ADR по
существу.

Незаписуемая полная маска `[bit;64]` **признаётся ограничением** и выносится
кандидатом: язык обязан либо расширить представление, либо дать для масок
отдельную форму записи.

## Consequences

### Положительные

- `taktc` больше не падает на числовом литерале любой длины — выдаётся
  `LE-009` с позицией и текстом литерала.
- Граница диапазона названа в документации: раздел «Лексика» (блок «Частые
  ошибки», правило 26) и приложение «Ошибки и предупреждения» (правило 25).
- Библиотека `takt-lang` перестала быть источником паники для LSP.

### Отрицательные / Action items

- **У `[bit;64]` остаётся незаписуемое значение** (полная маска). Кандидат:
  «Представление числовых литералов шире `i64`» — решать вместе с вопросом
  печати таких значений в целях.
- Версия языка поднимается (правило 22): добавлена диагностика, то есть
  наблюдаемое поведение изменилось.

### Acceptance criteria

1. `0xFFFFFFFFFFFFFFFF` и `18446744073709551615` дают `LE-009`, а не панику.
2. Граничные значения (`9223372036854775807`, `0x7FFFFFFFFFFFFFFF`) по-прежнему
   лексируются.
3. Диагностика несёт позицию литерала и его текст.
4. Код зарегистрирован в `docs/diagnostics/README.md`; гейт
   `check-diagnostic-codes.sh` зелёный.
5. Документация обновлена: таблица и подробный разбор в приложении, строка в
   «Частых ошибках» раздела «Лексика».
6. `./scripts/precheck.sh` зелёный.

> Диаграмма по правилу 18 **не требуется**: синтаксис не меняется — меняется
> реакция на ввод, который прежде ронял инструмент.
