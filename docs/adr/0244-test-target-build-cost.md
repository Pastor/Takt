# ADR 0244: Стоимость тестовых целей — 147 бинарников в предкоммите

- **Status:** Accepted (Option B, затем Option A — решение заказчика 2026-08-17)
- **Date:** 2026-08-17
- **Authors:** Архитектор + лид разработки
- **Related issues:** [Фича 0244](../features/0244-test-target-build-cost.md);
  преемник отменённой [0242](./0242-grammar-crate-split.md); продолжение
  [0241](./0241-precheck-speedup.md), [0234](./0234-precheck-time-profile.md)

## Context

`cargo test --all-features` — **152.9 с из 233.2 с** предкоммита (65.6 %). Фича
0242 предполагала, что дело в компиляции, и была отменена: замер показал, что
вся фаза `clippy` стоит 18.4 с, а компиляция `takt-lang` вместе с порождённым
парсером — 7.3–14.6 с. Настоящее разложение стадии тестов снято здесь.

### Замеры (2026-08-17, свободная машина, устоявшаяся ФС, каждый — в пустой каталог)

**Разложение стадии `cargo test`:**

| Слагаемое | Замер | Как получено |
|---|---|---|
| Компиляция и линковка всех тестовых целей | **29.3 с** | пустой каталог → `cargo test --no-run` |
| **Первый запуск 147 свежесобранных бинарников** | **≈ 88 с** | 20 бинарников за 12.07 с (0.60 с каждый) × 147 |
| Собственно исполнение тестов | **45.4 с** | сумма `finished in` по 147 наборам |
| Итого расчётно | ≈ 163 с | наблюдаемо в предкоммите — 152.9 с |

**Ключевой факт: первый запуск бинарника стоит в 18 раз дороже повторного.**

| Что | 20 бинарников | На один |
|---|---|---|
| Первый запуск (никогда не запускались) | **12.07 с**, загрузка ЦП **2 %** | 0.60 с |
| Повторный запуск тех же | **0.65 с** | 0.033 с |

Загрузка процессора 2 % означает, что время уходит **не на вычисления**:
свежий исполняемый файл проходит проверку кода ядром (AMFI/codesign), читается
с диска и раскладывается динамическим загрузчиком. Средний тестовый бинарник —
10.6 МиБ, всего их 148 (1.5 ГиБ). В предкоммите каждый запускается **впервые**,
потому что каталог сборки гейта живёт отдельно и часто пересобирается.

**Проверка гипотезы о двойной компиляции `clippy` → `test`:**

| Сценарий | Время |
|---|---|
| Пустой каталог → `cargo test --no-run` | 29.3 с |
| Пустой каталог → `clippy --all-targets` (18.2 с) → `cargo test --no-run` | **30.1 с** |

Экономии **ноль**: `clippy` подменяет `rustc` на `clippy-driver`, отпечаток
команды другой, артефакты не переиспользуются. То есть предкоммит компилирует
один и тот же код дважды, и 18.2 с — плата за то, что линты покрывают и тестовые
цели.

**Проверка отладочной информации и линкера:**

| Ход | Компиляция | Первый запуск (20 шт.) | Размер бинарника |
|---|---|---|---|
| База (`debug = true`) | 29.3 с | 12.07 с | 10.6 МиБ |
| `debug = "line-tables-only"` | **27.0 с** (−8 %) | **8.10 с** (−33 %) | 10.2 МиБ |
| `lld` (`-C link-arg=-fuse-ld=lld`) | **32.6 с** (+11 %) | — | — |

`lld` **отвергается замером** — он медленнее системного линкера на этом проекте.
`line-tables-only` выигрывает дважды: немного на компиляции и заметно на первом
запуске (что и подтверждает природу накладных — объём файла, а не вычисления).

## Decision Drivers

1. **Бить туда, где время.** 88 с из 153 — первый запуск бинарников; 45 с —
   сами тесты; 29 с — компиляция. Порядок ходов задаётся этими числами.
2. **Ни одной потерянной проверки.** 3082 теста, 147 наборов и `-D warnings` по
   тестовым целям обязаны остаться; ускорение за счёт покрытия — не ускорение.
3. **Замер, а не правдоподобие.** Проект отверг четыре хода замером
   (`cargo-nextest` — 0234, `MAKEFLAGS` — 0241, вынос грамматики — 0242, `lld` —
   здесь). Пятый не должен появиться по рассуждению.
4. **Различимость наборов.** Имя набора — рабочий инструмент
   (`cargo test --test <имя>`), оно живёт в отчётах и в привычке; слияние не
   вправе его отнять.

## Considered Options

### Option A. Свести интеграционные тесты в несколько целей, сохранив файлы

Один бинарник на тему вместо 147: `tests/<тема>.rs` объявляет `mod` для файлов
в подкаталоге. **Файлы не сливаются** — правило размера модуля (`docs/CODE.md`)
не задевается, имена тестов получают префикс модуля, фильтрация сохраняется
(`cargo test --test targets_c st::`).

**Pros:**
- Бьёт по главному слагаемому: каждый устранённый бинарник — минус 0.60 с
  первого запуска. При 12–15 целях вместо 147 экономия ≈ **80 с**.
- Попутно сокращает линковку (147 линковок → 15) и размер каталога сборки
  (1.5 ГиБ тестовых бинарников).

**Cons:**
- Работа по всем 147 файлам: путь `#[path]`/`mod`, правка `Cargo.toml`,
  вычистка `use` на уровне наборов.
- Ошибки имён ломают фильтры в скриптах — нужен реестр соответствия и проверка.
- Один упавший тест роняет весь бинарник позже по времени (диагностика чуть
  грубее).

### Option B. `debug = "line-tables-only"` в профиле тестов

**Pros:**
- Одна строка в `Cargo.toml`; измеренная экономия — 33 % первого запуска
  (≈ 30 с на 147 бинарниках) и 8 % компиляции.
- Обратные трассы остаются (номера строк сохраняются), теряются только
  локальные переменные под отладчиком.

**Cons:**
- Отладка тестов под `lldb` становится беднее. ⚠️ Проверить, не нужен ли полный
  `debug` кому-то из гейтов (в предкоммите отладчик не участвует).

### Option C. Отказаться от двойной компиляции `clippy` → `test`

**Pros:**
- Экономия 18.2 с.

**Cons:**
- **Неосуществимо без потери покрытия.** Артефакты `clippy` и `rustc`
  несовместимы по устройству cargo; единственный способ не платить — не гонять
  `clippy --all-targets`, то есть перестать проверять линтами тестовый код.
  Это отказ от проверки, а не ускорение.

### Option D. Ничего не менять

**Pros:** ноль риска.
**Cons:** предкоммит остаётся 233 с при измеренной возможности ≈ 120 с.

## Decision

**Принято решением заказчика 2026-08-17: делать оба хода, B первым.** Порядок:

1. **Option B** — дешёвая правка с измеренным эффектом ≈ 30 с; делается и
   проверяется в один заход.
2. **Option A** — основной выигрыш (≈ 80 с), но это работа по 147 файлам;
   разумно вести отдельной задачей `0244-02` с реестром соответствия имён и
   поэтапной проверкой (тема за темой, зелёный предкоммит после каждой).
3. **Option C отвергается**: экономия 18 с достигается только отказом от линтов
   по тестовым целям.
4. **`lld` отвергается замером** (медленнее на 11 %).

Ожидаемый итог: стадия тестов ≈ 45 с исполнения + ≈ 25 с компиляции + ≈ 10 с
запусков, предкоммит — примерно **120–130 с** вместо 233 с. ⚠️ Это **расчёт по
измеренным слагаемым**, а не обещание: каждый шаг подтверждается замером до и
после, по методике «устоявшаяся ФС + второй прогон».

## Consequences

### Положительные

- Стоимость предкоммита становится понятной по слагаемым, а не «долго собирает».
- Найден и измерен класс накладных, о котором проект не знал: **первый запуск
  свежесобранного бинарника — 0.60 с при 2 % ЦП**, повторный — 0.033 с.

### Отрицательные / Action items

- Слияние целей требует реестра «набор → цель»: без него `cargo test --test
  <имя>` в чужих скриптах и в привычке разработчика молча перестанет работать.
- `line-tables-only` обедняет отладку тестов — решение зафиксировать в
  `docs/CODE.md`, чтобы не всплывало как сюрприз.
- Замер накладных первого запуска стоит закрепить сторожем-подсказкой: если
  число тестовых целей снова вырастет, цена вернётся.

### Acceptance criteria

1. Решение заказчика зафиксировано в карточке фичи.
2. При Option B: `cargo test --no-run` и первый запуск измерены до и после;
   предкоммит зелёный, число тестов не изменилось (3082).
3. При Option A: число тестовых целей сокращено, **все 3082 теста на месте**,
   реестр соответствия имён заведён, предкоммит зелёный после каждой темы.
