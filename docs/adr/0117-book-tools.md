# ADR 0117: Раздел документа «Инструментарий»

- **Status:** Accepted
- **Date:** 2026-07-24
- **Authors:** Архитектор, лид документации
- **Related issues:** [Фича 0117](../features/0117-book-tools.md); влияет на [ADR 0101](0101-language-book.md) (состав документа), правило 24

## Context

Документ `book/` по правилу 24 описывает **только язык** и исключает детали
инструментов (компилятор, симулятор, генераторы), команды и вывод — они живут в
`README.md`. Заказчик запросил (2026-07-24) добавить в **сам документ** раздел про
инструментарий: описание работы, команды, примеры вызова и вывода. Это прямо
противоречит правилу 24, поэтому нужно решение о размещении и о судьбе правила.

## Decision Drivers

1. **Запрос заказчика.** Раздел про инструменты должен быть в документе (PDF),
   рядом с описанием языка, а не только в README.
2. **Целостность правила 24.** Языковые разделы должны остаться свободными от
   деталей инструментов — иначе документ теряет фокус «описание языка».
3. **Единый источник.** Дублирование команд в README и book рискует рассинхроном.

## Considered Options

### Option A. Раздел «Инструментарий» в book/ + точечное исключение из правила 24

**Pros:**
- Даёт заказчику запрошенное — раздел в PDF.
- Исключение **выделенное**: послабление только для прикладных разделов
  («Инструментарий», «Развёрнутый пример»), языковые разделы правило 24 защищает
  по-прежнему.

**Cons:**
- Правило 24 усложняется оговоркой.

### Option B. Только в README.md (правило 24 не трогать)

**Pros:**
- Правило 24 остаётся чистым.

**Cons:**
- Не выполняет запрос: раздела в документе/PDF нет.

### Option C. Дублировать в book/ и README

**Pros:**
- Максимальное покрытие.

**Cons:**
- Два источника истины по командам — рассинхрон (драйвер 3).

## Decision

Принимается **Option A**. В `book/` заводится раздел «Инструментарий»; правило 24
дополняется **точечным исключением** для прикладных разделов. Языковые разделы
остаются tool-free. **Номера фич/задач, ссылки на артефакты процесса и сведения о
процессе** не попадают в документ нигде (это ограничение правила 24 сохраняется
полностью, в т. ч. в прикладных разделах).

## Consequences

### Положительные

- Заказчик получает раздел инструментов в PDF.
- Правило 24 остаётся защитой языковых разделов; послабление явно очерчено.

### Отрицательные / Action items

- Команды/флаги инструментов теперь описаны в двух местах (README и book) —
  держать согласованными при изменении CLI.

### Acceptance criteria

1. Раздел `book/src/16-tools/index.typ` описывает `taktc`/`takt-sim`/`takt-lsp`:
   назначение, команды, примеры вызова и **реального** вывода.
2. Правило 24 в `docs/RULE.md` содержит оговорку об исключении.
3. Сборка PDF (`xelatex`) чистая; `precheck.sh` зелёный.
