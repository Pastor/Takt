# ADR 0214: Регистровый интерфейс `sv-mmio` отражает состав портов модели

- **Status:** Accepted (Option A — решение заказчика 2026-08-17)
- **Date:** 2026-08-17
- **Authors:** Архитектор + лид разработки
- **Related issues:** [Фича 0214](../features/0214-sv-mmio-unused-write-signals.md);
  родственные — [0062](./0062-sv-mmio-target.md) (цель `sv-mmio`),
  [0169](./0169-sv-mmio-bus-adapters.md) (адаптер APB),
  [0189](./0189-anonymous-ports.md) (находка сделана при её закрытии)

## Context

Цель `sv-mmio` печатает регистровый интерфейс из четырёх сигналов: `reg_addr`,
`reg_wdata`, `reg_wen`, `reg_rdata`. На модели, у которой нет **входных** портов,
писать шине некуда — и два сигнала записи остаются неподключёнными.

### Замеры (2026-08-17, verilator 5.050, `--lint-only -Wall`)

| Модель | Порты | Регистровый интерфейс | `UNUSEDSIGNAL` |
|---|---|---|---|
| проба `no_ports` (портов нет вовсе) | — | **не эмитится вовсе** | 0 |
| проба `only_in` (только `in cmd`) | входной | все четыре сигнала | 0 |
| `examples/regulator.takt` (только `out ready`) | выходной | все четыре сигнала | **2**: `reg_wdata`, `reg_wen` |
| `examples/stacker.takt` (входные и выходные) | оба | все четыре сигнала | 0 |

**Замер кандидата уточнён:** предупреждений **два**, а не четыре. Свойство
действительно старше фичи 0189 и к анонимным ячейкам не сводится.

**Решающее наблюдение — правило уже существует, но действует наполовину.**
Модель без единого порта регистрового интерфейса **не получает**: цель уже умеет
не печатать то, чему нет соответствия в модели. Не хватает лишь различения по
**направлению**: сигналы записи нужны, когда есть хотя бы один входной регистр,
а не когда есть хоть какой-нибудь.

**Почему гейт молчит.** Список `SV_MMIO_TRANSLATABLE` состоит из одного примера
— `stacker`, у которого входные порты есть. Модель без входных битов в гейт не
попадает, поэтому предупреждения никто не видит. ⚠️ При этом
`verilator --lint-only -Wall` завершается с **ненулевым** кодом
(`%Error: Exiting due to 2 warning(s)`): попади такая модель в гейт — он бы упал.

**APB-обёртка (0169) наследует ту же беду:** пара «ядро + обёртка» на
`regulator` даёт те же два предупреждения, и приходят они от ядра.

## Decision Drivers

1. **Интерфейс должен отражать модель.** Сигнал, которому в модели ничего не
   соответствует, — либо лишний, либо признак незаконченной трактовки.
2. **Правило уже принято на соседнем случае** (нет портов → нет интерфейса);
   решение должно его продолжить, а не завести второе.
3. **Гейт обязан ловить это сам.** Сегодня класс невидим, потому что в списке
   `sv-mmio` один пример с «удобным» составом портов.
4. **Ни одного молчаливого драйвера.** Любое решение, где шина и автомат пишут
   один разряд, требует явного арбитража — иначе синтез даст неопределённость.

## Considered Options

### Option A. Эмитить сигналы записи только при наличии входных регистров

`reg_wdata`/`reg_wen` печатаются, если у модели есть хотя бы один входной порт с
адресом; `reg_addr`/`reg_rdata` — как сейчас, при наличии любого регистра.

**Pros:**
- Продолжает уже принятое правило «интерфейс отражает модель».
- Снимает предупреждения без единой заглушки.
- Модуль только для чтения получает честный интерфейс — по нему видно, что
  запись не предусмотрена.

**Cons:**
- Форма интерфейса становится зависимой от состава портов — потребитель ядра
  (в том числе APB-обёртка) обязан это учитывать. ⚠️ Обёртка APB принимает
  `pwdata`/`pwrite` по спецификации шины; при ядре без записи они станут
  неиспользованными **в обёртке**, и её придётся честно закрыть — либо
  игнорировать запись с явным комментарием, либо не эмитить адаптер записи.

### Option B. Позволить шине писать в выходные регистры (арбитраж)

**Pros:** интерфейс постоянен, запись работает всегда.

**Cons:**
- **Два драйвера одного разряда:** автомат и шина. Требуется арбитраж в
  `always_ff` и решение «кто главнее» — то есть **изменение семантики цели**:
  значение выходного порта перестаёт быть функцией модели.
- Противоречит смыслу `out` в языке: выход — то, что вычисляет автомат.

### Option C. Заглушить предупреждение `/* verilator lint_off UNUSEDSIGNAL */`

**Pros:** одна строка.

**Cons:** прячет симптом, оставляя причину. Проект уже знает цену такого хода:
гейт, которому заглушили голос, перестаёт быть свидетелем (уроки 0171, 0045).

### Option D. Ничего не менять

**Pros:** ноль риска.
**Cons:** порождённый модуль несёт сигналы в никуда; попадание такой модели в
гейт уронит его с сообщением, объясняющим следствие, а не причину.

## Decision

**Принято решением заказчика 2026-08-17: Option A.**

1. `reg_wdata`/`reg_wen` эмитятся тогда и только тогда, когда есть хотя бы один
   **записываемый шиной** регистр (входной порт с адресом).
2. **APB-обёртка приводится в соответствие** тем же признаком: при ядре без
   записи её сигналы записи либо не подключаются к ядру с явным пояснением,
   либо не эмитятся — что именно, решает проба линтом (оба варианта обязаны
   пройти `--lint-only -Wall` и синтез).
3. **Гейт пополняется моделью без входных битов.** Сегодня список
   `SV_MMIO_TRANSLATABLE` — один `stacker`; без второго примера класс останется
   невидимым. Кандидат — `regulator` (все порты `out`), он уже в корпусе.

## Consequences

### Положительные

- Порождённый модуль перестаёт нести сигналы, которым в модели ничего не
  соответствует.
- Гейт начинает видеть класс: `verilator -Wall` на модели только для чтения
  падал бы, а теперь проверяется постоянно.

### Отрицательные / Action items

- Форма интерфейса ядра зависит от состава портов — это надо **назвать** в
  README (раздел о цели `sv-mmio`), иначе интегратор шины столкнётся с этим на
  плате, а не в документе.
- Обёртка APB требует парной правки и собственной пробы линтом и синтезом.
- ⚠️ Тестбенч APB (0169) написан руками и обращается к записи; для ядра без
  записи нужен либо отдельный тестбенч, либо явное исключение с причиной.

### Acceptance criteria

1. `regulator` целью `sv-mmio` даёт **0** `UNUSEDSIGNAL` под `--lint-only -Wall`.
2. `stacker` (входные порты есть) сохраняет прежний интерфейс — вывод не изменился.
3. Пара «ядро + APB-обёртка» на модели без записи проходит линт и синтез.
4. `SV_MMIO_TRANSLATABLE` содержит модель без входных битов, и гейт зелёный.
5. Форма интерфейса описана в README.
