# ADR 0187: Пересмотр задания адресов и доступа к портам

- **Status:** **Proposed** — проработка вариантов; решение принимается заказчиком
- **Date:** 2026-07-31
- **Authors:** Системный аналитик, архитектор, дизайнер языка
- **Related issues:** [Фича 0187](../features/0187-port-io-redesign.md); продолжает
  [0020](0020-port-address-decl.md) (три источника адреса),
  [0070](0070-port-initializer-address-role.md) (инициализатор порта — адрес),
  [0176](0176-bit-port-address-position.md) (умолчание бита, `SE-090`/`SE-091`)

> Документ **не принимает** решения. Он фиксирует, что есть сейчас (пробами, а не
> по памяти), как ту же задачу решают другие языки, и раскладывает пространство
> решений по четырём осям с ценой каждого варианта. Выбор — за заказчиком;
> вопросы для решения собраны в конце.

## Context

### Ось 1. Адрес задаётся инициализатором — форма вводит в заблуждение

`in btn: bit := 0x100:3;` читается как «начальное значение», а означает
**размещение**. Фича [0070](0070-port-initializer-address-role.md) закрепила эту
семантику, [0176](0176-bit-port-address-position.md) добавила предупреждение
`SE-091` на подозрительные `:= 0` / `:= 1` — но форма осталась.

Источников адреса три, с приоритетом (ADR 0020): inline `:=` < оператор
`address P = …;` < внешняя карта `--address-map`.

### Ось 2. Начального значения выходного порта задать нечем

Ни одна форма языка не позволяет сказать «при инициализации выставить на выход
0». Сегодня выход получает значение только когда тело автомата в него пишет; до
этого в регистре лежит то, что там было (после сброса МК — как правило мусор или
состояние по умолчанию периферии).

Обходной путь — писать в `enter` стартового состояния, но он не эквивалентен:
вход в стартовое состояние исполняется на такте 1 (фича 0033), то есть **после**
`_init`, и между сбросом и первым тактом выход не определён.

### Ось 3. Строгость направления заявлена, но применяется в части позиций

Правило есть: запись в `in` — `SE-026`, чтение из `out` — `SE-027`. **Проба
2026-07-31** показала, что проверка стоит только на пути условий
(`validate_cond` → `validate_expression`), а **тела блоков не обходятся**:

```takt
in A: u8 := 0x100;
out B: u8 := 0x104;
start S { always { A := 5; t := B; } … }   // компилируется молча
```

Что делают цели с этим входом:

| Цель | Поведение | Оценка |
|---|---|---|
| `c` | печатает `write_numeric(DIR2_A, 5)` и `read_numeric(DIR2_B)` | молча неверно |
| `c-hal` | то же, но индексы берутся из **чужих** таблиц: `DIR2_A = 0` в `In_Numeric__ADDR`, `DIR2_B = 0` в `Out_Numeric__ADDR` — запись уходит **по адресу другого порта** | молча неверно, опасно |
| `rust` | **отказ** `RS-018` «HAL-трейт даёт входному порту только чтение» | верно |
| `st` | печатает присваивание | молча неверно |
| `sv` | печатает `A = 5;` при `input logic [7:0] A` — **невалидный SystemVerilog** | молча неверно (гейт не покрывает: в корпусе такой модели нет) |
| симулятор | исполняет, в трассе виден `in:A=5` | молча неверно |

То есть направление сегодня — соглашение, которое соблюдают четыре потребителя
из шести, и единственная цель, ловящая нарушение, ловит его **случайно** —
потому что у неё направление выражено типом (трейт HAL).

### Ось 4. Форма порождаемого доступа к порту различна у целей

| Цель | Как читается/пишется порт |
|---|---|
| `c` | косвенно через колбэки структуры: `(*model->read_numeric)(PORT, model->userdata)` — HAL пишет пользователь |
| `c-hal` | те же колбэки + **дефолтная** реализация: таблица `{addr, bit, width}` и `*(volatile uintN_t*)addr` |
| `st` | обычная переменная `VAR` |
| `st-at` | размещённая переменная `AT %IX256.0 : BOOL;` |
| `rust` | метод трейта: `hal.read_numeric(Port::Btn)` / `hal.write_bit(Port::Led, v)` |
| `sv` | порт модуля `input`/`output` — адреса нет вовсе |
| `sv-mmio` | регистровый файл на шине: адрес → смещение регистра, бит → разряд |

Общего понятия «доступ к порту» в языке нет: каждая цель придумывает своё, а
адрес имеет смысл лишь для трёх из семи.

## Практика других языков

| Язык / среда | Размещение | Направление | Начальное значение | Чем полезно нам |
|---|---|---|---|---|
| **IEC 61131-3 (ST)** | `AT %QX0.0` — **отдельная конструкция**, локация кодирует и класс памяти (`%I` вход, `%Q` выход, `%M` память), и размер (`X`/`B`/`W`/`D`), и позицию бита | направление — часть локации: `%I` читают, `%Q` пишут | допускается инициализатор у located-переменной, но **не для всех форм**: проба MatIEC приняла `flag AT %QX0.0 : BOOL := TRUE;` | прямой прецедент «адрес — не инициализатор»; и предупреждение: реализуемость начального значения в ПЛК-цели надо проверять пробой, а не предполагать |
| **Ada** | `for X'Address use System'To_Address(16#4000_0000#);`, плюс record representation clause с точными битовыми полями | `pragma Volatile`/`Atomic`; направление не выражается | обычная инициализация переменной | размещение отделено от объявления и от значения — три независимые вещи |
| **VHDL** | адресов нет (порты сущности) | `in` / `out` / `inout` / `buffer`; чтение `out` было **запрещено** до VHDL-2008 — заводили внутренний сигнал либо `buffer` | значение по умолчанию у порта: `port (q : out std_logic := '0')` | готовый прецедент строгого направления **и** его смягчения; показывает цену запрета чтения `out` |
| **SystemVerilog** | адресов нет | `input`/`output`/`inout`, присваивание `input` — ошибка компиляции | значение по умолчанию у переменной | направление ловит компилятор целевого языка, а не наш |
| **Rust embedded (PAC/svd2rust, `embedded-hal`)** | адрес спрятан в типе периферии | направление — **в типе**: `InputPin`/`OutputPin`, регистры RO/WO/RW | «reset value» регистра описан в SVD | направление как свойство типа делает нарушение непредставимым |
| **C (CMSIS-стиль)** | `#define REG (*(volatile uint32_t*)0x40000000)` | не выражается | запись в стартовом коде | наш `c-hal` — ровно этот стиль |
| **Zig** | `@as(*volatile u32, @ptrFromInt(0x4000_0000))` | не выражается | — | то же |

Общий вывод: в языках, где размещение вообще выражается, оно **отдельно** от
объявления и от значения (IEC `AT`, Ada `for'Address use`). Направление же
надёжно работает там, где оно часть **типа или локации**, и компилятор целевого
языка сам отвергает нарушение.

## Оси и варианты

### Ось 1 — синтаксис адреса

- **1A. Ключевое слово размещения в объявлении:** `in btn: bit at 0x100:3;`
  (`at` — как `AT` в IEC, `for'Address use` в Ada). `:=` в объявлении порта
  освобождается под ось 2.
  *Плюсы:* форма перестаёт лгать; обе боли решаются одной правкой; прецедент в
  двух отраслевых языках. *Минусы:* новое ключевое слово (лексер, LSP, плагины —
  правило 29); ломает **все** существующие объявления с адресом (корпус: 16
  портов, документ: разделы 08 и 12).
- **1B. Оставить `:=`, усилить только диагностику** (сделать `SE-091` ошибкой).
  *Плюсы:* нулевая цена миграции. *Минусы:* форма продолжает лгать; ось 2
  остаётся нерешаемой — `:=` занят.
- **1C. Убрать inline-форму вовсе**, оставив оператор `address P = …;` и внешнюю
  карту. *Плюсы:* размещение всегда отдельной строкой, у объявления один смысл.
  *Минусы:* многословно для типичного случая; ломает корпус так же, как 1A, но
  без выигрыша в читаемости объявления.
- **1D. Атрибут/аннотация:** `@address(0x100, bit = 3) in btn: bit;`.
  *Плюсы:* расширяемо (сюда же лягут ширина доступа, `volatile`, порядок байт).
  *Минусы:* в языке нет понятия атрибута — вводить его ради одного случая дорого.

### Ось 2 — начальное значение выходного порта

- **2A. `:=` означает начальное значение** (в паре с 1A): `out led: bit at 0x40:2 := 0;`.
  *Плюсы:* совпадает с интуицией и с `var`; выражает то, чего сегодня нет.
  *Минусы:* реализуемость различна по целям — `c`/`c-hal`/`rust` пишут в `_init`
  (это наблюдаемое изменение: появляется запись в порт до первого такта), `st-at`
  ограничен тем, что примет MatIEC (проба показала: не всякая форма), `sv`
  — значение по умолчанию у выходного регистра, `sv-mmio` — reset-значение
  регистра.
- **2B. Отдельная форма `init`:** `out led: bit at 0x40:2 { init 0 }`.
  *Плюсы:* не занимает `:=`, совместимо с любой осью 1. *Минусы:* ещё одна
  синтаксическая форма ради одного свойства.
- **2C. Не вводить** — оставить запись в `enter` стартового состояния.
  *Плюсы:* нулевая цена. *Минусы:* не эквивалентно (такт 1 против `_init`), и
  между сбросом и первым тактом выход не определён; для `sv` это разница между
  «регистр сброшен» и «регистр неинициализирован».

### Ось 3 — строгость направления

- **3A. Строго и везде:** проверка направления обходит **все** позиции (тела
  блоков, функции, инициализаторы), нарушение — ошибка (существующие `SE-026`/
  `SE-027`). *Плюсы:* закрывает подтверждённый пробой класс «молча неверный
  продукт» (см. таблицу выше); равняет цели по строгой стороне. *Минусы:* может
  сломать существующие модели, где чтение `out` использовалось как «вспомнить,
  что выдали» (в корпусе таких нет — проверено, но у пользователей могут быть).
- **3B. Строго, но с явной формой смягчения** — как `buffer` в VHDL: чтение
  выхода разрешено, если порт объявлен особым видом (`out buffered led: bit;`)
  либо через «теневую» переменную, которую генератор заводит сам.
  *Плюсы:* сохраняет удобство, не теряя строгости. *Минусы:* новая форма и новая
  сущность в кодогене.
- **3C. Оставить как есть** (проверка в условиях, тела — молча).
  *Минусы:* подтверждённый дефект Tier 1 остаётся: `c-hal` пишет по адресу
  чужого порта, `sv` порождает невалидный модуль.

### Ось 4 — форма порождаемого доступа

- **4A. Оставить как есть** (каждая цель по-своему; `c` — колбэки, `c-hal` —
  volatile-таблица, `rust` — трейт). *Плюсы:* ноль работы. *Минусы:* «доступ к
  порту» не является понятием языка, и каждая новая цель изобретает его заново.
- **4B. Нормировать модель доступа в языке**: чтение порта — выражение, запись —
  оператор, а **как** это отображается, задаёт цель по единой таблице (по образцу
  того, как 0176 нормировала позицию бита). *Плюсы:* новая цель получает
  контракт, а не образец для подражания. *Минусы:* объём — затрагивает шесть
  печатников.
- **4C. Ввести «профиль доступа» флагом сборки** (`--port-access=callback|direct|register`),
  как `--float-as-q` у 0096. *Плюсы:* одна модель — разные прошивки без правки
  исходника. *Минусы:* CLI начинает менять форму вывода (осознанное исключение
  уже есть — 0096, но множить его нежелательно).

## Предварительная рекомендация (не решение)

Связка **1A + 2A + 3A** решает три подтверждённые боли минимальным числом
понятий: `at` отделяет размещение (как в IEC и Ada), `:=` возвращает себе смысл
«значение», направление становится проверяемым везде. Ось 4 — оставить **4A** и
вернуться к ней отдельной фичей: она не про боль пользователя, а про
внутреннюю стройность.

Цена связки: ломающее изменение синтаксиса (миграция корпуса — 16 портов,
документа — разделы 08, 12, приложение), подъём версии языка, правки лексера,
грамматики, LSP и плагинов (правило 29), новая эмиссия начального значения в
пяти целях.

## Decision

**Ожидает решения заказчика.** Вопросы, на которые нужен ответ, чтобы ADR стал
`Accepted`:

1. **Ось 1:** вводим ли ключевое слово размещения (`at`) — 1A, ограничиваемся
   ужесточением диагностики — 1B, или убираем inline-форму — 1C?
2. **Ось 2:** нужно ли начальное значение выходного порта, и если да — через
   освобождённый `:=` (2A) или отдельной формой (2B)?
3. **Ось 3:** делаем ли нарушение направления ошибкой **во всех** позициях (3A),
   и нужна ли явная форма смягчения для чтения выхода (3B)?
4. **Ось 4:** трогаем ли форму доступа сейчас (4B/4C) или откладываем (4A)?
5. **Миграция:** правим корпус и документ разом в этой фиче или заводим
   переходный период (обе формы принимаются, старая — с предупреждением)?

## Consequences

Раздел заполняется после выбора. Уже сейчас можно утверждать:

- **Ось 3 отдельно от прочих является дефектом Tier 1** и может быть закрыта
  раньше остальных: проверка направления во всех позициях не меняет синтаксиса,
  а лишь распространяет уже объявленное правило. Это самая дешёвая и самая
  ценная часть работы.
- **Оси 1 и 2 связаны:** пока `:=` занят адресом, начальное значение выразить
  нечем; решать их порознь бессмысленно.
- **Любой выбор по осям 1–2 — ломающее изменение языка** и требует подъёма
  версии (правило 22), миграции корпуса и документа, а также ревизии
  редакторского слоя (правило 29).
