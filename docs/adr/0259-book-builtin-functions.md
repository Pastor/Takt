# ADR 0259: Встроенные функции языка не описаны в документе book/

- **Status:** Accepted
- **Date:** 2026-08-19
- **Authors:** Архитектор + Аналитик
- **Related issues:** [Фича 0259](../features/0259-book-builtin-functions.md); [фича 0248](../features/0248-sim-builtin-functions.md) (где замер снят), [фича 0247](../features/0247-sim-bare-state-condition.md) (место `S(Модель)` определено), правила 24, 26, 27 свода

## Context

Язык несёт шесть встроенных функций — реестр `takt-lang/src/semantic/builtin.rs`:
`min`, `max`, `abs`, `clamp`, `debug`, `S`. Раздел «Функции» документа о них
молчал: слово `clamp` встречалось там лишь как имя **пользовательской** функции
примера. Автор узнавал о встроенных из исходников компилятора — либо не узнавал.

**Замер 2026-08-19** (правило 30, `scripts/probe.sh` + прогон целей):

| Функция | Эталон | `c`/`c-hal` | `st`/`st-at` | `rust` | `sv`/`sv-mmio` |
|---|---|---|---|---|---|
| `min`, `max`, `abs`, `clamp` | ✓ | ✓ | ✓ | ✓ | `SV-002` |
| `debug("…")` | печатает | **молча выбрасывает** | `ST-011` | `RS-011` | `SV-002` |
| `S(M) = Состояние` (условие) | ✓ | ✓ | `ST-011` | ✓ | ✓ |
| `S(M)` в выражении | `SIM-020` | `CC-022` | — | — | — |

⚠️ **Собственная функция закрывает встроенную** — проверено прогоном:
`fn clamp(p: u8) -> u8 { return 42; }` даёт `r = 42`. Это объясняет, почему
пример раздела с пользовательской `clamp` работает, и обязано быть сказано:
иначе таблица встроенных противоречит примеру на той же странице.

⚠️ **Побочно найдено два дефекта** (в объём документа не входят, вынесены
кандидатами): арность встроенной не проверяется — `min(1)` даёт `model->r = ;`
в C при нулевом коде возврата, а эталон отвечает `SIM-020` с текстом про
`S(Модель)`; и цель `c` выбрасывает `debug` **молча**, тогда как `st` и `rust`
на том же входе отказывают с причиной.

## Decision Drivers

1. **Правило 24:** документ описывает язык целиком; встроенные функции — часть
   языка, а не деталь реализации.
2. **Правило 26:** раздел обязан называть типичные ошибки с кодами.
3. **Документ не должен обещать больше, чем есть.** Поведение целей разное, и
   умолчание о нём дороже краткости: автор ПЛК-программы, прочитав про `debug`,
   вправе знать, что там её нет.

## Considered Options

### Option A. Отдельный раздел «Встроенные функции»

**Pros:** заметнее в оглавлении.
**Cons:** правило 24 требует заводить новый раздел отдельной фичей со своим
жизненным циклом; предмет — шесть функций, и он естественно живёт внутри
«Функций». Раздел из одной таблицы дробит изложение.

### Option B. Подраздел внутри раздела «Функции»

**Pros:**
- Читается там, где читатель уже про функции: объявление → вызов → композиция →
  **встроенные** → внешние.
- Пример раздела уже содержит пользовательскую `clamp`, и правило затенения
  объясняется на месте.

**Cons:** в оглавлении виден вторым уровнем.

### Option C. Приложение-справочник

**Pros:** место для полной таблицы (правило 25).
**Cons:** шесть строк — не тот объём, ради которого заводят приложение;
основной текст остался бы без упоминания вовсе.

## Decision

Принимается **Option B**: подраздел «Встроенные функции» в разделе «Функции»
(`book/src/07-functions/`), перед «Примером».

Состав: таблица шести функций (имя, аргументы, назначение), короткий пример
употребления, **поведение целей** списком с кодами диагностик и правило
затенения собственной функцией. Блок «Частые ошибки» дополнен кодами
`CC-022`, `ST-011`, `RS-011`, `SV-002`, `SIM-020` (правило 26).

**Отдельного примера подраздел не заводит** (правило 27 требует пример от
**раздела**, и он там есть — насосная станция): вместо него две строки кода,
показывающие вызов, и ссылка на пример раздела, где `clamp` — пользовательская.

## Consequences

### Положительные

- Автор узнаёт о встроенных из документа, а не из исходников компилятора.
- Названо поведение целей — включая то, что `debug` не доезжает до прошивки.
- Правило затенения перестало быть скрытым знанием: пример раздела и таблица
  больше не противоречат друг другу на вид.

### Отрицательные / Action items

- Таблица — **второй** носитель знания о наборе встроенных (первый — реестр
  `semantic/builtin.rs`), и машинной сверки между ними нет: гейт
  `check-book-keywords.py` сверяет ключевые слова, а имена встроенных
  ключевыми словами не являются. Расхождение возможно; вынесено кандидатом.
- Два найденных дефекта поведения (арность, молчание `c` на `debug`) остаются
  открытыми — они не предмет документной фичи.

### Acceptance criteria

1. Подраздел есть, таблица перечисляет **все шесть** функций реестра.
2. Поведение целей названо и совпадает с замером.
3. Правило затенения названо.
4. «Частые ошибки» дополнены кодами (правило 26).
5. Гейты документа зелены: сборка Typst, символы шрифта, лексика.
6. `./scripts/precheck.sh` — код 0.
