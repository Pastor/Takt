# ADR 0282: У формулы есть собственная позиция

- **Status:** Accepted
- **Date:** 2026-08-19
- **Authors:** Архитектор + аналитик + разработчик
- **Related issues:** [Фича 0282](../features/0282-formula-own-location.md); смежные — [0168](../features/0168-generator-warnings-return.md) (где замер снят), [0235](../features/0235-guard-formula-in-st-sv.md) (`ST-022` и счёт как сторож), [0203](../features/0203-validate-formulas-traversal.md) (реестр мест объявления формул), [0130](../features/0130-diagnostics-batch.md) (дедупликация `normalize`)

## Context

Реестр мест объявления формул (`semantic/formula/sites.rs`) клал в
`FormulaSite::loc` позицию **вместилища** — модели либо состояния, — потому что
своей позиции у `Formula` в дереве не было вовсе.

**Замер 2026-08-19** (`taktc compile -t st` на файле с двумя `invariant`):

```
model.takt:1:1: Предупреждение [ST-022]: …
model.takt:1:1: Предупреждение [ST-022]: …
```

Две записи с **одинаковой** координатой: автор не знает, о какой из формул речь.

⚠️ **Смежная опасность, и она серьёзнее неудобства.** Дедупликация
`diagnostics::normalize` сравнивает `(позиция, код, текст)`. Пока координата у
обеих формул одна, два предупреждения с одинаковым текстом схлопываются в одно —
ровно та потеря, от которой фича 0235 сторожила **счётом**. То есть отсутствие
позиции было не только неинформативностью, но и заряженной ловушкой.

⚠️ Док-строка поля прежде обещала «позицию объявления»; при 0168 обещание
исправили на честное описание, но **причина осталась**.

## Decision Drivers

1. **Диагностика обязана различать элементы**, о которых говорит.
2. **Дедупликация по позиции** делает совпадение координат потерей записи, а не
   косметикой.
3. **Позиция есть в АСД** — у `invariant` и у встроенной формулы; теряется она
   на построении семантического узла.

## Considered Options

### Option A. Оставить позицию вместилища

**Cons:** две формулы неразличимы; `normalize` схлопывает одинаковые тексты.

### Option B. Различать формулы по тексту диагностики

**Cons:** лечит симптом: координата остаётся ложной, а `normalize` по-прежнему
сравнивает позиции. И текст диагностики цели — не место для идентификаторов.

### Option C. Завести у формулы собственную позицию

**Pros:**
- координата указывает на строку объявления формулы;
- дедупликация перестаёт быть ловушкой;
- реестр мест продолжает работать: позиция вместилища остаётся **запасным
  ходом** для формул, построенных вне разбора.

**Cons:** меняется вариант `Formula::Guard` — 19 мест в двух крейтах; правка
механическая, каждое указывает компилятор.

## Decision

Принимается **Option C**: `Formula::Guard(ConditionNode, Option<String>,
Location)`.

1. Позиция берётся у АСД при построении: у `invariant` — позиция объявления, у
   встроенной формулы — позиция аннотации.
2. Реестр мест предпочитает **свою** позицию формулы; позиция вместилища
   остаётся запасным ходом (`condition_to_formula` строит формулу без исходного
   текста — у неё позиции нет).
3. `PartialEq for Formula` позицию **игнорирует** — по тому же доводу, что и
   `PartialEq for Extend` (0056): иначе две записи одной формулы стали бы
   разными узлами.

## Consequences

### Положительные

- Два `invariant` дают два предупреждения с разными координатами.
- `normalize` больше не схлопывает их в одно.

### Отрицательные / Action items

- ⚠️ **`Formula::LTL` позиции не получила:** у неё своя строгость (`SE-056` —
  предупреждение) и свой потребитель — верификатор, который координату не
  печатает. Граница названа; понадобится — вводится тем же приёмом.
- Вариант перечисления стал трёхместным: новый потребитель обязан его разобрать
  (компилятор скажет).

### Acceptance criteria

1. Два `invariant` дают координаты своих строк (A1).
2. Встроенная формула состояния несёт свою позицию (A2).
3. Две диагностики с одинаковым текстом переживают `normalize` (A3).
4. Формула, построенная вне разбора, берёт позицию вместилища (A4, контроль).
5. `./scripts/precheck.sh` зелён (A5).
