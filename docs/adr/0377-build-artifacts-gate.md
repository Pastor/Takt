# ADR 0377: Артефакты сборки не попадают в репозиторий

- **Status:** Accepted
- **Date:** 2026-08-21
- **Authors:** Архитектор + лид разработки
- **Related issues:** [Фича 0377](../features/0377-build-artifacts-gate.md);
  связь с [ADR 0315](0315-gate-guards.md) (у каждого гейта есть сторож),
  [ADR 0234](0234-precheck-time-profile.md) (гигиена каталога сборки)

## Context

Вопрос заказчика 2026-08-21: почему в корне лежат `*.rlib`. Замер: три файла,
84 КБ, **отслеживаются** гитом с коммита `3c6bec19` (фича 0334) — вывод ручных
проб `rustc` без `--out-dir`, попавший под `git add -A`.

Класс шире одного случая: замеры целей (правило 30, фича 0362) запускают
`rustc`, `cc`, `verilator`, `yosys`, `iec2c`, и каждый кладёт вывод в текущий
каталог, если не сказать иного.

## Decision Drivers

1. **Состояние репозитория — свойство гейта, а не дисциплины автора** (тот же
   довод, что у ADR 0234 про каталог сборки).
2. **Отказ обязан называть файлы**: список — то, с чем можно работать.
3. **Гейт без сторожа не гейт** (правило 0315).

## Considered Options

### Option A. `.gitignore` + гейт по отслеживаемым файлам (принято)

**Pros:**
- `.gitignore` не даёт файлу попасть в индекс — причина закрыта.
- Гейт ловит то, что уже отслеживается (и то, что добавят через `add -f`).
- Проверка дешёвая: `git ls-files` плюс сравнение расширений.

**Cons:** список расширений придётся дополнять при появлении нового
инструмента. Он закрытый и лежит в одном месте — в заголовке гейта.

### Option B. Только `.gitignore`

**Cons:** уже добавленный файл остаётся отслеживаемым — `.gitignore` его не
трогает. Ровно так три `.rlib` и прожили сутки.

### Option C. Проверять рабочее дерево, а не индекс

**Cons:** проба, оставившая рядом `probe.rlib`, роняла бы предкоммит — сторож,
кричащий всегда, замолкает навсегда (урок 0301).

### Option D. Проверять содержимое (`file(1)`), а не расширение

**Cons:** несколько секунд на 3700 файлов ради случая, где расширение известно
точно.

## Decision

Принимается **Option A**: `.gitignore` закрывает расширения в корне, гейт
`check-build-artifacts.py` проверяет **отслеживаемые** файлы и падает списком,
сторож `test-build-artifacts.sh` строит временный репозиторий и проверяет
четыре условия.

## Consequences

### Положительные

- Репозиторий чист, и новая протечка ловится предкоммитом, а не глазами.
- Причина (`--out-dir` в пробах) закрыта `.gitignore`.

### Отрицательные / Action items

- Список расширений закрытый: инструмент с новым расширением придётся внести.
  Он в одном месте, и гейт проверяет сам себя.
- Исторические файлы остаются в истории (удаление — только переписыванием,
  а оно уже делалось 2026-08-19 и стоило правки 61 ссылки).

### Acceptance criteria

1. Гейт падает списком на отслеживаемом `*.rlib` и молчит на чистом дереве.
2. Неотслеживаемый артефакт гейт не роняет.
3. Каталог без репозитория даёт **отказ**, а не рапорт об успехе.
4. Предкоммит зелёный; три файла из репозитория удалены.
