# ADR 0334: Сдвиг на величину не меньше ширины типа в цели `rust`

- **Статус:** Accepted
- **Дата:** 2026-08-20
- **Фича:** [../features/0334-rust-variable-shift-width.md](../features/0334-rust-variable-shift-width.md)

## Контекст

Фича 0326 закрыла **половину** класса: сдвиг **вправо** на **литеральную**
величину. В её заголовке стояла названная граница — «переменная величина не
покрывается: `checked_shr` в каждом выражении стоил бы дороже пользы».

Замер 2026-08-20 (`scripts/probe.sh`, `a: u8 := 200; n: u8 := 8`) опроверг
довод: цена умолчания — не лишняя инструкция, а **другой автомат**.

| Форма | Эталон | `c`, `c-hal`, `sv`, `sv-mmio` | `st`, `st-at` | `rust` |
|---|---|---|---|---|
| `a >> n`, `n = 8` | `0` | `0` | `ST-011` (отказ) | **паника** в отладке, **`200`** в релизе |
| `b >> n`, `b: i8 := -7` | `−1` | `−1` | `ST-011` | то же |
| `a << 8` (литерал) | `0` | `0` | `ST-014` | **не собирается**: «attempt to shift left by `8_i32`, which would overflow» |
| `a << n` | `0` | `0` | `ST-014` | паника / `200 << 0` |

Прогон `rustc -O` подтвердил релизное поведение: величина маскируется до
`n & 7 = 0`, то есть `a >> n` даёт **200**. Прошивки собирают именно в релизе.

Литеральный сдвиг **влево** при этом вовсе не собирался — при **нулевом** коде
возврата `taktc` (класс 0262, 0287).

## Решение

Правило распространено на **оба** направления и на **переменную** величину;
носитель прежний (`generator/rust/rust_shift.rs`), функция названа `guarded`.

| Форма | Направление | Печать |
|---|---|---|
| литерал `≥ ширины` | влево | `0` |
| литерал `≥ ширины` | вправо, беззнаковый | `0` |
| литерал `≥ ширины` | вправо, знаковый | `v >> (ширина − 1)` |
| переменная | влево | `v.checked_shl(n).unwrap_or(0)` |
| переменная | вправо, беззнаковый | `v.checked_shr(n).unwrap_or(0)` |
| переменная | вправо, знаковый | `v >> n.min(ширина − 1)` |

**Знаковый сдвиг вправо выражен `min`, а не `checked_shr`,** потому что его
насыщение зависит от самого значения (`v >> (ширина − 1)` есть знак), и
`unwrap_or` напечатал бы `v` **дважды** — а вычисление операнда в языке Takt
бывает с эффектом (вызов функции пишет в переменные модели).

**Приведение величины к `u32` печатается по нужде:** у величины типа `u32`
запись `x as u32` — это `clippy::unnecessary_cast`, то есть отказ сборки
порождённого кода под `-D warnings` (тот же класс, что фича 0263).

## Границы

- **Отрицательная величина сдвига под правило не подпадает:** эталон отвечает
  `SIM-002` и останавливает прогон — у записи нет верного значения вовсе.
  Прошивка считает её молча; это описанное разделение обязанностей (фича 0333).
- **Цель `c` не тронута.** На 8- и 16-битных типах она права по построению
  (операнды продвигаются до `int`). На `u32 >> 32` стандарт объявляет поведение
  неопределённым; замер `clang -O2` дал `0`, то есть совпало с эталоном.
  Выражение с ветвлением удорожило бы **каждый** сдвиг ради случая, не
  наблюдавшегося ни разу, — вынесено кандидатом.

## Отвергнутые варианты

1. **Оставить границу как есть.** Она держалась на цене инструкции, а платили
   за неё верностью автомата.
2. **Отказ `RS-011` на переменную величину.** Запись законна и исполняется
   эталоном; отказ на работающем входе — регресс.
3. **`wrapping_shr`.** Даёт **маскирование** — ровно то релизное поведение,
   которое расходится с эталоном.

## Последствия

- Вывод корпуса **не изменился**: сдвигов в `examples/` нет ни одного, поэтому
  гейт цели класс не видел и не увидит — сторожа фикстурные.
- Заголовок `rust_shift` больше не обещает несуществующей границы.
