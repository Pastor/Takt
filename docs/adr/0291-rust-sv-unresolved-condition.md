# ADR 0291: Решение «ребро безусловно» — у одного носителя

- **Status:** Accepted
- **Date:** 2026-08-18
- **Authors:** Архитектор + аналитик + разработчик
- **Related issues:** [Фича 0291](../features/0291-rust-sv-unresolved-condition.md); прямой предшественник — [ADR 0236](0236-c-unresolved-condition-refusal.md) (`CC-023`); класс «два списка одного набора» — [0084](../features/0084-address-map-qualified-key.md), [0193](../features/0193-shared-const-qualified.md), [0195](../features/0195-target-name-collisions.md)

## Context

Фича [0236](../features/0236-c-unresolved-condition-refusal.md) изъяла у цели
`c` ветвь, считавшую **неразрешённое** условие отсутствием условия: ребро
`ref T: <неразрешённое>;` становилось безусловным — вывод валиден, автомат
другой, и молча. Объёмом той фичи была одна цель; кандидат называл ещё две
(`rust`, `sv`).

**Замер 2026-08-18 дал две поправки к кандидату — обе существенные.**

### Поправка 1: копий правила не две, а восемь

Кандидат называл два места. Греп по обоим крейтам нашёл **восемь**
потребителей, каждый решавший «безусловно ли ребро» своим `matches!`:

| Место | Что решало | Считало `Unresolved` безусловным |
|---|---|---|
| `generator/c/c_model.rs` | печать перехода | нет (изъято 0236) |
| `generator/st/st_model.rs` | печать перехода | нет |
| `generator/rust/rust_tick.rs` | печать перехода | **да** |
| `generator/sv/sv_fsm.rs` | печать перехода | **да** |
| `takt-sim/src/unit/builder.rs` | предикат эталона | нет |
| `verification/kripke.rs` | нужна ли самопетля | нет |
| `semantic/validate/nondeterminism.rs` (×2) | Ce14 — счёт безусловных | нет |

Три последних кандидат не знал: их нашёл **сторож**, написанный в этой же
задаче, на первом прогоне. Это тот самый класс, которым проект уже платил
трижды (0084, 0193, 0195): один набор, много списков — списки расходятся.

### Поправка 2: дефект СЕГОДНЯ недостижим, и это меняет цену, а не решение

Кандидат утверждал, что цели дают «валидный вывод с другим автоматом».
Прогон показал: неразрешённое условие значит «имя не найдено», и такой вход
отсекает **`SE-025`** до генерации — одинаково для всех целей:

```
ref Done: nosuchname;
→ Ошибка компиляции [SE-025]: неразрешённое условие перехода …
```

То же верно и для `CC-023` цели `c`: её собственная документация прямо
говорит, что отказ «недостижим из корректной программы… недостижимость держит
другая фича». То есть речь не о живом дефекте, а о **ловушке**: ветвь молчаливой
подмены автомата, которую от срабатывания отделяет **чужая** проверка.

⚠️ **`Tier 1`, проставленный этой записи, замером не подтверждён.** Уровень
выводился из текста кандидата, а тот утверждал достижимость. По шкале
`FEATURES.md` запись отвечает `Tier 4` — «косметика внутреннего»: ни валидность,
ни поведение действующих программ не затронуты. Расстановка исправлена при
закрытии.

## Decision Drivers

1. **Правило одно — носитель должен быть один.** Восемь копий одного решения
   уже разъехались; починка двух копий из восьми оставляет ту же схему.
2. **Ловушка дешевле правила.** Стоимость снятия — один предикат и правка
   восьми вызовов; стоимость срабатывания — молчаливо другой автомат в прошивке.
3. **Недостижимость держит чужая фича.** `SE-025` не давала обещания охранять
   генераторы; она перестанет прикрывать эту ветвь при первом же изменении
   восстановления после ошибок или появлении новой формы `Unresolved`.
4. **У громкого отказа уже есть исполнители.** Печатники условий обеих целей
   отвергают `Unresolved` своими кодами (`RS-011`, `SV-002`) — новых диагностик
   заводить не нужно, достаточно **дойти** до печатника.

## Considered Options

### Option A. Ничего не делать: дефект недостижим

**Pros:** ноль правок.

**Cons:** оставляет восемь копий одного правила и две из них — неверными.
Недостижимость обеспечивает фича, которая об этом не знает.

### Option B. Снять `Unresolved` из двух ветвей (буква кандидата)

**Pros:** минимальная правка, две цели приходят в согласие с `c`.

**Cons:** копий остаётся восемь. Следующее расхождение случится так же молча —
причина не устранена, устранён случай.

### Option C. Один предикат `ConditionNode::is_unconditional()` + сторож

**Pros:**
- Решение перестаёт быть копируемым: восемь вызовов, одно знание.
- Сторож грепает оба крейта и падает **списком** — обойти предикат нельзя молча.
- Ветвь `Unresolved` уходит к печатнику, который уже отвечает `RS-011`/`SV-002`:
  громкий отказ вместо тихой подмены, без новых кодов.

**Cons:** правка задевает восемь мест вместо двух (включая три, о которых
кандидат не знал) — но именно они и есть предмет.

## Decision

Принимается **Option C**.

1. Заводится `ConditionNode::is_unconditional()` (`semantic/condition_node.rs`)
   — **единственное** место, где решается вопрос. Внутри — `ConditionNode::None`
   и только он.
2. Все восемь потребителей зовут предикат.
3. Сторож (`takt-lang/tests/semantic/unconditional_edge_tests.rs`): поведение
   предиката (`None` → да, `Unresolved` → нет, настоящее условие → нет), греп по
   `takt-lang/src` и `takt-sim/src` на обход предиката (падает списком) и
   **замер достижимости** — тест, фиксирующий, что вход отсекает `SE-025`.
4. Новых диагностик не заводится: неразрешённое условие, дойдя до печатника,
   получает существующие `RS-011` / `SV-002`.

## Consequences

### Положительные

- Восемь потребителей отвечают на один вопрос одинаково **по построению**.
- Ловушка «тихо другой автомат» снята у обеих целей.
- Сторож достижимости делает явным, **чем** держится недостижимость: если
  `SE-025` однажды перестанет отсекать вход, тест это покажет.

### Отрицательные / Action items

- Публичная поверхность `takt-lang` растёт на один метод.
- ⚠️ Сторож ищет форму `matches!(…, ConditionNode::None…)`. Обход, написанный
  иначе (`if let`, сравнение через `==`), он не увидит — граница названа в
  его док-строке.

### Acceptance criteria

1. Предикат отвечает `true` только на `ConditionNode::None` (A1).
2. Ни один потребитель не решает вопрос сам — сторож зелен (A2).
3. Замер достижимости: вход с неразрешённым условием отсекает `SE-025` (A3).
4. Поведение действующих программ не изменилось: `cargo test --all-features` и
   корпус зелены **без правок** (A4).
5. `./scripts/precheck.sh` зелён (A5).
