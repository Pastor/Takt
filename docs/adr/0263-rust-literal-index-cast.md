# ADR 0263: Приведение индекса к `usize` печатается по нужде

- **Status:** Accepted
- **Date:** 2026-08-19
- **Authors:** Архитектор + аналитик + разработчик
- **Related issues:** [Фича 0263](../features/0263-rust-literal-index-cast.md); смежные — [0250](../features/0250-bit-write-in-targets.md) (где замер снят), [0210](../features/0210-st-array-shared-and-index.md) (индекс — произвольное выражение), [0050](../features/0050-rust-backend.md) (политика линтов цели)

## Context

Цель `rust` печатала индексацию массива с приведением **всегда**:
`self.arr[1 as usize]`. Для индекса-переменной приведение необходимо (типы
Takt — `u8`…`i64`, а Rust требует `usize`), для литерала избыточно: он и так
выводится как `usize` по контексту.

**Замер 2026-08-19** (`clippy-driver --edition 2021 --crate-type=lib -D warnings`
по порождённому модулю — те же флаги, что в гейте `precheck.sh`):

| Строка исходника | Порождено | Ответ `clippy` |
|---|---|---|
| `arr[1] := 7;` | `self.arr[1 as usize] = 7;` | **error:** casting integer literal to `usize` is unnecessary |
| `seen := arr[1];` | `self.seen = self.arr[1 as usize];` | **error:** то же |
| `arr[i] := 9;` (контроль) | `self.arr[self.i as usize] = 9;` | замечаний нет |

Под `-D warnings` это **отказ**: порождённый модуль не проходит тот же гейт,
который проект применяет к своему выводу. Политика цели названа в
[0050](../features/0050-rust-backend.md) — «не эмитить недостижимое и не
ссориться с линтами».

⚠️ **Гейт этого не видит по устройству:** он гоняет **только корпус**, а там
индексируют переменной (`arr[i]`) — литеральных индексов в `examples/` нет ни
одного. Тот же слепой угол дал дефекты 0148-01 и 0148-02.

⚠️ **Отрицательный литерал до цели не доходит:** `arr[-1]` отсекает `SE-028` в
семантике. Иначе `self.arr[-1]` не скомпилировалось бы вовсе.

## Decision Drivers

1. **Вывод обязан проходить гейт проекта.** Цель, чей вывод отвергает
   собственный линтер проекта, не выполняет контракт.
2. **Приведение переменной снимать нельзя** — без него не компилируется весь
   корпус.
3. **Правило одно, печатников два** (выражения и условия): второе знание о нём
   разъедется — класс 0084/0193/0195.

## Considered Options

### Option A. Оставить как есть

**Cons:** порождённый модуль не проходит `clippy -D warnings`; автор узнаёт об
этом от чужого инструмента.

### Option B. Снять приведение везде

**Cons:** ломает индекс-переменную, то есть весь корпус. Отвергнуто сразу.

### Option C. Печатать приведение по нужде, одной функцией на цель

**Pros:** вывод проходит гейт; корпус не затронут (там индекс — переменная);
правило живёт в одном месте.

**Cons:** различие «литерал / не литерал» приходится знать печатнику — но оно
уже есть в узле (`Number`).

## Decision

Принимается **Option C**. Функция `rust_expr::subscript(base, index,
index_is_literal)` — единственный носитель правила; её зовут оба печатника
(`rust_expr` для выражений, `rust_cond` для условий).

## Consequences

### Положительные

- Порождённый модуль с литеральным индексом принимается `clippy -D warnings`.
- Вывод стал короче и читаемее там, где приведение было шумом.

### Отрицательные / Action items

- Форма вывода цели `rust` меняется, но **только** для литерального индекса;
  корпус его не содержит, снимки не двигаются.
- ⚠️ Правило распознаёт литерал по узлу `Number`. Свёрнутая константа
  (`const K := 1; arr[K]`) до печати доезжает литералом (0192), а имя, не
  свёрнутое до числа, приведение сохранит — это безопасная сторона.

### Acceptance criteria

1. `arr[1]` печатается без `as usize`, `arr[i]` — с ним (A1).
2. Печатник условий подчиняется тому же правилу (A2).
3. Порождённый модуль принимается `clippy -D warnings` (A3).
4. `./scripts/precheck.sh` зелён, снимки `examples/generated/` не изменились (A4).
