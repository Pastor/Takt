# ADR 0077: Реестр кодов диагностик — единый источник + машинный гейт

- **Status:** Accepted
- **Date:** 2026-07-22
- **Authors:** Архитектор + Аналитик
- **Related issues:** [Фича 0077](../features/0077-diagnostic-code-registry.md); прецедент [ADR 0027](0027-module-size-split.md) (правило, проверяемое машиной, — baseline-файл + гейт); повод — [0029](../features/0029-c-type-mapping.md)/[0028](../features/0028-c-generator-stubs.md) (коллизия `CC-014`).

## Context

Коды диагностик (`SE-036`, `CC-014`, `SIM-010`, `AM-001`, …) выдаются **голыми
строковыми литералами** через `Diagnostic::with_code(&str)` (≈330 мест в
`grammar`, плюс два централизованных `code()`-диспетчера — `lexer::LexicalError`
и `eval::EvalError`). **Валидации формата и уникальности нет.** Новый код
выбирается **грепом «последнего занятого»** в префиксе — именно так фичи 0028 и
0029 независимо взяли `CC-014` и друг друга не увидели (коллизия; лечение — 0028
переехала на `CC-018`).

Документация кодов — **вручную** пополняемые таблицы, разбросанные по `README.md`
(раздел 7 для LE/SY/SE/CC/SIM; отдельные таблицы целей RS/SV; таблица DF в разделе
карты адресов). Реестр **отстаёт от кода**: `AM-001…006` и `PU-001` не описаны
вовсе, `ST` — лишь 2 кода из 13.

Инвентаризация (grep по `*/src`): **11 префиксов**, ~173 уникальных кода. Формат
единообразный `XX-NNN` (2–4 буквы, дефис, 3 цифры) — отклонений нет. В нумерации
есть **пропуски** (`CC-009`, `SE-024/031/032`, `ST-003`…) — норма (код выведен/
зарезервирован).

| Префикс | Слой | Префикс | Слой |
|---|---|---|---|
| LE | лексика | ST | цель Structured Text |
| SY | синтаксис | SV | цель SystemVerilog |
| SE | семантика | DF | флаг `--define` |
| CC | цель C | AM | парсинг карты адресов |
| RS | цель Rust | PU | цель PlantUML |
| SIM | симулятор (`EvalError`) | | |

**Корневая проблема — не в кодах, а в отсутствии единого проверяемого места:**
источник истины размазан по коду и ручным таблицам, ничто не гарантирует ни
уникальности, ни синхронности код↔документация.

## Decision Drivers

1. **Коллизия обязана ловиться машиной, а не дисциплиной.** Прецедент правила
   размера модуля (ADR 0027): правило, живущее только в тексте, не работает
   (`validate.rs` дорос до 3654 строк). Реестр без гейта повторит судьбу README.
2. **Синхронность код↔документация — гейтом, а не ревью.** «AM/PU/ST не описаны» —
   прямое следствие ручного пополнения; гейт обязан валить сборку на
   незарегистрированном коде.
3. **Аддитивность (правило 11).** Решение не должно переписывать ≈330 мест
   `with_code` — риск регресса огромен, польза над гейтом маргинальна.
4. **Единый источник истины.** Одно место, где виден весь занятый диапазон и
   «следующий свободный» номер в префиксе, — чтобы греп-и-угадай стал не нужен.
5. **Соразмерность.** Не строить генератор/БД там, где хватает текстового реестра
   и shell-гейта (как `check-module-size.sh`).

## Considered Options

### Option A. Единый реестр-файл + машинный гейт (валидация, не типизация)

Единый **источник истины** — `docs/diagnostics/README.md`: одна таблица, **каждый
код ровно раз** (код · значение · слой/источник · фича). Гейт
`scripts/check-diagnostic-codes.sh` в `precheck.sh`:

- извлекает коды, **эмитируемые исходником** (`with_code("…")` + оба
  `code()`-диспетчера — тоже строковые литералы);
- **двусторонняя** сверка: каждый эмитируемый код ∈ реестр (ловит
  незадокументированный AM/PU/ST); каждая строка реестра ∈ исходник **или** помечена
  `RESERVED`/`RETIRED` (ловит протухшую);
- **формат** `XX-NNN`; **дубль строки** реестра → ошибка;
- печатает **по префиксам максимальный занятый номер** (даёт «следующий свободный»).

**Pros:**
- Коллизия и рассинхрон ловятся `precheck.sh`/CI — драйверы 1, 2.
- Аддитивно: `with_code(&str)` не тронут, ≈330 мест целы — драйвер 3.
- Единое место + «следующий свободный» — драйвер 4; прецедент 0027 — драйвер 5.
- Реестр строится один раз извлечением из исходника → полнота гарантирована гейтом.

**Cons:**
- Уникальность проверяется **в precheck**, а не компилятором (окно между правкой
  и гейтом). Смягчено: гейт в CI обязателен, локально — в `precheck.sh`.
- Разовая миграция ~173 строк реестра (бутстрап скриптом из исходника).

### Option B. Типизация: `with_code(DiagnosticCode)` (enum)

Заменить строковые литералы enum-ом (`DiagnosticCode::SE036`), уникальность —
вариантами enum (компайл-тайм).

**Pros:**
- Уникальность и полнота — гарантия компилятора; автодополнение в IDE.

**Cons:**
- ≈330 мест в **двух** крейтах + enum на ~173 варианта (риск лимита размера
  модуля 0027) — грубое нарушение драйвера 3 (аддитивность).
- Польза над гейтом маргинальна: гейт ловит те же коллизии в precheck; enum не
  решает рассинхрон с **документацией** (значение всё равно вне типа).
- `code()`-диспетчеры (lexer, eval) пришлось бы переплести с общим enum через
  границу крейтов (`simulation` → `grammar`).

### Option C. Только линт-скрипт без файла-реестра

Гейт проверяет лишь «формат» и «нет двух `with_code` с разным текстом на один код».

**Pros:** минимум артефактов.

**Cons:**
- Семантическую коллизию (один код — два **разных** смысла) из строк **не
  вывести**; не чинит рассинхрон с документацией (драйвер 2) — реестра-то нет.
  Недостаточно.

## Decision

Принимается **Option A**. Единый реестр-файл + гейт — прямой аналог
проверяемого-машиной правила размера модуля (ADR 0027), аддитивный (драйвер 3) и
соразмерный (драйвер 5). Enum (B) отвергнут ценой/риском при маргинальной пользе;
линт без реестра (C) не чинит документацию и семантическую коллизию.

- **Источник истины:** `docs/diagnostics/README.md` — таблица `Код · Значение ·
  Слой/источник · Фича`, по одной строке на код, отсортирована по префиксу и
  номеру. Значение мигрируется из README/комментариев; пробелы **AM/PU/ST**
  заполняются здесь (полнота — под гейтом).
- **Гейт** `scripts/check-diagnostic-codes.sh` (POSIX sh, как `check-module-size.sh`),
  включён в `precheck.sh` **и** в CI (через тот же `precheck.sh`, ADR 0090):
  1. извлечь `EMITTED` = коды из `grammar/src` + `simulation/src`
     (`with_code("…")` и литералы в `code()`-диспетчерах);
  2. извлечь `REGISTERED` = коды из таблицы реестра;
  3. `EMITTED ∖ REGISTERED ≠ ∅` → **ошибка** «код эмитируется, но не в реестре»;
  4. `REGISTERED ∖ EMITTED` минус `RESERVED`/`RETIRED` → **ошибка** «код в реестре
     протух»;
  5. дубль кода в реестре, нарушение формата `XX-NNN` → **ошибка**;
  6. печать по префиксам максимального номера (справка «следующий свободный»).
- **`with_code(&str)` НЕ меняется** — аддитивность. Doc-комментарий метода
  дополняется ссылкой на реестр и правилом «новый код — сперва в реестр».
- **README раздел 7 и таблицы целей:** остаются как **человеческое** описание, но
  **перестают быть источником истины** — над каждой добавляется ссылка «полный
  реестр — `docs/diagnostics/`». Их полнота больше не требуется (реестр полон по
  гейту); переписывать их — **вне объёма** (риск/объём; драйвер 5).

**Обратная совместимость (правило 11):** ни один код не меняется, ни одно место
`with_code` не трогается → **вывод компилятора и симулятора байт-в-байт неизменен**
(тексты и коузы диагностик те же). Изменение — новый документ + новый гейт +
дозаполнение документации. Версия языка **0.3.0** без изменений; версии крейтов
без изменений (публичный API не тронут).

## Consequences

### Положительные

- Коллизия кодов и рассинхрон код↔документация ловятся `precheck.sh`/CI.
- Один машинно-проверяемый список всех кодов; «следующий свободный» виден сразу.
- Пробелы документации (AM/PU/ST) закрыты и удерживаются гейтом.

### Отрицательные / Action items

- Разовая миграция реестра (~173 строки) — бутстрап скриптом из исходника, значения
  курируются вручную.
- Уникальность — в precheck, не в компиляторе (окно правка→гейт). Принято.
- Правило «новый код — сперва в реестр» задокументировать в `docs/CODE.md`/`RULE.md`
  и doc-комментарии `with_code`.

### Acceptance criteria

1. `docs/diagnostics/README.md` содержит **каждый** эмитируемый исходником код ровно
   один раз, с непустым значением; AM/PU/ST включены полностью.
2. `scripts/check-diagnostic-codes.sh` в `precheck.sh`: зелёный на текущем дереве;
   **краснеет** при (а) новом `with_code` вне реестра, (б) дубле кода в реестре,
   (в) нарушении формата, (г) протухшей записи без `RESERVED`/`RETIRED`.
3. Гейт печатает по префиксам максимальный занятый номер.
4. Ни один код и ни один текст диагностики не изменён — вывод целей и симулятора
   байт-в-байт прежний (двойной прогон `precheck.sh`, детерминизм 0048 цел).
5. README-таблицы несут ссылку на реестр как на источник истины; их переписывание —
   вне объёма (явно).
6. `./scripts/precheck.sh` зелёный.
