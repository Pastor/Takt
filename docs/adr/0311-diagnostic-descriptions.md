# ADR 0311: Запись реестра диагностик обязана называть смысл

- **Статус:** Accepted
- **Дата:** 2026-08-20
- **Фича:** [../features/0311-diagnostic-descriptions.md](../features/0311-diagnostic-descriptions.md)

## Контекст

У кода диагностики есть **три** места, где он объясняется:

1. текст самого сообщения (его пишет инструмент);
2. реестр `docs/diagnostics/README.md` — колонка «Значение»;
3. приложение «Ошибки» документа: сводная таблица (сверяется гейтом 0290) и
   **разбор с примером** — он есть не у каждого кода.

Замер 2026-08-20: разбор имеют **83 кода из 229**. Значит для 146 кодов реестр
и сводная таблица — единственное объяснение. И там нашлось **десять** записей,
не объясняющих ничего:

| Код | Описание в реестре |
|---|---|
| `DF-001`…`DF-003` | «ошибка» |
| `DF-004`, `CS-001` | «предупреждение» |
| `FM-001` | «ошибка» |
| `AM-001` | «ожидалось имя порта» (текст сообщения, не смысл) |
| `ST-004` | «оператор address» |
| `SV-005` | «`extern fn`» |
| `SV-006` | «`inout`» |

Слово «ошибка» повторяет то, что видно по колонке кода: справочник, в который
заглянули за смыслом, отвечает тавтологией.

## Решение

1. Десять записей получают описания, снятые **с кода эмиссии** (что именно не
   так у автора и что с этим делать).
2. Гейт `scripts/check-diagnostic-descriptions.py` с самопроверкой и сторожем
   `test-diagnostic-descriptions.sh`, шаг предкоммита. Два класса:
   - **D1** — описание есть служебное слово («ошибка», «предупреждение»,
     «отказ»): отвергается **всегда**, исключений нет;
   - **D2** — описание короче 25 символов: отвергается, если кода нет в
     `scripts/diagnostic-description-baseline.txt`.
3. Реестр долга — ратчет: **D3** ловит протухшую запись (описание выросло либо
   код исчез).

## Почему D2 — ратчет, а не запрет

Короткое ≠ плохое: «Модель не найдена» объясняет исчерпывающе, а раздувание
ради длины дало бы шум. Замер: таких записей 15, все осмысленны. Ратчет
фиксирует их и запрещает **новые**.

⚠️ Служебное слово в долг не вносится никогда — на это стоит отдельная проверка
сторожа (условие 3): узаконить «ошибку» значило бы отменить предмет фичи.

## Отвергнутые варианты

1. **Требовать разбор с примером для каждого кода.** Какие коды заслуживают
   разбора — решение о **пользе**, а не о согласованности (это и вывело разбор
   из объёма 0290). Механический запрет заставил бы писать 146 разделов, из
   которых большинство повторяло бы одну строку.
2. **Сверять описание реестра с текстом сообщения в коде.** Тексты
   параметризованы (`формат!` с подстановками) и пишутся для другого места;
   сверка ловила бы расхождение формулировок, а не отсутствие смысла.
3. **Порог длины без ратчета.** Уронил бы гейт на пятнадцати законных записях.

## Последствия

- Справочник отвечает на вопрос «что это значит» для всех 229 кодов.
- Новая безликая запись невозможна: класс D1 без исключений.
