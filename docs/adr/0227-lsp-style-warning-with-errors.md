# ADR 0227: Редактор показывает CS-001 и при ошибках в файле

- **Status:** Accepted
- **Date:** 2026-08-05
- **Authors:** Архитектор + Заказчик (решение — 2026-08-05)
- **Related issues:** [Фича 0227](../features/0227-lsp-style-warning-with-errors.md); источник — кандидат, найденный при закрытии [0226](../features/0226-naming-convention-warning.md) (задача [0226-03](../development/0226-03-naming-warning-wiring-tests.md)); смежные — [ADR 0226](0226-naming-convention-warning.md), фича [0130](../features/0130-diagnostics-batch.md) (накопление диагностик), фича [0152](../features/0152-semantic-recovery-element-boundary.md) (граница терминальных стадий)

## Context

Фича 0226 завела предупреждение `CS-001` и позвала проверку из **двух**
потребителей — `taktc fmt` и LSP. Реализация одна, но **доставка** разошлась:
`collect_diagnostics_at` возвращается сразу после ошибок, а проверка стиля стояла
**за** этим возвратом. На одном и том же файле `fmt` предупреждение печатал, а
редактор молчал.

Это не мелочь расположения строк: имена правят как раз в файле, который ещё не
собирается, и именно там подсказка нужнее всего. Проверке при этом семантика не
нужна **по построению** — она смотрит на текст (ADR 0226, Option A).

Расхождение было записано кандидатом и пришпилено тестом; заказчик взял кандидата
в работу 2026-08-05, назвав объём: правка касается **только** `CS-001`.

### Что определяет форму решения

**Политика «сперва ошибки» осмысленна — но не для всякого предупреждения.** Она
существует потому, что прочие предупреждения смотрят на **построенную модель**:
«переменная нигде не используется» (`SE-036`) на отвергнутом дереве может быть
ложным (использование стоит в теле, которое не разобралось), «переход
недетерминирован» — тем более. Показывать такие догадки рядом с настоящей
причиной значит утопить причину в следствиях — тот же довод, которым 0152
оставила терминальными стадии построения дерева.

**Канон именования к этому классу не принадлежит.** Имя либо в каноне, либо нет;
ни типы, ни разрешение имён, ни построенное дерево на вердикт не влияют. То есть
довод, оправдывающий политику, к `CS-001` **не применим**.

**Ветвей возврата три.** Ошибка разбора, ошибка построения дерева, ошибка
`validate`. Первая — граница: АСД не существует, проверять форму нечем (и `fmt`
там тоже отказывает, не предупреждая). Остальные две обязаны вести себя
одинаково, иначе предупреждение появлялось бы «через раз» в зависимости от вида
ошибки — поведение, которое пользователь объяснить не сможет.

## Decision Drivers

1. **Потребители не должны расходиться.** Одна реализация правил уже есть; без
   одинаковой доставки она даёт разный ответ на один вход — класс, который проект
   закрывал в 0084, 0193, 0195.
2. **Подсказка нужна там, где правят.** Файл в редакторе почти всегда в
   промежуточном состоянии; предупреждение, исчезающее от любой ошибки,
   бесполезно именно в момент работы.
3. **Причину нельзя утопить в следствиях.** Довод политики «сперва ошибки»
   остаётся в силе для предупреждений о смысле.
4. **Поведение обязано быть объяснимым.** Одинаково во всех ветвях, где АСД есть.

## Considered Options

### Option A. `CS-001` отдаётся во всех ветвях, где АСД разобран

Проверка считается сразу после разбора; результат добавляется и к ошибкам
построения дерева, и к ошибкам `validate`, и к успешному пути. Прочие
предупреждения — как прежде.

**Pros:**
- Паритет с `fmt` на любом входе, где есть АСД.
- Довод политики сохранён там, где он верен (предупреждения о смысле).
- Правка узкая и локальная: одно вычисление, три точки выдачи.

**Cons:**
- Политика «при ошибках предупреждений не показываем» перестаёт быть
  безусловной — её описание в коде приходится уточнять, иначе следующий читатель
  примет исключение за недосмотр.

### Option B. Показывать при ошибках **все** предупреждения

**Pros:** ни исключений, ни оговорок — одно правило.

**Cons:**
- Возвращает шум, от которого политика и защищает: `SE-036` на отвергнутом дереве
  и `SE-037` на неполном графе — догадки, а не факты.
- Меняет наблюдаемое поведение редактора далеко за пределами заявленного объёма
  (заказчик назвал `CS-001`).

### Option C. Оставить как есть, описав асимметрию в документе

**Pros:** нулевая правка кода; поведение уже пришпилено тестом.

**Cons:**
- Документу пришлось бы **объяснять** расхождение, которого пользователь не ждёт:
  «то же предупреждение, но в редакторе его иногда нет».
- Приложение документа (задача 0226-04) уже обещает «корректность программы не
  требуется» — при Option C обещание остаётся ложным для одного из двух
  потребителей.

## Decision

Принимается **Option A**.

`naming_warnings` считается **сразу после успешного разбора** и отдаётся во всех
трёх ветвях возврата, где АСД существует. Политика «сперва ошибки» сохраняется
для предупреждений о **смысле** и в коде названа по существу: «предупреждения о
смысле при наличии ошибок не показываем».

**Граница названа явно:** ветвь неудавшегося разбора предупреждений о стиле не
даёт — АСД нет, имя может быть недописано.

**Объём — только `CS-001`.** Прочие предупреждения (`SE-036`, `SE-037`,
`enum_type_safety_errors`) остаются на успешном пути; Option B отвергнут.

## Consequences

### Положительные

- Редактор и `fmt` говорят об именах одно и то же на любом входе с разобранным
  АСД.
- Автор видит замечание в момент правки, а не после того, как файл собрался.
- Обещание приложения документа («корректность программы не требуется»)
  становится верным для обоих потребителей.

### Отрицательные / Action items

- В коде появляется **исключение** из политики; оно обязано быть описано на
  месте, иначе будет прочитано как недосмотр и «исправлено» обратно.
- Тест, пришпиливавший прежнее поведение
  (`lsp_hides_style_warning_while_errors_present`), заменяется обратным по смыслу
  — вместе с проверкой узости исключения (`SE-036` при ошибках молчит).

### Acceptance criteria

1. На файле с ошибкой построения дерева редактор отдаёт `CS-001` рядом с ошибкой.
2. То же на файле, отвергнутом `validate`.
3. Множество текстов предупреждений о стиле у редактора и у `fmt` **совпадает** на
   обоих таких файлах.
4. При неудавшемся разборе предупреждений о стиле нет.
5. `SE-036` при наличии ошибок по-прежнему **не** показывается.
6. `./scripts/precheck.sh` — код возврата 0.
