# ADR 0268: У `SE-033` нет описания в приложении «Ошибки»

- **Status:** Accepted
- **Date:** 2026-08-19
- **Authors:** Архитектор + Аналитик
- **Related issues:** [Фича 0268](../features/0268-se033-appendix-description.md); [фича 0240](../features/0240-book-typst.md) (где найдено), [ADR 0077](0077-diagnostic-code-registry.md) (реестр кодов), [фича 0290](../features/0290-book-diagnostics-codes-gate.md) (отставание приложения от реестра — смежная), правила 25, 26

## Context

**Замер воспроизведён 2026-08-19** и оказался шире кандидата. Кандидат говорил о
пустой ячейке в приложении; на деле пусто было **в двух местах и по одной
причине**:

| Носитель | Что стояло |
|---|---|
| `docs/diagnostics/README.md` | `<анонимная>` — **фрагмент текста сообщения**, а не описание |
| `book/src/appendix-errors/` (таблица) | пустая ячейка |
| `book/src/appendix-errors/` (разбор) | записи нет вовсе |

`<анонимная>` — значение по умолчанию для имени модели в самом сообщении
(`unwrap_or_else(|| "<анонимная>")`). Кто-то заполнил ячейку реестра этой
строкой, конвертер Markdown принял её за HTML-тег и выбросил — в PDF ячейка
была пуста и до перевода на Typst, и после.

**Прогон показал третий дефект, которого кандидат не называл:** сам текст
диагностики содержал грамматическую ошибку и не объяснял правила —

```
Ошибка компиляции [SE-033]: Состояние 'Finished' не найдено в моделе 'Worker'
```

«в мод**е**ле» вместо «в модели», и ни слова о том, **почему** имя не найдено:
проверка `S(Модель) = Состояние` спрашивает о состоянии названной модели, а не
о любом имени.

## Decision Drivers

1. **Правило 25:** приложение — справочник, и пустая клетка в нём хуже
   отсутствующей строки: она утверждает, что описание есть.
2. **Правило 26:** раздел ссылается на приложение за подробностями; ссылаться
   не на что.
3. **Диагностика — лицо инструмента.** Опечатка в тексте живёт ровно до тех
   пор, пока текст никто не читает вслух.

## Considered Options

### Option A. Заполнить только ячейку приложения

**Pros:** буквально то, о чём кандидат.
**Cons:** реестр остаётся с `<анонимная>` — то есть **источник истины** (ADR
0077) продолжает лгать, а приложение и реестр расходятся.

### Option B. Привести в порядок все три носителя

**Pros:**
- Реестр получает описание, приложение — строку таблицы **и** разбор с
  примером (как у соседей `SE-030`, `SE-034`, `SE-035`).
- Текст диагностики исправлен и объясняет правило, а не только факт.

**Cons:** правится и код, то есть фича перестаёт быть чисто документной.

### Option C. Дополнительно завести гейт «в приложении нет пустых ячеек»

**Pros:** класс закрылся бы машиной.
**Cons:** это предмет фичи [0290](../features/0290-book-diagnostics-codes-gate.md)
(приложение отстаёт от реестра на 19 кодов) — там гейт и место. Дублировать
проверку в двух фичах значит завести два носителя одного правила.

## Decision

Принимается **Option B**.

1. **Реестр** `docs/diagnostics/README.md`: описание словами — «состояние,
   названное справа в проверке `S(Модель) = Состояние`, у этой модели не
   объявлено». Ссылка на источник очищена от номера строки (класс правила
   «`файл.rs:NNN` устаревает молча»).
2. **Приложение**: строка таблицы + разбор `SE-033` с примером и выводом, по
   образцу соседей.
3. **Текст диагностики**: опечатка исправлена, добавлено объяснение правила.

Гейт пустых ячеек **не заводится** — он предмет фичи 0290; граница названа
здесь и в анализе.

## Consequences

### Положительные

- Три носителя знания о `SE-033` согласованы и непусты.
- Автор, получивший ошибку, узнаёт из неё правило, а не только факт.
- Приложение получило разбор — раздел «Функции» и другие теперь могут на него
  ссылаться не вслепую.

### Отрицательные / Action items

- Пустые ячейки могли остаться у **других** кодов: машинной проверки нет, и
  она остаётся за фичей 0290.
- Текст диагностики изменён — тесты, сверяющие сообщение целиком, пришлось бы
  править; проверено: таких нет (сверяется код, а не текст).

### Acceptance criteria

1. В реестре у `SE-033` описание словами, `<анонимная>` не встречается.
2. В приложении заполнена строка таблицы и есть разбор с примером и выводом.
3. Вывод в разборе **совпадает с прогоном** — не сочинён.
4. Документ собирается, гейты символов и кодов зелены.
5. `./scripts/precheck.sh` — код 0.
