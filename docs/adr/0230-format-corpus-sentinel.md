# ADR 0230: Сторож форматтера — корпус восстановлен, KNOWN_GAPS с ратчетом

- **Status:** Accepted
- **Date:** 2026-08-05
- **Authors:** Архитектор + Заказчик (решение — 2026-08-05)
- **Related issues:** [Фича 0230](../features/0230-format-corpus-sentinel.md); источники — два кандидата: «список известных пробелов пуст по существу, но не по тексту» (замер [0229](../features/0229-format-unsupported-position.md)) и «сторож форматтера молча съёжился до одного каталога» (замер [0202](../features/0202-fmt-diagnostic-formatting.md)); найденный дефект — фикс [0199-01](../fixes/0199-01-fmt-drops-model-implement.md)

## Context

Корпусный тест форматтера (`format_tests.rs::a1_a3_corpus_report`) объявлен
главной проверкой фичи 0024: форматтер печатает **всё** дерево, поэтому его
нельзя проверить парой фикстур. Тест обещает три вещи — прогон по всему корпусу,
инварианты A1 (идемпотентность) и A3 (семантическая нейтральность), и падение при
появлении **нового** непокрытого узла.

Два независимых замера показали, что обещание пустое:

1. **Обход съёжился до одного каталога** (замер 0202). Список каталогов —
   `examples`, `grammar/tests/data`, `simulation/tests/data`; последние два
   переименованы в `takt-lang/` и `takt-sim/` ещё фичей 0100. Помощник обхода при
   ошибке чтения **молча возвращался**, поэтому тест оставался зелёным, видя 158
   файлов вместо 308.
2. **Список известных пробелов протух** (замер 0229). `KNOWN_GAPS` перечисляет
   «комментарии (печать — задача 0024-02)» и `InlineFormula`; обе печати давно
   сделаны, и на корпусе таких отказов ноль.

**Цена молчания измерена.** Первый же прогон по восстановленному обходу нашёл
дефект: форматтер **терял реализацию модели** (`model M = A | B { … }` →
`model M { … }`) и печатал невалидную «короткую форму» (`model M = A;`), после
которой файл переставал разбираться. Форма живёт ровно в одной фикстуре — в той
половине корпуса, которую тест не видел. Разбор — фикс
[0199-01](../fixes/0199-01-fmt-drops-model-implement.md).

### Что определяет форму решения

**Тихая усадка покрытия — свойство обхода, а не случайность.** `let Ok(entries)
= read_dir(dir) else { return }` — ровно та конструкция, из-за которой список
каталогов может врать сколько угодно долго.

**Список пробелов без ратчета копит обещания.** Прецедент в проекте есть:
реестр размеров модулей (`scripts/module-size-baseline.txt`) **запрещает**
оставлять запись, которая уложилась в лимит, и гейт это проверяет. Список
пробелов форматтера такого механизма не имел.

**Фикстуры намеренно не нормализованы** (их позиции пришпилены тестами), и
опасение «восстановление путей покраснеет массово» было записано в кандидате.
Замер его **не подтвердил**: корпусный тест не требует каноничности входа — он
проверяет `fmt(fmt(x)) == fmt(x)` и структурное равенство АСД. Из 279 файлов 257
форматируются, 22 не разбираются (намеренно невалидные фикстуры), непокрытых
узлов — ноль.

## Decision Drivers

1. **Сторож обязан сторожить то, что обещает.** Тест, рапортующий о «всём
   корпусе» и видящий половину, хуже отсутствующего: он создаёт ложную
   уверенность.
2. **Молчание при потере покрытия недопустимо** — оно и есть причина, по которой
   усадка прожила незамеченной.
3. **Список исключений не должен расти сам собой.** Запись, потерявшая
   основание, обязана удаляться.
4. **Объём — сторож.** Расширять печать форматтера фича не берётся; найденный
   дефект правится как фикс, потому что без него гейт не зелен.

## Considered Options

### Option A. Восстановить каталоги, сделать обход громким, завести ратчет списка

**Pros:**
- Все три обещания теста становятся истинными.
- Тихая усадка невозможна: пропавший каталог валит тест с именем каталога.
- Протухшая запись списка валит тест — та же дисциплина, что у реестра размеров.

**Cons:**
- Тест становится строже: перемещение каталога фикстур потребует правки списка.
  Это и есть цель, но она платится вниманием при переименованиях.

### Option B. Восстановить каталоги, список оставить как есть

**Pros:** правка меньше.

**Cons:** список продолжает обещать несуществующие пробелы; следующий настоящий
пробел, случайно совпав именем со старой записью, пройдёт **молча** — тот же
класс, что и усадка.

### Option C. Убрать список вовсе: любой непокрытый узел валит тест

**Pros:** нечему протухать.

**Cons:** исчезает способ **явно** узаконить временный пробел с обоснованием —
а он однажды понадобится (так и было при печати комментариев). Пустой список с
ратчетом даёт то же поведение, сохраняя механизм.

## Decision

Принимается **Option A**.

- Каталоги корпуса: `examples`, `takt-lang/tests/data`, `takt-sim/tests/data`.
- Обход **отказывает** на нечитаемом каталоге, называя его путь.
- `KNOWN_GAPS` пуст; запись, которой на корпусе не соответствует ни один отказ,
  валит тест (ратчет, образец — `module-size-baseline`).
- Найденный дефект печати правится фиксом
  [0199-01](../fixes/0199-01-fmt-drops-model-implement.md) — без него гейт не
  зелен, то есть работа не завершена.

**Каталог `book/src` в корпус не включается:** примеры документа держит свой
гейт (фича 0133), а дублирование сделало бы непонятным, чей отказ читать. Замер
показал, что они форматируются (проверено прогоном).

## Consequences

### Положительные

- Сторож видит 279 файлов вместо 158 — и уже окупился найденным дефектом.
- Пропажа каталога и протухшая запись списка теперь **шумят**.
- Список исключений говорит правду: он пуст, потому что пробелов нет.

### Отрицательные / Action items

- Переименование каталога фикстур потребует правки списка в тесте (осознанная
  цена громкого обхода).
- Тест стал дольше: 279 файлов вместо 158 — прогон по-прежнему меньше секунды.

### Acceptance criteria

1. Обход собирает файлы из трёх каталогов; счёт файлов вырос.
2. Пропавший каталог валит тест с именем каталога.
3. Протухшая запись `KNOWN_GAPS` валит тест.
4. Новый непокрытый узел по-прежнему валит тест.
5. A1 и A3 зелены на восстановленном корпусе (с учётом фикса 0199-01).
6. `./scripts/precheck.sh` — код возврата 0.
