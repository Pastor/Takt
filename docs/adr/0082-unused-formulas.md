# ADR 0082: `unused.rs` обходит формулы — Ce13 не ложный

- **Status:** Accepted
- **Date:** 2026-07-20
- **Authors:** Архитектор + Лид разработки
- **Related issues:** [Фича 0082](../features/0082-unused-formulas.md); выявлено при [0035](../features/0035-ltl-in-blocks.md); обострено [0081](../features/0081-lamc-print-warnings.md) (Ce13 теперь печатается пользователю)

## Context

`semantic::unused::check_unused_variables` (Ce13, `SE-036`) собирает использования
переменных обходом дерева модели: переменные, функции, условия, именованные блоки,
состояния, вложенные модели. Но **не** обходит **формулы** (`ModelNode::formulas`,
`StateNode::formulas`). Поэтому переменная, встречающаяся **только** в LTL/Guard-
формуле (`: [LTL] G flag;`, `invariant Inv = g = 0;`), считается неиспользуемой —
Ce13 даёт **ложное** предупреждение.

Дефект был латентным, пока `lamc` не печатал предупреждения. **Фича 0081**
подключила Ce13 к CLI — теперь ложное срабатывание видно пользователю.

## Decision Drivers

1. **Переменная в свойстве верификации — использование.** LTL/Guard-свойство на
   неё опирается; объявлять её мёртвой неверно.
2. **Не глушить настоящие находки.** Реально неиспользуемая переменная обязана
   по-прежнему давать `SE-036`.
3. **Обход — тем же механизмом**, что и прочие узлы (единообразие `collect_from_*`).

## Considered Options

### Option A (принято). Обходить формулы наравне с прочими узлами

Добавить `collect_from_formula` (Guard → `collect_from_condition`; LTL →
`collect_from_ltl`; `Formulas` → рекурсия) и вызвать его для `ModelNode::formulas`
(в `collect_from_model_tree`) и `StateNode::formulas` (в `collect_from_state`).

**Pros:**
- Устраняет ложный Ce13 (драйвер 1) в один обход.
- Настоящие находки сохранены (драйвер 2): формула добавляет использования, но не
  снимает проверку.
- Единообразно с существующими `collect_from_*` (драйвер 3).

**Cons:**
- Имя LTL-атома может быть именем **состояния**, а не переменной. Добавление его в
  `used` безвредно: проверяются только имена переменных, а лишнее имя лишь
  подавляет несуществующее предупреждение. Консервативно (драйвер 2 не нарушен).

### Option B. Исключить из проверки переменные, встречающиеся в формулах

**Cons:** требует отдельного прохода-исключения; дублирует логику сбора и
расходится с ней при добавлении нового вида формулы.

## Decision

Принимается **Option A**.

**Нормативные правила:**

1. **`collect_from_formula`** покрывает все варианты `Formula` (`None`,
   `Formulas`, `LTL`, `Guard`); `collect_from_ltl` — все варианты `Ltl`.
2. Вызывается для формул **модели** и **состояния**.
3. **Настоящие находки не глушатся**: реально мёртвая переменная даёт `SE-036`
   (негативный сторож).
4. Язык **не меняется** → версия не растёт (правило 22).

## Consequences

### Положительные

- Ce13 перестаёт ложно срабатывать на переменных свойств — особенно важно после
  0081 (предупреждения видны пользователю).

### Отрицательные / Action items

- **A-1. Имя состояния в `used`** через LTL-атом — безвредная сверх-аппроксимация
  (см. Cons Option A).

### Acceptance criteria

1. **A1.** Переменная только в LTL-формуле состояния (`: [LTL] G flag;`) → нет
   `SE-036`.
2. **A2.** Переменная только в `invariant` (Guard уровня модели) → нет `SE-036`.
3. **A3.** Реально неиспользуемая переменная → `SE-036` (не заглушено).
4. **A4.** `precheck.sh` зелёный; язык и версия не изменились.
