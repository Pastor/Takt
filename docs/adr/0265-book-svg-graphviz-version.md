# ADR 0265: SVG диаграмм не несут версию graphviz

- **Status:** Accepted
- **Date:** 2026-08-20
- **Authors:** Архитектор + Аналитик
- **Related issues:** [Фича 0265](../features/0265-book-svg-graphviz-version.md); [фича 0240](../features/0240-book-typst.md) (сборка документа — шаг предкоммита), [фича 0301](../features/0301-probe-checklist.md) (каталог бинарников — один носитель), [фича 0251](../features/0251-cargo-target-dir.md) (сборка переехала в `target/precheck`)

## Context

`book/scripts/render_verify_graphs.sh` порождает три SVG раздела «Практический
пример», и они **хранятся в репозитории**. `dot` вписывает в вывод свою версию:

```
<!-- Generated by graphviz version 15.1.0 (20260618.0150) -->
```

Замер (2026-08-18, при работе над 0249): `make -C book build` переписал три
файла, изменив в них ровно эту строку (`15.1.0 → 15.1.1`). Сборка документа
входит в предкоммит — значит любой прогон на машине с другим `graphviz` пачкает
рабочее дерево посторонним диффом.

**Вторая беда, найденная здесь же (кандидат блока 2, замер 0296):** скрипт искал
компилятор в `$ROOT/target/debug/taktc`, тогда как сборка идёт в
`target/precheck` (фича 0251). Регенерация молча не запускалась — печаталось
«регенерация не удалась, использую закоммиченные SVG», а **код возврата
оставался нулевым**. След этой поломки лежал в репозитории: файл
`lift-kripke.dot` был **пуст** (перенаправление создало его до неудачного
вызова).

## Decision Drivers

1. **Гейт не вправе пачкать дерево.** Предкоммит, оставляющий `git status`
   грязным, приучает игнорировать его вывод.
2. **Версия инструмента — не содержание диаграммы.** Она не влияет ни на
   картинку, ни на документ.
3. **Молчаливая неудача хуже отказа:** «использую закоммиченные SVG» с кодом 0
   — это отчёт об успехе там, где работа не сделана.

## Considered Options

### Option A. Не хранить SVG в репозитории

**Pros:** расхождению неоткуда взяться.
**Cons:** сборка документа станет требовать `graphviz` и шрифт ГОСТ у каждого,
кто собирает PDF, — против принципа 0240 («внешний инструмент один»).

### Option B. Вычищать строку версии при генерации

**Pros:** SVG остаются в репозитории и стабильны; сборка документа по-прежнему
требует только `typst`.
**Cons:** в файле остаётся комментарий-заглушка вместо версии — но она и не
нужна.

### Option C. Приводить SVG к каноническому виду отдельным скриптом

**Cons:** второй инструмент о том же предмете; расхождение с генератором —
вопрос времени.

## Decision

Принимается **Option B**, и вместе с ним чинится найденное:

1. `render_verify_graphs.sh` вычищает строку версии (`sed` после `flatten`),
   заменяя её стабильным комментарием.
2. Каталог бинарников берётся у **единственного носителя**
   `scripts/target-dir.sh` (фича 0301) — своей копии пути в скрипте больше нет.
3. Предкоммит проверяет **committed** файлы: в `book/src/*/images/*.svg` нет
   строки `graphviz version`, а `.dot`-исходники **непусты** (пустой файл — след
   молча не работавшей регенерации).
4. Комментарий в предкоммите исправлен: он объяснял выбор цели `pdf` вместо
   `build` в том числе «переписыванием SVG» — эта причина снята.

## Consequences

### Положительные

- Прогон на машине с другим `graphviz` дерево не пачкает.
- Регенерация диаграмм снова работает; пустой `lift-kripke.dot` наполнен.
- Молчаливая неудача теперь ловится гейтом — по пустому исходнику.

### Отрицательные / Action items

- Регенерация по-прежнему требует `graphviz` и шрифт ГОСТ — но она **не** входит
  в предкоммит (цель `pdf`, а не `build`).
- В SVG вместо версии стоит комментарий-заглушка: при отладке `dot` версию
  придётся смотреть иначе.

### Acceptance criteria

1. Перегенерированные SVG не содержат `graphviz version`.
2. Повторный прогон скрипта дерева не меняет.
3. Скрипт берёт каталог бинарников у `target-dir.sh`.
4. Предкоммит ловит committed SVG с версией и пустой `.dot`.
5. `./scripts/precheck.sh` — код 0.
