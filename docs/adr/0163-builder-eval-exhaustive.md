# ADR 0163: Исчерпывающий разбор узлов во втором вычислителе

- **Status:** Accepted
- **Date:** 2026-07-29
- **Authors:** Архитектор + Аналитик
- **Related issues:** [Фича 0163](../features/0163-builder-eval-exhaustive.md); граница [ADR 0093](0093-wildcard-match-rule.md); класс дефекта — [0025](0025-simulator-expression-eval.md)

## Context

Правило ADR 0093 требует **исчерпывающего** разбора узлов языка
(`ExpressionNode`/`ConditionNode`/`StatementNode`) и закрепляет это
`#![deny(clippy::wildcard_enum_match_arm)]`. Гейт
`scripts/check-exhaustive-nodes.sh` сторожит две вещи: чтобы узлы не пометили
`#[non_exhaustive]` и чтобы `deny` не сняли в `takt-sim/src/eval/`.

Но вычислителей над `ExpressionNode` в проекте **два**. Второй —
`builder.rs::eval_expr`, считающий начальные значения переменных и портов **до**
первого такта, — жил под веткой `_ => None` и в область действия правила не
попадал ни компилятором, ни гейтом.

Цена известна поимённо: класс «вычислители разошлись молча» дал **восемь**
дефектов фичи 0025 при зелёных тестах. Он уже срабатывал и здесь: длительность
(`var left: duration := 1m30s;`) молча превращалась в «значения нет», пока ветвь
`Duration` не была вписана вручную — комментарий об этом стоял прямо над
`_ => None`.

⚠️ Слить вычислители нельзя: у них разные входы (у второго нет ни контекста, ни
портов) и разная обязанность, а попытка слияния грозит порт-регрессом (урок
0080). Значит, инвариант нужно распространить, а не устранить дублирование.

## Decision Drivers

1. **Правило без принуждения — не правило.** `_ => None` не ломает сборку;
   добавленный вариант языка получает умолчание вместо решения.
2. **Механизм должен быть тем же, что уже работает.** В проекте `deny` живёт на
   **уровне модуля** (`eval/mod.rs`, `lsp/semantic_tokens.rs`,
   `semantic/usages/walk.rs`), и гейт проверяет именно файл модуля.
3. **Размер модуля.** `builder.rs` — 927 строк при лимите 1000; явное
   перечисление 39 вариантов упрёт его в гейт размера.
4. **Поведение менять нельзя.** Правка — про принуждение, а не про результат.

## Considered Options

### Option A. Вынести вычислитель в отдельный модуль с `#![deny(...)]`

`takt-sim/src/unit/initial.rs` — только `eval_expr`, модульный `deny`, гейт
проверяет второй файл.

**Pros:**
- **тот же механизм**, что у трёх существующих модулей: гейту достаточно
  проверить ещё один файл, изобретать форму проверки не нужно;
- `builder.rs` уменьшается (927 → 896) — запас под будущие правки;
- имя модуля называет **тему** («начальные значения»), а не место, откуда код
  переехал.

**Cons:**
- модуль из одной функции; оправдан тем, что несёт инвариант, а не только код.

### Option B. Item-level `#[deny(...)]` на самой функции (наметка карточки)

**Pros:**
- ничего не двигается.

**Cons:**
- **гейту нечего проверять простым способом**: атрибут внутри файла среди
  тысячи строк, привязка к конкретной функции требует разбора кода, а гейт
  писан на POSIX `sh` без зависимостей;
- расходится с тремя существующими местами, где `deny` — модульный;
- не решает вопрос размера `builder.rs`.

### Option C. Слить с `eval/`

**Pros:**
- один вычислитель вместо двух.

**Cons:**
- отвергнуто прежде и не этой фичей: разные входы, риск порт-регресса (урок
  0080). Фича про **инвариант**, а не про архитектуру вычислителей.

## Decision

Принимается **Option A**.

`eval_expr` переезжает в `takt-sim/src/unit/initial.rs` с
`#![deny(clippy::wildcard_enum_match_arm)]`; 39 вариантов, прежде попадавших в
`_ => None`, перечислены явно одной ветвью «не константа» с объяснением, почему
они таковы. Поведение **не менялось**: те же варианты дают тот же `None`.

Гейт `check-exhaustive-nodes.sh` проверяет теперь **оба** модуля.

### Поиск атрибута привязан к началу строки

Мутация вскрыла, что прежняя проверка (`grep -F`) находила атрибут **внутри
док-комментария**, объясняющего, зачем он нужен: модуль без атрибута, но с
рассказом о нём, гейт проходил. Проверка привязана к началу строки
(`grep '^#!\[deny(...)\]'`) — это чинит класс, а не случай.

⚠️ Находка получена **мутацией**, а не чтением: сам гейт до неё выглядел
работающим и на «правильном» дереве был зелёным.

### Разбор по `Value` тоже стал исчерпывающим

Модульный `deny` не отличает узлы языка от типов крейта, поэтому внутренний
`match` по `Value` в ветви `Negate` пришлось перечислить. Это **к лучшему**:
появится новое представление значения — компилятор потребует решить, отрицаемо
ли оно, вместо молчаливого `None`.

## Consequences

### Положительные

- второй вычислитель наконец под правилом ADR 0093: новый вариант языка ломает
  сборку и требует решения;
- гейт стережёт **оба** модуля и больше не обманывается комментарием;
- `builder.rs` получил запас по размеру.

### Отрицательные / Action items

- ветвь «не константа» длинна (39 вариантов). Это цена принуждения: короткая
  запись `_ =>` и есть дефект;
- ⚠️ прочие подстановочные ветки `builder.rs` (`TypeNode`, `StateNode`,
  `Extend`, `Value`) правилом **не** покрыты и остаются: правило ADR 0093 названо
  для трёх узлов языка, и расширять его — отдельное решение.

### Acceptance criteria

1. `_ => None` по `ExpressionNode` во втором вычислителе невозможен —
   отказывает **компилятор**.
2. Снятие `deny` в любом из двух модулей отвергает **гейт**.
3. Гейт не обманывается упоминанием атрибута в комментарии.
4. Поведение не изменилось: те же входы дают те же значения.
5. `./scripts/precheck.sh` зелёный; `examples/generated/**` не изменился.
