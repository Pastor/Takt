# ADR 0378: Имя переменной, совпавшее с именем типа, у цели st

- **Status:** Accepted
- **Date:** 2026-08-21
- **Authors:** Архитектор + лид разработки
- **Related issues:** [Фича 0378](../features/0378-st-name-type-clash.md);
  связь с [ADR 0065](0065-st-namespace-isolation.md) (`ST-014`, плоское
  пространство имён IEC), [ADR 0195](0195-target-name-collisions.md)
  (столкновения имён у цели `c`)

## Context

`var pair: Pair;` — естественная запись (переменная названа по своему типу).
Шесть потребителей её принимают, `iec2c` отвергает: идентификаторы IEC
регистронезависимы и делят одно пространство имён. Ответ инструмента обманчив
(«invalid located variable declaration» с указанием на `AT %…`), а `taktc`
возвращает ноль.

## Decision Drivers

1. **Молчаливо невалидного вывода быть не должно.**
2. **Причина обязана называться:** ответ `iec2c` её не называет.
3. **Правило цели согласовано само с собой:** у `st` уже есть два отказа того
   же рода.

## Considered Options

### Option A. Отказ `ST-023` с названной причиной (принято)

**Pros:**
- Согласуется с `ST-014`/`ST-020` той же цели и с `SV-012` цели `sv`: отказ
  принадлежит **цели**, текст говорит, что модель валидна для прочих.
- Автор узнаёт причину, которую `iec2c` не называет.
- Дёшево и не может ошибиться в тихую сторону.

**Cons:** модель приходится править ради одной цели.

### Option B. Переименование переменной у цели

**Cons:** имя переменной пришлось бы строить одним носителем для объявления и
**всех** обращений (класс 0193); пропуск одного печатника даёт ссылку в
пустоту. И это расходилось бы с `ST-014`, где цель отказывает, а не
переименовывает.

### Option C. Диагностика семантики (сузить язык)

**Cons:** запись законна и исполняется эталоном; шесть потребителей её
переводят. Сужать язык ради одной цели — решение заказчика, а не разработки.

## Decision

Принимается **Option A**. Проверка живёт в `st_reserved` — там же, где
`ST-014`: класс один (плоское регистронезависимое пространство имён IEC),
меняется лишь источник занятого имени. Имена типов собираются у карт
`structs`/`enums`/`types` модели **и её предков** — тех же, из которых цель
печатает раздел `TYPE`.

## Consequences

### Положительные

- Молчаливо невалидного вывода на этой записи больше нет.
- Автор получает причину и обход в одном сообщении.

### Отрицательные / Action items

- Проверка стоит на объявлении **переменной**; столкновение имени типа с именем
  функции или состояния не измерялось — граница названа.

### Acceptance criteria

1. Столкновение даёт `ST-023`, называющий оба имени.
2. Регистр не спасает (`PAIR` тоже отвергается).
3. Контрпример: непересекающееся имя переводится, `iec2c` вывод принимает.
4. Код внесён в реестр и в сводную таблицу приложения (гейт 0290).
5. Вывод корпуса не изменился; предкоммит зелёный.
