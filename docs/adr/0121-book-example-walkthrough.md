# ADR 0121: Разбор примеров в разделах с упором на тему

- **Status:** Accepted
- **Date:** 2026-07-24
- **Authors:** Архитектор, лид документации
- **Related issues:** [Фича 0121](../features/0121-book-example-walkthrough.md); дополняет блок «Пример» разделов (правило 24), соседствует с блоком «Частые ошибки» (правило 26)

## Context

Заказчик запросил: в блоке «Пример» каждого раздела **разобрать**, что пример
делает, с **упором на тему раздела** (в «Типах» — какие типы у переменных, где
вывод и какого типа, где сравнение; определение моделей/состояний/функций —
вскользь). Сейчас у примеров лишь короткая вводная фраза.

## Decision Drivers

1. **Обучающая ценность.** Читатель видит не просто код, а объяснение — что здесь
   иллюстрирует именно тему раздела.
2. **Фокус на теме.** Разбор не должен растекаться на обвязку (модель/состояния),
   если раздел не о ней.
3. **Единый формат** для всех разделов, в т. ч. будущих.

## Considered Options

- **(A) Абзац-разбор «Разбор (с точки зрения …)» сразу после примера**, перед
  блоком «Частые ошибки». Подробно — конструкции темы, вскользь — обвязка.
  **Выбрано.**
- **(B) Построчные комментарии в самом `.takt`** — раздувают пример, дублируют
  подсветку, тема тонет в деталях.
- **(C) Отдельный раздел «Разбор»** — избыточно дробит структуру.

## Decision

Заводится **правило 27** (`docs/RULE.md`): блок «Пример» сопровождается разбором с
упором на тему раздела (конструкции темы — подробно, обвязка — вскользь), сразу
после включённого примера. Retrofit разделов 02–07.

## Consequences

### Положительные

- Примеры «читаются» — видно, что именно они демонстрируют по теме.
- Формат обязателен (правило 27) — новые разделы не забудут разбор.

### Отрицательные / Action items

- При смене примера в разделе разбор нужно синхронизировать.
- Разделы 08–16 получат разбор при наполнении (правило 27).

### Acceptance criteria

1. Разделы 02–07 имеют разбор примера с упором на тему.
2. Правило 27 в `docs/RULE.md`.
3. Сборка PDF (`xelatex`) чистая; `precheck.sh` зелёный.
