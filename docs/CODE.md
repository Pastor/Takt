# Требования к написанию Rust-кода

Чек-лист, основанный на «Rust Design Patterns». При генерации Rust-кода соблюдай
приведённые правила. Формат: **Делай** — обязательные практики, **Избегай** —
антипаттерны.

## Общие принципы

- Следуй идиомам сообщества; отступай от них только при явной причине.
- Придерживайся SOLID, DRY, KISS и YAGNI: не добавляй абстракции и обобщённость
  «на будущее», пока в них нет реальной потребности.
- Выбирай паттерн осознанно: сначала «зачем» (какой компромисс решаешь), потом «как».
- Опирайся на систему типов и borrow checker, а не борись с ними.
- Предпочитай выражения инструкциям, а неизменяемость — изменяемости.

## Аргументы и типы

- **Делай:** принимай заимствованные срезовые типы вместо владеемых:
  `&str` вместо `&String`, `&[T]` вместо `&Vec<T>`, `&T` вместо `&Box<T>`.
- **Делай:** возвращай владеемые типы (`String`, `Vec<T>`), принимай — заимствованные.
- **Делай:** при ошибке в методе, потребляющем `self`/аргумент по значению,
  возвращай этот аргумент обратно (например, в варианте `Err`), чтобы вызывающий
  не терял владение.
- **Делай:** используй `Option` как итератор (`for x in option`, `.iter()`,
  `.chain(option)`) вместо ручной проверки `match`/`if let` там, где это уместно.

## Строки

- **Делай:** собирай/форматируй строки через `format!`, а не через цепочки `push_str`
  и конкатенацию `+`, когда важна читаемость.
- **Делай:** для конкатенации в горячем пути заранее резервируй ёмкость
  (`String::with_capacity`).

## Конструирование объектов

- **Делай:** предоставляй ассоциированную функцию `new()` для конструирования.
- **Делай:** реализуй трейт `Default` (по возможности через `#[derive(Default)]`)
  и используй `..Default::default()` для частичной инициализации.
- **Делай:** для типов с множеством опциональных параметров применяй паттерн
  **Builder** (пошаговая настройка + финальный `build()`).
- **Делай:** используй **Newtype** (`struct Wrapper(Inner);`) для типобезопасности,
  сокрытия реализации и обхода orphan rule.

## Владение, изменяемость, ресурсы

- **Делай:** ограничивай изменяемость по времени — делай значение `mut` только на
  этапе построения, затем «замораживай» через shadowing или вложенный блок.
- **Делай:** управляй ресурсами через RAII: захват в конструкторе, освобождение в
  `Drop`; для доступа к защищённым данным используй тип-страж (guard).
- **Делай:** для очистки/финализации, которая должна выполниться при любом выходе
  из области видимости, полагайся на `Drop`, а не на ручные вызовы.
- **Делай:** при изменении варианта `enum` с переносом владения используй
  `mem::take` / `mem::replace`, чтобы забрать значение без клонирования.
- **Избегай:** `.clone()` только ради того, чтобы «успокоить» borrow checker —
  сначала пересмотри структуру заимствований и времена жизни.

## Структуры и заимствования

- **Делай:** декомпозируй крупную структуру на части (или заимствуй отдельные поля),
  чтобы допускать независимые изменяемые заимствования разных полей.
- **Делай:** реализуй `Deref`/`DerefMut` только для собственных умных указателей и
  владеющих коллекций (доступ к содержимому), но не для эмуляции наследования.

## Диспетчеризация и обобщения

- **Делай:** предпочитай статическую диспетчеризацию (обобщения, `impl Trait`);
  переходи на динамическую (`dyn Trait`) при необходимости гетерогенности/гибкости.
- **Делай:** для условного выбора реализации без аллокаций применяй динамическую
  диспетчеризацию на стеке (отложенная инициализация переменной перед `&dyn`).
- **Делай:** прячь громоздкие наборы трейт-ограничений за собственным
  «маркер»-трейтом с blanket-реализацией, чтобы упростить сигнатуры.
- **Делай:** передавай замыкания, явно связывая захватываемые переменные через
  `let` перед `move`-замыканием (захватывай только нужное, а не весь контекст).

## Паттерны поведения

- **Делай:** для инкапсуляции действий применяй **Command** (трейт-объекты,
  указатели на функции или `Fn`-объекты).
- **Делай:** для взаимозаменяемых алгоритмов используй **Strategy** (трейт +
  сменные реализации), внедряя зависимость извне.
- **Делай:** для обхода разнородной структуры с разделением логики применяй
  **Visitor**; для вычисления по грамматике — **Interpreter**.
- **Делай:** для пошаговой обработки/трансформации коллекций и деревьев используй
  **Fold** (аккумуляция результата обходом).

## Расширяемость и API

- **Делай:** помечай публичные `enum`/`struct` атрибутом `#[non_exhaustive]`, если
  планируешь добавлять варианты/поля без слома обратной совместимости.
- **Делай:** используй приватные поля, чтобы запретить внешнее конструирование через
  литерал структуры и сохранить свободу изменений.
- **Делай:** дроби функциональность на небольшие крейты с чёткой зоной ответственности
  вместо одного монолитного крейта.

## Unsafe и FFI

- **Делай:** заключай `unsafe`-код в маленькие модули с безопасным публичным
  интерфейсом, поддерживающим инварианты.
- **Делай:** в FFI выражай ошибки идиоматично — плоские/структурированные `enum`,
  коды возврата, отдельные типы ошибок; не пробрасывай панику через границу FFI.
- **Делай:** на границе FFI принимай строки как `&str`/`&CStr`, а пути — как
  `Path`/`OsStr`; для передачи наружу владей `CString` и следи за её временем жизни.
- **Делай:** проектируй FFI как объектно-ориентированный API (непрозрачные указатели)
  и консолидируй связанные типы в обёртки.

## Документация

- **Делай:** пиши примеры в doc-комментариях как компилируемые doctests; прячь
  вспомогательный код строками с префиксом `#`, оставляя на виду только суть.

## Коды диагностик

- **Делай:** новый код диагностики (`SE-036`, `CC-014`, `SIM-010`, …) — **сперва
  в реестр** [`docs/diagnostics/README.md`](diagnostics/README.md) (единый
  источник истины, фича 0077), затем в `.with_code("…")`. Бери **следующий
  свободный** номер в нужном префиксе (гейт печатает максимальный занятый). Формат
  строго `XX-NNN`. Код без записи в реестре завалит `check-diagnostic-codes.sh`
  (в `precheck.sh`) — это и есть защита от коллизий вроде дважды занятого `CC-014`.
- **Не делай:** не переиспользуй выведенный номер под другой смысл; помечай его в
  реестре `RESERVED`/`RETIRED`, если он больше не эмитируется.

## Функциональный стиль

- **Делай:** предпочитай чистые функции, итераторы и комбинаторы (`map`, `filter`,
  `fold`) циклам с мутабельным состоянием, где это повышает ясность.
- **Делай:** моделируй обобщённое поведение через трейты как «классы типов».

## Чего избегать (антипаттерны)

- **Не** используй `#![deny(warnings)]` в публичных крейтах — это ломает сборку при
  обновлении компилятора; настраивай lint-и точечно и в CI.
- **Не** применяй `Deref` для имитации наследования и «полиморфизма» — это скрывает
  API и путает читателя.
- **Не** клонируй данные ради обхода borrow checker как первое решение.
- **Не** вводи преждевременные обобщения, трейты и слои абстракции (нарушение YAGNI).
- **Не** пробрасывай `panic!`/unwind через границу FFI.
