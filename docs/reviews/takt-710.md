# TAKT-710. Проверка архивных ссылок до правки карточек

Снимок выгрузки — `v2` на `89ba01950875cfed51c99dad3c27fc7578eaf4d5`.
Вершина сверена с GitHub. Архив — `3c154a13d979b18312a1250ebfbe3db2fa5247d3`.
Вход — 698 исторических карточек `TAKT-1`–`TAKT-698`. Результат по каждому
вхождению выдаёт [скрипт аудита](takt-710-audit.py).

## Правило адресации

Исходный путь карточки берётся из её строки «Источник» и сверяется с
архивом. Старый адрес разрешается от каталога этого файла в архивном
коммите. Для файла используется GitHub `/blob/<полный SHA>/<путь>`,
для каталога — `/tree/<полный SHA>/<путь>`. Путь кодируется по сегментам.
Часть после `#` переносится дословно. Например, в TAKT-10 адрес
`../fixes/0010-01-buchi-acceptance.md` от
`docs/features/0010-verification-ltl.md` указывает на
[архивную карточку исправления](https://github.com/Pastor/Takt/blob/3c154a13d979b18312a1250ebfbe3db2fa5247d3/docs/fixes/0010-01-buchi-acceptance.md).
Адрес `./0021-03-tool/` в TAKT-21 ведёт в [архивный каталог](https://github.com/Pastor/Takt/tree/3c154a13d979b18312a1250ebfbe3db2fa5247d3/docs/features/0021-03-tool).

Абсолютный URL одинаково разрешается из карточки aNaL и из файла в GitHub.
При ссылке на собственный исходник с фрагментом сохраняется смысл
перехода к историческому документу. Так,
`0018-code-guidelines.md#анализ` ведёт в [«Анализ» архивной карточки](https://github.com/Pastor/Takt/blob/3c154a13d979b18312a1250ebfbe3db2fa5247d3/docs/features/0018-code-guidelines.md#анализ).
Локальные ссылки вида `#итог-что-сделано` продолжают указывать на текущую
карточку. Если цель существует и по старому пути, и в выгрузке, адрес
нужно согласовать по смыслу. Таких совпадений в этой выгрузке нет.

Числа относятся к историческим карточкам. В TAKT-707 число 5 225 относится
ко всем относительным ссылкам, которые тогда проверил скрипт проверки ссылок.
Штатная проверка ищет локальную цель. Существование архивной цели и
ориентир для фрагмента проверяет скрипт аудита.

44 записи имеют форму, в которой короткого распознавания ссылки
недостаточно. Например, у TAKT-60 на строке 327 подпись включает
`[bit;N]` внутри кодового спана. Для этой группы нужно сверить, какие
вхождения действительно рендерятся как ссылки, и утвердить точные диапазоны
адресов. По двум записям нет совпадающей строки в исходном архивном файле.
Строка 495 TAKT-32 обрывается на подписи таблицы, строка 453 TAKT-48 —
посреди предложения после ссылки на ADR. Обе цели есть в архиве.
Смысл перехода и ограниченный объём правки этих строк следует сверить
вручную. Аудит сохраняет предложения по всем 46 случаям вместе с причиной
отсрочки.

Для фрагментов скрипт сопоставляет обычные Markdown-заголовки с
предполагаемыми идентификаторами. Проверка на отрисованной странице
нужна для вложенной разметки, явных HTML-якорей, повторов и ссылок на
строки. Среди распознанных фрагментов 1 719 совпали с заголовком и имеют
простую разметку ссылки. Ещё восемь попали в 46 случаев ручной сверки.
[Правила якорей GitHub](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#section-links).

## Согласованная выборка

В aNaL применены все 28 замен. Версии TAKT-10, TAKT-18, TAKT-34
и TAKT-598 стали 5, 2, 2 и 2. На момент заморозки задачи ветка
выгрузки содержала прежние версии. Данные для отката указаны
в комментарии TAKT-710.

| Карточка | ID / версия MCP | Ошибки до → после | Что проверяет |
| --- | --- | ---: | --- |
| TAKT-10 | 1064 / 4 | 2 → 0 | Соседняя фича и переход в `docs/fixes` из одной строки таблицы |
| TAKT-18 | 1072 / 1 | 16 → 0 | Шесть фрагментов, в том числе повторные переходы к одному заголовку |
| TAKT-34 | 1088 / 1 | 8 → 0 | Неизменный локальный якорь `#итог-что-сделано` |
| TAKT-598 | 1652 / 1 | 2 → 0 | Переходы из карточки исправления в `docs/features` |

Все четыре тела прочитаны через MCP. Версии совпали с выгрузкой,
Markdown совпал после удаления внешних пробельных символов при сравнении.
Проекция прошла штатную проверку ссылок на временных локальных копиях.
Заменялись только диапазоны адресов. Обратная подстановка по смещениям
восстановила исходные тела дословно. В локальной проекции также совпала
шапка OKF. Прямые испытания переходов в aNaL и в повторной выгрузке GitHub
остаются этапом согласованной пробы. Для архивной страницы TAKT-18
веб-чтение вернуло ошибку загрузки, поэтому наличие фрагмента подтверждено
по архивному Markdown.

## Воспроизведение

Из корня рабочего дерева запустить:

```sh
python3 docs/reviews/takt-710-audit.py --sample-diff \
  >/tmp/takt-710-links.tsv 2>/tmp/takt-710-sample.txt
wc -l /tmp/takt-710-links.tsv
tail -n 1 /tmp/takt-710-sample.txt
scripts/check-links.py
```

Ожидаются 5 151 строка TSV с заголовком и 5 150 ошибок штатной проверки
в рабочем дереве. TSV содержит ключ, ID, версию выгрузки, строку и колонку,
исходный путь, старый адрес, архивный путь, предложение, фрагмент, причину
и длину тела. Для чтения исходной карточки и цели можно использовать
`git show <SHA>:<путь>`. Вывод `--sample-diff` содержит только четыре
локальные проекции. Скрипт проверяет подмножество синтаксиса штатной
проверки и предназначен для отчёта. Ссылки с многострочными подписями,
ссылочные определения, HTML и код требуют отдельного разбора при
подготовке инструмента записи.

## Согласованная проба, повторы и откат

1. Для утверждённых карточек перечитать MCP `task` и сохранить дословное
   тело, его SHA-256, версию и поля карточки. Снимок в TSV показывает версию
   выгрузки. Для записи и отката использовать снимок MCP, сделанный прямо
   перед пробой. Копию Markdown и журнал хранить вне публикуемой выгрузки.
2. Создать предлагаемый Markdown поверх тела из свежего снимка, сохраняя
   текст, переводы строк, внешние адреса, ссылки на вложения и локальные
   якоря. Проверить обратную замену, лимит, набор точных изменённых
   диапазонов и хеш нового тела. При уже совпадающем новом теле пропустить
   запись. При ином теле, версии или конфликте остановить карточку на
   сверку и заново построить diff.
3. Передать в MCP `edit` только `id`, свежую `version`, `body` и
   `model`. После каждого ответа перечитать задачу, сверить хеш и
   зафиксировать версию результата. Сверить статус, заголовок, приоритет,
   отчёт, связи, зависимости, комментарии и адреса вложений. Версия,
   время обновления и контрольная сумма OKF ожидаемо обновятся.
4. После штатной выгрузки aNaL сравнить Markdown и остальные поля OKF
   с исходным снимком. В обоих интерфейсах открыть ссылки четырёх
   карточек. Проверить попадание к нужному заголовку, переходы на файлы,
   локальный якорь и ссылки на вложения, если они есть в карточке.
   Для выборки цель проверки — исчезновение 28 исходных ошибок.
   После полной правки нужен нулевой итог `scripts/check-links.py`.
   Внешние URL и фрагменты эта проверка пропускает, поэтому нужен
   отдельный просмотр переходов. C1 остаётся самостоятельной проверкой:
   TAKT-707 сообщил о 211 находках в выгрузке и одной в Rust-тесте.
5. Для отката взять сохранённое исходное тело. Проверить, что текущая
   версия соответствует записанному результату и что хеш совпадает
   с хешем проекции. Вернуть только `body` через версионный `edit`.
   При расхождении предусмотреть ручную сверку с сохранёнными телами.
   Дождаться штатной выгрузки и сверить хеш восстановленного Markdown.
   У отката будет новая версия и запись в истории.
