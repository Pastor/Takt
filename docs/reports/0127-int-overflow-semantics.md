# Отчёт о тестировании фичи 0127: Единая семантика переполнения целых во всех целях

> Фича: [../features/0127-int-overflow-semantics.md](../features/0127-int-overflow-semantics.md) · тест-план: [../tests/0127-int-overflow-semantics.md](../tests/0127-int-overflow-semantics.md) · ADR: [../adr/0127-int-overflow-semantics.md](../adr/0127-int-overflow-semantics.md)

## Резюме

**Вердикт: ✅ ПРОЙДЕН.** Одиннадцать проверок тест-плана выполнены. Дефектов в
реализации не найдено; по ходу потребовались две **вынужденные** правки
(разделение тестового модуля, упёршегося в лимит размера, и обновление
пиннинга в тесте фичи 0083) — обе описаны ниже.

**Окружение:** macOS (Darwin 25.5.0), толчейн `1.97.1` из `rust-toolchain.toml`;
инструменты — `cc`/`cmake`/`ninja`, `rustc`, `verilator`, `yosys`,
MatIEC `iec2c`. Дата прогона — 2026-07-27.

## Результаты по функциональности

- **Правило соблюдается всеми целями** (A3–A7). Впервые проверено поведение цели
  `st`: `USINT` именно **оборачивается** (`255 → 0`), а не насыщается и не даёт
  отказ.
- **Знаковый случай не «починен» молча** (A2, A9): обёртка для знаковых не
  печатается, эталон по-прежнему диагностирует.
- **Сторож настоящий** (A8): временный откат `is_unsigned_int` на `false` уронил
  сверку `rust` с той самой паникой, ради которой фича заводилась. Проверка
  сделана вручную и **не** оставлена в коде — она мутирует генератор.
- **Правило названо пользователю** (A10). Попутно **исправлено неверное
  утверждение** документации: прежняя фраза «арифметика выполняется по модулю
  разрядности типа» распространяла обёртку и на знаковые типы, где её нет.

## Влияние на порождённый корпус

Изменились два файла — `examples/generated/rust/comprehensive.rs` и
`stacker.rs`: беззнаковая арифметика печатается обёрткой
(`self.temperature -= 1;` → `self.temperature = self.temperature.wrapping_sub(1);`
и подобные). Вывод целей `c`, `st`, `sv`, `plantuml` **байт-в-байт неизменен** —
там правило выполнялось само.

## Вынужденные правки (не дефекты фичи)

1. **`conformance_c_tests.rs` упёрся в лимит размера** (1002 строки при лимите
   1000) — гейт сработал правильно. Тест переполнения вынесен в подмодуль
   `conformance_c_tests/overflow.rs` (`#[path]`, приём фичи 0088), файл вернулся
   к 960 строкам.
2. **Тест фичи 0083** пиннил строку `self.n += 1;` в порождённом Rust. Ожидание
   обновлено на `self.n = self.n.wrapping_add(1);`; смысл проверки (тело
   model-level `always` стоит **до** диспетчеризации) не изменился.

## Примеры и контрпримеры (правило 16)

Сформированы в тест-плане и перенесены в документацию: пример определённого
поведения (счётчик `u8`, переходящий через край) и контрпример ошибочной
программы (`i8`, `127 + 1` → `SIM-003`) — оба в разделе «Типы» → «Переполнение».

## Выводы и дальнейшие шаги

Фича закрывается со статусом **ГОТОВО**. Версия языка **не поднимается**: цикл
`0.6.0` открыт фичей 0128, и по правилу 22 последующие фичи цикла вносят
изменения в него же.

**Открытые следствия (перенесены из ADR):**

1. **Знаковое переполнение остаётся разноголосым** между целями (симулятор —
   диагностика, C — UB, Rust — паника/обёртка по профилю, SV — обёртка). Это
   **названо** правилом «программа ошибочна», но не устранено: полное
   устранение (проверки в рантайме у всех целей) отвергнуто по цене и
   невыразимости в RTL.
2. **Закрытие 0127 разблокирует [0134](../features/0134-language-time-model.md)**
   (модель времени): разрядность счётчика времени выбирает компилятор, и теперь
   у этого выбора есть определённая семантика переполнения.
