# Отчёт о тестировании фичи 0063: порт `en` (clock enable) для цели `sv`

> Фича: [../features/0063-sv-clock-enable.md](../features/0063-sv-clock-enable.md) · тест-план: [../tests/0063-sv-clock-enable.md](../tests/0063-sv-clock-enable.md) · ADR: [../adr/0063-sv-clock-enable.md](../adr/0063-sv-clock-enable.md)

- **Дата:** 2026-07-19
- **Окружение:** macOS (darwin 25.5.0), Verilator 5.050, yosys 0.67+post,
  cargo nightly 1.99. Оба гейта целевого языка доступны.
- **Вердикт:** **готово.** SV-юниты `grammar` (61) и потактовая сверка
  `conformance_sv_tests` (11, +1 к базе) зелёные; оба гейта принимают вывод с
  `en`; семантика `en` доказана **симуляцией**, а не только гейтом.

## Сверка с критериями приёмки

| # | Критерий | Результат | Способ |
|---|---|---|---|
| A1 | Порт `en = 1'b1`; verilator `-Wall` **и** yosys принимают | ✅ | `verilator --lint-only -Wall` (exit 0, 0 предупреждений) + `yosys synth -flatten` (exit 0) на `stacker`/`regulator` |
| A2 | Неподключённый `en` ≡ `en = 1'b1` **побитово**; `en = 0` — стоит | ✅ | `clock_enable_gates_step_but_not_reset`: 4 экземпляра `conformance_ticks`, `unc == en1` на каждом такте (1,2,3), `en0 == 0` |
| A3 | Потактовая сверка (`en` **не подключён**) — вердикты прежние | ✅ | `conformance_sv_tests` 11 passed; харнесс `sv_trace` инстанцирует `dut` **без** `en` — то есть сверка и есть проверка умолчания |
| A4 | Сброс работает при `en = 0` (правило 3) | ✅ | тот же тест: `dut_rst` (en=1 → n=3), затем `en=0` **и** `rst_n=0` одним фронтом → `n` вернулся к 0 |
| A5 | Модель с портом `en` → `SV-007` (правило 4) | ✅ | `service_names_are_sv007` включает `"en"`; ручная проба `in en: bit; … y := en;` → `SV-007` с полным пояснением |
| A6 | `is_done` от `en` не зависит | ✅ | `assign is_done = (state == …_END)` — комбинационный, `en` в нём не участвует (по построению) |
| A7 | Вывод прочих целей побайтово прежний; версия не поднята | ✅ | `git status examples/generated` — изменились **только** 4 `*.sv` (порт `en` + `end else if (en)`); язык 0.x не менялся |

## Реализация (одна тема, три точки)

1. **Порт** — `emit_module_header` (`sv_module.rs`): после `rst_n` печатается
   `input logic en = 1'b1` с комментарием, что порт **не** обязателен.
2. **Гейт шага** — `emit_ff` (`sv_fsm.rs`): `end else begin` → `end else if (en) begin`.
   Ветвь `if (!rst_n)` выше — **не** тронута (правило 3: `en` не гейтит сброс).
3. **Зарезервированное имя** — `"en"` добавлено в `RESERVED_NAMES`
   (`sv_module.rs`); текст `SV-007` дополнен упоминанием `en`.

## Отклонения от плана (с обоснованием)

- **Список чувствительности `always_ff` НЕ менялся на `posedge clk or negedge
  rst_n`** (вопреки буквальной записи задачи 0063-01, п. 2). Цель `sv` использует
  **синхронный** сброс (`always_ff @(posedge clk)`, охраняется `mod.rs::
  reset_is_synchronous`); нормативное правило 3 ADR требует лишь `if (!rst_n) …
  else if (en) …`, что синхронный сброс удовлетворяет: ветвь сброса вычисляется
  на фронте `clk` первой, независимо от `en`. Запись задачи `negedge rst_n` —
  иллюстрация типового async-паттерна, а не требование к этому бэкенду.
- **A2/A4 — один тестбенч, а не два прогона синтеза.** Семантика проверена
  `verilator --binary` (именно им гоняет основную сверку `conformance_sv_tests`);
  синтезная проба `-flatten` (23/23/1 ячейка) выполнена вручную при проработке
  ADR и в автотест не вынесена (сборка verilator дешевле и покрывает семантику).

## Найденные дефекты

Нет. Аддитивность подтверждена: `sv_trace` не подключает `en`, и все прежние
сверки остались зелёными без единой правки.

## Примеры и контрпримеры (правило 16)

- **Пример:** `dut (.clk(clk), .rst_n(rst_n), .is_done(done))` — `en` не
  подключён, поведение прежнее (умолчание `1'b1`); либо `dut (…, .en(divider_en))`
  — модель тактируется реже домена.
- **Контрпример:** `in en: bit; … y := en;` → `SV-007` (имя зарезервировано целью;
  модель остаётся валидной для `c`/`c-hal`/`plantuml`/`st`/`rust`).
