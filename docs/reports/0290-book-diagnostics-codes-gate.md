## Мутационные проверки (сторож не бутафорский)

Прогнаны все три мутации тест-плана — каждая обязана валить проверку:

| # | Мутация | Итог |
|---|---|---|
| М1 | из гейта изъято сравнение `registry - appendix` | сторож упал: 2 проверки провалены ✅ |
| М2 | изъято сравнение `appendix - registry` | сторож упал: «лишний код НЕ пойман» ✅ |
| М3 | коды документа читаются грепом по всему файлу, а не по сводной таблице | пропажа `SE-089` из сводной таблицы **не поймана** (гейт зелёный) ✅ |

М3 — не теория: ровно так расхождение и занижалось до 18 кодов, потому что у
четырнадцати из них есть разбор во второй части приложения.

## Что нашёл прогон (сверх текста кандидата)

1. **Расхождение больше заявленного: 32 кода, а не 19.** Греп по всему файлу
   приложения показывал 18 отсутствующих, но четырнадцать кодов (`SE-075`,
   `SE-077`…`SE-080`, `SE-083`…`SE-089`, `ST-020`, `SV-018`) имели **разбор**,
   не значась в **сводной таблице**. Вход в справочник — таблица, и по ней их
   было не найти.
2. **Обратное направление, которого кандидат не называл.** `SE-066`
   («периодическое действие `every` пока не реализовано») выведен задачей
   0134-09 — справочник обещал диагностику, которой инструмент не выдаёт
   никогда. Это ложь, а не пробел, и она дороже.
3. **Третий список кандидата не подтвердился.** README упоминает 119 кодов, и
   **все** они есть в реестре; списком кодов README не является. Запись
   кандидата в этой части была неверна.
4. **Ловушка замера.** Наивный греп по реестру ловит `CC-009` и `SE-024` из
   прозы про пропуски номеров — коды, которых не существует. Гейт читает
   строки таблиц; первая редакция замера дала 20 вместо 18 именно поэтому.
