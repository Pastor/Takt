## Что нашли **не** тесты

Самое важное наблюдение отчёта: **оба серьёзных дефекта фичи нашлись не тестами.**
Тесты были зелёными, корпус форматировался, A1/A3 проходили — а дефекты
обнаружились при **чтении диффа глазами** после пробного прогона по `examples/`:

1. **`while` молча переписывался в `loop`.** Формально A3 держался: в грамматике
   это синонимы, АСД **тот же самый**. Инвариант «семантика сохранена» такое
   пропускает по построению — и пропустил бы навсегда.
2. **Пустая строка между группами комментариев терялась** — шапка файла слипалась
   с доком следующего элемента. И текст, и семантика оставались корректными;
   терялся только замысел автора.

Вывод для будущих фич: пробный прогон инструмента на **реальном коде проекта** с
просмотром диффа ловит то, чего не ловит ни один инвариант. Инвариант проверяет
то, что мы догадались сформулировать.

Третий дефект — **нарушение идемпотентности** на `type_alias_inference.lam` —
поймал именно harness. Причина оказалась в допущении: `fn.loc` покрывает только
**сигнатуру** (`Source(0, 14, 28)` = `fn get() -> u8`), тело живёт в отдельном
`loc`, поэтому замер «зазора от `loc.end`» проезжал через всё тело. Переделано на
скан назад от узла — допущение устранено, а не обойдено.

## Уточнения ADR по итогам реализации

| Что предполагал ADR | Что оказалось |
|---|---|
| Привязка комментариев — «эвристика, требующая аккуратности» (главный риск) | Риск **снят конструктивно**: лексер хранит текст комментария **сырым** (вместе с `//`, `/* */`), а `Location` есть и у комментариев, и у узлов — сшивание по смещениям работает без эвристик |
| «Форматтер меняет только раскладку» (драйвер 3) | Печать от АСД этого **не позволяла**: синонимы (`while`/`loop`, `: [Guard]`/`:`) стирались на разборе. Потребовалось хранить выбор автора в АСД — **решение заказчика, вариант 2** |
| Скобки — риск семантического сдвига | `Parenthesis` — **явный узел** АСД, поэтому скобки автора сохраняются, а приоритеты пересчитывать не нужно: A3 достигнут почти бесплатно |
| «Reformat Code в IntelliJ поверх ядра» (задача 04) | **Невозможно**: `LamParser` — плоский разборщик (ADR 0023), а `FormattingModelBuilder` работает по структуре PSI. Вынесено в бэклог |
| Декомпозиция 01 (ядро) и 02 (комментарии) — разные задачи | Фактически **одна**: комментарии содержат **136 из 158** файлов, без них ядро непроверяемо (корпус форматировался в 0 файлов) |

## Известные ограничения (не препятствуют закрытию)

- **Фикстуры `tests/data/` не нормализованы** — осознанное сужение: часть тестов
  (прежде всего LSP) завязана на их раскладку и позиции. `precheck` проверяет
  только `examples/`.
- **Канон разворачивает блоки в многострочные** — детерминированно и
  идемпотентно, но `match` в примерах стал многословнее
  (`Auto => { log(x); }` → три строки). Кандидат на правило «короткий блок
  остаётся в одну строку» — вынести в бэклог, если стиль не устроит.
- **IntelliJ** — в бэклоге (см. выше).
