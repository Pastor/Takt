## Результаты по функциональности

Приёмы выноса (по классам файлов):

- **Генераторы** (0088-01/02/03/09): init-группа C → `c_model_init.rs`; печатники
  Rust → `rust_cond.rs`/`rust_tick.rs`; inline-тесты C → `c_source/tests/part2.rs`.
  Вывод целей `c`/`rust` байт-в-байт неизменен.
- **Парсер/лексер** (0088-04/05): `enum Token` → `parser/token.rs`; узел
  `Expression` → `parser/ast_expr.rs`.
- **Тесты** (0088-06/07/08/10/11): директория-подмодуль (`part2`/`more`) с
  `use super::*`; крупнейший файл проекта `semantic_tests.rs` (5015) → 5
  подмодулей. Ловушка 0088-11: два top-level `use` из середины файла подняты в
  шапку родителя (иначе `use super::*` не раздаёт их сиблингам).
- **Симуляция** (0088-12): `unit/viewport.rs` (1455) → вынос самодостаточного
  подмодуля `graph` в файл; `create_svg` **не тронут** → SVG-вывод неизменен.
  ⚠️ Врезка «viewport — одна функция ~1128 строк» оказалась неверной
  (`create_svg` ~550 строк); дробление тела и связанный с ним риск для SVG **не
  потребовались**.

Примеры/контрпримеры языка (правило 16) — **неприменимо**: фича язык не меняет.

## Выводы и дальнейшие шаги

Фича закрывается (`ГОТОВО`). Остаток — **6 файлов** (ядро семантики `tree`/`mod`/
`expression`/`type_inference` + пришпиленные `lamc`/`lib`): их вынос требует

фиксы не заводились.
