цели `c`, `st`, `rust`, `sv` (и HAL/MMIO-варианты) исполняют собственные рёбра
состояния-композиции так же, как эталон.

изменились.

## Замер 2026-08-19 (до правки)

| Вход | Эталон | Все восемь целей |
|---|---|---|
| условие истинно в момент завершения | → `Finish` | → `END` |
| условие ложно всегда | **остаётся** в состоянии | → `END` |
| `next Finish;` (контроль) | → `Finish` | → `Finish` |

⚠️ **Контроль отделил предмет от формы:** замер снят и с `S(Модель) = Состояние`,
и с обычным условием (`flag = 3`) — теряется в обоих случаях. Третий контроль
(`next`) показал, что механизм перехода у целей есть; недоставало печати рёбер.

## Находка сверх ожидаемого: карта не знала о таких состояниях

Правка целей одна не помогла бы цели `rust`: состояния, достижимого из
композиции по `ref`, **не было в карте** — `minimap::visit_state` в ветви
`Implement` клал в обход только `next`. В выводе `rust` не существовало ни
варианта перечисления, ни ветви `match`. Исправлено в общем слое, то есть для
всех целей сразу.

Побочно снята **копия** логики перехода в цели `c` (ветвь одиночной модели
`StateExtend::Model` несла своё «`next` либо `END`») — класс, знакомый по 0296.
