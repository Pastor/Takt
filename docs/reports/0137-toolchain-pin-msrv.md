## Найденные дефекты

**Д1 (окружение, не код). Неполная установка толчейна — молча.** После первой
установки пина сборка падала с `E0463: can't find crate for std`, при том что
`rustup component list --toolchain 1.97.1` показывал `rust-std … (installed)`:
каталог `lib/rustlib/aarch64-apple-darwin/lib` был **пуст** (0 файлов против 59 у
исправного толчейна), а `rustup component add rust-std` отвечал «up to date» и
ничего не менял.

- **Устранение:** `rustup toolchain uninstall 1.97.1` +
  `rustup toolchain install 1.97.1 --profile minimal -c rustfmt -c clippy`.
- **Профилактика:** компонент `rust-std` перечислен в `rust-toolchain.toml`
  **явно**, а диагностика («посчитай файлы в `$(rustc --print sysroot)/lib/rustlib/<target>/lib`»)
  записана в задаче [0137-01](../development/0137-01-toolchain-pin-msrv.md).
- **Класс:** дефект инструментария rustup, а не проекта; отдельного фикса
  (`docs/fixes/`) не заводилось.

## Выводы и дальнейшие шаги

Фича закрывается со статусом **ГОТОВО**. Примеров и контрпримеров языка не
формировалось: правило 16 к инфраструктурной фиче неприменимо (язык не
затронут) — это зафиксировано в тест-плане, где вместо них приведены
контрпримеры **процедуры проверки** (зелёный `precheck.sh` при живом `+nightly`
считался бы провалом).

**Открытые действия (перенесены из ADR):**

1. **Нижняя граница MSRV не исследована** — объявлена версия пина. Если появится
   потребитель с более старым компилятором, границу нужно измерять отдельно.
2. **CI живьём не проверен** — прогоны GitHub Actions заблокированы по биллингу
   (известная проблема, кандидат «Дожать CI-верификацию 0090»). При
   разблокировке убедиться, что rustup на раннере ставит пин из файла.
3. **Подъём версии — ручной ритуал:** правка `rust-toolchain.toml` отдельным
   коммитом + полный `./scripts/precheck.sh`.
