# Отчёт о тестировании фичи 0045: Бэкенд генерации в SystemVerilog

> Фича: [../features/0045-sv-backend.md](../features/0045-sv-backend.md) · тест-план: [../tests/0045-sv-backend.md](../tests/0045-sv-backend.md) · ADR: [../adr/0045-sv-backend.md](../adr/0045-sv-backend.md) · анализ: [../analyze/0045-sv-backend.md](../analyze/0045-sv-backend.md)

## Резюме

**Пройдено. Фича готова к закрытию (`ГОТОВО`).**

Цель `lamc compile -t sv` транслирует оба примера, которые обязана
(`stacker.lam`, `elevator_mini.lam`), и оба порождённых модуля проходят **оба**
гейта: `verilator --lint-only -Wall` и `yosys … synth` — код 0, без
предупреждений. Потактовые трассы симулятора и RTL совпадают; главное обещание
цели — **сдвиг такта = 0 на глубинах 1, 2 и 3** — подтверждено автоматическим
тестом против настоящего RTL, а не пробой.

`./scripts/precheck.sh` зелёный целиком; `cargo test -- --test-threads=1` —
**1882 теста**, из них 57 юнит-тестов бэкенда и 5 тестов сверки. `cargo clippy`
по `generator/sv/` — без предупреждений. Регресса нет: цели
`c`/`c-hal`/`plantuml`/`st`/`st-at`/`rust` не тронуты, `grammar.lalrpop` и версия
языка (0.3.0) не менялись.

Дефектов, требующих `docs/fixes/`, не выявлено: всё найденное исправлено в ходе
разработки. Однако **проработка (ADR и планы задач) в шести местах разошлась с
фактом** — см. «Выводы».

## Примеры и контрпримеры (правило 16)

**Примеры** — в README, раздел «Генерация SystemVerilog»: заголовок модуля с
`clk`/`rst_n`, ветвь сброса со стартовыми состояниями всех уровней, фрагмент
`always_comb` под-модели `LiftController` (**приведён дословно** из
`examples/generated/sv/stacker.sv`), таблица отображения типов, сводная таблица
шести целей.

**Контрпримеры** — проверены на живых моделях и юнит-тестами, **на код
диагностики, а не на текст**:

| Вход | Код | Проверено |
|---|---|---|
| `var x: float;` | `SV-003` | `rational_is_sv003_not_real` |
| `inout p: bit;` | `SV-006` | `lamc -t sv` вживую + `collect_ports` |
| `in clk: bit;` (и `rst_n`/`is_done`/`state`/`state_next`) | `SV-007` | `service_names_are_sv007` + вживую |
| `in fork: bit;` (и `wire`/`reg`/`always`/`begin`/`end`/`time`/`edge`) | `SV-012` | `sv_keywords_are_sv012` + вживую |
| `extern fn` (`elevator.lam`, 8 шт.) | `SV-005` | прогон корпуса |
| цикл `for` (`comprehensive.lam`) | `SV-002` | прогон корпуса |
| досрочный возврат (`extend_complex.lam`) | `SV-002` | прогон корпуса |
| `Array(0, u8)`, `Integer{0}`, перечисление без вариантов | `SV-004` | юнит-тесты |
| 7 внутренних/неразрешённых узлов `TypeNode` | `SV-002` | `uncovered_nodes_are_sv002` |

**Контрпример-негатив (ключевой):** модели с `inout`, портом `clk` и портом
`fork` компилируются целью `-t c` с кодом **0**. То есть все запреты принадлежат
**цели**, а язык не тронут — что и утверждают сами диагностики (`SV-007`/`SV-012`
называют цели, где модель по-прежнему валидна; закреплено тестом
`sv007_explains_that_language_is_intact`).

## Выводы и дальнейшие шаги

**Проверяемость цели подтвердилась полностью** — и оказалась главным активом
фичи. Обещание карточки («в отличие от 0041, проверяемость доказана до начала
разработки») выполнено: оба инструмента были установлены и опробованы **до**
написания кода, и это дало возможность ловить дефекты пробой, а не отладкой.

**Тезис «гейтов должно быть два» подтверждён четырежды**, причём тремя новыми
случаями сверх двух, известных из ADR:

| Дефект | `verilator --lint-only -Wall` | `yosys … synth` |
|---|---|---|
| `real` в `always_ff` | **принял молча** | поймал |
| комбинационная петля | поймал | **синтезировал молча** |
| `return` в функции (новое) | **принял молча** | поймал |
| ширина перечисления мала (новое) | поймал | **синтезировал молча** |

То есть расхожее «`--lint-only` даёт проверку синтеза» неверно, и убрать любой из
двух инструментов значит ослепнуть на класс дефектов.

**Проработка разошлась с фактом в шести местах.** Все шесть найдены зондами и
исправлены в коде; ни один не потребовал фикса постфактум, но ADR и планы задач
содержат утверждения, которые опровергнуты:

1. **Формула ширины перечисления (ADR, T11)** — `W = ⌈log₂(вариантов)⌉` неверна:
   на реальном `enum Action { Idle = 670 }` (`elevator.lam:121`) даёт
   `logic [0:0]` и `%Error-ENUMITEMWIDTH`. Считается по **диапазону значений**;
   для состояний формула вырождается в исходную, то есть это её замена, а не
   частный случай. **Тот же капкан ранее поймал бэкенды ST и Rust** — третий раз
   подряд.
2. **«Ширина литерала обязательна, иначе `WIDTHEXPAND`» (ADR)** — опровергнуто:
   Verilator принимает голые литералы чисто. Следствие крупное: печатнику **не
   нужен вывод типа в каждом узле** (у цели `st` нужен — `ST-011`).
3. **«`&&` или `&` — решать по типу операнда» (ADR, открытый вопрос)** — решается
   не типом, а **эталоном**: цель `c` печатает `&&` безусловно, и сверка идёт
   против C.
4. **«Все три примера отсекаются по `extern fn`» (план 0045-02)** — до
   `extern fn` у двух из трёх дело не доходит: `comprehensive` отвергается циклом
   `for`, `extend_complex` — досрочным возвратом.
5. **`SV-008` в первой редакции отвергала флагманский пример** —
   `enter { cmd_target_stack := CHARGE_STACK; }`. Карточка утверждала, что цена
   диагностики для корпуса нулевая, и **была права**: «константа» — не только
   литерал, но и `const` модели (становится `localparam`). Ошибалась проверка.
6. **Ветка `_ =>` (план 0045-03)** — была бы не сторожем, а его отключением:
   `#[non_exhaustive]` внутри объявляющего крейта не действует.

**Найдено сверх реестра диагностик — `SV-012`.** Ни ADR, ни план не
предусматривали коллизию имени Lam с ключевым словом SystemVerilog: `in fork:
bit;` язык принимает, цель `c` компилирует, а SV разваливается синтаксической
ошибкой. **Гейт эту дыру не закрывает** — он проверяет корпус, а в корпусе таких
имён нет: красный вывод увидел бы только пользователь, и увидел бы в виде ошибки
чужого инструмента.

**Самый ценный урок — дефект, которого не поймал ни один гейт.** Чтение внутри
такта печаталось как `w_next = v;` вместо `w_next = v_next;`, то есть `w`
получал значение **предыдущего** такта. Оба инструмента SV такой модуль
принимают: он валиден и синтезируем, просто считает не то. Это ровно то
расхождение, ради недопущения которого ADR выбрал two-process. Поймал его
**clippy** — предупреждением `only_used_in_recursion` на параметре `scope`, — то
есть линтер Rust нашёл семантическую ошибку в SystemVerilog. Отсюда вывод,
который стоит перенести на будущие бэкенды: **гейт целевого языка доказывает
валидность вывода, но не его верность**; поведенческую эквивалентность даёт
только потактовая сверка с симулятором, и заводить её нужно **вместе** с
бэкендом, а не после.

**Дальнейшие шаги:** фиксов не требуется. Кандидаты, вынесенные фичей и не
входящие в её объём, — в `FEATURES.md` (fixed-point Q(m.n) как расширение языка;
цель `sv-mmio` с регистровым файлом на шине; порт `en` clock enable;
предупреждение о делителе `SV-009`).
