> Фича: [../features/0281-rust-enum-compare-literal.md](../features/0281-rust-enum-compare-literal.md) · тест-план: [../tests/0281-rust-enum-compare-literal.md](../tests/0281-rust-enum-compare-literal.md) · анализ: [../analyze/0281-rust-enum-compare-literal.md](../analyze/0281-rust-enum-compare-literal.md)

## Резюме

**Пройдено; фича готова к закрытию (`ГОТОВО`).** Семь проверок тест-плана
зелены. Потребовалось **одно попутное исправление — в инструменте замера**
(фикс [0301-02](../fixes/0301-02-probe-type-declaration.md)), без которого
правило 30 исполнить было нельзя. Полный прогон: 3251 тест, ноль провалов;
`./scripts/precheck.sh` зелён.

## Найденные дефекты

**[0301-02](../fixes/0301-02-probe-type-declaration.md) — `probe.sh` падал на
пробе с объявленным типом.** Обнаружен при первом же снятии замера: под
`set -eu` тело цикла проверки 1б кончалось формой `[ … ] && printf`, и при
**отсутствии** совпадения статус 1 ронял весь скрипт. То есть инструмент,
обязательный по правилу 30, не работал на всякой пробе с `struct`/`enum`/`type`
— а сторож этого не видел, потому что отрицательная ветвь проверки не была
покрыта. Исправлено вместе с фичей; в сторож добавлена недостающая ветвь,
мутация «вернуть `&&`-форму» её валит (проверено).

## Выводы и дальнейшие шаги

- Фича закрывается; фикс 0301-02 закрыт вместе с ней.
- **Урок для правила 30:** инструмент снятия замера сам нуждается в
  отрицательных входах. Проверка, у которой покрыта лишь ветвь «ловушка есть»,
  молчит там, где ловушки нет, — и делает это громко, падением.
- **Кандидатов, называющих 0281, не осталось** (правило 28).
