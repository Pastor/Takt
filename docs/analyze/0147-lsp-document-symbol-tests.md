# Анализ фичи 0147: Тесты textDocument/documentSymbol

> Фича: [../features/0147-lsp-document-symbol-tests.md](../features/0147-lsp-document-symbol-tests.md) · ADR: [../adr/0147-lsp-document-symbol-tests.md](../adr/0147-lsp-document-symbol-tests.md) · тест-план: [../tests/0147-lsp-document-symbol-tests.md](../tests/0147-lsp-document-symbol-tests.md)

## Цель и контекст

Реализовать **Option A** ADR 0147: закрыть нулевое покрытие `documentSymbol`
тестами на состав, вложенность и диапазоны символов.

Работа в крейте `takt-lang`: новый файл тестов плюс две точечные правки
`src/lsp/symbols.rs`, найденные зондом. Язык **не меняется**, версия языка не
растёт (правило 22).

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет.
- **Влияние на порядок разработки:** ничего не блокирует. Смежна с открытой
  [0152](../features/0152-semantic-recovery-element-boundary.md) — см. Д2 ниже.

## Что показал зонд (2026-07-29)

Зонд по файлу со **всеми** видами объявлений верхнего уровня (тип, перечисление,
структура, константа, порт, переменная, `cond`, `invariant`, функция,
именованный блок, под-модель, состояния, `import`) дал 13 символов верхнего
уровня. Из фактического вывода сняты все ожидания тестов; из него же вскрылись
три расхождения.

| # | Что | Оценка |
|---|---|---|
| Д1 | у структуры `selection_range` == `range` (всё объявление), у всех прочих — имя | **дефект**, исправлен |
| Д2 | `def.name.clone().unwrap()` в ветви структуры вместо пропуска, как у соседей | **мина**, снята |
| Д3 | инвариант **состояния** символом не становится, инвариант **модели** становится | **пробел**, в объём не взят |

**Д2 сегодня недостижим.** Проверено четырьмя формами испорченного входа
(`struct { … }`, `struct 123 { … }`, `struct state { … }`, порча после валидной
модели): во всех `parse` возвращает `Err`, и `document_symbols` выходит раньше
ветви. Но недостижимость обеспечена **парсером**, а не этим модулем: фича 0152
(восстановление на границе элемента) вернёт `Ok` с восстановленным деревом, и
мина взведётся. Снятие — одна строка, приводящая ветвь к поведению соседних.

**Д3 в объём не взят** сознательно: исправление меняет **состав** панели
структуры, то есть это вопрос к аналитику («нужен ли инвариант состояния в
outline»), а не побочная правка тестовой фичи. Текущее поведение пришпилено
тестом с явным комментарием; находка записана в `FEATURES.md`.

## Требования и проверяемые условия

- **R1. Состав.** Каждое именованное объявление верхнего уровня становится
  символом, и вид (`SymbolKind`) соответствует роду объявления. Порт —
  `PROPERTY`, переменная — `VARIABLE`, константа/`cond`/`invariant` —
  `CONSTANT`, состояние — `CLASS`, под-модель — `MODULE`, блок — `EVENT`.
- **R2. Пропуски намеренны.** `import`, `address`, `clock`, формулы и одиночная
  `;` символами **не** становятся: они не объявляют имени в этом файле.
- **R3. Вложенность.** Под-модель отдаёт элементы детьми (и не дублирует их на
  верхнем уровне), состояние — именованные блоки, перечисление — варианты,
  структура — поля.
- **R4. `selection_range` покрывает имя** и содержится внутри `range`.
- **R5. `range` покрывает объявление целиком** — начинается с его ключевого
  слова.
- **R6. Неразбираемый вход → пустой список, не паника.** Сервер получает файл в
  каждом промежуточном состоянии набора, то есть чаще неразбираемый, чем
  разбираемый.
- **R7. Возможность объявлена клиенту** — иначе реализация мертва: редактор не
  пришлёт запрос.

## Взведённость (A10)

Проверяется тремя мутациями, каждая обязана валить **свой** тест и только его:

| Мутация | Ожидается падение |
|---|---|
| `selection_range` структуры возвращён на объявление | `selection_range_covers_the_name` |
| у состояния нет детей (ветвь блоков отключена) | `state_owns_its_named_blocks` |
| порт печатается как `VARIABLE` | `every_top_level_declaration_becomes_a_symbol` |

## Особенности по обратной совместимости (правило 11)

Тесты **аддитивны**. Правки `symbols.rs` меняют наблюдаемое поведение LSP в
одной точке: `selection_range` структуры теперь указывает на имя, а не на всё
объявление, — то есть переход из панели структуры ставит курсор на имя, как у
всех прочих символов. Это **исправление**, а не смена контракта: спецификация
LSP требует от `selection_range` именно диапазона имени.

Плагины (`extensions/`) своих списков символов не ведут и правок не требуют:
IntelliJ строит структуру собственным PSI, Zed делегирует серверу.

## Риски

- **Риск пришпилить дефект.** Снижается порядком работы: сперва зонд, затем
  правка найденного, и только потом тест. Так и вскрылись Д1 и Д2.
- **Риск теста, который ничего не стережёт.** Снижается мутациями (A10): каждая
  адресно валит свой тест.
- **Хрупкость пиннинга состава.** `syms.len()` придётся править при добавлении
  вида символа — это замысел (состав панели не должен меняться молча), но он
  требует, чтобы сообщение об отказе объясняло, что делать: тест печатает
  фактический список имён.
