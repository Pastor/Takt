# Анализ фичи 0244: Стоимость тестовых целей

> Фича: [../features/0244-test-target-build-cost.md](../features/0244-test-target-build-cost.md) · ADR: [../adr/0244-test-target-build-cost.md](../adr/0244-test-target-build-cost.md) · тест-план: [../tests/README.md](../tests/README.md)

## Цель и контекст

`cargo test --all-features` — 152.9 с из 233.2 с предкоммита. Разложение
([ADR 0244](../adr/0244-test-target-build-cost.md)): компиляция и линковка
тестовых целей — 29.3 с, **первый запуск 147 свежесобранных бинарников — ≈ 88 с**
(0.60 с каждый при загрузке ЦП 2 %), исполнение самих тестов — 45.4 с.

Заказчик принял **оба** хода, B первым:

- **B (задача `0244-01`)** — `debug = "line-tables-only"` для тестового профиля;
- **A (задача `0244-02`)** — свести 147 интеграционных целей к нескольким,
  сохранив файлы и различимость наборов.

## Зависимости фичи (правило 17/19)

- **Зависит от:** `нет`. Правка затрагивает манифест workspace и раскладку
  тестовых целей; языка, семантики и целей генерации не касается.
- **Влияние на порядок разработки:** ничего не блокирует и не разблокирует.
  Фича унаследовала первое место в очереди от отменённой 0242 (решение
  заказчика).

## Требования и проверяемые условия

### Общие

- **R1. Ни одной потерянной проверки.** После обеих задач исполняются **все
  3082 теста** (6 ignored). Число тестов — приёмочный инвариант.
- **R2. Предкоммит зелёный** после каждой задачи, а не только в конце.
- **R3. Каждый шаг подтверждён замером до и после** по методике «устоявшаяся
  файловая система + второй прогон» (иначе повторяется класс испорченных
  замеров, найденный при отмене 0242).

### Задача 0244-01 (ход B)

- **R4. Профиль — `[profile.test]`, а не `[profile.dev]`.** Замер показал
  равный эффект (компиляция 26.7 с против 27.0 с; холодный запуск 20 целей
  8.13 с против 8.10 с), но `dev` управляет отладкой бинарников `taktc`,
  `takt-sim`, `takt-lsp` — их отладочную информацию урезать незачем.
- **R5. Обратные трассы сохраняются.** `line-tables-only` оставляет номера
  строк; теряются только значения локальных переменных под отладчиком.
- **R6. Решение записано в `docs/CODE.md`** — чтобы обеднённая отладка тестов
  не всплыла как сюрприз.

### Задача 0244-02 (ход A)

- **R7. Файлы тестов не сливаются.** Цель-агрегатор объявляет `mod`; исходные
  файлы остаются раздельными, правило размера модуля не задевается.
- **R8. Имена тестов остаются различимыми** — через префикс модуля; фильтрация
  `cargo test <подстрока>` продолжает работать.
- **R9. Реестр соответствия «набор → цель»** заведён и упомянут в `README.md`:
  без него `cargo test --test <имя>` в скриптах и в привычке разработчика
  молча перестанет работать.
- **R10. Уникальность временных каталогов сохраняется.** Ключ уникальности —
  имя потока (`std::thread::current().name()`, фича 0190). ⚠️ При слиянии в один
  бинарник имя потока остаётся именем теста, но **префикс модуля меняет его
  вид** — надо убедиться, что помощники, строящие каталог по этому имени, не
  начнут пересекаться (иначе вернутся гонки, которые 0190 устраняла).

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | `line-tables-only` даёт измеримый выигрыш | `cargo test --no-run` и холодный запуск целей — до и после |
| A2 | Число тестов не изменилось | `cargo test --all-features` → 3082 passed, 6 ignored |
| A3 | Предкоммит зелёный и быстрее | `./scripts/precheck.sh` с построчной разметкой времени |
| A4 | Целей стало меньше, тесты все на месте | подсчёт целей + A2 |
| A5 | Фильтрация по имени работает | `cargo test --test <цель> <модуль>::` на пробе |
| A6 | Гонок за временные каталоги нет | параллельный прогон зелёный дважды подряд |

## Особенности по обратной функциональности

- **Задача B обратно совместима полностью:** меняется только объём отладочной
  информации в тестовых бинарниках.
- **Задача A ломает вызовы `cargo test --test <имя>`** для слитых наборов — это
  единственное наблюдаемое изменение, и оно закрывается реестром (R9). Внутри
  репозитория такие вызовы есть в документации и в привычке; в `precheck.sh`
  тесты запускаются одной командой без `--test`, то есть гейт не затронут
  (проверено чтением скрипта).

## Риски и зависимости

- **Риск: слияние вернёт гонки за временные каталоги** (класс 0190). Снижение —
  R10 и двойной параллельный прогон.
- **Риск: расчёт «120–130 с» не подтвердится.** Это расчёт по слагаемым, а не
  обещание; каждый шаг меряется отдельно, и отрицательный результат
  фиксируется так же, как положительный (образец — отвергнутый `lld`).
- **Риск: один упавший тест валит весь агрегат** — диагностика становится чуть
  грубее. Принимается осознанно: имена тестов остаются, место падения видно.
