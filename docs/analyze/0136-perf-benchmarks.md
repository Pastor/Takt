# Анализ фичи 0136: бенчмарки производительности

> Фича: [../features/0136-perf-benchmarks.md](../features/0136-perf-benchmarks.md) · ADR: [../adr/0136-perf-benchmarks.md](../adr/0136-perf-benchmarks.md) · тест-план: [../tests/0136-perf-benchmarks.md](../tests/0136-perf-benchmarks.md)

## Цель и контекст

ADR зафиксировал решения заказчика: **`criterion` + `benches/`** (мерить
функции, а не процессы) и **без гейта**. Анализ уточняет, что мерить, каким
входом и какие ловушки замера уже сработали.

## Факты, снятые замерами (2026-07-27)

**F1. Корпус как объект замера бесполезен.** Компиляция любого примера
`examples/` в цель `c` — менее 0.05 с; шум измерения сопоставим с сигналом.
Мерить надо синтетику известного размера, а корпус держать как «реальную» точку
узнаваемости.

**F2. Рост по числу состояний линеен** там, где виден: 2000 → 20000 состояний
дало 0.053 → 0.645 с (×12 при ×10 размера).

**F3. Ловушка замера сработала на первой же редакции бенча.** Модель строилась
как `model Big { … } start Root = Big;`, а `verify_model` проверяет **ровно ту
модель, которую ей дали** — у анонимного корня своих состояний нет, атом `S199`
неизвестен, и проверка возвращает `Unsupported`. Бенч мерил **отказ**: 376 нс,
одинаково для 200 и 2000 состояний. После правки (состояния на верхнем уровне) —
116.8 мкс и 1.55 мс соответственно.

⚠️ Отсюда требование: бенч верификации обязан **проверять вердикт** перед
измерением. Бенч, меряющий ранний отказ, хуже отсутствующего — он «доказывает»,
что верификация мгновенна.

**F4. Вторая ловушка того же рода.** Формула `G Hot` упоминает только `v0`,
поэтому вторая переменная **не отслеживается** (фича 0068 отслеживает только
переменные из φ), и `vars = 2` мерило ровно то же, что `vars = 1`: 87.5 мс
против 87.7 мс. Формула обязана упоминать все переменные (конъюнкция через `&` —
в LTL не `&&`).

**F5. Главная находка.** После исправления F4 верификация при **двух**
отслеживаемых `u8` перестала завершаться: процесс убит по таймауту 90 с (одна
переменная — 0.09 с и 76 МБ). Вершин при этом 131 072 — **вшестеро ниже**
потолка `VERTEX_LIMIT = 1_000_000` (фича 0068). То есть потолок пропускает вход,
который практически неприменим.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет.
- **Влияние на порядок:** ничего не блокирует; находка F5 порождает кандидата.

## Что и где меняется

| Задача | Файл | Изменение |
|---|---|---|
| 0136-01 | `takt-lang/Cargo.toml`, `takt-sim/Cargo.toml` | `criterion` в dev-зависимости; `[[bench]]` с `harness = false`; `bench = false` у `[lib]` и бинарников |
| 0136-01 | `takt-lang/benches/compile.rs` | разбор, семантика, полный конвейер, индекс LSP, слой использований, форматтер |
| 0136-01 | `takt-lang/benches/verify.rs` | управляющие свойства и свойства над данными + сторож вердикта |
| 0136-02 | `takt-sim/benches/simulate.rs` | построение `Unit` и такт |
| 0136-02 | `scripts/bench.sh`, `README.md` | запуск, baseline, сравнение |
| 0136-03 | отчёт, `FEATURES.md` | числа и кандидаты |

⚠️ `bench = false` у `[lib]` и бинарников обязателен: иначе `cargo bench`
пытается прогнать их стандартным harness, который не понимает флагов criterion
(`--quick`, `--baseline`), и падает с `Unrecognized option`.

## Требования и проверяемые условия

- **R1. Меряются функции**, а не время процесса.
- **R2. Вход осмыслен:** синтетика известного размера + пример корпуса.
- **R3. Бенч не меряет отказ:** перед измерением верификации проверяется
  вердикт.
- **R4. Не гейт:** `precheck.sh` бенчи не вызывает, время предкоммита прежнее.
- **R5. Сравнение возможно:** `--save-baseline` / `--baseline` через
  `scripts/bench.sh`.
- **R6. Числа зафиксированы** в отчёте с указанием машины и режима сборки.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | R1 — бенчи собираются и гоняются | `cargo bench --workspace --benches -- --quick` |
| A2 | R2 — вход из синтетики и корпуса | чтение бенчей; в выводе группы `chain/*` и `corpus/*` |
| A3 | R3 — сторож вердикта | `assert_verifiable` падает, если вердикт `Unsupported` |
| A4 | R4 — не гейт | `grep bench scripts/precheck.sh` пусто; `precheck.sh` зелёный |
| A5 | R5 — baseline | `scripts/bench.sh --save`/`--compare` |
| A6 | R6 — числа в отчёте | таблица с машиной, толчейном, режимом |
| A7 | Предкоммит | `./scripts/precheck.sh` зелёный |

## Особенности по обратной функциональности

Код проекта не меняется: добавляются dev-зависимость, каталоги `benches/` и
скрипт. ⚠️ `Cargo.lock` вырастает (`criterion` тянет заметное дерево) — цена
принята ради замера внутренних функций. Язык не затрагивается, версия не растёт.

## Границы

- **Непрерывного отслеживания нет** — замедление увидит только тот, кто запустит
  бенч (осознанная цена отказа от гейта).
- **`vars = 2` в бенче данных не ставится** — прогон повиснет (F5); факт вынесен
  кандидатом.
- **Быстро ≠ верно:** бенч ловит замедление, а не ошибку.

## Риски и как снижаются

| # | Риск | Снижение |
|---|---|---|
| P1 | Бенч меряет отказ или вырожденный вход | сторож вердикта (F3); осмысленность входа проверяется числами (F4: одинаковое время — сигнал тревоги) |
| P2 | Бенчи подключат к предкоммиту | явное «не гейт» в шапке скрипта и в README |
| P3 | Синтетика устареет при смене синтаксиса | генератор минимален (состояния и `ref`), ломается заметно — бенч не соберётся |
| P4 | `Cargo.lock` разрастётся | однократно, ради развилки A; зафиксировано в отчёте |
