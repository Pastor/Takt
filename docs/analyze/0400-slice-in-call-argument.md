# Анализ фичи 0400: Срез в аргументе вызова

> Фича: [../features/0400-slice-in-call-argument.md](../features/0400-slice-in-call-argument.md) · ADR: [../adr/0400-slice-in-call-argument.md](../adr/0400-slice-in-call-argument.md) · тест-план: [../tests/README.md](../tests/README.md)

## Цель и контекст

`first(src[1:3])` исполняет эталон и не переводит **ни одна** цель. Фича
разворачивает форму в семантике во временную переменную — там, где механика
передачи массива у целей уже есть.

## Замер (правило 30, переснят 2026-08-22)

| Потребитель | Ответ |
|---|---|
| эталон | `o = 6`, затем `7` |
| `c`, `c-hal` | `CC-022` |
| `st`, `st-at` | `ST-011` |
| `rust` | `RS-011` |
| `sv`, `sv-mmio` | `SV-002` |
| `plantuml` | принимает |

Прежний замер (0355) подтверждён полностью.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет; опорные закрыты — [0355](../features/0355-array-slice-in-targets.md)
  (присваивание среза), [0348](../features/0348-st-array-parameter.md),
  [0369](../features/0369-sv-array-parameter.md),
  [0389](../features/0389-rust-array-by-reference.md) (передача массива).
- **Влияние на порядок:** работа исполнительская.

## Требования и проверяемые условия

- **R1.** Форму переводят все восемь целей; инструменты вывод принимают.
- **R2.** Значения совпадают с эталоном потактово.
- **R3.** Синтетическая переменная **невидима автору**: `SE-036` молчит,
  `rename` не задевает, в `documentSymbol` её нет, `usages` не показывает.
- **R4.** Имя уникально в блоке — затенение существующего имени невозможно.
- **R5.** Порядок вычисления аргументов сохранён (срез снимается до вызова).
- **R6.** Контроль: ручной обход (`var part := src[1:3];`) печатается как
  прежде; вывод корпуса не изменился.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | R1 | `scripts/probe.sh` со всеми инструментами |
| A2 | R2 | потактовая сверка эталона с целью `c` |
| A3 | R3 | тесты `usages`/`SE-036`/`rename`/`documentSymbol` |
| A4 | R4 | тест с переменной, чьё имя совпадает с шаблоном синтетического |
| A5 | R5 | вход с двумя аргументами, второй — с побочным эффектом |
| A6 | R6 | `git diff --exit-code examples/generated/` |

## Объём работ (Option A)

| Место | Что делается |
|---|---|
| `semantic/statement/` или новый проход | развернуть `f(src[a:b])` в объявление + вызов |
| именование | синтетическое имя, невидимое слоям редактора (образец — `synthetic_name` анонимного порта, 0189) |
| фикстуры | вход, контроль (ручной обход), порядок аргументов, затенение |
| сверка | потактовая (эталон ↔ `c`) |

⚠️ Печатники целей **не трогаются** — это главный довод за Option A.

## Редакторский слой (правило 29)

**Правки требуются в виде проверки:** синтетическая переменная не должна
попасть ни в `semantic::usages` (иначе `rename` её «переименует»), ни в
`lsp/symbols.rs` (иначе она появится в панели структуры), ни в `SE-036`.
Образец невидимого имени — `AnonPortAccess::synthetic_name` (0189).

## Особенности по обратной функциональности

Вход, сегодня отвергаемый всеми целями, начнёт переводиться — расширение
множества принимаемых программ, обратно совместимое. Версия языка не
поднимается: форма уже разбирается и исполняется эталоном.

## Риски и зависимости

- **Видимость синтетического имени** — главный риск (класс 0195/0131).
- **Порядок вычисления**: срез обязан сниматься до вызова, иначе аргумент с
  побочным эффектом изменит смысл.
- **Корпус класс не покрывает** — срезов в аргументах в `examples/` нет.
