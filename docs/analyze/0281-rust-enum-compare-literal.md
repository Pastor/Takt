# Анализ фичи 0281: Сравнение перечисления с числом в цели `rust`

> Фича: [../features/0281-rust-enum-compare-literal.md](../features/0281-rust-enum-compare-literal.md) · ADR: [../adr/0281-rust-enum-compare-literal.md](../adr/0281-rust-enum-compare-literal.md) · тест-план: [../tests/0281-rust-enum-compare-literal.md](../tests/0281-rust-enum-compare-literal.md)

## Цель и контекст

Цель `rust` восстанавливала вариант перечисления при **присваивании** и не
восстанавливала при **сравнении**: `ref Done: c = 1;` давало `self.c == 1` и
`E0308` от `rustc` при нулевом коде возврата `taktc`. Фича сводит оба места к
одной функции.

## Замер (снят заново, правило 30)

Проба снята `scripts/probe.sh` 2026-08-19 — и первым же прогоном вскрыла дефект
**самого инструмента**: скрипт падал на любой пробе с объявленным типом (фикс
[0301-02](../fixes/0301-02-probe-type-declaration.md)). После починки замер снят
полностью:

| Потребитель | Ответ |
|---|---|
| эталон | исполняет: `c=1`, переход в `Done` |
| `c`, `c-hal`, `st`, `st-at`, `sv`, `sv-mmio`, `plantuml` | переводят без замечаний |
| **`rust`** | генерация «успешна», но `rustc`: **`E0308`** (`expected Command, found integer`) |
| **контроль** `c = Go` (имя варианта) | `self.c == Command::Go` — верно у всех |

Контроль отделяет предмет: отвергается не сравнение перечисления вообще, а
именно сравнение с **числом**.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет.
- **Влияние на порядок разработки:** не разблокирует. Соседняя запись
  [0299](../features/0299-rust-non-ascii-lowercase-name.md) — тот же класс
  «вывод цели `rust` не принимается инструментом», иная причина.

## Требования и проверяемые условия

- **R1. Сравнение перечисления с числом печатается вариантом.**
- **R2. Обе формы (`==`, `!=`) и оба порядка операндов** обрабатываются
  одинаково.
- **R3. Имя варианта строит один носитель** — общий с присваиванием.
- **R4. Сравнение с именем варианта не изменилось** (контроль).
- **R5. Значение вне набора вариантов — честный отказ с причиной.**
- **R6. Порождённый модуль принимается `rustc` и `clippy -D warnings`.**

## Особенности по обратной функциональности

Меняется **форма** вывода цели `rust` для сравнения перечисления с числом.
Прежняя форма не компилировалась, то есть контрактом не была. Корпус её не
содержит — снимки не двигаются.

## Версия языка (правило 22)

**Язык не меняется.** Версия языка остаётся `0.10.0`; версия крейта `takt-lang`
поднимается на патч.

## Редакторский слой (правило 29)

**Проверка не требуется, и это ответ:** новых токенов, форм объявления, узлов
АСД и диагностик языка нет.

## Документирование (правило 24)

**Не требуется:** документ описывает язык, а форма записи и её смысл не
изменились — изменился перевод одной целью.

## Риски и зависимости

- **Риск: ветвь перехватит чужую форму.** Снижен тем, что она срабатывает
  только при статическом типе `Enum` у одного операнда и числовом литерале у
  другого; контрольный тест T3 сторожит форму с именем варианта.
- ⚠️ **Граница:** сравнение `c = Go` идёт узлом `ConditionNode::EnumVariant` и
  в новую ветвь не попадает — так было и раньше.
- ⚠️ **Инструмент замера чинился по ходу** (фикс 0301-02): правило 30 требует
  прогона, а `probe.sh` падал на любой пробе с типом. Сторож дефекта не видел —
  у проверки не была покрыта отрицательная ветвь.
