# Анализ фичи 0209: Внешний интерфейс модели — extern fn в симуляторе и агрегат как аргумент

> Фича: [../features/0209-model-external-interface.md](../features/0209-model-external-interface.md) · ADR: [../adr/0209-model-external-interface.md](../adr/0209-model-external-interface.md) · тест-план: [../tests/0209-model-external-interface.md](../tests/0209-model-external-interface.md)

## Цель и контекст

Сделать модель с внешним интерфейсом **проверяемой эталоном** и выразить
«программу как аргумент». Две независимые части, обе подтверждены пробой:
стенд `extern fn` из сценария (решение заказчика) и агрегат в аргументе
параметра.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Смежные [0185](../features/0185-model-parameters.md)
  (параметры), [0134](../features/0134-language-time-model.md) (время ставит
  `runner` — образец для стенда) — закрыты.
- **Влияние на порядок разработки:** снимает ограничение, названное в
  `CLAUDE.md` («в примерах значения датчиков берут входным портом, а `extern fn`
  оставляют для команд-действий»): теперь пример документа вправе читать внешнюю
  функцию, если сценарий задаёт значения.

## Замеры

Таблицы — в ADR. Кратко: `extern fn` **со значением** останавливал прогон
(`SIM-019`), без возврата — исполнялся; агрегат в аргументе отвергался
`SE-083`. ⚠️ Снятие второго отказа **обнажило** неготовность цели `c`: она
печатала присваивание агрегата, которое `cc` отвергает; дефект был недостижим,
пока семантика отвергала форму раньше.

## Требования и проверяемые условия

- **R1. Стенд из сценария.** Две формы: одно значение на такт и таблица по
  первому аргументу.
- **R2. Умолчания нет.** Не задали — прежний `SIM-019`. ⚠️ Это главное
  требование фичи: ноль сделал бы сверку трасс зелёной при расхождении.
- **R3. Стенд принадлежит шагу**, а не прогону.
- **R4. Стенд доезжает до всех областей видимости** — тела блоков и функций
  исполняются в своих контекстах, а такт идёт с `Unit` в роли контекста.
- **R5. Ошибка сценария называется.** Нечисловой ключ таблицы и нечитаемое
  значение — отказ с именем функции, а не молчаливый пропуск.
- **R6. Агрегат вычисляется** и доезжает до эталона значением.
- **R7. Цель `c` печатает агрегат поэлементно** — иначе вывод отвергает `cc`.
- **R8. Неконстантный элемент отвергается** (значение параметра — величина
  сборки).
- **R9. Границы целей названы:** `st`/`sv` агрегатный аргумент не печатают.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Таблица кормит чтения | прогон сценария, разные значения по тактам |
| A2 | Одно значение на такт | прогон |
| A3 | Без стенда — отказ | контр-пример |
| A4 | Стенд — свойство шага | контр-пример (второй такт без стенда) |
| A5 | Ошибка сценария названа | контр-пример с нечисловым ключом |
| A6 | Агрегат в эталоне | значенческий тест |
| A7 | Поэлементная печать в C | сверка текста + `cc` |
| A8 | Неконстантный элемент | контр-пример `SE-083` |
| A9 | Отказы `st`/`sv` пришпилены | тест кодов |
| A10 | Предкоммит и корпус | `./scripts/precheck.sh`, `git status` |

## Особенности по обратной совместимости (правило 11)

Обе части — **расширения**: программы и сценарии, работавшие прежде,
работают. Поле `extern` в шаге необязательно; отказ `SIM-019` сохраняется там,
где стенда нет. Язык не меняется: синтаксис `extern fn` и агрегата прежний,
меняется **множество вычислимого** (агрегат стал константой) и поведение
инструмента прогона. Версия языка не поднимается (правило 22).

## Редакторский слой (правило 29)

**Правок не требуется:** новых токенов, форм объявления и узлов АСД нет.

## Документирование (правило 24)

Раздел [`book/src/15-simulation/`](../../book/src/15-simulation/index.typ)
дополняется подразделом «Внешние функции в прогоне» (две формы стенда, отсутствие
умолчания); в «Частых ошибках» уточняется `SIM-019` — он больше не значит «так
нельзя», а значит «сценарий не задал значение».

## Риски

- **Р1. Стенд не доедет до вложенной области.** Реализовалось при первой сборке:
  подмена не сработала, пока `extern_result` не был передан в области блока,
  функции и в `Unit`. Снижение — тест на модель, где вызов идёт из тела `always`.
- **Р2. Умолчание проникнет позже.** Снижение — контр-пример «без стенда отказ»
  стоит рядом с положительными.
- **Р3. Агрегат в целях.** Снижение — поэлементная печать в `c` сверяется
  текстом, отказы `st`/`sv` пришпилены.
