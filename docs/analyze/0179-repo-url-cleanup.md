# Анализ фичи 0179: Дочистка URL репозитория после переезда BuT → Takt

> Фича: [../features/0179-repo-url-cleanup.md](../features/0179-repo-url-cleanup.md) · ADR: [../adr/0179-repo-url-cleanup.md](../adr/0179-repo-url-cleanup.md) · тест-план: [../tests/README.md](../tests/README.md)

## Цель и контекст

Переезд репозитория состоялся; старое имя осталось в дереве. Решение — Option B
[ADR 0179](../adr/0179-repo-url-cleanup.md): правка + гейт согласованности,
проверяющий **не имя `Takt`**, а единственность адреса, — чтобы следующий
переезд ловился машиной.

## Зависимости фичи (правило 17/19)

- **Зависит от:** `нет`. Правки — метаданные, тексты и doc-комментарии; ни один
  слой компилятора не затрагивается.
- **Влияние на порядок разработки:** никого не разблокирует и не блокирует.
  Стоит среди процессных: дёшева и снимает дезинформацию в README, который
  читает каждый новый пользователь.

## Требования и проверяемые условия

- **R1. Живых вхождений старого адреса нет** вне исторических артефактов.
- **R2. Инструкция клонирования работает целиком** — `git clone` и `cd`
  согласованы.
- **R3. Гейт заведён** (`scripts/check-repo-url.sh`) и вызывается из `precheck.sh`.
- **R4. Гейт проверяет согласованность, а не имя** — эталон берётся из
  `takt-lang/Cargo.toml`, в скрипте имени `Takt` нет.
- **R5. Исключения явные** — список исторических путей в скрипте, с
  обоснованием.
- **R6. Поведение инструментов не изменено** — правки только в метаданных,
  текстах и doc-комментариях; вывод генераторов байт-в-байт прежний.
- **R7. Плагины переустановлены** — в установленных артефактах старого URL нет.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Старого адреса нет вне истории | греп по дереву |
| A2 | `clone` + `cd` согласованы | чтение README + прогон гейта |
| A3 | Гейт валит рассогласование | **мутация**: вернуть `BuT` в один файл → предкоммит красный |
| A4 | Гейт не зашивает имя | **мутация**: заменить `Takt` на вымышленное имя во **всех** местах → гейт **зелёный** (граница A-2 ADR) |
| A5 | Гейт ловит рассогласованный `cd` | **мутация**: испортить только `cd` → гейт красный |
| A6 | Вывод генераторов не изменён | дифф `examples/generated/` пуст |
| A7 | Предкоммит зелёный | `./scripts/precheck.sh` |
| A8 | Плагины чисты | греп по установленным артефактам RustRover и `index.json` Zed |

⚠️ **A4 — не формальность.** Он фиксирует **границу** гейта: тот проверяет
согласованность, а не правильность. Без этой проверки легко поверить, что гейт
защищает от неверного адреса, — он защищает лишь от разнобоя.

## Особенности по обратной функциональности

- **Крейты:** меняется поле `repository` — метаданные публикации. Версии крейтов
  **не растут**: изменение не касается ни API, ни поведения.
- **Версия языка не растёт** (правило 22): язык не затронут.
- **Плагины:** меняются манифесты → требуется пересборка и переустановка (A-3
  ADR), иначе установленные копии сохранят старый URL.

## Риски и зависимости

- **Риск 1: гейт завалит артефакт будущей фичи**, законно цитирующий старый
  адрес (A-1 ADR). Лечится добавлением пути в список исключений с обоснованием;
  рост списка — сигнал ревью.
- **Риск 2: ложное чувство защиты** (A-2 ADR). Снимается проверкой A4, которая
  границу гейта демонстрирует явно.
- **Риск 3: правка doc-ссылок ломает `cargo doc`.** Ссылки внешние (http), их
  корректность гейтом не проверяется; `check-links.py` смотрит только
  относительные пути в Markdown. Проверяется чтением диффа.
