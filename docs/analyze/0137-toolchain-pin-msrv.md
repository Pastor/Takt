# Анализ фичи 0137: Фиксация толчейна Rust и MSRV

> Фича: [../features/0137-toolchain-pin-msrv.md](../features/0137-toolchain-pin-msrv.md) · ADR: [../adr/0137-toolchain-pin-msrv.md](../adr/0137-toolchain-pin-msrv.md) · тест-план: [../tests/0137-toolchain-pin-msrv.md](../tests/0137-toolchain-pin-msrv.md)

## Цель и контекст

Сделать сборку воспроизводимой: зафиксировать компилятор, объявить MSRV и
закрепить состав зависимостей. Решение — Option A
[ADR 0137](../adr/0137-toolchain-pin-msrv.md): пин конкретной **стабильной**
версии, `Cargo.lock` в репозитории, `resolver = "3"`, CI без собственного
указания толчейна.

## Зависимости фичи (правило 17/19)

- **Зависит от:** `нет`.
- **Влияние на порядок разработки:** формально никого не разблокирует, но
  выполняется **первой** из содержательных: пока канал плавает, любой прогон
  гейтов может упасть по причине, не связанной с правкой, — и тогда неверный
  вывод сделает уже следующая фича.

## Что именно ломалось (воспроизведено)

`./scripts/precheck.sh` упал на `cargo clippy` с **21 ошибкой** `E0463`/`E0514`
после смены nightly: артефакты `target/` были собраны предыдущим компилятором.
Лечение — только `cargo clean`, а каталог занимает **~140 ГБ / 708 тыс. файлов**.
Код при этом исправен: после очистки предкоммит зелёный.

## Требования и проверяемые условия

- **R1. Один источник истины.** Версия компилятора описана в **одном** файле;
  ни `precheck.sh`, ни `ci.yml` её не дублируют и не задают канал явно.
- **R2. Nightly не требуется.** Подтверждается двумя пробами: (а) clippy
  `--all-targets --all-features -D warnings` на стабильной версии — **ноль**
  предупреждений; (б) стабильный `rustfmt` принимает дерево, отформатированное
  nightly, **байт-в-байт** (`cargo fmt --check` → rc 0).
- **R3. Состав зависимостей закреплён.** `Cargo.lock` отслеживается; git-
  зависимость `lalrpop` зафиксирована коммитом; `--locked` проходит.
- **R4. MSRV объявлен и честен.** Указывается версия, на которой гейты
  действительно гоняются; нижняя граница **не выдумывается**.
- **R5. Поведение проекта не меняется.** Порождаемый код, тесты и гейты — те же;
  фича трогает только окружение сборки.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Пин существует и активен | `rustup show active-toolchain` → `1.97.1 … (overridden by '…/rust-toolchain.toml')` |
| A2 | Компоненты на месте | `cargo fmt --version`, `cargo clippy --version` |
| A3 | MSRV задан в обоих манифестах | `grep rust-version takt-lang/Cargo.toml takt-sim/Cargo.toml` |
| A4 | `Cargo.lock` в репозитории | `git ls-files Cargo.lock` непусто; в `.gitignore` записи нет |
| A5 | Зависимости согласованы | `cargo check --locked --all-targets --all-features` |
| A6 | Явного канала нет | `grep -n "nightly" scripts/precheck.sh .github/workflows/ci.yml` — только пояснения |
| A7 | Предкоммит зелёный на пине | `./scripts/precheck.sh` → `EXIT=0` |
| A8 | Резолвер 3 не меняет граф | `cargo check --locked` после смены `resolver` проходит без правки lock |

## Особенности по обратной функциональности

Обратная совместимость **языка** не затрагивается: ни синтаксис, ни семантика, ни
порождаемый код не меняются. Затрагивается **контракт окружения**: разработчику
теперь нужен rustup, который поставит пин автоматически при первом вызове
`cargo`. Для потребителя библиотеки `takt-lang` появляется объявленный MSRV —
это ужесточение, но оно **фиксирует уже существующее** требование, а не вводит
новое.

## Риски и зависимости

- **Риск: пин не устанавливается на чужой машине.** Снимается тем, что канал —
  обычная стабильная версия из основного канала rustup.
- **Риск: неполная установка толчейна.** Наблюдался живьём: каталог
  `lib/rustlib/<target>/lib` оказался пуст при `rust-std … (installed)` в выводе
  `rustup component list`, сборка падала с `E0463: can't find crate for std`.
  Лечится переустановкой толчейна; в `rust-toolchain.toml` компонент перечислен
  явно, а случай описан в задаче 0137-01 — чтобы следующий столкнувшийся не
  искал причину в коде.
- **Риск: CI не проверен живьём.** Прогоны Actions заблокированы по биллингу
  (известная проблема). Правка `ci.yml` проверена логически; действие вынесено в
  ADR.
- **Риск: возврат `cargo +канал`.** Любое явное указание канала в скриптах
  вернёт неопределённость; сторожа нет — только правило, записанное в ADR и в
  комментарии `precheck.sh`.
