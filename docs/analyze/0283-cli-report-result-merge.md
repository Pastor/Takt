# Анализ фичи 0283: Печать результата компиляции

> Фича: [../features/0283-cli-report-result-merge.md](../features/0283-cli-report-result-merge.md) · ADR: [../adr/0283-cli-report-result-merge.md](../adr/0283-cli-report-result-merge.md) · тест-план: [../tests/0283-cli-report-result-merge.md](../tests/0283-cli-report-result-merge.md)

## Цель и контекст

Свести печать результата к одной функции, решив вопрос, оставленный фичей 0168:
каким должен быть `--verbose` у адрес-потребляющих целей. ADR принял Option B —
одинаковым для всех.

## Замер (снят 2026-08-20, правило 30)

Кандидат подтверждён **прогоном инструмента**, и замер нашёл второй разнобой,
которого кандидат не называл.

| Цель | `--verbose` | Что печатается |
|---|---|---|
| `st` | учитывается | абсолютный путь входа, выход **без** слэша |
| `st-at` | **игнорируется** | путь как передан, выход со слэшем |

То есть различий было два: наличие verbose и форма пути выхода.

**Контроль совместимости:** `--verbose` в README не описан (греп по документу —
пусто), строка «Скомпилировано:» в тестах и скриптах не разбирается (греп по
`takt-lang`, `takt-sim`, `scripts` — только упоминания в комментариях). Значит
изменение наблюдаемого никого в дереве не ломает.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет (0168 и 0275, на которые опирается устройство, закрыты).
- **Влияние на порядок:** никого не разблокирует.

## Требования и проверяемые условия

- **R1.** Печать результата — одна функция на все цели, кроме `c` (у неё своё
  сообщение с путями поиска).
- **R2.** `--verbose` даёт канонический путь входа у **всех** целей.
- **R3. Контрпример:** без флага печатается путь как передан.
- **R4.** `--quiet` глушит результат у обеих ветвей прежнего деления.
- **R5.** Путь выхода печатается со слэшем в обоих режимах.
- **R6.** Предупреждения по-прежнему идут через `print_warnings` с реестром
  файлов (границы фич 0228 и 0275 не сдвигаются).

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | verbose у «простой» цели | `cli_report_result_tests::verbose_prints_canonical_input_for_simple_target` |
| A2 | verbose у адресной цели | `…_for_address_target` |
| A3 | Контрпример | `without_verbose_input_path_is_as_given` |
| A4 | quiet у обеих ветвей | `quiet_suppresses_result_for_both_kinds` |
| A5 | Форма пути выхода | `output_path_is_printed_with_slash_in_both_modes` |
| A6 | Регрессия и предкоммит | `cargo test --all-features`, `./scripts/precheck.sh` |

## Особенности по обратной функциональности (правило 11)

**Меняется наблюдаемый вывод**, и изменение названо: при `--verbose` цели
`c-hal`/`st-at`/`sv-mmio` печатают абсолютный путь входа; verbose-вывод прочих
целей получил слэш после пути выхода. Контракта на строку нет, зависимостей в
дереве нет (см. контроль в замере). Прежнее поведение было дефектом: флаг
принимался и игнорировался.

Язык не затронут; версия языка прежняя (`0.10.0`).

## Редакторский слой (правило 29)

**Не требуется.** Правка в CLI; лексика, синтаксис и семантика не менялись.

## Документирование (правило 24)

**Не требуется.** Раздел «Инструментарий» описывает вызовы `taktc`, а не форму
строки результата; `--verbose` в документе не описан.

## Риски и зависимости

- **Риск: кто-то разбирает строку результата снаружи дерева.** **Снижение:**
  контракта на неё нет; формат стал **более** единообразным, а не менее.
- **Риск: слияние утащит границы фич 0228/0275.** **Снижение:** реестр файлов
  по-прежнему приходит параметром, `print_warnings` не менялся; тест
  `cli_warning_position_tests` (0228) остаётся зелёным.
