# Анализ фичи 0093: Запрет _ => в семантических узлах и разрешение конфликта с #[non_exhaustive]

> Фича: [../features/0093-wildcard-match-rule.md](../features/0093-wildcard-match-rule.md) · ADR: [../adr/0093-wildcard-match-rule.md](../adr/0093-wildcard-match-rule.md) · тест-план: [../tests/0093-wildcard-match-rule.md](../tests/0093-wildcard-match-rule.md)

## Цель и контекст

Закрыть два пробела инварианта «семантические узлы разбираются явно» (ADR 0025):
(1) правила нет в своде `docs/CODE.md` (живёт лишь в коде `eval/` и `CLAUDE.md`);
(2) свод сам себе противоречит — рекомендует `#[non_exhaustive]`, который **отключает**
этот инвариант. Решение — Option A ADR: правило + исключение в `docs/CODE.md` +
машинный гейт `check-exhaustive-nodes.sh`, ловящий «тихую смерть» (пометка узла
`#[non_exhaustive]` / снятие `deny` в `eval/`).

## Зависимости фичи (правило 17/19)

- **Зависит от:** **нет.** Затрагивает `docs/CODE.md` и `scripts/` (новый гейт);
  код крейтов **не трогается** (гейт лишь проверяет **факт** отсутствия пометки/
  наличия `deny`). Инвариант 0025 уже реализован точечно (`eval/`).
- **Влияние на порядок разработки:** не блокирует других; защищает инвариант для
  всех будущих правок.

## Требования и проверяемые условия

- **R1. Правило в своде.** `docs/CODE.md` содержит правило: разбор
  `ExpressionNode`/`ConditionNode`/`StatementNode` — **без** `_ =>`; enforce
  `#[deny(clippy::wildcard_enum_match_arm)]` в модуле-источнике семантики (`eval/`).
  Со ссылкой на ADR 0025 (почему).
- **R2. Исключение для `#[non_exhaustive]`.** Рекомендация `#[non_exhaustive]` в
  `docs/CODE.md` несёт явное исключение: три семантических узла пометке **не**
  подлежат (иначе инвариант тихо умрёт).
- **R3. Машинный гейт.** `scripts/check-exhaustive-nodes.sh` падает, если
  (а) `ExpressionNode`/`ConditionNode`/`StatementNode` помечены `#[non_exhaustive]`,
  либо (б) `simulation/src/eval/mod.rs` потерял `#![deny(clippy::wildcard_enum_match_arm)]`.
  В `precheck.sh`.
- **R4. Аддитивность.** Код, вывод целей и поведение симулятора **неизменны**
  (правило 11); язык/крейты не затрагиваются, версии не поднимаются.
- **R5. Рецидив — кандидат.** `unit/builder.rs::eval_expr` (второй вычислитель с
  `_ => None`) в объём **не** входит (территория 0034, второй вычислитель намеренно
  не слит — 0080); фиксируется кандидатом.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Правило и исключение в `docs/CODE.md` | инспекция + гейт `check-links` |
| A2 | Гейт зелёный на текущем дереве | прогон `check-exhaustive-nodes.sh` (код 0) |
| A3 | Гейт красный при пометке узла `#[non_exhaustive]` | проба: временно пометить → ненулевой код |
| A4 | Гейт красный при снятии `deny` в `eval/` | проба: временно убрать → ненулевой код |
| A5 | Гейт в `precheck.sh` | прогон полного предкоммита |
| A6 | Вывод/поведение неизменны | код не тронут → тривиально; `precheck.sh` зелёный |

## Особенности по обратной функциональности

Полностью аддитивно: правка документа + новый проверочный скрипт. Код крейтов не
меняется — вывод целей и симулятора байт-в-байт неизменны, версии языка/крейтов не
поднимаются.

## Риски и зависимости

- **Риск: гейт привязан к путям/именам узлов.** Снижение: гейт грепает конкретные
  `pub enum` в `semantic/mod.rs` и `deny` в `eval/mod.rs`; при переносе — согласовать
  (документируется в скрипте). Проба A3/A4 доказывает срабатывание.
- **Граница (не риск): рецидив `builder.rs`** — кандидат, владелец 0034.
- **Tier:** **Tier 3** (процесс/стандарты кода + защитный гейт; боль — латентный
  риск «тихой смерти» инварианта, стоившего проекту дорого по ADR 0025).
