# Анализ фичи 0129: Устранение переполнения стека на глубине выражений и операторов

> Фича: [../features/0129-semantic-deep-nesting.md](../features/0129-semantic-deep-nesting.md) · ADR: [../adr/0129-semantic-deep-nesting.md](../adr/0129-semantic-deep-nesting.md) · тест-план: [../tests/0129-semantic-deep-nesting.md](../tests/0129-semantic-deep-nesting.md)

## Цель и контекст

Превратить аварийное завершение на глубоко вложенном вводе в диагностику.
Решение — Option A [ADR 0129](../adr/0129-semantic-deep-nesting.md): предел
вложенности + `SE-062`.

## Зависимости фичи (правило 17/19)

- **Зависит от:** `нет`.
- **Влияние на порядок разработки:** побочно **уменьшает долг размера модулей**
  (см. ниже), то есть облегчает работу фичи
  [0099](../features/0099-module-size-core.md).

## Локализация (чем измерено)

`lldb -b -o run -o bt` по аварийному процессу — две точки рекурсии:

| Ввод | Падало в |
|---|---|
| 300 вложенных скобок в условии `ref` | `semantic::condition::resolve_condition` |
| 300 вложенных скобок в выражении / вложенные `if` | `semantic::expression::construct_expression` |

Пороги (сборка debug): основной поток (8 МиБ) — между 240 и 280; поток 2 МиБ
(столько по умолчанию у потока `cargo test`) — 48 проходит, 64 роняет. Отсюда
оценка кадра рекурсии — десятки килобайт, и отсюда же выбран предел **32**.

## Требования и проверяемые условия

- **R1. Никакого `SIGABRT`.** На любой глубине инструмент возвращает диагностику.
- **R2. Одинаково у всех потребителей.** `taktc compile`, `taktc verify`,
  `takt-sim` — одно и то же поведение (общий семантический слой).
- **R3. Работает в любом потоке.** Счётчик потоковый: библиотеку зовут из LSP.
- **R4. Счётчик не протекает.** Ранний выход по `?` обязан уменьшать глубину,
  иначе вторая компиляция в том же потоке упрётся в чужой остаток.
- **R5. Обычный код не задет.** Вложенность реальных спецификаций (единицы
  уровней) строится как прежде; вывод корпуса `examples/` байт-в-байт неизменен.
- **R6. Предел назван пользователю.** Сообщение содержит число, документация —
  объяснение и способ обхода.
- **R7. Реестр размера модулей не нарушен.** Правка затрагивает файл из реестра
  долга, которому расти нельзя.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | глубина 300 → `SE-062`, не падение | тест `deep_nesting_that_used_to_crash_is_diagnosed` + сквозная проба CLI |
| A2 | то же для выражения в теле | тест `deep_nesting_in_expression_is_diagnosed_too` |
| A3 | вложенность в пределах лимита строится | тест `nesting_within_limit_is_accepted` |
| A4 | превышение на единицу диагностируется | тест `nesting_beyond_limit_is_diagnosed_not_crash` |
| A5 | сообщение называет предел | тест `diagnostic_names_the_limit` |
| A6 | счётчик не протекает | тесты `counter_does_not_leak_between_builds`, `early_return_does_not_leak_depth`, `guard_releases_depth_on_drop` |
| A7 | одинаково у трёх инструментов | проба: `compile`/`verify`/`takt-sim` на одной модели |
| A8 | реестр кодов | `./scripts/check-diagnostic-codes.sh` |
| A9 | реестр размера | `./scripts/check-module-size.sh` (записей 5, новых нарушителей нет) |
| A10 | предкоммит | `./scripts/precheck.sh` → `EXIT=0` |

## Особенности по обратной функциональности

Формально это **ужесточение**: ввод, который прежде принимался, теперь может
быть отвергнут. Практически затронут только ввод, который **ронял инструмент**
(глубина в сотни уровней) либо был к этому близок: предел 32 при наблюдаемом
пороге 240–280 в CLI-потоке отсекает лишь заведомо патологические тексты.
Корпус `examples/` и книга не содержат вложенности глубже единиц уровней —
порождённый код не изменился.

Альтернатива «не ограничивать» проверена и отвергнута (ADR, Option B): она не
даёт гарантии, потому что производные `Clone`/`Drop` и печать форматтера
рекурсивны по построению.

## Риски и зависимости

- **Риск: предел мешает настоящему коду.** Снижается замером (реальная
  вложенность — единицы уровней) и документированным обходом (именованные
  условия `cond`, промежуточные переменные).
- **Риск: рассинхрон предела с тестом.** Константа продублирована числом в
  интеграционном тесте (модуль `pub(crate)`); держит парный сторож
  `constant_matches_documented_limit`.
- **Риск: правка не влезет в реестр размера.** Реализовался: `expression.rs`
  (1360 строк) расти не имел права. Снят разделением на `expression/mod.rs` +
  `expression/tests.rs` — файл **выбыл** из реестра долга.
- **Остаточный риск (принят):** потолки вне семантики — форматтер на ~3000
  скобок и производный `Clone` АСД на ~2000 вложенных операторов. Замерено при
  приёмке, вынесено кандидатом.
