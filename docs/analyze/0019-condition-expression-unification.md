# Анализ фичи 0019: унификация грамматик Condition/Expression

> Фича: [../features/0019-condition-expression-unification.md](../features/0019-condition-expression-unification.md) · ADR: [../adr/0019-condition-expression-unification.md](../adr/0019-condition-expression-unification.md)

## Цель и контекст

Снизить стоимость поддержки грамматики выражений, устранив дублирование. По ADR
0019 принят **Option B**: убрать дубликат `LoopCond` переиспользованием
`Expression`; `Condition` остаётся отдельной грамматикой (намеренно — иная
семантика `=`).

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Затрагивает только `grammar` (лексер/парсер не зависят от
  других незакрытых фич). 0020 (порты) независима — пересечения нет.
- **Влияние на порядок разработки:** завершение 0019 никого не разблокирует;
  приоритет — по проработанности. Может идти параллельно 0020.

## Требования и проверяемые условия

- **R1. Сохранение семантики условий.** `=` в `Condition` остаётся
  `Condition::Equal`; `=` в `Expression`/`LoopCond` — `Expression::Assign`.
  Инвариант `=`/`==` (CLAUDE.md) не нарушается.
- **R2. Идентичный AST для loop.** Разбор `loop <cond> { … }` продолжает давать
  `ast::Expression` с тем же деревом, что и до рефактора.
- **R3. Дизамбигуация `{`.** Сохраняется различение `loop { body }` (бесконечный)
  и `loop {init} { body }` — ведущий `{` в условии по-прежнему недопустим без
  скобок (`loop ({1,2}) { body }`).
- **R4. Нулевой регресс.** Все существующие `.lam`-фикстуры и тесты
  (`if_while_for`, `syntax_simple`, кодоген) дают прежний результат.
- **R5. Без новых LR(1)-конфликтов.** `cargo build` не выдаёт предупреждений
  LALRPOP о конфликтах.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | `LoopCondP*` удалены, `loop`-условие через параметризованное `Expression` | grep по `grammar.lalrpop` (нет `LoopCondP`) + сборка |
| A2 | Регресс = 0 | `cargo test --features lsp -- --test-threads=1` (1438 тестов зелёные) |
| A3 | Инвариант `=`/`==` | тест `syntax_simple` + фикстуры условий зелёные |
| A4 | Нет LR(1)-конфликтов | `cargo build` без предупреждений LALRPOP |
| A5 | Дизамбигуация `{` | тесты `loop { … }` и `loop ({…}) { … }` |

## Особенности по обратной функциональности

Изменение **чисто внутреннее** (структура грамматики), синтаксис и семантика
языка не меняются → обратная совместимость полная, версия языка не повышается
(правило 22). Слома `.lam` нет — это ключевое отличие от отвергнутого Option A.

## Риски и зависимости

- **Риск: LALRPOP-макрос над леворекурсивной цепочкой** может дать конфликты или
  не выразить ограничение «нет ведущего `{`». → **Снижение:** сначала
  PoC/spike (dev-задача 0019-01) на изолированной ветке грамматики; при неуспехе
  — откат к Option C (факторизация макросом всех трёх) или сохранение статус-кво
  с документированием.
- **Риск: скрытая зависимость LSP/подсветки** от имён нетерминалов. → регресс
  LSP-тестами.
- **Ожидание в карточке** («единый Expression с семантической валидацией»)
  **сознательно сужено** ADR 0019: полное слияние ломает инвариант `=`/`==` и
  совместимость. Это зафиксировано и обосновано.

## Декомпозиция разработки

  вернуть фичу к пересмотру объёма.
