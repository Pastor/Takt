# Анализ фичи 0258: `Verdict::Unsupported` не различает причину отказа

> Фича: [../features/0258-verify-unsupported-reason.md](../features/0258-verify-unsupported-reason.md) · ADR: [../adr/0258-verify-unsupported-reason.md](../adr/0258-verify-unsupported-reason.md) · тест-план: [../tests/0258-verify-unsupported-reason.md](../tests/0258-verify-unsupported-reason.md)

## Цель и контекст

Дать вердикту-отказу структурированную причину и печатать **одну** — ту, по
которой проверка не выполнена. ADR принял Option B: поле `reason` вердикта,
текст — у единственного носителя `UnsupportedReason::text()`.

## Замер (снят 2026-08-19, правило 30)

Кандидат подтверждён и **уточнён**: причин не «несколько», а ровно пять, и они
различимы по месту отказа. Прогон по входам (`verify_model`):

| Вход | Что происходит | Причина |
|---|---|---|
| `G nosuch` | атом не связан ни с состоянием, ни с предикатом | `UnknownAtom` |
| `cond P = t + 1 > 2` | арифметика в предикате | `PredicateOutsideSubset` |
| `var x: float := 0.0; cond P = x <= 1.0` | тип не перечислим | **`PredicateOutsideSubset`** |
| то же с `q(4,4)`, `[bit;8]`, структурой | то же | **`PredicateOutsideSubset`** |
| три `u8` в предикате | рёбер за потолком | `SizeOverLimit` |
| `var x: u8 := src()` | инициализатор не сворачивается | `InitialValueUnknown` |
| `var f: bit := 0; cond P = f = 0` | **контроль** — проверяемо | причины нет |

⚠️ **Главное открытие замера: ветвь `DomainNotEnumerable` недостижима.**
Неперечислимый тип отсекает `collect_tracked` (шаг 2), а проверка домена стоит
шагом позже (шаг 3). Документация модуля обещала обратное («`float`/`q` →
`Unsupported`, правило 5») — формально верно по вердикту, но причина другая.
Проверено на **четырёх** входах, а не на одном: `float`, `q`, массив,
структура.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Фичи 0068 и 0145 закрыты; правка идёт в их слоях.
- **Влияние на порядок разработки:** никого не разблокирует.

## Требования и проверяемые условия

- **R1. Причина — часть вердикта**, а не пересказ в печати.
- **R2. Каждая достижимая причина приходит на своём входе** и не приходит на
  чужом.
- **R3. Проверяемое свойство причины не получает** (контроль: иначе «причина
  такая-то» доказывало бы лишь, что вердикт всегда `Unsupported`).
- **R4. Текст один на всех потребителей** — CLI и экспорт графа.
- **R5. Тексты различны, непусты и не несут имён вариантов Rust** (класс 0231).
- **R6. Недостижимая ветвь названа** в коде, а не спрятана.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Причина у вердикта | тип `Verdict::Unsupported { atoms, reason }` |
| A2 | Соответствие вход → причина | `unsupported_reason_tests` (5 входов) |
| A3 | Контроль | `checkable_property_has_no_reason` |
| A4 | Один носитель текста | `taktc.rs` и `dot.rs` зовут `reason.text()` |
| A5 | Тексты различны | `reason_texts_are_distinct_and_nonempty` |
| A6 | Недостижимость названа | док-комментарий `DomainNotEnumerable` + комментарий теста `float_predicate_is_unsupported` |
| A7 | Регрессия | `cargo test --all-features` |
| A8 | Предкоммит | `./scripts/precheck.sh` |

## Особенности по обратной функциональности (правило 11)

**Ломается публичный тип.** `Verdict::Unsupported(Vec<String>)` →
`Verdict::Unsupported { atoms, reason }`: сопоставления правятся у всех
потребителей (в дереве их семь, включая тесты). Обоснование: причину нужно
**принести** из места отказа, а не собрать в печати; иначе текст и вердикт
расходятся молча — ровно это и дало ложное сообщение, снятое фичей 0145.

**Наблюдаемый вывод меняется** — печать `taktc verify` вместо четырёх строк
даёт две (причина + охват). Язык не затронут: версия языка прежняя, версия
крейта `takt-lang` поднимается минорно.

⚠️ **Текст `PredicateOutsideSubset` дополнен** упоминанием неперечислимых
типов: именно так они сегодня и отсекаются. Без этого сообщение было бы
формально верным, но автор с `float` в предикате не понял бы, о чём речь.

## Редакторский слой (правило 29)

**Не требуется.** Лексика, синтаксис и семантика языка не затронуты: правка в
слое верификации и в печати CLI. LSP вердиктов верификации не показывает
(предупреждения LTL идут отдельным путём — `semantic::warnings`).

## Документирование (правило 24)

**Не требуется.** Язык не меняется. Приложение «Ошибки» описывает коды
диагностик, а вердикт верификации кода не имеет (и не должен — у него нет
позиции в исходнике; см. Option C ADR).

## Риски и зависимости

- **Риск: причина названа неверно** (место отказа не то, что думает автор).
  **Снижение:** каждая причина проверена **прогоном** на своём входе, а не
  чтением; ветвь, не подтверждённая прогоном, объявлена недостижимой.
- **Риск: тексты разъедутся** между CLI и экспортом графа. **Снижение:**
  единственный носитель `UnsupportedReason::text()`.
- **Риск: `concat!` против продолжения строки.** Первая редакция текстов
  использовала перенос с `\`, и в вывод попали десятки пробелов подряд —
  поймано прогоном CLI, а не чтением.
