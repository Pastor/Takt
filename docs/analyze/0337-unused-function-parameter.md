# Анализ фичи 0337: неиспользуемый параметр функции

> Фича: [../features/0337-unused-function-parameter.md](../features/0337-unused-function-parameter.md) · ADR: [../adr/0337-unused-function-parameter.md](../adr/0337-unused-function-parameter.md) · тест-план: [../tests/0337-unused-function-parameter.md](../tests/0337-unused-function-parameter.md)

## Цель и контекст

Кандидат заведён замером 0336 — там неиспользуемый параметр всплыл как помеха
проверке. Отдельный замер показал, что целей три, а не одна.

## Зависимости фичи (правило 17/19)

- **Зависит от:** 0260 (признак и идиома у цели `c`), 0169 (приём поглощения у
  `sv`). Закрыты.
- **Влияние на порядок разработки:** снимает кандидата, заведённого 0336.

## Требования и проверяемые условия

- **R1.** `c`: `(void)v;`, `cc -Werror` молчит.
- **R2.** `rust`: `let _ = v;`, сборка под `-D warnings`.
- **R3.** `sv`: поглощение редукцией, `verilator -Wall` и `yosys` молчат.
- **R4.** Используемый параметр заглушки **не** получает.
- **R5.** Имя параметра в сигнатуре не изменилось.
- **R6.** Вывод корпуса не изменился.

## Разбор

### Почему признак общий, а идиомы разные

Вопрос «пользуется ли тело параметром» один и решается одинаково — по
напечатанному тексту. Идиома же принадлежит целевому языку, и у каждого своя:
в C это приведение к `void`, в Rust — связывание с `_`, в SystemVerilog —
поглощение редукцией (объявлений «неиспользуемо» там нет вовсе).

### Почему буфер

Чтобы задать вопрос напечатанному телу, тело надо сперва напечатать. У
`Printer` для этого уже есть `fork`, заведённый фичей 0260 ровно с этой целью —
и наследующий уровень отступа.

## Риски

- **Ложное «использован»** при совпадении имени с подстрокой: снято проверкой
  границ идентификатора (тот же урок 0260, где `domain` содержит `main`).
