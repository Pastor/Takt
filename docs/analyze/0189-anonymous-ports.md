# Анализ фичи 0189: Анонимные порты

> Фича: [../features/0189-anonymous-ports.md](../features/0189-anonymous-ports.md) · ADR: [../adr/0189-anonymous-ports.md](../adr/0189-anonymous-ports.md) · тест-план: [../tests/0189-anonymous-ports.md](../tests/0189-anonymous-ports.md)

## Цель и контекст

[ADR 0189](../adr/0189-anonymous-ports.md) принят решением заказчика 2026-08-01
по семи осям: `#A:B as T` — поле разрядности `T` с бита `B` (1A), формы `.B` и
`:B as T` законны обе с разным смыслом (2A), запись даёт предупреждение с
названным способом снять (3B), поддерживают `c-hal`/`st-at`/`sv-mmio` (4A),
симулятор моделирует ячейку синтетическим портом (5B), обособленным оператором
остаются только присваивание и вызов (6A), голый адресный литерал вне позиции
адреса запрещён (7A).

Анализ переводит это в точки кода, задачи, замеры и риски.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет. [0187](../features/0187-port-io-redesign.md) закрыта
  2026-08-01; принятая ею модель (`at` размещает, `:=` — начальное значение,
  доступ нормирован таблицей) — вход этой фичи, а не ожидание.
- **Влияние на порядок разработки:** фича не разблокирует ничего — ни одна
  незакрытая фича на 0189 не ссылается. Порядок таблицы `FEATURES.md` не
  меняется: 0189 стоит первой как единственная проработанная до `АНАЛИЗ`.
- **Смежно:**
  - [0020](../features/0020-port-address-decl.md) — три источника адреса.
    Анонимное обращение **четвёртым источником не является**: у ячейки нет
    имени, значит ни оператор `address`, ни `--address-map` её не адресуют.
    Приоритет источников не трогается.
  - [0098](../features/0098-port-bit-range-safe-hal.md) — предел бита `[0, 63]`
    и ширина доступа по слову; анонимное обращение подчиняется тем же правилам,
    иначе `c-hal` получит два разных закона для одной ячейки.
  - [0187](../features/0187-port-io-redesign.md) — таблица доступа и её сторож
    `takt-lang/tests/port_access_contract_tests.rs`: анонимный доступ входит в
    **ту же** таблицу.

## Что подтверждено пробами и чтением кода (2026-08-01)

1. **Токен `#` уже есть** (`Token::Sharp`, `parser/lexer.rs`), в грамматике не
   используется, в `lsp/semantic_tokens.rs` разобран. Нового токена не нужно.
2. **Адресный литерал уже атом выражения** (`Precedence1Full`,
   `Precedence1NoBrace`) и даёт `ExpressionNode::Address(addr, bit)`. В грамматике
   **условий** его нет (проба: `ref Done: 0x105:0 = 1;` → `SY-002`).
3. **Голый адресный литерал в теле — молчаливое расхождение (Tier 1).** Проба:
   `always { x := 0x105:0; }` — симулятор `x = 5` (адрес как число, обёртка
   `u8`), цель `c` **теряет оператор целиком**, `rust`/`st`/`sv` отказывают
   (`RS-011`/`ST-011`/`SV-002`). Ось 7A устраняет причину.
4. **Обособленное выражение принимается языком.** Проба: `always { x + 1; }`
   компилируется, цель `c` печатает `model->x + 1;`, а гейт `cc -Wall -Werror`
   отвергает вывод (`error: expression result unused [-Wunused-value]`). Ось 6A
   устраняет причину.
5. **`if` в теле разбирается через `Expression`** (`grammar.lalrpop`,
   `OpenStatement`/`ClosedStatement`), а не через `Condition`. Значит требование
   заказчика `if #0x346619.4 && b = 4 { … }` покрывается атомом **выражения**;
   грамматика **условий** нужна отдельно — для рёбер `ref` и именованных `cond`.
6. **В грамматике условий нет `as`** (факт фичи 0143: «`*`, `/` и `as` там
   отсутствуют»). Следствие: в условии выразима только **битовая** форма
   `#A.B`; словная требует приведения и потому в условии незаконна.
7. **Механику доступа по адресу имеют три цели** — `c-hal` (таблица
   `{addr, bit, width}` + `*(volatile uintN_t*)`), `st-at` (локация `%IX256.0` у
   **именованной** глобальной), `sv-mmio` (срез `reg[bit +: width]`). Имени не
   требует только `c-hal`.
8. **Прецедент точной диагностики парсера есть**: `parse_entry.rs`
   перехватывает `ParseError::UnrecognizedToken` по токену `:=` и печатает
   `SY-006` — правило языка вместо механики разбора (фикс 0187-01).
9. **Свободные коды:** `SE-096`, `SE-097`, `SE-098`; `SY-007`, `SY-008` (занято
   до `SE-095` и `SY-006`; `SE-091` — `RETIRED`).

### Замер цены ломающих осей (2026-08-01)

| Ось | Что отвергается | Найдено в проекте |
|---|---|---|
| 7A | голый `0xNNN:B` в выражении | **0** в `.takt` (корпус, `book/`, все фикстуры). 16 совпадений в `.rs` — это **карты адресов** (`.ld`-формат) и доктест `parse_address_literal`, к выражениям отношения не имеют |
| 6A | обособленное выражение-оператор | **0** в `.takt`: все 21 совпадение эвристики — поля структур, `break;`, `return;` |

и часть из них разбирает именно эти формы (`parser_tests.rs:378`,
`parser_tests/part2.rs:935` проверяют разбор адресного литерала **как
выражения**). Их правка — часть задачи 0189-06; полный список даст прогон, а не
греп.

## Форма и её разбор

### Синтаксис (принят ADR)

```
AnonAddress ::= '#' AddressLiteral      // #0x346619:3 — начало поля бит 3
              | '#' HexNumber           // #0x346619   — начало поля бит 0
Ширина      ::= 'as' Type               // обязательна, кроме битовой формы
Бит         ::= '.' Number              // #0x346619.4 — один бит
```

### Как это ложится на существующие узлы

Обращение **не** поглощает `as` и `.N` в свой узел: оба оператора в языке уже
есть (`Expression::Cast`, `Expression::BitAccess`), у них свои приоритеты
(`Chain7` и постфикс), и дублировать их разбор внутри нового атома значило бы
завести вторую грамматику приведения. Поэтому:

| Запись | Дерево АСД | Узел семантики |
|---|---|---|
| `#0x346619:0 as u64` | `Cast(AnonAddress(0x346619, 0), u64)` | `AnonPort { addr, bit: 0, width: 64 }` |
| `#0x346619.4` | `BitAccess(AnonAddress(0x346619, 0), 4)` | `AnonPort { addr, bit: 4, width: 1 }` |
| `#0x346619:3 as u8` | `Cast(AnonAddress(0x346619, 3), u8)` | `AnonPort { addr, bit: 3, width: 8 }` |
| `#0x346619` | `AnonAddress(0x346619, 0)` | **`SE-097`** — ширина не задана |

**Канонизация — в одной воронке.** Свёртку `Cast`/`BitAccess` над `AnonAddress`
в тройку делает **одно** место семантики (образец — `canonicalize_state_of`
фичи 0074, где скобки паттерна снимаются в единственной воронке
`resolve_condition`). Обёртки `Parenthesis` снимаются **только** у операнда
анонимного обращения: глобально их снимать нельзя — генераторы печатают их как
группировку (урок 0074).

⚠️ **Ширину задаёт ближайшее приведение.** `#A as u32 as u8` — доступ шириной 32
с последующим сужением значения до `u8`, а не доступ шириной 8: приведение,
стоящее непосредственно над обращением, задаёт **ширину доступа к памяти**, все
последующие — обычные операции над прочитанным значением. Иначе ширина
обращения к MMIO зависела бы от хвоста выражения.

## Требования и проверяемые условия

### Форма и разбор

- **R1.** `#0x346619:0 as u64`, `#0x346619.4`, `#0x346619 as u32` разбираются в
  позиции **выражения** (тело блока, тело функции, `if`, аргумент вызова,
  инициализатор).
- **R2.** `#0x346619.4` разбирается в позиции **условия** (ребро `ref`,
  именованный `cond`, `invariant`). Словная форма в условии незаконна и даёт
  **называющую** диагностику (в грамматике условий нет `as` — факт 6), а не
  `SY-002` про неведомый токен.
- **R3.** Позиции узла сохранены: диагностика указывает на само обращение, а не
  на начало оператора.
- **R4.** Форматтер печатает обращение обратно байт-в-байт, сохраняя выбор формы
  (`.4` против `:4 as bit`): синонимы не канонизируются, как `while`/`loop`.
- **R5.** Предел глубины разбора (`MAX_PARSE_DEPTH`, 0156) считает новый узел, а
  отвергнутое дерево утилизируется итеративно (`parser/depth/dismantle.rs`).

### Семантика

- **R6.** Узел семантики несёт **тройку** `{addr, bit, width}` — ту же, которой
  оперируют `c-hal` и `sv-mmio`.
- **R7.** Ширина не задана (`#A` без `as` и без `.B`) → **`SE-097`**,
  называющая, чего не хватает.
- **R8.** Запись по анонимному адресу → предупреждение **`SE-096`**, текст
  которого **называет способ снять**: объявить именованный порт с тем же
  адресом (решение 3B). Чтение — молча.
- **R9.** Бит вне `[0, 63]` либо `bit + width > 64` → **`SE-098`**. Пределы те
  же, что у именованного порта (0098): два закона для одной ячейки недопустимы.
- **R10.** Тип выражения — тип ширины (`as T` → `T`; `.B` → `bit`), а не
  `Unsupported`: иначе проверки типов обойдут обращение молча.

### Ломающие правила (оси 6A и 7A)

- **R11.** Обособленным оператором остаются **присваивание** и **вызов
  функции**; `x + 1;`, `#A.4;`, `A;` → **`SY-007`** от **парсера**, с текстом о
  правиле языка, а не о механике разбора (прецедент `SY-006`).
- **R12.** Голый адресный литерал вне позиции адреса (`x := 0x105:0;`) →
  **`SY-008`**, текст которого называет замену (`#0x105:0 as ТИП`). Позиции
  `at`, `address` и внешняя карта не затронуты.
- **R13.** Миграция фикстур выполнена в этой же фиче; `precheck.sh` зелёный.

### Потребители

- **R14. Симулятор** исполняет обращение как синтетический порт
  (имя строится из адреса, бита и ширины): значение читается и пишется,
  наблюдаемо в трассе, задаётся сценарием по имени (механизм 0132).
- **R15. `c-hal`** порождает доступ `*(volatile uintN_t*)0xADDR` со сдвигом и
  маской по `{bit, width}` — той же формы, что дефолтный HAL именованного порта.
- **R16. `st-at`** порождает размещённую переменную с синтезированным именем;
  `iec2c` вывод принимает.
- **R17. `sv-mmio`** порождает срез регистрового файла `[bit +: width]`; чтение
  — вход регистрового файла, запись — выход (направление принадлежит биту,
  правило 4 ADR 0062). Оба инструмента (`verilator`, `yosys`) вывод принимают.
- **R18. `c`, `rust`, `st`, `sv`** отказывают **с причиной** («доступ по адресу
  требует цели с картой памяти: `c-hal`, `st-at`, `sv-mmio`»), а не теряют
  оператор молча.
- **R19. Сверка потактовая:** симулятор ≡ `c-hal` на модели с чтением и записью
  анонимной ячейки. Гейт цели доказывает компилируемость, но не верность (уроки
  0045, 0050).
- **R20.** Таблица контракта доступа 0187 расширена строкой анонимного
  обращения, сторож падает при отклонении.

### Общее

- **R21.** Версия языка: `0.8.0` не выпущена — изменения накапливаются в неё
  (правило 22), подъёма нет.
- **R22.** Редакторский слой (правило 29) — см. раздел ниже; ответ «не нужно»
  фиксируется наравне с правкой.
- **R23.** Документ `book/`: разделы 05 (выражения) и 08 (порты и адреса) плюс
  приложение «Ошибки и предупреждения» (`SE-096`…`SE-098`, `SY-007`, `SY-008`).

## Особенности по обратной совместимости (правило 11)

- **Ломающих изменений два**, оба приняты заказчиком осознанно:
  - обособленное выражение-оператор перестаёт быть законным (`SY-007`);
  - голый адресный литерал в выражении перестаёт быть законным (`SY-008`).
- **Цена в проекте близка к нулю** (замер выше): в `.takt` нет ни одного случая
  ни того, ни другого; правки требуют лишь строковые фикстуры тестов парсера,
  сознательно проверяющие отменяемые формы.
- **Цена у пользователя** ненулевая, но обе отменяемые формы сегодня либо молча
  неверны (адресный литерал: расхождение эталона и цели `c`), либо отвергаются
  инструментом цели на порождённом файле (обособленное выражение:
  `-Wunused-value`). Отменяется то, что и так не работало.
- **Переходного периода нет** — прецедент 0187, решение заказчика.
- **Приоритет источников адреса (0020) не трогается**: анонимное обращение
  четвёртым источником не является.
- **Версия языка** не поднимается: `0.8.0` не выпущена (правило 22).

## Риски

- **Риск: две грамматики (выражения и условия) разъедутся.** Атом `#` вводится в
  обе; забыть вторую легко, а проявится это как `SY-002` на законном ребре.
  Снижение — критерий A2 и фикстура с ребром `ref Next: #0x100.0;`.
- **Риск: свёртка `Cast`/`BitAccess` окажется в двух местах.** Уроки 0042
  («арифметика — в одном месте») и 0074 («канонизация — в единой воронке»):
  свёртка пишется один раз, оба потребителя (выражения и условия) зовут её.
- **Риск: ширина доступа станет догадкой.** Класс 0029 (`_ => 4`): если
  приведение не найдено, обязан быть **отказ** `SE-097`, а не умолчание.
- **Риск: `SE-098` разойдётся с `SE-060`.** Предел бита у именованного порта
  считает слой адресов, у анонимного — семантика. Значение предела и правило
  ширины слова обязаны браться из **общего** места, иначе один и тот же адрес
  получит два закона.
- **Риск: цель `c` потеряет оператор молча** — ровно тот дефект, который фича
  устраняет. Отказ обязан быть **возвращён вызывающему**, а не проглочен
  печатником (класс 0155); критерий A13 проверяет наличие диагностики, а не
  отсутствие вывода.
- **Риск: 5B скроет перекрытие полей.** Симулятор моделирует `#A as u8` и
  `#A as u32` как **разные** порты, `c-hal` читает одну и ту же память. Это
  осознанное ограничение (ADR, раздел Decision) — оно обязано попасть в документ
  и в отчёт, иначе станет молчаливым расхождением.
- **Риск: `SY-007` заденет законную форму.** Вызов функции, возвращающей
  значение (`beep();` при `fn beep() -> u8`), обязан остаться законным: эффект у
  него есть. Проверяется отдельной фикстурой.
