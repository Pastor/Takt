# Анализ фичи 0163: Исчерпывающий разбор узлов во втором вычислителе

> Фича: [../features/0163-builder-eval-exhaustive.md](../features/0163-builder-eval-exhaustive.md) · ADR: [../adr/0163-builder-eval-exhaustive.md](../adr/0163-builder-eval-exhaustive.md) · тест-план: [../tests/0163-builder-eval-exhaustive.md](../tests/0163-builder-eval-exhaustive.md)

## Цель и контекст

Реализовать **Option A** ADR 0163: распространить инвариант исчерпывающего
разбора на второй вычислитель. Работа целиком в `takt-sim` плюс расширение
гейта. Язык **не меняется**, версия языка не растёт.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет.
- **Влияние на порядок разработки:** ничего не блокирует. Смежна с фичей 0034
  (её территория — структуры и инициализаторы), но пересечения нет: правится
  принуждение, а не поведение.

## Разбор: где именно правило не действовало

Подстановочные ветки `builder.rs` на входе (номера после правок фичи 0181):

| Строка | Разбор по | В области правила ADR 0093? |
|---|---|---|
| 199 | `Option<&TypeNode>` | нет — не узел языка |
| 220 | `Value` | нет — тип крейта |
| **232** | **`ExpressionNode`** | **ДА — цель фичи** |
| 262 | `TypeNode` | нет |
| 346 | `StateNode` | нет |
| 573 | `Extend` | нет |

То есть в область правила попадает **одна** ветвь — `_ => None` в `eval_expr`.
Карточка перечисляла четыре места; замер показал, что три из них разбирают не
узлы языка. Уточнение существенно: расширять правило на `TypeNode`/`Extend` —
отдельное решение, а не часть этой фичи.

**Прецедент срабатывания уже был.** Над `_ => None` стоял комментарий: ветвь
`Duration` (фича 0134) пришлось вписать вручную, потому что без неё
`var left: duration := 1m30s;` молча превращалась в «значения нет». Дефект
поймал тест — то есть правило отсутствовало, и цена уже уплачена.

## Требования и проверяемые условия

- **R1. `_ =>` по `ExpressionNode` не собирается.** Принуждение — компиляторное,
  а не соглашение.
- **R2. Снятие `deny` отвергает гейт** — в **любом** из двух модулей.
- **R3. Гейт не обманывается комментарием.** Упоминание атрибута в док-тексте не
  должно засчитываться за атрибут.
- **R4. Поведение не изменилось.** Варианты, прежде попадавшие в `_ => None`,
  дают тот же `None`; корпус и порождённый код не тронуты.
- **R5. Лимит размера соблюдён.** Ни `builder.rs`, ни новый модуль не выходят за
  1000 строк; реестр долга не пополняется.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | компилятор отвергает `_ =>` (R1) | мутация: вернуть `_ => None` → `cargo clippy` отказывает |
| A2 | гейт отвергает снятие `deny` в `initial.rs` (R2) | мутация + `check-exhaustive-nodes.sh` |
| A3 | гейт отвергает снятие `deny` в `eval/` (R2) | мутация + гейт |
| A4 | гейт не обманывается комментарием (R3) | та же мутация A2 при сохранённом док-тексте |
| A5 | поведение не изменилось (R4) | `cargo test --all-features` зелёный; `git diff examples/generated` пуст |
| A6 | размеры (R5) | `scripts/check-module-size.sh`; `builder.rs` 927 → 896, `initial.rs` 128 |
| A7 | корпус зелёный | `./scripts/precheck.sh` |

## Особенности по обратной совместимости (правило 11)

Изменение **внутреннее**: публичный API крейтов не затронут, поведение
вычислителя прежнее. Порождённый код и трассы симулятора не меняются — правка
касается того, что произойдёт при добавлении **будущего** узла языка.

Прочие стеки (цели генерации, LSP, плагины) — **н/п**.

## Риски

- **Риск «перечислили и забыли».** Длинная ветвь «не константа» соблазняет
  дописывать в неё новый вариант не думая. Снижение: у ветви стоит объяснение,
  **почему** эти узлы не константы (читают состояние, зовут функции, ветвятся),
  то есть автор обязан сопоставить с ним свой узел.
- **Риск мнимого сторожа.** Гейт может выглядеть работающим и не работать —
  ровно это и вскрыла мутация (`grep -F` находил атрибут в комментарии).
  Снижение: каждая ловушка проверена мутацией, а не чтением.
- **Риск разрастания правила.** Соблазн навесить `deny` на весь `builder.rs`
  затронул бы разбор `TypeNode`/`StateNode`/`Extend`, где подстановочная ветвь
  осмысленна. Снижение: модуль вынесен **узкий**, по теме.
