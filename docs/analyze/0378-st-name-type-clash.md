# Анализ фичи 0378: Имя переменной, совпавшее с именем типа, у цели st

> Фича: [../features/0378-st-name-type-clash.md](../features/0378-st-name-type-clash.md) · ADR: [../adr/0378-st-name-type-clash.md](../adr/0378-st-name-type-clash.md) · тест-план: [../tests/0378-st-name-type-clash.md](../tests/0378-st-name-type-clash.md)

## Цель и контекст

Класс найден **пробой чужой фичи**: при работе над 0373 проба назвала локальную
`pair` при типе `Pair`, и `iec2c` отверг файл по причине, к предмету 0373
отношения не имевшей. Дважды подряд это уводило замер не туда — потому класс и
записан отдельно.

### Замер (`scripts/probe.sh -n 2`, 2026-08-21)

Вход: `struct Pair { lo: u8, hi: u8 } var pair: Pair := {1, 2};` с чтением и
записью полей.

| Потребитель | Ответ |
|---|---|
| эталон | исполняет (`a=1,2`, `b=11,12`) |
| `c`, `c-hal` | `cc` принял |
| `rust` | `rustc` принял · `clippy` принял |
| `sv`, `sv-mmio` | verilator принял · yosys синтезировал |
| `st`, `st-at` | **`iec2c` ОТВЕРГ:** `invalid variable(s) declaration` |

⚠️ `taktc` во всех восьми случаях вернул **ноль**.

⚠️ Ответ `iec2c` **обманчив**: на голом `pair : Pair;` он отвечает «invalid
located variable declaration» и «unexpected token after 'VAR' in located
variable(s) declaration» — то есть указывает на размещение `AT %…`, которого в
объявлении нет вовсе. Проба с переименованным типом (`PairT`) проходит: это и
доказало, что дело в столкновении имён, а не в структуре как таковой.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет. 0065 (`ST-014`, плоское пространство имён IEC) и 0293
  (структуры у целей) закрыты.
- **Влияние на порядок разработки:** снимает кандидат «Переменная, названная как
  её тип, ломает вывод цели `st`».

## Требования и проверяемые условия

- **R1. Отказ с причиной.** Столкновение даёт `ST-023`, называющий имя
  переменной и имя типа.
- **R2. Отказ принадлежит цели.** Текст говорит, что модель остаётся валидной
  для прочих шести целей (образец `ST-014`, `SV-012`).
- **R3. Регистронезависимость.** `PAIR`, `Pair`, `pair` — одно и то же.
- **R4. Контрпример.** Непересекающееся имя переводится, и `iec2c` вывод
  принимает.
- **R5. Один список имён.** Имена типов берутся у тех же карт, из которых цель
  печатает раздел `TYPE` (включая предков).
- **R6. Реестры.** Код внесён в `docs/diagnostics/README.md` и в сводную
  таблицу приложения «Ошибки» (гейт 0290 требует тождества множеств).

## Особенности по обратной функциональности

Ломающее изменение **формально**: модель, где переменная названа как тип,
перестаёт транслироваться целью `st`. Но прежде она транслировалась в файл,
который `iec2c` **не принимает**, то есть работоспособного вывода не было и
раньше — меняется лишь то, кто и как об этом говорит.

## Риски и зависимости

- **Ложное срабатывание** запретило бы валидное имя. Снижение: сравнение идёт
  только с **объявленными в файле** типами, и контрпример стоит рядом.
- **Граница:** воронка стоит на объявлениях переменной, порта и константы;
  столкновение имени типа с именем функции или состояния не измерялось.
