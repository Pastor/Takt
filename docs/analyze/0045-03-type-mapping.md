# Анализ 0045-03: Отображение типов Lam → SystemVerilog

> Обзор: [0045-sv-backend.md](0045-sv-backend.md) · ADR: [../adr/0045-sv-backend.md](../adr/0045-sv-backend.md) (вопрос 4) · задача: [../development/0045-03-type-mapping.md](../development/0045-03-type-mapping.md) · тест-план: [../tests/0045-sv-backend.md](../tests/0045-sv-backend.md)
>
> Требования **R4**, **R5**; критерии **A5**, **A6**, **A7**, **A11**.

## Вход: `TypeNode`

`semantic/type_node.rs:496`, помечен **`#[non_exhaustive]`** (строка 495).
Варианты: `Bit`, `Bool`, `Rational`, `Array(u16, Box<TypeNode>)`, `Enum(String)`,
`Struct(String)`, `Integer { bits: u8, signed: bool }`, плюс служебные
(`Inference`, `Address`, `Unsupported`, `Unit`, `Builtin*`).

Тот же вход, что у `get_c_type` (`generator/c/mod.rs:150`) и у будущей
`get_st_type` (0041-02). **Общего слоя отображения не заводим** — решение ADR 0045
(вопрос 4) и ADR 0041 (вопрос 2), принятое **независимо и одинаково**: три цели —
три несовместимые системы типов.

## Нормативная таблица `T1..T14`

Сигнатура: `fn get_sv_type(typ: &TypeNode, model: &ModelNode) -> Result<String, Diagnostic>`.

**Отличие от C принципиально:** `get_c_type` возвращает `Option<String>` и на
непокрытом узле отдаёт `None` — **молча** (класс «тихий пропуск», дефект фичи
0029). `get_sv_type` возвращает `Result` и на непокрытом узле отдаёт **ошибку**
(R4). Это не стилистика, а прямое следствие уроков 0025/0028/0029.

| # | `TypeNode` | **SystemVerilog** | Примечание |
|---|---|---|---|
| **T1** | `Bit` | **`logic`** | **Идеальное соответствие.** `bit` Lam = один провод/триггер. В C — `int` (32 бита, **дефект 2 фичи 0029**), в ST — `BOOL`. Только SV выражает это точно. Корпус: `stacker.lam` — 13 портов, `elevator_mini.lam` — 44 |
| **T2** | `Bool` | `logic` | Совпадает с T1 по представлению; различие `Bit`/`Bool` семантическое (Lam их различает), для RTL оба — один провод |
| **T3** | `Integer{8,false}` | `logic [7:0]` | Разрядность **буквальна**: 8 триггеров, а не байт в машинном слове |
| **T4** | `Integer{16,false}` | `logic [15:0]` | |
| **T5** | `Integer{32,false}` | `logic [31:0]` | |
| **T6** | `Integer{64,false}` | `logic [63:0]` | |
| **T7** | `Integer{N,true}` | `logic signed [N-1:0]` | `signed` меняет семантику сравнений и сдвигов — обязателен |
| **T8** | `Integer{N,*}`, N ∉ {8,16,32,64} | `logic [N-1:0]` | **Преимущество RTL:** произвольная разрядность бесплатна. C вынужден округлять до `uint{8,16,32,64}_t` (кандидат 0029 заводит `CC-014` на прочие N) — в SV `logic [11:0]` совершенно нормален |
| **T9** | `Rational` | **ошибка `SV-003`** | **Граница цели.** Разбор ниже |
| **T10** | `Array(N, T)` | `<T> name [0:N-1]` | **Настоящий массив** (распакованный). В C — `uint{N}_t` (число элементов путается с разрядностью), а переменная **молча исчезает** — **дефект 1 фичи 0029**. Контрпример A6 |
| **T11** | `Enum(name)` | `typedef enum logic [W-1:0] { … } name_e;`, W = ⌈log₂(вариантов)⌉, минимум 1 | Типобезопасно; в осциллограмме видны **имена**, а не числа — критично для отладки RTL |
| **T12** | `Struct(name)` | `typedef struct packed { … } name_t;` | Упакованная — синтезируема. Поле-массив → **`SV-004`** (см. ниже) |
| **T13** | `Unit` | `void` | Только в `function automatic void f(…)` |
| **T14** | `Inference`, `Unsupported`, `Address`, `Builtin*` | **ошибка `SV-002`** | Никогда `None`/пропуск. В C — `None` **молча** |

**Вынужденная ветка `_`.** `TypeNode` помечен `#[non_exhaustive]`
(`type_node.rs:495`), поэтому `match` обязан иметь ветку `_` — та самая коллизия
из процессного бэклога («`#[non_exhaustive]` против запрета `_ =>`»). Ветка
возвращает **`SV-002`** (ошибку), а не `None` — ровно как `eval::coerce_to_type`
(исключение, зафиксированное ADR 0025 по той же причине).

## `Rational` — граница цели, а не дефект (T9)

**В синтезируемом RTL типа с плавающей точкой не существует.** `real` в
SystemVerilog — конструкция **только для симуляции и тестбенчей**; арифметика с
плавающей точкой в железе — это IP-ядро (десятки тысяч ячеек, многотактная
латентность, свой протокол готовности), а не тип данных.

**Проверено фактически** ([0045-02](0045-02-validation.md), проба 2):

| Инструмент | `real` в `always_ff` | Код |
|---|---|---|
| `verilator --lint-only -Wall` | **принял молча** | **0** |
| `yosys … synth` | `ERROR: syntax error, unexpected TOK_REAL` | **1** |

Отвергнутые альтернативы (ADR, вопрос 4):

- **Option R-B (fixed-point Q(m.n))** — математически правильный путь для
  управления, **но язык не выражает формат**: разрядность целой/дробной части,
  округление, насыщение. Генератор был бы вынужден **угадать** (Q16.16) — то есть
  молча изменить численную семантику: симулятор считает в f64, RTL считал бы в
  Q16.16 → сверка с симулятором проваливалась бы **by design**, а не из-за
  дефекта. Это языковое решение, а не решение бэкенда. → **кандидат**.
- **Option R-C (`real` только для симуляции)** — порождённый модуль **не
  синтезируется**, то есть цель `sv` не выполняет своё единственное обещание.
  Хуже: Verilator это **пропускает** — дефект уехал бы в CI незамеченным.

**Область запрета (уточнение).** `SV-003` — на **типы** переменных, портов и
полей структур. Константные выражения времени компиляции (свёртка `const`) под
запрет **не подпадают**: если `float`-константа участвует только в вычислении
целочисленного значения на этапе компиляции, её в RTL нет.

**Цена сегодня — нулевая.** Проверено `grep` по `examples/*.lam`: **0 вхождений**
`float`. Ни один пример корпуса не пострадает.

## Граничные случаи и их диагностики

| Случай | Решение | Код |
|---|---|---|
| `Rational` в типе переменной/порта/поля | ошибка | **`SV-003`** |
| Непокрытый/служебный узел `TypeNode` (`Inference`, `Unsupported`, `Address`, `Builtin*`) | ошибка | **`SV-002`** |
| Поле-массив внутри `struct packed` | ошибка: распакованный массив не входит в упакованную структуру | **`SV-004`** |
| `Array(0, T)` (нулевой размер) | ошибка: `[0:-1]` — не диапазон | **`SV-004`** |
| `Enum` без вариантов | ошибка: ширина не определена | **`SV-004`** |
| `Array` от `Array` (`[[u8;2];3]`) | допустимо: `logic [7:0] name [0:2][0:1]` — многомерный распакованный | — |
| `Integer{0,*}` | ошибка: `logic [-1:0]` невозможен | **`SV-004`** |
| `Integer{bits > 64}` | **допустимо** (`u128` → `logic [127:0]`): в RTL машинного слова нет. Контраст: кандидат 0029 заводит для C `CC-014`, т.к. `uint128_t` не существует | — |

Все — **диагностика**, ни один — «молча» (R4).

## Пространство кодов `SV-0xx`

**Проверено `grep` по `grammar/src`:** заняты `SE-*` (84 вхождения), `CC-*` (23),
`AM-*` (11), `PU-*` (1). Префикс **`SV-` свободен** (как и `ST-`, который
резервирует 0041). Пересечения нет.

Резервируются этой фичей:

| Код | Смысл | Задача |
|---|---|---|
| `SV-001` | ошибка записи файла (по образцу `PU-001`) | 0045-01 |
| `SV-002` | непокрытый узел `TypeNode`/АСД — **никакого тихого пропуска** | 0045-03 |
| `SV-003` | `Rational`/`float` в синтезируемом RTL | 0045-03 |
| `SV-004` | недопустимая форма типа (нулевой массив, поле-массив в `packed`, `Enum` без вариантов, `Integer{0}`) | 0045-03 |
| `SV-005` | `extern fn` — в синтезируемом RTL аналога нет | 0045-06 |
| `SV-006` | `inout`-порт — требует `oe`, невыразимого в Lam | 0045-04 |
| `SV-007` | коллизия имени порта со служебным `clk`/`rst_n` | 0045-04 |
| `SV-008` | неконстантный `enter` стартового состояния — не отображается в цепь сброса | 0045-05 |

## Связь с фичей 0029 — урок, не зависимость

Разобрано в [обзоре](0045-sv-backend.md). Кратко: `get_c_type` приватна для
C-бэкенда, SV её не вызывает; общий слой не заводится сознательно; 0029 к тому же
**ЗАБЛОКИРОВАНА** фичей 0026 — привязка к ней была бы вредна.

**Сводка «где SV лучше C» (все три — контрпримеры к дефектам 0029):**

| Дефект 0029 | C (как есть) | **SV** |
|---|---|---|
| 1. `Array(size, elem)` → `uint{size}_t`; переменная **молча исчезает** | `[u8; 4]` → `uint4_t` (невалидно) | `logic [7:0] data [0:3]` — **A6** |
| 2. `Bit` → `int` (32 бита) | `int flag;` | `logic flag;` — **A7** |
| 3. `Rational` → `float` (f32 против f64 симулятора) | тихое расхождение точности | **`SV-003`** — честный отказ |

**Полезный побочный эффект.** Таблица `T1..T14` — готовая спецификация «как должно
быть» для фичи 0029, когда та возьмётся за `get_c_type` (в той мере, в какой цели
сопоставимы).

## Проверка (задача 0045-03)

- Юнит-тесты `get_sv_type` — **по строке на вариант** `TypeNode` (14 шт., T1..T14).
- Тест на **вынужденную ветку `_`**: возвращает `Err`, а не `Ok`/`None`.
- Контрпримеры `grammar/tests/data/sv/invalid/*.lam` — по одному на `SV-002`,
  `SV-003`, `SV-004`; тест проверяет **код** диагностики, а не текст сообщения.
- **A6** — фикстура `var data: [u8; 4];` (**тот же вход**, что в пробе кандидата
  0029, где C молча теряет переменную) → в SV присутствует
  `logic [7:0] data [0:3]`.
- **A7** — `stacker.lam`: `input logic task_valid` (не `int`).
- Сперва **зонд** реального вывода, затем assertions против захваченного
  (`CLAUDE.md`: не угадывать строки).
