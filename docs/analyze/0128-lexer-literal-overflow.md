# Анализ фичи 0128: Диагностика вместо паники на числовом литерале больше `i64::MAX`

> Фича: [../features/0128-lexer-literal-overflow.md](../features/0128-lexer-literal-overflow.md) · ADR: [../adr/0128-lexer-literal-overflow.md](../adr/0128-lexer-literal-overflow.md) · тест-план: [../tests/0128-lexer-literal-overflow.md](../tests/0128-lexer-literal-overflow.md)

## Цель и контекст

Убрать отказ инструмента на числовом литерале, не помещающемся в `i64`, и
**назвать** границу диапазона. Решение — Option A
[ADR 0128](../adr/0128-lexer-literal-overflow.md): диагностика `LE-009`,
представление чисел не меняется.

## Зависимости фичи (правило 17/19)

- **Зависит от:** `нет`.
- **Влияние на порядок разработки:** никого не блокирует. Взята рано как самый
  дешёвый из трёх дефектов Tier 1 (две строки в лексере против сквозных правок у
  0127 и 0129).

## Что именно ломалось (воспроизведено пробой)

| Ввод | Прежде | Место |
|---|---|---|
| `0xFFFFFFFFFFFFFFFF` | паника, `rc = 101` | `lexer.rs`, `i64::from_str_radix(..).unwrap()` |
| `18446744073709551615` | паника, `rc = 101` | `lexer.rs`, `i64::from_str(..).unwrap()` |
| `9223372036854775807` | успех | — |

Полная маска `[bit;64]` — реалистичный, а не выдуманный ввод: тип официально
поддержан фичей [0078](../features/0078-bit-array-semantics.md).

## Требования и проверяемые условия

- **R1. Отказ устранён.** Литерал любой длины даёт диагностику, а не панику.
- **R2. Граница ровно на `i64`.** Значения `i64::MAX` и `0x7FFFFFFFFFFFFFFF`
  по-прежнему принимаются — правка не должна сузить диапазон «на всякий случай».
- **R3. Диагностика полезна.** Несёт **позицию** литерала и его **текст**:
  сообщение без места бесполезно в файле с сотней констант.
- **R4. Обе формы записи.** Десятичная и шестнадцатеричная ветви лексера
  правятся одинаково — иначе одна из них останется с `unwrap()`.
- **R5. Реестр и документация.** Новый код попадает в
  `docs/diagnostics/README.md` (гейт `check-diagnostic-codes.sh`), в таблицу и
  подробный разбор приложения «Ошибки» (правило 25) и в блок «Частые ошибки»
  раздела «Лексика» (правило 26).
- **R6. Версия языка.** Добавление диагностики меняет наблюдаемое поведение →
  подъём версии (правило 22).

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | десятичный литерал вне диапазона → `LE-009` | тест `decimal_literal_beyond_i64_is_diagnostic_not_panic` |
| A2 | шестнадцатеричный вне диапазона → `LE-009` | тест `hex_literal_beyond_i64_is_diagnostic_not_panic` |
| A3 | граница `i64` принимается | тест `literal_at_i64_boundary_still_lexes` |
| A4 | диагностика несёт позицию и текст | тест `out_of_range_literal_carries_position_and_text` |
| A5 | сквозная проба CLI | `taktc compile` на файле с `0xFFFFFFFFFFFFFFFF` → `rc = 1`, `LE-009`, без трассы паники |
| A6 | код в реестре | `./scripts/check-diagnostic-codes.sh` → rc 0 |
| A7 | версия языка согласована | `./scripts/check-language-version.sh` → rc 0 |
| A8 | предкоммит | `./scripts/precheck.sh` → `EXIT=0` |

## Особенности по обратной функциональности

**Ломающих изменений нет.** Ввод, который прежде принимался, принимается и
теперь: менялось поведение только на входе, который **ронял инструмент**, — то
есть ни одна работавшая программа не затронута. Вывод компилятора для корпуса
`examples/` байт-в-байт неизменен (корпус таких литералов не содержит).

Ужесточения диапазона **не произошло**: граница как была на `i64`, так и
осталась — она лишь перестала выражаться падением. Сторож направления — тест A3.

## Риски и зависимости

- **Риск: сузить диапазон правкой.** Снимается тестом A3 на граничных значениях.
- **Риск: починить одну ветвь из двух.** Снимается тестами A1 и A2 (десятичная и
  шестнадцатеричная записи проверяются раздельно).
- **Риск: остаться с непригодной диагностикой** (без позиции). Снимается тестом
  A4, который проверяет **смещение** литерала в исходнике, а не только факт
  ошибки.
- **Остаточное ограничение:** полная маска `[bit;64]` по-прежнему незаписуема —
  вынесено кандидатом (см. ADR, action items).
