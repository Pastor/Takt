# Анализ фичи 0049: Верификация модели (Model Checking) на основе LTL

> Фича: [../features/0049-model-checking-ltl.md](../features/0049-model-checking-ltl.md) · ADR: [../adr/0049-model-checking-ltl.md](../adr/0049-model-checking-ltl.md) · тест-план: [../tests/0049-model-checking-ltl.md](../tests/README.md)

## Цель и контекст

Довести конвейер верификации до рабочего: `lamc verify` проверяет LTL-свойства
(`: [LTL] φ;`) методом model checking. Затравка `verification/` (фича 0010) даёт
`Ltl`, `to_nnf`, `build_buchi` (GPVW); отсутствует середина — структура Крипке,
произведение, проверка пустоты, контрпример, CLI (картирование кода 2026-07-16,
пути в [ADR](../adr/0049-model-checking-ltl.md)).

По решению заказчика (2026-07-16, [ADR](../adr/0049-model-checking-ltl.md),
Option A) — **абстракция управляющего графа**: атом = имя состояния FSM, Крипке =
граф переходов автомата, данные абстрагированы. Конвейер: `A_¬φ =
build_buchi(Not(φ))` → произведение `K × A_¬φ` → проверка пустоты (достижимый
принимающий цикл) → вердикт + контрпример-лассо.

Анализ **не переоткрывает** решение ADR, но фиксирует уточнения, снятые чтением
кода:

1. **Разметка автомата Бюхи неявна.** `BuchiAutomaton.transitions` — рёбра
   `usize→usize` без пометки; литералы (`Atom`/`Not(Atom)`) лежат в
   `states[i]` (`buchi.rs:74`, `:90-96`). Для произведения их **извлекают** из
   состояния-множества, а не из ребра.
2. **Терминальные состояния FSM обрывают прогон.** Семантика Бюхи требует
   бесконечных слов; тупиковое/`End`-состояние (`get_end_states`, `mod.rs:201`)
   получает **самопетлю** (stutter), иначе у него нет исходящих рёбер и лассо не
   строится.
3. **`build_buchi` вызывается впервые из продуктового пути** — сейчас 0 вызовов
   вне юнит-тестов (`grep`). Отрицание — `Ltl::Not(Rc::new(φ))` (или `to_nnf`
   уже разворачивает `Not`).

## Зависимости фичи (правило 17/19)

- **Зависит от:** `0010`, `0035` — **обе `ГОТОВО`** → фича **не блокируется**,
  `ЗАБЛОКИРОВАНА` не ставится.

  | Фича | Статус | Характер связи | Блокирует? |
  |---|---|---|---|
  | [0010](../features/0010-verification-ltl.md) | ГОТОВО | Даёт `Ltl`, `to_nnf`, `build_buchi` — переиспользуются целиком | Нет (закрыта) |
  | [0035](../features/0035-ltl-in-blocks.md) | ГОТОВО | Разбор LTL во всех позициях + `collect_atoms`; `verify` читает `: [LTL]` формулы | Нет (закрыта) |
  | [0044](../features/0044-sim-assert-invariant.md) | ГОТОВО | Имя инварианта — атом LTL; в абстракции A атом = состояние, поэтому инвариант-атом (условие) в 0049 **не проверяется** (диагностика A4) | Нет |
  | [0048](../features/0048-deterministic-codegen.md) | ГОТОВО | Детерминизм вердикта опирается на упорядоченные обходы (`BTreeMap`/`BTreeSet` уже в `buchi.rs`) | Нет |

- **Влияние на порядок разработки:** 0049 никого формально не разблокирует, но
  реализует профильную цель (правило 12) и превращает затравку 0010 в работающий
  инструмент. Расширения (данные, `X`-stutter, трасса-контрпример) — отдельные
  фичи поверх готового конвейера.

## Требования и проверяемые условия

- **R1. Структура Крипке из `ModelNode`.** Конечный граф: вершины — состояния
  FSM (`states`), рёбра — `ref`-переходы (`references()`); терминальные/тупиковые
  вершины получают самопетлю (R2-инвариант бесконечности). Стартовая вершина —
  `get_start_state()`.
- **R2. Оценка атома.** `Ltl::Atom(name)` истинен в вершине `k` ⟺ `k` — состояние
  с именем `name`. Прочие атомы (не имена состояний) → диагностика (R7), не
  молчаливый false.
- **R3. Отрицание и автомат свойства.** `A_¬φ = build_buchi(Not(φ))` —
  переиспользование затравки без правок `buchi.rs`.
- **R4. Синхронное произведение.** Состояние произведения — пара `(k, q)`; переход
  `(k,q)→(k',q')` ⟺ `k→k'` в Крипке, `q→q'` в автомате, и **литералы** состояния
  `q'` согласованы с разметкой `k'` (атом `S` ∈ q ⟹ `k'=S`; `!S` ∈ q ⟹ `k'≠S`).
  Принимающие пары — где `q` принимающее.
- **R5. Проверка пустоты.** Достижимый из начальной пары **принимающий цикл**
  (nested-DFS или SCC Тарьяна). Есть цикл ⟹ язык непуст ⟹ `φ` нарушено.
- **R6. Контрпример-лассо.** При нарушении — путь «префикс до цикла + цикл» в
  терминах состояний FSM; помечен «абстракция управления» (over-approximation,
  ADR A4).
- **R7. Честная граница.** Атом, не являющийся именем состояния, даёт явную
  диагностику «в абстракции управления не поддержан; поддержаны имена состояний»
  (наследие 0035: ни один путь не молчит).
- **R8. CLI `lamc verify`.** Подкоманда: `lamc verify <file> [-I …] [--property
  "φ"]`. Без `--property` проверяет все `: [LTL]` формулы модели. Код возврата: 0
  — все держатся, ≠0 — есть нарушение.
- **R9. Детерминизм и завершаемость.** Вердикт воспроизводим (гейт 0048);
  проверка завершается на всех `examples/` (конечность Крипке).
- **R10. Версия языка не растёт.** Синтаксис не тронут; `lamc verify` —
  аддитивная оснастка (прецедент `lamc fmt`). Вывод целей `c`/`plantuml`/`st` не
  меняется.
- **R11. `verification/` — публичный вход.** Новый модуль (`kripke`, `product`,
  `check`) и публичная функция `verify_model(model, φ) -> Verdict` — по образцу
  `ltl_warnings`.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | `lamc verify` проверяет все `: [LTL]` модели: держится/нарушено + контрпример | Интеграционный тест на фикстурах; проба CLI |
| A2 | `G(Fault -> F Idle)` опровергается на модели без гарантии; подтверждается на модели с гарантией | Пара фикстур `verify/{holds,fails}.lam` + тест на вердикт и контрпример |
| A3 | Достижимость: `F Done` ⟺ `Done` достижимо из старта | Тест на малой Крипке (достижимо / недостижимо) |
| A4 | Атом-переменная/`cond` → диагностика «не поддержан», не молча false | Фикстура `verify/atom_not_state.lam` → диагностика |
| A5 | Проверка завершается на всех `examples/` | `lamc verify examples/*.lam` — без зависания |
| A6 | Вердикт детерминирован | 10 прогонов `verify` → один вердикт (гейт 0048) |
| A7 | Известные теоремы: `F p`/`G p` на малых Крипке дают ожидаемый вердикт | Юнит-тесты `verification/` на построенных вручную Крипке |
| A8 | `build_buchi`/произведение согласованы (пустота корректна) | Юнит-тесты: пустой/непустой продукт на эталонных φ |
| A9 | Версия языка не изменена; вывод генераторов неизменен | `git diff grammar.lalrpop`/Cargo.toml пуст; codegen-снапшоты зелены |
| A10 | Регрессий нет | `./scripts/precheck.sh`; `cargo test --all-features`; `cargo test --features lsp` |

## Особенности по обратной функциональности

**Обратная совместимость сохраняется полностью (правило 11).** Синтаксис не
меняется; `lamc verify` — новая подкоманда, `compile`/`fmt` не тронуты; вывод
генераторов байт-в-байт прежний; версия языка 0.3.0 не растёт (R10). Атом получает
**операционный** смысл (имя состояния) — это придание значения ранее
неспецифицированной конструкции (прецедент ADR 0025), а не слом: множество
принимаемых программ то же, ни одна валидная программа не меняет смысла компиляции.

## Риски и зависимости

| # | Риск | Оценка | Снижение |
|---|---|---|---|
| Р1 | Разметку автомата извлечь неверно (литералы в `states[i]`, не на ребре) | средний | Юнит-тест A8 на эталонных φ; извлечение — по `matches!(f, Atom\|Not)` как в `buchi.rs:92` |
| Р2 | Терминальные состояния без самопетли → нет бесконечных слов, лассо не строится | высокий, если забыть | R2/A2 — самопетля на `get_end_states` и тупиках; тест на завершаемой модели |
| Р3 | Over-approximation: ложный контрпример (недостижим по данным) | средний (осознанный) | ADR A4 — пометка «абстракция управления»; документируется, не выдаётся за точный |
| Р4 | Взрыв произведения на больших моделях | низкий (Крипке конечна = число состояний) | |Крипке|×|A| ограничено; A5 — завершаемость на `examples/` |
| Р5 | `parse_ltl` (тестовый, паникует, атом=1 символ) просочится в продукт | низкий | Продуктовый путь — `ltl_ast_to_semantic`; `--property` парсится им же (не `parse_ltl`) |
| Р6 | Недетерминизм вердикта (обходы `HashMap`) | низкий | `buchi.rs` уже на `BTreeMap`/`BTreeSet`; Крипке/произведение строить на `BTree*` (гейт 0048) |
| Р7 | Тесты «на факт построения», а не на вердикт (капкан 0025) | средний | Тесты утверждают **вердикт** (держится/нарушено) и **контрпример**, а не «автомат непуст» |
