# Анализ фичи 0065: Изоляция пространства имён цели `st`

> Фича: [../features/0065-st-namespace-isolation.md](../features/0065-st-namespace-isolation.md) · ADR: [../adr/0065-st-namespace-isolation.md](../adr/0065-st-namespace-isolation.md) · тест-план: [../tests/0065-st-namespace-isolation.md](../tests/0065-st-namespace-isolation.md)

## Цель и контекст

Кандидат называл две беды пространства имён `st` и утверждал про **обе**: «`iec2c`
ловит **громко**, **тихого расхождения нет** — поэтому кандидат, а не дефект».

**Проработка проверила пробами. Главная заявка опровергнута:** одноимённые `fn`
разных моделей склеиваются **молча**, и `iec2c` этого **не ловит**. Заведён
[фикс 0041-01](../fixes/0041-01-st-fn-dedup-silent.md), **Tier 1**.

ADR принял **Option A**: префикс POU именем модели (как в `c`) + диагностика
`ST-014` на столкновение со стандартной библиотекой IEC.

## Замер (пробы 2026-07-17, арбитр — `iec2c`)

| # | Что | Результат | Заявка кандидата |
|---|---|---|---|
| 1 | Две модели, у каждой `fn helper` с **разными** телами | **`st`: одна** `FUNCTION helper` с телом первой (`x + 1`); `iec2c` **принял** (rc=0). Эталон `c`: `DupA_helper` **и** `DupB_helper` | **ОПРОВЕРГНУТА** («громко») |
| 2 | `concat.lam` → `FUNCTION_BLOCK Concat` | `error: invalid function block name` — **громко** | подтверждена |
| 3 | Локальная `var left: u8` | `error: invalid located variable declaration` + `unexpected token after 'VAR'` — громко, но **обманчиво** (про `AT %…`, которых нет) | подтверждена |

**Механизм дефекта 1** — `st_func.rs:275`:

```rust
// Одноимённые функции разных моделей столкнулись бы; столкновение поймает
// `iec2c` («duplicate»), то есть громко, а не молча.
let mut emitted: Vec<String> = Vec::new();
```

Комментарий **неверен**: дедупликация именно и означает, что `iec2c` дубля **не
увидит**. Модель `B` вместо `w = 3` получает `w = 2` → `ref Done2: w = 3` не
срабатывает **никогда** → автомат стоит.

⚠️ **Кандидат унаследовал ошибку из комментария** — дословно. Из-за этого дефект
Tier 1 числился «долгом Tier 3». Урок: *формулировка кандидата — гипотеза, а не
факт, даже если списана из кода*.

## Зависимости фичи (правило 17/19)

- **Зависит от:** **нет**. Опоры **закрыты**: [0041](../features/0041-st-backend.md)
  (цель `st`), [0048](../features/0048-deterministic-codegen.md) (дифф корпуса
  читаем).
- **Пересечения:** [0066](../features/0066-st-bool-literals.md) правит
  `st_expr.rs` (печать выражений); 0065 — `st_func.rs`/`st_model.rs`/имена.
  Конфликта нет. [0060](../features/0060-enum-width-shared-layer.md) правит
  `st_type.rs` — тоже не пересекается.
- **Влияние на порядок:** **закрывает Tier 1** ([фикс 0041-01](../fixes/0041-01-st-fn-dedup-silent.md))
  → довод поднять фичу (критерий 4 правила 19). Никого не блокирует.

## Приоритет (Tier) — обоснование

**Tier 2** (кандидат утверждал Tier 3 — «не дефект»; проработка переоценила).

- Фича **закрывает Tier 1**-дефект: молчаливо неверный вывод, из-за которого
  автомат на ПЛК стоит.
- Против Tier 1 для самой фичи: дефект **условен** — бьёт только по моделям с
  одноимёнными `fn` в разных моделях, каких в корпусе нет.
- Против Tier 3: «изолировать имена» — не долг, когда один из его симптомов
  молча ломает поведение.

## Требования и проверяемые условия

- **R1. POU префиксуются именем модели** — как в цели `c`.
- **R2. Дедупликация по голому имени удаляется** вместе с причиной.
  ⚠️ Убрать её **не префиксуя** нельзя: `iec2c` даст «duplicate», то есть тихий
  дефект станет громким отказом на **корректной** модели.
- **R3. `ST-014`** — идентификатор совпал со стандартной функцией IEC либо
  ключевым словом.
- **R4. Сравнение без учёта регистра** (идентификаторы IEC регистронезависимы).
- **R5. Текст `ST-014` называет причину** — то, чего нет в диагностике `iec2c`.
- **R6. Проверка распространяется на имя модели** (берётся из имени файла).
- **R7. Комментарий `st_func.rs:275` исправлен** (он утверждает неправду).
- **R8. Прочие цели не задеты**; язык не меняется → версия не растёт.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Две одноимённые `fn` → **две** функции с разными телами | Фикстура + греп |
| A2 | Модель `B` даёт `w = 3`; переход срабатывает | Прогон |
| A3 | **Потактовая сверка `st`** — зелёная | Новая сверка (см. A-1 ADR) |
| A4 | `concat.lam` → `ST-014`, а не `invalid function block name` | Контрпример |
| A5 | `var left` → `ST-014` с причиной | Контрпример |
| A6 | `left`/`LEFT`/`Left` → одинаково | Контрпримеры |
| A7 | Гейт `iec2c` по корпусу зелёный; прочие цели побайтово прежние | `precheck.sh` + `git diff` |
| A8 | Комментарий исправлен | Ревью |
| A9 | Дифф `st` объяснён построчно | Ревью диффа |

## Особенности по обратной функциональности

**Вывод цели `st` изменится** (правило 11): имена POU получат префикс. Это
**ожидаемо** и объяснимо построчно (детерминизм — закрытая 0048). Прочие цели,
симулятор, LSP, форматтер — **не задеты** (A7).

⚠️ **Изменение контракта, названное честно:** модель с именем `Concat` или
переменной `left` перестанет собираться целью `st` **внятно** (`ST-014`). Сегодня
она **уже** не собирается — `iec2c` отвергает её обманчивым текстом. То есть
меняется **кто и как** об этом говорит, а не факт. **Это не регресс.**

Язык не меняется → версия не растёт (правило 22).

## Риски и зависимости

- **R-1. Поведенческую правку нечем проверить.** **Сверки для цели `st` не
  существует** (`conformance_{c,sv,rust}_tests` есть, `st` — нет). Именно поэтому
  0041-01 дожил: гейт `iec2c` доказывает компилируемость, но **не верность**
  (уроки 0045/0050). Снижение: A3 — завести сверку. ⚠️ Она требует **исполнять**
  порождённый ST (runtime), объём нетривиален → задача 0065-03; **может быть
  признана отдельной фичей**, если окажется несоизмерима.
- **R-2. Убрать дедупликацию, забыв префикс.** Дало бы «duplicate» от `iec2c` на
  корректной модели — громко, но неверно. Снижение: R1 и R2 — **одной** задачей.
- **R-3. Список стандартных функций IEC неполон.** Пропущенное имя → столкновение
  поймает `iec2c` (громко, но обманчиво). Снижение: прецедент `SV_KEYWORDS`;
  ⚠️ **структурный** случай (дубли) правилом 1 закрыт **независимо** от полноты
  списка — то есть худшее (тихое) не зависит от полноты.
- **R-4. Префикс сломает читаемость ST на ПЛК.** Инженер видит `Stacker_travel_time`
  вместо `travel_time`. Принято: ровно так уже делает эталон `c`; альтернатива
  (mangling) хуже — см. Option C ADR.
