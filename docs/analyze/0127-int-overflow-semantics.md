# Анализ фичи 0127: Единая семантика переполнения целых во всех целях

> Фича: [../features/0127-int-overflow-semantics.md](../features/0127-int-overflow-semantics.md) · ADR: [../adr/0127-int-overflow-semantics.md](../adr/0127-int-overflow-semantics.md) · тест-план: [../tests/0127-int-overflow-semantics.md](../tests/0127-int-overflow-semantics.md)

## Цель и контекст

Возвести уже существующий эталон (S1/S2 анализа
[0025](0025-simulator-expression-eval.md)) в **правило языка**, привести к нему
цель `rust` и проверить исполнением все четыре цели. Решение — Option A
[ADR 0127](../adr/0127-int-overflow-semantics.md).

## Зависимости фичи (правило 17/19)

- **Зависит от:** `нет`.
- **Влияние на порядок разработки:** **разблокирует
  [0134](../features/0134-language-time-model.md)** (модель времени): разрядность
  счётчика времени выбирает компилятор, и без определённой семантики
  переполнения выбор не обоснован.

## Что измерено до правки

| Цель | `u8`, `255 + 1` | `i8`, `127 + 1` |
|---|---|---|
| симулятор (эталон) | `0` — обёртка (S1) | **`SIM-003`**, прогон остановлен (S2) |
| `c` | `0` (тип `uint8_t`, обёртка определена C11 6.2.5p9) | **UB** (`int8_t`) |
| `rust` | **паника** `attempt to add with overflow` (debug) / `0` (release) | паника (debug) / обёртка (release) |
| `sv` | `0` (регистр `logic [7:0]`) | обёртка |
| `st` | **не проверялось никем** | не проверялось |

Ключевое: у цели `rust` результат зависел от **профиля сборки пользователя**, а
конструкция-источник (`always { t := t + 1; }`) есть в каждом примере книги.

## Требования и проверяемые условия

- **R1. Правило названо.** Беззнаковое — обёртка `mod 2ⁿ`; знаковое — ошибка
  программы. Записано в документ описания языка, а не только в анализ.
- **R2. Цель `rust` приведена к S1** — беззнаковая арифметика печатается
  обёрткой; результат не зависит от профиля сборки.
- **R3. Знаковый случай не «чинится» молча.** Обёртка для знаковых **не**
  печатается: тихое расхождение с эталоном (`SIM-003`) хуже паники.
- **R4. Проверка исполнением, а не декларацией.** Потактовая сверка переполнения
  во **всех четырёх** целях.
- **R5. Сторож взведён.** Откат правки генератора обязан красить сверку `rust`.
- **R6. Свёртка в `+=` не возвращает панику.** `x := x + 1` над беззнаковым не
  должен схлопываться в `x += 1`.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | цель `rust` печатает `wrapping_*` для беззнаковых | чтение вывода + сверка A3 |
| A2 | свёртка в `+=` для таких узлов отключена | греп по порождённому корпусу: `+= 1` над `u8` отсутствует |
| A3 | сверка `rust` | `unsigned_overflow_wraps_like_generated_rust` |
| A4 | сверка `c` | `unsigned_overflow_wraps_like_generated_c` |
| A5 | сверка `sv` | `unsigned_overflow_wraps_like_generated_sv` |
| A6 | сверка `st` (впервые) | `unsigned_overflow_wraps_like_generated_st` |
| A7 | взведённость сторожа | ручной откат `is_unsigned_int` → сверка `rust` краснеет |
| A8 | правило в документации | раздел «Типы» → «Переполнение» + «Частые ошибки» |
| A9 | предкоммит | `./scripts/precheck.sh` → `EXIT=0` |

## Особенности по обратной функциональности

**Меняется вывод цели `rust`** для любой беззнаковой арифметики: `a + b` →
`a.wrapping_add(b)`. Это **исправление**, а не поломка: прежний вывод в
debug-профиле паниковал вместо счёта. Программы, полагавшиеся на панику как на
сигнал (её не было в контракте), не существуют по построению — контракт языка
такого не обещал.

Вывод целей `c`, `sv`, `st` **не меняется** (там правило выполнялось само).
Знаковая арифметика во всех целях печатается как прежде.

## Риски и зависимости

- **Риск: обёртка для знаковых «за компанию».** Снят решением R3 и явной
  проверкой: знаковый `+` печатается прежним оператором.
- **Риск: сверка проходит потому, что обе стороны стоят.** Снят пиннингом трасс
  (ожидаемая последовательность записана числом в каждом тесте) и проверкой
  взведённости (A7).
- **Риск: сверка `st` невозможна из-за сдвига тактов.** Реализовался частично:
  цель `st` тратит такт на вход в каждый уровень стартового состояния
  (существующий долг контракта 0033). Снят той же конвенцией, что уже принята в
  Q-сверке: сравнение с поправкой на сдвиг **плюс** отдельная проверка, что
  переход `255 → 0` в трассе присутствует.
