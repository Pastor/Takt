# Анализ фичи 0278: Мёртвая упаковка последовательной композиции

> Фича: [../features/0278-compact-implement-dead-branch.md](../features/0278-compact-implement-dead-branch.md) · ADR: [../adr/0278-compact-implement-dead-branch.md](../adr/0278-compact-implement-dead-branch.md) · тест-план: [../tests/0278-compact-implement-dead-branch.md](../tests/0278-compact-implement-dead-branch.md)

## Цель и контекст

Кандидат ставил вопрос-развилку: `semantic::extend::compact_implement` — это
**мёртвый код** (удалить) или **отключённая ветвь** (назвать причину)?

Замер 2026-08-19 (ADR 0278) отвечает: мёртвый, и отключён он не «пока», а
**решением** — ADR 0057 рассмотрел этот путь как Option B и отверг его. Ответ
выбран в пользу удаления; попутно замер вскрыл, что мёртвое в модуле не одно, и
что прячет его **публичность**.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Правка изымает неисполняемый код; ни одна незакрытая
  фича на него не опирается (проверено грепом по `docs/features/`,
  `FEATURES.md` и коду).
- **Влияние на порядок разработки:** никого не разблокирует и не блокирует.
  Работа, которая когда-нибудь пересмотрит представление `A + B`, заведётся
  своей фичей и напишет реализацию заново — сегодняшняя ей всё равно не годится
  (безусловный `next`, обход `SE-106`, минимап).

## Требования и проверяемые условия

- **R1. Мёртвого кода в модуле не остаётся.** `compact_implement` и следы
  синтетической модели `X_Sequence` изъяты из `takt-lang/src` и `takt-sim/src`.
- **R2. Публичность не прячет мёртвое.** Наружу крейта из `semantic::extend`
  видны только типы `Extend` и `ParameterArgument`; функции и предикаты —
  `pub(crate)`, и всё, что после этого не зовётся никем, кроме собственных
  тестов, снято.
- **R3. Компилятор молчит.** `cargo clippy --all-targets --all-features` — без
  предупреждений: сужение видимости не оставило нерешённых `dead_code`.
- **R4. Поведение не изменилось.** `A + B` работает как прежде — эталон, цели,
  гейт синтеза, потактовые сверки.
- **R5. Комментарии говорят о правиле, а не о несуществующем коде.** Примечание
  в `validate/implemented.rs` переписано: реализация в дереве плоская — это
  свойство конвейера, а не «пока не включили».

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | `compact_implement`/`X_Sequence` в коде нет | `grep` по обоим крейтам |
| A2 | Наружу видны только типы | сборка `takt-sim` и тестов; ручной обзор `pub` модуля |
| A3 | Предупреждений нет | `cargo clippy --all-targets --all-features` |
| A4 | Поведение `A + B` прежнее | потактовые сверки sim ≡ C ≡ SV, гейт синтеза `batch_cycle`, прогон примеров |
| A5 | Регресс проекта | `./scripts/precheck.sh` |

## Особенности по обратной функциональности

Правило 11. **Наблюдаемое поведение инструментов не меняется вовсе**: изымается
код, который не исполняется с 7 апреля 2026 — ни одна программа на Takt не
проходит через него.

Формально сужается **публичный API крейта** `takt-lang`: из
`semantic::extend` перестают экспортироваться функции и предикаты. Крейт
публикуется только в этом репозитории; единственный внешний потребитель
(`takt-sim`) использует лишь типы `Extend` и `ParameterArgument` — проверено
грепом и подтверждается сборкой. Обоснование по правилу 11: сохранять
экспорт мёртвых функций значит сохранять то, ради чего класс и дожил, — `pub`,
который глушит `dead_code`.

**Версия языка не меняется** (правило 22): ни синтаксис, ни семантика, ни
наблюдаемое поведение целей фичой не затронуты.

## Правило 29: редакторский слой

Фича **не меняет** лексику, синтаксис и семантику языка, поэтому LSP и плагины
`extensions/` правок не требуют. Ответ фиксируется явно, как требует правило:
`compact_implement` не вызывался ни из одного пути, включая `lsp/`; изъятие
неисполняемой функции не может изменить ни подсветку, ни автодополнение, ни
структуру документа.

## Документирование (правило 24)

**Не требуется.** Документ `book/` описывает язык, а последовательная
композиция `A + B` описана в нём по её **наблюдаемому** поведению, которое не
меняется. Синтетическая модель `X_Sequence` в документе не упоминается ни разу
(проверено грепом): она была внутренним представлением, а не конструкцией языка.

Правится **живой контекст** `CLAUDE.md`: запись о последовательной композиции
получает причину, по которой упаковки в синтетическую модель нет и не будет без
отдельного решения.

## Риски и зависимости

- **Риск: сужение видимости вскроет мёртвый код, оставленный без решения.**
  Это не риск, а **цель** (R3): всё вскрытое либо получает потребителя, либо
  снимается в этой же фиче. Отступать к `pub` нельзя — иначе класс возвращается.
- **Риск: удаление заденет живой путь.** Снижается прогоном сверок и гейта
  синтеза (A4): `A + B` покрыт тремя свидетелями с разными наблюдаемыми
  (тестбенч SV, контракт сценария, харнесс C).
- **Риск: тесты модуля проверяли только удаляемое.** Юнит-тесты `extend.rs`
  просматриваются поимённо: сохраняются те, что проверяют **живое**
  (`unroll_extend_expression`, `Display`, `name`), снимаются те, что проверяли
  снятое.
