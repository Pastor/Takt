# Анализ фичи 0223: Три примера объясняют выходной порт устаревшей нуждой цели rust

> Фича: [../features/0223-examples-port-rationale-stale.md](../features/0223-examples-port-rationale-stale.md) · ADR: [../adr/0223-examples-port-rationale-stale.md](../adr/0223-examples-port-rationale-stale.md) · тест-план: [../tests/0223-examples-port-rationale-stale.md](../tests/0223-examples-port-rationale-stale.md)

## Цель и контекст

Снять из комментариев корпуса объяснение выходного порта `ready` нуждой цели
`rust` (`clippy::new_without_default`): после фичи 0174 модель без портов
получает `impl Default`, и линт молчит. Вместо удаления — замена **фактической**
причиной (решение ADR, Option B): у трёх примеров порт держит тестбенч SV, у
одного не держит ничего, и это надо сказать прямо.

Правка затрагивает **только комментарии** примеров. Язык, компилятор, симулятор
и порождаемый код не меняются.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Фича 0174, снявшая нужду, закрыта 2026-07-29 (коммит
  `728100a2`); фича 0214, давшая `regulator` вторую роль в гейте `sv-mmio`, —
  закрыта. Иных контрактных связей нет: правка не касается кода.
- **Влияние на порядок разработки:** никого не разблокирует. Фича независима и
  может быть выполнена в любой момент; её место в очереди определяется только
  приоритетом (Tier 4 — «прочее»).

## Требования и проверяемые условия

- **R1. Устаревшего объяснения не остаётся.** Ни один файл `examples/` не
  ссылается на `clippy::new_without_default` как на причину существования порта.
- **R2. Правка охватывает ЧЕТЫРЕ файла.** `regulator.takt`,
  `float_regulator.takt`, `pid_regulator.takt` — названы кандидатом;
  `batch_cycle.takt` несёт то же объяснение в своей формулировке и потому под
  греп кандидата не попал (замер ADR).
- **R3. Причина названа по факту.** Формулировка каждого файла соответствует
  таблице ADR: `regulator` — тестбенч SV + гейт `sv-mmio` (0214);
  `pid_regulator`, `batch_cycle` — тестбенч SV; `float_regulator` — гейтом не
  удерживается, стоит ради паритета с `regulator.takt`.
- **R4. Порты не снимаются.** Состав портов всех четырёх моделей прежний.
- **R5. Вывод целей не меняется.** Комментарий Takt в порождённый код не
  переносится, поэтому `examples/generated/` обязан остаться байт-в-байт
  прежним.
- **R6. Канон форматтера соблюдён.** `taktc fmt --check examples/` зелёный
  (комментарии печатает форматтер, привязка комментария к узлу — известное
  тонкое место, фиксы 0197-01/0198-01).

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | R1: устаревшего объяснения нет | `grep -rn 'new_without_default' examples/` — пусто |
| A2 | R2: правка в четырёх файлах | `git diff --stat examples/` — ровно 4 файла `.takt` |
| A3 | R3: причина соответствует факту | чтение диффа против таблицы ADR; для трёх примеров причина подтверждена исполнением тестбенчей SV в `precheck.sh` |
| A4 | R4: порты на месте | `grep -c 'out ready' examples/{regulator,float_regulator,pid_regulator,batch_cycle}.takt` — по 1 |
| A5 | R5: вывод целей не изменился | `git status --porcelain examples/generated/` после `precheck.sh` — пусто |
| A6 | R6 + общая исправность | `./scripts/precheck.sh` — код 0 |

## Особенности по обратной функциональности (правило 11)

Обратная совместимость **не затрагивается**: правятся комментарии в примерах.
Программы на Takt, порождённый код, форматы файлов и CLI неизменны. Версия языка
не поднимается (правило 22): язык не меняется — ни синтаксис, ни семантика, ни
наблюдаемое поведение, ни диагностики.

## Редакторский слой (правило 29)

**Не требуется.** Лексика, синтаксис и семантика не меняются, новых токенов,
узлов АСД, форм объявления и диагностик не появляется — LSP (`takt-lang/src/lsp/`)
и плагины (`extensions/`) правок не требуют. Ответ зафиксирован здесь и
повторён в отчёте (стадия 6).

## Документирование (правило 24)

**Не требуется.** Документ `book/` описывает язык; комментарии примеров корпуса
в него не входят. Проверено: разделы `book/` устаревшую формулировку не
воспроизводят (`grep -rn 'new_without_default' book/` — пусто).

## Риски и зависимости

- **Риск: комментарий снова устареет.** Формулировка `float_regulator.takt`
  прямо говорит, что гейт порт не держит; войди пример в `SV_TRANSLATABLE` или
  `FLOAT_AS_Q_EXAMPLES` — запись придётся обновить. Снижение: у трёх остальных
  причина проверяется **исполнением** тестбенча (`$error`, если `ready` не
  поднялся), то есть молча устареть не может. Машинного сторожа на текст
  комментария не заводится (ADR, Option C отвергнут).
- **Риск: сдвиг комментариев ломает канон `fmt`.** Привязка комментария к узлу
  — известное тонкое место (фиксы 0197-01, 0198-01). Снижение: правка идёт в
  шапке файла и в комментариях уровня модели; проверка — `fmt --check` в
  предкоммите (A6).
- **Зависимостей от незакрытых фич нет.**
