# Анализ фичи 0265: SVG диаграмм и версия graphviz

> Фича: [../features/0265-book-svg-graphviz-version.md](../features/0265-book-svg-graphviz-version.md) · ADR: [../adr/0265-book-svg-graphviz-version.md](../adr/0265-book-svg-graphviz-version.md) · тест-план: [../tests/0265-book-svg-graphviz-version.md](../tests/0265-book-svg-graphviz-version.md)

## Цель и контекст

Сделать так, чтобы прогон предкоммита не пачкал дерево. ADR принял Option B:
вычищать версию при генерации.

## Замер (снят 2026-08-20, правило 30)

Кандидат подтверждён: `dot` вписывает в SVG строку
`<!-- Generated by graphviz version 15.1.0 (20260618.0150) -->`, и при смене
версии она даёт дифф в трёх файлах.

**Находка сверх кандидата — молчаливая поломка регенерации.** Скрипт искал
`taktc` в `$ROOT/target/debug`, а сборка идёт в `target/precheck` (фича 0251):

```
book/scripts/render_verify_graphs.sh: line 33: …/target/debug/taktc: No such file or directory
  ⚠ регенерация не удалась — использую закоммиченные SVG.
```

**Код возврата при этом нулевой.** След поломки лежал в репозитории: файл
`book/src/18-showcase/images/lift-kripke.dot` был **пуст** — перенаправление
создало его до неудачного вызова, и пустышка попала в коммит.

Это ровно класс фичи 0301 («каталог бинарников — один носитель»), и запись о
нём висела кандидатом блока 2 `FEATURES.md`; она снимается закрытием 0265
(правило 28).

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет (0301 и 0251 закрыты; здесь используется их носитель).
- **Влияние на порядок:** снимает кандидата про третью копию знания о каталоге.

## Требования и проверяемые условия

- **R1.** Порождённые SVG не содержат `graphviz version`.
- **R2.** Повторная регенерация дерева не меняет.
- **R3.** Скрипт берёт каталог бинарников у `scripts/target-dir.sh`.
- **R4.** Предкоммит ловит committed SVG со строкой версии.
- **R5.** Предкоммит ловит **пустой** `.dot` — след молча не сработавшей
  регенерации.
- **R6.** Комментарий предкоммита о выборе цели `pdf` приведён к правде.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Версии в SVG нет | `grep 'graphviz version' book/src/*/images/*.svg` |
| A2 | Повторный прогон стабилен | два прогона скрипта + `git status` |
| A3 | Каталог у носителя | `grep 'target/debug' book/scripts/render_verify_graphs.sh` (только комментарий) |
| A4/A5 | Гейт ловит оба класса | проба порчей файла |
| A6 | Комментарий верен | чтение (правило 4) |
| A7 | Предкоммит | `./scripts/precheck.sh` |

## Особенности по обратной функциональности (правило 11)

**Не нарушается.** Меняются порождаемые SVG (одна строка комментария) и
скрипт; язык, инструменты и порождаемый компилятором код не затронуты.

## Редакторский слой (правило 29)

**Не требуется.**

## Документирование (правило 24)

**Не требуется.** Содержание диаграмм не меняется — только служебный
комментарий SVG.

## Риски и зависимости

- **Риск: смена `dot` изменит геометрию, а не только версию.** **Снижение:**
  тогда дифф будет содержательным, и его увидит человек; гейт ловит именно
  **служебную** строку, которая содержания не несёт.
- **Риск: регенерация снова сломается молча.** **Снижение:** пустой `.dot`
  теперь роняет предкоммит — то есть след поломки стал сигналом.
