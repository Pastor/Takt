# Анализ фичи 0217: Ветвь-заглушка до будущей задачи переживает саму задачу

> Фича: [../features/0217-stub-branch-gate.md](../features/0217-stub-branch-gate.md) · ADR: [../adr/0217-stub-branch-gate.md](../adr/0217-stub-branch-gate.md) · тест-план: [../tests/0217-stub-branch-gate.md](../tests/0217-stub-branch-gate.md)

## Цель и контекст

Сделать просроченную ветвь-заглушку видимой для машины. Решение ADR (Option B):
реестр `scripts/stub-branches.txt` с держателем у каждой заглушки плюс гейт
`scripts/check-stub-branches.py` с тремя условиями отказа — по образцу храповика
размеров модулей (0027).

Правка касается скриптов и документов процесса; код компилятора и симулятора не
меняется. Две найденные живые заглушки получают **фичи-держатели** (0247, 0248)
— их починка в объём не входит.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Прецеденты (0027 — реестр-храповик, 0149 — сверка со
  статусом фичи, 0218 — нормализация статуса) закрыты.
- **Влияние на порядок разработки:** заводит две фичи класса «расхождение
  эталона с целями» (0247, 0248) — они попадают в таблицу Tier 2, то есть выше
  прочих незакрытых. Само 0217 никого не блокирует.

## Требования и проверяемые условия

- **R1. Три условия отказа.** Гейт краснеет, если: (а) заглушка в коде не
  объявлена в реестре; (б) держатель записи в статусе `ГОТОВО`/`ОТМЕНА`;
  (в) записи не соответствует ничего в коде.
- **R2. Ключ записи — код + файл**, а не номер строки: строка уедет при первой
  правке (правило живого контекста, гейт 0149 запрещает ссылки `файл.rs:NNN`).
- **R3. Постоянный отказ отличим от временного.** Держатель `ПОСТОЯННЫЙ`
  законен, статус фичи для него не спрашивается.
- **R4. Нормализация статуса держателя** — те же пять форм записи, что и в 0218.
- **R5. Комментарий не считается заглушкой.** Док-строка, рассказывающая о
  механизме отказа (`format/mod.rs`), не место отказа: иначе гейт потребовал бы
  регистрировать прозу.
- **R6. Правило записано.** `docs/CODE.md` называет формулировку заглушки и
  обязанность регистрации; иначе гейт ловит форму, о которой автор не знал.
- **R7. Найденное получило адрес.** Живые заглушки `SIM-013` и `SIM-020`
  заведены фичами 0247 и 0248 с пробами в карточках.
- **R8. Цена мала**, гейт стоит в предкоммите с самотестом.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | R1 (а) | мутация: удалить запись `SIM-020` → отказ с именем файла |
| A2 | R1 (б) | мутация: держатель `SIM-013` → `0025` (ГОТОВО) → отказ «пережила свою задачу» |
| A3 | R1 (в) | мутация: добавить запись на несуществующее место → отказ «реестр окаменеет» |
| A4 | R3, R4 | `--self-test`: `ПОСТОЯННЫЙ` не даёт находок; держатель-несуществующий и неразобранная строка дают |
| A5 | R5 | прогон на дереве: `format/mod.rs` объявлен один раз (по коду `FM-001`), док-строка находок не даёт |
| A6 | R6 | раздел «Ветви-заглушки» в `docs/CODE.md` |
| A7 | R7 | карточки 0247/0248 в `docs/features/` и строки в `FEATURES.md` |
| A8 | R8 | `./scripts/precheck.sh` — код 0 |

## Особенности по обратной функциональности (правило 11)

Не затрагивается: добавлены скрипт, реестр и правила; код компилятора и
симулятора не изменён, версия языка не поднимается. Поведение инструментов
прежнее — включая **сами заглушки**: `SIM-013` и `SIM-020` продолжают
отвечать отказом, пока их не снимут фичи 0247/0248.

## Редакторский слой (правило 29)

**Не требуется:** лексика, синтаксис и семантика не менялись.

## Документирование (правило 24)

**Не требуется** для `book/`: язык не меняется. Правило разработки записано в
`docs/CODE.md` (правило 23) — там же, где прочие правила Rust-кода.

## Риски и зависимости

- **Риск: обнаружение по формулировке.** Заглушка, написанная иначе, гейту не
  видна. Снижение — правило в `docs/CODE.md`; ограничение названо и в гейте, и
  в реестре, чтобы не создавать ложного чувства полноты (тот же приём, что у
  греп-сторожей 0168 и 0213).
- **Риск: реестр окаменеет.** Снимается условием (в): запись без места в коде
  роняет гейт.
- **Риск: держателем назначат «удобную» открытую фичу.** Гейт этого не
  распознает — он судит форму (правило 4). Смягчение: держатель виден в реестре
  рядом с пояснением, и при закрытии фичи гейт всё равно потребует решения.
