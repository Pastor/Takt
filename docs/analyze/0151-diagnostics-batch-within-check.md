# Анализ фичи 0151: Накопление диагностик внутри отдельной проверки `validate`

> Фича: [../features/0151-diagnostics-batch-within-check.md](../features/0151-diagnostics-batch-within-check.md) · ADR: [../adr/0151-diagnostics-batch-within-check.md](../adr/0151-diagnostics-batch-within-check.md) · тест-план: [../tests/0151-diagnostics-batch-within-check.md](../tests/0151-diagnostics-batch-within-check.md)

## Цель и контекст

Довести до конца то, что 0130 сделала наполовину: диагностики накапливаются
**между** проверками, но внутри каждой оставался ранний возврат. Разбор и выбор
правила — в [ADR 0151](../adr/0151-diagnostics-batch-within-check.md).

**Язык фича не меняет.** Ни синтаксиса, ни семантики, ни кодов, ни условий
срабатывания: меняется **сколько** сообщений пользователь видит за прогон.
Версия языка остаётся `0.8.0`.

## Замер (2026-08-05)

**Ответ на вопрос кандидата** («дыра обхода или ранний выход?»): ранний выход.
Два неразрешённых условия теряются одинаково и в разных состояниях, и в одном —
значит обход доходит, а проверка возвращается после первой находки.

| Вход | До | После |
|---|---|---|
| два `ref` с неразрешённым условием | 1 | **2** |
| два `cond` с неразрешённым условием | 1 | **2** |
| две переменные `bit` с недопустимым значением | 1 | **2** |
| два массива недопустимого размера | 1 | **2** |
| два `address` на несуществующие порты | 1 | **2** |
| два обращения к ячейке в инициализаторах | 1 | **2** |
| две ссылки на несуществующее состояние (`SE-002`) | 1 | 1 — **граница 0152** |
| два неизвестных имени (`SE-003`) | 1 | 1 — **граница 0152** |

⚠️ Последние два приходят **не из `validate`**, а со стадий построения дерева;
их терминальность — решение фичи 0152, а не упущение этой.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет незакрытых. Продолжает
  [0130](../features/0130-diagnostics-batch.md); границу разделяет с
  [0152](../features/0152-semantic-recovery-element-boundary.md).
- **Влияние на порядок разработки:** закрывает кандидата блока 2 («два
  неразрешённых условия дают одну диагностику»), который оказался этой же
  фичей.

## Требования и проверяемые условия

- **R1. Одна диагностика на элемент; высказываются все элементы.** Элемент —
  объявление, ребро перехода, именованное условие, оператор `address`.
- **R2. Внутри одного выражения — первая ошибка.** Дальше по нему идут
  следствия.
- **R3. Свойство 0130 не потеряно:** разные проверки складываются.
- **R4. Стадии построения остаются терминальными** (решение 0152).
- **R5. Порядок вывода — по позиции**, а не по обходу `BTreeMap`.
- **R6. Интерфейс проверок однороден:** все отдают `Vec<Diagnostic>`.

## Критерии приёмки и способ проверки

Нумерация совпадает с критериями приёмки ADR 0151.

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | два нарушения — два сообщения (шесть классов) | `validate_batch_tests`, по тесту на класс |
| A2 | разные проверки складываются | `…::different_checks_still_accumulate` |
| A3 | стадии построения терминальны | `…::build_stage_errors_stay_terminal` |
| A4 | порядок по позиции | `…::diagnostics_are_ordered_by_position` |
| A5 | одна диагностика на элемент | `…::one_diagnostic_per_element` |
| A6 | `./scripts/precheck.sh` — код 0 | прогон |

## Особенности по обратной функциональности

| Функциональность | Задета | Что проверяется |
|---|---|---|
| `taktc compile` | да | больше сообщений за прогон; коды и тексты прежние |
| LSP | да (тем же кодом) | редактор подчёркивает все нарушения — общий вход `validate_model_all` |
| Стадии построения дерева | нет | терминальность сохранена |
| Цели генерации, симулятор | нет | при ошибке порождения не происходит, как и прежде |
| Корпус | нет | он валиден: ошибок нет вовсе |

## Риски и зависимости

- **Шум.** Больше сообщений — но каждое о **своём** элементе; следствия внутри
  выражения по-прежнему не печатаются.
- **Порядок.** Накопление могло бы сделать наблюдаемым обход `BTreeMap`; снято
  нормализацией (0130) и тестом порядка.
- **Тесты на `Result`.** Сигнатуры сменились — тесты, стоявшие на `is_ok`/
  `unwrap_err`, обновлены; это цена однородности интерфейса.
