# Анализ фичи 0193: Цели `rust` и `sv` — одноимённые константы разных моделей

> Фича: [../features/0193-shared-const-qualified.md](../features/0193-shared-const-qualified.md) · ADR: [../adr/0193-shared-const-qualified.md](../adr/0193-shared-const-qualified.md) · тест-план: [../tests/README.md](../tests/README.md)

## Цель и контекст

ADR принял **Option A** (рекомендация архитектора и решение заказчика совпали):
константа печатается **именем, квалифицированным владельцем**, — как это уже
делает цель `c`. Исключение «квалифицируется только константа-параметр»,
заведённое задачей [0185-06](../development/0185-06-model-parameters.md) под
требование «вывод корпуса байт-в-байт», снимается: оно было временным.

## Зависимости фичи (правило 17/19)

**Нет.** Механизм квалификации уже в дереве (`const_ident`/`const_signal`),
прецедент ключа — `address_map::resolve::qualified_port_key` (фича 0084).

## Места правки

| # | Что | Файл | Замечание |
|---|---|---|---|
| М1 | имя константы в цели `rust` | `generator/rust/rust_expr.rs::const_ident` | снять условие `is_parameter`: квалифицировать **всегда**. Форма прежняя — `TUNER_P1_GAIN` (`unique_uppercase_snakecase` + `_` + `const_name`) |
| М2 | имя константы в цели `sv` | `generator/sv/sv_expr.rs::const_signal` | то же; форма прежняя — `svspec_tuner_p1_gain` (`unique_lowercase_snakecase` + `_` + имя как написано) |
| М3 | ключ «константа используется» | `semantic/unused.rs` (`UsageSet.constants`, **4** точки вставки) | ключ становится парой `(владелец, имя)`; строится **одной** функцией — прецедент `qualified_port_key` |
| М4 | потребители фильтра | `rust_decl.rs:341`, `sv_const.rs:189`, `c_decl.rs:75` | ⚠️ всего три, и ключ обязан строиться **из `upper` узла**, а не из «модели, которую печатаем» |
| М5 | снапшоты корпуса | `examples/generated/rust/{comprehensive,extend_complex,stacker}.rs`, `examples/generated/sv/stacker.sv` | 15 `const` + 9 `localparam`; дифф читается глазами |

⚠️ **Правка М1/М2 — снятие условия, а не новая ветвь.** Обе функции уже умеют
печатать квалифицированное имя; заводить второе правило нельзя — именно
раздвоение правила и было дефектом.

## Ограничения, которые определяют форму решения

- **О1. Продюсер и потребитель ключа обязаны строить одну строку.** Урок 0084
  (`qualified_port_key`): разъехавшись на символ, они дают либо потерянное
  объявление, либо ссылку в пустоту. Поэтому ключ — **одна** функция, а её
  аргумент — `upper` узла константы, тот же источник, из которого строится
  печатаемое имя.
- **О2. Фильтр использования — над-аппроксимация, и после квалификации она
  становится ошибкой.** Замер 2026-08-03: неиспользуемая `const` в Rust под
  `-D warnings` — **ошибка** (`dead-code`), а не предупреждение. Сегодня `A::K`
  и `B::K` делят запись `"K"`, и если используется хотя бы одна — фильтр
  пропускает обе; после квалификации напечатаются обе, и неиспользуемая уронит
  гейт.
- **О3. Форма имени не изобретается.** У цели `rust` — `unique_uppercase_snakecase`,
  у `sv` — `unique_lowercase_snakecase`; обе уже действуют для констант-параметров
  и пришпилены тестами (`model_parameter_specialize_tests.rs`,
  `model_parameter_const_tests.rs`). Вторая форма развела бы вывод одной цели сам
  с собой.
- **О4. В корпусе одноимённых констант нет** (замер: `comprehensive` 5,
  `extend_complex` 2, `stacker` 12, дублей ноль). Следствие: уточнение фильтра
  М3 **ничего не удалит** из вывода — дифф корпуса состоит только из
  переименований. Это делает критерий приёмки A5 проверяемым.
- **О5. Цель `st` не задета** — константы там поля `FUNCTION_BLOCK`, коллизии нет
  по устройству, фильтра констант у неё нет вовсе (потребителей ровно три).

## Требования и проверяемые условия

| # | Требование | Проверяемое условие |
|---|---|---|
| R1 | Одноимённые константы разных моделей не сливаются | проба ADR: цели `rust`/`sv` дают `x=2`, `y=3` |
| R2 | Печать и дедупликация — одно правило | объявление печатается тем же именем, которым к нему обращаются выражения (обе цели) |
| R3 | Неиспользуемая константа-тёзка не печатается | вход «`A::K` используется, `B::K` — нет» проходит гейт `rust` под `-D warnings` |
| R4 | Форма имени прежняя | тесты 0185-06 зелёные **без правок** |
| R5 | Цели `c`/`st` и предупреждения не задеты | вывод корпуса для них байт-в-байт прежний; текст «переменная не используется» прежний |
| R6 | Дифф корпуса — только переименования | `examples/generated/`: 4 файла, изменения только в именах констант и их вхождениях |
| R7 | Поведение сверено значенчески, а не «собралось» | потактовая сверка sim ≡ `rust` и sim ≡ `sv` на одноимённых константах |

## Критерии приёмки и способ проверки

| # | Критерий (из ADR) | Способ проверки |
|---|---|---|
| A1 | проба даёт `x=2`, `y=3` в `rust`/`sv` | сверка значений (новый тест) |
| A2 | одно правило имени на цель | чтение + тест печати |
| A3 | тёзка-неиспользуемая не печатается | новый тест + гейт `rust` |
| A4 | сверка роняется мутацией | вернуть голое имя → сверка краснеет |
| A5 | дифф корпуса — только переименования | `git diff examples/generated/` глазами + `precheck.sh` |

⚠️ **A4 обязателен.** Гейты целей дефект не ловят и поймать не могут: `clippy`,
`verilator` и `yosys` нынешний вывод принимают — он валиден, просто считает не
то. Зелёный тест ничего не стоит, пока не доказано, что он краснеет (урок 0191).

## Особенности по обратной совместимости (правило 11)

- **Язык не меняется**, публичный API крейта не меняется.
- **Вывод целей `rust`/`sv` меняется** — это и есть предмет фичи. Потребитель,
  который зовёт порождённую константу по имени из своей обвязки (например,
  `CHARGE_STACK` из Rust-кода), обязан обновить имя. В дереве проекта такой
  потребитель один — снапшоты корпуса; внешних гарантий на имена констант проект
  не давал.
- **Цели `c`/`st` не задеты**: у `c` квалификация уже была, у `st` вопроса нет.

## Документирование (правило 24)

**Не требуется.** Язык не меняется: одноимённые константы разных моделей законны
и были законны; меняется трансляция. (При отвергнутых Option C/D документирование
потребовалось бы — появилось бы новое ограничение языка.)

## Редакторский слой (правило 29)

**Правок не требуется.** Проверено чтением кода **на этой стадии** — урок 0192,
где пункт был пропущен и восполнялся при закрытии:

| Что проверялось | Вывод |
|---|---|
| лексика, синтаксис, семантика языка | **не меняются** — фича живёт в генераторах `rust`/`sv` и во внутреннем ключе `semantic/unused.rs`, наружу не выходящем |
| новое ключевое слово / токен / узел АСД | **нет** — `lsp/semantic_tokens.rs`, `lsp/keywords.rs::BUT_KEYWORDS`, `TaktTokenTypes.KEYWORDS`, `format/`, `semantic/usages/walk.rs` не задеты |
| переход к объявлению, ссылки, переименование | **не задеты**: слой вхождений (0131) адресует символы позициями в исходнике и об именах цели не знает вовсе |
| hover, структура документа | **не задеты**: печатают тип и объявление, а не имя в порождённом коде |
| новая диагностика | **нет** — Option A отказов не заводит (их заводили бы отвергнутые C/D) |

⚠️ `semantic/unused.rs` даёт предупреждение «переменная не используется», и оно
до редактора доезжает. Уточнение касается поля `constants` (его потребители —
только генераторы), а не текста предупреждения; что предупреждения не
изменились — условие R5.

## Риски

- **Риск «дифф корпуса больше, чем переименования».** Снижение: О4 (дублей в
  корпусе нет) + A5 (дифф читается глазами, а не только гейтом детерминизма
  0048).
- **Риск разъезда ключа** (О1). Снижение: одна функция построения, вызванная из
  четырёх точек вставки и трёх потребителей; аргумент — всегда `upper` узла.
- **Риск молчаливой неверности сторожа.** Снижение: A4 — мутация обязана уронить
  сверку. Без этого зелёный тест не доказывает ничего: инструменты целей нынешний
  дефектный вывод принимают.
