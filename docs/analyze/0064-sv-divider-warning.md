# Анализ фичи 0064: Предупреждение о делителе (`SV-009`) в цели `sv`

> Фича: [../features/0064-sv-divider-warning.md](../features/0064-sv-divider-warning.md) · ADR: [../adr/0064-sv-divider-warning.md](../adr/0064-sv-divider-warning.md) · тест-план: [../tests/0064-sv-divider-warning.md](../tests/0064-sv-divider-warning.md)

## Цель и контекст

Задача [0045-06](../development/0045-06-expressions-functions.md) зарезервировала
код `SV-009`, но диагностику **не завела**, оставив вопрос дословно: «полезная
подсказка или шум? **Решить пробой `yosys stat` на модели с делением**».

Проба сделана. ADR 0064 принял **Option B**: предупреждать **только на переменный
делитель**.

## Замер (пробы 2026-07-17) — он дважды перевернул вывод

**Шаг 1. Обобщённый синтез** (`yosys synth -flatten`), ячеек:

| Ширина | `a + b` | `a * b` | `a / b` | `a % b` |
|---|---|---|---|---|
| `u8` | 60 | 166 | 228 | 252 |
| `u16` | 118 | 733 | 870 | 914 |
| `u32` | 240 | 3030 | 3437 | 3525 |

→ Предварительный вывод: `*` почти так же дорог, как `/` (u32 — разрыв ×1.13),
значит предупреждать только про `/` — вводить в заблуждение. **Вывод оказался
неверным.**

**Шаг 2. FPGA-поток** (`yosys synth_ice40 -dsp -flatten`, `u32`):

| Операция | `SB_LUT4` | `SB_MAC16` (DSP) |
|---|---|---|
| `a + b` | 49 | 0 |
| `a * b` | **17** | **3** |
| **`a / b`** | **558** | **0** |
| **`a % b`** | **591** | **0** |
| `a / 2` (константа) | **17** | 0 |
| `a / 3` (константа) | **106** | 0 |

⚠️ **Шаг 1 моделировал не ту технологию.** Обобщённое отображение на вентили
**не знает про DSP-блоки**. На FPGA у умножения аппаратная поддержка **есть**
(3 DSP + 17 LUT — **дешевле сложения**), у деления — **нет** (558 LUT, ноль DSP;
×11 от сложения).

**Шаг 3.** Делитель-константа дёшев: `/ 2` → сдвиг (17 LUT), `/ 3` → умножение на
обратное (106 LUT) — порядка сложения.

**Ответ на вопрос 0045-06:** подсказка — **но только для переменного делителя**.
В форме «предупреждать на всякое `/`» это был бы **шум**: сработало бы на `a / 2`,
который дешевле сложения.

## Находка проработки: у цели `sv` канала предупреждений НЕТ

Греп по `generator/sv/`: ни `Diagnostic::warning`, ни `report` — **ноль**
вхождений. У соседей есть: `rust/mod.rs:199`, `st/mod.rs:290`.

⚠️ **Следствие для объёма:** `SV-009` без канала будет **немой**. Заведение
`report` в `generator/sv/mod.rs` **входит в объём** 0064 — иначе фича не достигает
цели.

## Находка проработки: сам канал дефектен (вне объёма)

`report` печатает **`eprintln!` прямо из библиотеки** (`rust/mod.rs:202`,
`st/mod.rs:293`), а не возвращает диагностики вызывающему: `compile_to_sv` и
`compile_to_rust` объявлены `Result<(), Diagnostic>` и предупреждений **не
отдают**. Следствия: `--quiet` их **не глушит** (греп по `generator/`: слова
`quiet` нет); LSP получит их в свой stderr; тест не может проверить факт
предупреждения иначе как перехватом stderr. Заведено кандидатом; 0064
воспроизводит сложившийся образец, чтобы не превращаться в рефакторинг доставки.

## Зависимости фичи (правило 17/19)

- **Зависит от:** **нет**. Опора — **закрытая** [0045](../features/0045-sv-backend.md).
- **Пересечения:** [0061](../features/0061-fixed-point-type.md) строит `/` над
  `q(m,n)` на целочисленном делении → когда она будет реализована, `SV-009`
  обязана срабатывать и там (делитель тот же). Не зависимость: порядок любой, но
  0061 обязана про `SV-009` знать.
  [0063](../features/0063-sv-clock-enable.md) и
  [0057](../features/0057-sv-sequential-composition.md) правят `sv_fsm.rs`; 0064 —
  `sv_expr.rs` + `sv/mod.rs`. Конфликтов нет.
- **Смежно:** [0081](../features/0081-lamc-print-warnings.md) (`lamc` не печатает
  Ce13/Ce14). ⚠️ **Не зависимость:** проверено — предупреждения **генераторов**
  доставляются иначе (своим `eprintln!` внутри цели), то есть 0081 про другой
  канал. Ловушка, в которую легко попасть, читая только карточку 0081.
- **Влияние на порядок:** никого не блокирует.

## Приоритет (Tier) — обоснование

**Tier 3.**

- Трансляция **верна**: деление синтезируется корректно, дефекта нет.
- Корпус деления **не содержит** → предупреждение сегодня не сработало бы ни разу.
- Ценность — предупредить об **эксплуатационной** цене (потолок частоты), которую
  автор `.lam` увидеть не может.
- Против Tier 2: ничего не сломано, никто не заблокирован.

## Требования и проверяемые условия

- **R1. `SV-009` — предупреждение, а не ошибка** (деление работает).
- **R2. Срабатывает только на переменный делитель** `/` и `%`.
- **R3. Делитель-константа — молча** (замер 3).
- **R4. Про `*` не предупреждать** (замер 2: DSP).
- **R5. Текст называет причину и следствие** (нет аппаратного делителя → потолок
  частоты), **без конкретных LUT** — они технологичны и устареют.
- **R6. Канал доставки заведён** у цели `sv` (`report`) — иначе диагностика немая.
- **R7. Корпус не задет**; язык не меняется → версия не растёт.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | `a / b` (переменный) → `SV-009`; трансляция **успешна** | Фикстура + перехват stderr |
| A2 | `a / 2`, `a / 3` → предупреждения **нет** | Фикстуры |
| A3 | `a % b` → `SV-009`; `a % 4` → молча | Фикстуры |
| A4 | `a * b` → предупреждения **нет** | Фикстура |
| A5 | Текст называет причину и следствие, без LUT | Ревью |
| A6 | Корпус: предупреждений ноль; вывод целей побайтово прежний | `git diff --exit-code examples/generated` |
| A7 | Предупреждение **доходит** до пользователя | Прогон `lamc -t sv` (канал заведён — R6) |

## Особенности по обратной функциональности

**Правка аддитивна** (правило 11): добавляется **предупреждение**, трансляция не
меняется. Корпус деления не содержит → вывод всех целей побайтово прежний (A6).
Язык не меняется → версия не растёт (правило 22).

Единственная структурная правка — **новый канал** `report` у цели `sv` (R6),
аддитивный по образцу `rust`/`st`.

## Риски и зависимости

- **R-1. Померить не ту технологию** (уже случилось внутри этой проработки).
  Обобщённый `synth` завысил цену `*` вчетверо и едва не привёл к решению
  «предупреждать и про умножение», которое было бы прямым шумом. Снижение:
  замеры на **FPGA-потоке**; записать ловушку в `CLAUDE.md` (A-4 ADR).
- **R-2. Числа в тексте предупреждения устареют.** LUT технологичны (`synth_ice40`
  ≠ `synth_xilinx`). Снижение: R5 — называть **порядок** и **следствие**.
- **R-3. Немая диагностика.** У `sv` канала нет вовсе. Снижение: R6 в объёме;
  A7 проверяет доставку, а не только факт.
- **R-4. Шум обесценивает сторожа.** Сработав на `/ 2`, `SV-009` будет заглушена
  вместе с полезным случаем. Снижение: R2/R3 + A2 как сторож.
- **R-5. Константа по потоку данных.** `b := 3; r := a / b;` даст предупреждение,
  хотя синтезатор свернёт. Консервативно и осознанно (A-2 ADR).
