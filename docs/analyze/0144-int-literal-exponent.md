# Анализ фичи 0144: Экспонента числового литерала

> Фича: [../features/0144-int-literal-exponent.md](../features/0144-int-literal-exponent.md) · ADR: [../adr/0144-int-literal-exponent.md](../adr/0144-int-literal-exponent.md) · тест-план: [../tests/README.md](../tests/README.md)

## Цель и контекст

Лексер принимает экспоненту и молча её отбрасывает — у **обоих** видов литерала.
Решение — Option A [ADR 0144](../adr/0144-int-literal-exponent.md): экспонента
вычисляется; знак показателя выбирает вид литерала; переполнение даёт `LE-009`.

## Зависимости фичи (правило 17/19)

- **Зависит от:** `нет`. Слой представления литерала закрыт фичей
  [0128](../features/0128-lexer-literal-overflow.md) (`LE-009`), и эта фича им
  пользуется, а не ждёт его.
- **Влияние на порядок разработки:** смежна с
  [0157](../features/0157-literal-u64-representation.md) («полная маска
  `[bit;64]` незаписуема») — обе упираются в `Token::Number(i64)`. ⚠️ Но
  **зависимости нет**: 0144 при переполнении отдаёт тот же `LE-009`, который уже
  есть; расширение представления (0157) её не требуется. Если 0157 когда-нибудь
  расширит тип, правило 3 ADR 0144 продолжит работать без правки.

## Что именно неверно (замер 2026-07-29)

| Вход | Сейчас | Станет | Где ломается |
|---|---|---|---|
| `1e3` | `Number(1)` | `Number(1000)` | значение по `old_end` — до экспоненты |
| `1E3` | `Number(1)` | `Number(1000)` | то же |
| `1e-3` | `Number(1)` | `RationalNumber("1e-3")` = 0.001 | то же |
| `2.5e3` | `RationalNumber("2.5")` | `RationalNumber("2.5e3")` = 2500.0 | срез обрывается на `rational_end` |

Обе ветви `parser/lexer.rs::parse_number` вычисляют границы показателя и
присваивают их `let _exp` — то есть выбрасывают сознательно.

## Требования и проверяемые условия

- **R1. Экспонента вычисляется** у целого литерала; регистр `e`/`E` незначим.
- **R2. Знак показателя выбирает вид:** без минуса — целый, с минусом —
  рациональный.
- **R3. Экспонента сохраняется в тексте рационального литерала** (авторская
  форма, как `2.5` и `1m30s`).
- **R4. Переполнение даёт `LE-009`**, вычисление — проверяемой арифметикой.
- **R5. `float → q` понимает экспоненту** (`semantic/type_node.rs`).
- **R6. Вывод генераторов на корпусе байт-в-байт неизменен** (корпус литералов с
  экспонентой не содержит — проверено грепом).
- **R7. Версия языка поднята**, README согласован (правило 22).
- **R8. Ответ по правилу 29 зафиксирован:** правки LSP и плагинов не требуются.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | `1e3` = `1E3` = 1000 | тест лексера на **значении** токена |
| A2 | `2.5e3` = 2500.0 | тест значения через симулятор |
| A3 | `1e-3` = 0.001 и **рационален** | тест вида и значения токена |
| A4 | Сквозная: в порождённом C для `1e3` стоит `1000` | компиляция + греп |
| A5 | `1e19` даёт `LE-009` | тест лексера на код ошибки |
| A6 | `--float-as-q` на `2.5e3` даёт верный repr | тест понижения |
| A7 | Вывод генераторов неизменен | дифф `examples/generated/` |
| A8 | Версия языка и README согласованы | `check-language-version.sh` |
| A9 | Форматтер не отказывает на новых формах | `taktc fmt --check examples/` + прогон на пробном файле |

⚠️ **A1–A3 проверяются значением, а не формой токена.** Дефект прожил именно
потому, что форма была верна: диапазон токена `1e3` покрывал `0..3`, ошибок не
было — неверным было только число. Тест на «токен разобран» здесь ничего не
доказывает.

## Особенности по обратной функциональности

- **Меняется семантика лексики** — это подъём версии языка (правило 22).
- **Существующие исходники:** корпус (`examples/`, `book/`, фикстуры) литералов
  с экспонентой **не содержит** (греп), поэтому наблюдаемых изменений в выводе
  быть не должно. Чужой код вне репозитория, полагавшийся на `1e3 == 1`,
  изменит поведение — это и есть исправление дефекта.
- **Форматтер:** целый литерал канонизируется (`1e3` → `1000`) — согласуется с
  действующим поведением (`0xFF` → `255`); рациональный сохраняет форму.

## Риски и зависимости

- **Риск 1: тихая обёртка при вычислении.** `1e19` в `i64` не влезает.
  Снимается проверяемой арифметикой (`checked_mul`) и тестом A5.
- **Риск 2: q-путь ломается на тексте с экспонентой** (снято пробой при
  проработке): `type_node.rs` парсит текст вручную через `split_once('.')`.
  Требует правки — R5, тест A6.
- **Риск 3: печать в цели.** C, Rust, SV принимают `2.5e3`; ST проверен пробой
  `iec2c` (строчная `e` — `rc=0`). Отдельной правки печатников не требуется.
- **Риск 4: `1e3ms`.** Форма «экспонента + единица времени» сегодня отвергается
  (`reject_time_suffix`). Поведение сохраняется — длительность выражается
  литералом без экспоненты.
