# Анализ фичи 0094: Доработка scripts/new-feature.sh (идемпотентность, статус ADR, поздние стадии)

> Фича: [../features/0094-new-feature-script-fixes.md](../features/0094-new-feature-script-fixes.md) · ADR: [../adr/0094-new-feature-script-fixes.md](../adr/0094-new-feature-script-fixes.md) · тест-план: [../tests/0094-new-feature-script-fixes.md](../tests/0094-new-feature-script-fixes.md)

## Цель и контекст

Устранить три дефекта генератора заготовок `scripts/new-feature.sh` (фича 0015):
преждевременный `Accepted` у ADR, **недублирование** при повторном `--register`
(конкретная боль — ×3 за сессию), добор одной поздней стадии (включая `report`).
Решение — Option A ADR: идемпотентный `insert_row` по ключу-номеру, `Draft`,
`--stage`/`--subtask`, `NF_ROOT` + машинный гейт. Пересборка реестра из файлов
(3b) отложена (ненадёжна в POSIX sh).

## Зависимости фичи (правило 17/19)

- **Зависит от:** **нет.** Инфраструктура (`scripts/`, `docs/templates/`), крейты
  `grammar`/`simulation` и язык не затрагиваются.
- **Влияние на порядок разработки:** не блокирует других фич, но снимает трение
  генератора для **всех** будущих (правило 19, критерий 3 — процессная фича по
  влиянию на цикл).

## Требования и проверяемые условия

- **R1. Идемпотентный `--register`.** `insert_row` пропускает вставку, если строка
  с ключом-номером уже есть в реестре (ключ — литерал первого столбца:
  `| [NNNN]` / `| NNNN |` / `| NNNN-YY |`). Повторный прогон → одна строка.
- **R2. Честный статус ADR.** ADR-строка реестра и шаблон `adr.md` — `Draft`
  (не `Accepted`); `Accepted` проставляет автор на стадии 2.
- **R3. Добор одной стадии.** `--stage NAME` (`feature|adr|analyze|dev|tests|
  report`) рендерит и идемпотентно регистрирует **только** её. `report` поддержан
  впервые. `--subtask NN` задаёт номер dev-подзадачи (`XXXX-NN`).
- **R4. Обратная совместимость.** Дефолтный вызов
  `[--with-dev] [--register] XXXX slug "Заголовок"` по поведению неизменен, кроме
  R1 (недублирование) и R2 (`Draft`). POSIX sh без внешних зависимостей.
- **R5. Проверяемость.** `scripts/test-new-feature.sh` в `precheck.sh` гоняет
  генератор в temp-дереве (`NF_ROOT`) и проверяет R1/R2/R3.

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Двойной `--register` → одна строка в каждом реестре | тест: 2 прогона, `grep -c` == 1 |
| A2 | ADR-строка и шаблон — `Draft` | тест: `grep Draft`, `! grep Accepted` в свежей заготовке/строке |
| A3 | `--stage report` создаёт+регистрирует отчёт | тест: файл есть, строка reports/README одна |
| A4 | `--subtask NN` добирает `XXXX-NN` идемпотентно | тест: dev-файл + строка, повтор без дубля |
| A5 | Дефолтный путь неизменен по поведению | тест: заведение фичи в temp даёт ожидаемый набор файлов/строк |
| A6 | `precheck.sh` зелёный | полный прогон |

## Особенности по обратной функциональности

Аддитивно: дефолт неизменен (кроме недублирования и `Draft` — оба **исправления**,
не сломы). Новые флаги opt-in. Язык и крейты не затрагиваются — версии не
поднимаются. `NF_ROOT` по умолчанию = каталог скрипта/.. (прежнее поведение).

## Риски и зависимости

- **Риск: ключ идемпотентности ложно совпадёт** (напр. `| 0094 |` внутри другой
  ячейки). Снижение: ключ — литерал первого столбца с граничными `|`; номер
  4-значный; тест проверяет счётчик строк.
- **Риск: `--stage`/`NF_ROOT` сломают дефолт.** Снижение: дефолтная ветка
  сохранена отдельно; тест A5 гоняет полный сценарий заведения.
- **Граница (не риск): пересборка реестра из файлов (3b)** — отложена в кандидат
  (ненадёжна в POSIX sh); повторяющуюся боль снимает идемпотентность.
- **Tier:** **Tier 3** (инфраструктура/процесс; боль конкретная и повторяющаяся,
  но не в продукте).
