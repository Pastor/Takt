# Анализ фичи 0075: эталонная модель порождает компилируемый C

> Фича: [../features/0075-lib-src-reference-model.md](../features/0075-lib-src-reference-model.md) · ADR: [../adr/0075-lib-src-reference-model.md](../adr/0075-lib-src-reference-model.md)

## Зависимости

- **Смежно, блокирует полный ремонт генератора:** [0078](../features/0078-bit-array-semantics.md)
  (семантика `[bit;N]`). 0075 её **не** решает — разделяет эталон, обходя дефекты.
- **Приоритет / Tier:** **Tier 2** — тест `syntax_simple` проверял строку, а не
  компиляцию (слабее, чем должен); прод-код не задет.

## Проба (замер по коду, 2026-07-20)

`lamc compile SRC -t c` → `cc -fsyntax-only` даёт 11 ошибок:

| Класс | Причина | Куда упирается |
|---|---|---|
| `no member 'read_numeric'` (×N) | `out`-порт `u8` с бит-доступом (RMW) зовёт `read_numeric`, а эмитится только `write_numeric` | локальный баг `c_header` (кандидат) |
| `{…} >> 5` (expected ';') | `const [bit;8]` печатается макросом-массивом, бит-доступ трактует числом | семантика `[bit;N]` — 0078 |

Строка `S(Ping) = End` ошибок **не даёт** (проверено: ошибки на соседних строках).

## Ключевые решения анализа

1. **Разделение ролей эталона:** `SRC` — разбор (парсер), `SYNTH_SRC` —
   компиляция (`cc`). Не дублирование.
2. **`SYNTH_SRC` сохраняет** композицию `(Ping|Pong)+Toggle` и `S(Ping)=End`
   (главное, что охранял `syntax_simple`), убирает numeric-порт-бит-доступ и
   const-массив-бит-доступ.
3. **`syntax_simple` переезжает** в интеграционный тест: `lib.rs` пришпилен к
   лимиту размера, а `compile_to_c` — публичный API.

## Риски

- **Потеря сторожа `ref`** — снят: `reference_model_compiles_and_translates_state_ref`
  проверяет `S(Ping)=End` в выводе (ссылка пережила конвейер).
