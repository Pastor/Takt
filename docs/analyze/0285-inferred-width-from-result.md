# Анализ фичи 0285: Ширина выведенного типа

> Фича: [../features/0285-inferred-width-from-result.md](../features/0285-inferred-width-from-result.md) · ADR: [../adr/0285-inferred-width-from-result.md](../adr/0285-inferred-width-from-result.md) · тест-план: [../tests/0285-inferred-width-from-result.md](../tests/0285-inferred-width-from-result.md)

## Цель и контекст

`const K := 1 + 255;` давал ноль: тип выводился от левого операнда, а
нормирование (0207) заворачивало результат. Фича берёт ширину выведенного типа
у **результата** вычисления, не трогая явные типы и соседние правила.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Предшественники (0192, 0207, 0208) закрыты.
- **Влияние на порядок разработки:** не разблокирует.
  [0287](../features/0287-wider-type-array-literal.md) («`wider_type(Integer,
  Array)` даёт ложную `SE-089`») — **соседний класс той же причины**: там
  правило расширения типов побеждает явно объявленный тип источника. Замер
  показал, что фичи не пересекаются: 0285 правит выбор ширины **после**
  свёртки, 0287 — само правило `wider_type`.

## Замер (перепроверен инструментом, правило 30)

Проба снята `scripts/probe.sh` и признана **годной** (объявления используются,
имя файла не сталкивается с типами, общих отказов нет). Значения — у эталона,
подтверждены выводом цели `c`:

| Запись | Было | Ожидается |
|---|---|---|
| `1 << 8` | `0` | `256` |
| `1 + 255` | `0` | `256` |
| `255 + 1` | `0` | `256` |
| `2 * 128` | `0` | `256` |
| `128 * 2` | `0` | `256` |
| `200 + 200` | `144` | `400` |
| `300 - 44` | `256` ✓ | `256` |
| `1000 + 1` | `1001` ✓ | `1001` |

⚠️ **Кандидат винил сдвиг; замер показал любую арифметику.** Две последние
строки объясняют причину: ширины хватало **случайно** — левый операнд там сам
не влезал в восемь бит.

⚠️ **Расхождения между потребителями нет:** значение свёрнуто в семантике, и
все девять дают одно. `Tier 2` подтверждён в его собственном смысле — «молча
неверное значение при согласии инструментов».

## Требования и проверяемые условия

- **R1. Ширина выведенного типа — по результату.**
- **R2. Явный тип не трогается** (правило 0207 в силе).
- **R3. Тип из сигнатуры функции не трогается** (вывод Ce6 в силе).
- **R4. Отрицательное значение не расширяется** — домен 0207.
- **R5. Границы типа — у единственного носителя**, общего с `SE-089`.

## Особенности по обратной функциональности

**Наблюдаемое поведение меняется сознательно** (правило 11): `const K := 1 +
255;` было `0`, стало `256`. Прежнее значение — дефект, а не контракт: оно
следовало из порядка проходов, а не из решения о языке.

⚠️ **Корпус не затронут:** правок `examples/` не потребовалось, ни один тест
прежнего значения не закреплял. Два теста **соседних** правил упали на
переборах правки (см. ниже) и после сужения зелены без изменений — то есть
границы проверены их сторожами, а не моими.

## Версия языка (правило 22)

**Язык меняется** — наблюдаемое значение. Версия языка **не поднимается**: цикл
`0.10.0` открыт фичей 0243 (накопление). Версия крейта `takt-lang`: `0.43.0` →
`0.44.0`.

## Редакторский слой (правило 29)

**Проверка не требуется, и это ответ.** Новых токенов, форм объявления, узлов
АСД и диагностик нет — меняется выбор ширины уже существующего вывода типов.

## Риски и зависимости

- **Риск: правка шире предмета.** Реализовался **дважды**, и оба раза его
  поймали чужие сторожа: переопределение типа **всегда** сломало вывод Ce6 из
  сигнатуры функции; расширение по **нижней** границе сломало `~0` (правило
  0207). Отсюда три границы в решении.
- **Риск: расширение разойдётся с `SE-089`.** Снят тем, что границы берутся у
  `validate::literal_range::type_range`.
- ⚠️ **Граница:** правка опирается на множество «имена без объявленного типа»,
  снятое **до** вывода типов. Путь, добавляющий объявления после вывода, обойдёт
  её молча; названо в коде.
