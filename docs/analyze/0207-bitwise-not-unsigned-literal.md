# Анализ фичи 0207: Отрицание ~0 для беззнакового типа — два правила языка столкнулись

> Фича: [../features/0207-bitwise-not-unsigned-literal.md](../features/0207-bitwise-not-unsigned-literal.md) · ADR: [../adr/0207-bitwise-not-unsigned-literal.md](../adr/0207-bitwise-not-unsigned-literal.md) · тест-план: [../tests/0207-bitwise-not-unsigned-literal.md](../tests/0207-bitwise-not-unsigned-literal.md)

## Цель и контекст

Снять несогласованность языка: `~0` законен в теле и запрещён в объявлении.
Решение — Option B ADR (**решение заказчика 2026-08-16**): вычисленное значение
инициализатора нормируется по типу объявления правилом
[0127](../adr/0127-int-overflow-semantics.md), литерал автора не трогается.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Столкнувшиеся фичи — [0192](../features/0192-const-init-fold.md)
  (свёртка) и [0157](../features/0157-literal-u64-representation.md) (`SE-089`) —
  закрыты; норма [0127](../adr/0127-int-overflow-semantics.md) принята.
- **Влияние на порядок разработки:** ничего не блокирует.

## Замеры

Таблица «тело против объявления» — в ADR. Дополнительно:

- `~1` → `SE-089` («-2»), то есть дело не в нуле;
- выведенный тип (`var u := ~0;` → `[bit;8]`) — тот же отказ;
- **знаковый** тип работал и до фичи (`-1` везде);
- цель `st` отвергает `~` над операндом без статического типа (`ST-011`) — своё
  ограничение цели, вне объёма;
- в `examples/` и `book/` оператор `~` **не встречается** — вывод корпуса
  измениться не может.

⚠️ **Ключевой факт:** после свёртки вычисленное значение неотличимо от литерала
автора — оба приходят узлом `Number`. Значит, разделять их обязана **свёртка**,
и место для этого уже есть: она пропускает литералы (`is_literal`), чтобы не
отменять понижение `q` (0096).

## Требования и проверяемые условия

- **R1. Нормирование вычисленного.** Беззнаковый тип — обёртка `mod 2ⁿ`;
  ширина берётся у **типа объявления**, а не у литерала.
- **R2. Знаковый тип не нормируется.** Выход за границы остаётся `SE-089`
  (правило 0127: знаковое переполнение — ошибка программы).
- **R3. Литерал автора неприкосновенен.** `var u: u8 := 300;` — по-прежнему
  ошибка. ⚠️ Без этого правка означала бы «разрешить всё».
- **R4. Объявление и тело отвечают одинаково** — предмет фичи.
- **R5. Границы — из одного места.** Свёртка зовёт
  `validate::literal_range::type_range`; своя копия разошлась бы с проверкой.
- **R6. Вывод корпуса неизменен.**
- **R7. Версия языка 0.9.0** в трёх источниках + тег `v0.9.0` (правило 22).

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | `~0` → 255 / 65535 / 255 (u8, u16, выведенный) | значенческие тесты + строка `_init` порождённого C |
| A2 | `i8` → −1 | тот же тест |
| A3 | Литерал автора вне диапазона → `SE-089` | контр-пример |
| A4 | Знаковое вычисленное вне диапазона → `SE-089` | контр-пример |
| A5 | Объявление ≡ тело | отдельный тест сравнения |
| A6 | Корпус неизменен | `git status` по `examples/generated/` |
| A7 | Версия языка | `scripts/check-language-version.sh` + тег |
| A8 | Предкоммит | `./scripts/precheck.sh` |

## Особенности по обратной совместимости (правило 11)

Изменение — **расширение**: записи, бывшие ошибками, становятся законными.

⚠️ Одно исключение названо прямо: `var u: u8 := 200 + 100;` прежде отвергался
`SE-089`, теперь даёт `44` молча. Это не побочный эффект, а то же правило: в
теле та же запись уже даёт `44`. Цена согласованности — потеря диагностики о
переполнении **вычисленного** беззнакового значения; знаковое по-прежнему
ошибка.

Версия языка поднимается `0.8.0 → 0.9.0` (правило 22, первая языковая фича
цикла), коммит помечается тегом `v0.9.0`.

## Редакторский слой (правило 29)

**Правок не требуется:** лексика и синтаксис не менялись (`~` существовал),
новых узлов АСД и диагностик нет. Подсветка и автодополнение не задеты.

## Документирование (правило 24)

- `book/src/05-expressions/` («Результат за границами типа») — правило
  дополняется абзацем об инициализаторе и примерами `~0` / `200 + 100`.
- `book/src/appendix-errors/` (`SE-089`) — статья уточняется: проверка смотрит
  на литерал **автора**, вычисленное нормируется.

## Риски

- **Р1. Молчаливая обёртка вычисленного.** Снижение — правило описано в
  документе и симметрично телу; знаковый случай остаётся ошибкой.
- **Р2. Расхождение границ у свёртки и проверки.** Снижение — R5: один носитель
  границ.
- **Р3. Нормирование задело бы литерал автора.** Снижение — контр-пример A3 в
  тестах.
