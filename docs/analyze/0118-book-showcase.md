# Анализ фичи 0118: Раздел документа «Развёрнутый пример»

> Фича: [../features/0118-book-showcase.md](../features/0118-book-showcase.md) · ADR: [../adr/0118-book-showcase.md](../adr/0118-book-showcase.md) · тест-план: [../tests/README.md](../tests/README.md)

## Цель

Прикладной раздел, сквозным примером раскрывающий тракт «описание → генерация →
симуляция → верификация → инвариант». Язык **не меняется** (Tier 3). Опирается на
исключение правила 24 (ADR 0117).

## Модель-носитель (проверено прогонами)

`examples/dispenser.takt` — дозатор, 3 состояния (`Idle`/`Filling`/`Ready`),
`invariant SafeLevel = level <= TARGET`, `next`+`ref`:

- **Генерация:** `c`, `rust`, `sv`, `plantuml` — все компилируются (EXIT 0).
- **Симуляция:** цикл `Filling(0→80) → Ready(100) → Idle(0) → …`; инвариант
  соблюдён (максимум `level` = 100 = TARGET).
- **Верификация:** `F Filling` — **держится** (из `Idle` безусловный `next` в
  `Filling`); `F Ready` — **нарушено** под управляющей абстракцией (контрпример
  «застрять в `Filling`» недостижим по данным) — поучительная иллюстрация границ
  абстракции.
- **Инвариант в C:** `assert(model->level <= CONST_DISPENSER_TARGET);` в
  `Dispenser_tick`.

## Картинка симуляции в PDF

`takt-sim -o` по умолчанию — анимированный GIF (в PDF не встраивается). Решение
(ADR 0118): `--graphics-config default_svg.json` даёт покадровые SVG; два кадра
(`dispenser-0003` наполнение, `dispenser-0006` готовность) скопированы в
`images/`; `pandoc`+`rsvg-convert` встраивают их в PDF (проверено: PDF собран,
картинки внутри).

## Ограничения (правило 24)

Раздел прикладной — показывать вывод инструментов можно (ADR 0117). Номера
фич/задач и сведения о процессе в текст не попадают.
