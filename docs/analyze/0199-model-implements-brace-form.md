# Анализ фичи 0199: Реализация модели (`model M = A | B { … }`)

> Фича: [../features/0199-model-implements-brace-form.md](../features/0199-model-implements-brace-form.md) · ADR: [../adr/0199-model-implements-brace-form.md](../adr/0199-model-implements-brace-form.md) · тест-план: [../tests/README.md](../tests/README.md)

## Цель и контекст

ADR принял **Option C** (рекомендация архитектора и решение заказчика совпали):
реализация модели разрешается, а конфликт «реализация + собственные состояния»
отвергается диагностикой.

## Зависимости фичи (правило 17/19)

**Нет.** Смежна с [0194](../features/0194-sim-composition-model-always.md): та
завела ветвь `build_composition`, но проверить её значением не могла — вход
ломался раньше. Эта фича даёт такой вход.

## Места правки

| # | Что | Файл | Замечание |
|---|---|---|---|
| М1 | разворот реализации в синтетическое состояние | `semantic/tree.rs::expand_model_implement` | вызывается **до** цикла разрешения состояний — синтетическое состояние проходит тот же путь |
| М2 | диагностика конфликта | там же | **`SE-101`** с двумя позициями (модель и её собственное состояние) |
| М3 | реестр диагностик | `docs/diagnostics/README.md` | запись `SE-101` |
| М4 | документ языка (правило 24) | `book/src/04-models-states/` | форма и правило её взаимодействия с телом |

⚠️ **Ключевое решение реализации — разворот, а не поддержка новой формы у
потребителей.** Форма есть **синоним** записи `model M { start Имя = A | B; }`,
которая работает у эталона и всех четырёх целей. Развернув её на построении
дерева, мы не заводим для пяти потребителей новый вид узла: за границей
построения формы не существует. Тот же приём, каким свёрнуты выдержка `after`
(0143), начальное значение порта (0187) и инициализатор объявления (0192).

## Ограничения, которые определяют форму решения

- **О1. Разрешить `implements` в поле — недостаточно.** Первая редакция правки
  сделала именно это: эталон заработал, но **все четыре цели остались красными**.
  Причина: карта (`minimap`) строит состояния из `model.states`, и модель без
  состояний даёт стартовое состояние с пустым именем. Значит нужен не
  разрешённый `Extend`, а **состояние**.
- **О2. Имя синтетического состояния не может конфликтовать** — и не конфликтует
  **по построению**: модель с реализацией и собственными состояниями отвергается
  `SE-101`, то есть других состояний у неё нет.
- **О3. Тело владельца остаётся телом модели.** `always` не переносится в
  синтетическое состояние: его исполнение обеспечивает фича 0194 (model-level
  `always` — каждый такт до диспетчеризации). Это надо проверить **значением**:
  ровно раз за такт.
- **О4. Форма без тела (`model M = A | B;`) остаётся синтаксической ошибкой** —
  грамматика требует блок. Объём фичи её не меняет.

## Требования и проверяемые условия

| # | Требование | Проверяемое условие |
|---|---|---|
| R1 | Форма исполняется эталоном | `model M = A \| B { always … }` → композиция тикает |
| R2 | Форма переводится всеми четырьмя целями | `c`, `rust`, `sv`, `st` принимают |
| R3 | Трассы совпадают | потактовая сверка эталона и цели `c` |
| R4 | Тело владельца — ровно раз за такт | инвариант 0194 в этой форме |
| R5 | Конфликт назван | реализация + свой `start` → `SE-101` с двумя позициями |
| R6 | Форма без тела — по-прежнему ошибка разбора | `SY-002` |
| R7 | Эквивалент не задет | `model M { start Inner = A \| B; }` работает как раньше |
| R8 | Корпус не задет | дифф `examples/generated/` пуст |

## Критерии приёмки и способ проверки

| # | Критерий (из ADR) | Способ проверки |
|---|---|---|

| A4 | форма без тела — ошибка разбора | тест |

## Особенности по обратной совместимости (правило 11)

- **Язык расширяется**: форма, которая не работала, начинает работать. Ломающих
  изменений нет — то, что раньше отвергалось целями, теперь переводится.
- ⚠️ **Одно ужесточение**: `model M = A | B { start S … }` раньше принималось
  (молча теряя реализацию), теперь — `SE-101`. Это исправление молчаливой
  потери, а не сужение осмысленного: работавшего поведения у формы не было.
- Корпус и `book/` не задеты: формы там нет.

## Документирование (правило 24)

**Требуется.** Язык получает работающую форму и новое ограничение. Место —
раздел о моделях (`book/src/04-models-states/`): форма, её эквивалент и правило
«модель не может быть и композицией, и автоматом», плюс запись `SE-101` в
«Частые ошибки» и приложение об ошибках.

## Редакторский слой (правило 29)

**Правок не требуется.** Новых токенов и узлов АСД нет — форма уже разбиралась
грамматикой; меняется только её обработка на семантике. Новая диагностика
`SE-101` идёт общим путём `collect_compile_diagnostics` (0130) и доезжает до
редактора без правок LSP.

## Риски

- **Риск «починили эталон, забыли цели»** (О1) — уже случился в первой редакции
  правки и был пойман прогоном целей. Снижение: R2 проверяет все четыре.
- **Риск потерять инвариант 0194** (О3). Снижение: R4 на накапливающем теле.
- **Риск коллизии имени** синтетического состояния (О2). Снижение: `SE-101`
  делает коллизию невозможной по построению.
