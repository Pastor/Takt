# Анализ фичи 0101: Документ описания языка Takt

> Фича: [../features/0101-language-book.md](../features/0101-language-book.md) · ADR: [../adr/0101-language-book.md](../adr/0101-language-book.md) · тест-план: [../tests/README.md](../tests/README.md)

## Цель и контекст

Завести справочное **описание языка** Takt в каталоге `book/` (mdBook, ADR 0101),
инфраструктуру сборки и **процессное правило** его актуализации (правило 24).
0101 — **инфраструктурная** фича: она создаёт скелет документа (конфигурация,
Makefile, оглавление, вводная часть, seed-раздел «Обзор», приложения-заготовки) и
правило; **наполнение** каждого из 15 разделов — отдельные фичи-преемники. Язык
0101 **не меняет** → версия языка не поднимается.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Инфраструктура самодостаточна.
- **Влияние на порядок:** порождает **пул фич-разделов** (наполнение разделов 2–15
  + приложений); каждая — отдельная фича по правилу 17, приоритет расставит
  аналитик (базовые разделы «Лексика»/«Типы»/«Модели» логично раньше). Правило 24
  вводит стадию «Документирование» во **все** будущие фичи, меняющие язык.

## Состав документа (обоснование)

Структура опирается на референсы описаний языков:

- **Rust** (*The Book* + *Reference*) — разделы с автонумерацией, HTML с поиском
  (⇒ выбор mdBook); деление «обзор → конструкции → приложения».
- **Java** (*JLS*) — формальная последовательность: лексика → типы → выражения →
  операторы → грамматика в приложении.
- **IEC 61131-3 (ST)** и **IEEE 1800 (SystemVerilog)** — стандартный порядок:
  обзор/область → лексические соглашения → типы и значения → объявления →
  конструкции → модель исполнения → приложение с формальной грамматикой.

Отсюда состав (нумерация автоматическая из `SUMMARY.md`):

## Требования и проверяемые условия

- **R1. Только язык.** Документ описывает синтаксис/семантику/модель исполнения/
  конструкции/примеры; **не** содержит деталей реализации инструментов, номеров
  фич, ссылок на ADR/анализ/отчёты, истории процесса (правило 24).
- **R2. Структура из исходников.** Порядок и **автонумерация** разделов — из
  `src/SUMMARY.md`; каждый раздел — в своей папке с `index.md`, `examples/`,
  ресурсами.
- **R3. Сборка скриптом.** `make -C book build` собирает документ в **PDF**
  (mdBook + `mdbook-pandoc` + `xelatex`; шрифт текста/кода **Fira Code**);
  зависимости задокументированы, `precheck.sh` их не требует (обновление решения
  ADR — вывод PDF вместо HTML).
- **R4. Вводная часть и приложения.** Есть титул/введение/назначение и приложения
  «Грамматика»/«Литература»/«Глоссарий».
- **R5. Правило актуализации.** Правило 24 в `docs/RULE.md`; шаблон карточки
  содержит раздел «Документирование»; «каждый новый раздел — фича».
- **R6. Ссылочная целостность.** `check-links.py` зелёный (ссылки внутри `book/` и
  на `book/` из доков целы).

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Скелет `book/` заведён (config/Makefile/SUMMARY/вводная/seed/приложения) | `ls book/`, `ls book/src` |
| A2 | Сборка работает при наличии mdBook, иначе понятная ошибка | `make -C book build` (или `have-mdbook`) |
| A3 | Автонумерация из `SUMMARY.md` | сборка нумерует разделы 1..15 |
| A4 | «Папка на раздел» + пример кода в seed-разделе | `book/src/01-overview/examples/blinker.takt` |
| A5 | Правило 24 + шаблон «Документирование» | `docs/RULE.md`, `docs/templates/feature.md` |
| A6 | Нет процесса/номеров фич в документе | греп по `book/src` на `фич`/`ADR`/`0[0-9]{3}` — пусто |
| A7 | `check-links.py` зелёный | прогон |

## Особенности по обратной функциональности

Правило 11 неприменимо (новая инфраструктура, обратной совместимости не нарушает).
`precheck.sh`/CI не затрагиваются (mdBook — вне тулчейна). Код `takt-lang`/
`takt-sim` не меняется.

## Риски и зависимости

- **mdBook не установлен в среде** — сборка документа локально/в CI требует
  `cargo install mdbook`. Снижение: Makefile даёт явную диагностику; гейт «документ
  собирается» — отдельный кандидат (не в `precheck.sh`).
- **Дрейф документа от языка** — снижается правилом 24 (стадия «Документирование» в
  каждой языковой фиче) и шаблоном карточки.
- **Проникновение процесса в документ** — снижается R1/A6 (греп-проверка) и
  формулировкой правила 24.
- **Объём наполнения** — 15 разделов; декомпозирован на фичи-преемники (по разделу
  на фичу), 0101 несёт только инфраструктуру + seed.
