# Анализ 0045-05: Модель времени, сброс, автомат и композиция

> Обзор: [0045-sv-backend.md](0045-sv-backend.md) · ADR: [../adr/0045-sv-backend.md](../adr/0045-sv-backend.md) (вопросы 1, 2, 3) · задача: [../development/0045-05-fsm-time-reset.md](../development/0045-05-fsm-time-reset.md) · тест-план: [../tests/0045-sv-backend.md](../tests/0045-sv-backend.md)
>
> Требования **R6**, **R7**, **R8**; критерии **A8**, **A9**, **A10**.
>
> Это ядро фичи: здесь модель исполнения Lam встречается с моделью исполнения RTL.

## 1. Модель времени

**Проблема.** В `.lam` тактового сигнала **нет**. `tick` — шаг модели, абстрактный:
в C его инициирует вызов `_tick`, в ST — скан-цикл ПЛК, в симуляторе —
`Unit::tick`. В RTL без `clk` не существует ни одного регистра, и шаг происходит
**сам**, физически, по фронту.

**Решение (ADR, вопрос 1, Option A).** Такт Lam ≡ `posedge clk`. `clk` и `rst_n` —
**неявные служебные порты модуля**, добавляемые генератором; в языке их нет.

**Почему это честно, а не натяжка.** Мы не приписываем модели новой семантики —
мы выбираем **исполнителя шага**. Шаг Lam уже абстрактен и ничего не утверждает о
своём источнике. Отображение «шаг → фронт» — самое прямое из трёх целей: в C/ST
шаг ещё надо кому-то инициировать, в RTL он происходит сам.

**Почему не расширять язык** (Option B, `clock`/`reset` в `.lam`): версия языка
выросла бы (правило 22), фича перестала бы быть аддитивной, а конструкция
оказалась бы **ложью для трёх целей из четырёх** (что делать с `clock` на ПЛК?).
Ровно тот довод, по которому ADR 0033 отверг свой Option C («явная модель такта
запуска в семантике языка») как преждевременный: требований нет, а неудачную
языковую конструкцию не убрать дёшево.

**Зарезервированные имена.** `clk`/`rst_n` — **не ключевые слова языка**, а
зарезервированные имена **цели** `sv`. Модель с портом `clk` остаётся валидной для
`c`/`c-hal`/`plantuml`/`st` и отвергается **только** целью `sv` — **`SV-007`**.
Проверено `grep` по `examples/`: ни один `.lam` корпуса не объявляет порт
`clk`/`rst_n` → цена сегодня **нулевая**.

**Граница фичи:** один тактовый домен, один сброс. CDC, множественные домены,
SDC/XDC, gated clocks, потолок частоты — **вне объёма** (кандидаты).

## 2. Сброс и контракт фичи 0033 — ядро анализа

### Что постановил ADR 0033

Генератор C заводит синтетическое состояние `{PREFIX}_INIT` **на каждый уровень
иерархии** (`c_header.rs:49,102,153,181`), и `case INIT` завершается `break`
(`c_model.rs:649`) — то есть **вход в стартовое состояние стоит такта**. Сдвиг
относительно симулятора = **глубине вложенности** (пробы 0033: 1/2/3 уровня →
сдвиг 1/2/3 такта).

ADR 0033 принял **Option B**: генератор C перестаёт тратить такт на `INIT`; эталон
моментности — **модель**; сдвиг обязан быть **нулевым на любой глубине**.
Решающий довод (драйвер 3) — **композируемость**: если обёртка
`model Mid { start S = Inner; }` молча съедает такт, потактовые свойства модели не
композируемы, и рассуждать о времени в языке нельзя.

Следствия ADR 0033 прямо адресованы нам: «Будущие бэкенды (0041 ST) получают
**контракт** “вход в стартовое состояние не стоит такта”, а не прецедент чужой
бухгалтерии».

**0045 — первый бэкенд, пишущийся уже под этот контракт.**

### Решение (ADR, вопрос 2, Option A): синхронный `rst_n`, ветвь сброса несёт `enter` стартового состояния

```systemverilog
always_ff @(posedge clk) begin
    if (!rst_n) begin
        state    <= LIFT_IDLE;   // стартовое состояние — напрямую
        cmd_fork <= 1'b0;        // enter { cmd_fork := 0; } — инлайн в сброс
    end else begin
        state    <= state_next;
        cmd_fork <= cmd_fork_next;
    end
end
```

**Синтетического `INIT`-состояния нет вообще.** Его роль исполняет цепь сброса.

### Почему это качественно лучше, чем в C

| | C (до 0033) | C (после 0033) | **SV (0045)** |
|---|---|---|---|
| `INIT` в `enum` состояний | **есть** (`stacker.h:46`) | остаётся как внутренняя метка | **отсутствует** |
| Вход стоит такта? | **да, по такту на уровень** | нет (правка `c_model.rs`) | **нет — невозможно иначе** |
| Как достигается сдвиг 0 | — | **правкой**: диспетчеризация `INIT` до `switch`, рекурсивно по уровням | **по построению**: цепь сброса |
| Сдвиг на глубине N | **N** | 0 (после правки) | **0 — бесплатно** |
| Механизм на глубине N | N вложенных `case INIT` | N вложенных `if (state == INIT)` | **N параллельных `always_ff`, один фронт** |

**Ключевое наблюдение.** В C сдвиг = глубине, потому что уровни входят
**последовательно** (каждый `case INIT` тратит свой такт). В RTL все `always_ff`
сбрасываются **одновременно, одним фронтом** — параллелизм здесь физический.
Поэтому сдвиг = 0 на любой глубине достаётся **даром**, без рекурсивной правки,
которую задача 0033 вынуждена делать для C.

**Совпадение с симулятором.** `Unit::tick` первым делом зовёт
`enter_initial_state()` и **в том же такте** исполняет тело (задача 0025-04). SV
приводится к **уже существующей** семантике, а не изобретает свою.

### Проверено фактически (проба тестбенча)

```
после сброса (до 1-го такта): state=0 cmd_fork=0
такт 1: state=0 cmd_fork=0 lift_done=0     <- тело LiftIdle исполняется УЖЕ здесь
```

Против C (зонд ADR 0033, трёхуровневая модель): тело впервые исполняется на
**такте 4**. Против симулятора: такт 1. **SV = симулятор. Сдвиг = 0.**

### Вердикт по зависимости

**0033 — НЕ зависимость 0045.** Полный разбор — в [обзоре](0045-sv-backend.md).
Кратко: 0033 правит `generator/c/`, который SV не вызывает; контракт SV исполняет
конструктивно **сегодня**; сверка «SV ↔ симулятор» сходится **без** закрытия 0033
(обе стороны — сдвиг 0). Сверка «SV ↔ C» до закрытия 0033 не сойдётся, но она **не
входит** в критерии 0045.

**Риск (РИ9):** если 0033 отменят и `INIT`-такт возведут в семантику языка —
вопрос 2 придётся пересматривать (SV пришлось бы держать лишнее состояние и
тратить такт после сброса ради чужой бухгалтерии). Оценка низкая: ADR 0033
**Accepted**, а его Option A отвергнут явно — в том числе доводом «заражает
будущие бэкенды».

### Ограничение: `enter` стартового состояния обязан быть константным

Ветвь сброса синтезируется в **цепь сброса триггеров** — она не вычисляет
выражений. Отображаются только **константные** присваивания.

- **Цена для корпуса — нулевая** (проверено зондом): `LiftIdle.enter` —
  `cmd_fork := 0` (`stacker.lam:358`); `MovementController.enter` — константы
  (`stacker.c:298-302`).
- **Если `enter` стартового состояния вычисляет значение от входов/функций** —
  отобразить нельзя → **`SV-008`** (ошибка), а не несинтезируемый вывод.
- **Обход для автора:** перенести вычисление в `always` стартового состояния (оно
  исполнится на такте 1 — сдвиг всё равно 0).
- Послабление (двухфазный сброс) — кандидат, не эта фича.

## 3. Форма автомата: two-process

**Решение (ADR, вопрос 3, Option A):** `always_comb` (тело состояния, переходы,
`*_next`, **блокирующие** присваивания) + `always_ff` (латч, **неблокирующие**,
ветвь сброса).

**Решающий довод — семантика операторов внутри такта.** Тело состояния Lam —
императивная последовательность: `v := 1; w := v;` даёт `w = 1` (так в C, так в
симуляторе). Варианты:

| Стиль | Что стало бы с `v := 1; w := v;` | Вердикт |
|---|---|---|
| **`always_comb`, блокирующие `=`** | `w = 1` — **как в C** | **принято** |
| `always_ff`, неблокирующие `<=` | `w` получает **старое** `v` — **другая модель** | отвергнут |
| `always_ff`, блокирующие `=` | результат верен, но это **грубое нарушение правил RTL** (гонки между блоками, расхождение симуляции и синтеза) | отвергнут: лечение хуже болезни |

Инлайн `enter` цели в переход (обязательный для изоморфизма с C) требует, чтобы
запись выхода была видна последующим операторам **внутри такта** — в неблокирующей
семантике это невозможно в принципе.

**Изоморфизм с C.** `unique case (state)` в `always_comb` ≡ `switch (model->state)`
(`c_model.rs:554`); порядок `if` по `ref`-рёбрам — тот же; инлайн `enter` — тот
же. Сверка A9 против зонда `stacker.c:277-326`.

## 4. Композиция `M1 | M2` — где RTL выигрывает и где нет

**Не поддаться формуле «параллельные модели в RTL естественны — это просто
параллельные `always_ff`». Она верна наполовину, и вторая половина определяет
решение.**

### Что действительно выигрыш

Регистры состояний параллельных моделей — **физически одновременные** триггеры. C
**сериализует** такт: `CommandReceiver_tick` → `MovementController_tick` →
`LiftController_tick` (`stacker.c:425-433`); такт родителя стоит **суммы** их
работ. RTL тактирует все три автомата **одним фронтом за один такт**, независимо
от их количества. **Масштабирование по числу параллельных моделей — бесплатное.**
Ни C, ни ST этого дать не могут — настоящее и крупное преимущество цели.

### Что не выигрыш — координационные переменные

Параллельные модели `stacker.lam` общаются через переменные корня (`lift_request`,
`lift_op`, `lift_done`). **Семантика C** (зонд `stacker.c:425-433`): модели
вызываются **по порядку**, и модель, идущая позже, **видит записи, сделанные
ранее в этом же такте**: `MovementController` пишет `lift_request`,
`LiftController` читает его **в том же такте**.

**То есть `|` в Lam — не «одновременно и независимо», а «последовательно внутри
такта, в порядке объявления».** Это факт о языке, установленный зондом, а не
предположение.

Наивное «модуль на под-модель с комбинационными связями» даёт один из трёх
неприемлемых исходов:

| Исход | Почему неприемлем |
|---|---|
| **Несколько драйверов** одной переменной (`lift_done` пишет `LiftController`, `busy` — `CommandReceiver`) | ошибка компиляции SV |
| **Комбинационная петля** `MovementController → lift_request → LiftController → lift_done → MovementController` | несинтезируемо. **Проверено:** Verilator ловит (`UNOPTFLAT`, код 1), yosys — **не ловит**, синтезирует молча |
| **Регистрация** координационных переменных | **сдвиг на такт** → SV исполняет **другую модель**, чем C и симулятор. Ровно то, что ADR 0033 осудил в `INIT`-тактах (зависимость моментности от структуры) |

### Решение (ADR, вопрос 3, Option A′): уплощение с сохранением порядка

Один SV-модуль на **корневую** модель. Регистры состояний под-моделей —
**независимы** (`always_ff`). Вся комбинационная логика — в **одном**
`always_comb`, где блоки под-моделей идут **в том же порядке, в каком C зовёт их
`_tick`**, и общаются через **блокирующие** присваивания.

Почему это работает:

- **Порядок + блокирующие присваивания = семантика C буквально** («позже вызванный
  видит записи раньше вызванного»).
- **Один драйвер** на переменную → SV-корректно.
- **Петли нет:** порядок разрывает цикл ровно там же, где его разрывает такт в C.
  (В C `MovementController` читает `lift_done`, записанный `LiftController` на
  **предыдущем** такте, — то есть через регистр; а `lift_request` передаётся
  **внутри** такта, вперёд по порядку. Уплощение воспроизводит обе стороны точно.)
- **Выигрыш параллелизма сохраняется:** регистры состояний остаются независимыми
  триггерами; такт по-прежнему один на всю композицию.

**Плата (документируется):** иерархия SV не отражает дерево моделей Lam (один
модуль вместо дерева); длинная комбинационная цепь → потолок частоты.

### `M1 + M2` (конкатенация)

Шаги `case` родителя: пока `!m1_is_done` — работает логика `M1`, затем `M2`.
Изоморфно C (последовательные шаги по `state` родителя).

## 5. Таблица отображения (нормативная)

| Конструкция Lam | C (зонд) | **SystemVerilog** |
|---|---|---|
| `model M { … }` (корень) | `struct M` + `M_tick()` | `module m (input logic clk, input logic rst_n, …);` |
| `state S { … }` | `case …_S:` в `switch` | ветвь `case` в `always_comb` |
| **стартовое состояние** | синтетический `case …_INIT`, **стоит такта** | **ветвь `if (!rst_n)`** в `always_ff`; `INIT` **отсутствует**; **сдвиг = 0** |
| `enter` стартового состояния | в `case INIT` | **в ветвь сброса** (только константы, иначе `SV-008`) |
| `enter` цели при переходе | инлайн в переход | инлайн в ветвь `case` (блокирующие) |
| `always` | тело `case` | тело ветви `case` |
| `exit` | перед сменой `state` | перед присваиванием `state_next` |
| `ref S: cond;` | `if (cond) { …; state = S; break; }` | `if (cond) begin …; state_next = S; end` (порядок рёбер сохраняется) |
| `M1 \| M2` | под-структуры + последовательные `_tick` | независимые `always_ff` на состояние + инлайн в **общий** `always_comb` **в порядке C** |
| `M1 + M2` | шаги по `state` родителя | шаги `case` родителя по `is_done` |
| терминальность | `_is_done()` → `state == …_END` | `assign is_done = (state == ST_END);` |
| переменная модели | поле структуры | `logic`-регистр + `*_next` |

## 6. Проверка (задача 0045-05)

- **A8 (сдвиг = 0, R7):** тестбенчи на глубину **1, 2 и 3** — те же формы, что в
  пробах ADR 0033 (`start Idle { always { v := 7; } }`;
  `model Conf {…} start Entry = Conf;`; трёхуровневая). Ожидание: тело исполняется
  на **такте 1** во всех трёх (C сегодня даёт 2/3/4). **Проба на глубине 1 уже
  пройдена вручную** — трасса выше. **Не требует закрытия 0033.**
- **A9 (изоморфизм с C):** сверка переходов `LiftController` с зондом
  `stacker.c:277-326`, зафиксированным в ADR: та же последовательность условий,
  тот же инлайн `enter`.
- **A10 (сверка с симулятором):** `conformance_sv_tests.rs` по образцу
  `conformance_c_tests.rs` (0025-07). **Отличие в лучшую сторону:** тот тест
  вынужден сверять только **установившиеся** значения из-за `INIT`-тактов C
  (комментарий модуля, строки 30-42); для SV сдвиг = 0 с обеих сторон → **можно
  сверять потактовую трассу**. Механика (`verilator --binary --timing` +
  потактовая печать) **опробована**.
- **Петля (РИ1):** контрпример — модель с координационным циклом; проверить, что
  порождённый SV **не** содержит петли (гейт Verilator, код 0). Дополнительно —
  негативный тест: рукописная петля валит `verilator --lint-only` (**проверено**,
  код 1), то есть гейт живой.
- **`SV-008`:** фикстура с неконстантным `enter` стартового состояния → ошибка.
- Сперва **зонд**, затем assertions против захваченного (`CLAUDE.md`).
