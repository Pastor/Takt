# Анализ фичи 0197: Стиль кода языка Takt

> Фича: [../features/0197-language-code-style.md](../features/0197-language-code-style.md) · ADR: [../adr/0197-language-code-style.md](../adr/0197-language-code-style.md) · тест-план: [../tests/0197-language-code-style.md](../tests/0197-language-code-style.md)

## Цель и контекст

ADR принял **Option A**: истина — `taktc fmt`, свод излагает действующее
поведение. Форма — единый сплошной список (решение заказчика). Синонимы
объясняются, выбор остаётся автору.

Работа целиком документная: правок кода не требуется, корпус не сдвигается.

## Зависимости фичи (правило 17/19)

- **Зависит от:** `нет`. [0024](../features/0024-lam-formatter.md) (форматтер) и
  [0101](../features/0101-language-book.md) (инфраструктура документа) закрыты.
- **Влияние на порядок:** ничего не блокирует.

## Ограничения, определяющие форму

**О1. Каждое утверждение о расстановке — из пробы, а не из чтения кода.**
Свод, расходящийся с инструментом, хуже отсутствующего. Поэтому все правила о
скобках, пробелах, отступах и переносах получены прогоном `taktc fmt --stdin` на
нарочно сбитом входе, а не выведены из `format/`.

**О2. Правила, которые инструмент не исполняет, обязаны читаться как советы.**
Замер: `fmt` не трогает порядок элементов, именование, содержание комментариев и
длину строки. Заказчик выбрал единый список без деления на блоки — значит
различие несёт **сама формулировка** («форматтер порядок не меняет — он ваш»,
«инструмент имена не проверяет»).

**О3. Примеры раздела проходят гейт документа** (фича 0133: компиляция целью `c`
+ прогон симулятора). Значит функциональный пример обязан быть самостоятельной
моделью, а не фрагментом.

**О4. Эмодзи в `book/` недопустимы** — шрифт документа их не содержит, и гейт
символов (фича 0146) их ловит.

## Требования и проверяемые условия

- **R1.** Раздел заведён и подключён в `SUMMARY.md`.
- **R2.** Каждое правило о форматировании подтверждено пробой `taktc fmt`.
- **R3.** Неисполняемые инструментом правила сформулированы как советы.
- **R4.** Синонимы `while`/`loop` и `[Guard]` объяснены; выбор оставлен автору.
- **R5.** Функциональный пример (правило 27) компилируется и симулируется.
- **R6.** Блок типичных ошибок (правило 26) присутствует.
- **R7.** Все примеры раздела каноничны — то есть `fmt --check` на них молчит.

## Критерии приёмки и способ проверки

| # | Критерий | Способ |
|---|---|---|
| A1 | R1 | греп по `SUMMARY.md`; сборка документа |
| A2 | R2 | прогон `fmt --stdin` на сбитом входе, сверка с текстом |
| A3 | R3 | чтение формулировок (машинно непроверяемо — правило 4) |
| A4 | R4 | наличие подраздела «Равноправные написания» |
| A5 | R5 | `taktc compile -t c` + `takt-sim -n 10` на примере |
| A6 | R6 | наличие подраздела «Частые ошибки» |
| A7 | **R7** | извлечь все блоки ```takt и прогнать `fmt --check` |
| A8 | гейт документа | `precheck.sh` (фича 0133) |
| A9 | предкоммит | код возврата 0 |

⚠️ **A7 — не формальность.** Первая редакция раздела содержала пример с
хвостовыми комментариями, **выровненными по колонке**; `fmt --check` его
отверг. То есть свод о стиле нарушал стиль, который описывает. Проверка нашла и
недостающее правило (см. ниже).

## Особенности по обратной функциональности (правило 11)

**Ничего не меняется.** Фича не трогает код, форматтер, корпус и язык. Версия
языка и версия крейта неизменны.

## Документирование (правило 24)

**Составляет предмет фичи.** Новый раздел `book/src/21-code-style/` в блоке
«Применение», последним пунктом: стиль — не описание языка, а способ им
пользоваться. Перенумеровывать разделы 01–20 ради «правильного» места не стали —
цена (все пути и ссылки) несопоставима с пользой.

## Редакторский слой (правило 29)

**Правок не требуется** — лексика, синтаксис и семантика не меняются. Ответ
зафиксирован здесь и в отчёте.

## Риски

- **Р1. Текст разойдётся с форматтером** при будущей правке `fmt`. Машинной
  сверки нет (ADR). Снижение — запись в живой контекст: фича, меняющая
  поведение `taktc fmt`, обязана проверить этот раздел.
- **Р2. Читатель примет советы за проверяемые правила** (риск принятой формы —
  единого списка). Снижение — О2: различие несёт формулировка.
