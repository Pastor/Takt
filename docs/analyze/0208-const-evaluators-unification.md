# Анализ фичи 0208: Три константных вычислителя компилятора живут порознь

> Фича: [../features/0208-const-evaluators-unification.md](../features/0208-const-evaluators-unification.md) · ADR: [../adr/0208-const-evaluators-unification.md](../adr/0208-const-evaluators-unification.md) · тест-план: [../tests/0208-const-evaluators-unification.md](../tests/0208-const-evaluators-unification.md)

## Цель и контекст

Снять **дубль правил** целочисленной арифметики константного вычисления. Решение
— Option B ADR: одна таблица операций (`const_eval::int_ops`), у вызывающих
остаётся носитель, набор допустимых форм и свои диагностики.

## Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Все три вычислителя заведены закрытыми фичами (0042,
  0143, 0185).
- **Влияние на порядок разработки:** ничего не блокирует. ⚠️ Смежная работа этой
  сессии показала, что **сводить вычислители нужно не всегда**: фича
  [0205](../features/0205-as-in-declaration-initializer.md) провела между ними
  границу (приведение `as` — право эталона, а не компилятора), а
  [0207](../features/0207-bitwise-not-unsigned-literal.md) добавила свёртке
  нормирование. Общее правило — сводить **правила**, а не вычислители.

## Замеры

Таблицы — в ADR (замеры 1–3). Кратко:

- **З1.** Дублей **два**, а не три: вычислитель выдержки считает наносекунды
  `checked_*` и живёт в другом домене.
- **З2.** Две таблицы уже разошлись формулировками («сдвиг **определён**» против
  «сдвиг **допустим**»).
- **З3.** Прочие различия — не правила, а специфика: носитель `i64`/`i128`,
  набор форм (у адреса отсекает **матчер**), запрет операнда `адрес:бит`, коды и
  тексты диагностик.

## Требования и проверяемые условия

- **R1. Правила — в одном месте.** Операции, обёртка, деление на ноль и граница
  сдвига описаны один раз.
- **R2. Наблюдаемое поведение не меняется.** Коды и тексты диагностик обоих
  путей прежние.
- **R3. Носитель адреса цел.** Сужение `as i64` равносильно прежней обёртке
  `wrapping_*` по 64 битам.
- **R4. Набор форм адреса цел.** Сравнения и логика по-прежнему отвергаются —
  их отсекает матчер, а не таблица.
- **R5. Выдержка не тронута** (домен длительностей, замер 1).
- **R6. Корпус неизменен.**

## Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Одинаковые значения в обеих позициях языка | тест по списку всех арифметических и побитовых операций |
| A2 | Отказы прежние (код + текст) | тесты деления на ноль, границы сдвига, сравнения |
| A3 | Обёртка по 64 битам | тест `i64::MAX + 1` → `i64::MIN` |
| A4 | Таблица проверена сама по себе | юнит-тесты `int_ops` |
| A5 | Корпус и предкоммит | `git status`, `./scripts/precheck.sh` |

## Особенности по обратной совместимости (правило 11)

Изменений поведения нет **вовсе** — это рефакторинг. Ни язык, ни диагностики, ни
вывод целей не меняются; версии крейтов и языка прежние (правило 22).

## Редакторский слой (правило 29)

**Правок не требуется:** язык не менялся.

## Документирование (правило 24)

**Не требуется:** ни синтаксис, ни семантика, ни диагностики не изменились —
правка внутренняя.

## Риски

- **Р1. Рефакторинг доказывается не мутацией.** Тесты сторожат равносильность, и
  на дефектной версии они зелёные — это свойство задачи, а не слабость тестов.
  Снижение: тесты гоняют **оба** пути на одном списке операций, то есть ловят
  именно будущее расхождение.
- **Р2. Сужение к `i64` могло изменить поведение при переполнении.** Снижение —
  отдельный тест и юнит-тест равносильности в самой таблице.
