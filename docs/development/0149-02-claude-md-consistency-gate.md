# Задача 0149-02: Правка расхождений живого контекста

> Фича: [../features/0149-claude-md-consistency-gate.md](../features/0149-claude-md-consistency-gate.md) · ADR: [../adr/0149-claude-md-consistency-gate.md](../adr/0149-claude-md-consistency-gate.md) · анализ: [../analyze/0149-claude-md-consistency-gate.md](../analyze/0149-claude-md-consistency-gate.md)

## Что было

Первый прогон гейта дал **6** расхождений — гейт был бы красным с первого дня,
если бы файл не привели в соответствие.

## Что сделано

| Строка | Было | Стало |
|---|---|---|
| 276–309 | «Генератор C: порождённый C **сегодня не компилируется** (фичи 0026, 0029, **обе в работе**)», `Bit` → `int`, `Rational` → f32, **«не используй вывод C как эталон»** | «вывод компилируется, отображение типов доверено»: `Bit` → `uint8_t`, `Rational` → `double`/`float` по `FloatWidth`, массивы через `bit_vector` либо `CC-014`/`CC-015`; сказано, что `conformance_c_tests` — основной потактовый эталон |
| 267 | `takt-lang/src/lsp.rs` | `takt-lang/src/lsp/` (модуль разделён) |
| 181 | `tree.rs:476` | `semantic/tree.rs` (имя файла, без номера) |
| 307 | `c_header.rs:344` | `c_header.rs::generate_model_header` |
| 280 | `generator/c/mod.rs:150` | `generator/c/mod.rs` (символ назван в тексте) |
| 1130 | «Форматтер (фича 0024, **в работе**)» | «(фича 0024, **закрыта**)» |
| 220, 991 | «Крейт `takt-sim` — 0.3.0» (читается как настоящее) | «Фича подняла крейт `takt-sim` до 0.3.0» |

⚠️ **Правка пункта о цели `c` — не косметика.** Прежний текст **запрещал**
использовать вывод C как эталон для `Bit`/`Rational`/массивов. При этом
`conformance_c_tests` сверяет с целью `c` поведение симулятора потактово, а гейт
`cc` компилирует весь корпус. Инструкция противоречила действующим проверкам и
могла увести следующую сессию от единственного имеющегося эталона.

⚠️ **Каждое новое утверждение сверено с кодом**, а не переписано по памяти:
`map_c_type` прочитан, гейты `cc`/`cmake` в предкоммите проверены зелёными.
