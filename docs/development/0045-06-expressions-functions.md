
### Разделение `Condition` / `Expression` — намеренное (инвариант проекта)

`CLAUDE.md` и ADR 0019: это **две грамматики с разной семантикой `=`** — в условии
равенство (`Condition::Equal`), в выражении присваивание (`Expression::Assign`).
**Не унифицировать.** Для SV это означает два печатающих пути, как в C.

Операторы (фича 0021, версия языка 0.1.0): присваивание — `:=`
(`Expression::Assign`); сравнение — `=` в выражениях (`Expression::Equal`) **и** в
условиях (`Condition::Equal`); `==` выведен из языка.

### `fn → fn` сегодня не работает (фича 0031)

`fn g(…){…} fn f(…){ return g(…); }` в одной модели → **`SE-004` «Неизвестная
функция 'g'»**. Причина — дефект прохода 5: `std::mem::take` (`semantic/tree.rs:822`)
опустошает карту функций модели на время разрешения их тел.

Фича 0031 (**РАЗРАБОТКА**, ADR **Accepted**) приняла Option B: вызовы `fn → fn`
разрешить, **циклы** в графе вызовов запретить новой диагностикой **`SE-053`**.
Обоснование запрета рекурсии — домен: MISRA C:2012 Rule 17.2; IEC 61131-3 не
допускает рекурсию в POU.

**Следствие для этой задачи:** падение происходит **в семантике, до генератора** →
SV-бэкенд таких моделей **не увидит**. **0031 — не зависимость.**

## Что сделано

> **Планируется (разработка не начата).**

План — `generator/sv/sv_expr.rs`.

### 1. `fn` → `function automatic`

```systemverilog
function automatic logic [7:0] travel_time(input logic [7:0] to_stack,
                                           input logic [7:0] to_row,
                                           input logic [7:0] to_section);
    logic [7:0] ds, dr, dy, t;
    // тело: блокирующие присваивания — как в C
    return t;
endfunction
```

**`automatic` обязателен.** У статических функций SV переменные разделяются между
вызовами — при двух вызовах в одном `always_comb` это дало бы **гонку**.
`automatic` даёт свежий кадр на вызов — семантика C. Это не стилистика: `function`
без `automatic` — скрытый дефект.

### 2. Рекурсия — писать нечего, и это правильно

**В синтезируемом RTL рекурсия невозможна физически:** функция разворачивается в
комбинационную логику, рекурсия означала бы бесконечную схему. Не «не
рекомендуется», а «не существует».

Работы по рекурсии в этой задаче **нет**: семантика отсекает её раньше — сегодня
`SE-004`, после 0031 — `SE-053`. **SV даёт третий, самый жёсткий довод в пользу
решения ADR 0031** (после MISRA и IEC 61131-3) — фиксируется как вклад фичи, а не
как код.

### 3. `extern fn` → **ошибка `SV-005`**

Обоснование (в тексте диагностики): в синтезируемом RTL аналога **нет**. DPI-C —
только симуляция. «Внешняя функция» на железе — это отдельный **модуль** со своим
интерфейсом, а `extern fn` Lam **не описывает ни портов, ни тактов, ни
латентности** — вывести их невозможно.

**Следствие, которое надо назвать прямо:** `elevator.lam`, `comprehensive.lam`,
`extend_complex.lam` для цели `sv` **не транслируются**. Флагман цели —
**`stacker.lam`** (0 `extern fn`), и это удачно: он же основной пример профиля
(три параллельные модели — витрина преимущества RTL).

Кандидат (не эта фича): «`extern fn` → чёрный ящик-модуль с объявленным
интерфейсом» — требует расширения языка.

### 4. Выражения и условия

Два печатающих пути (инвариант `Condition`/`Expression` не нарушать):

| Lam | **SV** | Примечание |
|---|---|---|
| `a & b`, `a \| b`, `!a` | `a && b`, `a \|\| b`, `!a` (логические) — либо `&`/`\|`/`~` (побитовые) | **Требует внимания:** для однобитных `logic` результат совпадает, для многобитных — **нет**. Решить по типу операнда, а не по токену |
| `=` (сравнение) | `==` | |
| `<`, `<=`, `>`, `>=` | те же | для `signed` — семантика от `logic signed` (0045-03) |
| `:=` (присваивание) | `=` в `always_comb`; `<=` только в `always_ff` | ключевое различие (задача 0045-05) |
| `+`, `-`, `*`, `/`, `%` | те же | **`/` и `%` синтезируются в делитель** — крупный блок; предупреждение? (открытый вопрос) |
| `<<`, `>>` | те же | |
| доступ к биту `port.N` | `port[N]` | |
| индексация массива `a[i]` | `a[i]` | |
| литералы | `8'd7`, `1'b1` | ширина **обязательна**, иначе `verilator -Wall` даст `WIDTHEXPAND` |
| вызов `f(x)` | `f(x)` | |
| непокрытый узел АСД | **ошибка `SV-002`** | **никакого тихого пропуска** (R4) |

**Статус по обратной функциональности (правило 11):**

| Функциональность | Работа |
|---|---|
| `Condition`/`Expression` в АСД | **н/п** — не унифицируются (инвариант, ADR 0019) |
| `generator/c/c_expr.rs` | **н/п** — не вызывается |
| Фича 0031 | **н/п** — не зависимость; после её закрытия SV примет вложенные вызовы **без правок** |
| Язык `.lam` | **н/п** |
| `generator/sv/sv_expr.rs` | **новый** |

## Открытые вопросы (решаются в этой задаче)

- **`/` и `%`.** В C — инструкция процессора; в RTL — **делитель**, крупный
  комбинационный блок (десятки/сотни ячеек, длинный путь → потолок частоты).
  Синтезируется, но автор об этом не знает. Предупреждение `SV-009`
  («деление синтезируется в аппаратный делитель») — обсудить: полезная подсказка
  или шум? Решить пробой `yosys stat` на модели с делением.
- **Логические vs побитовые операторы** для многобитных операндов — уточнить
  семантику `&`/`|` в Lam по `eval/ops.rs` (единственный источник истины,
  фича 0025) и отобразить **точно**, а не «похоже».
