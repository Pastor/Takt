# Задача 0024-02: Печать комментариев (переассоциация по `Location`)

> Фича: [../features/0024-lam-formatter.md](../features/0024-lam-formatter.md) · ADR: [../adr/0024-lam-formatter.md](../adr/0024-lam-formatter.md) · анализ: [../analyze/0024-lam-formatter.md](../analyze/0024-lam-formatter.md) · предыдущая: [0024-01](0024-01-format-core.md)

> **Статус:** ВЫПОЛНЕНО. Главный риск фичи снят.

## Что было

Задача [0024-01](0024-01-format-core.md) показала: **136 из 158** файлов корпуса
содержат комментарии, поэтому ядро печати было **непроверяемо** — критерии A1
(идемпотентность) и A3 (семантическая нейтральность) подтверждались только на
синтетических входах. `format_source` на входе с комментариями **отказывала**
(лучше отказ, чем тихая потеря), то есть корпус форматировался в **0** файлов.

## Что сделано

Модуль `grammar/src/format/comments.rs` — курсор по комментариям с
переассоциацией по байтовым смещениям (ADR Option A):

| Класс | Правило |
|---|---|
| **Ведущий** | начинается раньше узла → печатается на своих строках перед ним |
| **Хвостовой** | начинается после конца узла и **на той же строке** исходника → приклеивается к строке узла (`var x: u8 := 0; // счётчик`) |
| **Остаточные** | всё после последнего узла → хвост файла |

Опора — факты, а не эвристика: лексер хранит текст комментария **сырым**
(`input[start..end]`, вместе с `//`, `///`, `/* */`), поэтому он печатается
дословно, а `Location::Source(файл, начало, конец)` есть и у комментариев, и у
узлов АСД.

### Единая точка печати — чтобы комментарий не потеряла отдельная ветка

Добавлен `Out::node_line(loc, text)`: он сам печатает ведущие комментарии узла,
затем строку, затем хвостовой. Ветки печати не решают судьбу комментариев
самостоятельно — иначе достаточно забыть про них в одной из ~14 веток, и
комментарий исчезнет молча.

Плюс `debug_assert!(comments.is_exhausted())` в конце `format_source` —
страховка R2: непогашенный комментарий это дефект привязки, а не норма.

### Попутно закрыты пробелы печати

Реализованы `cond Имя = условие;` (печатью **условий**, а не выражений —
`=` здесь равенство, инвариант ADR 0019), `address ИМЯ = выражение;` (фича 0020)
и оператор `match`.

## Результат: гейт по корпусу включился

| Метрика | 0024-01 | 0024-02 |
|---|---|---|
| Отформатировано | **0** из 137 разбираемых | **136** из 137 |
| Непокрытых узлов | 137 (136 × комментарии) | **1** (`InlineFormula`) |
| A1 + A3 на корпусе | не проверялись | **проверены на 136 файлах** |

**Идемпотентность и семантическая нейтральность подтверждены на 136 реальных
файлах** — включая `elevator.lam`, `stacker.lam`, `comprehensive.lam`. Это и есть
главный результат: раньше эти критерии были обещанием.

## Проверки

- `cargo test --all-features -- --test-threads=1` → **1597 passed** (было 1594),
  0 провалов. `cargo clippy` → 0; `run_simulations.sh` → 5 из 5; ссылки 0.
- Гейт harness'а ужесточён: `KNOWN_GAPS` сократился до `InlineFormula` — любой
  другой непокрытый узел валит тест.
- Новые тесты: комментарии всех трёх видов (`//`, `///`, `/* */`) в ведущей и
  хвостовой позиции сохраняются (A2); хвостовой остаётся **на строке своего
  узла**; комментарии **идемпотентны** (не дублируются при повторном прогоне) —
  это главный риск идемпотентности.

### Устаревший тест заменён — и это правильный сигнал

`comments_are_refused_not_dropped` из задачи 01 проверял, что форматтер
**отказывает** на комментариях. Ограничение снято → тест устарел по замыслу.
Заменён на проверку реальной печати. Та же ситуация уже была в фиче 0025
(задача 02b-2): падение теста при снятии временного ограничения — признак того,
что тест проверял именно ограничение, а не выдумку.

## Что осталось по фиче

- Восстановление осмысленных пустых строк из зазоров исходника (ADR).
- **`0024-03`** — подкоманда `lamc fmt` (`--check`/`--stdin`).
- **`0024-04`** — LSP `textDocument/formatting` и действие IntelliJ.
