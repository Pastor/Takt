# Задача 0090-01: обобщённый строгий режим `precheck.sh` (`PRECHECK_STRICT=1`)

> Фича: [../features/0090-ci-precheck.md](../features/0090-ci-precheck.md) · ADR: [../adr/0090-ci-precheck.md](../adr/0090-ci-precheck.md) · анализ: [../analyze/0090-ci-precheck.md](../analyze/0090-ci-precheck.md)

## Что было

`precheck.sh` при отсутствии инструмента печатает `[пропуск]` и продолжает
(python3 → пропуск проверки ссылок; cc → пропуск гейта c-hal; iec2c → пропуск
гейта ST; verilator/yosys → пропуск гейтов sv/sv-mmio/тестбенчей). Строгость
существует **только** у SV-гейта — флаг `SV_GATE_REQUIRED=1` (превращает пропуск
verilator/yosys в `sv_failed=1`). Формат идёт как `cargo +nightly fmt` — **применяется**,
а не проверяется. То есть в CI пять из шести классов гейтов остались бы мягкими:
пропущенный гейт зелёный, неотличим от пройденного (риск R2/R3 анализа).

## Что сделано

Вводится **единый** флаг строгости `PRECHECK_STRICT` (умолчание `0`). Под
`PRECHECK_STRICT=1`:

1. **`SV_GATE_REQUIRED` подчиняется общему флагу.** В начале скрипта:
   `SV_GATE_REQUIRED="${SV_GATE_REQUIRED:-$PRECHECK_STRICT}"` — строгий режим
   автоматически включает и SV-строгость, но явный `SV_GATE_REQUIRED` по-прежнему
   уважается (обратная совместимость с CI-шагом до переписывания).
2. **Общий хелпер `require_tool <имя> <как поставить>`** для каждого мягкого
   пропуска: под флагом печатает ошибку и валит скрипт (`exit 1`), без флага —
   прежний `[пропуск]`. Заменяет разрозненные `else echo [пропуск]` в:
   - проверка ссылок (`python3`);
   - гейт c-hal (`cc`);
   - гейт ST (`iec2c` — проверка `-x $IEC2C_BIN`);
   - живая сборка C (`cmake`/`ninja` — сейчас безусловны; под флагом отсутствие →
     ошибка, а не падение с неясным сообщением).
   Существующий `sv_tool_missing` переиспользует тот же флаг (уже делает через
   `SV_GATE_REQUIRED`, теперь связанный с `PRECHECK_STRICT`).
3. **Формат под флагом — `--check`.** Строка `$CARGO_CMD +nightly fmt` заменяется
   на условную: `PRECHECK_STRICT=1` → `$CARGO_CMD +nightly fmt --check` (падает на
   неканоне), иначе — прежнее применение `fmt`.

Изменения **аддитивны** (правило 11): без `PRECHECK_STRICT` (умолчание) поведение
байт-в-байт прежнее — мягкие пропуски мягкие, `fmt` применяется, `SV_GATE_REQUIRED`
управляется как раньше. Строгость — свойство **среды вызова**, а не скрипта.

⚠️ Лимит размера модуля (правило 27/0027) на `precheck.sh` не распространяется
(это не Rust-модуль), но скрипт близок к 630 строкам — хелпер `require_tool`
сокращает дублирование, а не наращивает.

## Проверки

- **A4 (негативный сторож DX):** снять `verilator` из PATH, запустить без флага →
  строка `[пропуск] verilator …`, `EXIT=0`. Локальное поведение неизменно.
- **A3 (строгость):** `PRECHECK_STRICT=1` + недоступный `verilator` → `EXIT≠0` с
  явным сообщением про обязательность гейта.
- **A6 (формат):** испортить формат любого `.rs`, `PRECHECK_STRICT=1 ./scripts/
  precheck.sh` → провал на шаге `fmt --check` до долгих гейтов.
- **Регресс:** полный `./scripts/precheck.sh` (без флага) на машине со всеми
  инструментами → `EXIT=0`, `git status` чист (правило 5).
