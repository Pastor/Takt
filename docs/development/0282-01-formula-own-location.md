# Задача 0282-01: Собственная позиция формулы

> Фича: [../features/0282-formula-own-location.md](../features/0282-formula-own-location.md) · ADR: [../adr/0282-formula-own-location.md](../adr/0282-formula-own-location.md) · анализ: [../analyze/0282-formula-own-location.md](../analyze/0282-formula-own-location.md)

## Что было

`Formula::Guard(условие, имя)` позиции не имел. Реестр мест
(`semantic/formula/sites.rs`) клал в `FormulaSite::loc` координату **вместилища**
— модели либо состояния. Два `invariant` давали два `ST-022` с одинаковой
координатой `1:1`.

## Что сделано

1. **Третье поле — позиция:** `Formula::Guard(ConditionNode, Option<String>,
   Location)`. Берётся у АСД при построении дерева: у `invariant` — позиция
   объявления, у встроенной формулы — позиция аннотации.
2. **Реестр мест предпочитает свою позицию**; координата вместилища осталась
   запасным ходом — `condition_to_formula` строит формулу без исходного текста.
3. **`PartialEq` позицию игнорирует** — довод 0056: иначе две записи одной
   формулы стали бы разными узлами.

Правка затронула 19 мест в двух крейтах; каждое указал компилятор (`E0023`).

⚠️ **Дедупликация была заряженной ловушкой:** `diagnostics::normalize` сравнивает
`(позиция, код, текст)`, и при одинаковой координате два предупреждения с
одинаковым текстом схлопывались бы в одно — ровно та потеря, от которой 0235
сторожила счётом. Теперь это проверяется прямо (тест T3).

## Проверки

```sh
cargo test --test semantic formula_position   # 4 теста, включая прогон normalize
cargo test --all-features                     # 3286 тестов

```

внутренний реестр мест.
