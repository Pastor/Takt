# Задача 0043-02: Эмиттер формата `json` — контракт с внешними инструментами

> Фича: [../features/0043-address-map-export.md](../features/0043-address-map-export.md) · ADR: [../adr/0043-address-map-export.md](../adr/0043-address-map-export.md) · анализ: [../analyze/0043-address-map-export.md](../analyze/0043-address-map-export.md) · тест-план: [../tests/0043-address-map-export.md](../tests/0043-address-map-export.md)

## Что было

*Реальное состояние кода на 2026-07-15.*

- **Машиночитаемой выгрузки карты адресов нет.** Адреса существуют только внутри
  `AddressResolution` (`grammar/src/address_map.rs:372`) и утекают наружу
  единственным способом — как C-таблицы `{Enum}__ADDR[]` в заголовке, порождаемом
  целью `-t c-hal` (`generator/c/c_header.rs:675`). Чтобы получить адрес, внешний
  инструмент вынужден **парсить порождённый C** — что и делает фичу нужной.
- **Данных для полной записи в карте не хватает** — `ResolvedAddress` (`:361`)
  содержит только `addr`, `bit`, `source`. Тип и направление добавляет задача
  **0043-01** (они лежат в `VariableNode::Port { ty, direction }`,
  `semantic/mod.rs:847`, и уже под рукой в `resolve_model`, `:447–453`).
  **Эта задача зависит от 0043-01.**
- **Разрядности достоверной нет** — `width_from_ctype` (`c_header.rs:617`) для
  `Bit` даёт 4 (проба: `PROBE_SW` → `width 4` при однобитовом типе), дефект в
  кандидате 0029. Поэтому `json` разрядность **не эмитит** (ADR: не врать
  потребителю).
- **Зависимости в `grammar/Cargo.toml` (проверено):**
  - `serde` — **опциональна** (за фичей `ast-serde`);
  - `serde_json` — **опциональна** (за фичей `lsp`), то есть в дефолтной сборке
    `lamc` её **нет**;
  - `serde_json = "1.0.149"` — **безусловная dev-зависимость**.

  Отсюда решение: **эмиссию писать руками** (записи плоские — строки и числа),
  **разбор в тестах** — через `serde_json`. Новых обязательных зависимостей у
  `lamc` не появляется (ADR, драйвер 5).
- **Контракта формата не существует** — ни версии, ни перечня значений источника,
  ни документа. Его предстоит создать, и он сразу становится **внешним**.

## Что сделано

> **Планируется (разработка не начата).** Ниже — план задачи по ADR 0043 и
> анализу; заполняется фактом по мере реализации.

1. **Эмиттер `json`** — функция вида `export_address_json(&AddressResolution) ->
   String`, рядом с эмиттером `map` (модуль `address_map/export.rs`, заведён
   0043-01). Эмиссия — ручная, без `serde` в бинаре (см. «Что было»).
   Обязательное: экранирование строк и детерминированный порядок записей
   (сортировка по имени) — иначе `diff` выгрузок между ревизиями бесполезен.

2. **Состав записи на порт** (R5) — **только то, что есть в карте** после 0043-01:
   имя, адрес, бит, источник, тип, направление. **Не эмитить**: разрядность
   (недостоверна — 0029), reset-значения и группировку в peripherals (понятий в
   языке Lam нет). Это то же основание, по которому ADR отклонил SVD.

3. **Версия формата** (R6) — поле версии на верхнем уровне, **с первого
   выпуска**. Без него у потребителя нет точки ветвления, а формат — внешний
   контракт: чинить его задним числом негде.

4. **Открытый перечень источников** (R7) — в документации формата зафиксировать,
   что `source` **открыт**: потребитель обязан корректно принимать незнакомое
   значение. Это не формальность, а развязка с фичей **0042** (`--define`),
   которая добавит четвёртый источник: без R7 её выпуск сломал бы потребителей
   выгрузки, и между 0042 и 0043 пришлось бы заводить зависимость.
   - Смежное обязательство: адрес из define'а выгружается **разрешённым
     числом**, не именем символа (потребитель не имеет доступа к `-D`-окружению
     `lamc`). Расширение `AddressSource` — задача 0042, не 0043.

5. **Порт без адреса** (R8) — **явная пометка** отсутствия адреса, а не `0`
   и не пропуск записи (в отличие от `map`, где формат записи без адреса не
   поддерживает). `json` достаточно выразителен, чтобы сказать «порт есть,
   адреса нет» — и обязан это сказать.

6. **Документация формата** (правило 15) — описание в `README.md` с примерами из
   тест-плана (П1/П3). Правило 16: примеры после проверки идут в документацию.

| Функциональность | Статус |
|---|---|
| `grammar` / `address_map/export.rs` | планируется (после 0043-01) |
| `grammar` / `Cargo.toml` | **н/п** — новых зависимостей не добавляется (эмиссия ручная, `serde_json` уже dev-зависимость) |
| `grammar` / `generator/c` | **н/п** — не затрагивается |
| Язык `.lam` | **н/п** — язык не меняется (0.2.0) |
| `simulation`, LSP | **н/п** — не затронуты |

## Проверки

> **Планируется (разработка не начата).**

- `cargo test -- --test-threads=1`; `cargo test --features lsp -- --test-threads=1`;
  `./scripts/precheck.sh` (правило 5).
- Соответствие анализу: **R5** (валидность и полнота), **R6** (версия формата),
  **R7** (открытый перечень источников), **R8** (порт без адреса).
- Тест-план: **T10** (валидный JSON — `serde_json::from_str`), **T11** (полнота
  полей), **T12** (версия формата), **T13** (открытость `source`
  задокументирована), **T14** (мёртвый порт помечен, `0x0` не появляется), **T8**
  (после кругового рейса все `source` = `External`).
- Отдельно: сборка **без** `--features lsp` (дефолтная) должна проходить — это
  прямая проверка того, что эмиттер не утащил `serde_json` в бинарь.
- Ожидаемые значения — из **пробы 2026-07-15** (`CLAUDE.md`: сперва зонд, затем
  assertions против захваченного): для П1 источники обязаны выйти как
  `BTN → External`, `LED → Operator`, `SW → Inline`.
