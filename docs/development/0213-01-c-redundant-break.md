# Задача 0213-01: Безусловное ребро завершает цепочку в цели `c`

> Фича: [../features/0213-c-redundant-break.md](../features/0213-c-redundant-break.md) · ADR: [../adr/0213-c-redundant-break.md](../adr/0213-c-redundant-break.md) · анализ: [../analyze/0213-c-redundant-break.md](../analyze/0213-c-redundant-break.md)

## Что было

`generate_state_transitions` (`takt-lang/src/generator/c/c_model.rs`) на
безусловном ребре печатала переход, свой `break;` и **продолжала** обход
`references()`. Ветвь `case` закрывается общим `break;`, поэтому вывод содержал
пару `break; break;` (7 мест в корпусе), а рёбра после безусловного печатались
недостижимым кодом:

```c
case PROBE_RUN: {
    model->n = model->n + 1;
    model->state = PROBE_DONE;
    break;
    if (model->n == 1) {          // недостижимо
        model->state = PROBE_LATE;
        break;
    }
    break;                        // недостижимо
}
```

Три другие цели этот вопрос решают одинаково и обратного не печатают
(`rust_tick.rs`, `st_model.rs`, `sv_fsm.rs`).

## Что сделано

**`takt-lang` (цель `c`).** Ветвь безусловного ребра печатает `exit → enter →
state` и **возвращает управление** (`return Ok(())`): собственного `break;` у
неё больше нет, обход рёбер на ней заканчивается. Условная ветвь не тронута — её
`break;` обязателен (выход из `switch` изнутри блока `if`). Док-комментарий
функции переписан под новый контракт, причина правки и цена прежнего устройства
записаны рядом с кодом.

**Сторожа.**

- `takt-lang/tests/c_redundant_break_tests.rs` — четыре проверки: корпус без пар
  `break;` (падает **списком** «файл: строки»), фикстура «хвост после
  безусловного», контр-примеры на условное ребро и терминальное состояние.
- `takt-sim/tests/conformance_c_unconditional_edge_tests.rs` — **потактовая**
  сверка эталона и порождённой прошивки на модели с хвостом; условие хвоста
  истинно на том же такте, поэтому сверка отличает верную правку от
  половинчатой.
- Фикстуры — `takt-lang/tests/data/cbreak0213/{tail_after_unconditional,
  conditional_and_terminal}.takt` (корпус этот класс не покрывает: записи «ребро
  после безусловного» в `examples/` нет ни одной).

**Корпус и документ.** Пересобран `examples/generated/c` (4 отслеживаемых файла,
−5 строк). Обновлён снимок порождённого C в документе —
`book/src/18-showcase/generated/c/lift.{c,h}` и цитата в
`book/src/18-showcase/index.md`; попутно снят долг фичи 0195 (снимок нёс имена
портов без сегмента `PORT_`, то есть отставал от вывода инструмента).

**`takt-sim`, семантика, грамматика, LSP, плагины — правки не требуется** (н/п):
фича меняет только форму вывода одной цели; язык, диагностики и наблюдаемое
поведение прежние (правило 29 — ответ зафиксирован в анализе и отчёте).

## Проверки

```sh
cargo test --test c_redundant_break_tests                      # 4 проверки цели c
cargo test -p takt-sim --test conformance_c_unconditional_edge_tests  # потактовая сверка
./scripts/precheck.sh                                          # полный предкоммит
```

**Мутационная проверка сторожей** (прогнана 2026-08-17):

| Мутация | Кто падает | Наблюдаемое |
|---|---|---|
| M1: вернуть `break;` и продолжение обхода (полный откат) | `corpus_has_no_two_breaks_in_a_row`, `edge_after_unconditional_is_not_emitted` | список из 7 мест в 6 файлах — ровно замер ADR |
| M2: `break;` снят, обход **не** оборван (половинчатая правка) | `unconditional_edge_trace_matches_generated_c` | `sim=[1, 0, 0, 0]` против `C=[1, 9, 9, 9]` |

M2 — та причина, по которой сверка сделана значенческой: вывод половинчатой
правки `cc -Wall -Werror` принимает молча.
