# Задача 0060-02: Миграция четырёх целей на общий факт + закрытие фикса 0005-01

> Фича: [../features/0060-enum-width-shared-layer.md](../features/0060-enum-width-shared-layer.md) · ADR: [../adr/0060-enum-width-shared-layer.md](../adr/0060-enum-width-shared-layer.md) · анализ: [../analyze/0060-enum-width-shared-layer.md](../analyze/0060-enum-width-shared-layer.md)

## Что было

Каждая цель считает диапазон сама; цель `c` при этом **теряет знак молча** —
[фикс 0005-01](../fixes/0005-01-c-enum-signedness.md), Tier 1.

## Что сделано

Все четыре цели спрашивают факт у общего слоя ([0060-01](./0060-01-enum-facts.md))
и **только отображают** его в свой тип (правило 4 ADR):

| Цель | Было | Стало |
|---|---|---|
| `c` (`c/mod.rs:218`) | `max` → **всегда** `uint{bits}_t` | факт → `int{bits}_t` при `signed`, иначе `uint{bits}_t` — **это и есть фикс 0005-01** |
| `st` (`st_type::enum_type`) | свой каскад | факт → `integer_type(machine_bits, signed)` |
| `rust` (`rust_type::enum_repr`) | свой каскад | факт → `i8`/`u16`/… |
| `sv` (`sv_type::enum_width`) | свой расчёт | факт → `(min_bits, signed)`; `SV-004` при `None` |

`variants_range` (`st_type`) и локальные извлечения диапазона **удаляются**
(правило 5 ADR: в `generator/` не остаётся ни одного — сторож A4/T5).

**Машинная ширина** (округление `min_bits` до {8,16,32,64}) нужна трём целям
(`c`/`st`/`rust`) — считается **один раз** в общем слое как производная факта, а
не тремя каскадами.

⚠️ **Пустое перечисление — поведение сохраняется дословно** (правило 3 ADR):
`c` → `uint8_t`, `st` → `USINT`, `rust` → `u8`, `sv` → `SV-004`. Унификация — это
вопрос **семантики языка**, вынесен кандидатом; 0060 не вправе протащить его
рефакторингом (прецедент: 0029 сознательно не решала семантику `[bit;N]`).

Статус по обратной функциональности (правило 11): вывод `st`/`rust`/`sv` и всего
корпуса — **побайтово прежний**; у цели `c` меняется поведение **только** на
моделях с отрицательным перечислением, и это **исправление** доказанного дефекта,
а не смена контракта.

## Проверки

- **T1/A1:** `enum Level { Low = -5, … }` → `c` даёт **`int8_t`** (было `uint8_t`).
- **T2:** переход `ref Done: lv = Low;` **срабатывает** (было — никогда: `251 == -5`).
- **T3/A3 — ОСНОВНАЯ:** потактовая сверка на новой модели с отрицательным
  перечислением (`conformance_c_tests`) — зелёная. ⚠️ Заводится **вместе** с
  правкой: гейт `c` дефект **принимает** (`cc` даёт лишь предупреждение
  `-Wtautological-constant-out-of-range-compare`, а гейт идёт без `-Werror`), то
  есть зелёный гейт про этот дефект **не говорит ничего**.
- **T4/A2:** `git diff --exit-code examples/generated` — **пусто** по **всем**
  целям (в корпусе нет отрицательных перечислений). Сильный сторож «рефакторинг не
  задел лишнего»; опора — детерминизм закрытой 0048.
- **T5/A4:** `grep -rn "variants.iter().map(|(_, v)| \*v)" grammar/src/generator/`
  — ноль.
- **T7/A6:** пустое перечисление — четыре ответа **как сегодня**.
- **T8/A7:** `670` → `u16` / `UINT` / `uint16_t` / **10 бит**.
- **T9/A8:** `cc` не выдаёт `-Wtautological…` на фикстуре.
- **T11:** существующие тесты границ — зелёные **без правки ожиданий**.
- **T12:** `sv`, `V = -1` → `(2, signed)`.
- **T14:** мутация «вернуть `c` расчёт по `max`» обязана **валить T3**.
- **T13/A10:** поправить `CLAUDE.md` — там `Enum` объявлен доверенным для сверки с
  C («сверка — только `Integer`/`Enum`/`Bool`»); доверять можно лишь
  **неотрицательному**. Без этой правки следующий читатель снова поверит тексту.
- **A9:** `./scripts/precheck.sh` — гейты `c`/`st`/`rust`/`sv` зелёные.
