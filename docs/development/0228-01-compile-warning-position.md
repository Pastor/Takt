# Задача 0228-01: Предупреждение taktc compile несёт позицию

> Фича: [../features/0228-compile-warning-position.md](../features/0228-compile-warning-position.md) · ADR: [../adr/0228-compile-warning-position.md](../adr/0228-compile-warning-position.md) · анализ: [../analyze/0228-compile-warning-position.md](../analyze/0228-compile-warning-position.md)

## Что было

```text
Предупреждение [SE-036]: переменная 'BadVar' объявлена, но нигде не используется
probe.takt:2:17: Ошибка компиляции [SE-034]: Локальный тип 'NoSuchType' не найден
```

Две строки одного инструмента: у ошибки позиция есть, у предупреждения нет.
Координата у предупреждения при этом **была** — `position_prefix` без пути к файлу
отдаёт пустую строку, а путь предупреждению никто не ставил (ошибкам его ставит
`pipeline::stamp_file`).

У целей `c-hal`/`st-at`/`sv-mmio` было хуже: `report_hal_result` печатал формат
**литералом**, минуя `format_warning`, — то есть правка общей точки эти цели не
задела бы вовсе.

## Что сделано

**Одна точка печати.** Заведена `compile_cli::print_warnings(warnings, files,
quiet)`: разрешает `file_no` диагностики в путь через `FileTable::path_of`,
печатает общим `format_warning`, уважает `--quiet`. Литеральная копия формата в
`report_hal_result` удалена — цель печатает через ту же функцию.

**Реестр файлов вместо однодневки.** Модель для сбора предупреждений строится
`construct_model_with_files` с реестром, который остаётся у вызывающего (прежде
`construct_model` заводил `FileTable::default()` внутри и наружу не отдавал).
Благодаря этому предупреждение импортированного файла называет **его** путь:

```text
./lib.takt:1:1: Предупреждение [SE-036]: переменная 'lib_unused' объявлена, но нигде не используется
```

⚠️ **Штамповать именем входа нельзя** — это отвергнутый Option B: смещения
диагностики принадлежат тексту **своего** файла, и путь импортёра дал бы верный
код с координатами, указывающими не туда. `path_of` отвечает `None` на
незарегистрированный номер, поэтому непокрытая диагностика остаётся без
префикса — как прежде, но не врёт.

⚠️ **Ограничение HAL-ветви названо в коде:** там реестр содержит только корневой
файл (цель строит своё дерево внутри и таблицу наружу не отдаёт), поэтому
предупреждение импортированного файла остаётся без префикса. Расширение —
смена сигнатур трёх функций генерации, в объём не входит.

⚠️ **Ошибки `--define` (`DF-…`) оставлены со своим форматом** (`Ошибка --define
[DF-002]: …`): у аргумента командной строки нет места в файле, и префикс позиции
для него выдумывать нечем.

## Проверки

`takt-lang/tests/targets/cli_warning_position_tests.rs` — 5 тестов прогоном бинаря:

| Тест | Что держит |
|---|---|
| `warning_carries_path_line_and_column` | A1: путь, строка **и** колонка (2:5 у объявления) |
| `hal_target_warning_carries_position` | A2: цель `c-hal`, где формат был копией |
| `imported_warning_names_the_library_file` | A3: путь библиотеки, **не** импортёра |
| `warning_prefix_matches_error_prefix` | A4: форма префикса та же, что у ошибки |
| `quiet_suppresses_hal_warnings` | A5: `--quiet` на задетой ветви |

- `cargo test --test cli_warning_position_tests` — 5/5.
- `cargo test --test cli_warnings_tests` — 4/4 (фича 0081 не задета).
- `./scripts/precheck.sh` — код возврата 0.

**Пригодность проверок подтверждена мутацией:**

| Мутация | Ожидание | Факт |
|---|---|---|
| штамповать путь входа вместо `path_of` (Option B) | падает `imported_warning_names_the_library_file` | подтверждено (1 из 5) |
| вернуть литеральную копию формата в `report_hal_result` | падает `hal_target_warning_carries_position` | подтверждено |
| потерять учёт `--quiet` в `print_warnings` | падает `quiet_suppresses_hal_warnings` | подтверждено |

⚠️ Первая мутация проверяет **границу решения**: тесты отличают принятый Option A
от отвергнутого Option B, то есть «префикс появился» и «префикс верен» —
разные утверждения.

## Документ

**Правок не требует, и это стоит записать.** Раздел
[«Диагностики»](../../book/src/16-diagnostics/index.typ) и вводная часть приложения
об ошибках уже объявляют формат единым: «Сообщение строится единообразно:
`путь:строка:колонка: <вид> [<код>]: <текст>`». Для предупреждений `compile` это
было **неверно** — фича делает обещание документа верным, а не меняет его.

⚠️ Второй раз подряд документ оказался впереди инструмента (первый — фраза
приложения про `CS-001`, задача 0227-01). Документ, написанный про **свойство**, а
не про реализацию, тем самым работает сторожем: расхождение видно при чтении.
