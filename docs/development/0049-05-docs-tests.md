# Задача 0049-05: Документация, примеры и тесты

> Фича: [../features/0049-model-checking-ltl.md](../features/0049-model-checking-ltl.md) · ADR: [../adr/0049-model-checking-ltl.md](../adr/0049-model-checking-ltl.md) · анализ: [../analyze/0049-model-checking-ltl.md](../analyze/0049-model-checking-ltl.md)

## Что было

LTL описан в README как разбираемая, но **непроверяемая** аннотация (после 0035).
Тестов верификации нет (`ltl_tests.rs` — только parse + диагностики 0035;
`buchi.rs` — parse + непустота). Проверки пустоты/вердикта нет нигде.

## Что сделано

> **Готово.** Реализовано по ADR 0049 (R9, R10; правила 15, 16).

1. **README** — раздел «Верификация модели (`lamc verify`)» (рядом с
   `lamc fmt` — оснастка к оснастке):
   - что проверяется (таблица: достижимость `F Done`, живость
     `G (Fault -> F Idle)`, порядок `G (Open -> X Closing)`, отсутствие
     залипания `G F Idle`) и что **не** (данные вне абстракции);
   - смысл абстракции управления и **несимметричность вердикта**: «держится»
     надёжно, «нарушено» может быть ложным срабатыванием;
   - синтаксис, коды возврата, формат лассо (и оговорка: контрпример — какой-то,
     не кратчайший);
   - **примеры и контрпримеры** (правило 16): `holds.lam`/`fails.lam` (отличие —
     одна самопетля), атом-не-состояние, вложенная модель;
   - как отлаживать: `--trace` с разбором реального вывода;
   - раздел «Ограничения (текущий срез)».
   Статус LTL в разделе «Формулы» обновлён (было «верификация не реализована»).
2. **Фикстуры** `grammar/tests/data/verify/`: `holds.lam`, `fails.lam`,
   `reachable.lam`, `unreachable.lam`, `atom_not_state.lam` — парами
   «пример / контрпример» с минимальным отличием внутри пары.
3. **Тесты** (48 новых, зелёные):
   - юнит-тесты `verification/{kripke,product,check,verify}.rs` (37) — на
     вердикт/лассо, не «непусто» (капкан 0025, риск Р7);
   - интеграционные `grammar/tests/verify_tests.rs` (15) через `verify_all` /
     `verify_model` на фикстурах (A2, A3, A4), детерминизм (A6), завершаемость
     на корпусе `examples/` (A5), разбор `--property` (R8), README-паритет;
   - CLI-аргументы `lamc.rs::tests` (9).
4. **CHANGES.md**, **CLAUDE.md** — сняты утверждения «`build_buchi` из исходника
   не вызывается» и «LTL не верифицируется»; зафиксированы абстракция
   управления, `lamc verify` и капкан фикса 0010-01.
5. Версия языка **не растёт** (R10): `grammar.lalrpop`/`Cargo.toml` не тронуты —
   синтаксис не менялся, `lamc verify` аддитивен (прецедент `lamc fmt`).

**Тест-план** ([../tests/0049-model-checking-ltl.md](../tests/0049-model-checking-ltl.md))
— T1–T39 с привязкой к R/A и разбивкой по задеваемой функциональности
(правило 11).

**SE-055 не снят, а переформулирован.** ADR (Consequences) предполагал снять
предупреждение для проверяемых формул — «появился потребитель». На практике
потребитель появился у **отдельной подкоманды**: `lamc compile` LTL по-прежнему
не проверяет. Снять SE-055 значило бы вернуть ровно тот класс дефекта, который
закрыла 0035 (формула молча ничего не делает). Предупреждение оставлено, текст
теперь указывает на `lamc verify`.

## Проверки

- `./scripts/precheck.sh` — зелёный (включая гейт детерминизма 0048 и гейт
  `iec2c`); `cargo test -p grammar` — 1486 тестов; `cargo test --doc` — примеры
  публичного API (`verify_model`, `parse_ltl_property`) исполняются.
- **README-примеры прогнаны пробой** (правило 16): каждый фрагмент раздела
  (включая вывод `--trace`) воспроизведён `lamc verify` дословно; формулы из
  таблицы «что проверяется» закреплены тестами `readme_order_invariant`,
  `readme_no_starvation` — README обещает пользователю ровно то, что проверено.
- Соответствие анализу: R9, R10; критерии A1–A10.
