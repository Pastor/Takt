# Задача 0043-01: Ядро экспорта — обогащение записи и формат `map`

> Фича: [../features/0043-address-map-export.md](../features/0043-address-map-export.md) · ADR: [../adr/0043-address-map-export.md](../adr/0043-address-map-export.md) · анализ: [../analyze/0043-address-map-export.md](../analyze/0043-address-map-export.md) · тест-план: [../tests/0043-address-map-export.md](../tests/0043-address-map-export.md)

> ✅ **СДЕЛАНО (2026-07-19).** `ResolvedAddress` обогащён полями `ty`/`direction`
> (заполняются тем же обходом `resolve_model` — второго прохода нет); мёртвые
> порты пишутся в новое `AddressResolution::address_less`. Эмиттер `map` —
> `address_map/export.rs::export_address_map` (сортировка по имени, формат
> `{:#010x}`, порт без адреса опускается — `0x0` не эмитится). Круговой рейс —
> `export_map_entries` (общий печатник `write_map_line`). Тесты — T2–T9, T14,
> T20, T21 в `address_export_tests.rs`. Итог — [отчёт 0043](../reports/0043-address-map-export.md).

## Что было

*Реальное состояние кода на 2026-07-15 (проверено чтением и живой пробой).*

Модуль карты — **`grammar/src/address_map.rs`** (~600 строк). Вопреки описанию в
`CLAUDE.md`, файла `grammar/src/semantic/address_map.rs` **не существует**.

Что уже поставлено фичей 0020 (закрыта, `ГОТОВО` 2026-07-14):

| Сущность | Строка | Содержимое |
|---|---|---|
| `AddressMapEntry` | `:36` | `name: String`, `addr: i64`, `bit: Option<i64>`, `loc: Location` |
| `parse_address_map` | `:138` | парсер `.ld`-подобного формата; коды `AM-001…006`; устойчив к ошибкам (пропуск до `;`) |
| `AddressSource` | `:350` | `Inline` \| `Operator` \| `External` |
| `ResolvedAddress` | `:361` | `addr: i64`, `bit: Option<i64>`, `source: AddressSource` — **и всё** |
| `AddressResolution` | `:372` | `map: HashMap<String, ResolvedAddress>`, `diagnostics: Vec<Diagnostic>` |
| `lower_addr_expr` | `:384` | `ExpressionNode` → `(addr, Option<bit>)` |
| `resolve_addresses` | `:409` | публичная точка входа; вызывает `compute_usage` (`semantic/unused.rs`), затем `resolve_model` |
| `resolve_model` | `:440` | рекурсивный обход; приоритет **карта > оператор > inline** (`:464–495`); SE-050 (`:468`), SE-052 (`:505`); SE-051 — в `resolve_addresses` (`:424`) |

Единственный сегодняшний потребитель карты — C-генератор в режиме `c-hal`:
`generate_hal` (`generator/c/c_header.rs:644`) читает `options.address_map`
(`:651`) и печатает таблицы `{Enum}__ADDR[]` (`:675`). Наружу карта **не
выгружается никак** — публичной функции экспорта нет.

**Проблемы, которые решает задача (из анализа):**

1. **Экспорта нет** — ADR 0020 назвал его потребителем, но вынес в отдельную фичу.
2. **`ResolvedAddress` беден для выгрузки.** Нет типа и направления порта, хотя
   они **под рукой** в `resolve_model`: цикл уже деструктурирует
   `VariableNode::Port { expr, loc, name, .. }` (`:447–453`), а поля `ty` и
   `direction` лежат в той же структуре (`semantic/mod.rs:847`). Сегодня они
   просто отбрасываются. Направление и тип нужны формату `json` (0043-02) и,
   по анализу, будущей фиче 0041 (ST `AT %IX/%QX`).
3. **Разрядности в карте нет и брать её неоткуда** — `width_from_ctype`
   (`c_header.rs:617`) живёт в C-генераторе и для типа `Bit` даёт **4** (проба:
   `PROBE_SW`/`PROBE_LED` → `width 4` при однобитовом типе), тогда как дефолтный
   HAL разыменовывает `uint8_t`. Дефект известен (кандидат 0029). **Поэтому
   выбранный формат разрядность не эмитит** — и задача её в карту не тащит.
4. **Латентный дефект ядра 0020 (риск Р2, не чиним здесь).** Ключ карты —
   **голое** имя порта (`HashMap<String, _>`, `:374`; вставка `:499`), тогда как
   C-генератор индексирует таблицу **квалифицированными** вариантами. Проба на
   `examples/elevator_mini.lam`: варианты `ELEVATOR_MINI_CABIN_CABIN_BUTTON_DC` /
   `ELEVATOR_MINI_MOTOR_ELEVATOR_MOTOR_UP` при ключах `CabinButton_DC` /
   `ElevatorMotor_Up`. Одноимённые порты в разных под-моделях делят ключ —
   побеждает последний. В корпусе замаскировано ручной префиксацией имён.

**Живая проба 2026-07-15** (`lamc compile -t c-hal --address-map plat.map`):
приоритет источников работает — inline `BTN := 0x00200000` перекрыт картой
`BTN = 0x40000000` (`SE-050`); `GHOST` из карты дал `SE-051`;
`examples/elevator_mini.lam` без карты — `SE-052`, с полной картой на 44 порта —
компилируется. То есть данные для выгрузки есть и корректны.

## Что сделано

> **Планируется (разработка не начата).** Ниже — план задачи по ADR 0043 и
> анализу; заполняется фактом по мере реализации.

1. **Обогатить `ResolvedAddress`** (`address_map.rs:361`) полями, нужными
   выгрузке и берущимися бесплатно там, где обход уже идёт:
   - `ty` — тип порта (из `VariableNode::Port { ty }`, `semantic/mod.rs:847`);
   - `direction` — направление (оттуда же), основа прав доступа в `json`;
   - квалификация имени модели — **в объёме, не ломающем ключ** (см. п. 4).

   Заполнение — в `resolve_model` (`:447–453`), где `var` уже деструктурируется.
   Второго обхода модели **не заводить** (ADR, Action items). Добавление полей в
   публичную структуру ⇒ **минорный бамп** крейта `grammar` (правило 22; версия
   **языка** не меняется — 0.2.0).

2. **Эмиттер формата `map`** — публичная функция вида
   `export_address_map(&AddressResolution) -> String`, печатающая `.ld`-подобный
   формат, который читает `parse_address_map` (`:138`): `NAME = 0xADDR[:bit];`.
   Грамматику формата **не расширять** (R3) — воспроизводить существующую
   (EBNF: `address_map.rs:14–21`).
   - Порядок записей — **детерминированный** (сортировка по имени): `map` —
     `HashMap`, а недетерминированный вывод сломает идемпотентность (T7) и `diff`
     карт между ревизиями.
   - **Порт без адреса — запись опускается** (R8). Категорически **не**
     подставлять `0`, как это делает C-таблица (`c_header.rs:686`,
     `.unwrap_or(0)`): там это безопасно (SE-052 уже отсеял достижимые порты), а
     в выгрузке `0x0` неотличим от настоящего адреса.

3. **Круговой рейс** (R4) — обеспечить `export → parse_address_map → export`
   = побайтовое равенство. Оговорка контракта: источник **не** переживает рейс
   (после импорта всё `External`) — это семантика оверлея, а не дефект.

4. **Ограничение плоского ключа — задокументировать, не чинить.** Правка ключа
   задевает `c_header.rs:685` (`addr_map.get(port_name)`) и цель `c-hal`, то есть
   выходит за рамки 0043 и рискует регрессом закрытой фичи. Здесь: зафиксировать
   поведение тестом (T21) и вынести кандидатом.

5. **Размещение кода** — эмиттеры вынести в отдельный модуль (напр.
   `address_map/export.rs`), не наращивая `address_map.rs` (~600 строк) к порогу
   ~1000 (`CLAUDE.md`, риск Р6).

| `grammar` / `generator/c` | **н/п** — задача не трогает C-эмиссию; `c-hal` обязан остаться байт-в-байт |
| Язык `.lam` | **н/п** — язык не меняется (0.2.0); грамматика формата `map` не расширяется |
