## Что было

### Как устроен существующий гейт для C

`scripts/precheck.sh` собирает порождённый C настоящим компилятором (cmake/ninja
над `examples/generated/c`) — то есть проект **уже знает** приём «сгенерировали →
скормили настоящему инструменту». Эта задача повторяет его форму для SV.

`simulation/tests/conformance_c_tests.rs:69` — образец **мягкой деградации**:

```rust
fn cc_available() -> bool {
    Command::new("cc").arg("--version").output()
        .map(|o| o.status.success()).unwrap_or(false)
}
```

Тест пропускается, если компилятора нет, — не падает.

### Что показали пробы (проведены фактически)

Пробы — на рукописном модуле `stacker_lift_controller.sv` в целевом стиле (модель
`LiftController` из `examples/stacker.lam`, сверена с зондом C `stacker.c:277-326`)
и на двух контрпримерах.

| Проба | Verilator `--lint-only -Wall` | yosys `read_verilog -sv; synth` |
|---|---|---|
| Целевой модуль | **чисто, код 0** | **синтезирован, код 0, 22 ячейки** |
| `real` в `always_ff` | **принял молча, код 0** | **`ERROR: unexpected TOK_REAL`, код 1** |
| Комбинационная петля | **`UNOPTFLAT: Circular combinational logic`, код 1** | **синтезировал молча, код 0** |
| Тестбенч `verilator --binary --timing` | **собран и прогнан**; трасса подтверждает сдвиг = 0 | — |

### Вывод, определяющий эту задачу

**Инструменты ловят непересекающиеся классы дефектов, причём ровно те два, что
критичны для решений ADR:**

- **Verilator пропускает `real`** → расхожее «`--lint-only` даёт проверку синтеза»
  **неверно**. Verilator — линтер и **симулятор**; для него `real` легален.
  Если бы гейт был один (Verilator), решение «`Rational` → `SV-003`» (вопрос 4)
  осталось бы непроверенным.
- **yosys пропускает комбинационную петлю** → центральный риск отображения
  `M1 | M2` (вопрос 3) синтезатор **не ловит**; ловит только линтер.

**Гейта должно быть два.** Это установлено пробами, а не выбрано из осторожности.

## Что сделано

> **Планируется (разработка не начата).**

План:

1. **Шаг в `scripts/precheck.sh`** по образцу существующего C-гейта: для всех
   **транслируемых** `examples/*.lam` (список — см. ниже) выполнить
   `lamc compile -t sv` → `verilator --lint-only -Wall` → `yosys -p
   "read_verilog -sv …; synth"`. Оба обязаны вернуть 0.
2. **Мягкая деградация:** инструмент отсутствует → шаг **пропускается с явным
   сообщением** (образец — `cc_available()`), не падает. Машина разработчика может
   быть без Verilator/yosys; **в CI они обязательны** — иначе гейт бессмыслен.
3. **Шаг в `.github/workflows/ci.yml`.** Установка инструментов + оба гейта.
   Зафиксировать **минимальные версии** (см. открытый вопрос).
4. **Проверить, что гейт ловит регресс (T9/T10)** — обязательно:
   - намеренно эмитировать `real` → `precheck.sh` **краснеет** (на yosys;
     Verilator пропустит — это ожидаемо и фиксируется);
   - намеренно замкнуть комбинационную петлю → **краснеет** (на Verilator; yosys
     пропустит).

   **Гейт, который никогда не падал, — не гейт.** Эти две пробы документируют, что
   один инструмент недостаточен.
5. **Список транслируемых примеров** (проверено `grep`): `stacker.lam`,
   `elevator_mini.lam`. Отсекаются по `extern fn` (`SV-005`): `elevator.lam` (8),
   `comprehensive.lam` (2), `extend_complex.lam` (1). Список ведётся явно, а не
   «все, кроме падающих», — иначе гейт замолчит регресс.
6. Никаких `lint_off` в порождённом коде: если он требует глушения предупреждения
   — это **дефект генератора**, а не повод глушить.

**Статус по обратной функциональности (правило 11):**

| Функциональность | Работа |
|---|---|
| `precheck.sh` | **расширяется** — два новых шага; существующие не трогаются |
| CI (`.github/workflows/ci.yml`) | **расширяется** — установка инструментов + гейты |
| Цели `c`/`c-hal`/`plantuml` | **н/п** — их шаги не меняются |
| Код `grammar`/`simulation` | **н/п** — задача инфраструктурная |

- **T10 (регресс «петля»):** намеренная порча → краснеет; зафиксировать, что
  **yosys пропустил**, а поймал **Verilator**.
- **T11 (деградация):** снять инструмент с `PATH` → шаг пропущен с сообщением,

- `./scripts/precheck.sh` — зелёный целиком.

**Команды:**

```sh

verilator --lint-only -Wall out/sv/stacker.sv
yosys -p "read_verilog -sv out/sv/stacker.sv; synth -top stacker; stat"
```

## Открытые вопросы (решаются в этой задаче)

- **Версии в CI.** Verilator 5.x и yosys 0.6x — свежие; в Ubuntu-репозиториях
  версии старее → возможен разрыв «работает локально — падает в CI». Зафиксировать
  минимальные версии; при необходимости — сборка из исходников или OSS CAD Suite.
- **`unique case` на старых yosys.** В пробе (0.67) принят; при откате на
  репозиторную версию проверить повторно. Запасной путь — обычный `case` +
  `default`.
- **Время прогона.** `verilator --binary` в пробе собирался ~5 с (сборка C++).
  Для `precheck.sh` это приемлемо, но тестбенчи (0045-07) могут заметно удлинить
  прогон — измерить и, при необходимости, вынести в отдельный шаг CI.
