# Задача 0037-01: Кросс-платформенные тесты разбора `-I` в `lamc`

> Фича: [../features/0037-windows-test-failures.md](../features/0037-windows-test-failures.md) · ADR: [../adr/0037-windows-test-failures.md](../adr/0037-windows-test-failures.md) · анализ: [../analyze/0037-windows-test-failures.md](../analyze/0037-windows-test-failures.md) · тест-план: [../tests/0037-windows-test-failures.md](../tests/0037-windows-test-failures.md)

## Что было

**Реальное состояние кода на 2026-07-15** (ветка `v2`, коммит `6984471`;
установлено чтением `grammar/src/bin/lamc.rs`, 1149 строк).

### Продуктовый код — платформо-корректен, дефекта нет

`split_include_dirs` (строки 105–118) выбирает разделитель через `cfg`:

```rust
pub fn split_include_dirs(s: &str) -> Vec<String> {
    // На Windows путь может начинаться с буквы диска «X:», поэтому разделителем
    // служит точка с запятой. На Unix используется двоеточие (стандарт POSIX).
    #[cfg(windows)]
    let sep = ';';
    #[cfg(not(windows))]
    let sep = ':';

    s.split(sep)
        .map(str::trim)
        .filter(|seg| !seg.is_empty())
        .map(String::from)
        .collect()
}
```

Поведение задокументировано в doc-комментарии функции (81–104), в модульной
документации (11–26) и в `print_usage()` (425–426); `-I` можно повторять
(190–196) и писать слитно `-I<путь>` (198–200). **Продуктового бага не
обнаружено:** на Windows `C:\lib;C:\usr` режется по `;`, буква диска не
страдает.

### Механизм сбоя на Windows

`sep = ';'` → строка с `:` **не режется** → `include_dirs` получает один элемент
вместо двух (или два вместо трёх в `parse_full_args`) → `assert_eq!` не сходится
→ **пять падений**. Число совпадает с
[отчётом 0021](../reports/0021-swap-assign-compare.md) («5 тестов `lamc`»).

**Класс дефекта: платформо-нейтральный `#[test]` проверяет платформо-зависимое
поведение.** Дефект — **в тестах**, не в продукте. Формулировка кандидата
(«разбиение по `:` конфликтует с буквами дисков») описывает **мотив** `cfg`, а
не механизм падения.

**Соседние тесты, которые НЕ падают** (проверено — в них нет `:`):
`parse_single_include_dir` (799), `parse_multiple_include_flags` (823),
`parse_include_dirs_order_preserved` (1002), `parse_verbose_with_other_flags`
(1090) — они уже платформо-нейтральны и правки не требуют.

### Прогон на darwin (эталон «до»)

```sh
cargo test --bin lamc -- --test-threads=1   # → 44 passed
```

**Все 44 зелёные** — на macOS `sep = ':'`, вход совпадает с ожиданием. Это
ключевой факт: локально сбой **не воспроизводится**, и после правки локальный
прогон тоже даст 44/44. Утверждение о падении на Windows основано на **чтении
кода** и отчёте 0021, **не на прогоне**.

## Что сделано

> **Планируется (разработка не начата).** Ниже — план по решению **Option A**
> ADR 0037; ни строки кода ещё не изменено.

**Суть:** параметризовать вход пяти тестов платформенным разделителем. Тесты
проверяют «строка режется **разделителем платформы**» вместо ложного «строка
режется двоеточием». Продуктовый код **не трогается**.

**План правки** (весь дифф — внутри `mod tests`, строки > 661):

1. Ввести в `mod tests` `cfg`-константу разделителя:

   ```rust
   /// Разделитель списка путей `-I` на текущей платформе (см. `split_include_dirs`).
   #[cfg(windows)]
   const SEP: &str = ";";
   #[cfg(not(windows))]
   const SEP: &str = ":";
   ```

2. Переписать пять тестов на `format!` с `SEP` вместо литерала `:`; ожидания
   (`vec!["/lib/lam", "/usr/lam"]` и т. д.) остаются **прежними** — на обеих
   платформах результат один. Пример для теста 1:

   ```rust
   #[test]
   fn parse_include_dirs_separator() {
       let args = vec![
           "-I".to_string(),
           format!("/lib/lam{SEP}/usr/lam"),
           "main.lam".to_string(),
       ];
       let opts = parse_compile_args(&args).unwrap();
       assert_eq!(opts.include_dirs, vec!["/lib/lam", "/usr/lam"]);
   }
   ```

3. **Переименования** (имена с «colon» становятся ложными):
   `parse_include_dirs_colon` → `parse_include_dirs_separator`;
   `parse_include_dir_glued_colon` → `parse_include_dir_glued_separator`.
   Остальные три имени (`parse_include_dirs_long_flag`, `parse_full_args`,
   `parse_include_filters_empty_segments`) — оставить: они разделитель не
   называют.
4. **Не трогать** секцию 1 (713–780): её шесть `cfg`-тестов проверяют
   **конкретный символ** разделителя на конкретной платформе — это их предмет,
   параметризация его бы уничтожила (R4).
5. **Не трогать** doc-комментарии, включая doctest `parse_compile_args`
   (149–161), который тоже содержит `"/lib/lam:/usr/lam"`. **Проверено — этот
   doctest не исполняется вовсе:**
   - `lamc` объявлен как `[[bin]]` (`grammar/Cargo.toml:15–17`), а `cargo test`
     собирает doctest'ы **только с lib-таргета**;
   - прогон подтверждает: `cargo test --doc -p grammar` → **31 passed,
     5 ignored** — все из `grammar/src/lib.rs` и модулей библиотеки;
   - решающее доказательство: doctest начинается с
     `# use grammar_bin::{parse_compile_args, CompileOptions};`, а крейта
     `grammar_bin` **в workspace не существует** (`grep` по репозиторию — только
     эта строка). Если бы doctest исполнялся, он не компилировался бы **на всех**
     платформах, включая darwin, где прогон зелёный.

   Следовательно, на Windows он тоже не падает и в объём 0037 не входит.
   **Найденное попутно:** doctest мёртв (не исполняется и не скомпилировался бы),
   то есть пример в документации `lamc` **никем не проверяется** и может
   разойтись с кодом. К Windows отношения не имеет → **кандидат в бэклог**
   (правило 7), а не правка внутри 0037.

**Честная оговорка о пределах проверки.** Ни одна команда выше **не
доказывает**, что пять тестов проходят на Windows: на darwin они зелёные и до, и
после правки (эталон: 44/44). `cargo check --target …-windows-msvc` проверяет
только **компилируемость** ветки `cfg(windows)`, но не исполняет её. Настоящее
доказательство — критерий **A8**: лог job `windows` (подзадача
[0037-03](0037-03-ci-windows-matrix.md)) с явными именами пяти тестов в списке
`passed`. До этого статус подзадачи в отчёте — **⬜ «не проверялось на целевой
платформе»**, и закрывать A8 локальным прогоном **запрещено**.
