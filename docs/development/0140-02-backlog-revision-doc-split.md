# Задача 0140-02: правило свода и подсказка

> Фича: [../features/0140-backlog-revision-doc-split.md](../features/0140-backlog-revision-doc-split.md) · ADR: [../adr/0140-backlog-revision-doc-split.md](../adr/0140-backlog-revision-doc-split.md) · анализ: [../analyze/0140-backlog-revision-doc-split.md](../analyze/0140-backlog-revision-doc-split.md)

## Что было

Кандидаты снимались как придётся: разовая уборка не мешала накопиться заново.
Процессной обязанности «пройти по кандидатам при закрытии» в своде не было.

## Что сделано

1. **Правило 28** в `docs/RULE.md`: фича, доходя до закрытия, обязана пройти по
   кандидатам, которых называет её карточка или отчёт, и каждого **снять** либо
   **актуализировать** — опираясь на пробу или чтение кода, а не на память.
2. **`scripts/check-stale-candidates.sh`** — подсказка: с номером фичи печатает
   кандидатов, упоминающих её (тех, кого закрытие обязано просмотреть); без
   номера — размер блока. Подключён к `precheck.sh` **через `|| true`**: код
   возврата не меняет.

## Замер, изменивший замысел

Карточка фичи предлагала машинную проверку «кандидат ссылается на фичу в статусе
`ГОТОВО` → повод к ревизии». Реализовал, замерил — **28 из 28**. Ссылка на
закрытую фичу есть почти у каждого кандидата, потому что туда их и выносят
**при** закрытии; как сигнал счётчик пуст.

Метрика убрана, а вывод записан прямо в скрипт и в правило — чтобы её не
завели снова. Полезной осталась выборка **по номеру фичи**: она отвечает на
вопрос, который реально возникает при закрытии («что мне здесь просмотреть»).

## Проверки

```sh
sh -n scripts/check-stale-candidates.sh    # синтаксис
./scripts/check-stale-candidates.sh 0131   # печатает двух кандидатов 0131
./scripts/check-stale-candidates.sh        # сводка, код возврата 0
./scripts/precheck.sh                      # EXIT=0 (подсказка не влияет)
```
