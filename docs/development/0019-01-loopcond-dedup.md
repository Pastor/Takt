# Задача 0019-01: устранение дубликата LoopCond параметризацией Expression

> Фича: [../features/0019-condition-expression-unification.md](../features/0019-condition-expression-unification.md) · ADR: [../adr/0019-condition-expression-unification.md](../adr/0019-condition-expression-unification.md) · анализ: [../analyze/0019-condition-expression-unification.md](../analyze/0019-condition-expression-unification.md)

> **Статус:** ЗАПЛАНИРОВАНО (реализация не начата — фича доведена до стадии
> «Разработка» по запросу; код будет писаться отдельно с TDD).

## Что было

`grammar/src/grammar.lalrpop` содержит цепочку `LoopCondP14…LoopCondP1` —
почти дословную копию `Precedence14…Precedence1` (`Expression`), отличающуюся
лишь запретом ведущего `{` в первом операнде. Оба дают `ast::Expression`.

## План реализации (по шагам, TDD)

1. **Spike (PoC).** На отдельной копии грамматики проверить, выражается ли
   ограничение «нет ведущего `{`» через параметризованное правило LALRPOP:
   - вынести цепочку приоритетов в макрос `ExprChain<Atom>` (или эквивалент);
   - инстанцировать `Expression = ExprChain<FullAtom>` и
     `LoopCond = ExprChain<AtomNoBrace>`;
   - собрать, убедиться в отсутствии LR(1)-конфликтов.
   Если LALRPOP не позволяет — зафиксировать в отчёте, перейти к запасному
   варианту (Option C из ADR или статус-кво).
2. **Реализация.** Заменить дублирующие правила переиспользованием; удалить
   `LoopCondP*`.
3. **Регресс.** `cargo test --features lsp -- --test-threads=1` — все 1438 тестов
   и doc-тесты зелёные; отдельно проверить `if_while_for`, `syntax_simple`,
   примеры с `loop { … }` и `loop ({…}) { … }`.
4. **Документация.** В `CLAUDE.md` зафиксировать намеренное разделение
   `Condition`/`Expression` (разная семантика `=`); обновить комментарии в
   `grammar.lalrpop`.

## Проверки (ожидаемые)

- A1–A5 из анализа. Регресс = 0 (R4), инвариант `=`/`==` (R1), дизамбигуация
  `{` (R3), нет новых LR(1)-конфликтов (R5).

## Заметки по риску

Если PoC (шаг 1) показывает нерешаемые LR(1)-конфликты — реализацию **не**
форсировать: задокументировать результат, вернуть фичу на пересмотр объёма
(возможен Option C или закрытие как «нецелесообразно»). Не ломать инвариант
`=`/`==` ради устранения дублирования.
