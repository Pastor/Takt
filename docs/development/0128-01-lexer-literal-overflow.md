# Задача 0128-01: Диагностика вместо паники на числовом литерале больше `i64::MAX`

> Фича: [../features/0128-lexer-literal-overflow.md](../features/0128-lexer-literal-overflow.md) · ADR: [../adr/0128-lexer-literal-overflow.md](../adr/0128-lexer-literal-overflow.md) · анализ: [../analyze/0128-lexer-literal-overflow.md](../analyze/0128-lexer-literal-overflow.md)

## Что было

Две точки разбора числа в `takt-lang/src/parser/lexer.rs` вызывали `unwrap()`:

```rust
let hex_val = i64::from_str_radix(&hex, 16).unwrap();   // шестнадцатеричная ветвь
let mut n = i64::from_str(&n_clean).unwrap();           // десятичная ветвь
```

Литерал шире `i64` ронял компилятор трассой паники (`rc = 101`). Ввод при этом
осмысленный: `0xFFFFFFFFFFFFFFFF` — полная маска типа `[bit;64]`.

## Что сделано

1. **Новый вариант ошибки** `LexicalError::NumberOutOfRange(Location, String)` с
   кодом **`LE-009`**; добавлены армы в `loc()` и `code()`. Сообщение называет и
   сам литерал, и границы: `числовой литерал '…' вне диапазона i64 [-…, …]`.
2. **Оба `unwrap()` заменены** конструкцией `let Ok(..) = .. else { return Err(..) }`
   — с позицией, указывающей на **начало литерала**, и его текстом.
3. **Реестр** `docs/diagnostics/README.md` — строка `LE-009` со ссылкой на место
   эмиссии (гейт `check-diagnostic-codes.sh` требует соответствия).
4. **Документация** (правила 24–26): строка в сводной таблице приложения
   «Ошибки и предупреждения», подробный разбор `LE-009` с примером и выводом,
   строка в блоке «Частые ошибки» раздела «Лексика».
5. **Версия языка** `0.5.0 → 0.6.0` (правило 22: первая закрытая фича цикла;
   добавлена диагностика — наблюдаемое поведение изменилось). Правлены оба места:
   `takt_lang::LANGUAGE_VERSION` и канон README, гейт согласованности зелёный.

## Почему граница осталась на `i64`

Расширение представления (`i128`, беззнаковый шаблон в hex-ветви) — **сквозная**
правка от токена до пяти генераторов, каждый со своей печатью чисел. ADR
отверг оба варианта: цель фичи — убрать отказ инструмента, а не переопределить
представление чисел. Незаписуемая полная маска `[bit;64]` признана ограничением и
вынесена кандидатом.
