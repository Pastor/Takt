# Задача 0300-01: Точная десятичная свёртка и `SE-114`

> Фича: [../features/0300-fractional-init-arithmetic.md](../features/0300-fractional-init-arithmetic.md) · ADR: [../adr/0300-fractional-init-arithmetic.md](../adr/0300-fractional-init-arithmetic.md) · анализ: [../analyze/0300-fractional-init-arithmetic.md](../analyze/0300-fractional-init-arithmetic.md)

## Что было

Константный вычислитель отвергал **любую** арифметику над дробными, а
`declaration.rs` на несвёрнутом инициализаторе делал `continue` — «невычислимое
оставляем как есть». В результате один вход давал три значения: `0.0` у
эталона, `3.0` у целей `c`/`rust`, `0.1875` в поле `q(4, 4)` цели `c`, плюс
молчаливую потерю у `st`.

## Что сделано

**1. Точная десятичная арифметика** — `semantic/const_eval/decimal.rs`. Пара
«мантисса `i128` + число знаков после запятой»; `+`, `-`, `*`, приём целого
операнда. Переполнение и масштаб выше `MAX_SCALE` — **отказ**, а не обёртка и
не потеря точности.

⚠️ **Не `f64`:** двоичная плавающая точка дала бы `0.1 + 0.2 ≠ 0.3`, то есть
свёрнутое значение разошлось бы с эталоном — ровно то, ради устранения чего
фича заведена.

**2. Ветвь дробных в `const_eval` переписана.** Пара «дробное с дробным» и
смешанная «дробное с целым» сворачиваются; деление и прочее округляемое
отвергаются с прежним доводом. Смешанную пару включили сознательно:
`1 + 3.14` точно так же точно, и отвергать за форму записи не за что (вывод
типов и так даёт `Rational`).

**3. Свёрнутый литерал понижается в q-представление** —
`declaration::lower_folded_fixed`, зовущий **тот же** `lower_fixed_literal`, что
и понижение авторского литерала.

⚠️ **Без этого шага правка была бы наполовину сделана**: понижение литералов
(0061/0096) идёт при **выводе типов**, то есть до свёртки, и `1.0 + 2.0` ему не
литерал — оно проходило мимо. Проба после первой правки: эталон `3.0`, цель `c`
`model->s = 3.0;` в поле `int8_t` — то есть `3`, а надо `48`.

**4. `SE-114`** — `declaration::unfoldable_fractional`: дробное объявление,
инициализатор которого содержит **арифметику** и не свернулся.

⚠️ **Первая редакция была шире и ломала чужую фичу.** Она отвергала любой
несвёрнутый дробный инициализатор — и отвергла `var v := 3 as q(4, 4);`, вход,
на котором эталон и цель **уже согласны** (48 у обоих, работа фичи 0205).
Поймали это её сторожа (`cast_in_initializer_tests`), а не чтение кода. Отказ
сужен до арифметики; граница закреплена тестом рядом с правилом.

**5. Документ.** Реестр диагностик и приложение «Ошибки и предупреждения»
получили `SE-114`; языковой раздел «Типы» — подраздел «Дробная арифметика в
инициализаторе» с примером и контрпримером плюс строку в «Частые ошибки»
(правило 26).

**6. Тесты, закреплявшие прежнее правило, переписаны:**
`const_eval_tests::rational_arithmetic_is_rejected_with_the_reason` → три
теста (точное сворачивается, смешанное сворачивается, деление отвергается);
`type_inference::tests::infer_type_from_add_rational` заработал сам —
`1 + 3.14` теперь сворачивается, а тип прежний.

## Проверки

```sh
cargo test --all-features        # 3190 тестов (+11), 0 провалов
cargo run --bin takt-sim -- probe.takt -n 1      # f=3.0000, s=3.0000
cargo run --bin taktc -- compile probe.takt -t c # model->f = 3.0; model->s = 48;
./scripts/precheck.sh            # код возврата 0
```

Соответствие условиям анализа: R1 — A1/A2, R2 — контрольная пара в сторожах,
R3 — A3, R4 — A4, R5 — A5.

Версия крейта `takt-lang`: `0.41.0` → `0.42.0`. Версия языка **не растёт** —
цикл `0.10.0` открыт фичей 0243 (правило 22, накопление).
