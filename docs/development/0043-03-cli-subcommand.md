# Задача 0043-03: CLI-подкоманда `lamc address-map --emit`

> Фича: [../features/0043-address-map-export.md](../features/0043-address-map-export.md) · ADR: [../adr/0043-address-map-export.md](../adr/0043-address-map-export.md) · анализ: [../analyze/0043-address-map-export.md](../analyze/0043-address-map-export.md) · тест-план: [../tests/0043-address-map-export.md](../tests/0043-address-map-export.md)

## Что было

*Реальное состояние `grammar/src/bin/lamc.rs` на 2026-07-15 (проверено чтением
и запуском бинаря).*

- **Подкоманд ровно две:** `fmt` (диспетчеризация — строка 462) и `compile`
  (474). Любое иное первое слово → «Ошибка: неизвестная команда … Используйте
  'compile' или 'fmt'» (475–481). То есть `lamc address-map …` сегодня падает —
  **имя свободно**, и его занятие ничего не отнимает (обратная совместимость,
  правило 11).
- **Флаги `compile`** (`parse_compile_args`, 162–252): `-t/--target` (176),
  `-o/--output` (183), `-I/--include-dirs` (190) + слитная форма `-I<путь>` (198),
  `-v/--verbose` (201), `-q/--quiet` (204), `--guard-enable`/`--guard-disable`
  (207/210), `--address-map` (213). Взаимоисключение `-v`/`-q` — 232.
- **Цели:** `c` (588), `c-hal` (552), `plantuml` (622); неизвестная → выход с
  кодом 1 (649).
- **Разбор внешней карты уже написан и живёт в `main`** (506–530): чтение файла,
  `grammar::parse_address_map`, печать `AM-*` и `process::exit(1)`. Пере-использовать
  его подкоманде **нельзя без выноса** — он вшит в тело `main`. Отсюда action item
  ADR про дублирование разбора.
- **Прецедент формы:** `fmt` — уже подкоманда, не являющаяся компиляцией; у неё
  свой `parse_fmt_args` (274) с юнит-тестами рядом (666–707) и свой
  исполнитель `run_fmt` (321), возвращающий код процесса. Это образец для
  `address-map` (ADR, обоснование формы CLI п. 2).
- **Диагностики сейчас идут в stderr** (`eprintln!` везде), stdout занят только
  выводом `fmt --stdin` (337). Для машиночитаемой выгрузки это **удачно**: канал
  свободен (R9).
- **Замечено попутно (не чинится здесь):** сообщение о неизвестной цели (651)
  гласит «Поддерживается: c, plantuml» — цель **`c-hal` пропущена**. Мелкий
  дефект справки, оставшийся от 0020; вынесен кандидатом в анализе.

## Что сделано

> **Планируется (разработка не начата).** Ниже — план задачи по ADR 0043 и
> анализу; заполняется фактом по мере реализации.

1. **Подкоманда** (R1) — `lamc address-map [-I …] [--address-map FILE]
   [--emit map|json] [-o FILE] <input.lam>`; диспетчеризация в `main` рядом с
   `fmt` (462) и `compile` (474). Форма выбрана ADR (подкоманда, **не** флаг
   `compile --emit-address-map`): экспорт не порождает целевой код, у `compile`
   вид результата уже выбирается `-t`, и ортогональный `--emit` создал бы
   бессмысленную матрицу (`-t c --emit json`).

2. **`parse_address_map_args`** — по образцу `parse_fmt_args` (274), с
   юнит-тестами в том же модуле (образец — 666–707). Флаги: `-I` (включая
   слитную форму), `--address-map`, `--emit` (по умолчанию `map`), `-o`,
   `-q`/`-v`. **Не** брать `-t` и `--guard-*` — подкоманде они бессмысленны.

3. **Вынести общий разбор** (ADR, action item; риск Р4) — чтение и разбор
   внешней карты сейчас вшиты в `main` (506–530). Вынести в функцию, вызываемую
   и `compile`, и `address-map`; поведение `compile` при этом обязано остаться
   **точно прежним** (те же коды `AM-*`, тот же выход 1). Также переиспользовать
   `split_include_dirs` (105).

4. **Исполнитель `run_address_map`** — возвращает код процесса (как `run_fmt`,
   321): разбирает исходник, строит модель, зовёт `resolve_addresses`
   (`address_map.rs:409`), затем эмиттер из 0043-01/0043-02.

5. **Разделение каналов** (R9) — выгрузка **только в stdout** (или в файл при
   `-o`), диагностики SE-050/051/052 и `AM-*` — **только в stderr**. Инвариант:
   stdout обязан целиком разбираться `parse_address_map` даже при наличии
   предупреждений (T16) — иначе круговой рейс ломается на любой модели с
   оверлеем.

6. **Коды возврата** — `0` — успех; `1` — ошибка (в т. ч. **SE-052**: достижимый
   порт без адреса, как в `c-hal`; неизвестный `--emit`; битая входная карта).
   Неизвестный формат обязан дать **внятную ошибку**, а не пустой вывод (К4):
   `--emit svd` — вероятный запрос, а SVD отклонён ADR.

7. **Справка** (`print_usage`, 417) — добавить подкоманду `address-map`, её флаги
   и примеры. Правило 15: синхронизировать `README.md`.

| Функциональность | Статус |
|---|---|
| `grammar` / `bin/lamc.rs` | планируется (после 0043-01, 0043-02) |
| `compile` (`c`/`c-hal`/`plantuml`) | планируется — регресс = 0 при выносе общего разбора |
| `fmt` | **н/п** — не затрагивается |
| Язык `.lam` | **н/п** — язык не меняется (0.2.0) |
| `simulation`, LSP | **н/п** — не затронуты |

## Проверки

> **Планируется (разработка не начата).**

- `cargo build --bin lamc`; `cargo test -- --test-threads=1`;
  `cargo test --features lsp -- --test-threads=1`; `./scripts/precheck.sh`
  (правило 5).
- Соответствие анализу: **R1** (подкоманда и флаги), **R9** (диагностики в
  stderr, stdout чист), **R10** (регресс = 0), **R11** (неизвестный формат).
- Тест-план: **T1** (разбор флагов), **T15** (SE-052 → ненулевой код),
  **T16/T17** (каналы; SE-050/SE-051), **T18** (`--emit svd` → ошибка), **T19**
  (`-o` в файл), **T22** (регресс `compile`/`fmt`).
- **Ключевая проверка выноса разбора:** до и после правки прогнать `compile
  --address-map` на битой карте (К5) и убедиться, что код диагностики и код
  возврата не изменились — вынос общего кода не должен задеть закрытую фичу 0020.
- Живая проверка (правило 5): `lamc address-map --emit map examples/elevator_mini.lam
  --address-map <карта на 44 порта>` → выгрузка, принимаемая обратно
  `lamc compile -t c-hal --address-map <выгрузка>`.
