# Задача 0045-07: Тестбенч и сверка с симулятором Lam

> Фича: [../features/0045-sv-backend.md](../features/0045-sv-backend.md) · ADR: [../adr/0045-sv-backend.md](../adr/0045-sv-backend.md) · анализ: [../analyze/0045-05-fsm-time-reset.md](../analyze/0045-05-fsm-time-reset.md), [0045-02](../analyze/0045-02-validation.md) · тест-план: [../tests/0045-sv-backend.md](../tests/0045-sv-backend.md)
>
> Требования: **R7**, **R12**. Критерии: **A8**, **A10**.

## Что было

### Образец: `simulation/tests/conformance_c_tests.rs`

Автосверка симулятора с порождённым C (критерий A8 фичи 0025, задача 0025-07).
Прочитан целиком; устройство:

- фикстура `tests/data/eval/conformance_u8.lam` (строка 45);
- `simulate()` — `parse` → `construct_model` → `build_unit` → `MAX_TICKS` тактов;
- порождает C тем же `lamc`, компилирует **настоящим** `cc`, запускает, сверяет
  значения (`CHECKED`, строка 58: `wrapped`, `truncated`, `divided`, `shifted`,
  `mode`, `flag`);
- `cc_available()` (строка 69) — **мягкая деградация**: нет компилятора → тест
  пропускается.

**Три ограничения, зафиксированные в заголовке модуля** (строки 16-42) — все три
для SV снимаются или ослабевают:

| Ограничение C-сверки | Причина | **Для SV** |
|---|---|---|
| **Сверяются установившиеся значения, а не потактовая трасса** (строки 30-42) | C заводит **синтетическое `INIT`** на каждый уровень; тело исполняется на **3-м** такте, симулятор — на **1-м**. «Значения совпадают, расходится **моментность**» | **Снимается.** У SV `INIT`-состояния **нет**; сдвиг = 0 с обеих сторон → **потактовая сверка возможна** (проверено пробой) |
| **Область сужена до `Integer`/`Enum`/`Bool`** (строки 16-22) | C дефектен на `Rational`/`Bit`/`Array` (фича 0029): `Bit` → `int`, `Rational` → `float`. «Сверяться с дефектным эталоном — значит узаконить его дефекты» | **Ослабевает: `Bit` включается.** В SV `bit` → `logic` — эталон пригоден. `Rational` — **запрещён** (`SV-003`), сверять нечего |
| **Фикстура обёрнута в `model`** (строки 24-28) | для **одиночной** корневой модели C не эмитит `typedef` → **не компилируется** (дефект, фича 0026) | **Не применимо.** У SV своя эмиссия модуля; проблемы не существует. Фикстуру можно переиспользовать как есть |

### Что уже проверено фактически (проба тестбенча)

Механика опробована **до** начала разработки:

```
$ verilator --binary --timing --top-module tb_lift tb_lift.sv \
            stacker_lift_controller.sv -o simtb
$ ./obj_dir/simtb
после сброса (до 1-го такта): state=0 cmd_fork=0
такт 1: state=0 cmd_fork=0 lift_done=0
такт 2: state=0 cmd_fork=0 lift_done=0
такт 3: state=1 cmd_fork=1 lift_done=0
такт 5: state=2 cmd_fork=0 lift_done=1
такт 7: state=0 cmd_fork=0 lift_done=1
```

**Доказано:**

1. **Сдвиг = 0** — сразу после сброса автомат в стартовом `LIFT_IDLE` (`state=0`) с
   исполненным `enter` (`cmd_fork=0`); такт 1 исполняет **тело**. Контракт
   [ADR 0033](../adr/0033-init-tick-alignment.md) выполняется — **без** закрытия
   фичи 0033.
2. **Механика работает:** `verilator --binary --timing` собирает и прогоняет
   тестбенч с потактовой печатью (сборка ~5 с).

> **Оговорка о добросовестности.** В **пробном** тестбенче воздействия поданы
> после фронта, поэтому реакция видна через такт — артефакт пробы, а не модуля.
> В этой задаче воздействия подаются от трассы симулятора (см. ниже).

### Инструменты (проверено)

Verilator **5.050**, yosys **0.67+post** — установлены (`brew`); изначально в
среде отсутствовали.

## Что сделано

> **Планируется (разработка не начата).**

План — `simulation/tests/conformance_sv_tests.rs` (образец —
`conformance_c_tests.rs`) + генерация тестбенча.

1. **Генерация тестбенча.** Открытый вопрос (см. ниже): порождать `tb_*.sv`
   генератором (`lamc -t sv --testbench`?) или писать в тесте на Rust. Предпочтение
   — **в тесте**: тестбенч — принадлежность проверки, а не продукта; генератор не
   должен уметь то, что нужно только тестам.
2. **Схема сверки:**
   - `simulate()` — как в `conformance_c_tests.rs`: `build_unit` + N тактов, но с
     сохранением **потактовой** трассы (не только финальных значений);
   - `lamc -t sv` → `verilator --binary --timing` → прогон → разбор потактовой
     печати;
   - сверка **трасс потактово** (A10/T33) — то, чего C-сверка позволить не может.
3. **Подача воздействий.** Входные порты должны меняться **одинаково** с обеих
   сторон. Источник истины — трасса симулятора (`--sim-file`/`Unit::variable`);
   тестбенч подаёт те же значения на тех же тактах. **Подавать до фронта**, иначе
   получится артефакт пробного тестбенча.
4. **Мягкая деградация** — по образцу `cc_available()` (строка 69):
   `verilator_available()`; нет инструмента → тест пропускается. В CI —
   обязателен (задача 0045-02).
5. **Область сверки:** `Integer`, `Enum`, `Bool` **+ `Bit`** (расширение против
   C-сверки). `Rational` — не применимо (`SV-003`). `Array` — проверить пробой
   (в SV массив настоящий, дефекта 0029 нет; вероятно, тоже включается).
6. **Тестбенчи для T20/T21/T22** (сдвиг = 0 на глубине 1, 2, 3) — на тех же формах,
   что пробы ADR 0033.

**Статус по обратной функциональности (правило 11):**

| Функциональность | Работа |
|---|---|
| `conformance_c_tests.rs` | **н/п** — не трогается; служит образцом |
| Симулятор | **н/п** — только эталон; ни строчки не меняется |
| Фикстура `conformance_u8.lam` | **переиспользуется** как есть (обёртка в `model` для SV не нужна, но и не мешает) |
| Фича 0033 | **н/п** — не зависимость; сверка «SV ↔ симулятор» сходится **сегодня** |
| `simulation/tests/conformance_sv_tests.rs` | **новый** |

## Проверки

> **Планируется (разработка не начата).**

- **T32 (R7/A10):** значения совпадают с симулятором.
- **T33 (R7/A10) — потактовая сверка:** трассы совпадают **потактово**. Это
  **главное отличие** от C-сверки, вынужденной сверять только установившиеся
  значения (`conformance_c_tests.rs`, строки 30-42). Возможно потому, что сдвиг = 0
  с обеих сторон.
- **T34 (R5/A10):** **`Bit` включён** в область сверки (в C-сверке исключён из-за
  дефекта 0029 `Bit` → `int`).
- **T20/T21/T22 (R7/A8):** сдвиг = 0 на глубине 1, 2, 3 — тело исполняется на
  **такте 1** (C сегодня: 2/3/4). **Проба на глубине 1 пройдена вручную.**
- **T11:** нет Verilator → тест пропускается с сообщением, не падает.
- Сперва **зонд** (снять реальную трассу), затем assertions против захваченного —
  **не угадывать** значения и такты (`CLAUDE.md`; урок 0025: тесты **на значения**,
  а не на факт перехода — именно отсутствие этого слоя дало восемь дефектов при
  зелёных тестах).
- `cargo test --test conformance_sv_tests -- --test-threads=1` — зелёный.

## Открытые вопросы (решаются в этой задаче)

- **Кто порождает тестбенч** — генератор (`--testbench`) или тест? Предпочтение —
  тест (тестбенч не входит в продукт). Если заказчик захочет тестбенч как
  артефакт — отдельная фича.
- **Разбор вывода тестбенча.** Печать `$display` → парсинг в Rust. Формат
  зафиксировать один раз (образец — потактовая печать пробы).
- **Время прогона.** `verilator --binary` собирает C++ ~5 с на модуль. При
  тестбенче на каждую фикстуру прогон тестов заметно удлинится — измерить; при
  необходимости вынести в отдельный шаг CI (не в `cargo test`).
- **Тройная сверка SV ↔ C ↔ симулятор** — **вне этой задачи**: до закрытия 0033
  C сдвинут на глубину, сверка с ним невозможна. После закрытия 0033 станет
  возможна **без правок** в SV. Кандидат «общий каркас сверки бэкендов» —
  после 0041 и 0045.
