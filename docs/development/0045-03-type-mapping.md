# Задача 0045-03: Отображение типов Lam → SystemVerilog + диагностики

> Фича: [../features/0045-sv-backend.md](../features/0045-sv-backend.md) · ADR: [../adr/0045-sv-backend.md](../adr/0045-sv-backend.md) (вопрос 4) · анализ: [../analyze/0045-03-type-mapping.md](../analyze/0045-03-type-mapping.md) · тест-план: [../tests/0045-sv-backend.md](../tests/0045-sv-backend.md)
>
> Требования: **R4**, **R5**. Критерии: **A5**, **A6**, **A7**, **A11**.

## Что было

### Вход: `TypeNode`

`semantic/type_node.rs:496`, помечен **`#[non_exhaustive]`** (строка 495).
Варианты: `Bit`, `Bool`, `Rational`, `Array(u16, Box<TypeNode>)`, `Enum(String)`,
`Struct(String)`, `Integer { bits: u8, signed: bool }` + служебные (`Inference`,
`Address`, `Unsupported`, `Unit`, `Builtin*`).

### Как это делает C — и почему повторять нельзя

`get_c_type` (`generator/c/mod.rs:150`):

```rust
pub fn get_c_type(typ: &TypeNode, model: &ModelNode) -> Option<String>
```

**Возвращает `Option`** — на непокрытом узле отдаёт `None` **молча**. Три дефекта
(кандидат/ADR 0029, статус фичи — **РАЗРАБОТКА, ЗАБЛОКИРОВАНА** фичей 0026):

1. `Array(size, elem)` → `uint{size}_t`, где `size` — **число элементов**, а не
   разрядность: `[u8; 4]` → невалидный `uint4_t`; при этом переменная-массив
   **молча исчезает** из структуры (проба кандидата 0029: `var data: [u8; 4];` →
   в `arr.h` только `int flag;`, **без диагностики**) — класс «тихий пропуск»
   (фичи 0025, 0028, 0029);
2. `Bit` → `int` (32-битный знаковый) вместо 1-битной семантики;
3. `Rational` → `float` (f32), тогда как симулятор считает в f64
   (`eval/mod.rs:73-75`) → тихое расхождение точности.

Именно из-за (2) и (3) сверка `conformance_c_tests.rs` **сужена** до
`Integer`/`Enum`/`Bool` (комментарий модуля, строки 16-22): «сверяться с дефектным
эталоном — значит узаконить его дефекты».

### Что уже проверено фактически

- Префикс **`SV-` свободен** (`grep` по `grammar/src`: заняты `SE-*` — 84
  вхождения, `CC-*` — 23, `AM-*` — 11, `PU-*` — 1; `ST-` резервирует 0041).
- **`float` в корпусе не используется**: `grep` по `examples/*.lam` — **0
  вхождений** → цена запрета `SV-003` сегодня **нулевая**.
- **`real` не синтезируется**, и это ловится **только** yosys:
  `verilator --lint-only -Wall` принял молча (код 0); `yosys read_verilog -sv` →
  `ERROR: syntax error, unexpected TOK_REAL` (код 1).
- `typedef enum logic [1:0] {…}` принимается **и** Verilator, **и** yosys
  (проба целевого модуля: линт чист, синтез — 22 ячейки).

### Связь с 0029 — урок, не зависимость

`get_c_type` приватна для C-бэкенда; SV её **не вызывает**. Общий слой отображения
типов **не заводится сознательно** (ADR 0045 вопрос 4; ADR 0041 вопрос 2 —
решено независимо и одинаково): три цели = три несовместимые системы типов
(`uint8_t` / `USINT` / `logic [7:0]`). Привязка к 0029 была бы вредна вдвойне —
она сама **ЗАБЛОКИРОВАНА** фичей 0026.

## Что сделано

> **Планируется (разработка не начата).**

План — `generator/sv/sv_type.rs`:

```rust
fn get_sv_type(typ: &TypeNode, model: &ModelNode) -> Result<String, Diagnostic>
```

**Ключевое отличие от C: `Result`, а не `Option`** — на непокрытом узле
**ошибка**, а не молчание (R4). Прямое следствие уроков 0025/0028/0029.

Нормативная таблица `T1..T14` — [анализ 0045-03](../analyze/0045-03-type-mapping.md).
Существенное:

| `TypeNode` | **SV** | Против C |
|---|---|---|
| `Bit` | **`logic`** | C: `int` (32 бита) — **дефект 2 фичи 0029**. `logic` — **идеальное** соответствие: один провод |
| `Integer{N,false}` | `logic [N-1:0]` | разрядность **буквальна**; произвольная N бесплатна (C округляет до `uint{8,16,32,64}_t`) |
| `Integer{N,true}` | `logic signed [N-1:0]` | `signed` обязателен: меняет семантику сравнений/сдвигов |
| `Rational` | **ошибка `SV-003`** | C: `float` (f32 против f64) — **дефект 3**. В синтезируемом RTL FP **не существует** |
| `Array(N, T)` | `<T> name [0:N-1]` | C: `uint{N}_t`, переменная **молча теряется** — **дефект 1** |
| `Enum(name)` | `typedef enum logic [W-1:0] {…}`, W = ⌈log₂(вариантов)⌉ | имена видны в осциллограмме — критично для отладки RTL |
| `Struct(name)` | `typedef struct packed {…}` | поле-массив → `SV-004` |
| `Inference`/`Unsupported`/`Address`/`Builtin*` | **ошибка `SV-002`** | C: `None` **молча** |

**Вынужденная ветка `_`.** `TypeNode` — `#[non_exhaustive]` (`type_node.rs:495`),
поэтому `match` обязан её иметь (коллизия из процессного бэклога:
«`#[non_exhaustive]` против запрета `_ =>`»). Ветка возвращает **`SV-002`
(ошибку)**, а не `None` — ровно как `eval::coerce_to_type` (исключение,
зафиксированное ADR 0025 по той же причине).

**Диагностики этой задачи:**

| Код | Смысл |
|---|---|
| `SV-002` | непокрытый узел `TypeNode` — никакого тихого пропуска |
| `SV-003` | `Rational`/`float` в синтезируемом RTL не существует |
| `SV-004` | недопустимая форма типа: `Array(0,T)`, поле-массив в `struct packed`, `Enum` без вариантов, `Integer{0}` |

**Область запрета `SV-003` (уточнение):** на **типы** переменных, портов, полей.
Константные выражения времени компиляции (свёртка `const`) под запрет **не
подпадают** — если `float`-константа участвует только в вычислении целого на этапе
компиляции, в RTL её нет.

**Статус по обратной функциональности (правило 11):**

| Функциональность | Работа |
|---|---|
| `get_c_type` и цель `c` | **н/п** — не вызывается, не меняется |
| `TypeNode` | **н/п** — не меняется (0029 тоже его не трогает) |
| Общий слой типов | **н/п** — сознательно не заводится |
| Язык `.lam` | **н/п** |
| `generator/sv/sv_type.rs` | **новый** |

## Проверки

> **Планируется (разработка не начата).**

- **T12 (R5/A5):** юнит-тесты `get_sv_type` — **по строке на вариант** `TypeNode`
  (14 шт., T1..T14).
- **T16 (R4/A5):** тест на вынужденную ветку `_` — возвращает **`Err`**, не
  `Ok`/`None`.
- **T13 (A7):** `stacker.lam` → `input logic task_valid` (**не** `int`).
  **Контрпример к дефекту 2 фичи 0029.**
- **T14 (A6):** фикстура `var data: [u8; 4];` — **тот же вход**, что в пробе
  кандидата 0029, где C молча теряет переменную → в SV присутствует
  `logic [7:0] data [0:3];`. **Контрпример к дефекту 1 фичи 0029.**
- **T15:** `var x: u12;` → `logic [11:0] x;` (в RTL машинного слова нет).
- **T17:** `typedef enum logic [W-1:0]` для состояний `stacker.lam`.
- **Контрпримеры** (`grammar/tests/data/sv/invalid/*.lam`), тест на **код**
  диагностики, а не на текст:
  | Фикстура | Код |
  |---|---|
  | `var x: float;` | `SV-003` |
  | `struct { data: [u8; 4] }` | `SV-004` |
  | непокрытый узел | `SV-002` |
- **T7/T8:** порождённый SV проходит **оба гейта** (Verilator + yosys). Для
  `SV-003` важно: если бы запрет не работал и `real` попал в вывод — **Verilator
  бы это пропустил**, поймал бы только yosys (проверено).
- **Методика (`CLAUDE.md`):** сперва **зонд** реального вывода, затем assertions
  против захваченного — **не угадывать** строки, ширины, имена.
- `cargo test -- --test-threads=1` — зелёный.
