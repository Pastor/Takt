# Задача 0045-03: Отображение типов Lam → SystemVerilog + диагностики

> Фича: [../features/0045-sv-backend.md](../features/0045-sv-backend.md) · ADR: [../adr/0045-sv-backend.md](../adr/0045-sv-backend.md) (вопрос 4) · анализ: [../analyze/0045-03-type-mapping.md](../analyze/0045-03-type-mapping.md) · тест-план: [../tests/0045-sv-backend.md](../tests/0045-sv-backend.md)
>
> Требования: **R4**, **R5**. Критерии: **A5**, **A6**, **A7**, **A11**.

## Что было

### Вход: `TypeNode`

`semantic/type_node.rs:496`, помечен **`#[non_exhaustive]`** (строка 495).
Варианты: `Bit`, `Bool`, `Rational`, `Array(u16, Box<TypeNode>)`, `Enum(String)`,
`Struct(String)`, `Integer { bits: u8, signed: bool }` + служебные (`Inference`,
`Address`, `Unsupported`, `Unit`, `Builtin*`).

### Как это делает C — и почему повторять нельзя

`get_c_type` (`generator/c/mod.rs:150`):

```rust
pub fn get_c_type(typ: &TypeNode, model: &ModelNode) -> Option<String>
```

**Возвращает `Option`** — на непокрытом узле отдаёт `None` **молча**. Три дефекта
(кандидат/ADR 0029, статус фичи — **РАЗРАБОТКА, ЗАБЛОКИРОВАНА** фичей 0026):

1. `Array(size, elem)` → `uint{size}_t`, где `size` — **число элементов**, а не
   разрядность: `[u8; 4]` → невалидный `uint4_t`; при этом переменная-массив
   **молча исчезает** из структуры (проба кандидата 0029: `var data: [u8; 4];` →
   в `arr.h` только `int flag;`, **без диагностики**) — класс «тихий пропуск»
   (фичи 0025, 0028, 0029);
2. `Bit` → `int` (32-битный знаковый) вместо 1-битной семантики;
3. `Rational` → `float` (f32), тогда как симулятор считает в f64
   (`eval/mod.rs:73-75`) → тихое расхождение точности.

Именно из-за (2) и (3) сверка `conformance_c_tests.rs` **сужена** до
`Integer`/`Enum`/`Bool` (комментарий модуля, строки 16-22): «сверяться с дефектным
эталоном — значит узаконить его дефекты».

### Что уже проверено фактически

- Префикс **`SV-` свободен** (`grep` по `grammar/src`: заняты `SE-*` — 84
  вхождения, `CC-*` — 23, `AM-*` — 11, `PU-*` — 1; `ST-` резервирует 0041).
- **`float` в корпусе не используется**: `grep` по `examples/*.lam` — **0
  вхождений** → цена запрета `SV-003` сегодня **нулевая**.
- **`real` не синтезируется**, и это ловится **только** yosys:
  `verilator --lint-only -Wall` принял молча (код 0); `yosys read_verilog -sv` →
  `ERROR: syntax error, unexpected TOK_REAL` (код 1).
- `typedef enum logic [1:0] {…}` принимается **и** Verilator, **и** yosys
  (проба целевого модуля: линт чист, синтез — 22 ячейки).

### Связь с 0029 — урок, не зависимость

`get_c_type` приватна для C-бэкенда; SV её **не вызывает**. Общий слой отображения
типов **не заводится сознательно** (ADR 0045 вопрос 4; ADR 0041 вопрос 2 —
решено независимо и одинаково): три цели = три несовместимые системы типов
(`uint8_t` / `USINT` / `logic [7:0]`). Привязка к 0029 была бы вредна вдвойне —
она сама **ЗАБЛОКИРОВАНА** фичей 0026.

## Что сделано

> **Реализовано** (2026-07-16). План выполнен; **три отличия**, каждое —
> результат пробы, опровергшей посылку плана. См. «Отличия от плана».

План — `generator/sv/sv_type.rs`:

```rust
fn get_sv_type(typ: &TypeNode, model: &ModelNode) -> Result<String, Diagnostic>
```

**Ключевое отличие от C: `Result`, а не `Option`** — на непокрытом узле
**ошибка**, а не молчание (R4). Прямое следствие уроков 0025/0028/0029.

Нормативная таблица `T1..T14` — [анализ 0045-03](../analyze/0045-03-type-mapping.md).
Существенное:

| `TypeNode` | **SV** | Против C |
|---|---|---|
| `Bit` | **`logic`** | C: `int` (32 бита) — **дефект 2 фичи 0029**. `logic` — **идеальное** соответствие: один провод |
| `Integer{N,false}` | `logic [N-1:0]` | разрядность **буквальна**; произвольная N бесплатна (C округляет до `uint{8,16,32,64}_t`) |
| `Integer{N,true}` | `logic signed [N-1:0]` | `signed` обязателен: меняет семантику сравнений/сдвигов |
| `Rational` | **ошибка `SV-003`** | C: `float` (f32 против f64) — **дефект 3**. В синтезируемом RTL FP **не существует** |
| `Array(N, T)` | `<T> name [0:N-1]` | C: `uint{N}_t`, переменная **молча теряется** — **дефект 1** |
| `Enum(name)` | `typedef enum logic [W-1:0] {…}`, W = ⌈log₂(вариантов)⌉ | имена видны в осциллограмме — критично для отладки RTL |
| `Struct(name)` | `typedef struct packed {…}` | поле-массив → `SV-004` |
| `Inference`/`Unsupported`/`Address`/`Builtin*` | **ошибка `SV-002`** | C: `None` **молча** |

**Вынужденная ветка `_`.** `TypeNode` — `#[non_exhaustive]` (`type_node.rs:495`),
поэтому `match` обязан её иметь (коллизия из процессного бэклога:
«`#[non_exhaustive]` против запрета `_ =>`»). Ветка возвращает **`SV-002`
(ошибку)**, а не `None` — ровно как `eval::coerce_to_type` (исключение,
зафиксированное ADR 0025 по той же причине).

**Диагностики этой задачи:**

| Код | Смысл |
|---|---|
| `SV-002` | непокрытый узел `TypeNode` — никакого тихого пропуска |
| `SV-003` | `Rational`/`float` в синтезируемом RTL не существует |
| `SV-004` | недопустимая форма типа: `Array(0,T)`, поле-массив в `struct packed`, `Enum` без вариантов, `Integer{0}` |

**Область запрета `SV-003` (уточнение):** на **типы** переменных, портов, полей.
Константные выражения времени компиляции (свёртка `const`) под запрет **не
подпадают** — если `float`-константа участвует только в вычислении целого на этапе
компиляции, в RTL её нет.

**Статус по обратной функциональности (правило 11):**

| Функциональность | Работа |
|---|---|
| `get_c_type` и цель `c` | **н/п** — не вызывается, не меняется |
| `TypeNode` | **н/п** — не меняется (0029 тоже его не трогает) |
| Общий слой типов | **н/п** — сознательно не заводится |
| Язык `.lam` | **н/п** |
| `generator/sv/sv_type.rs` | **новый** |

### Отличия от плана

#### 1. Ширина перечисления — по ДИАПАЗОНУ ЗНАЧЕНИЙ, а не по числу вариантов (дефект ADR)

Таблица **T11** ADR предписывала `W = ⌈log₂(вариантов)⌉, минимум 1`. **Проба
2026-07-16 опровергла это на реальном примере корпуса.** `enum Action { Idle =
670, … }` (`elevator.lam:121`) — два варианта, то есть по формуле ADR `logic
[0:0]`, — тогда как значение 670 требует десяти бит:

```text
%Error-ENUMITEMWIDTH: Enum value exceeds width of enum type (IEEE 1800-2023 6.19)
    typedef enum logic [0:0] { IDLE = 670, UP = 671 } action_e;
```

Это **тот же капкан, что уже поймал два соседних бэкенда**: ST (`CLAUDE.md`:
«Разрядность перечисления считается по диапазону вариантов, а не берётся
`USINT`, как предполагал ADR») и Rust (`#[repr(u8)]` не принял `Idle = 670`).
Здесь он пойман **до** написания кода — пробой, а не отладкой.

Реализовано `enum_width(variants) -> (ширина, знаковое)` — по диапазону. Важно,
что это **не «частный случай в дополнение к формуле ADR», а её замена одной
ветвью**: у перечисления состояний значения назначает сам генератор (`0..n-1`),
поэтому «по диапазону» вырождается ровно в `⌈log₂(n)⌉`. Отдельного правила для
состояний не требуется; закреплено тестом
`enum_width_of_sequential_states_matches_log2`.

⚠️ **Наблюдение для гейта:** `%Error-ENUMITEMWIDTH` выдал **Verilator**, а
**yosys синтезировал молча** (код 0). Ещё один случай той самой
взаимодополняемости, ради которой в 0045-02 заведены два гейта.

#### 2. Ветки `_ =>` нет — она была бы не сторожем, а его отключением

План требовал ветку `_ =>` с `SV-002`, полагая `#[non_exhaustive]` действующим.
Это неверно: **атрибут не действует внутри объявляющего крейта**, поэтому
исчерпывающий разбор `TypeNode` здесь возможен — и обязателен. Ветка `_`
проглотила бы новый вариант `TypeNode` **молча**, тогда как её отсутствие
заставляет добавление варианта валить сборку. Непокрытые узлы (`Inference`,
`Unsupported`, `Address`, `Builtin*`) перечислены **поимённо** и дают `SV-002`.
Так же устроен `rust_type` (0050-03).

#### 3. Тип возвращает `SvType { prefix, suffix }`, а не `String`

Синтаксис объявления SV **разрывен вокруг имени**: `logic [7:0] data [0:3];`, где
`logic [7:0]` — упакованная часть (ширина элемента), а `[0:3]` — распакованная
(число элементов). Склейка в одну строку дала бы `logic [7:0] [0:3] data` — то
есть **двумерный упакованный вектор**, другой тип с другой семантикой. Поэтому
возвращается пара с методом `declare(name)`. У `get_c_type` той же проблемы нет
лишь потому, что C-генератор массивы фактически теряет (дефект 0029).

### Не сделано в этой задаче (сознательно)

- **Коллизия имён Lam с ключевыми словами SystemVerilog** (`var reg: bit;` →
  `logic reg;`) реестром `SV-0xx` не предусмотрена и в плане не значится. Место
  ей — задача [0045-04](0045-04-module-ports.md), где пользовательские имена
  впервые попадают в вывод (там же живёт `SV-007` — коллизия с `clk`/`rst_n`,
  то есть ровно этот класс).
- **Проверка «поле-массив внутри `struct packed` → `SV-004`»** (один из четырёх
  случаев `SV-004`) остаётся за эмиссией структур: `sv_type` видит `Struct(name)`
  как имя типа и состава полей не разбирает. Сама форма `SV-004` заведена и
  протестирована на трёх остальных случаях.

## Проверки

> **Выполнено** (2026-07-16). Результаты ниже.

- **T12 (R5/A5): пройдено.** Юнит-тесты `sv_type` — по тесту на вариант
  `TypeNode` (T1…T14), 29 тестов модуля зелёные.
- **T16 (R4/A5): пройдено, но иначе, чем задумано.** Ветки `_` **нет** (см.
  «Отличия», п. 2), поэтому тест проверяет не её, а поимённое перечисление
  непокрытых узлов: `uncovered_nodes_are_sv002` прогоняет все семь
  (`Inference`, `Unsupported`, `Address`, `BuiltinString`, `BuiltinModel`,
  `BuiltinState`, `BuiltinNumeric`) и требует `Err` с кодом `SV-002`. Сторож от
  добавления нового варианта здесь — **компилятор**, а не тест.
- **T13 (A7): отложено до 0045-04.** Проверка требует порождённого текста
  модуля с портами, а порты — предмет следующей задачи. Отображение, на котором
  она стоит, закреплено юнит-тестом `bit_maps_to_logic_not_int` (включая
  `assert_ne!` против `int` — контрпример к дефекту 2 фичи 0029).
- **T14 (A6): пройдено на уровне отображения** —
  `array_maps_to_unpacked_array_not_uint4_t`: `[u8; 4]` → `logic [7:0] data
  [0:3]`, с `assert!` против `uint4_t`. **Контрпример к дефекту 1 фичи 0029.**
  Присутствие в порождённом файле проверяется в 0045-04.
- **T15: невыполнима как записана — посылка ложна.** Проба 2026-07-16: `u12`
  языком **не принимается вовсе** — `SE-034: Локальный тип 'u12' не найден`;
  конструктор типов строит только 8/16/32/64. Утверждение ADR «произвольная
  разрядность бесплатна» верно применительно к **отображению**, и это проверено
  напрямую на `TypeNode` (`arbitrary_width_integer_maps_without_rounding`:
  `Integer{12}` → `logic [11:0]`, `Integer{1}` → `logic [0:0]`). Появится ли
  `u12` в языке — вопрос к языку, а не к цели; отображение готово заранее.
- **T17: отложено до 0045-05** (перечисление состояний — предмет автомата).
  Формула ширины, на которой оно стоит, реализована и протестирована здесь.
- **Контрпримеры: пройдены как юнит-тесты, фикстур `.lam` не заводилось.**
  Отображение типов — чистая функция от `TypeNode`, и проверять её через
  исходник `.lam` значило бы тестировать заодно лексер, парсер и семантику.
  Тесты — **на код** диагностики, а не на текст:
  | Вход | Код | Тест |
  |---|---|---|
  | `Rational` | `SV-003` | `rational_is_sv003_not_real` |
  | `Array(0, u8)` | `SV-004` | `zero_sized_array_is_sv004` |
  | `Integer{0}` | `SV-004` | `zero_width_integer_is_sv004` |
  | перечисление без вариантов | `SV-004` | `empty_enum_is_sv004` |
  | 7 внутренних/неразрешённых узлов | `SV-002` | `uncovered_nodes_are_sv002` |

  Фикстура `struct { data: [u8; 4] }` → `SV-004` **не заводилась**: этот из
  четырёх случаев `SV-004` принадлежит эмиссии структур, а не отображению (см.
  «Не сделано в этой задаче»).
- **T7/T8: пройдено** — оба гейта зелёные (вывод этой задачей не изменён:
  `sv_type` подключается к эмиссии в 0045-04).
- **Методика (`CLAUDE.md`) соблюдена:** каждое нетривиальное решение снято
  **зондом**, а не угадано, — ширина перечисления (`ENUMITEMWIDTH` на реальном
  `Idle = 670`), отсутствие `u12` в языке (`SE-034`), форма объявления массива.
  Оба случая, где план расходится с фактом, найдены зондом **до** написания кода.
- **`cargo test -- --test-threads=1` — зелёный** (1850 тестов); `cargo clippy` по
  `generator/sv/` — без предупреждений.
