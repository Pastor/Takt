# Задача 0050-02: Гейт проверяемости — `rustc` + `clippy` по порождённому коду

> Фича: [../features/0050-rust-backend.md](../features/0050-rust-backend.md) · ADR: [../adr/0050-rust-backend.md](../adr/0050-rust-backend.md) · анализ: [../analyze/0050-rust-backend.md](../analyze/0050-rust-backend.md) · тест-план: [../tests/0050-rust-backend.md](../tests/0050-rust-backend.md)
>
> Требования: **R8**, **R9**, **R10**. Критерии: **A2**, **A3**, **A12**.
> Порядок: **вторая, до эмиссии** (0050-03…07). Обоснование — риск Р1: политика
> линтов определяет форму эмиссии, и принимать её после написания генератора
> значит переписывать генератор.

## Что было

*Проверено пробами 2026-07-16.*

Гейт цели — единственный автоматизируемый способ доказать, что порождённый код
валиден. У соседних бэкендов это главный риск:

| Цель | Арбитр | Цена |
|---|---|---|
| `st` (0041) | MatIEC `iec2c` | пакетом не поставляется, собирается из исходников (`scripts/ensure-iec2c.sh`, ≈15 с); **гейт до сих пор не включён** |
| `sv` (0045) | Verilator + yosys | `brew install verilator yosys`; нужны **оба** — ловят непересекающиеся классы |
| `rust` (0050) | **`rustc` + `clippy`** | **ноль**: уже зависимости проекта |

`precheck.sh` уже содержит: гейт `cc` (цель `c`), гейт `iec2c` (подготовлен),
жёсткий гейт детерминизма 0048 (два прогона × цели → `diff -r`).

## Что сделано

> **Планируется (разработка не начата).** План по ADR 0050.

1. **Гейт в `precheck.sh`** (по образцу гейта `cc`): по каждому порождённому
   `.rs` — `rustc --edition 2021 --crate-type=lib` и `clippy-driver`; ненулевой
   код валит предкоммит. Инструменты в наличии всегда (это Rust-проект) —
   мягкого пропуска, как у `iec2c`, **не требуется**.
2. **Цель `rust` добавляется в гейт детерминизма 0048** (список целей два
   прогона × `diff -r`).
3. `grep -r unsafe` по `examples/generated/rust/` → пусто (**A12**).
4. **Решение по политике линтов (R9) — главный вопрос задачи.**

### Находка пробы: калька с C гейт не проходит

Целевой модуль, написанный руками по решению ADR (образец —
`examples/elevator_mini.lam`):

| Прогон | Результат |
|---|---|
| `rustc --crate-type=lib` | **код 0**, 4 предупреждения |
| `rustc --crate-type=lib -D warnings` | **код 1**: `variant End is never constructed` (×2), `variants Tick and End are never constructed` |
| `clippy-driver -D warnings` | **код 1**, то же |

Причина: C-бэкенд эмитит состояния `_INIT`/`_END`/`_TICK` **всегда**
(`examples/generated/c/elevator_mini.h`: `ELEVATOR_MINI_CABIN_END`,
`ELEVATOR_MINI_MAIN_TICK`), а конкретная модель их не конструирует. В C это
молча — компилятор о неиспользуемом варианте `enum` не говорит. В Rust `dead_code`
превращает это в отказ гейта.

**Варианты решения** (выбрать и обосновать в этой задаче):

| # | Решение | Плюс | Минус |
|---|---|---|---|
| (а) | **Не эмитить недостижимые варианты** | код честен: в `enum` только то, что бывает; линт остаётся сторожем | нужен анализ достижимости — но он **уже есть** (`minimap::Map` хранит снимок достижимых состояний; SE-046 считает достижимость) |
| (б) | `#[allow(dead_code)]` на state-enum | одна строка | глушит сторожа на **всём** enum: будущая настоящая ошибка эмиссии пройдёт молча |
| (в) | Гейт без `-D warnings` | ничего не менять | предупреждения копятся; «порождённый код чист» перестаёт быть проверяемым утверждением |

**Предпочтение ADR — (а)**; (б) допустимо только с письменным обоснованием в
этой задаче (риск Р2), (в) — ослабление гейта, требует решения заказчика.

## Проверки

- Гейт валит предкоммит на **намеренно испорченном** выводе (сторож самого
  гейта: если гейт не умеет краснеть, он не гейт — урок фикса
  [0010-01](../fixes/0010-01-buchi-acceptance.md), где зелёные тесты годами
  прикрывали неверный автомат).
- `./scripts/precheck.sh` зелёный на корпусе.
- Два прогона `-t rust` → `diff -r` пуст (**A10**, гейт 0048).
- `grep -r unsafe examples/generated/rust/` → пусто (**A12**).
