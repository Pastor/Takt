# Задача 0045-04: Модуль и порты — `clk`/`rst_n`, `in`/`out` → порты модуля

> Фича: [../features/0045-sv-backend.md](../features/0045-sv-backend.md) · ADR: [../adr/0045-sv-backend.md](../adr/0045-sv-backend.md) (вопросы 1, 5) · анализ: [../analyze/0045-05-fsm-time-reset.md](../analyze/0045-05-fsm-time-reset.md) · тест-план: [../tests/0045-sv-backend.md](../tests/0045-sv-backend.md)
>
> Требования: **R6** (часть: служебные порты), **R9**. Критерии: **A2**, **A11**.

## Что было

### Как порт Lam выражается сегодня в каждой цели

| Цель | `out cmd_fork: bit` | Механика |
|---|---|---|
| `c` | `(*main->write_bit)(STACKER_CMD_FORK, 1, main->userdata)` | косвенный вызов через таблицу колбэков в структуре модели (зонд `stacker.c:281`) |
| `c-hal` | `*(volatile uint8_t*)0x500 = 1` | запись по адресу; таблица адресов + дефолтный HAL (0020-05) |
| `plantuml` | — | порты не отображаются |
| `st` (0041) | `VAR_OUTPUT cmd_fork : BOOL;` / `VAR_GLOBAL … AT %QX…` | две цели: `st` и `st-at` |

**Ни у одной цели порт не выражается напрямую** — всюду промежуточный слой.

### Что даёт семантика

- `VariableNode::Port { direction: PortDirection, .. }` (`semantic/mod.rs:847-860`);
  `PortDirection::{In, Out, InOut}` (`ast.rs:181`).
- Карта адресов (фича 0020, **ГОТОВО**): `resolve_addresses(model, external) ->
  AddressResolution` (`address_map.rs:409`), `ResolvedAddress { addr, bit, source }`
  (`address_map.rs:361`); канал в генератор — `GenerateOptions { hal, address_map }`
  (`generator/mod.rs:33-41`).
- **`bin/lamc.rs:532`** — `if !external_entries.is_empty() && options.target !=
  "c-hal"` — внешняя карта отсекается для всех целей, кроме `c-hal`.

### Факты по корпусу (проверено `grep`)

- **`inout` не используется ни в одном `.lam`** — 0 вхождений.
- **Порт с именем `clk`/`rst_n` не объявлен ни в одном `.lam`** — 0 вхождений.
- `stacker.lam` — 13 `bit`-портов; `elevator_mini.lam` — 44.

Следствие: цена решений этой задачи (зарезервировать `clk`/`rst_n`, запретить
`inout`) сегодня — **нулевая**.

### Что решено ADR

- **Вопрос 1:** такт Lam ≡ `posedge clk`; `clk`/`rst_n` — **неявные служебные
  порты**, добавляемые генератором (в языке Lam их нет). Имена **зарезервированы**;
  коллизия → `SV-007`. Язык **не меняется** (Option B — объявление `clock`/`reset`
  в `.lam` — отвергнут: сломал бы аддитивность и был бы ложью для трёх целей из
  четырёх).
- **Вопрос 5:** порты Lam → порты модуля — **самое естественное соответствие из
  всех целей**. Карта адресов **не потребляется**: MMIO-адрес для RTL бессмыслен
  (у RTL-модуля нет процессора; сигнал приходит на вывод кристалла, а не по
  адресу). Цели `sv-at`/`sv-mmio` **нет** (`sv-mmio` — кандидат).

## Что сделано

> **Планируется (разработка не начата).**

План — `generator/sv/sv_module.rs`:

1. **Заголовок модуля.** Имя — `normalize_lowercase_snakecase` (как в
   `plantuml/mod.rs:36`). Порты в порядке: служебные, затем `in`, затем `out`:
   ```systemverilog
   module stacker_lift_controller (
       input  logic clk,           // служебный, в .lam отсутствует
       input  logic rst_n,         // служебный, в .lam отсутствует
       input  logic lift_request,  // in  lift_request: bit
       output logic cmd_fork,      // out cmd_fork: bit
       output logic is_done        // терминальность
   );
   ```
2. **Отображение направлений:**
   | `PortDirection` | SV |
   |---|---|
   | `In` | `input logic …` (тип — `get_sv_type`, задача 0045-03) |
   | `Out` | `output logic …` |
   | `InOut` | **ошибка `SV-006`** |
3. **`SV-006` — обоснование отказа (в тексте диагностики):** `inout` в SV — это
   **трёхстабильная** шина, требующая сигнала разрешения выхода
   (`assign pad = oe ? val : 1'bz;`). **Lam сигнала `oe` не выражает**, и вывести
   его из модели нельзя: язык не знает, когда порт «ведёт», а когда «слушает».
   Угадать = молча изменить поведение; эмитировать без `oe` = несинтезируемо.
   Честный отказ. (Кандидат: явный `oe` либо расщепление `_i`/`_o`/`_oe`.)
4. **`SV-007` — коллизия имён.** Порт модели с именем `clk` или `rst_n` → ошибка.
   **Важно для формулировки диагностики:** это **не ключевые слова языка**, а
   зарезервированные имена **цели** `sv`; модель остаётся валидной для
   `c`/`c-hal`/`plantuml`/`st`. Сообщение обязано это объяснять, иначе автор решит,
   что сломан язык.
5. **Адрес не потребляется.** `GenerateOptions.address_map`/`hal` **не читаются**.
   Проверить, что `--address-map` с `-t sv` отсекается **существующей** проверкой
   (`bin/lamc.rs:532`) — правок не требуется.
6. **`is_done`** — выход модуля (`assign is_done = (state == ST_END);`); подробнее
   — задача 0045-05.
7. **Открытый вопрос — неиспользуемые порты.** В C `UsageSet` (`c_map.rs`)
   фильтрует неиспользуемые элементы. В SV неиспользуемый порт — это **лишний
   вывод кристалла** плюс `UNUSEDSIGNAL` от `verilator -Wall` (проверено: в пробе
   он сработал на неподключённый `clk`). Решить пробой: фильтровать ли по
   `UsageSet`, либо эмитировать все объявленные порты. Предположение: фильтровать
   (как C), иначе гейт T7 будет краснеть на легальных моделях.

**Статус по обратной функциональности (правило 11):**

| Функциональность | Работа |
|---|---|
| Язык `.lam` | **н/п** — `clk`/`rst_n` не становятся ключевыми словами |
| Карта адресов (0020) | **н/п** — не потребляется; отсечение даёт существующая проверка |
| Цели `c`/`c-hal` (колбэки, HAL) | **н/п** — не трогаются |
| `GenerateOptions` | **н/п** — поля `hal`/`address_map` не читаются |
| `generator/sv/sv_module.rs` | **новый** |

## Проверки

> **Планируется (разработка не начата).**

- **T18 (R6):** `stacker.lam` → модуль имеет `input logic clk`, `input logic rst_n`;
  в исходном `.lam` их нет.
- **T19 (R9/A2):** `in` → `input logic`, `out` → `output logic`; в выводе **нет**
  ни колбэков, ни `volatile`, ни `AT %`.
- **T13 (A7):** `bit`-порт → `logic` (не `int`, как в C).
- **T5 (R9):** `lamc compile -t sv --address-map elev.map …` отсекается
  существующей проверкой `bin/lamc.rs:532` — **убедиться, что правок не
  потребовалось**.
- **Контрпримеры** (`grammar/tests/data/sv/invalid/`), тест на **код**:
  | Фикстура | Код |
  |---|---|
  | `inout p: bit;` | `SV-006` |
  | `in clk: bit;` | `SV-007` |
  | `in rst_n: bit;` | `SV-007` |
- **Контрпример-негатив:** та же модель с `inout`/`clk` **успешно** компилируется
  в `-t c` — доказывает, что язык не тронут (границы принадлежат **цели**).
- **T7/T8:** порождённый модуль проходит оба гейта; в частности **нет
  `UNUSEDSIGNAL`** — иначе решить вопрос 7 (фильтрация по `UsageSet`).
- Сперва **зонд** реального вывода, затем assertions (`CLAUDE.md`).
- `cargo test -- --test-threads=1` — зелёный.
