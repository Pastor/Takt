## Что сделано

### Ответы проб (2026-07-30)

| # | Вопрос анализа | Ответ пробы | Следствие для примера |
|---|---|---|---|
| О2 | Как задаётся содержимое ПЗУ | Агрегат — **фигурные скобки**: `var rom: [u8;8] := {1, 2, …};`. Форма `[1, 2, …]` не разбирается (`SY-002`). Инициализатор обязан перечислить **все** элементы: `{1,2,3}` для `[u8;8]` → `CC-017` | размер массива равен длине программы; «хвост нулей» пишется явно |
| — | Индекс массива | **Только литерал или имя**: `mem[pc]` — да, `mem[pc + 1]` — `SY-002` («ожидалось `]`») | адрес обязан вычисляться в переменную заранее — а это ровно **адресный регистр шины**, то есть ограничение совпало с предметом |
| О3 | Хватит ли гейту книги `-n 10` | Гейт требует от симуляции **кода возврата 0**, а не завершения: прогон, упёршийся в лимит, — успех | правки гейта не нужны; машине можно быть длиннее десяти тактов |
| О4 | Имена | `Memory` в IEC 61131-3 свободно (`iec2c` принимает FB `ScalarMemory`). ⚠️ `step` — занято (`ST-014`), как и предупреждает живой контекст | имена ядра и памяти безопасны; «шаг» называть `cursor`/`phase` |
| О10 | Как различить два одноимённых ядра | Снимок `--save-state`: `{"kind":"Parallel","children":[{…"id":1},{…"id":2}]}` — экземпляры различаются структурно | трассы двух ядер в разделе читаются снимком, а не печатью шага |
| О11 | Дисциплина такта на шине | При `Core \| Memory` ветви идут в порядке объявления: ядро выставляет адрес, память отвечает **в том же такте**, но ядро прочитает ответ **в следующем** | получается честная синхронная память с задержкой в один такт — и трёхтактный машинный цикл вытекает из неё, а не назначается |

### Находка вне объёма (записана кандидатом)

**Массив как общая переменная в цель `st` не транслируется**: `iec2c` отвергает
передачу массива в `FUNCTION_BLOCK` («Data type incompatibility … when invoking
FB»). Скалярная общая переменная работает. Для раздела значения не имеет — гейт
книги проверяет цель `c` и симуляцию, — но обещать «пример собирается всеми
целями» нельзя.

### Система команд (учебная, 8-битная)

Команда — пара «опкод + аргумент», хранится **двумя массивами** (`prog_op`,
`prog_arg`), поэтому память отдаёт команду целиком за одно обращение. Это
упрощение названо в тексте раздела: в настоящей машине это две ячейки.

| Опкод | Мнемоника | Действие |
|---|---|---|
| 0 | `NOP` | ничего |
| 1 | `LDA a` | `acc := ram[a]` |
| 2 | `STA a` | `ram[a] := acc` |
| 3 | `ADD a` | `acc := acc + ram[a]` |
| 4 | `SUB a` | `acc := acc - ram[a]` |
| 5 | `JNZ a` | если `acc ≠ 0`, то `pc := a` |
| 6 | `HLT` | останов |

⚠️ **Индексного регистра и косвенной адресации в ISA нет** — сознательно: адрес
операнда берётся из самой команды. Поэтому «сумма массива» из первой редакции ADR
невыразима без самомодификации кода, и программой-примером взято **умножение
сложением** — цикл, который складывает одно слагаемое ровно `n` раз. Косвенная
адресация — упражнение раздела.

### Программа-пример

```text
0: LDA 0   ; acc := sum
1: ADD 1   ; acc += x
2: STA 0   ; sum := acc
3: LDA 2   ; acc := n
4: SUB 3   ; acc -= 1
5: STA 2   ; n := acc
6: JNZ 0   ; пока n ≠ 0 — на начало
7: HLT
```

Данные: `ram = {sum = 0, x = 7, n = 3, one = 1}`; ожидаемый результат —
`ram[0] = 21`.

## Проверки

Все пробы воспроизводимы файлами в 5–20 строк; ни одна не опирается на чтение
кода компилятора.

- **Программа исполняется и даёт верный ответ** (проба ступени 1):
  `takt-sim -n 80` — машина доходит до `Halted`, снимок памяти
  `ram = [21, 7, 0, 1]`, то есть `7 × 3 = 21`, счётчик обнулён.
- **Цель `c`** принимает эту же модель (`taktc compile -t c`).
- Ограничение индекса и форма агрегата проверены **отказами** компилятора
  (`SY-002`, `CC-017`), а не догадкой.

Соответствие анализу: сняты О2, О3, О4, О10, О11; ISA и программа зафиксированы.
