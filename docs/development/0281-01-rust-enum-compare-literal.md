# Задача 0281-01: Сравнение перечисления с числом в цели `rust`

> Фича: [../features/0281-rust-enum-compare-literal.md](../features/0281-rust-enum-compare-literal.md) · ADR: [../adr/0281-rust-enum-compare-literal.md](../adr/0281-rust-enum-compare-literal.md) · анализ: [../analyze/0281-rust-enum-compare-literal.md](../analyze/0281-rust-enum-compare-literal.md)

## Что было

Восстановление варианта по числу жило **внутри** `coerce_to`
(`rust_expr.rs`) — то есть было доступно только присваиванию. Печатник условий
о нём не знал и печатал `self.c == 1`; `rustc` отвечал `E0308` при нулевом коде
возврата `taktc`.

## Что сделано

1. Тело восстановления вынесено из `coerce_to` в функцию
   `rust_expr::enum_variant_literal(enum_name, value, scope)` — **единственный**
   носитель правила. `coerce_to` теперь её зовёт.
2. В печатник условий (`rust_cond.rs`) добавлена ветвь `enum_comparison` —
   по образцу `boolean_comparison` (фикс 0148-01, тот же класс дефекта):
   литерал ищется с обеих сторон, формы `==` и `!=` обрабатываются одинаково,
   тип операнда берётся у `condition_type`.

⚠️ **Носитель обязан быть один.** Дефект и состоял в том, что знание жило в
одном месте из двух; третья копия разъехалась бы так же молча (класс
0084/0193/0195).

⚠️ **Значение вне набора вариантов** отвергается с причиной — эта ветвь
существовала и раньше, теперь она обслуживает и сравнение.

