# Задача 0279-01: Подсказка о выборочном импорте

> Фича: [../features/0279-qualified-import-model-reference.md](../features/0279-qualified-import-model-reference.md) · ADR: [../adr/0279-qualified-import-model-reference.md](../adr/0279-qualified-import-model-reference.md) · анализ: [../analyze/0279-qualified-import-model-reference.md](../analyze/0279-qualified-import-model-reference.md)

## Что было

`SE-001` строился в двух местах `semantic/extend.rs` одинаковым литералом:
«Модель 'X' не найдена». На естественной записи

```takt
import "lib.takt";
start Main = Helper;   // Helper объявлен ВНУТРИ lib.takt
```

это утверждение автор читает как «такой модели нет» и идёт переносить состояния
на верхний уровень библиотеки — замер 0211 показал, что так и поступают.

## Что сделано

Обе точки зовут `model_not_found(&model, &id)`. Она добавляет **сноску**, если
имя найдено среди вложенных моделей соседей: называет владельца и форму
подключения (`import { Helper } from "…";`).

- позиция сноски — **объявление вложенной модели**, то есть чужой файл:
  координата там не печатается (правило 0243 — чужую строку под своим путём
  показывать нельзя), а до редактора позиция доезжает;
- файл в подсказке **не называется**: обратной ссылки на путь импорта у обёртки
  нет, а имя файла автор видит в своей строке `import`;
- обход — **один уровень** вложенности, по `BTreeMap` (детерминированно, 0048).

⚠️ **Замер снял с фичи её первоначальный объём.** Кандидат предлагал ввести
`Lib::Helper`; прогон показал, что `import { Helper } from "lib.takt";`
**работает** — вводить второй способ выразить то же самое не нужно.

