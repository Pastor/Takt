# Задача 0127-01: Единая семантика переполнения целых

> Фича: [../features/0127-int-overflow-semantics.md](../features/0127-int-overflow-semantics.md) · ADR: [../adr/0127-int-overflow-semantics.md](../adr/0127-int-overflow-semantics.md) · анализ: [../analyze/0127-int-overflow-semantics.md](../analyze/0127-int-overflow-semantics.md)

## Что было

Правило существовало (S1/S2 анализа 0025), но не как правило **языка**, и цели к
нему не сверялись. Цель `rust` печатала `n += 1`, и на `255 + 1` прошивка
паниковала в debug-профиле, а в release молча оборачивалась — поведение зависело
от профиля сборки пользователя. Поведение цели `st` при переполнении не
проверялось никем.

## Что сделано

1. **Цель `rust`** (`generator/rust/rust_expr.rs`): беззнаковая арифметика
   `+`, `−`, `*` печатается как `wrapping_add`/`wrapping_sub`/`wrapping_mul`.
   Знаковость определяется уже существующим `rust_fixed::expression_type`
   (используется и Q-путём). Свёртка в составное присваивание (`x += 1`) для
   таких узлов **отключена** — она вернула бы панику.
2. **Знаковая арифметика не тронута:** по правилу S2 такая программа ошибочна;
   паника debug-профиля — полезный сигнал, а не дефект.
3. **Фикстура** `takt-sim/tests/data/eval/conformance_overflow.takt`: счётчик
   `u8` от 253, обёртка случается **внутри** прогона (254 → 255 → 0 → 1 → 2 → 3).
4. **Потактовые сверки во всех четырёх целях:** `c`, `rust`, `sv`, `st`.
   Для `st` — впервые; сравнение с поправкой на INIT-сдвиг цели (существующий
   долг контракта 0033) плюс отдельная проверка, что переход `255 → 0` в трассе
   присутствует.
5. **Документация:** раздел «Типы» книги получил подраздел «Переполнение» с
   нормативной формулировкой и двумя примерами; в «Частые ошибки» добавлен
   `SIM-003`. ⚠️ Прежняя фраза «арифметика выполняется по модулю разрядности
   типа» **исправлена**: она распространяла обёртку и на знаковые типы, где её
   нет.

## Вынужденные правки по ходу

- **`conformance_c_tests.rs` упёрся в лимит размера** (1002 строки при лимите
  1000). Тест переполнения вынесен в подмодуль
  `conformance_c_tests/overflow.rs`, подключён `#[path]` (корень тестового крейта
  ищет подмодули рядом с собой) — приём фичи 0088.
- **Тест фичи 0083** (`rust_emits_model_level_always_before_match`) пиннил
  строку `self.n += 1;`. Ожидание обновлено на
  `self.n = self.n.wrapping_add(1);` — сам смысл проверки (тело `always` стоит
  ДО диспетчеризации) не изменился.
