# Задача 0203-01: validate не обходит формулы: неизвестное имя в Guard молчит

> Фича: [../features/0203-validate-formulas-traversal.md](../features/0203-validate-formulas-traversal.md) · ADR: [../adr/0203-validate-formulas-traversal.md](../adr/0203-validate-formulas-traversal.md) · анализ: [../analyze/0203-validate-formulas-traversal.md](../analyze/0203-validate-formulas-traversal.md)

## Что было

Обход мест объявления формулы в проекте **уже существовал** —
`semantic/ltl_check.rs::model_ltl_formulas`, — и его док-строка объявляла себя
общим источником истины: «добавится новое место объявления формулы — добавлять
его нужно здесь». Но обход был написан **под одного потребителя**: на выходе
стоял фильтр `Formula::Guard(_, _) | Formula::None => {}`, выбрасывающий
охранные формулы. Второй потребитель (проверка `validate`, задача 0203-02) не
мог им воспользоваться, а завести собственный список мест значило получить
расхождение при первом же новом месте — класс 0084/0193/0195 (R1 анализа, риск
Р1).

## Что сделано

Обход вынесен в отдельный модуль **`takt-lang/src/semantic/formula/sites.rs`**;
он собирает **все шесть** мест объявления формулы (тело модели, тело состояния,
именованные блоки состояния и модели, тела функций, вложенные операторы) и
отдаёт **листья** дерева `Formula`:

```rust
pub enum FormulaLeaf { Ltl(Ltl), Guard(ConditionNode) }
pub struct FormulaSite { formula: FormulaLeaf, loc: Location, state: Option<String> }
```

- **Варианта `Formulas` у листа нет** — обход разворачивает запись
  `: [Guard] a, [LTL] b;` сам, поэтому у потребителя не появляется недостижимой
  ветки (урок 0233: недостижимый код нельзя ни проверить, ни удержать от
  расхождения). `Formula::None` объявлением не является и сайта не порождает.
- **Имя инварианта лист не несёт**: оно метаданные диагностики симулятора
  (`SIM-025`, фича 0044), ни один потребитель обхода его не спрашивает, а
  неиспользуемое поле нечем удержать от расхождения.
- Разбор `Formula` — **исчерпывающий, без `_`**: новый вид формулы обязан
  заставить принять решение в одном месте, а не выпасть молча из обоих
  потребителей.
- `ltl_check::model_ltl_formulas` **перестал быть обходом** и стал фильтром над
  сбором (`FormulaLeaf::Ltl` → `LtlSite`). Поведение LTL не меняется — это и
  есть регресс задачи.

Функциональности: **семантика** — да (перенос обхода, поведение прежнее);
**цели генерации, симулятор, LSP, документ** — н/п: наблюдаемое поведение
задача не меняет.

## Проверки

```sh
cargo test --lib -p takt-lang     # 1025 тестов, зелено (включая регресс LTL)
cargo test --all-features
```

- **R1** (обход остаётся один): список мест существует в единственном
  экземпляре — `semantic/formula/sites.rs`; `ltl_check` его только фильтрует.
- Регресс LTL: `verification::*`, `semantic::ltl_check` — без изменений
  (предупреждения `SE-055`/`SE-056` на тех же местах и позициях).
- Сторож A9 (перечисление шести мест) заводится задачей 0203-02 вместе с
  проверкой — здесь наблюдаемого поведения, которое он мог бы сторожить, ещё
  нет.
