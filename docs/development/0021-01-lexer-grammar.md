# Задача 0021-01: лексер и грамматика — `:=` присваивание, `=` равенство

> Фича: [../features/0021-swap-assign-compare.md](../features/0021-swap-assign-compare.md) · ADR: [../adr/0021-swap-assign-compare.md](../adr/0021-swap-assign-compare.md) · анализ: [../analyze/0021-swap-assign-compare.md](../analyze/0021-swap-assign-compare.md)

> **Статус:** ЗАПЛАНИРОВАНО (реализация не начата — фича доведена до стадии
> «Разработка»; код пишется отдельно с TDD).

## Что было

`grammar/src/lexer.rs`: `"=" => Token::Assign`, `"==" => Token::Equal`,
`"<=" => Token::LessEqual`. В `grammar.lalrpop` `=` даёт `Expression::Assign`
(строки 419, 516) и `Condition::Equal` (350); `==` — `Expression::Equal`
(436, 533); `<=` — `LessEqual` (358, 444, 541).

## План реализации (по шагам, TDD)

1. **Лексер (`lexer.rs`).** Ввести токен `:=` → `Token::Assign`. Токен `=`
   перевести в роль равенства; `==` — вывести (оставить лексему временно как
   алиас `=` для переходного периода **не** нужно — миграция делает 0021-03).
   `<=` не трогать (`Token::LessEqual`).
2. **Грамматика (`grammar.lalrpop`).**
   - `Expression`: присваивание — по `:=` (`Expression::Assign`); `=` →
     `Expression::Equal`; убрать правила по `==`.
   - Декларации/инициализаторы (`var/const/in/out/inout … = e`, `model = …`,
     `type = …`, `enum V = n`, `cond C = …`) — связыватель остаётся `=`? **Нет:**
     по решению B инициализатор значения — тоже `:=` (`var x := e;`), чтобы `=`
     нигде не означало «присваивание/связывание значения». Связыватели
     объявления имени (`type T = …`, `enum V = n`, `model = …`, `cond C = …`)
     остаются на `=` как **определение**, а не присваивание значения переменной —
     зафиксировать это разграничение в комментарии грамматики и в анализе.
   - `Condition`: `=` уже равенство (`Condition::Equal`) — **без изменений**;
     `<=` — `Condition::LessEqual` без изменений.
   - `LoopCond`/`Precedence*`: синхронно с `Expression`.
3. **PoC LR(1).** Собрать `grammar.lalrpop`, убедиться в отсутствии новых
   конфликтов LALRPOP (свежий токен `:=` не пересекается с `<`, `<=`, `:`).
4. **Зонд-тесты парсера.** Сперва зонд для захвата реального AST (CLAUDE.md:
   «новые тесты — сперва зонд»), затем ассерты: `a := b` → `Assign`; `a = b` в
   выражении → `Equal`; `x <= y` → `LessEqual`.

## Проверки (ожидаемые)

- R1 (однозначность присваивания), R2 (`<=` сохранён), R3 (вывод `==`), R6
  (нет LR(1)-конфликтов). Критерии A1, A2, A5 из анализа.
- Сборка `cargo build --bin lamc` без предупреждений LALRPOP.

## Заметки по риску

Разграничение «`:=` присваивание значения» vs «`=` определение имени в
декларации» — потенциальный источник путаницы у пользователя; вынести в README
таблицей (0021-04). Если окажется, что единообразнее сделать декларации тоже на
`:=` — согласовать с заказчиком до реализации 0021-03/04.
