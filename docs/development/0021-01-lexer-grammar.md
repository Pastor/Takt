# Задача 0021-01: лексер и грамматика — `:=` присваивание, `=` равенство

> Фича: [../features/0021-swap-assign-compare.md](../features/0021-swap-assign-compare.md) · ADR: [../adr/0021-swap-assign-compare.md](../adr/0021-swap-assign-compare.md) · анализ: [../analyze/0021-swap-assign-compare.md](../analyze/0021-swap-assign-compare.md)

> **Статус:** ВЫПОЛНЕНО (лексер + грамматика реализованы, PoC на LR(1)
> пройден, зонд-тесты зелёные). Миграция легаси-фикстур — задача 0021-03.

## Что было

`grammar/src/lexer.rs`: `"=" => Token::Assign`, `"==" => Token::Equal`,
`"<=" => Token::LessEqual`. В `grammar.lalrpop` `=` даёт `Expression::Assign`
(строки 419, 516) и `Condition::Equal` (350); `==` — `Expression::Equal`
(436, 533); `<=` — `LessEqual` (358, 444, 541).

## План реализации (по шагам, TDD)

1. **Лексер (`lexer.rs`).** Ввести токен `:=` → `Token::Assign`. Токен `=`
   перевести в роль равенства; `==` — вывести (оставить лексему временно как
   алиас `=` для переходного периода **не** нужно — миграция делает 0021-03).
   `<=` не трогать (`Token::LessEqual`).
2. **Грамматика (`grammar.lalrpop`).**
   - `Expression`: присваивание — по `:=` (`Expression::Assign`); `=` →
     `Expression::Equal`; убрать правила по `==`.
   - Декларации/инициализаторы — **решение заказчика (2026-07-10):** инициализатор
     **значения** переменной — `:=` (`var x := e;`, `const k := e;`,
     `in/out/inout … := e`), чтобы `=` нигде не означало присваивание значения;
     **определения имени** остаются на `=` как определение: `type T = …`,
     `enum V = n`, `model = …`, `cond C = …`. Разграничение зафиксировать
     комментарием в грамматике и таблицей в README (0021-04).
   - `Condition`: `=` уже равенство (`Condition::Equal`) — **без изменений**;
     `<=` — `Condition::LessEqual` без изменений.
   - `LoopCond`/`Precedence*`: синхронно с `Expression`.
3. **PoC LR(1).** Собрать `grammar.lalrpop`, убедиться в отсутствии новых
   конфликтов LALRPOP (свежий токен `:=` не пересекается с `<`, `<=`, `:`).
4. **Зонд-тесты парсера.** Сперва зонд для захвата реального AST (CLAUDE.md:
   «новые тесты — сперва зонд»), затем ассерты: `a := b` → `Assign`; `a = b` в
   выражении → `Equal`; `x <= y` → `LessEqual`.

## Что сделано (факт)

- **Лексер** (`parser/lexer.rs`): добавлен токен `Token::ColonAssign` (`:=`);
  ветка `:` в токенайзере склеивает `:=` (max munch не затрагивает `::`);
  Display и doctest обновлены (`var x := 42`). Токен `Token::Equal` (`==`)
  сохранён для понятной диагностики, но грамматикой не используется.
- **Грамматика** (`grammar.lalrpop`): в `extern` добавлен `":=" => Token::ColonAssign`;
  присваивание в `Expression`/`LoopCond` переведено на `:=`; равенство — с `==`
  на `=`; инициализаторы `var`/`const`/`in`/`out`/`inout` — на `:=`; определения
  `type`/`enum`/`model`/`state`/`cond` оставлены на `=`; `Condition` не тронут
  (`=` уже равенство), `<=` без изменений.
- **LSP** (`lsp.rs`): `ColonAssign` добавлен в класс операторов подсветки.

## Проверки (выполнено)

- **PoC LR(1):** `cargo build --bin lamc` — сборка успешна, LALRPOP **без новых
  конфликтов** (R6, A5). ✅
- **Зонд-тесты** `grammar/tests/feature_0021_operators.rs` — 6/6 зелёные: `:=`
  инициализатор; `=` → `Expression::Equal`; `<=` → `Expression::LessEqual`; `:=`
  → `Expression::Assign`; `==` → ошибка разбора; `cond … = … = …` →
  `Condition::Equal` (R1, R2, R3 · A1, A2, A5). ✅
- **End-to-end:** модель `var counter := 0; cond IsZero = counter = 0; …`
  компилируется в C: инициализатор → `counter = 0;`, равенство → `if (counter == 0)`
  — генератор C не изменён, семантика корректна. ✅
- Диагностика `==`: «нераспознанный токен '==', ожидалось … "=" …» (подсказка на `=`).

## Заметки по риску

Разграничение «`:=` присваивание/инициализация значения» vs «`=` определение
имени (`type`/`enum`/`model`/`cond`)» — потенциальный источник путаницы у
пользователя; **обязательно** вынести в README таблицей-памяткой (0021-04) и
добавить в тест-план проверку T9 (определения принимают `=`, инициализаторы —
`:=`). Решение согласовано с заказчиком (2026-07-10) — пересмотр не требуется.
