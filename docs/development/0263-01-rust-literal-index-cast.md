# Задача 0263-01: Приведение индекса к `usize` по нужде

> Фича: [../features/0263-rust-literal-index-cast.md](../features/0263-rust-literal-index-cast.md) · ADR: [../adr/0263-rust-literal-index-cast.md](../adr/0263-rust-literal-index-cast.md) · анализ: [../analyze/0263-rust-literal-index-cast.md](../analyze/0263-rust-literal-index-cast.md)

## Что было

Два печатника цели `rust` — выражений (`rust_expr.rs`) и условий
(`rust_cond.rs`) — печатали индексацию **каждый своей копией** одной строки
`"{}[{} as usize]"`. На литеральном индексе это `clippy::unnecessary_cast`,
то есть отказ под `-D warnings` — флагами гейта предкоммита.

## Что сделано

Правило вынесено в **одну** функцию `rust_expr::subscript(base, index,
index_is_literal)`; оба печатника зовут её. Приведение печатается, только когда
индекс не литерал.

⚠️ **Носитель обязан быть один:** копия правила в двух печатниках разъехалась бы
при первой же правке — класс 0084/0193/0195. Именно из-за двух копий дефект и
пришлось бы чинить дважды.

⚠️ **Отрицательный литерал сюда не доходит** — `SE-028` отсекает его в
семантике; проверено прогоном, а не рассуждением.

## Проверки

```sh
cargo test --test targets rust_index_cast   # 3 теста, включая настоящий clippy-driver
cargo test --all-features                   # 3245 тестов
./scripts/precheck.sh                       # полный гейт
```

Мутация «снять приведение и у переменной» валит T1 (обе формы проверяются одним
тестом) и гейт цели `rust` на корпусе.
