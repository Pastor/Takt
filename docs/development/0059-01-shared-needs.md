# Задача 0059-01: Состав `Shared` — объединение нужд под-моделей

> Фича: [../features/0059-rust-shared-struct.md](../features/0059-rust-shared-struct.md) · ADR: [../adr/0059-rust-shared-struct.md](../adr/0059-rust-shared-struct.md) · анализ: [../analyze/0059-rust-shared-struct.md](../analyze/0059-rust-shared-struct.md)

## Что было

`shared` считается **по каждой под-модели отдельно** (минимум по её нуждам) и
разворачивается в параметры по одному (`rust_model.rs:855–862`). Понятия «состав
общих переменных модели» — то есть **объединения** нужд — не существует.

Замер (`stacker.lam`, 9 переменных корня): `CommandReceiver` — 6,
`MovementController` — **8** (все, кроме `eta`), `LiftController` — 3.

## Что сделано

1. Ввести вычисление **объединения нужд под-моделей** для композирующей модели —
   состав будущего `Shared` (правило 2 ADR: переменная, не нужная **ни одной**
   под-модели, в состав **не входит** и остаётся прямым полем; иначе имя типа
   лжёт, а поле ловит `dead_code`).
2. Считать нужды **тем же** механизмом, что уже считает нужды такта/функции
   (`rust_needs`), а не вторым предикатом рядом: разойдясь, они дали бы либо
   `dead_code` на поле, либо неразрешённое имя. Прецедент, ради которого это
   требование записано, — `function_needs` / `rust_expr::call` в этом же
   генераторе.
3. Правило 1 ADR: **нет нуждающихся под-моделей — нет типа** (в корпусе такой
   случай есть: `comprehensive`).
4. Правило 4 ADR: объединение считается **для каждой** композирующей модели
   независимо (в корпусе есть уровни: `extend_complex`).
5. Детерминизм (фича 0048): состав `Shared` — упорядоченный контейнер
   (`BTreeMap`/`BTreeSet`), порядок полей задаётся **типом контейнера**, а не
   строкой на эмиссии.

**⚠️ Исправить неверный комментарий** `rust_model.rs:911` (A-3 ADR): «`MovementController`
разделяет с корнем **девять** переменных» → **восемь**; девять — это размер
**корня**. Ошибка кочует из кандидата в код и обратно, поэтому правится вместе с
кодом, а не «когда-нибудь».

Статус по обратной функциональности (правило 11): шаг **ничего не печатает** —
вывод всех целей неизменен; задача подготовительная.

## Проверки

- `cargo build --bin lamc` — зелёная.
- Юнит-тесты состава: `comprehensive` → пусто (R3); модель с «ничьей» переменной →
  её в составе нет (R2/T6); `stacker` → у корня в составе 9 (объединение 6 ∪ 8 ∪ 3).
- `git diff --exit-code examples/generated/rust` — **пусто** (печать не тронута).
- **Негативный сторож (T13):** мутация «класть все переменные корня» обязана дать
  непрочитанное поле — то есть отказ гейта на следующем шаге. Сторож, не
  проверяющий взведённость ловушки, проверяет собственную удачу (урок 0056).
