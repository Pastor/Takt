## Что сделано

> **Планируется (разработка не начата).**

План:

1. **README (правило 15)** — новый раздел о цели `sv`:
   - **чем `sv` отличается принципиально:** такт = **фронт `clk`**, а не итерация
     цикла сканирования. Это первое, что автор модели обязан понять;
   - **служебные порты `clk`/`rst_n`**, которых нет в `.lam`: откуда берутся,
     почему имена зарезервированы **для цели**, а не в языке;
   - **сброс = стартовое состояние**: ветвь сброса несёт `enter` стартового
     состояния; синтетического `INIT` нет; **сдвиг = 0 на любой глубине**;
   - **таблица отображения типов** (`bit` → `logic` и т. д.);
   - **сравнение целей** — сводная таблица (см. ниже);
   - **пример:** `stacker.lam` → фрагмент порождённого SV (`LiftController`);
   - **границы цели** — раздел обязателен (правило 16): `float`, `extern fn`,
     `inout`, `clk`/`rst_n`, неконстантный `enter` стартового состояния,
     уплощение иерархии, один тактовый домен, потолок частоты;
   - **как проверить вывод:** `verilator --lint-only -Wall` **и** `yosys … synth`
     — с оговоркой, что **нужны оба** (Verilator пропускает `real`; yosys
     пропускает комбинационные петли — **проверено**).

   Сводная таблица для README:

   | | `c` | `c-hal` | `st` (0041) | **`sv`** |
   |---|---|---|---|---|
   | Платформа | МК | МК | ПЛК | **FPGA/ASIC** |
   | Такт | вызов `_tick` | вызов `_tick` | скан-цикл | **фронт `clk`** |
   | `out cmd_fork: bit` | колбэк `write_bit` | `*(volatile*)0x500` | `VAR_OUTPUT` / `AT %QX` | **`output logic`** |
   | `bit` | `int` (32 бита) | `int` | `BOOL` | **`logic`** (1 провод) |
   | `float` | `float` (f32) | `float` | `LREAL` (f64) | **запрещён `SV-003`** |
   | `extern fn` | прототип | прототип | заглушка | **запрещён `SV-005`** |
   | Адрес порта | не эмитит | **потребляет** | `st-at` потребляет | **не потребляет** |
   | Вход в старт | **стоит такта** (до 0033) | стоит такта | стоит такта | **бесплатен** |
   | `M1 \| M2` | последовательно, такт = сумма | то же | то же | **параллельно, такт = один** |

2. **Примеры и контрпримеры в документацию (правило 16).** После проверки (тест-план
   T1–T34) в README попадают:
   - **примеры:** `stacker.lam` → SV (`LiftController`, фрагмент из ADR — **прошёл
     линт, синтез и тестбенч**); `[u8; 4]` → `logic [7:0] data [0:3]`;

   **Версия языка не трогается — остаётся 0.2.0** (`README.md:1007`).

## Открытые вопросы

- **Куда девать `elevator.lam`.** Флагманский пример README **не транслируется** в
  `sv` (8 `extern fn`). Варианты: (а) честно указать в README, что для `sv` он
  недоступен, и вести раздел на `stacker.lam`; (б) завести `elevator_sv.lam` без
  `extern fn`. **Предпочтение — (а):** второй вариант умножает корпус и маскирует
  реальную границу цели. Решает координатор/заказчик.
- **Кандидаты в `FEATURES.md`** (заводит координатор — вне границ фичи; перечень —
  в [анализе](../analyze/0045-sv-backend.md), раздел «Вынесено в кандидаты»):
  `sv-mmio`, fixed-point Q(m.n), `extern fn` → чёрный ящик, порт `en`, `inout` с
  `oe`, CDC/многодоменность, общий каркас сверки бэкендов, кодификация версии
  языка константой, детерминизм генерации.
