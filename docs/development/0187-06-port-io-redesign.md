# Задача 0187-06: нормированная модель доступа к порту (ось 4)

> Фича: [../features/0187-port-io-redesign.md](../features/0187-port-io-redesign.md) · ADR: [../adr/0187-port-io-redesign.md](../adr/0187-port-io-redesign.md) · анализ: [../analyze/0187-port-io-redesign.md](../analyze/0187-port-io-redesign.md)

## Что было

[ADR 0187](../adr/0187-port-io-redesign.md), ось 4: «общего понятия „доступ к
порту“ в языке нет: каждая цель придумывает своё». Заказчик выбрал вариант
**4B** — нормировать модель доступа в языке (чтение — выражение, запись —
оператор), а отображение задать целям **единой таблицей**.

Формулировка звучала как забота о внутренней стройности. Проба (2026-08-01)
показала, что за ней стоит настоящий дефект.

## Проба: что делали потребители с записью внутри выражения

Вход `seen := (value := 3) + 1;` при `out value: u8` — **шесть потребителей, три
поведения**, и ни одного внятного отказа:

| Потребитель | Что происходило |
|---|---|
| `c` | `model->seen = ((*main->write_numeric)(…)) + 1;` — `void + int`, **`cc` отвергает** |
| `rust` | `self.seen = hal.write_u8(…) + 1;` — `() + {integer}`, **`rustc` отвергает** (E0369) |
| `st` | `seen := (value := 3) + 1;` — в IEC присваивание не выражение, **`iec2c` отвергает** |
| `sv` | честный отказ `SV-002` при генерации |
| `sv-mmio` | то же, что `sv` |
| симулятор | отказ `SIM-014` **в такте**, то есть уже на исполнении |

То есть язык позволял написать то, чего не умеет **ни один** потребитель, а
диагностику давали чужие инструменты — на порождённом файле и с координатами
этого файла.

⚠️ **На обычных переменных цена была выше, чем на портах.** `seen := (a := 3) +
1;` цель `c` печатает **валидным** C (`(model->a = 3) + 1`) и считает `4`, тогда
как эталон-симулятор ту же модель не исполняет вовсе (`SIM-014`). Это уже не
«невалидный вывод», а расхождение эталона и цели — то, ради чего сверки и
заводятся.

## Что сделано

### Правило языка: присваивание — оператор (`SE-095`)

Позиций оператора ровно две: выражение-оператор тела (`led := 1;`) и шаг цикла
(`for var i: u8 := 0; i < 3; i := i + 1`). Везде ещё присваивание — ошибка
**`SE-095`** с указанием цели записи.

Правило живёт в **семантике**, а не в грамматике: `Expression::Assign` остаётся
узлом АСД (форма `(x := 7)` по-прежнему разбирается). Делить грамматику
выражений надвое значило бы взяться за слияние `Condition`/`Expression`, которое
ADR 0019 отверг.

### Один обход тел, два судьи

Модуль `validate/port_direction.rs` переименован в **`validate/bodies.rs`**: имя
стало врать, когда судей стало двое. Он по-прежнему ничего не решает сам —
доставляет выражения:

| Судья | Правило | Диагностика |
|---|---|---|
| `validate/common.rs::validate_expression` | направление порта | `SE-026`, `SE-027` |
| `validate/assignment_position.rs` | присваивание — оператор | `SE-095` |

Второму судье нужна **позиция** выражения (`Position::Statement` /
`Position::Value`) — обход знает её по построению, судья только принимает. Так
правило не размножается: заводя новую позицию в языке, её добавляют в обход, а
не пишут второе правило (тот же принцип, что ввела 0188).

⚠️ Разбор в судье **исчерпывающий**, ветки `_` нет: новый узел языка, способный
нести выражение, обязан завалить сборку модуля, а не молча вывести своё
содержимое из-под правила.

⚠️ Диагностика указывает позицию **объявления** цели записи, а не места
нарушения: `ExpressionNode` позиций не несёт (осознанное решение фичи 0056 — не
тащить позицию через ~40 вариантов ради одного потребителя). Тот же компромисс
уже принят у `SE-026`/`SE-027`.

### Таблица отображения доступа и сторож к ней

Контракт зафиксирован таблицей — в шапке
`takt-lang/tests/port_access_contract_tests.rs` и в живом контексте:

| Цель | Чтение | Запись |
|---|---|---|
| `c` | `(*ptr->read_<класс>)(ПОРТ, ptr->userdata)` | `(*ptr->write_<класс>)(ПОРТ, значение, ptr->userdata);` |
| `c-hal` | то же | то же |
| `rust` | `hal.read_<тип>(In<Тип>Port::Имя)` | `hal.write_<тип>(Out<Тип>Port::Имя, значение);` |
| `st` | имя порта (вход `FUNCTION_BLOCK`) | `имя := значение;` |
| `st-at` | имя порта (`VAR_EXTERNAL` над размещённой глобальной) | `имя := значение;` |
| `sv` | имя входного порта модуля | `имя_next = значение;` |
| `sv-mmio` | имя сигнала бита регистрового файла | `имя_next = значение;` |

Сторож проверяет каждую строку **текстом вывода** — это и есть условие R11:
новая цель получает контракт, а не образец для подражания, и сторож падает,
если цель печатает доступ иначе. Документ без сторожа — договорённость, которую
следующая правка нарушит молча.

⚠️ Отображение целей **не менялось**: таблица описывает то, что цели печатают
сегодня. Граница задачи из анализа («существующее отображение меняется только
там, где противоречит таблице») соблюдена — противоречий не нашлось.

## Что НЕ сделано (границы задачи)

- **Правило держит семантика, а не грамматика.** Присваивание синтаксически
  остаётся выражением: `takt_lang::parse` (только разбор) принимает `(x := 7)` в
  инициализаторе, в арифметике и в условии `if` — проба 2026-08-01. Заказчик
  потребовал (2026-08-01), чтобы границу проводил **синтаксис** языка, поэтому
  заведён фикс
  [0187-01](../fixes/0187-01-assignment-is-statement-in-grammar.md): вывести
  `Assign` из цепочки выражений в правило оператора и отвечать `SY-006`.
  ⚠️ Правка идёт в цепочку приоритетов, которую ADR 0019 велел писать один раз
  (`Chain<Atom>`, два инстанцирования), — это отдельная работа с прогоном всего
  корпуса, а не довесок к этой задаче.
- **Позиция диагностики `SE-095`** — объявление цели записи, а не место
  нарушения (см. выше). Улучшение требует позиций в `ExpressionNode`, то есть
  отдельной работы, затрагивающей ~40 вариантов узла и его равенство. Фикс
  0187-01 снимает и это: парсер знает позицию токена `:=`.
- **`SIM-014` не снят**: симулятор по-прежнему умеет отказать в такте. Теперь
  это недостижимый путь для скомпилированной модели, но страховка эталона
  сохранена намеренно — она дешевле, чем доказательство недостижимости.

## Проверки

| Условие | Результат |
|---|---|
| `seen := (value := 3) + 1;` → `SE-095` (порт) | да |
| `seen := (a := 3) + 1;` → `SE-095` (переменная) | да |
| `value := acc + 1;` и `for var i: u8 := 0; …; i := i + 1` — молчат | да |
| форма доступа каждой из 7 целей совпадает с таблицей | да |
| `cargo test -p takt-lang -- --test-threads=1` | зелёные |
| `./scripts/precheck.sh` | зелёный |

Сторожа: `takt-lang/tests/port_access_contract_tests.rs` (9 тестов — 7 целей,
отказ и контрпример законных позиций).
