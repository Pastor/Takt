# Задача 0024-01: Ядро печати АСД (`format_source`)

> Фича: [../features/0024-lam-formatter.md](../features/0024-lam-formatter.md) · ADR: [../adr/0024-lam-formatter.md](../adr/0024-lam-formatter.md) · анализ: [../analyze/0024-lam-formatter.md](../analyze/0024-lam-formatter.md)

> **Статус:** ВЫПОЛНЕНО частично — ядро печати готово и проверяемо, но **гейт по
> корпусу не активен**: его блокируют комментарии (задача `0024-02`). См.
> «Находка» — она меняет декомпозицию фичи.

## Что было

Форматтера не существовало ни в одном инструменте: у `lamc` единственная
подкоманда `compile`, `lam-lsp` не отвечает на `textDocument/formatting`, плагин
IntelliJ без реформата.

## Что сделано

Создан модуль `grammar/src/format/` (799 строк) с публичным API
`format_source(&str) -> Result<String, FormatError>`:

| Файл | Содержание |
|---|---|
| `format/mod.rs` | API, `FormatError`, накопитель отступов `Out`, печать элементов модели, состояний, функций |
| `format/expr.rs` | Выражения (39 вариантов), условия (19), типы, объявления переменных/портов, импорты |
| `format/stmt.rs` | Операторы и блоки |

Реализовано по ADR (Option A): печать **от АСД**, семантический проход не
запускается — форматтер работает и на семантически некорректных, но
синтаксически валидных файлах (R1).

### Два решения, снявшие риски ADR

1. **Скобки не пересчитываются.** `Expression::Parenthesis` и
   `Condition::Parenthesis` — **явные узлы АСД**, поэтому авторская расстановка
   сохраняется как есть, а анализ приоритетов не нужен. Семантическая
   нейтральность (R4) достигается почти бесплатно — риск «форматтер меняет смысл»
   снят конструктивно, а не тестами.
2. **`Condition` печатается отдельной функцией**, а не переиспользованием
   `expression`. Это не дублирование, а следствие решения [ADR 0019](../adr/0019-condition-expression-unification.md):
   у условий **другая** семантика `=` (равенство, а не присваивание). Слияние
   печати подменило бы операторы — молча.

### Отказ вместо тихой потери (урок фичи 0025)

Непокрытый узел даёт `FormatError::Unsupported`, а не пустую строку: напечатать
«что-нибудь» вместо неизвестного узла означало бы молча испортить исходник
пользователя. Там, где перечисление помечено `#[non_exhaustive]`
(`ast::Statement`), ветка `_` вынужденная — и она **отказывает**.

## Находка: комментарии блокируют 88% корпуса — декомпозиция фичи неверна

Harness (`grammar/tests/format_tests.rs`) прогоняет форматтер по **всему корпусу**
`.lam` репозитория (158 файлов) и печатает сводку покрытия. Результат:

```
── Форматтер: покрытие корпуса ──
  всего .lam:            158
  отформатировано:       0
  не разбирается:        21 (невалидные фикстуры — норма)
  узел не поддержан:     137
      136 × комментарии (печать — задача 0024-02)
        1 × InlineFormula
```

**136 из 158 файлов содержат комментарии.** Анализ отнёс их к отдельной задаче
`0024-02`, как если бы это была деталь. На деле печать комментариев — **условие
проверяемости ядра**: пока её нет, критерии A1 (идемпотентность) и A3
(семантическая нейтральность) на реальных файлах проверить **невозможно** —
они проверяются только на синтетических входах без комментариев.

**Вывод:** задачи `0024-01` и `0024-02` следует считать **одной** — ядро без
комментариев не приёмопригодно. Аналогичная ошибка декомпозиции уже встречалась
в фиче 0025 (задача 02 делилась дважды по ходу реализации).

## Проверки

- `cargo test --all-features -- --test-threads=1` → **1594 passed** (было 1586;
  +8), 0 провалов. `cargo clippy` → 0; `run_simulations.sh` → 5 из 5.
- **Гейт harness'а осмыслен, а не декоративен:** тест падает, если появляется
  **новый** непокрытый узел; известные пробелы перечислены явно (`KNOWN_GAPS`).
  Так «не отформатировано» не превращается в тихую норму.
- Юнит-тесты ядра: нормализация объявлений, отступы тела состояния, финальный
  перевод строки, идемпотентность на «грязном» входе, сохранение операторов
  `:=`/`=` (инвариант фичи 0021).

## Что осталось по фиче

- **`0024-02`** — печать комментариев (переассоциация по `Location`);
  **объединить с 01**: без неё гейт по корпусу не включается.
- Печать `Formula`, `ConditionDefine`, `InlineFormula`, `Address`, `CodeBlock`,
  `NamedFunction`, `Type::Function` — сейчас явный отказ.
- Восстановление осмысленных пустых строк из зазоров исходника (ADR).
- **`0024-03`** — подкоманда `lamc fmt`; **`0024-04`** — LSP и IntelliJ.
