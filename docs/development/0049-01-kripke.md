# Задача 0049-01: Структура Крипке из ModelNode

> Фича: [../features/0049-model-checking-ltl.md](../features/0049-model-checking-ltl.md) · ADR: [../adr/0049-model-checking-ltl.md](../adr/0049-model-checking-ltl.md) · анализ: [../analyze/0049-model-checking-ltl.md](../analyze/0049-model-checking-ltl.md)

## Что было

*Проверено картированием кода 2026-07-16.* Готовой структуры Крипке нет; есть
сырьё — граф FSM:

- `StateNode` (`semantic/mod.rs:1023`): варианты `Simple`/`Implement` с
  `references(): &[ReferenceNode]`, `formulas()`, `name()`, `kind()`
  (`StateNodeKind::{Simple,Start,End}`, `mod.rs:1149`).
- `ReferenceNode` (`mod.rs:1455`): `{ name: String (цель), cond: ConditionNode,
  object: Box<StateNode> }`.
- `ModelNode::get_start_state()` (`mod.rs:189`), `get_end_states()` (`mod.rs:201`).
- Образец обхода — `generator/c/c_model.rs:430` `generate_state_transitions`.

## Что сделано

> **Планируется (разработка не начата).** План по ADR 0049 (Option A —
> управляющий граф, атом = состояние).

1. Новый модуль `grammar/src/verification/kripke.rs`:
   ```rust
   pub struct Kripke {
       pub states: Vec<String>,                 // имена состояний (детерминированный порядок)
       pub initial: usize,                      // индекс стартового
       pub transitions: BTreeMap<usize, BTreeSet<usize>>,
   }
   pub fn build_kripke(model: &ModelNode) -> Kripke;
   ```
2. Вершины = состояния FSM (по `states`, упорядоченно — гейт 0048). Рёбра — по
   `references()` каждого состояния (цель по `reference.name`). **Гарантии рёбер
   абстрагированы** (guarded-`ref` → возможный переход; `cond` игнорируется).
3. **Самопетля терминальных/тупиковых** вершин (R2): состояние без исходящих рёбер
   (`End` или без `ref`) получает `k → k`, иначе нет бесконечных прогонов.
4. Оценка атома (R2/R7): `atom_holds(k, name) = states[k] == name`. Атом, не
   совпадающий ни с одним именем состояния, — не молчаливый false, а сигнал для
   диагностики (R7, реализуется в 0049-03 при связывании).

## Проверки

- Юнит-тесты на малых моделях: число вершин = число состояний; рёбра = `ref`;
  терминальные имеют самопетлю; стартовая вершина = `get_start_state`.
- Детерминизм: `build_kripke` дважды даёт идентичную структуру (`BTree*`).
- Соответствие анализу: R1, R2 (частично), R7 (оценка атома).
