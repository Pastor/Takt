# Задача 0049-01: Структура Крипке из ModelNode

> Фича: [../features/0049-model-checking-ltl.md](../features/0049-model-checking-ltl.md) · ADR: [../adr/0049-model-checking-ltl.md](../adr/0049-model-checking-ltl.md) · анализ: [../analyze/0049-model-checking-ltl.md](../analyze/0049-model-checking-ltl.md)

## Что было

*Проверено картированием кода 2026-07-16.* Готовой структуры Крипке нет; есть
сырьё — граф FSM:

- `StateNode` (`semantic/mod.rs:1023`): варианты `Simple`/`Implement` с
  `references(): &[ReferenceNode]`, `formulas()`, `name()`, `kind()`
  (`StateNodeKind::{Simple,Start,End}`, `mod.rs:1149`).
- `ReferenceNode` (`mod.rs:1455`): `{ name: String (цель), cond: ConditionNode,
  object: Box<StateNode> }`.
- `ModelNode::get_start_state()` (`mod.rs:189`), `get_end_states()` (`mod.rs:201`).
- Образец обхода — `generator/c/c_model.rs:430` `generate_state_transitions`.

## Что сделано

> **Готово.** Реализовано по ADR 0049 (Option A — управляющий граф, атом =
> состояние).

1. Новый модуль `grammar/src/verification/kripke.rs`:
   ```rust
   pub struct Kripke {
       pub states: Vec<String>,                 // имена состояний (детерминированный порядок)
       pub initial: usize,                      // индекс стартового
       pub transitions: BTreeMap<usize, BTreeSet<usize>>,
   }
   pub fn build_kripke(model: &ModelNode) -> Option<Kripke>;
   ```
   **Отличие от плана:** возвращается `Option`, а не `Kripke`. Модель без
   стартового состояния графа не задаёт, а молчаливый вердикт «держится» на
   пустом графе был бы ложью (ADR 0025). `None` поднимается до
   `Verdict::NoStartState` (0049-03). Через `construct_model` такая модель не
   проходит (SE-011 — «должно быть только одно начальное состояние»), поэтому
   ветка защитная; юнит-тест собирает узел вручную.
2. Вершины = состояния FSM (ключи `states: BTreeMap` — алфавитный порядок, гейт
   0048). Рёбра — цели `ref` **и** `next` состояния-реализации. **Гарантии рёбер
   абстрагированы** (guarded-`ref` → возможный переход; `cond` игнорируется).
3. **Самопетля** (R2/A2) ставится вершине, в которой автомат **может
   задержаться** (`may_stutter`): у неё нет ни одного **безусловного** `ref`.
   Не только тупику!

   Эталон — порождённый C (`c_model.rs::generate_state_transitions`):

   ```c
   case S: {
       if (cond) { model->state = NEXT; break; }
       break;                 // ← ни один guard не сработал: состояние прежнее
   }
   ```

   ⚠ **Первая редакция ставила самопетлю только вершине без рёбер — и это
   ломало главную гарантию фичи** (найдено ревью до сдачи). Состояние, все
   выходы которого условны, теряло реальный прогон «стоим на месте вечно»;
   Крипке становилась **недо**-аппроксимацией, и `F Done` на
   `start A { ref Done: x = 1; } state Done;` объявлялось **доказанным**, хотя
   автомат вправе никогда не уйти из `A`. Ошибаться дозволено лишь в сторону
   **лишних** прогонов: они дают ложные срабатывания, а не пропущенные
   нарушения. `next` состояния-**реализации** безусловным выходом не считается —
   он ждёт конца вложенной модели, а она может не закончиться никогда
   (`next` состояния *без* реализации `tree.rs` уже превратил в безусловный
   `ref`, поэтому он засчитывается).
4. Оценка атома (R2/R7): `atom_holds(k, name) = states[k] == name`; список
   неподдержанных атомов — `Kripke::unknown_atoms` (потребитель — 0049-03).
5. `Kripke::trace()` — дамп графа для отладки (`lamc verify --trace`).

**Переиспользование вместо копирования.** Обход рёбер взят не из образца
`c_model.rs:430`, а вынесен в общий помощник: `validate.rs::get_reachable_targets`
(анализ достижимости SE-046) стал `pub(crate) reachable_targets` и служит
единым источником истины о рёбрах графа FSM. Расхождение «что считается
переходом» между SE-046 и верификатором теперь невозможно by construction.

## Проверки

Юнит-тесты `verification/kripke.rs::tests` (9, зелёные):

- вершины = состояния, рёбра = `ref`; guarded-`ref` — ребро (условие
  абстрагировано); `next` состояния-реализации — ребро, вложенная модель **не**
  разворачивается;
- тупик имеет самопетлю; стартовая вершина — состояние `start`, а не первое по
  алфавиту (сторож: контрпример `state A { ref Z; } start Z { … }`);
- модель без `start` → `None`;
- оценка атома: имя состояния истинно, атом-переменная ложен всюду;
  `unknown_atoms` перечисляет неподдержанные;
- детерминизм: 10 построений дают идентичную структуру.

Соответствие анализу: R1, R2 (частично), R7 (оценка атома); тест-план T1–T5.
