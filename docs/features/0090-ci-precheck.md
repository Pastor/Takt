## Краткое описание

CI (`.github/workflows/ci.yml`) выполняет только `cargo build/check/test` — **весь
предкоммит-гейт в CI не идёт**. Не покрыты:

- **живая проверка порождённого C** (cmake/ninja по `examples/`);
- **ST-гейт `iec2c`**: работает и **включён в `precheck.sh`** (валит предкоммит на
  невалидном ST), но в CI не идёт — связывать не с чем;
- **`scripts/check-links.py`** (правило 14): заведён 2026-07-14 и подключён в
  `precheck.sh`; остаток исходного пункта бэклога — ровно «подключить в CI».

То есть предкоммит проверяет живьём **две** цели (`c` и `st`), и обеих CI не видит.

⚠️ **Урок закрытой [0026](0026-c-root-typedef.md):** дефект «порождённый C не
компилируется для одиночной модели» дожил до своего исправления именно потому, что
дыра была **не в коде, а в покрытии** — все пять `examples/*.lam` имеют под-модели,
а простейший класс моделей живой проверкой не покрывался вовсе. `precheck.sh` эту
дыру **по-прежнему не закрывает** (там всё те же пять примеров).

**Инструмент CI-пригоден:** MatIEC собирается из исходников
(`scripts/ensure-iec2c.sh`), лицензия открытая, на `ubuntu-latest` bison 3.x (на
macOS системный bison 2.3 сборку **валит** — нужен `brew` bison ≥ 2.4).

> **Объединены два пункта** процессного бэклога («подключить `check-links.py` в CI»
> и «CI не запускает `precheck.sh`»): `check-links.py` уже **часть** `precheck.sh`,
> поэтому второй пункт поглощает первый (решение заказчика 2026-07-17).
>
> **Матрица Windows в объём не входит:** пункт «Windows отсутствует в матрице CI»
> остаётся за фичей [0037](0037-windows-test-failures.md) (задача 0037-03) —
> решение заказчика 2026-07-17. Там же: CI не соблюдает `--test-threads=1` (при том
> что `CLAUDE.md` требует), `actions-rs/*` архивированы.

> Фича зарегистрирована **2026-07-17** переводом пункта **процессного бэклога**
> `FEATURES.md` (решение заказчика: «завести фичи по кандидатам и процессному
> бэклогу, пока без проработки»). **Проработка не проводилась:** ADR, анализ,
> зависимости, Tier и объём — за стадиями 2–3 (правило 17). Приоритет процессной
> фичи определяется по влиянию на разблокировку других (правило 19, критерий 3).

## Итог (что сделано)

**Закрыта 2026-07-20 по локальной проверке** (решение заказчика; вердикт отчёта —
**ГОТОВО с оговоркой**). Принята **Option A** ([ADR](../adr/0090-ci-precheck.md)):
CI прогоняет **весь** `scripts/precheck.sh` — единый источник истины гейтов, а не
вторая их реализация в workflow (причина фичи — дрейф этих двух реализаций).

Сделано (крейты `grammar`/`simulation` **не затронуты** — только инфраструктура):

- **0090-01 — обобщённый строгий режим `precheck.sh`.** Единый флаг
  `PRECHECK_STRICT=1` + хелпер `require_tool`: под флагом отсутствие любого
  инструмента гейта (`python3`/`cc`/`iec2c`/`verilator`/`yosys`) — **ошибка**, а не
  мягкий пропуск; `SV_GATE_REQUIRED` наследует флаг; формат под флагом —
  `fmt --check`. Локально без флага поведение **байт-в-байт прежнее** (аддитивно,
  правило 11).
- **0090-02 — `ci.yml` → `precheck.sh`.** Единый ubuntu-джоб: `checkout@v4` +
  `dtolnay/rust-toolchain@nightly` + apt-инструменты + `ensure-iec2c.sh` + **один**
  вызов `./scripts/precheck.sh` под `PRECHECK_STRICT=1`. Логики гейтов в workflow
  не осталось; архивные `actions-rs/*` уведены (побочно закрыта CI-модернизация,
  числившаяся за 0037 — за 0037 остаётся только матрица Windows).
- **Устаревшие заметки про «невключённый ST-гейт»** исправлены (`CLAUDE.md`,
  `README`, комментарий `precheck.sh`): проба `iec2c` — **8/8** примеров валидны.
  README получил раздел про CI-строгость.

**Локальная проверка (✅):** строгий `precheck.sh` `EXIT=0` (110 строк успешных
гейтов, живых пропусков нет, вывод генераторов не изменён); пробы `require_tool`
(A3/A4) и `fmt --check` (A6) верны. Детали — [отчёт](../reports/0090-ci-precheck.md).

⚠️ **Оговорка (долг верификации):** критерии **A5/T2/T3/T11** (реальный прогон
GitHub Actions) **не проверены** — Actions на аккаунте **заблокирован по биллингу**
(job не стартует; те же 3-секундные падения у прогонов 0062/0082). Блокер внешний,
вне кода. При восстановлении Actions первый push по `v2` подтвердит зелёность либо
вскроет расхождение apt-версий verilator/yosys (единственный неснятый локально
риск). Заведён кандидат «дожать CI-верификацию 0090 после снятия биллинга».

**Язык не менялся** → версия не поднята (правило 22). Исправлений (`docs/fixes/`)
не потребовалось.
