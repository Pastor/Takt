## Краткое описание

Сервер проектов обязан судить **суммарный объём** данных пользователя при каждой
записи — загрузке архива проекта, загрузке и создании файла, копии чужого
проекта — и отказывать, если запись выводит владельца за его квоту. Второе
требование — в проект попадают только файлы тех родов, которые проект
использует: `.takt`, `.takt-ui`, `.takt-map`, `.json`, `.md`; проверка стоит
и при загрузке, и при создании, на сервере и на странице.

Исходная точка (чтение кода 2026-09-12, не прогон — замер снимает ADR):

- **Квоты на пользователя нет.** Пределы есть у файла (64 КиБ), у проекта
  (32 файла, 512 КиБ) и у числа проектов (100 у владельца), то есть
  суммарный объём ограничен лишь их произведением — около 50 МиБ исходников
  на человека, без счёта свёрнутых архивов на диске. Предел числа проектов
  проверяется в трёх местах (создание, загрузка архива, копия) одной и той же
  выпиской — квота обязана встать во все пути записи, включая запись файла.
- **Правило родов уже одно** — `takt_project::check_file_name`; его зовут
  запись и переименование файла и разбор архива (на каждый файл `src/`), база
  держит тот же список ограничением столбца. Пробелы — на краях: поле выбора
  файла на странице не знает `.takt-map` (`accept` перечисляет четыре рода из
  пяти), а страница до отправки проверяет лишь занятость имени, и о чужом
  расширении автор узнаёт отказом сервера.
- **Разбор архива читает файл целиком до сверки с пределом.** Предел тела
  запроса (1 МиБ) ограничивает сжатый архив, а не распакованный: объём,
  который сервер прочтёт в память, задаёт отправитель. Сверка по мере чтения
  — предмет проверки на стадии анализа.
- Файлы архива вне `src/` (манифест, вывод целей) пропускаются молча — это
  законно для вывода, но решение о постороннем содержимом архива принимает ADR.

Вопросы ADR: величина квоты и где она живёт (постоянная рядом с пределами,
настройка стенда либо поле пользователя; иная ли она у администратора); что
считается — исходники по базе (`size_bytes`) или занятое на диске вместе со
свёрнутыми архивами; как квота показывается автору до отказа (занято из
доступного в панели учётной записи); что с владельцем, уже вышедшим за квоту
(чтение и удаление — да, рост — нет). Отказ — прежней формой пределов: число
предела и факт, код ответа `413`.

Рядом стоит кандидат «второй файл в проекте со страницы не завести»: создание
файла со страницы требует того же правила родов, и решать их порознь значило бы
завести второе правило имени на странице.

> Фича зарегистрирована по запросу заказчика 2026-09-12; далее проходит
> жизненный цикл по своду.

### Context

Замер 2026-09-16, чтение кода и проба архива.

- Записей, от которых растёт объём владельца, четыре: запись файла
  (`files.rs::write_file`, она же создание файла со страницы и загрузка файла с
  диска), загрузка архива (`archive_api.rs::import`), копия чужого проекта
  (`grants.rs::fork`) и заведение проекта (`projects.rs::create`, объём нулевой).
  Переименование объёма не меняет, удаление файла и проекта его уменьшает.
- Предел числа проектов считается в трёх местах одной выпиской внутри транзакции,
  но транзакция запирает строку **проекта**. Сумма по владельцу охватывает все его
  проекты, и замок одного проекта двух записей в разные проекты не разводит.
- Файл пишет и тот, кому выдано право правки: данные лежат у **владельца**
  проекта, и квота обязана быть его.
- Разбор архива (`takt_project::unpack`) читает запись целиком
  (`read_to_string`) и лишь затем сверяет размер с пределом файла. Проба: архив
  с одним файлом `src/a.takt` из 500 МиБ одинаковых байтов весит 509 820 Б —
  меньше предела тела запроса (1 МиБ). Полгигабайта в памяти сервера задаёт
  отправитель одним запросом; манифест читается так же.
- Страница: окно «Новый файл» уже есть, ряд родов (`FILE_KINDS`, пять родов) и
  правило алфавита на нём стоят — запись кандидата «второй файл в проекте со
  страницы не завести» устарела. Пробелы остались у загрузки файла с диска:
  `accept` поля выбора перечисляет четыре рода из пяти (нет `.takt-map`), а
  расширение, алфавит имени и размер файла страница не проверяет — автор узнаёт
  о них отказом сервера.
- Занятое место странице неоткуда узнать: `GET /api/me` его не отдаёт.

### Decision Drivers

- D1 — квота одна на владельца и считается по базе (решение заказчика): сумма
  `projects.size_bytes` всех его проектов, свёрнутые включительно.
- D2 — величина — настройка стенда с умолчанием 10 МиБ (решение заказчика).
- D3 — администратор под квотой; сверх квоты запрещён только **рост** объёма
  (решение заказчика): чтение, удаление и запись, не увеличивающая объём,
  разрешены.
- D4 — отказ прежней формой пределов: `413`, код `limit_exceeded`, текст
  называет предел и факт.
- D5 — сверка стоит в транзакции записи и сериализуется по владельцу: иначе квоту
  обходят две вкладки в двух проектах.
- D6 — разбор архива ограничен по мере чтения: в памяти не больше предела файла
  плюс один байт.
- D7 — у страницы один список родов, и `accept` строится из него; список
  сверяется с крейтом проекта проверкой.

### Considered Options

1. **Квота — постоянная в `limits.rs`** — отвергнуто заказчиком: смена величины
   требовала бы выкатки.
2. **Поле квоты у пользователя** — отвергнуто: миграция схемы и ручка правки ради
   возможности, которой не просили.
3. **Настройка стенда `TAKT_WEB_USER_BYTES`** — принято.
4. **Считать занятое на диске** (свёрнутые — размером `.zip`) — отвергнуто
   заказчиком: обход диска на каждой записи, и число зависело бы от того, свёрнут
   ли проект.
5. **Замок — строка `users` под `FOR UPDATE`** — отвергнуто: строку пользователя
   читают вход и `me`, и запись в проект задерживала бы их.
6. **Замок — `pg_advisory_xact_lock` по владельцу** — принято: снимается
   фиксацией транзакции, чужих чтений не держит.
7. **Отказ при любой записи сверх квоты** — отвергнуто заказчиком: владелец,
   вышедший за квоту уменьшением её величины, не мог бы даже сократить файл.

### Decision

- `Config::user_bytes` из `TAKT_WEB_USER_BYTES`, умолчание 10 485 760. Запуск
  отказывает, если величина меньше предела проекта: иначе законный проект
  становится невозможным.
- Модуль `quota.rs` сервера: `lock(транзакция, владелец)` — замок по владельцу;
  `used(транзакция, владелец)` — сумма `size_bytes` его проектов; чистая
  `limits::check_quota(было, станет, квота)` — отказ только при
  `станет > было` и `станет > квота`.
- Сверка стоит в `write_file` (владелец проекта, было минус прежний размер файла
  плюс новый), в `import` (плюс сумма архива) и в `fork` (плюс размер исходного
  проекта). `create` не проверяется: объём не растёт.
- `GET /api/me` отдаёт `used_bytes` и `quota_bytes`; панель учётной записи на
  странице показывает «занято N из M».
- `takt_project::unpack` читает манифест и каждый исходник через
  `Read::take(предел + 1)`: превышение — прежний отказ предела с фактом «больше
  предела».
- Страница: `accept` поля выбора файла строится из `FILE_KINDS`; загрузка с диска
  до рейса проверяет род, алфавит имени и размер тем же правилом, что окно
  «Новый файл»; сверх квоты — отказ сервера показывается как есть.

### Consequences

- Существующие владельцы сверх 10 МиБ данных не теряют: растить объём им нельзя,
  уменьшать можно.
- Квоту проверяет и загрузка архива, и копия — трёх путей роста больше нет.
- Правка файла чужим редактором расходует квоту владельца: это названная граница
  решения.
- Объём, который сервер держит в памяти при разборе архива, ограничен пределом
  проекта, а не отправителем.

#### Acceptance criteria

1. Запись файла, загрузка архива и копия, выводящие владельца за квоту, получают
   `413` с пределом и фактом; в пределе — проходят (проверки с базой).
2. Владелец сверх квоты сокращает файл и удаляет проект; рост — отказ.
3. Две записи одного владельца в два проекта разом квоту не обходят (замок).
4. `me` отдаёт занятое и квоту; страница их показывает.
5. Архив с файлом больше предела отвергается, в память не читая больше предела
   плюс байт (проверка крейта проекта).
6. Страница: `accept` содержит пять родов, загрузка чужого расширения и
   негодного имени отвергается до рейса; список родов сверен с крейтом проекта.

## Анализ

### Цель и контекст

Ограничить объём данных одного человека на сервере проектов и закрыть путь,
которым отправитель задаёт объём памяти сервера. Замер — в ADR.

### Зависимости фичи

Нет. Кандидат «второй файл в проекте со страницы не завести» поглощается:
замер показал, что окно создания файла уже есть, и при закрытии запись
снимается.

### Обратная совместимость

Язык, формат архива и схема базы не меняются. Новое поведение — отказ записи
сверх квоты; ответ `me` получает два поля (страница старой версии их не читает).
Версия языка не поднимается.

Язык не меняется — LSP и плагины не затрагиваются. Панель схемы IntelliJ

### Риски и зависимости

- Размер модуля: `projects.rs` на 995 строках — новое уходит в `quota.rs`.

- Объём `size_bytes` пересчитывается в транзакции записи; сверка читает его в той
  же транзакции под замком владельца.

## Разработка

### Задача — разбор архива по мере чтения

#### Что было

`takt_project::unpack` читал манифест и каждый исходник `read_to_string` целиком и
лишь затем сверял размер с пределом файла.

#### Что сделано

- `read_bounded` в `takt-project/src/archive.rs`: `Read::take(предел + 1)`,
  превышение — отказ предела, не текст UTF-8 — отказ формы. Им читаются и
  манифест, и исходники.
- Тесты: сжатый архив с файлом в 64 МиБ (меньше 1 МиБ по сети) отвергается;
  счётчик байтов подтверждает, что прочитано не больше предела и одного байта;
  файл ровно в предел принимается, на байт больше — нет.

### Задача — квота владельца на сервере

#### Что сделано

- `config.rs`: `user_bytes` из `TAKT_WEB_USER_BYTES` (умолчание 10 МиБ),
  `check_user_bytes` отказывает запуску ниже предела проекта.
- `limits::check_quota(было, станет, квота)` — отказ только при росте сверх
  квоты.
- `quota.rs`: `lock` (`pg_advisory_xact_lock` по владельцу), `used` (сумма
  `size_bytes`), `check` (замок, сумма, правило).
- Сверка в `files.rs::write_file` (квота владельца проекта, прирост — разность
  размеров файла), `archive_api.rs::import` (сумма архива) и
  `grants.rs::fork` (размер исходника); замок берётся после замка строки
  проекта.
- `routes.rs::me`: поля `used_bytes`, `quota_bytes`.
- Набор `tests/quota.rs` (пять проверок) и помощник стенда `execute`.

### Задача — страница

#### Что сделано

- Модуль `web/static/file-kinds.js`: список родов, `kindOf`, `accept`,
  `uploadRefusal`; окно «Новый файл» берёт роды отсюда же.
- `account.js`: `accept` поля выбора строится из списка; загрузка с диска
  проверяет род, имя и размер до рейса; занятое место показывается рядом с
  логином (`#usage`), `api.refreshMe` отдаёт его, не кладя в сеанс.
- `index.html`: у `filepick` нет своего `accept`; узел `usage` в списке узлов
  `app.js`.
- Словари `ru`/`en`: `profile.usage`, `file.badKind`, `file.badUploadName`,
  `file.tooBig`.
- `web-tests.mjs`: сверка родов страницы с `takt-project/src/kind.rs`, отказы
  загрузки до рейса, отсутствие второго списка в разметке; прежние проверки
  родов переведены на новый модуль.

## Отчёт о тестировании

Окружение: macOS, PostgreSQL 18 во временном контейнере, `TAKT_WEB_TEST_DB`
задан, статика собрана `build-web.sh`. Дата — 2026-09-16.

1. `takt-project`: 13 модульных тестов, включая два новых, зелёные; `clippy`
   чистый.
2. Сервер без базы: 58 проверок зелёные (квота, настройка).
3. Сервер с базой: `check-web-server.sh` — все наборы зелёные, набор квоты — пять
   из пяти. Контроль замка: при снятом `lock` проверка двух записей упала в трёх
   прогонах из трёх («раунд 0/1: 200 и 200»); замок возвращён.
4. `check-web.sh`: 152 теста зелёные. Контроль сверки родов: подмена `.md` на
   `.markdown` роняет проверку «роды страницы и крейта разошлись».
5. Живая проверка (сервер на порту 8733, квота 512 КиБ): запись сверх квоты —
   `413`, «объём данных владельца в байтах: предел 524288, получено 540000»;
   меньший файл проходит. Панель: «quota2 занято 508 из 512 КиБ» рядом с
   «Выйти». `accept` — `.takt,.takt-ui,.json,.md,.takt-map`. Загрузка
