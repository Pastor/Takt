## Краткое описание

Сборка PDF документа `book/` формирует **корректные перекрёстные ссылки**
(оглавление, кросс-главные ссылки на приложения) из штатного `make build`: движок
профиля `pdf` переключён на **latexmk** (`-xelatex`), который сам гоняет xelatex до
сходимости меток. Makefile дополнен зависимостью latexmk и путями TeX в PATH.
Инфраструктура сборки — язык не меняется (Tier 3).

> Фича зарегистрирована **2026-07-24 по запросу заказчика**.

## Документирование (правило 24)

**Не требуется** — инфраструктура сборки документа, язык (синтаксис/семантика/
поведение) не меняется. Содержимое разделов `book/` не затронуто.

## Итог (что сделано)

- **`book/book.toml`** — профиль `pdf`: `pdf-engine = "latexmk"`,
  `pdf-engine-opts = ["-xelatex", "-interaction=nonstopmode"]`. latexmk
  перезапускает xelatex до сходимости перекрёстных ссылок (одиночный проход
  оставлял бы «??»/устаревшие номера).
- **`book/Makefile`** — в `deps` добавлен `latexmk`; в PATH добавлены типичные
  каталоги TeX (`/Library/TeX/texbin`, `…/texlive/2026/…`), чтобы `make build`
  находил движок даже когда TeX не в интерактивном PATH; шапка описывает механизм
  сходимости ссылок.

**Живая проверка:** `make build` (в т. ч. с урезанным PATH) собирает PDF;
`pdftotext takt-language.pdf | grep -c '??'` = **0** (кросс-ссылки разрешены);
`precheck.sh` зелёный (сборка PDF в него не входит — зависимости вне precheck).
