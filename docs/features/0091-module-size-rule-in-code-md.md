## Краткое описание

Кандидат 0027 ссылался на «лимит ~1000 (`CLAUDE.md`, `docs/CODE.md`)», но в
`docs/CODE.md` такого правила **нет** — единственный источник `CLAUDE.md:128`, то
есть файл **живого контекста** (правило 9), а не **свод правил кода** (правило 23).

Лечение: перенести правило в `docs/CODE.md`.

Выявлено при [0027](0027-module-size-split.md).

> Фича зарегистрирована **2026-07-17** переводом пункта процессного бэклога.
> Проработана и закрыта **2026-07-22**.

## Итог (что сделано)

**Закрыта 2026-07-22 (`ГОТОВО`).** Реализована **Option A**
[ADR 0091](../adr/0091-module-size-rule-in-code-md.md): правило о размере модуля
(≤ ~1000 строк вместе с тестами, «дели по логике», машинная проверка
`check-module-size.sh`, семантика реестра-долга) перенесено в свод `docs/CODE.md`
(новая секция «Размер модулей», правило 23). В `CLAUDE.md` формулировка заменена
**указателем** на свод, живой контекст (реестр-долг, храповик, выполненные
разделения) сохранён, число файлов реестра актуализировано **22 → 18**.

**Аддитивно:** код, гейт `check-module-size.sh` и реестр `module-size-baseline.txt`
**не тронуты** — правило уже машинно проверяется (0027); 0091 лишь поставило
формулировку на место, устранив вводящую в заблуждение ссылку кандидата 0027 «см.
`docs/CODE.md`». Остаток нарушителей (18 файлов) — незакрытая фича 0088. Версии не
поднимаются.
