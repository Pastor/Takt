## Краткое описание

Потактовых сверок длительностей для целей `st` и `sv` нет. Подробности находки, замеры и оговорки — в разделе «Что известно на
входе»; форма решения определяется стадиями архитектуры и анализа.

**Потактовых сверок длительностей для целей `st` и `sv` нет.** Замер при
закрытии [0183](0183-duration-type-in-targets.md) (2026-07-29):
значения `duration` и вычисляемая выдержка сверяются с эталоном только для целей
`c` и `rust` (`conformance_{c,rust}_duration_tests`). Для `st` и `sv` проверяется
**текст** вывода на конкретные числа миллисекунд плюс прогон `iec2c` и
`verilator`. ⚠️ Это слабее: оба инструмента принимают и молча неверный код —
ровно на этом стояли дефекты 0041 и 0045.
Чего не хватает: обвязки наблюдения — для `st` трансляция MatIEC → C и драйвер к
`POUS.c` с точными именами полей (образец есть в `conformance_st_tests.rs`), для
`sv` тестбенч RTL (образец — `conformance_sv_tests.rs`). Работа механическая, но
не однострочная.

## Документирование (правило 24)

**Не требуется.** Поведение целей не меняется — заводятся сверки уже
описанного: `duration` в целях есть целое число миллисекунд. Новых конструкций
и диагностик фича не вносит.

## Итог (что сделано)

**Значения `duration` сверяются с эталоном у четырёх целей вместо двух.**

- **`st`** — `takt-sim/tests/conformance/conformance_st_duration_tests.rs`: та же
  фикстура, что у `c` и `rust`; порождение → `iec2c` → драйвер на C читает
  `TIMERS0.MS`, `TIMERS0.LATE`, `TIMERS0.ELAPSED` и сверяет с эталоном.
- **`sv`** — `conformance_sv_duration_tests.rs` на своей фикстуре
  `conformance_duration_value_sv.takt`: приведение `as` цель не транслирует
  (`SV-002`), поэтому значение зажимается тремя сравнениями (нижняя граница,
  **равенство**, верхняя) и читается сигналом `elapsed` через тестбенч
  `verilator`. Равенство длительностей не покрыто даже у `c`/`rust`.
- Оба набора — модули темы `conformance` (правило 0244): новых тестовых целей
  не появилось.

**Ценность измерена, а не заявлена.** Порча пересчёта в миллисекунды
(`value_millis`) даёт валидный вывод с другим поведением — `elapsed := pause +
(75)`, `IF (elapsed > (50))`; `iec2c` и `verilator --lint-only -Wall`
принимают его **с кодом 0**, а обе новые сверки краснеют.

**Дефектов не найдено:** обе цели считают верно, сверки заведены сторожем.
