## Краткое описание

Плагин не собирается под системным JDK 25: Kotlin 2.0.21 не разбирает его версию.
Требование к окружению нигде не записано — следующий, кто возьмёт плагин,
потратит время заново. Класс — окружение сборки, не дефект кода.

> Фича зарегистрирована из бэклога кандидатов (отобрана заказчиком 2026-07-28); далее проходит жизненный цикл по правилу 17.

## Что известно на входе

- Kotlin 2.0.21 (`JavaVersion.parse`) не разбирает версию системного JDK
  `25.0.2` → `IllegalArgumentException: 25.0.2` при `compileKotlin`.
- Обходится запуском Gradle под JDK 21 (`JAVA_HOME=<jdk-21>`).
- `jvmToolchain(21)` таргет **не спасает** — падает сам Kotlin-компилятор в
  daemon под JDK 25.
- Плагин вне `precheck.sh`/CI, поэтому машина об этом не скажет.

## Направление решения (наметка, не решение)

- Зафиксировать требование JDK 21 в `extensions/intellij-takt/README` (или
  `org.gradle.java.home` в `gradle.properties`).
- Либо поднять Kotlin до версии, понимающей Java 25, — тогда требование снимется
  вовсе.

⚠️ Окончательный выбор — за стадиями **архитектуры** (ADR) и **анализа**: раздел
выше фиксирует то, что уже проверено, а не предрешает реализацию.

## Документирование (правило 24)

**Не требуется.** Окружение сборки инструмента; язык не меняется.

## Итог (что сделано)

**Требование к JDK стало исполняемым, а не устным.** Сборка плагина проверяет
**пусковой** JDK на этапе конфигурации: ≤ 21 — молчит, 22–24 — предупреждает,
≥ 25 — отказывает с объяснением причины, границы и лечения
(`JAVA_HOME=$(/usr/libexec/java_home -v 21) ./gradlew …`). README плагина
исправлен: разделены **JDK компиляции** (21, скачивается Gradle) и **пусковой**
(из окружения).

⚠️ **Замеры поправили постановку в трёх местах.**
(1) «Не собирается» — уже не так: системный JDK на машине **17.0.19**, сборка
зелёная; проблема стала **невидимой**, а не исчезла.
(2) Граница — **не 25**: Gradle разбирает версии до 27, а обрывается таблица
внутри `kotlin-gradle-plugin` 2.0.21 — на **`JAVA_21`**; 25 было просто той
версией, что стояла на машине.
(3) Ломается **пусковой** JDK, а README говорил про JDK **компиляции** —
`jvmToolchain(21)` его не меняет.

⚠️ **Неизмеренное не запрещается:** 22–24 дают предупреждение, а не отказ —
блокировать возможно рабочую сборку значило бы гадать с обратным знаком.

⚠️ **Проверки выполнены мутацией порогов** (JDK 22+ на машине нет — сказано
прямо), и мутация же нашла изъян: номер версии в подсказке был зашит числом и
разошёлся с границей. Исправлено до коммита, сторож оставлен.
