## Краткое описание

Определить **нормативно** семантику переполнения целых типов и привести к ней
все цели генерации. Сегодня семантика не определена: один и тот же счётчик даёт
разные результаты в разных целях, а порождённый Rust **падает**.

> Фича зарегистрирована из бэклога кандидатов (отобрана заказчиком 2026-07-27); далее проходит жизненный цикл по правилу 17.

## Что известно на входе

Живая проба (аудит 2026-07-27), модель `var t: u8 := 250; always { t := t + 1; }`
— типовая конструкция всех примеров книги (`beacon`, `traffic`, `watchdog`, `lift`):

- **симулятор** — `255 → 0` (wraparound, прогон `takt-sim`);
- **цель `c`** — `uint8_t`, wraparound;
- **цель `sv`** — `logic [7:0]`, wraparound;
- **цель `rust`** — печатает `self.t += 1` и **паникует**:
  `attempt to add with overflow` (проба: `rustc` + драйвер, паника на 6-м такте).
  В release-профиле — молча wraparound, то есть **поведение зависит от профиля
  сборки пользователя**, а в `no_std` паника означает останов системы;
- **цель `st`** — поведение **не проверялось**, проверить в объёме фичи.

Отдельный слой: у языка есть **знаковые** типы (`i8`/`i16`/`i32`,
`semantic/type_node.rs:95`), а знаковое переполнение в C — **UB**.

## Направление решения (наметка, не решение)

- Нормативное правило по образцу правила 3 ADR [0061](0061-fixed-point-type.md)
  (там wraparound для `q(m, n)` зафиксирован **явно**, чтобы автор не принял
  умолчание за обещание).
- Цель `rust`: `wrapping_add`/`wrapping_sub`/`wrapping_mul` в `rust_expr`.
- Цель `c`: для знаковых — `-fwrapv` в контракте сборки либо беззнаковая
  арифметика с приведением.
- Потактовые сверки переполнения во **всех** `conformance_*` (иначе повторится
  урок 0045: «гейт доказывает компилируемость, но не верность»).

⚠️ Окончательный выбор — за стадиями **архитектуры** (ADR) и **анализа**: раздел
выше фиксирует то, что уже проверено, а не предрешает реализацию.

## Документирование (правило 24)

**Требуется.** Раздел `book/` о типах и выражениях: нормативное правило
переполнения + блок «Частые ошибки» (правило 26) со ссылкой на приложение
диагностик. Правило меняет **наблюдаемое поведение** конструкции, поэтому версия
языка растёт (правило 22).

## Итог (что сделано)

- **Правило языка названо** (нормативно, в разделе «Типы» документа):
  переполнение **беззнакового** целого — обёртка по модулю `2ⁿ`; переполнение
  **знакового** — **ошибка программы** (симулятор даёт `SIM-003`, поведение
  порождённого кода языком не гарантируется — в C это UB). Эталон при этом не
  изобретался: правило существовало как S1/S2 анализа
  [0025](0025-simulator-expression-eval.md) и лишь возведено в норму.
- **Цель `rust` приведена к правилу:** беззнаковые `+`, `−`, `*` печатаются как
  `wrapping_add`/`wrapping_sub`/`wrapping_mul`; свёртка в `x += 1` для таких
  узлов отключена (она возвращала бы панику). Прежде прошивка **паниковала** в
  debug-профиле и молча оборачивалась в release — то есть поведение зависело от
  профиля сборки пользователя.
- **Знаковая арифметика намеренно не тронута:** обёртка для неё **не**
  печатается. Тихое расхождение с эталоном (который диагностирует) сочтено
  худшим исходом, чем паника debug-профиля, полезная как сигнал.
- **Проверено исполнением во всех четырёх целях** — потактовые сверки
  `conformance_{c,rust,sv,st}` на общей фикстуре. Для цели **`st` это первая в
  истории проверка поведения при переполнении**: `USINT` именно оборачивается.
- **Сторож взведён:** ручной откат правки генератора роняет сверку `rust` с той
  самой паникой, ради которой фича заводилась.
- **Исправлено неверное утверждение документации:** фраза «арифметика
  выполняется по модулю разрядности типа» распространяла обёртку и на знаковые
  типы, где её нет.
- Отчёт — вердикт **✅ ПРОЙДЕН** (11/11, `precheck.sh` `EXIT=0`, 2194 теста),
  [`docs/reports/0127-int-overflow-semantics.md`](../reports/0127-int-overflow-semantics.md).
- Версия языка **не поднималась**: цикл `0.6.0` открыт фичей 0128 (правило 22 —
  накопление). Порождённый корпус изменился в двух файлах цели `rust`
  (`comprehensive.rs`, `stacker.rs`); вывод остальных целей байт-в-байт прежний.
- ⚠️ **Остаточное следствие:** знаковое переполнение по-прежнему ведёт себя в
  целях по-разному. Это **названо** правилом («программа ошибочна»), но не
  устранено; устранение (проверки в рантайме) отвергнуто по цене и
  невыразимости в RTL.
- **Разблокирует [0134](0134-language-time-model.md)** (модель времени):
  разрядность счётчика времени выбирает компилятор, и теперь у этого выбора есть
  определённая семантика переполнения.
