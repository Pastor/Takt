- **Номер:** 0063
- **Статус:** **ГОТОВО** (2026-07-19, `precheck.sh` зелёный) — см. «Итог (что сделано)» ниже
- **Зависит от:** **нет** (проверено аналитиком 2026-07-17 — см. [анализ](../analyze/0063-sv-clock-enable.md)). Опоры **закрыты**: [0045](0045-sv-backend.md) (каркас `generator/sv/`, `RESERVED_NAMES`, `SV-007`), [0048](0048-deterministic-codegen.md) (критерий A7). ⚠️ **Очерёдность:** вести **после** [0057](0057-sv-sequential-composition.md) — обе правят `always_ff` в `sv_fsm.rs`.
- **Приоритет / Tier:** **Tier 3** — ничего не сломано. ⚠️ Но **обход, обещанный ADR 0045, не существует** (см. итог), поэтому это не чистая косметика: сегодня пользователю, которому нужен автомат на 1 кГц в дизайне на 100 МГц, предложить нечего.

## Краткое описание

Служебный порт `en` с умолчанием `1'b1`, дающий возможность тактировать модель
**реже** тактового домена. Аддитивен поверх принятого решения 0045 (`clk`/`rst_n`
— служебные порты, которых в языке нет).

Вынесено закрытой [0045](0045-sv-backend.md) (ADR, вопрос 1, Option C — признан
«преждевременным, но **не неверным**»).

## Итог проработки (2026-07-17)

**ADR 0045 отверг Option C тремя возражениями. Проработка проверила их пробами —
два из трёх не устояли.**

| # | Возражение ADR 0045 | Вердикт |
|---|---|---|
| 1 | Расширяет зону зарезервированных имён | **в силе** — цена — **одна строка** в `RESERVED_NAMES` (`sv_module.rs:57`); механизм `SV-007` уже есть; имени `en` в корпусе **нет** |
| 2 | «Тот, кому нужен делитель, **добавит его снаружи — одна строка**» | **НЕ УСТОЯЛО** — снаружи clock enable добавить **нельзя**: либо делить `clk` (второй домен → CDC, ровно то, чего Option A избегал), либо клоковый гейт (ICG-ячейки; в FPGA-потоках не рекомендуется, задевает DFT). **Штатный** способ — именно вход `en` |
| 3 | «Усложняет тестбенч и сверку» | **ОПРОВЕРГНУТО пробой** — с умолчанием `en` не подключают, и поведение **побитово** прежнее |

**Аддитивность доказана, а не обещана** (правило 11) — двумя способами, потому что
«принял» ≠ «значит `1`» (урок 0045: `real` verilator принимает молча, петлю yosys
синтезирует молча):

- **Симуляция** (`verilator --binary` — именно им гоняет сверка):
  `en не подключён = 10 | en=1 = 10 | en=0 = 0`;
- **Синтез** (`yosys synth -flatten`): не подключён → **23 ячейки, `8 × $_DFF_PN0_`**
  (без разрешения); `en=1'b1` → **идентично**; `en=1'b0` → **1 ячейка**.

⚠️ **Ловушка самой пробы, стоящая записи:** без `-flatten` `yosys synth` иерархию
не уплощает, константы не распространяются, и все три случая дают одинаковый
результат — проба выглядит проведённой и **не доказывает ничего**. Первый прогон
именно так и выглядел.

**Принято** ([ADR](../adr/0063-sv-clock-enable.md), Option A): `en` с умолчанием
`1'b1` (IEEE 1800 §23.2.2.4); шаг — на `posedge clk` при `en == 1`; **`en` не
гейтит сброс** (иначе модуль нельзя сбросить, пока он не разрешён); `en` — в
`RESERVED_NAMES` → коллизия даёт `SV-007`. Отклонены: обязательный `en` (ломает
всех), флаг генератора (две формы вывода → два пути кода — довод 0059),
статус-кво.

⚠️ **Изменение контракта, названное честно** (правило 11): имя `en` становится
**зарезервированным** — модель с портом `en` перестанет транслироваться целью `sv`.
Корпус свободен; это единственная устоявшая плата.

Язык не меняется (`en` — как `clk`/`rst_n`, в `.lam` не выразим) → версия не
растёт (правило 22).

## Итог (что сделано) — 2026-07-19

**Реализовано ровно по ADR (Option A), одной темой в трёх точках** (отчёт —
[`docs/reports/0063-sv-clock-enable.md`](../reports/0063-sv-clock-enable.md)):

1. **Порт** `input logic en = 1'b1` печатается `emit_module_header`
   (`generator/sv/sv_module.rs`) после `rst_n`, с комментарием «НЕ обязателен».
2. **Гейт шага** — `emit_ff` (`generator/sv/sv_fsm.rs`): `end else begin` →
   `end else if (en) begin`. Ветвь `if (!rst_n)` **не тронута** — `en` не гейтит
   сброс (правило 3 ADR).
3. **Имя `en` зарезервировано** — `RESERVED_NAMES` (`sv_module.rs`) + упоминание в
   тексте `SV-007`.

**Все 7 критериев приёмки закрыты** (таблица в отчёте). Ключевое:

- **A2/A4 доказаны СИМУЛЯЦИЕЙ, а не гейтом** — новый тест
  `conformance_sv_tests::clock_enable_gates_step_but_not_reset` инстанцирует
  **четыре** экземпляра `conformance_ticks` (неподключённый `en` / `en=1` / `en=0`
  / сброс при `en=0`) и `verilator --binary` доказывает: неподключённый `en`
  **побитово** тождествен `en=1` (умолчание держится), `en=0` замораживает
  счётчик, а сброс при `en=0` возвращает `n` к 0. Урок 0045 (гейт принимает
  молча неверное) соблюдён: тест — сторож против мутации «`if (en)` выше `rst_n`».
- **A3** — сверка `sv_trace` инстанцирует `dut` **без** `en`, поэтому 11
  потактовых тестов и есть проверка умолчания; вердикты не изменились.
- **A7** — `examples/generated`: изменились **только** 4 `*.sv` (порт + `else if
  (en)`); прочие цели байт-в-байт прежние, версия не поднята.

⚠️ **Осознанное отклонение от буквы задачи 0063-01:** список чувствительности
`always_ff` **не** менялся на `posedge clk or negedge rst_n`. Цель `sv` использует
**синхронный** сброс (охраняется `mod.rs::reset_is_synchronous`), а нормативное
правило 3 требует лишь структуру `if (!rst_n) … else if (en) …`, которую синхронный
сброс удовлетворяет. Запись задачи `negedge rst_n` — иллюстрация типового
async-паттерна, а не требование к бэкенду.

⚠️ **Устоявшая плата (A-1 ADR):** имя `en` стало зарезервированным для цели `sv`.
Корпус свободен (`grep`), но модель с портом `en` теперь → `SV-007`.
