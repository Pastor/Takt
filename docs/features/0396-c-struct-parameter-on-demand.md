## Краткое описание

- **Структурный параметр цели `c` эмитится всегда, а не по нужде.** Замер
  [0260](0260-c-unused-struct-parameter.md) (2026-08-19): фича
  сняла предупреждения заглушкой `(void)параметр;`, но параметр в сигнатуре
  остался. Точный интерфейс дал бы предикат «нужен ли параметр» по телу —
  **транзитивный вверх** (родитель обязан иметь `main`, если он нужен потомку),
  как `needs_hal` у цели `rust`. Цена: двойной проход генерации либо знание обо
  всех каналах (переменные корня, порты, состояние соседа, время, `userdata`),
  согласование пяти модулей эмиссии и сигнатура, зависящая от тела (правка одной
  строки модели меняет сигнатуры всей цепочки предков). ⚠️ Отвергнуто **по
  цене, а не по существу**: пока заглушка держит оба гейта зелёными, класс
  косметический.

## Архитектура (ADR)

- **Status:** Proposed — исполнителю; **брать по решению заказчика** (класс косметический)
- **Date:** 2026-08-22
- **Authors:** Архитектор + Аналитик
- **Related issues:** [Фича 0396](0396-c-struct-parameter-on-demand.md);
  замер и заглушка — [0260](0260-c-unused-struct-parameter.md#архитектура-adr); образец предиката —
  `needs_hal` цели `rust` ([0050](0050-rust-backend.md#архитектура-adr))

### Context

Протокол вызова цели `c` единообразен: под-модель получает `main`,
пользовательская функция — `model`, помощник HAL — `m`. Тело пользуется ими не
всегда; фича 0260 погасила предупреждения заглушкой `(void)параметр;`, но
параметр в сигнатуре остался.

Замер **переснят 2026-08-22** по корпусу: в `examples/generated/c/` **53**
заглушки — то есть 53 места, где параметр передаётся и не используется.

⚠️ Оба гейта цели (`cmake` корпуса и `cc -c` для `c-hal`) зелены: заглушка
делает вывод валидным. Класс **косметический** — цена в интерфейсе и в
читаемости порождённого кода, а не в валидности.

### Decision Drivers

1. **Точный интерфейс лучше, но не бесплатен:** предикат «нужен ли параметр»
   **транзитивен вверх** — родитель обязан иметь `main`, если он нужен потомку.
2. **Сигнатура начинает зависеть от тела:** правка одной строки модели меняет
   сигнатуры всей цепочки предков — диффы порождённого кода станут шире.
3. **Знание о каналах:** «нужен ли `main`» складывается из переменных корня,
   портов, состояния соседа (0267), времени и `userdata` — пять источников,
   каждый со своим обходом.
4. **Образец есть:** `needs_hal` цели `rust` решает ровно такую задачу и
   работает; риск известен и ограничен.

### Considered Options

#### Option A. Оставить заглушки (статус-кво)

**Pros:** ноль работы; гейты зелены; вывод стабилен.
**Cons:** 53 лишних параметра и заглушки в корпусе; читателю прошивки видно
«параметр, который не нужен».

#### Option B. Предикат «нужен ли параметр», транзитивный вверх

По образцу `needs_hal`: обход тела + сумма по вызываемым.

**Pros:** точный интерфейс; заглушки исчезают вместе с параметрами.
**Cons:** двойной проход генерации (сигнатуру надо знать до печати тела, а
предикат считается по телу); согласование пяти модулей эмиссии; вывод корпуса
поедет целиком — снапшоты обновляются разом.

#### Option C. Печатать параметр, но помечать `__attribute__((unused))`

**Cons:** расширение GNU — цель `c` держится C11 (0284 отвергла расширение по
той же причине).

### Decision

**Предлагается Option B**, но брать фичу — **по решению заказчика**: класс
косметический, а цена (двойной проход, пять модулей, полный сдвиг снапшотов)
сопоставима с ценой языковых фич.

⚠️ Если Option B принимается, предикат обязан быть **одним** носителем и
считаться так же, как `needs_hal` — иначе два правила «нужен ли параметр»
разъедутся (класс 0084/0193/0195).

### Consequences

#### Положительные (B)

- Сигнатуры порождённых функций отражают их зависимости; 53 заглушки исчезают.

#### Отрицательные / Action items

- Снапшоты `examples/generated/c` обновляются целиком — один большой дифф.
- Сигнатура зависит от тела: правка модели меняет интерфейс цепочки предков.
- Гейт детерминированности (0048) обязан остаться зелёным: предикат считается
  по `BTreeMap`-обходам, иначе порядок поедет.

#### Acceptance criteria

1. Параметр печатается только там, где тело (или вызываемые им) им пользуется.
2. Заглушек `(void)параметр;` в выводе не остаётся (кроме случаев, где параметр
   всё-таки нужен по одному из каналов, но не назван в тексте).
3. Оба гейта цели `c` зелены без исключений по флагам.
4. Потактовые сверки не изменились — поведение прежнее.
5. Снапшоты корпуса обновлены одним диффом; `precheck.sh` зелёный.

## Анализ

### Цель и контекст

Цель `c` передаёт структурный параметр (`main`, `model`, `m`) всегда, а гасит
неиспользование заглушкой (0260). Фича делает интерфейс точным.

### Замер (правило 30, переснят 2026-08-22)

- **53 заглушки** `(void)параметр;` в `examples/generated/c/` — столько мест
  принимают параметр и не пользуются им;
- оба гейта цели зелены: класс **косметический**, вывод валиден;
- образец решения — `needs_hal` цели `rust`, работающий с 0050.

### Зависимости фичи (правило 17/19)

- **Зависит от:** нет; опорная [0260](0260-c-unused-struct-parameter.md)
  закрыта.
- **Влияние на порядок:** брать по решению заказчика — цена сопоставима с
  языковой фичей, польза косметическая.

### Требования и проверяемые условия

- **R1.** Параметр печатается только по нужде; предикат транзитивен вверх.
- **R2.** Предикат — **один** носитель (как `needs_hal`), а не копия в каждом
  модуле эмиссии.
- **R3.** Поведение не изменилось: все потактовые сверки зелены.
- **R4.** Оба гейта цели `c` зелены **без** исключений по флагам.
- **R5.** Детерминированность вывода сохранена (инвариант 0048).
- **R6.** Снапшоты корпуса обновлены осознанно, одним диффом.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | R1 | греп по выводу: параметр отсутствует там, где не используется |
| A2 | R2 | чтение + мутация (вторая копия предиката ломает вывод) |
| A3 | R3 | `takt-sim/tests/conformance/` целиком |
| A4 | R4 | гейты предкоммита |
| A5 | R5 | двойной прогон генерации + `diff -r` (гейт 0048) |
| A6 | R6 | ревью диффа снапшотов |

### Объём работ

| Место | Что делается | Риск |
|---|---|---|
| предикат «нужен ли параметр» | новый носитель, транзитивный по вызовам | средний |
| пять модулей эмиссии цели `c` | сигнатура и вызов согласуются | **высокий**: разъезд даёт невалидный C |
| снапшоты | обновление корпуса целиком | низкий, но дифф широкий |

⚠️ **Двойной проход:** сигнатуру надо знать до печати тела, а предикат
считается по телу. У цели `rust` эта задача решена (`function_needs`) — образец
есть.

### Редакторский слой (правило 29)

**Не применимо:** предмет — форма вывода одной цели.

### Особенности по обратной функциональности

Сигнатуры порождённых функций — **внутренний** интерфейс модуля цели `c`
(функции `static`), поэтому пользовательский код не задет. Исключение —
помощники HAL (`<Root>_bind_default_hal` и подобные): они видны пользователю,
и их сигнатуру трогать нельзя.

### Риски и зависимости

- **Разъезд сигнатуры и вызова** — даёт невалидный C; сторож обязан собирать
  вывод, а не только сравнивать текст.
- **Ширина диффа снапшотов** маскирует посторонние изменения: обновлять
  корпус надо отдельным коммитом.
