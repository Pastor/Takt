# Фича 0406: Комментарий перед блочным оператором уезжает внутрь блока

- **Номер:** 0406
- **Статус:** СОЗДАНА
- **Зависит от:** нет
- **Tier:** 3
- **Класс:** синтаксис
- **Связанные issue (анализ):** находка фичи [0405](0405-format-formula-assembly.md)

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32). Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Комментарий, написанный **перед блочным оператором**, форматтер переносит
внутрь его тела. Замер 2026-08-23 (прогон `taktc fmt --stdin`):

```takt
a := 1;

// комментарий перед if
if a > 0 {
    a := 2;
}
```

печатается как

```takt
a := 1;
if a > 0 {

    // комментарий перед if
    a := 2;
}
```

Комментарий сменил хозяина: он относился к оператору, а стал первой строкой
его тела. Пустая строка перед оператором при этом теряется.

## Документирование (правило 24)

Языка фича не меняет — раздел `book/` правки не требует. ⚠️ Проверить придётся
раздел «Комментарии» свода стиля: если он обещает сохранение привязки, обещание
станет исполняемым, а не декларативным.

## Заметки к проработке

- **Класс известен и правился трижды** — фичи 0198 (операторы), 0197-01
  (перечисление), 0198-01 (структура), 0295 (закрывающая скобка тела). Здесь
  четвёртое место: **заголовок блочного оператора**.
- Причина видна в коде: `stmt::block_with_head` печатает заголовок через
  `out.line`, то есть **без позиции узла**, поэтому ведущие комментарии не
  выдаются перед ним и всплывают внутри тела. У неблочных операторов заголовок
  идёт через `out.node_line(loc, …)`, и там привязка верна.
- ⚠️ Правка затронет **все** блочные операторы (`if`, `while`/`loop`, `for`,
  ветви `match`, именованные блоки, тела функций, `assembly`, `formula`),
  то есть может изменить вывод форматтера на живом корпусе — снимки
  `examples/generated/` и канон `examples/` придётся пересобрать вместе с ней.
- ⚠️ Проверять надо **отступ** комментария, а не порядок строк: уезжая внутрь
  тела, комментарии сохраняют взаимный порядок и проверка порядка дефект не
  ловит (урок фичи 0295).
