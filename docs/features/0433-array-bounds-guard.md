# Фича 0433: Проверка границ массива: статическая диагностика и guard в порождённом коде по флагу

- **Номер:** 0433
- **Статус:** СОЗДАНА
- **Зависит от:** <проставляет аналитик на стадии анализа, правило 17>
- **Tier:** 1 — инструменты противоречат друг другу молча: один вход даёт **пять** разных поведений, и ни один инструмент не жалуется
- **Класс:** генерация
- **Связанные issue (анализ):** запрос заказчика 2026-08-23

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32).

## Краткое описание

**Запрос заказчика 2026-08-23:** «Мы в процессе компиляции (трансляции) с языка
Takt знаем размер массивов и поэтому статически можем проверить выход за
границу массивов, выставив guard в транслируемый код — это всё по флагу».

Размер массива известен компилятору всегда (он часть типа), а индекс бывает
переменным — и тогда каждый потребитель ведёт себя по-своему, вплоть до
неопределённого поведения в прошивке.

## Замер (правило 30, 2026-08-23)

Вход: `var data: [u8; 3] := {1, 2, 3};` и `probe := data[i];`, где `i` растёт
на единицу каждый такт (то есть с третьего такта индекс выходит за границу).

| Потребитель | Трасса `probe` по тактам | Что происходит |
|---|---|---|
| эталон | `2 3` → **`SIM-010`** | останов с диагностикой |
| **`c`, `c-hal`** | `2 3 3 1 0` | **чтение за границей массива** — неопределённое поведение; `cc -Werror` молчит |
| **`rust`** | `2 3` → **паника** | `index out of bounds: the len is 3 but the index is 3` |
| **`st`, `st-at`** | `2 3 0 4 0` | чтение по правилам MatIEC |
| **`sv`, `sv-mmio`** | `2 3 0 1 2` | индекс **усечён** по ширине (0365) — циклический доступ |

⚠️ **Литеральный** индекс вне границ уже отвергает семантика (`SE-028`):
`data[7]` при `[u8; 3]` — ошибка компиляции.

### Второй предмет: КОНСТАНТА в позиции индекса и разряда (уточнение заказчика 2026-08-23)

> «То же самое можно сделать и к обращению к конкретному биту. Если есть
> константа (не переменная) и можно в семантическом анализе проверить
> статически выход за границу массива (границу области памяти) — выдавать
> ошибку».

Замер 2026-08-23 показал, что проверка обрывается на **литерале**: значение
константы компилятору известно (её инициализатор свёрнут на стадии 2, фича
0192), а проверка на него не смотрит.

| Запись | Ожидание | Что сейчас |
|---|---|---|
| `d[7]` при `[u8; 3]` | ошибка | **`SE-028`** ✅ |
| `d[K]` при `const K: u8 := 5` | ошибка | **принимается молча**; эталон отвечает `SIM-010` в такте, а прошивка `c` читает за границей ❌ |
| `x.70` при `x: u8` | ошибка | **`SE-125`** ✅ |
| `s.f.70` при поле `u8` | ошибка | **`SE-125`** ✅ |
| `#0x100.70` (ячейка) | ошибка | **`SE-098`** ✅ |
| `x.B` при `const B: u8 := 70` | ошибка | **принимается молча** ❌ |
| `x.b` при `var b: u8 := 70` | рантайм | `SIM-011` в такте — переменная, статически недоказуемо |

То есть **две** проверки (`SE-028` для индекса, `SE-125`/`SE-098` для разряда)
обрывают разбор на литерале, хотя значение константы известно тем же
вычислителем, что сворачивает инициализаторы. Уточнение заказчика сводится к
одному правилу: **проверка смотрит на значение, а не на форму записи**.

⚠️ Ни один инструмент цели не возражает: `cc -Wall -Wextra -Werror`,
`iec2c`, `rustc`, `verilator`, `yosys` вывод принимают, `taktc` возвращает
ноль.

## Что предстоит решить (стадия 2, ADR)

1. **Поведение guard при нарушении.** Варианты: пропустить операцию (чтение
   даёт нуль, запись не выполняется), прижать индекс к границе, остановить
   автомат (перевести в терминальное состояние), сообщить наружу через HAL.
   Выбор — решение заказчика: это наблюдаемое поведение прошивки, а не
   деталь печати.
2. **Флаг и его умолчание.** Guard стоит тактов и вентилей, поэтому включение
   по умолчанию изменило бы вывод всего корпуса и цену прошивки; выключение по
   умолчанию оставляет опасное поведение штатным. Имя флага и умолчание —
   часть решения.
3. **Область.** Все ли цели (`c`, `c-hal`, `rust`, `st`, `st-at`, `sv`,
   `sv-mmio`), и что делает эталон: у него guard **всегда включён**
   (`SIM-010`), и это уже расхождение с флагом «выключено».
4. **Статическая часть.** Индекс, чей диапазон доказуем (переменная цикла
   `for` с литеральными границами, 0321; индекс, ограниченный сравнением на
   ребре), guard не требует — вопрос, доказывать ли это в первой редакции или
   оставить «guard на каждый переменный индекс».
5. **Константа против литерала.** Правило «значение известно ⇒ проверяем»
   должно действовать в обеих проверках (`SE-028` и `SE-125`/`SE-098`), а
   вычислитель для этого уже есть (`const_eval`, 0192/0208). Вопрос — какой
   диагностикой отвечать: прежними кодами (текст назовёт значение) или новыми.
6. **Запись против чтения.** Запись за границей опаснее: у цели `c` это порча
   соседнего поля структуры. Возможно, для записи guard обязателен даже при
   выключенном флаге.

## Документирование (правило 24)

**Требует решения на стадии анализа.** Поведение при выходе за границу —
наблюдаемое свойство языка: если guard меняет исполнение (пропуск, прижатие,
останов), это описывается в [`book/`](../../book/) наравне с семантикой
переполнения (0127). Флаг компилятора в документ языка не попадает (правило
24), но его следствие — попадает.
