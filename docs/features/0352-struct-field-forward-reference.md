## Краткое описание

Тип поля структуры разрешается **в порядке текста**, поэтому ссылка на тип,
объявленный **ниже**, не разрешается вовсе: `construct_type` возвращает ошибку,
а вызывающий подменяет её `TypeNode::Unsupported`
(`tree.rs`, `.unwrap_or(TypeNode::Unsupported)`).

**Замер 2026-08-21** (`scripts/probe.sh -n 3`):

| Вход | эталон | цели |
|---|---|---|
| `struct Aa { b: Bb }` **выше** `struct Bb { m: u8 }` | `v=Aa{b=0,n=0}` — поле-структура стала **числом** | `c`/`c-hal` `CC-015`, `st`/`st-at` `ST-002`, `rust` `RS-014`, `sv`/`sv-mmio` `SV-002`, `plantuml` OK |
| `struct Cfg { m: Mode }` выше `enum Mode` | то же | то же |
| `struct Holder { cells: [Cell; 2] }` выше `struct Cell` | то же | то же |
| `type Alias = Point;` выше `struct Point` | — | **`SE-034`** «Локальный тип 'Point' не найден» — тип есть, объявлен ниже |

⚠️ **Контрольный вход** (правило 30): тот же файл с **обратным** порядком
объявлений принимают все девять потребителей — значит ломает **порядок**, а не
форма записи.

⚠️ **Эталон хуже целей:** он не отказывает, а **молча** подменяет тип поля,
то есть модель исполняется с другим устройством данных.

Документ (`book/`, раздел «Типы») правила порядка для **типов** не задаёт вовсе:
там описан порядок **значений** (переменная ссылается назад — `SE-109`,
константа свободна). Пробел заполняется в пользу «тип виден во всём файле» —
как у констант.

Второй предмет — **цикл структур**: `struct A { b: B }` и `struct B { a: A }`.
Сегодня запись принимается семантикой, а после снятия зависимости от порядка
она станет **разрешаемой**, то есть даст тип бесконечного размера. Вводится
диагностика **`SE-124`**.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл
> по правилу 17.

## Документирование (правило 24)

**Требуется.** Раздел [`book/src/03-types/`](../../book/src/03-types/) описывает
порядок объявлений для **значений** и молчит о **типах**. Добавляется абзац:
имя типа видно во всём файле независимо от места объявления (как у констант), а
структура, содержащая себя прямо или через цепочку полей, отвергается —
с кодом в блоке «Частые ошибки» (правило 26) и записью в приложении «Ошибки и
предупреждения» (правило 25).

## Итог (что сделано)

**Порядок объявления типов перестал быть значимым, а структура больше не может
содержать себя.** Версия языка `0.10.0` → `0.11.0`.

- **Имена всех типов занимаются предпроходом** (`type_registry::predeclare_named_types`
  — воронка 0243 переехала выше по конвейеру), псевдонимы разрешаются **до
  неподвижной точки**. Прежде объявления строились одним проходом в порядке
  текста, и ломались **пять** форм: поле-структура, поле-перечисление, элемент
  массива, псевдоним на структуру, псевдоним на псевдоним.
- **Подмена ошибки снята:** `construct_type(...).unwrap_or(TypeNode::Unsupported)`
  глотал диагностику, из-за чего эталон исполнял модель с полем-структурой,
  ставшей числом, — молча.
- **`SE-124`** (`validate/struct_cycle.rs`): цикл структур, в том числе через
  элемент массива и через псевдоним. Пока порядок был значим, такая запись была
  **недостижима**; снятие зависимости сделало её разрешимой, поэтому запрет
  введён той же фичей.
- ⚠️ **Завершение разрешения псевдонимов держит `SE-039`** — она отсекает
  циклы среди них раньше. Зависимость по порядку проверок, в коде не видная.
- ⚠️ **Сторож на пару псевдонимов оказался недостаточным:** мутация «один виток
  вместо повторения» его не роняла, потому что финальная попытка служит вторым
  проходом. Настоящий сторож — цепочка из **трёх**.
- Заведён кандидат: цель `c` не обнуляет переменные без инициализатора вовсе
  (мусор стека), тогда как эталон и семь остальных целей дают ноль.
