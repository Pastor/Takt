## Краткое описание

Довести конвейер верификации до рабочего: проверять LTL-свойства модели (`: [LTL]
φ;`) методом model checking. Затравка (`verification/`) даёт **два звена** — тип
`Ltl` и построение автомата Бюхи `build_buchi` (GPVW). Отсутствует **середина**:
структура Крипке из `ModelNode`, произведение с автоматом `¬φ`, проверка пустоты
(достижимый принимающий цикл), контрпример-лассо и подкоманда `lamc verify`.

По решению заказчика (2026-07-16) принята **абстракция управляющего графа**: атом
LTL — **имя состояния** FSM («автомат сейчас в состоянии S»); структура Крипке —
граф переходов автомата (состояния + рёбра `ref`), данные абстрагированы.
Проверяемы порядок состояний, достижимость, живость (`G(Fault -> F Idle)`);
свойства над данными (`G(temp <= 100)`) — вне охвата, будущее расширение.

> заказчика 2026-07-16); проходит жизненный цикл по правилу 17.

## Состояние разработки (2026-07-16)

> Раздел — история стадий. Сводка закрытой фичи — в «Итоге» ниже (правило 21).

Задачи `0049-01`…`0049-06` реализованы; тест-план (T1–T47) сформирован и
пройден; отчёт выпущен; фича закрыта. Задача `0049-06` заведена **после** ревью
стадии тестирования (решение заказчика по области формулы состояния — вариант
«б»), фича на неё возвращалась в `РАЗРАБОТКА`.

Что сделано: `lamc verify [--property "φ"] [--trace] <file>`; модули
`verification/{kripke,product,check,verify}.rs`; публичный API `verify_model` /
`verify_all` / `parse_ltl_property`; фикстуры `tests/data/verify/` (примеры и
контрпримеры); 48 новых тестов; раздел README с прогнанными пробой примерами.

**Побочный результат — дефект затравки.** Задача 0049-02 вскрыла зондом, что
`build_buchi` (фича 0010) принимал **любой** бесконечный прогон: автомат `F p`
принимал слово, где `p` не наступает. Без исправления первый же вердикт
`lamc verify` был бы ложным на классе свойств живости. Правка — фикс
[0010-01](../fixes/0010-01-buchi-acceptance.md). Дефект прожил в зелёном CI с
0010, потому что у затравки не было потребителя, а её тесты проверяли структуру
автомата, а не принимаемый язык.

**Отступление от ADR (обосновано):** `SE-055` не снят для проверяемых формул, а
**переформулирован** (текст указывает на `lamc verify`). Причина: потребитель
появился у отдельной подкоманды, а `lamc compile` LTL по-прежнему не проверяет;
снятие вернуло бы класс дефекта, закрытый фичей 0035 (формула молча ничего не
делает). Детали — [0049-05](../development/0049-05-docs-tests.md).

### Найдено ревью и исправлено (до отчёта)

- **Недо-аппроксимация Крипке — `Holds` был неверен.** Самопетля ставилась
  только состоянию **без рёбер**. Но такт, в котором ни один guard не сработал,
  состояния не меняет (эталон — порождённый C: `if (cond) {…break;} break;`),
  поэтому состояние, все выходы которого условны, вправе стоять на месте вечно.
  Этот прогон в Крипке отсутствовал → множество прогонов было **меньше**
  реального → `F Done` на `start A { ref Done: x = 1; }` объявлялось
  **доказанным**, хотя автомат вправе никогда не уйти из `A`. Сломана была
  ровно главная гарантия фичи. Исправлено: самопетля ставится, если нет
  **безусловного** `ref` (`kripke.rs::may_stutter`); `next` состояния-реализации
  безусловным выходом не считается (вложенная модель может не завершиться).
  Закреплено юнит-тестами против эталона C.
- **`--property` со своей `;` молча усекался** до первой формулы
  (`-p "F Done; : [LTL] G Idle"` → «проверено: F Done»). Теперь отказ: строка
  обязана разбираться ровно в одну формулу.
- **Повторный `--property`** молча затирал первый — теперь отказ.

### Открытые вопросы стадии тестирования — решения заказчика (2026-07-16)

Найдены ревью; **не** дефекты реализации — неопределённости семантики, которых
ADR не касался. Все три вынесены заказчику и закрыты:

1. **Область формулы состояния** → вариант **«б»**: `: [LTL] φ;` в теле
   состояния `S` — сокращение для `G (S -> φ)`. Потребовало доработки: задача
   [0049-06](../development/0049-06-state-formula-scope.md).
2. **Импортированные модели** → вариант **«а»**: проверяются все модели файла,
   включая импортированные; поведение задокументировано (README, «Ограничения»).
   Сужение области (`--scope`) — кандидат в фичи.
3. **Глубина рекурсии** → вариант **«а»**: обходы остаются рекурсивными
   (замер: 3000 состояний — норма, 20000 — падение); ограничение
   задокументировано, итеративный обход — кандидат в фичи.

## Итог (что сделано)

Фича **закрыта** 2026-07-16. Отчёт о тестировании —
[`docs/reports/0049-model-checking-ltl.md`](../reports/0049-model-checking-ltl.md)
(вердикт «готово»: T1–T47 пройдены, `precheck.sh` зелёный, 1618 тестов).

**Крейт `grammar`.** Конвейер верификации доведён до рабочего: `build_kripke` →
`build_buchi(¬φ)` → `product` → `emptiness` (nested-DFS) → `Verdict`
(`verification/{kripke,product,check,verify}.rs`); публичный API `verify_model` /
`verify_all` / `parse_ltl_property`; подкоманда `lamc verify [--property "φ"]
[--trace]` (код возврата `0`/`1` — пригодно для CI). Абстракция — управляющий
граф (ADR 0049, Option A): атом = имя состояния, условия рёбер и данные
абстрагированы. Отсюда несимметричность вердикта: `Holds` надёжен, `Violated`
может быть ложным срабатыванием, атом-переменная даёт честный `Unsupported`, а
не молчаливое «ложно». Версия языка не менялась (0.3.0), вывод генераторов
неизменен.

**Ключевые решения и правки:**

- **Фикс затравки [0010-01](../fixes/0010-01-buchi-acceptance.md)** — `build_buchi`
  принимал **любой** бесконечный прогон (`F p` принимал слово без `p`). Прожил в
  зелёном CI с фичи 0010: тесты проверяли структуру автомата, а не язык, и
  потребителя у затравки не было.
- **Самопетля — не только у тупика** (`kripke.rs::may_stutter`): её получает
  всякое состояние без **безусловного** `ref`. Первая редакция ставила петлю
  лишь вершине без рёбер → Крипке была **недо**-аппроксимацией → ложный
  `Holds`, то есть сломана главная гарантия фичи.
- **Область формулы состояния** — `G (S -> φ)` (0049-06, решение заказчика):
  десахаризация живёт у верификатора, а не у сборщика формул, потому что
  второму потребителю сборщика (диагностикам SE-055/SE-056) нужна **авторская**
  формула.
- **`SE-055` не снят, а переформулирован** (текст указывает на `lamc verify`):
  `lamc compile` LTL по-прежнему не проверяет, и молчать об этом нельзя.

**Живая проверка:** `lamc verify` прогнан на корпусе `examples/` (завершается на
всех) и на 7 фикстурах-примерах/контрпримерах `grammar/tests/data/verify/`,
попавших в README (правило 16).
