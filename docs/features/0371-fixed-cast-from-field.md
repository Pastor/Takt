## Краткое описание

Замер 2026-08-21 на `one := g.kp as u8;` при `struct Gains { kp: q(8, 8), … }`
и `g.kp = 1.5`:

| Потребитель | Печать | Значение |
|---|---|---|
| эталон | — | **1** |
| `c`, `c-hal` | `(uint8_t)model->g.kp` | **128** |
| `rust` | `self.g.kp as u8` | **128** |
| `sv`, `sv-mmio` | `8'(…g.kp)` | **128** |
| `st`, `st-at` | `INT_TO_USINT(g.kp)` | **128** |

Все четыре цели теряли **масштабирование** (деление на 2ⁿ), и все — молча, при
нулевом коде возврата `taktc`. На выражении над полями (`(g.kp + g.ki) as u8`)
цель `st` вдобавок отказывала `ST-011`.

⚠️ Контроль: та же запись **над переменной** (`(a + b) as u8`) печатается
верно у всех целей — тип терялся именно у поля.

## Документирование (правило 24)

**Не требуется** — язык не меняется: запись законна и исполняется эталоном;
правится вывод типа операнда у четырёх целей и в семантике.

## Итог (что сделано)

- Приведение `q → целое` из поля структуры, из выражения над полями и из поля
  элемента массива **масштабируется** у всех четырёх целей.
- ⚠️ **Класс был у четырёх целей сразу и молчал у всех:** вывод валиден,
  значение неверно (128 против 1). Вердикт дала только потактовая сверка.
- ⚠️ **Одной правки в семантике мало:** тип операнда выводят четыре носителя, и
  каждый пришлось научить полю. Их сведение вынесено кандидатом.
- ⚠️ Доступ к разряду (`x.N`) не трогался — его тип есть вопрос правила 0356.
- Побочно снят отказ `ST-011` на выражении над полями; вывод корпуса не
  изменился.
