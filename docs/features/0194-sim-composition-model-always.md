## Краткое описание

Фича [0083](0083-model-always-block-c.md) установила: тело `always` на уровне
модели исполняется **каждый такт** — в эталоне и во всех целях. У модели, чьё
состояние есть композиция, эталон его **не исполняет вовсе**, а цель `c`
исполняет. Расхождение молчаливое: обе стороны работают и рапортуют успех.

> Фича зарегистрирована из бэклога кандидатов (решение заказчика 2026-08-02:
> Tier-1 находки переводятся в фичи вперёд Tier 2); далее проходит жизненный
> цикл по правилу 17.

## Что известно на входе

Перепроверено пробой 2026-08-02, находка жива. Вход:
`var probe: u8 := 0; model Tuner { … } always { probe := probe + 1; } start Main = Tuner | Tuner;`

| Сторона | Результат |
|---|---|
| эталон | `probe = 0` на всех тактах |
| цель `c` | `model->probe = model->probe + 1;` в теле такта |

- То же с **именованной** моделью-композицией (`start Main = Tuner \| Tuner;`
  внутри `model Root2 { … always { … } }`).
- У модели со **своими** состояниями (`always { … } start S { … }`) блок
  исполняется верно — то есть дефект в ветви, где такт модели уходит в
  композицию, и тело модели-владельца до исполнения не доезжает.
- ⚠️ Корпус класс **не покрывает**: `always` на уровне модели есть только у
  моделей со своими состояниями.
- ⚠️ Урок фикса 0181-01: тела корпуса идемпотентны (`x := <выражение>`), и на
  них лишнее либо пропущенное исполнение **неразличимо**. Сторож обязан стоять
  на **накапливающем** теле (`probe := probe + 1`).

## Направление решения (наметка, не решение)

- Правка эталона (`takt-sim`), а не целей: контракт 0083 уже принят, и цель `c`
  ему следует.
- ⚠️ Осторожно с направлением ошибки: соседний фикс
  [0181-01](../fixes/0181-01-sim-parallel-always-twice.md) снял **двойное**
  исполнение `always` у композиции (`Unit::execution` в дочерние юниты не
  спускается). Починка обязана дать ровно **одно** исполнение за такт — и это
  надо доказать значением, а не фактом наличия кода.
- Сторож — значенческая сверка sim ≡ `c` на накапливающем теле, по образцу
  `takt-sim/tests/sequential_composition_tests.rs`.

⚠️ Окончательный выбор — за стадиями **архитектуры** (ADR) и **анализа**.

## Документирование (правило 24)

**Не требуется.** Правило «model-level `always` исполняется каждый такт» уже
описано и не меняется — фича приводит эталон в соответствие с ним. Если анализ
покажет, что для композиции правило требует **уточнения** формулировки, раздел
о композиции придётся освежить; решение принимается на стадии анализа.
