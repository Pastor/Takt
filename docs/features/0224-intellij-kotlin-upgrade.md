**Подъём Kotlin в плагине `intellij-takt` снял бы ограничение на пусковой JDK.**
Вскрыто при закрытии [0159](0159-intellij-jdk21-build.md)
(2026-07-29). Таблица версий Java внутри `kotlin-gradle-plugin` **2.0.21**
обрывается на `JAVA_21` (замер: чтение класса commons-lang3 `JavaVersion` из
jar), поэтому пусковой JDK новее ломает `compileKotlin`. Более свежий Kotlin
ограничение снял бы вовсе. ⚠️ Не сделано в 0159 по трём причинам: нужна **сеть**;
нужна проверка совместимости с `org.jetbrains.intellij.platform` 2.1.0 и
платформой 2024.2; и **проверить исход нечем** — JDK 22+ на машине нет, то есть
«починка» осталась бы недоказанной.

## Итог (что сделано)

Ограничение на **пусковой** JDK сборки плагина снято: сборка и все 90 тестов
проходят под JDK **17** и **26** (прежде верхней границей был 21).

⚠️ **Гипотеза, из которой заведена фича, оказалась неверна.** Кандидат винил
`kotlin-gradle-plugin` 2.0.21; проба показала, что падал **встроенный в Gradle**
компилятор Kotlin-скриптов — тот, что компилирует сам `build.gradle.kts`, то
есть до применения `kotlin("jvm")`. Независимая проверка: таблица версий Java
даже у Kotlin 2.4.10 обрывается на `JAVA_24`, значит подъём одного Kotlin JDK 26
не покрыл бы. Лечение — подъём связки: **Gradle 8.10.2 → 9.7.0**, плагин
**`org.jetbrains.intellij.platform` 2.1.0 → 2.18.1**, **Kotlin 2.0.21 → 2.4.10**
(последний — ради предупреждений «legacy Usage attribute», обещающих отказ на
Gradle 10).

Побочно: форма списка IDE верификатора заменена вынужденно (`ide("IC-…")` в
2.18.1 нет), и её эквивалентность доказана прогоном — `verifyPlugin` даёт **три**
верификации, все `Compatible`. Преflight-проверка перезамерена (жёсткого отказа
на неизмеренной версии больше нет), скрипт установки перестал искать именно
JDK 17 и следит за диапазоном, README и живой контекст приведены в соответствие.
`platformVersion`, `sinceBuild` и круг совместимых IDE не менялись.
