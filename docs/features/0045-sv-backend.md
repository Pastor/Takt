# Фича 0045: Бэкенд генерации в SystemVerilog

- **Номер:** 0045
- **Статус:** РАЗРАБОТКА
- **Зависит от:** `нет` — проверены 0020, 0026, 0029, 0031, 0033, 0041;
  содержательных зависимостей не найдено (разбор — [анализ](../analyze/0045-sv-backend.md),
  раздел «Зависимости фичи»). Статус **`ЗАБЛОКИРОВАНА` не ставится**, фичу можно
  брать в работу сразу.
- **Приоритет / Tier:** **Tier 2 (высокий)** — профильная фича (правило 12),
  заведена **по прямому запросу заказчика**. Открывает **аппаратный контур**
  промышленного управления (FPGA/ASIC: жёсткое реальное время, аппаратные
  блокировки безопасности), не покрытый ни одной существующей целью. Ниже Tier 1
  фичи [0041](0041-st-backend.md) (ST/ПЛК — доминирующая платформа отрасли и
  первая по профилю); сопоставима с ней по объёму (8 подзадач), но **ниже по
  риску**: проверяемость доказана до начала разработки.
- **Крейт:** `grammar` (крейт `0.2.0` → минорный рост; **версия языка не
  меняется** — синтаксис и семантика `.lam` не тронуты, правило 22. Коллизия
  номера версии с 0041 — см. [анализ](../analyze/0045-sv-backend.md), R11)
- **Связанные issue (анализ):** **новая фича по прямому запросу заказчика** (не из
  блока «Кандидаты в фичи» `FEATURES.md` — в отличие от 0041, вынесенной заделом
  фичи [0020](0020-port-address-decl.md))

## Краткое описание

Четвёртый целевой язык генерации наряду с C, PlantUML и (прорабатываемым
параллельно) Structured Text: `generator::Language` сегодня имеет ровно два
варианта — `C` и `PlantUML`
([`generator/mod.rs:14`](../../grammar/src/generator/mod.rs)). Фича добавляет
вариант `SV` и модуль `grammar/src/generator/sv/`, транслирующий семантическое
дерево модели в **синтезируемый SystemVerilog (IEEE 1800)** — язык описания
аппаратуры для FPGA/ASIC.

Автоматная модель Lam ложится на синтезируемый RTL-автомат естественнее, чем на
любую другую цель (FSM — каноническая форма RTL), но это **принципиально иная
модель исполнения**: у C и ST такт — итерация цикла сканирования, у RTL — **фронт
тактового сигнала**. Ключевые решения ([ADR](../adr/0045-sv-backend.md)):

- **Время:** такт Lam ≡ `posedge clk`; `clk`/`rst_n` — неявные служебные порты
  модуля (в языке Lam их нет), имена зарезервированы. Язык **не меняется**.
- **Сброс:** синхронный, активный низкий `rst_n`; ветвь сброса устанавливает
  стартовое состояние и исполняет его `enter`. Синтетического `INIT`-состояния
  **нет** → **сдвиг = 0 на любой глубине**: контракт
  [ADR 0033](../adr/0033-init-tick-alignment.md) выполняется **конструктивно** (в
  C его требуется *убирать* правкой, здесь его просто нет).
- **Автомат:** two-process — `always_comb` (тело состояния, блокирующие
  присваивания → порядок операторов как в C) + `always_ff` (латч + сброс).
- **Композиция:** один модуль на корневую модель; регистры состояний под-моделей
  независимы, логика инлайнится в общий `always_comb` в порядке вызова `_tick`
  C-бэкендом (иначе `stacker.lam` даёт **комбинационную петлю** — проверено).
- **Типы:** `bit` → `logic` (**идеальное** соответствие; в C — `int`, дефект
  0029); `Rational` → **ошибка `SV-003`**: в синтезируемом RTL плавающей точки не
  существует.
- **Порты:** `in`/`out` → `input`/`output logic` — **самое естественное
  соответствие из всех целей**. Карта адресов [0020](0020-port-address-decl.md)
  **не потребляется**: адрес MMIO для RTL бессмыслен.

Изменение **аддитивно**: `Language` помечен `#[non_exhaustive]`
([`generator/mod.rs:13`](../../grammar/src/generator/mod.rs)), существующие цели
`c`/`c-hal`/`plantuml` байт-в-байт не меняются, `.lam` не тронут.

> Фича зарегистрирована **по прямому запросу заказчика**; далее проходит
> жизненный цикл по правилу 17.

## Проверяемость: доказана до начала разработки

В отличие от соседней фичи 0041 (её гейт MatIEC `iec2c` — **главный риск**, в
репозитории не проверен), проверяемость 0045 подтверждена **фактическими пробами**
в ходе проработки. Изначально в среде не было ни одного SV-инструмента; оба
установлены (`brew install verilator yosys`) и опробованы:

| Проба | Verilator 5.050 `--lint-only -Wall` | yosys 0.67 `synth` |
|---|---|---|
| Целевой модуль `LiftController` (написан от руки по решению ADR) | **чисто, код 0** | **синтезирован, 22 ячейки** |
| Контрпример `real` в `always_ff` | **принял молча, код 0** | **`ERROR: TOK_REAL`, код 1** |
| Контрпример: комбинационная петля | **`UNOPTFLAT`, код 1** | **синтезировал молча, код 0** |
| Тестбенч (`verilator --binary --timing`) | **собран и прогнан**; трасса подтверждает сдвиг = 0 | — |

**Главная находка:** инструменты ловят **непересекающиеся** классы дефектов —
Verilator пропускает `real` (то есть расхожее «`--lint-only` = проверка синтеза»
**неверно**), yosys молча синтезирует комбинационную петлю (центральный риск
отображения `M1 | M2`). Поэтому гейтов **два**, и они обязательны оба. Подробно —
[анализ 0045-02](../analyze/0045-02-validation.md).

## Ключевые ограничения (документируются, правило 15)

- **`extern fn` не транслируется** (`SV-005`) → `elevator.lam` (8 шт.),
  `comprehensive.lam` (2), `extend_complex.lam` (1) для цели `sv` **недоступны**.
  Флагманский пример цели — **`stacker.lam`** (0 `extern fn`, 0 `float`, 13
  `bit`-портов, три параллельные модели — витрина преимущества RTL).
- **`float` запрещён** (`SV-003`): в синтезируемом RTL плавающей точки нет.
  Fixed-point Q(m.n) — кандидат (требует расширения **языка**, а не бэкенда).
- **`inout` запрещён** (`SV-006`): требует сигнала `oe`, которого Lam не выражает.
- **Уплощение иерархии:** один SV-модуль на корневую модель — плата за точную
  семантику `|`.
- Один тактовый домен; CDC, множественные домены, SDC/XDC, потолок частоты — вне
  объёма.

Цена всех запретов на сегодня — **нулевая** (корпус их не использует, проверено
`grep`), но границы обязаны быть в документации.
