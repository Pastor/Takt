## Краткое описание

Умолчание переменной строит `takt-sim::unit::builder::default_field`, и
`duration` попадала в общую ветвь «целочисленный ноль» (`Value::Number(0)`).
Вид значения терялся, и `d := d + 1s;` отвечало **`SIM-005`** «операция '+' не
определена для операндов целое и длительность» — **в такте**.

**Замер 2026-08-21** (`scripts/probe.sh -n 3`): все **восемь** целей вход
переводят и исполняют, эталон отказывает. Контроль — та же переменная с
инициализатором (`:= 0s`): её эталон исполняет, то есть ломался именно вид
умолчания.

⚠️ **Постороннюю причину пришлось снимать:** первая проба звала переменную
`step`, и цель `st` отказывала `ST-014` (имя зарезервировано в IEC 61131-3)
раньше предмета — правило 30, «одна причина за раз».

## Документирование (правило 24)

**Не требуется** — правило языка не менялось: умолчание длительности определено
восемью целями (ноль), фича приводит к нему эталон. Наблюдаемое поведение
законной записи не менялось нигде, кроме входа, который эталон прежде **не
исполнял вовсе**.

## Итог (что сделано)

- `default_field` получил ветвь `TypeNode::Duration => Value::Duration(0)`.
  Носитель один — он же строит умолчания полей структуры и элементов массива,
  поэтому `struct T { hold: duration }` и `[duration; N]` вылечились тем же
  изменением.
- Сторож — потактовая сверка с целью `c`
  (`conformance_duration_default_tests`), а не тест «отказа больше нет»: снять
  отказ мало, значение обязано **совпасть**, а носители у сторон разные —
  наносекунды у эталона (ADR 0134), миллисекунды у цели (0183).
- ⚠️ Мутация «вернуть целочисленный ноль» роняет сверку на **предусловии**:
  трасса эталона становится `[0, 0, 0, 0, 0]`, то есть накопление исчезает.

Детали — в [отчёте](../reports/0354-sim-duration-default.md).
