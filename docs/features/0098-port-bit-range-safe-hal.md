## Краткое описание

Бит адреса порта (`0xADDR:бит`) не проверяется, а дефолтный HAL цели `c-hal`
читает **один байт** и сдвигает на `b.bit` → биты 8…31 читаются как **ноль**
(молча неверно), биты ≥ 32 дают **UB** (`int >> 33`). Воспроизводится на
`examples/extend_complex.lam` (бит 33). Дожило, потому что **`c-hal` не
компилируется ни одним гейтом**.

Решение (ADR 0098, Option C): диапазон бита **[0, 63]** (`SE-060` вне его);
ширина доступа HAL — **минимальное слово, содержащее бит** (1/2/4/8 байт) →
UB исключён конструктивно; **гейт компиляции `c-hal`** в `precheck.sh`.

## Итог (что сделано) — 2026-07-20

Принята **Option C** (ADR 0098): диапазон бита **[0, 63]**, ширина доступа HAL —
минимальное слово, содержащее бит. Реализовано:

- **`SE-060`** (`address_map/resolve.rs`): бит вне [0, 63] → ошибка с локацией
  порта, в адрес-потребляющем слое (`c-hal`/`st-at`); цель `c` не задета.
- **Безопасный HAL** (`generator/c/c_hal.rs`): `word_bytes_for_bit` даёт
  1/2/4/8 байт по биту; `read_bit`/`write_bit` выбирают тип по `b.width`
  (`switch`), маска `(uint64_t)1u << s`. UB и «молча ноль» устранены
  **конструктивно**.
- **Гейт компиляции c-hal** (`precheck.sh`): 7 примеров с адресами компилируются
  (`cc -c`), `elevator_mini` — пропуск SE-052. Прежде c-hal не компилировалась
  нигде — эта дыра и дала дожить дефекту.
- **Вынос HAL в `c_hal.rs`**: `c_header.rs` упёрся в лимит размера (1334 > 1000);
  после выноса 955 строк — удалён из `module-size-baseline.txt` (долг −1).

**Открытый вопрос фикса разрешён** (уточнение при проработке): набросок «диапазон =
ширина типа порта» отвергнут — он запрещает битовую упаковку корпуса (биты 1/2/33
на одном слове). `extend_complex.lam` **не правлен** — бит 33 обоснован (читается
`uint64_t`).

**Проверки:** `grammar/tests/hal_bit_range_tests.rs` (T1/T2 диапазон, T3
значенческий через `mmap` — «1001»), `c_hal::tests::bit_word_width_by_bit_index`,
гейт c-hal в `precheck.sh`. Вывод цели `c` байт-в-байт прежний. Язык не менялся,
версия не поднята (правило 22). Фикс 0020-01 закрыт.
