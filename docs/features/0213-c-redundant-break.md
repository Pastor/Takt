## Краткое описание

входе»; форма решения определяется стадиями архитектуры и анализа.

**Класс:** генерация целей (Tier 3 — приоритет по решению заказчика
2026-08-03: синтаксис → семантика → генерация → остальное).

**Цель `c` печатает лишний `break` после безусловного перехода.** Замер там же
(2026-08-02): у состояния с единственным `ref` тело ветви кончается
`state = …; break; break;` — второй недостижим. `cc -Wall -Werror` молчит
(недостижимый код в `-Wall` не входит), поведение верное, то есть цена —
только шум в порождённом коде, который читает пользователь. Класс —
косметика кодогена, Tier 3.

**Перепроверка замера (стадия 2, 2026-08-17): подтверждён и расширен.** Пар
`break; break;` в корпусе — **7** в шести файлах. У того же корня есть второе
проявление, кандидатом не названное: ребро, записанное **после** безусловного,
печатается целиком и недостижимо вместе со своим `if`. И главное — цель `c` в
этом одинока: `rust`, `st` и `sv` на безусловном ребре обход прекращают.

## Итог (что сделано)

**Цель `c`: безусловное ребро завершает цепочку** — как в `rust`, `st` и `sv`.
Ветвь безусловного перехода в `takt-lang/src/generator/c/c_model.rs` печатает
`exit → enter → state` и возвращает управление: собственного `break;` у неё нет
(ветвь `case` закрывает общий), а рёбра за безусловным — недостижимый код — не
печатаются вовсе. Условное ребро не тронуто: его `break;` обязателен.

Из корпуса ушли все **7** пар `break; break;` (4 отслеживаемых файла,
−5 строк); обновлён снимок порождённого C в документе.

Сторожа: `takt-lang/tests/c_redundant_break_tests.rs` (корпус без пар — падает
**списком** мест; фикстуры на хвост после безусловного, на условное ребро и на
терминальное состояние) и потактовая сверка
`takt-sim/tests/conformance_c_unconditional_edge_tests.rs`. Обе проверены
мутацией: полный откат роняет греп-сторож списком из 7 мест, половинчатая правка
(`break;` снят, обход не оборван) роняет сверку трасс — `[1, 0, 0, 0]` против
`[1, 9, 9, 9]`; `cc -Wall -Werror` такой вывод принимает молча.
