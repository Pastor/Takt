## Краткое описание

Пространство имён `FUNCTION`/`FUNCTION_BLOCK` в IEC 61131-3 **плоское и общее со
стандартной библиотекой**, а генератор `st` печатает имена как есть. Три следствия
(все подтверждены гейтом `iec2c`):

1. **Одноимённые `fn` разных моделей столкнутся** — цель `c` префиксует именем
   модели (`Stacker_travel_time`), цель `st` — нет.
2. **Модель с именем `Concat`/`ABS`/`MIN`/`SEL`** даёт `invalid function block
   name`; имя корневой модели берётся **из имени файла**, поэтому ловушка
   срабатывает на `concat.lam` (поймано на фикстуре 0041-07, файл переименован).
3. ⚠️ **Капкан шире POU — бьёт и по обычным переменным.** Локальная переменная
   функции с именем `left` даёт «invalid located variable declaration» — `LEFT` в
   IEC стандартная **строковая** функция. Проверено: `left`/`LEFT`/`right`/`mid`
   отвергаются, `remaining`/`v` принимаются; идентификаторы IEC
   **регистронезависимы**, поэтому нижний регистр не спасает. Диагностика
   **обманчива** — говорит про «located variable» (`AT %…`), которых в объявлении
   нет вовсе, то есть по тексту ошибки причину не найти.

Оба класса `iec2c` ловит **громко** («duplicate»/«invalid name») — тихого
расхождения нет. Лечение общее: префиксовать имена уникальным именем модели, как в
цели `c`. Обойдено переименованием в примере (`left` → `remaining`).

В корпусе п. 3 был замаскирован тем, что до 0030 **ни одна** функция примеров не
имела локальных переменных.
