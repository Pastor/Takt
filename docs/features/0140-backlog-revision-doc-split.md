## Краткое описание

Две смежные проблемы процесса: **кандидаты в витрине не снимаются**, когда
проблема закрыта, и **описание языка задвоено** между `README.md` и `book/` без
какого-либо гейта согласованности.

> Фича зарегистрирована из процессного бэклога (отобрана заказчиком 2026-07-27); далее проходит жизненный цикл по правилу 17.

## Что известно на входе

**Кандидаты не снимаются.** Аудит нашёл две записи блока 2, описывавшие уже
сделанное:

- «Потактовой сверки для цели `st` НЕ СУЩЕСТВУЕТ» — сверка есть,
  `takt-sim/tests/conformance/conformance_st_tests.rs` (задача 0065-03);
- «Цель `c-hal` не компилируется ни одним гейтом» — гейт есть, `precheck.sh`
  (фича [0098](0098-port-bit-range-safe-hal.md)).

Витрина — вход в проект для новой сессии, и устаревшая запись стоит **дороже
отсутствующей**: по ней заводят уже сделанную работу.

**Задвоение описания языка.** `README.md` — 2599 строк, из них разделы
«4. Синтаксис» и «5. Семантика» (≈500 строк) описывают язык; параллельно тем же
занят `book/` (17 разделов, ≈101 страница PDF). Правило 15 требует детального
README, правило 24 — актуального `book/`; обе обязанности исполняются вручную,
гейта согласованности нет. Прецедент дрейфа уже есть: `Takt.ebnf` отстал от
языка на реформу операторов фичи 0021.

## Направление решения (наметка, не решение)

1. Разовая ревизия блока 2 `FEATURES.md` с вычёркиванием закрытого.
2. Правило: **закрывающая фича обязана снять или актуализировать кандидатов**,
   которых называет её карточка.
3. По возможности — машинная проверка (по образцу `check-links.py`): хотя бы
   «кандидат ссылается на фичу в статусе `ГОТОВО`» как повод к ревизии.
4. **Решение заказчика** по дублю: либо README сокращается до обзора и ссылок на
   `book/` (правило 15 переформулируется), либо заводится гейт согласованности.

⚠️ Окончательный выбор — за стадиями **архитектуры** (ADR) и **анализа**: раздел
выше фиксирует то, что уже проверено, а не предрешает реализацию.

## Документирование (правило 24)

**Не требуется** для процесса. Если будет принято решение сократить `README.md`,
затрагивается правило 15 свода, но не содержание `book/`.

## Итог (что сделано)

Закрыта 2026-07-27, `./scripts/precheck.sh` → `EXIT=0`. Отчёт —
[`docs/reports/0140-*`](../reports/0140-backlog-revision-doc-split.md) (вердикт
**✅ ПРОЙДЕН**, 12/12 проверок). Обе развилки решил заказчик.

**Ревизия витрины.** Проверено 17 кандидатов из 28 — пробами и грепом. Три
записи оказались неверными: «цель `c` не эмитит констант перечисления» (эмитит,
но **в `.c`**, где прежний греп не искал, и не использует их), «пустое
перечисление трактуется четырьмя целями по-разному» (такую программу **нельзя
написать** — `SY-002`), «`rust` глушит `too_many_arguments` пять раз» (восемь).
Остальные проверенные подтвердились. ⚠️ 11 записей не проверялись (нужен IDE или
дорогой замер) — это **названо** в отчёте, а не выдано за полную сверку.

**Правило 28 свода.** Закрывающая фича обязана пройти по кандидатам, которых
называет её карточка, и снять либо актуализировать их — опираясь на пробу, а не
на память. Подсказка `scripts/check-stale-candidates.sh NNNN` печатает
кандидатов, упоминающих фичу; код возврата предкоммита не меняет.
⚠️ Предлагавшаяся карточкой метрика «кандидат ссылается на закрытую фичу»
**замерена и отвергнута**: 28 из 28 — ссылка есть почти у каждого, потому что
туда их и выносят при закрытии.

**Роли документов разделены** (правило 15 переформулировано): README описывает
**проект и инструментарий**, `book/` — **язык**. Языковые разделы README сжаты с
513 строк до 80 (обзорный пример + указатель на 12 разделов документа + пять
тезисов о ключевых решениях). README: 2708 → 2275 строк; `book/` не тронут.

**Находка вне объёма:** `CLAUDE.md` утверждал «версия языка сейчас `0.4.0`» при
фактических `0.6.0` — гейт сверяет константу и README, а живой контекст остался
вне проверки и увёл за собой три карточки закрытых фич. Исправлено в восьми
файлах; кандидат на гейт заведён.

Код не затронут, язык не менялся.
