## Краткое описание

Две настройки прогона на странице — задержка показа и частота модельных часов —
живут по-разному: задержка записана в проект по сценарию (`run_delays`), частота
([частота модельных часов прогона на странице](0596-web-run-clock-frequency.md)) —
в браузере читателя. Заказчик просит держать обе в метаданных
симуляции: частота становится свойством сценария проекта, как задержка, едет в
архиве и манифесте и одинакова у всех, кто открыл проект.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-13
- **Authors:** разработчик; решение о хранении — заказчик

### Context

Метаданные прогона у проекта уже есть — задержка по сценарию, `run_delays`:
колонка базы `projects.run_delays` (JSON-карта), проверка сервера
`limits::check_run_delays` (секунды 0…60, миллисекунды, ноль не хранится, ключ
обязан быть сценарием проекта), поле манифеста `takt-project` (формат 4 и выше),
страница (`account.delayOf`/`setDelay`: пишет владелец, у прочих — до
перезагрузки). Частота страницы хранится ключом браузера `takt.ui.tickHz`: другой
читатель того же проекта и архив её не видят, а `takt-sim export` при том же
сценарии снимает видео в другом темпе, чем показывает страница.

### Decision Drivers

- D1 — одна модель хранения на обе настройки: частота — свойство сценария, как
  задержка (иначе две похожие настройки с разным поведением).
- D2 — носитель метаданных один: база, манифест, архив и страница читают одно
  поле, без второго списка правил.
- D3 — старые проекты открываются как прежде: нет записи — частота из `clock`
  модели, задержки нет.
- D4 — экспорт и страница прогоняют сценарий одинаково.

### Considered Options

1. **Отдельная карта `run_frequencies` рядом с `run_delays`** — та же форма,
   та же проверка, та же запись; миграция — одна колонка.
2. **Общий объект `run_settings: {сценарий: {delay, hz}}`** вместо двух карт —
   чище по форме, но меняет уже выпущенное поле манифеста (формат 4) и API
   страницы: цена перевода старых проектов выше пользы.
3. **Частота в самом файле сценария** — отвергнуто: сценарий — вход прогона,
   его читает и `takt-sim -s`, и формат его описан документом.

### Decision

Вариант 1.

- База: колонка `projects.run_frequencies TEXT NOT NULL DEFAULT '{}'`, схема
  версии 10; проверка `limits::check_run_frequencies` — целые герцы до 10⁹,
  ноль не хранится, ключ — сценарий проекта; запись списком целиком, как у
  задержек; копирование проекта переносит карту; переименование и удаление
  сценария правят обе карты одним запросом.
- Манифест: поле `run_frequencies` (`#[serde(default)]`), формат `6`.
- Страница: частота сценария показывается и пишется как задержка
  (`account.frequencyOf`/`setFrequency` над общим `setRunSetting`); ключ
  браузера `takt.ui.tickHz` снят — без проекта значение живёт до перезагрузки,
  как задержка.
- `takt-sim export`: без `--tick-ms` период берётся из частоты выбранного
  сценария манифеста, затем из `clock` модели. Модуль экспорта страницы получает
  частоту поля картой по сценарию — тем же путём, что из манифеста.

### Consequences

- Старые проекты и архивы формата 5 читаются: карты нет — частот нет.
- Архив формата 6 старый модуль отвергнет словами (незнакомая версия формата) —
  тем же правилом, что прежде.
- Видео экспорта и прогон страницы при одном сценарии идут в одном темпе.
- Граница: прогон без сценария экспортируется в темпе `clock` модели — частота
  ключуется сценарием, и без него ей не к чему привязаться.

#### Acceptance criteria

1. Владелец ставит частоту сценарию — после перезагрузки и у другого читателя
   поле показывает её же; прогон идёт в этом темпе.
2. Сервер отвергает дробную, отрицательную и больше предела частоту и ключ, не
   являющийся сценарием, — словами.
3. Архив и манифест несут карту; круговой рейс «выгрузка — загрузка» её
   сохраняет.
4. `takt-sim export` на проекте с частотой сценария снимает видео в её темпе.

## Разработка

### Задача — частота как метаданные сценария

#### Что было

Частота прогона жила ключом браузера; сервер, манифест и экспорт о ней не знали.

#### Что сделано

- `takt-project`: поле манифеста `run_frequencies`, `FORMAT = 6`.
- `takt-sim export`: приоритет периода — `--tick-ms`, частота сценария из
  манифеста, `clock` модели; период не короче наносекунды.
- `takt-wasm-export`: поле запроса `run_frequencies` уходит в манифест проекта.
- Сервер: колонка и переход схемы 9 → 10, `check_run_frequencies`, поле проекта
  и запроса правки, выборки, копия проекта, выгрузка и загрузка архива; запросы
  `RENAME_RUN_SETTINGS` и `FORGET_RUN_SETTINGS` правят обе карты.
- Страница: `frequencyOf`/`setFrequency` над общим `setRunSetting`, поле частоты
  берёт значение сценария при его открытии, экспорт получает частоту поля; ключ
  `takt.ui.tickHz` снят.
- Версии: `takt-project` 0.2.0, `takt-sim` 0.17.0, `takt-wasm-export` 0.3.0,
  `takt-lang` 0.62.2.

## Тест-план

1. Сервер: негодная частота (ключ-модель, чужой ключ, минус, дробь, выше
   предела) — отказ; годная принимается; запись задержки частоту не трогает;
   переименование уносит обе настройки; ноль не хранится; удаление забывает.
2. Переход схемы: состаренная база доходит до версии 10 и совпадает со схемой с
   нуля.
3. Архив: `format` 6, `run_frequencies` — объект.
4. Экспорт: видео с частотой сценария 2 Гц равно видео с `--tick-ms 500` байт в
   байт и отличается от видео без частоты.
5. Страница: запрос экспорта несёт карту по сценарию, без сценария или частоты —
   пустую; прогон с 2 Гц идёт по 500 мс; ключа браузера нет.
6. `precheck.sh` зелёный.

## Отчёт о тестировании

1. `cargo check` основного workspace и сервера — без ошибок и предупреждений.
2. `takt-sim`: тест экспорта с частотой зелёный (видео равно видео с периодом
   500 мс, от видео без частоты отличается); `takt-project`, `takt-wasm-export` и
   модульные тесты сервера зелёные. Тесты сервера над базой без
   `TAKT_WEB_TEST_DB` пропускаются — названное ослабление проекта; они написаны и
   собираются.
3. `check-web.sh`: 150 тестов, все зелёные.
4. Прогон страницы (собранная статика, модуль 0.62.2): после перезагрузки поле
   частоты пустое, ключ `takt.ui.tickHz` не пишется; модель
   `start Green { ref Yellow: after 1s; } state Yellow;` при 2 Гц — шаг 2 на
   500 мс, `[Yellow]` на шаге 3. Запись в проект требует сервера — её держит
   тест сервера.

Предкоммит зелёный. Стенд — проверка после выкатки в разделе «Итог».

## Итог

ГОТОВО. Частота модельных часов прогона — метаданные сценария проекта рядом с
задержкой: хранится на сервере, едет в копии проекта, архиве и манифесте
(формат 6), одинакова у всех читателей. `takt-sim export` и экспорт со страницы
снимают видео в темпе частоты сценария. Прогон без сценария экспортируется в
темпе `clock` модели.
