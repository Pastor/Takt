## Краткое описание

Две настройки прогона на странице — задержка показа и частота модельных часов —
живут по-разному: задержка записана в проект по сценарию (`run_delays`), частота
([частота модельных часов прогона на странице](0596-web-run-clock-frequency.md)) —
в браузере читателя. Заказчик просит держать обе в метаданных
симуляции: частота становится свойством сценария проекта, как задержка, едет в
архиве и манифесте и одинакова у всех, кто открыл проект.

### Context

Метаданные прогона у проекта уже есть — задержка по сценарию, `run_delays`:
колонка базы `projects.run_delays` (JSON-карта), проверка сервера
`limits::check_run_delays` (секунды 0…60, миллисекунды, ноль не хранится, ключ
обязан быть сценарием проекта), поле манифеста `takt-project` (формат 4 и выше),
страница (`account.delayOf`/`setDelay`: пишет владелец, у прочих — до
перезагрузки). Частота страницы хранится ключом браузера `takt.ui.tickHz`: другой
читатель того же проекта и архив её не видят, а `takt-sim export` при том же
сценарии снимает видео в другом темпе, чем показывает страница.

### Decision Drivers

- D1 — одна модель хранения на обе настройки: частота — свойство сценария, как
  задержка (иначе две похожие настройки с разным поведением).
- D2 — носитель метаданных один: база, манифест, архив и страница читают одно
  поле, без второго списка правил.
- D3 — старые проекты открываются как прежде: нет записи — частота из `clock`
  модели, задержки нет.
- D4 — экспорт и страница прогоняют сценарий одинаково.

### Considered Options

1. **Отдельная карта `run_frequencies` рядом с `run_delays`** — та же форма,
   та же проверка, та же запись; миграция — одна колонка.
2. **Общий объект `run_settings: {сценарий: {delay, hz}}`** вместо двух карт —
   чище по форме, но меняет уже выпущенное поле манифеста (формат 4) и API
   страницы: цена перевода старых проектов выше пользы.
3. **Частота в самом файле сценария** — отвергнуто: сценарий — вход прогона,
   его читает и `takt-sim -s`, и формат его описан документом.

### Decision

Вариант 1.

- База: колонка `projects.run_frequencies TEXT NOT NULL DEFAULT '{}'`; проверка
  `limits::check_run_frequencies` — целые герцы 1…10⁹, ноль не хранится, ключ —
  сценарий проекта; запись списком целиком, как у задержек; копирование проекта
  (`fork`) переносит карту.
- Манифест: поле `run_frequencies` (`#[serde(default)]`), формат `6`.
- Страница: частота сценария показывается и пишется как задержка
  (`account.frequencyOf`/`setFrequency`); ключ браузера `takt.ui.tickHz`
  снимается — без проекта значение живёт до перезагрузки, как задержка.
- `takt-sim export`: без `--tick-ms` период берётся из частоты выбранного
  сценария манифеста, затем из `clock` модели.

### Consequences

- Старые проекты и архивы формата 5 читаются: карты нет — частот нет.
- Архив формата 6 старый модуль отвергнет словами (незнакомая версия формата) —
  тем же правилом, что прежде.
- Видео экспорта и прогон страницы при одном сценарии идут в одном темпе.

#### Acceptance criteria

1. Владелец ставит частоту сценарию — после перезагрузки и у другого читателя
   поле показывает её же; прогон идёт в этом темпе.
2. Сервер отвергает дробную, нулевую-с-записью, отрицательную и больше предела
   частоту и ключ, не являющийся сценарием, — словами.
3. Архив и манифест несут карту; круговой рейс «выгрузка — загрузка» её
   сохраняет.
4. `takt-sim export` на проекте с частотой сценария снимает видео в её темпе.
