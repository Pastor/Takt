## Краткое описание (как понято требование)

Вводится **анонимный порт** — обращение к ячейке по адресу **без объявления
имени**, прямо в выражении. Префикс `#` относится **только** к этой форме:
объявление порта остаётся таким, каким его задаёт
[0187](0187-port-io-redesign.md), и в этой фиче **не меняется**.

### Обращение по анонимному адресу (без объявления)

Адрес пишется в выражении литералом с префиксом `#`, к нему применимы уже
существующие операции языка:

```takt
#0x000346619.4                  // 4-й бит по адресу 0x346619 (битовый доступ)
#0x000346619:0 as u64           // ячейка по адресу как 64-разрядное целое
#0x000346619:0 as u64 := 67     // запись 67 по адресу как u64
```

- `.4` — **битовый доступ** к анонимному порту (тот же оператор, что `x.0`);
- `:0` — часть **адресного литерала** (позиция бита), как в `0xADDR:бит`;
- `as u64` — приведение, задающее **ширину доступа** к ячейке;
- присваивание `:= 67` — **запись** по адресу.

**Направление у анонимного порта не объявлено**, поэтому его использование
**для записи всегда даёт предупреждение** — компилятор не может проверить, что
запись по этому адресу законна.

### Анонимное обращение — операнд, а не оператор

Само по себе обращение обособленно стоять **не может**: чтение ячейки, значение
которой никуда не идёт, эффекта не имеет. Такая запись — **синтаксическая**
ошибка (её даёт парсер, а не семантика):

```takt
#0x000346619.4;                        // ОШИБКА: обособленное обращение
```

Законно оно там, где значение **потребляется** — в условии, в правой части, в
аргументе:

```takt
if #0x000346619.4 && b = 4 { … }       // корректно: значение потребляет условие
x := #0x000346619:0 as u64;            // корректно: значение потребляет присваивание
```

…и там, где обращение само является **целью записи** (эффект есть):

```takt
#0x000346619:0 as u64 := 67;           // корректно: запись (с предупреждением)
```

### Объявление порта — по 0187, без изменений

Размещение именованного порта задаётся ключевым словом `at`, а `:=` означает
начальное значение (решение заказчика 2026-07-31, [ADR 0187](../adr/0187-port-io-redesign.md)).
Фича 0189 этой формы **не касается** — примеры записываются так:

```takt
out X: bit at 0x000346619:7;        // выход, бит 7 по адресу
out Y: u32 at 0x000346619:0;        // выход, бит 0, тип u32
in  P: bit at 0x000346619:8;        // вход, бит 8
out H: u16 at 0x000346619 := 89;    // выход, тип u16, начальное значение 89
```

То есть `#` и `at` **не конкурируют**: `at` размещает **именованный** порт,
`#` адресует ячейку, у которой имени нет вовсе.

## Решения стадии 2 (ADR принят 2026-08-01)

Все семь развилок закрыты решением заказчика — подробности и цена вариантов в
[ADR 0189](../adr/0189-anonymous-ports.md), раздел `Decision`:

| Ось | Решение |
|---|---|
| смысл `:B` / `as T` | `:B` — начало поля, `as T` — его разрядность; `#A` без ширины — ошибка |
| формы бита | `.B` (один бит) и `:B as T` (поле) законны обе |
| запись | предупреждение `SE-096`, текст называет способ снять |
| цели | `c-hal`, `st-at`, `sv-mmio` — поддерживают; `c`, `rust`, `st`, `sv` — отказ с причиной |
| симулятор | синтетический порт с именем из адреса |
| обособленное выражение | оператором остаются присваивание и вызов; прочее — `SY-006` |
| голый адресный литерал | вне позиции адреса запрещён (закрывает Tier-1-находку Ф2) |

## Открытые вопросы регистрации (закрыты стадией 2)

Ниже — исходный список вопросов, с которыми фича заводилась; каждый решён ADR:

1. **Тип и ширина доступа анонимного порта.** `as u64` задаёт ширину; что
   означает `#ADDR` без `as` и без бита — ошибка или умолчание?
2. **Разрешение бита:** `#ADDR:бит` (адресный литерал) и `#ADDR.бит` (битовый
   доступ) дают одно и то же значение разными путями — нужно решить, обе ли
   формы законны и как они соотносятся.
3. **Взаимодействие с картой адресов** (`--address-map`, оператор `address`):
   анонимный порт имени не имеет, значит переопределить его извне нечем — это
   осознанное ограничение или дыра в переносимости?
4. **Поведение целей.** Анонимный доступ естественен для `c-hal` (`*(volatile
   T*)addr`), но у `c` доступ идёт через HAL-колбэки по перечислению портов, у
   `st-at` — через located-переменные, у `sv` адресов нет вовсе. Требуется
   решить, какие цели фичу поддерживают, а какие отказывают диагностикой.
5. **Симулятор**: чем является анонимный адрес в прогоне — ячейкой модели
   памяти, портом со сгенерированным именем или отказом.
6. **Код предупреждения** на запись без направления и его текст.
7. **Как грамматика различает позиции.** Требование — отказ **синтаксический**:
   обособленное обращение недопустимо, а обращение-операнд и обращение-цель
   записи допустимы. Значит анонимный доступ входит в правило выражения, но
   оператор-выражение из него одного не выводится; форму правила предстоит
   выбрать так, чтобы отказ давал парсер, а не проверка после разбора.
