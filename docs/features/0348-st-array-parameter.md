## Краткое описание

`first(arr)` при `fn first(a: [u8;2])` давал `iec2c` «Data type incompatibility
for value passed in position 1» — при нулевом коде возврата `taktc`, тогда как
эталон и три другие цели вход исполняли.

## Документирование (правило 24)

**Не требуется** — подтверждено: правится представление одной цели.

## Итог (что сделано)

**Массив передаётся именованной формой через `VAR_IN_OUT`.**

- ⚠️ **Форму выбрал полный цикл `iec2c` → `cc`, а не одна трансляция:**
  `VAR_INPUT` с массивом инструмент **разбирает**, но порождает C, который не
  компилируется («operand of type '__ARRAY_OF_USINT_2' where arithmetic or
  pointer type is required»). Правило для будущих проб цели `st`: форма,
  принятая разбором, не годна, пока не собран вывод.
- **Имя типа — по форме** (`TAKT_ARR_2_USINT`), а не по владельцу: функция
  вызывается с разными массивами. Этим он отличается от именованных типов 0210.
- **Именованными становятся только формы из параметров:** иначе правка задела
  бы каждый массив вывода.
- ⚠️ **Порядок аргументов следует секциям:** параметры-массивы объявлены в
  `VAR_IN_OUT`, а позиционный вызов IEC идёт по порядку объявления. Вход с
  параметрами обеих секций обязателен — перестановка видна только на нём.
- ⚠️ **`VAR_IN_OUT` — ссылка:** функция, меняющая параметр, изменила бы массив
  вызывающего. Сегодня язык такой записи не порождает; граница названа.
