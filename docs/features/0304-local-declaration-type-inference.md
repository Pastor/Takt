## Краткое описание

`var g := F + 1;`, написанное **внутри** `always { … }`, оставалось с типом
`Inference`: вывод типов шёл только по объявлениям верхнего уровня. Один вход
давал **три** разных ответа, и один из них был молчаливым.

## Документирование (правило 24)

**Не требуется.** Язык не меняется — исполняется то, что он уже обещает: вывод
типа из инициализатора. Раздел документа о переменных описывает вывод без
оговорки «только на верхнем уровне», то есть текст был верен, а инструменты —
нет.

## Итог (что сделано)

**Одна запись — один ответ у всех девяти потребителей.**

- **Тип локального объявления выводится** из инициализатора при понижении
  оператора (`semantic/statement/mod.rs`). Общим проходом это сделать нельзя:
  локальное объявление живёт в теле блока, а не в таблице модели, и к моменту
  `type_inference` тела ещё не построены.
- **Цель `sv` перестала печатать невалидный модуль.** Второй дефект,
  **не зависевший** от первого: локальные переменные тел состояний не
  объявлялись вовсе (`hoist_locals` звался только для функций) — воспроизводится
  и на **явном** типе. Объявление печатается как `automatic logic …` в ветви
  `unique case`; форма проверена **обоими** инструментами (verilator и yosys,
  урок 0235).
- **Сверка** `takt-sim/tests/conformance/conformance_local_decl_tests.rs`:
  потактовая трасса эталона против цели `c` на **накапливающем** теле плюс
  проверка валидности вывода `sv` линтом.

**Замер 2026-08-20** (`scripts/probe.sh`, правило 30): эталон — `SIM-007` в
такте; `c`/`c-hal` — `CC-015`; `st`/`st-at` — `ST-002`; `rust` — `RS-014`;
**`sv`/`sv-mmio` — код 0 и невалидный модуль**. После правки все восемь целей
переводят, эталон исполняет, трассы совпадают.

⚠️ **Первая редакция фикстуры мерила не то:** состояние без переходов уходит в
`END` после первого такта (правило 0303), накопление не наблюдалось, и трассы
разошлись (6,12,18 против 6,6,6). Поймано **самой сверкой**; фикстура получила
самопереход.
