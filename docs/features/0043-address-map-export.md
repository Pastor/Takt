## Краткое описание

Выгрузка консолидированной карты адресов портов наружу — подкомандой
`lamc address-map --emit <fmt>`, чтобы адресами могли пользоваться сторонние
инструменты (генераторы HAL, отладчики, платформенные скрипты). Экспортируется
**фактически разрешённая** карта — та же, что потребляет цель `-t c-hal`: с
учётом приоритета источников (inline `:=` < оператор `address` < внешняя карта
`--address-map`).

Поставляются **два формата**: `map` — тот же `.ld`-подобный формат, который уже
читается флагом `--address-map` (даёт **круговой рейс** export → import), и
`json` — машиночитаемая выгрузка с типом, направлением и источником адреса для
генераторов HAL. **Настоящий CMSIS-SVD не выбран**: у Lam нет данных, которых
требует его схема (группировка в peripherals, reset-значения, достоверная
разрядность регистра), и выпуск правдоподобного-но-неверного SVD для отладчиков
хуже его отсутствия — обоснование в [ADR](../adr/0043-address-map-export.md).

> Фича зарегистрирована из бэклога кандидатов `FEATURES.md` (вынесена из фичи
> 0020); далее проходит жизненный цикл по правилу 17.

## Декомпозиция (см. анализ)

- **0043-01** — ядро экспорта: обогащение записи разрешённого адреса (тип,
  направление) + эмиттер формата `map` + круговой рейс.
- **0043-02** — эмиттер формата `json` (контракт с внешними инструментами).
- **0043-03** — CLI-подкоманда `lamc address-map --emit <fmt>`.

## Приоритет (правило 19 п.3)

**Tier 3 (средний).** Аргументы:

1. **Это интеграционное удобство, а не дефект корректности.** В отличие от
   Tier 1–2 фич генератора C (0026, 0029), которые выдают **невалидный C**, здесь
   ничего не сломано: карта адресов уже работает и потребляется целью `c-hal`.
   Фича добавляет наружный выход к готовым данным.
2. **Правило 12 (профиль проекта) — по касательной.** Основная цель — задание и
   синтез автоматных моделей; экспорт карты обслуживает **смежный** тулинг
   (отладчики, генераторы HAL), а не сам синтез. Поэтому ниже фичи 0041
   (ST-бэкенд), которая добавляет целевой язык промышленной автоматики и потому
   бьёт прямо в правило 12.
3. **Никого не блокирует.** Ни одна фича не зависит от 0043 (проверено по
   `docs/features/README.md`), поэтому по правилу 19 п.1 её не нужно поднимать
   ради разблокировки.
4. **Но дёшева и хорошо проверяема.** Переиспользует готовые
   `resolve_addresses` и `parse_address_map`; круговой рейс даёт сильный
   тестовый оракул. Это удерживает её на Tier 3, а не ниже.

## Риски

- **Формат выгрузки становится внешним контрактом** — его потребители вне
  репозитория; менять задним числом дорого. → Версионирование формата и
  «открытый» перечень источников с первого выпуска (см. анализ, R7).
- **Плоское пространство имён портов** (`HashMap<String, ResolvedAddress>`,
  `address_map.rs:374`) — одноимённые порты в разных под-моделях делят ключ.
  Латентный дефект ядра 0020, напрямую бьющий по экспорту. → Оформлен отдельным
  кандидатом; в 0043 — задокументированное ограничение (см. анализ, риск Р2).
- **Пересечение с 0042** (`--define`): добавит четвёртый источник адреса →
  значение поля `source` в выгрузке. → Снимается «открытым» перечнем (R7).

## Итог (что сделано)

Подкоманда **`lamc address-map --emit map|json`** выгружает фактически
разрешённую карту адресов портов наружу (фича закрыта, `precheck.sh` EXIT=0).

**Крейт `grammar`** (язык не менялся, 0.2.0; крейт — минорный бамп **0.5.0 →
0.6.0**, добавлен публичный API):

- **`address_map/resolve.rs`** — `ResolvedAddress` обогащён `ty`/`direction`
  (заполняются тем же обходом `resolve_model`, второго прохода нет); мёртвые
  порты пишутся в новое `AddressResolution::address_less` (для выгрузки `json`).
- **`address_map/export.rs`** — эмиттеры: `export_address_map` (формат `map`,
  `{:#010x}`, сортировка по имени, порт без адреса **опускается** — `0x0` не
  эмитится), `export_map_entries` (второе плечо кругового рейса, общий печатник),
  `export_address_map_json` (версионированный JSON: имя/тип/направление/адрес/бит/
  источник; мёртвый порт — `"address": null`). JSON печатается **вручную** — не
  тянет `serde_json` в дефолтный `lamc`.
- **`address_map/export_cli.rs`** — CLI-обвязка (`run_export_subcommand`): разбор
  флагов, разрешение адресов (как `-t c-hal`), печать. Вынесена сюда, а не в
  `bin/lamc.rs`: тот пришпилен к baseline размера — в бинарнике **тонкий
  диспетчер**. `split_include_dirs` переехал в библиотеку (нужен и обвязке);
  baseline `lamc.rs` понижён 2039 → 2009.

**Форматы и контракты:**

- `map` — тот же `.ld`-синтаксис, что читает `--address-map`: **круговой рейс**
  `export → parse → export` байт-в-байт (R4). Источник после реимпорта — `external`
  (семантика оверлея).
- `json` — версионирован (`format_version`), перечень источников **открыт** (R7:
  потребитель терпит незнакомое). Плоский ключ карты (Р2) задокументирован, не
  чинится (правка задевает `c-hal`).
- Приоритет источников (inline `<` `address` `<` внешняя карта) наследуется от
  ядра 0020; сверено с таблицей `__ADDR[]` цели `c-hal` (T9).
- **CMSIS-SVD не поставляется** (ADR): `--emit svd` → внятная ошибка.
- `SE-052` (достижимый порт без адреса) обрывает экспорт; предупреждения — в
  stderr, stdout — чистая выгрузка.

**Проверка:** `grammar/tests/address_export_tests.rs` (15, T1–T21 + K5) + юниты
`export_cli` (11). Вывод целей `c`/`c-hal`/`st`/… байт-в-байт прежний. Детали —
[отчёт 0043](../reports/0043-address-map-export.md).
