## Краткое описание

Ключевые слова языка, встречающиеся **в тексте** документа `book/` (в прозе, не в
блоках кода), выделяются **моноширинным + жирным + цветом** (как подсветка
синтаксиса), чтобы читатель отличал ключевое слово Takt от постороннего
англоязычного слова. Реализовано lua-фильтром pandoc — автоматически, по всему
тексту. Инфраструктура/стиль — язык не меняется (Tier 3).

> Фича зарегистрирована **2026-07-24 по запросу заказчика**.

## Документирование (правило 24)

**Не требуется** — стиль отображения документа, язык (синтаксис/семантика/
поведение) не меняется. Содержимое разделов не переписывается — подсветка
применяется автоматически при сборке.

## Итог (что сделано)

- **`book/keywords.lua`** — lua-фильтр pandoc: инлайн-код (`Code`), равный
  ключевому слову лексера (`model`, `if`, `state`, …), печатается
  `\textbf{\textcolor[HTML]{204A87}{\texttt{…}}}` (tango KeywordTok — тот же цвет,
  что у ключевых слов в блоках кода). Блоки кода (`CodeBlock`) не трогаются.
  **Исключены** одиночные `X`/`F`/`G`/`U`/`R` (операторы LTL) и `_` (wildcard) —
  риск ложных срабатываний. Типы (`bit`/`bool`/`u8`…) — не ключевые слова лексера,
  не подсвечиваются.
- **`book/book.toml`** — в профиль `pdf` добавлен `filters = ["keywords.lua"]`.

**Живая проверка:** фильтр применяется (в `.tex` — 80 вхождений
`\textcolor[HTML]{204A87}`, образцы `model`/`state`); разметка компилируется
xelatex без ошибок; `make build` (latexmk) собирает PDF, `pdftotext | grep '??'`
= 0. `precheck.sh` зелёный (сборка PDF в него не входит).

**Ведение:** при добавлении ключевого слова в лексер обновить `keywords.lua`
(кандидат — гейт сверки с `KEYWORDS`).
