## Краткое описание

Было 587 строк, стало **1054** без тестов (1116 с ними) — вычислитель выражений
адреса добавил ~460. Лимит ~1000 (`CLAUDE.md`) превышен.

Анализ [0042](0042-address-defines.md) это **предвидел** («при росте вычислитель
выделяется в `address_map/eval.rs`»), но оценивал прирост в 150–200 строк.

Лечение — ровно то, что и планировалось: вынести вычислитель (`eval_addr_expr`,
`apply_binary`, `resolve_symbol`, `AddressEnv`) в подмодуль.

Смежно с [0027](0027-module-size-split.md) (храповик размера) и с фичей
[0088](0088-module-size-remaining.md) (остальные нарушители лимита).

Выявлено при закрытой [0042](0042-address-defines.md).

## Итог проработки (2026-07-17)

⚠️ **Уточнение против кандидата: сборка НЕ падает.** «Лимит превышен»
подразумевает красный храповик — он **зелёный**: файл числится в реестре
**узаконенного долга** (`module-size-baseline.txt:31` → `1116
grammar/src/address_map.rs`); прогон даёт «157 файлов, записей долга 22,
превышение 12049 строк», отказа нет.

**Как так вышло:** **0042 закрылась раньше 0027** (`b5aacfb` → `0eac9ed`), поэтому
к моменту заморозки базы файл уже был 1116 и вошёл в реестр **законно**. Храповик
назад не проворачивали. Значит суть фичи — **снять запись** (правило 0027:
«уложившийся в лимит обязан быть из реестра удалён»), а не починить отказ.

**Замер подтвердил оценку кандидата и уточнил структуру** — файл распадается на
восемь частей, из них **четыре самостоятельные темы**:

| Часть | Строки |
|---|---|
| **парсер `.ld`-карты** | **270** |
| **среда define** (`AddressEnv`) | **170** |
| **вычислитель** | **268** |
| **разрешение адресов** | **176** |
| прочее (шапка, типы, оверлей, диагностики) | 170 |

Вычислитель + `AddressEnv` = **438** строк (кандидат говорил «~460») → остаток 616,
под лимитом. ⚠️ Анализ 0042 оценивал прирост в **150–200** строк против фактических
**~460**: предвидение верное, оценка вдвое оптимистичная.

**Принято** ([ADR](../adr/0069-address-map-eval-split.md), **Option B**): делить
**по темам** (`parse`/`env`/`eval`/`resolve` + `mod.rs`-реэкспорт), а не по лимиту.
Кандидат предлагал вынести только вычислитель — этого хватило бы для лимита, но
лимит здесь **следствие**, а не причина: правило проекта требует делить **по
логике**, а парсер внешнего `.ld`-формата (270 строк) не имеет с разрешением
адресов ничего общего и упёрся бы в лимит на следующей же фиче по адресам.

⚠️ **`apply_binary` остаётся ОДНОЙ функцией** на оба матчера (сырой АСД у оператора
`address` и понижённый `ExpressionNode` у inline): `CLAUDE.md` предупреждает —
«разъехавшись, они дали бы **разный адрес для одного текста**». Разделение файлов —
типичный повод завести «свой хелпер» в каждом; здесь это дефект.

⚠️ **Фикс [0020-01](../fixes/0020-01-port-bit-out-of-range.md) (Tier 1) живёт в
этом же файле — но чинить его здесь нельзя:** перекладка обязана дать **пустой**
дифф вывода (главный сторож фичи), а фикс его меняет.

Язык не меняется → версия не растёт (правило 22).

## Итог (что сделано) — 2026-07-18

Принят **Option B** (деление по темам). `grammar/src/address_map.rs` (1116 строк
с тестами) заменён каталогом `grammar/src/address_map/`:

| Модуль | Что | Строк |
|---|---|---|
| `parse.rs` | парсер `.ld`-карты (`Scanner`, `parse_address_map`, `parse_entry`) + оверлей `address_map_overlay_warnings` + тесты | ~380 |
| `env.rs` | `AddressEnv`, `parse_defines`, `is_valid_symbol` | ~180 |
| `eval.rs` | вычислитель (`apply_binary`, `eval_ast_addr`, `eval_addr_value`, `eval_addr_expr`, `resolve_symbol`) | ~300 |
| `resolve.rs` | `resolve_addresses`, `resolve_model`, `address_expr_warnings`, типы разрешения | ~290 |
| `mod.rs` | шапка + реэкспорт | ~50 |

**Все файлы под лимитом 1000.**

**Критерии приёмки — выполнены:**

- **A1/T1.** Файл заменён каталогом; все модули под лимитом.
- **A2/T4.** Запись `1116 grammar/src/address_map.rs` **снята** из
  `module-size-baseline.txt`; новых не добавлено.
- **A3/T5.** `check-module-size.sh` зелёный; долг **22 → 21**, превышение
  12049 → **11920**. ⚠️ План оценивал ~10933, вычтя полные 1116; фактически
  «превышение» считает лишь строки **сверх** 1000 (у файла было 116), поэтому
  падение меньше — оценка плана была ошибочной, факт верен.
- **A4/T2.** Пути импорта у потребителей **не изменились** — реэкспорт из
  `mod.rs`; `git diff` вне `address_map/` не содержит правок `use` (проверено).
- **A5/T3 (ОСНОВНАЯ).** Вывод **всех** целей побайтово прежний —
  `git diff --exit-code examples/generated` пусто.
- **A6/T6.** `apply_binary` — **одна** функция (`eval.rs`), греп подтверждает.
- **A7/T7/T8.** Приоритет источников и коды диагностик (SE-048…055,
  AM-001…006, DF-001…004) прежние; тесты 0020/0042 зелёные.
- **A8/T10.** `./scripts/precheck.sh` зелёный целиком (rustc, clippy,
  1701 тест grammar, гейты `c`/`rust`/`sv`/`st`).
- **T9.** Тесты парсера карты переехали в `parse.rs`.

⚠️ **`apply_binary` осталась единственной** (правило 5 ADR): разделение по файлам
— типичный повод завести «свой хелпер» в каждом; здесь это дало бы **разный
адрес для одного текста**. Фикс [0020-01](../fixes/0020-01-port-bit-out-of-range.md)
**не** трогался — перекладка обязана дать пустой дифф.

**Урок (A-3 ADR, в `CLAUDE.md` не заносим — он уже фиксирует инвариант
`apply_binary`):** предвидение «при росте вынесем» (анализ 0042) оценило прирост
в 150–200 строк против фактических ~460 — вынос не случился вовремя, потому что
«ещё влезало». Оценка вдвое оптимистична; мерить надо, а не полагаться на «потом».
