## Краткое описание

Форма `model M = A | B { … }` не работает ни в одной стороне. Подробности находки, замеры и оговорки — в разделе «Что известно на
входе»; форма решения определяется стадиями архитектуры и анализа.

> Фича зарегистрирована **из бэклога кандидатов** (запрос заказчика 2026-08-03:
> перевести кандидатов в фичи без проработки); далее проходит жизненный цикл по
> правилу 17.

## Что известно на входе

> Фича заведена **из кандидата** блока 2 `FEATURES.md` (запрос заказчика
> 2026-08-03: перевести кандидатов в фичи без проработки). Проработка —
> стадии 2–3 жизненного цикла; ниже — запись кандидата **как есть**, вместе с
> замерами и оговорками, сделанными при его заведении.
>
> ⚠️ Замеры кандидата **не перепроверялись** при переводе в фичу: их
> актуальность подтверждает пробой стадия архитектуры (урок 0195 — записи
> кандидатов устаревают, и две из них оказались неверны).

**Класс:** синтаксис языка (Tier 1 — приоритет по решению заказчика
2026-08-03: синтаксис → семантика → генерация → остальное).

**Форма `model M = A | B { … }` не работает ни в одной стороне.** Замер при
закрытии [0194](0194-sim-composition-model-always.md)
(2026-08-03): эталон даёт пустую трассу `[—]` и завершение на первом же шаге,
цель `c` отвергает вход `CC-005` («State with name ' ()' not found»). То есть
форма разбирается грамматикой, но ни один потребитель её не исполняет — отказ
приходит поздно и невнятно, а эталон **молчит**. ⚠️ В корпусе формы нет, и
фича 0194 её не покрывала: правку своей ветви `build_impl` она сделала
симметрично, но **проверить значением не смогла** — ломается раньше.
Решить надо, чем эта форма отличается от `model M { start Inner = A | B; }`:
либо она синоним (и тогда должна работать), либо не должна разбираться вовсе
(и тогда нужен внятный отказ на разборе, а не `CC-005` из кодогена).

## Итог (что сделано)

Форма `model M = A | B { … }` работает у эталона и **всех четырёх** целей:

| Форма | Было | Стало |
|---|---|---|
| реализация + тело без состояний | эталон — пустая трасса; `CC-005`, `RS-013`, `SV-011`, `ST-013` | работает везде |
| реализация + собственный `start` | **работала, молча теряя** `= A \| B` | `SE-101` с двумя позициями |
| реализация без тела | `SY-002` | без изменений |

⚠️ **Худшим было не то, что называл кандидат.** Он описывал отказ у цели `c`;
отказывают все четыре, а вторая форма вообще работала, **молча теряя** половину
записи. Это и определило выбор Option C — единственного варианта, где ответ
получают все три наблюдения.

Реализация разворачивается на построении дерева в синтетическое стартовое
состояние, то есть форма становится **синонимом** записи
`model M { start Имя = A | B; }`, работавшей всегда. За границей построения
формы не существует, и пяти потребителям не по чему разойтись — приём
0143/0187/0192.

⚠️ **Починка эталона не означала починки целей.** Первая редакция разрешала
`implements` в поле: эталон заработал, все четыре цели остались красными —
карта строит состояния из `model.states`. Поймал прогон целей, а не чтение.

⚠️ Правка живёт в `semantic/extend.rs`, а не в `tree.rs`: гейт размера отверг
рост дважды, и это привело к верному по смыслу месту — рядом с `Extend` и
`unroll_extend_expression`.

Побочно: ветвь `build_composition` (заведена [0194](0194-sim-composition-model-always.md))
впервые получила вход, проверяемый **значением**.
