# Фича 0429: Разовое падение сверки sv осталось необъяснённым

- **Номер:** 0429
- **Статус:** ГОТОВО
- **Зависит от:** 0190 (параллельные тесты и уникальность каталога), 0241 (`verilator -j 0`)
- **Tier:** proc — вывода инструмента не касается; цена в недоверии к красному предкоммиту
- **Класс:** прочее
- **Связанные issue (анализ):** кандидат блока 2 `FEATURES.md`, переведён в фичу пакетно 2026-08-23

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32).

## Краткое описание

`conformance_sv_struct_local_tests` упал **один раз** из шести прогонов
предкоммита и не воспроизводился. Причина найдена: имя потока делает каталог
теста уникальным **внутри процесса**, а прогонов тестов бывает два (предкоммит
и запущенный руками `cargo test`) — тогда один процесс сносит каталог другого
`remove_dir_all` прямо во время сборки. Каталог теста теперь лежит внутри
каталога **своего процесса**, и это сторожит гейт.

## Документирование (правило 24)

**Не требуется.** [`book/`](../../book/) описывает язык, а не устройство
тестового окружения.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-23
- **Authors:** архитектор, разработчик

### Context

Наблюдение 2026-08-23 (текст кандидата): падение с
`Vtb__ALL.a.verilator_deplist.tmp: No such file or directory` и
`Undefined symbols … _main`; воспроизвести не удалось ни изолированным
прогоном набора, ни четырьмя полными. Гипотез было две — гонка каталогов
(признак, найденный чтением, устранён фиксом
[0190-01](../fixes/0190-01-test-temp-dir-collision.md), но **не проявлен**) и
перегрузка машины сборкой `verilator --binary -j 0`.

**Замер 2026-08-23 (воспроизведение):** две копии тестового бинарника,
запущенные одновременно с фильтром `struct_local`, роняют набор:

```text
%Error: Cannot find file containing module: 'partial.sv'
shell-init: error retrieving current directory: getcwd: cannot access
            parent directories: No such file or directory
```

Каталог строился как `takt_<тег>_<имя потока>` — имя потока уникально **внутри
процесса**, и второй процесс, начав с `remove_dir_all`, сносит рабочий каталог
первого. Инструмент падает в снесённом каталоге, и отказ выглядит его
собственным сбоем.

⚠️ Прежний замер честно говорил «воспроизвести не удалось»: он повторял прогон
**одним** процессом, а класс требует двух.

### Decision Drivers

- Отказ, который «бывает», перестают читать — цена класса в недоверии к
  красному предкоммиту.
- Правка обязана быть **правилом с гейтом**, а не привычкой: каталог, забытый
  в новом тесте, вернул бы класс молча.

### Considered Options

1. **Свой `TMPDIR` на процесс, задаваемый предкоммитом.** Отвергнут: ручной
   прогон `cargo test` его не получает — то есть лечится только один из двух
   участников гонки.
2. **Общий крейт-помощник для тестов.** Отвергнут: новый крейт стоит времени
   сборки (уроки 0242 и 0244) ради одной функции.
3. **Каталог процесса как звено пути** (принято): `temp_dir()` →
   `takt_pid<PID>` → прежнее имя. Правка механическая, форма машинно
   сторожится.

### Decision

- Каталог теста лежит внутри каталога процесса:
  `std::env::temp_dir().join(format!("takt_pid{}", std::process::id())).join(…)`.
- Гейт `scripts/check-test-temp-dirs.py` получает класс **D4** — каталог от
  `temp_dir()` без идентификатора процесса.

⚠️ **Каталог процесса общий у всех файлов ПО ЗАМЫСЛУ** — он и разводит прогоны;
классы D1/D2 (совпадение имён) обязаны его пропускать, иначе гейт запретил бы
собственное лекарство. На это стоит отдельное условие сторожа.

### Consequences

- Два прогона тестов больше не мешают друг другу.
- Правка затронула **212 мест в 182 файлах** — механическая вставка звена.

#### Acceptance criteria

Две (и три) копии тестового бинарника, запущенные одновременно, зелены; гейт
ловит каталог без идентификатора процесса.

## Разработка

### Задача 0429-01

#### Что было

`std::env::temp_dir().join(format!("takt_<тег>_{thread}"))` — уникальность
только внутри процесса.

#### Что сделано

- 212 мест в 182 файлах тестов: добавлено звено `takt_pid<PID>`.
- `scripts/check-test-temp-dirs.py`: разбор звеньев пути переписан (ключом
  стало первое звено, не являющееся каталогом процесса), заведён класс D4,
  подсказка отказа показывает форму лекарства.
- `scripts/test-test-temp-dirs.sh`: девять условий вместо шести — D4, текст
  отказа и «каталог процесса пересечением не считается».

#### Проверки

Воспроизведение до правки (падение), после правки (три процесса зелены),
мутация гейта, полный прогон тестов, предкоммит.

### Результаты по функциональности

Гипотеза «перегрузка машины» проверки не потребовала: найденная причина
объясняет и текст исходной ошибки — verilator продолжал сборку в каталоге,

### Найденные дефекты

⚠️ **Правка сделала мигающим ЧУЖОЙ тест** (найдено при работе над 0433):
`address_export_tests::cli_output_to_file_matches_stdout` пишет файл по пути
`takt_pid<PID>/…`, а каталог процесса создаёт только тот тест, который зовёт
`create_dir_all`. Пока в прогоне был хоть один такой, файл ложился; в одиночном
прогоне — нет. Лечение: каталог процесса создаётся там, где файл пишет
**инструмент**, а не тест (четыре места). ⚠️ `create_dir_all` рекурсивен,
поэтому места, создающие свой подкаталог, в правке не нуждались.

⚠️ **Правка чуть не ослепила гейт:** после вставки звена `takt_pid{}` регулярки
D1/D2 перестали видеть имя каталога (оно ушло во **второй** `join`), и оба
класса замолчали бы. Поймал это сторож гейта — разбор звеньев переписан.

⚠️ **Первая редакция D4 объявила пересечением каталог процесса** — он общий у
всех по замыслу. Условие «общий каталог процесса пересечением не считается»
добавлено в сторожа именно поэтому.

### Выводы и дальнейшие шаги

Класс закрыт правилом и гейтом. Вторая гипотеза кандидата (перегрузка машины
`verilator -j 0`) осталась неподтверждённой и в работу не бралась.
