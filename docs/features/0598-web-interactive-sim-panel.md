## Краткое описание

Отдельная настраиваемая панель симуляции на странице. Рядом с кнопками прогона
(пуск, шаг, сброс, стоп) появляется кнопка **интерактивного режима**; она
открывает панель, построенную по портам модели, с двумя вкладками:

- **Входы** — входные порты модели, значения которых читатель меняет в реальном
  времени, пока идёт прогон;
- **Выходы** — порты вывода, которые читатель выбирает для наблюдения.

Интерактивный режим работает по шагам либо запуском. Прогон можно **записать**
и по кнопке сохранить в файл для последующего использования.

Отдельный режим — **интерактивная правка сценария** (дополнение заказчика
2026-09-14): прогон идёт по шагам уже имеющегося сценария, и на каждом шаге
читатель правит его значения прямо в панели — правка ложится в сам сценарий,
а не только в текущий прогон.

Сегодня входы прогона задаёт только сценарий — файл шагов (`in_ports` на такт,
проверки `guard`), составленный заранее; поменять вход посреди прогона нельзя.

## Вопросы к проработке

Записаны при регистрации, чтобы не потерять; ответы — в ADR.

- **Сессия эталона.** Прогон страницы — сессия `takt-wasm` (`open`/`tick`/`close`)
  с неизменным сценарием; нужен запрос «задать значения входов перед следующим
  тактом» тем же `SimulationRunner`, без второго цикла исполнения (инвариант
  «такт прогона делает `SimulationRunner::step`»). Значения портов эталон
  удерживает между тактами — ручной ввод ложится на то же правило.
- **Сценарий и ручной ввод вместе.** Перекрывает ли ручное значение шаг
  сценария, или интерактивный режим идёт без сценария.
- **Режим правки сценария.** Чем он отличается от интерактивного прогона и
  как между ними переключаться; что правится на шаге — `in_ports`, `guard`,
  `extern`, пояснение `_step`; можно ли вставить и удалить шаг; правка
  шага, стоящего до текущего, — перезапуск прогона с начала или отказ;
  шаг сценария задаёт не каждый такт (значения удерживаются) — идёт ли
  правка по шагам сценария или по тактам; сохранение — в тот же файл
  сценария с ревизией (конфликт с черновиком и чужой правкой), права — как у
  правки файла проекта.
- **Форма поля по типу порта.** `bit`/`bool` — переключатель, целые и
  `duration` — число с проверкой диапазона типа, перечисление — список
  вариантов, `q(m, n)`, составной порт (развёрнутые листья), двунаправленный
  порт (сторона чтения). Состав портов и типы даёт модуль, а не разбор текста
  на странице (веб-часть не знает языка).
- **Вкладка «Выходы».** Выбор наблюдаемых портов (и переменных?), где
  показывается значение — в панели, в трассе, на схеме; «вводить нужные порты
  вывода» — уточнить у заказчика: выбор списка наблюдения или ожидаемые
  значения для проверки.
- **Запись.** Формат файла — сценарий проекта (`in_ports` по тактам и,
  возможно, `guard` по наблюдаемым выходам), чтобы запись открывалась прогоном
  страницы и `takt-sim -s` без преобразования; такты без изменений входов
  (удержание значений) — сжимать ли; куда сохраняется — файл проекта (род
  «сценарий») или скачивание.
- **Настраиваемость панели.** Место (панели холста уже встают в одно из
  четырёх мест — `tool-dock`), размер, запоминание набора выходов: память
  браузера или метаданные проекта, как задержка и частота прогона.
- **Паритет плагина IntelliJ.** Панель схемы плагина собирается из `web/`
  ([панель схемы в webview плагинов редакторов](0543-scheme-in-editor-webview.md)) —
  входит ли интерактивный режим в объём.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-16
- **Authors:** разработчик, решения — заказчик

### Context

Замер 2026-09-16, чтение кода.

- Прогон страницы — сессия модуля: `takt_sim_open` строит модель и
  `SimulationRunner` со сценарием, `takt_sim_tick` делает порцию тактов,
  `takt_sim_close` закрывает. Поток прогона (`worker.js`) держит одну сессию,
  ключ сессии — текст, сценарий, частота, состав проекта и длина прогона.
- Входы такта ставит `SimulationRunner::step` из шага сценария:
  `apply_step_inputs` → `resolve_values` (имена, квалифицированные имена,
  длительность в миллисекундах, `SIM-030`/`SIM-031`) → `Unit::set_port`.
  Значения портов удерживаются между тактами. Ввести значение посреди прогона
  нечем.
- Реестр `PortNames` знает имена и направления портов модели и под-моделей,
  но не их типы; тип знает семантическое дерево (`TypeNode`), а страница языка не
  знает (правило веб-части) — форму поля ей обязан дать модуль.
- Ответ такта несёт строки трассы, состояния и переходы; значения портов уходят
  только внутри строки трассы (`Unit::get_value` → `format_value`).
- Сценарий в формате файла `-s`: `in_ports`, `inout`, `time_ms`, `extern`,
  `guard`. Файл-сценарий проекта — род `scenario` (`.json`).
- Задержка и частота прогона хранятся в метаданных проекта по имени сценария
  (`run_delays`, `run_frequencies`): столбец базы, разбор в `limits.rs`, перенос
  ключа при переименовании и удалении, копия, архив.
- `web/server/src/projects.rs` — 995 строк при пределе модуля 1000.

### Decision Drivers

- D1 — ручное значение перекрывает шаг сценария и удерживается (решение
  заказчика): правило удержания эталона не меняется.
- D2 — второго цикла исполнения нет: ручной ввод идёт через `step` той же
  воронкой разбора, что шаг сценария.
- D3 — вкладка «Выходы» — список наблюдения; набор хранится в метаданных
  проекта (решение заказчика), без проекта — до перезагрузки.
- D4 — запись — сценарий проекта: файл `.json` в открытом проекте либо
  скачивание (решение заказчика); запись открывается прогоном страницы и
  `takt-sim -s` без преобразования.
- D5 — объём тремя задачами: панель, запись, правка сценария; панель IntelliJ
  не входит (решение заказчика).
- D6 — страница языка не знает: состав портов, типы, границы и варианты
  перечислений отдаёт модуль.

### Considered Options

1. **Интерактив без сценария** — отвергнуто заказчиком.
2. **Ручной ввод пересборкой сценария и новой сессией** — отвергнуто: прогон
   начинался бы заново с первого такта на каждое изменение.
3. **Ручной ввод прямой записью в `Unit` из модуля** — отвергнуто: мимо
   `resolve_values` терялись бы квалифицированные имена, длительность и отказы
   `SIM-030`/`SIM-031`, то есть второй разбор входа.
4. **Ожидаемые значения на вкладке «Выходы»** — отвергнуто заказчиком.
5. **Набор наблюдения в браузере** — отвергнуто заказчиком.
6. **Запись только скачиванием либо только в проект** — отвергнуто заказчиком.

### Decision

- **Эталон.** `SimulationRunner::set_manual_inputs(in_ports, inout)` кладёт
  значения, которые применяются перед следующим тактом **после** шага сценария
  той же воронкой `resolve_values`; разбор идёт при постановке, и отказ приходит
  сразу. Применённое удерживается правилом эталона; повторная постановка того же
  имени заменяет значение. Такт отдаёт применённые ручные значения в `Step`
  (для записи).
- **Модуль.** Ответ `takt_sim_open` получает `ports`: имя (квалифицированное у
  двусмысленного), направление, текст типа и род поля — `bit`, `bool`,
  `integer` (границы), `duration` (миллисекунды), `fixed` (`m`, `n`), `float`,
  `enum` (варианты и значения), `composite` (без поля ввода, только наблюдение).
  Новый вызов `takt_sim_inputs {id, in_ports, inout}`. Ответ такта получает
  `values` — значения портов после последнего такта порции тем же форматом, что
  у трассы, и `manual` — применённые ручные значения по тактам.
- **Поток и страница.** Кнопка интерактивного режима рядом с пуском и шагом
  открывает панель холста с вкладками «Входы» и «Выходы»; поля строятся по
  `ports`. Изменение поля шлёт `inputs` потоку, поток — модулю, до следующего
  такта. Панель встаёт в место панелей холста, как прочие.
- **Хранение набора.** Метаданные проекта `run_watch`: объект «модель → список
  портов», ключ — имя файла модели; правило, перенос ключа, копия и архив — как у
  `run_delays`. Код сервера — в новом модуле рядом с `projects.rs`.
- **Запись (задача 02).** Страница копит применённые значения по тактам и
  строит сценарий: шаг на каждый такт, `in_ports`/`inout` — только на тактах с
  изменениями; `.json` в проект с правом записи либо скачивание.
- **Правка сценария (задача 03).** Проработка — в разделе «Анализ» этой задачи
  перед её разработкой.

### Consequences

- Трасса и сверки без ручного ввода прежние: пустой набор ручных значений не
  меняет `step`.
- Ручное значение того же порта, что шаг сценария, побеждает на своём такте;
  следующий шаг сценария снова ставит своё — это удержание эталона, а не
  «запертый» порт.
- Составной порт наблюдается, но вводится только листьями — развёрнутыми
  именами; целиком он в панели не редактируется.

#### Acceptance criteria

1. Ручное значение применяется перед следующим тактом, побеждает шаг сценария
   и удерживается (тест эталона).
2. Неизвестное имя и негодное значение отвергаются при постановке тем же кодом,
   что у сценария (тест эталона и модуля).
3. Без ручного ввода трасса байт в байт прежняя (тождественность модуля).
4. `ports` даёт род поля, границы и варианты для каждого рода порта (тест модуля).
5. Панель: вкладки, поля по роду, значения выходов после такта (тест страницы,
   живая проверка).
6. Набор наблюдения сохраняется в проекте, переносится при переименовании
   модели, копируется и попадает в архив (проверки сервера).

### Цель и контекст

Дать читателю менять входы модели во время прогона, видеть выбранные выходы,
записывать прогон сценарием и править сценарий по шагам. Замер — в ADR.

### Зависимости фичи

Нет. Панели холста, поток прогона и метаданные проекта уже существуют.

### Обратная совместимость

Язык не меняется, версия языка не поднимается. Формат сценария не меняется —
запись пишет существующие поля. Ответы модуля получают новые поля; схема базы —
новый столбец с умолчанием `'{}'`; архив — необязательное поле манифеста.
