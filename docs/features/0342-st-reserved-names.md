## Краткое описание

`var ln: u8 := 1;` давал невалидный ST при нулевом коде возврата `taktc`: `LN` —
стандартная функция IEC, но список зарезервированных имён её не знал. Не хватало
двадцати имён.

## Документирование (правило 24)

**Не требуется** — подтверждено: правится список цели, не язык.

## Итог (что сделано)

**Знание о чужом инструменте теперь проверяется прогоном этого инструмента.**

- **Список дополнен двадцатью именами** — математические функции (`ln`, `log`,
  `exp`, тригонометрия, `trunc`) и операции с функциональной формой (`mod`,
  `and`, `or`, `xor`, `not`, `add`, `sub`, `mul`, `div`, `move`).
- **Сторож прогоняет `iec2c`** по каждой записи и требует контрольного имени,
  которое инструмент принимает: иначе тест доказывал бы лишь, что `iec2c`
  ругается на любой вход.
- ⚠️ **Сторож немедленно опроверг мой собственный замер:** `adr`, `size`,
  `bcd_to_int`, `int_to_bcd` инструмент **принимает** — они в список не вошли,
  иначе цель отказывала бы зря.
- ⚠️ **Полноту список не доказывает** (словаря всех имён MatIEC нет) — только
  обоснованность каждой записи. Граница названа.
- ⚠️ **Класс найден случайно:** имя `ln` стояло в пробе фичи 0341 и дало
  посторонний отказ, приписанный сперва вложенной структуре (правило 30 —
  снимать причины по одной).
