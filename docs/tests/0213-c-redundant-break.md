# Тест-план фичи 0213: Цель c печатает лишний break после безусловного перехода

> Фича: [../features/0213-c-redundant-break.md](../features/0213-c-redundant-break.md) · ADR: [../adr/0213-c-redundant-break.md](../adr/0213-c-redundant-break.md) · анализ: [../analyze/0213-c-redundant-break.md](../analyze/0213-c-redundant-break.md)

## Область и цель

Проверяется **форма вывода** цели `c` и **тождественность поведения**: после
безусловного ребра цель не печатает ни собственный `break;` (R2), ни рёбра,
стоящие за ним (R1), при этом условное ребро (R4), терминальное состояние и
прочие места печати `break;` (R5) не затронуты, автомат прежний (R3), вывод
детерминирован (R6), корпус пересобран (R7).

Инструменты в этой области не свидетели: `cc -Wall -Wextra -Wunreachable-code`
принимает и прежний вывод, и новый, и вывод половинчатой правки. Поэтому
проверки — на **текст порождённого C** и на **потактовую трассу**.

## Проверки (условие → ожидаемый результат)

| # | Проверка | Предусловие | Ожидаемый результат | Ссылка на R/A |
|---|---|---|---|---|
| T1 | Корпус не даёт двух `break;` подряд | каждый `examples/*.takt` компилируется целью `c` | ни одной пары; при провале — **список** «файл: строки» | R2 / A1 |
| T2 | Ребро после безусловного не печатается | фикстура `tail_after_unconditional.takt` | в ветви `case … RUN` есть переход в `DONE`, нет упоминания `LATE`, ровно один `break;` | R1 / A2 |
| T3 | Условное ребро сохраняет свой `break;` | фикстура `conditional_and_terminal.takt` | в ветви `case … WAIT` два `break;`: внутри `if` и общий | R4 / A2 |
| T4 | Терминальное состояние уходит в `_END` | та же фикстура | в ветви `case … STOP` есть `model->state = …_END;` и ровно один `break;` | R5 / A2 |
| T5 | Поведение тождественно | модель с безусловным ребром и **истинным на том же такте** хвостом | трассы эталона и порождённой прошивки совпадают: `[1, 0, 0, 0]` | R3 / A3 |

## Тестовые данные и окружение

- Фикстуры: `takt-lang/tests/data/cbreak0213/tail_after_unconditional.takt`,
  `conditional_and_terminal.takt`. Условие хвоста — `n = 1` (истинно на такте
  безусловного перехода): при ложном условии T5 не отличает верную правку от
  половинчатой.
- Модель сверки T5 задана строкой в самом тесте
  (`conformance_c_unconditional_edge_tests.rs`), наблюдаемое — переменная `n`.
- Окружение: toolchain `1.97.1` (пин `rust-toolchain.toml`), `cc` (Apple clang),
  cmake + ninja, `iec2c`, verilator, yosys — как в `precheck.sh`.
