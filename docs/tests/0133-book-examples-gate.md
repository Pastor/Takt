# Тест-план фичи 0133: Гейт компиляции и симуляции примеров документа `book/`

> Фича: [../features/0133-book-examples-gate.md](../features/0133-book-examples-gate.md) · анализ: [../analyze/0133-book-examples-gate.md](../analyze/0133-book-examples-gate.md) · отчёт: [../reports/0133-book-examples-gate.md](../reports/0133-book-examples-gate.md)

## Область и цель

Фича **инфраструктурная плюс правка документации**: заводится проверка и чинится
один пример. Язык не меняется, поэтому правило 16 применяется в части «примеры и
контрпримеры» — но не к языку, а **к самому гейту**: проверяется, что он ловит
ровно то, ради чего заведён.

Ключевой риск области — «зелёный гейт, который ничего не проверяет». Поэтому
центральные проверки — **ловушки**: намеренно испорченный пример обязан валить
предкоммит.

## Примеры и контрпримеры (правило 16)

**Пример — то, что гейт обязан пропускать:**

```takt
model Lamp {
    in btn: bit;
    out led: bit;
    start Off { enter { led := 0; } ref On: btn = 1; }
    state On  { enter { led := 1; } ref Off: btn = 0; }
}
start Main = Lamp;
```

**Контрпример 1 — не компилируется** (недопустимая форма и нет входа):

```takt
model Broken {
    start state Off { }
}
```

**Контрпример 2 — компилируется, но падает на такте** (правило переполнения,
фича 0127):

```takt
var s: i8 := 127;
start S { always { s := s + 1; } ref S: s = 100; }   // SIM-003
```

## Разбивка проверок по функциональности

- **Полнота охвата** — A1, A2.
- **Гейт взведён** — A3, A4 (обе стороны правила 27д: компиляция и симуляция).
- **Найденное починено** — A5, A6, A7.
- **Единый источник истины** — A8, A9.

## Тестовые данные и окружение

Отдельных фикстур не требуется: гейт работает по реальному дереву `book/src`.
Ловушки ставятся **временной подменой** существующего примера и откатываются
сразу после проверки — в репозиторий они не попадают (это ручная проверка
взведённости, а не автотест: автотест мутировал бы документ).

Сценарий кнопки для A6 — четыре шага JSON (`btn` = 1, 1, 0, 0), подаётся
`takt-sim -s`.
