# Тест-план фичи 0220: Флаг -Wextra для гейта цели c: 38 предупреждений одного класса

> Фича: [../features/0220-c-gate-wextra.md](../features/0220-c-gate-wextra.md) · ADR: [../adr/0220-c-gate-wextra.md](../adr/0220-c-gate-wextra.md) · анализ: [../analyze/0220-c-gate-wextra.md](../analyze/0220-c-gate-wextra.md)

## Область и цель

Фича меняет **флаги гейтов**, а не код. Поэтому обычных автотестов у неё нет, а
проверки отвечают на три вопроса:

1. **Флаг стоит там, где обещано** — в обоих гейтах цели `c` (T1).
2. **Флаг работает, а не вписан** — предупреждение из набора `-Wextra` роняет
   сборку с этими флагами и **не** роняет со старыми (T4). Без этой проверки
   «включение строгости» неотличимо от строки в скрипте.
3. **Строгость бесплатна и генератор не тронут** — предкоммит зелёный,
   порождённый код прежний (T2, T3, T5).

## Тестовые данные и окружение

- Гейты: `scripts/precheck.sh` (сборка корпуса через `cmake`+`ninja`, сборка
  `c-hal` через `cc -c`).
- Корпус: `examples/generated/c` (39 файлов, включая харнессы `*_main.c`);
  вывод `c-hal` строится в прогоне для всех `examples/*.takt`.
- Мутация T4 — на **копии** корпуса во временном каталоге сессии: рабочее
  дерево не трогается.
- Окружение: `cc` (Apple clang), `cmake`, `ninja`; прочие инструменты
  `precheck.sh` — как обычно.
