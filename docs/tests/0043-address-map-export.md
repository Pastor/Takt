# Тест-план фичи 0043: Экспорт карты адресов во внешний формат

> Фича: [../features/0043-address-map-export.md](../features/0043-address-map-export.md) · ADR: [../adr/0043-address-map-export.md](../adr/0043-address-map-export.md) · анализ: [../analyze/0043-address-map-export.md](../analyze/0043-address-map-export.md)

## Область и цель

Проверяем, что выгрузка карты адресов **соответствует факту** (тем адресам, что
разрешает `resolve_addresses` и потребляет `-t c-hal`), что формат `map`
**замыкается** через `--address-map`, что `json` — валиден и полон, и что
поведение на краях (порт без адреса, неизвестный формат, оверлей) определено.

Фича **не меняет язык** (версия 0.2.0), поэтому правило 16 применяется к
**формату выгрузки** как к языку интерфейса: примеры и контрпримеры ниже — это
модели и ожидаемые выгрузки, они же идут в документацию по формату.

Покрытие требований анализа: R1–R11; критерии A1–A10.

## Проверки (условие → ожидаемый результат)

| # | Проверка | Предусловие | Ожидаемый результат | Ссылка на R/A |
|---|---|---|---|---|

## Примеры и контрпримеры (правило 16)

Правило 16 требует примеры и контрпримеры; язык здесь не меняется, поэтому они
формулируются для **формата выгрузки**. После реализации примеры идут в
документацию формата (`README.md` — правило 15).

### Примеры (должны выгружаться корректно)

- **П1 — три источника и оверлей** (основа T2–T5, воспроизведена пробой
  2026-07-15). Фикстура `tests/data/address_export/probe.lam`:

  ```lam
  type u8 = [bit;8];
  in  BTN: u8 := 0x00200000;
  out LED: bit;
  in  SW:  bit := 0x00300000:3;
  address LED = 0x00200004;
  start Idle { ref On: BTN; }
  state On { ref Idle: SW; }
  ```

  плюс карта `plat.map`:

  ```text
  // оверлей платформы
  BTN = 0x40000000;
  ```

  Ожидаемая выгрузка `--emit map` (`BTN` — из карты, `LED` — из оператора
  `address`, `SW` — inline с битом):

  ```text
  BTN = 0x40000000;
  LED = 0x00200004;
  SW = 0x00300000:3;
  ```

  Сверка с фактом (T9): при `-t c-hal` та же модель и карта дают
  `[PROBE_BTN] = { 0x40000000u, -1, 1 }`, `[PROBE_LED] = { 0x200004u, -1, 4 }`,
  `[PROBE_SW] = { 0x300000u, 3, 4 }` — адреса и биты обязаны совпасть.

- **П2 — полная карта на реальном примере.** `examples/elevator_mini.lam`
  (44 порта) + карта, покрывающая все порты: выгрузка содержит ровно 44 записи;
  круговой рейс замыкается (T20).

- **П3 — `json` полон.** Та же П1 в `--emit json`: на каждый порт — имя, адрес,
  бит (пусто для `LED`/`BTN`), источник (`External`/`Operator`/`Inline`), тип,
  направление; плюс версия формата.

### Контрпримеры (должны отвергаться или явно помечаться)

- **К1 — достижимый порт без адреса** (T15). `examples/elevator_mini.lam` без
  карты → `SE-052` («порт 'ElevatorMotor_Up' используется в кодогенерации, но не
  имеет адреса»), ненулевой код. Воспроизведено пробой 2026-07-15.
- **К2 — мёртвый порт без адреса** (T14). Порт объявлен, нигде не используется,
  адреса нет → **не** ошибка (согласовано с политикой полноты 0020), но и **не**
  `0x0`: в `map` записи нет, в `json` — явная пометка. Проверяем именно
  отсутствие `0x0` — это главный способ соврать в выгрузке.
- **К3 — висячая запись карты** (T17). `GHOST = 0x50000000;` при отсутствии порта
  `GHOST` → `SE-051` в stderr, `GHOST` в выгрузку **не попадает**.
- **К4 — неизвестный формат** (T18). `--emit svd` → ошибка. Существенно: SVD
  отклонён в ADR, и подкоманда обязана сказать это внятно, а не выдать пустой
  файл.
- **К5 — испорченная входная карта.** `--address-map` с битой записью
  (`BTN 0x40000000;` — нет `=`) → `AM-002`, ненулевой код, выгрузки нет.
- **К6 — stdout, испорченный диагностикой** (T16). Контрпример к реализации: если
  `SE-050` уедет в stdout, `parse_address_map` над stdout упадёт — тест обязан
  это поймать.

## Тестовые данные и окружение

- **Фикстуры:** `grammar/tests/data/address_export/` — `probe.lam` (П1),
  `plat.map` (оверлей), `ghost.map` (К3), `broken.map` (К5),
  `dead_port.lam` (К2), `collide.lam` (T21).
- **Реальный корпус:** `examples/*.lam` (T20); `examples/elevator_mini.lam` —
  К1/П2 (карта на 44 порта генерируется в тесте, чтобы не хранить производное).
- **Тесты:** `grammar/tests/address_map_tests.rs` (существует — расширяем
  экспортом и круговым рейсом); сверка с C — по образцу
  `grammar/tests/codegen_tests.rs::c_hal_emits_address_table_and_hal`;
  юнит-тесты разбора флагов — в `grammar/src/bin/lamc.rs` рядом с
  `parse_fmt_args`.
- **Валидация `json`** — `serde_json` (**безусловная dev-зависимость** `grammar`,
  проверено в `Cargo.toml`); внешних схем и сетевых валидаторов **не требуется**.
  Это прямое следствие отказа от SVD: XSD-валидация в CI потребовала бы внешнего
  валидатора и копии схемы, а `serde_json` уже есть.
- **Оракул кругового рейса** — `parse_address_map` (`address_map.rs:138`);
  эталонных файлов выгрузки не заводим: инвариант
  `export∘import∘export = export` самодостаточен и не протухает.
- **Порядок прогона:** `cargo test -- --test-threads=1` (однопоточно —
  `CLAUDE.md`), `cargo test --features lsp -- --test-threads=1`,
  `./scripts/precheck.sh`.
- **Методика новых тестов** (`CLAUDE.md`): сперва зонд, захватывающий реальный
  вывод, затем assertions против **захваченных** значений — строки и адреса не
  угадывать. Ожидания в П1 уже получены пробой, а не выдуманы.
