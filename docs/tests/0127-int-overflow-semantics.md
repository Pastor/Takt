# Тест-план фичи 0127: Единая семантика переполнения целых во всех целях

> Фича: [../features/0127-int-overflow-semantics.md](../features/0127-int-overflow-semantics.md) · анализ: [../analyze/0127-int-overflow-semantics.md](../analyze/0127-int-overflow-semantics.md) · отчёт: [../reports/0127-int-overflow-semantics.md](../reports/0127-int-overflow-semantics.md)

## Область и цель

Фича **языковая**: нормируется семантика арифметики, поэтому правило 16
применяется полностью — проверки, примеры и контрпримеры.

Центральный вопрос проверки: **одинаково ли считают эталон и все цели**. Поэтому
основной инструмент — потактовая сверка исполнением, а не чтение вывода: молча
неверная трансляция компилируется и проходит гейты (урок 0045).

## Проверки (условие → ожидаемый результат)

| # | Условие | Ожидаемый результат |
|---|---|---|
| A1 | вывод цели `rust` для `u8`-арифметики | `wrapping_add`/`wrapping_sub`/`wrapping_mul`, ни одного `+=` над беззнаковым |
| A2 | вывод цели `rust` для `i8`-арифметики | обычный `+` (обёртка НЕ печатается) |
| A3 | трасса симулятора на фикстуре переполнения | `254, 255, 0, 1, 2, 3` — обёртка на третьем такте |
| A4 | сверка с целью `c` | трассы совпадают потактово |
| A5 | сверка с целью `rust` | трассы совпадают потактово |
| A6 | сверка с целью `sv` | трассы совпадают потактово |
| A7 | сверка с целью `st` | трассы совпадают с поправкой на INIT-сдвиг; в трассе присутствует переход `255 → 0` |
| A8 | взведённость сторожа | откат правки генератора (`is_unsigned_int` → `false`) обязан красить A5 |
| A9 | знаковое переполнение в симуляторе | `SIM-003`, прогон остановлен |
| A10 | документация | раздел «Типы» содержит нормативную формулировку обоих случаев |
| A11 | `./scripts/precheck.sh` | `EXIT=0` |

## Примеры и контрпримеры (правило 16)

**Пример — определённое поведение (беззнаковое):**

```takt
var t: u8 := 254;
start Counting {
    always { t := t + 1; }   // 254 → 255 → 0 → 1 …
}
```

**Контрпример — ошибочная программа (знаковое):**

```takt
var s: i8 := 127;
start Counting {
    always { s := s + 1; }   // SIM-003: 128 не помещается в i8
}
```

Оба вошли в документацию (раздел «Типы» → «Переполнение»); упоминание `SIM-003` —
в блоке «Частые ошибки» того же раздела.

## Разбивка проверок по функциональности

- **Правило соблюдается всеми целями** — A3–A7 (главная группа).
- **Знаковый случай не «починен» молча** — A2, A9.
- **Сторож настоящий, а не удачливый** — A8.
- **Правило названо пользователю** — A10.
- **Контракт проекта** — A11.

## Тестовые данные и окружение

Фикстура — `takt-sim/tests/data/eval/conformance_overflow.takt` (общая для
сверок `c`, `sv`, `st`); сверка `rust` использует собственный исходник с
выходным портом, поскольку поля порождённой прошивки приватны и наблюдение идёт
через HAL. Инструменты: `cc`, `rustc`, `verilator`, MatIEC `iec2c`; при
отсутствии любого из них соответствующая сверка **мягко пропускается**, а трасса
симулятора остаётся пришпиленной числом — то есть тест не превращается в
пустышку.

⚠️ **Ограничение сверки `st`:** цель тратит такт на вход в каждый уровень
стартового состояния (долг контракта 0033, к переполнению отношения не имеющий),
поэтому сравнение идёт с поправкой на сдвиг — по конвенции, уже принятой в
Q-сверке. Чтобы поправка не «съела» смысл, добавлено отдельное утверждение о
наличии перехода `255 → 0`.
