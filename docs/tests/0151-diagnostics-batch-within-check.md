# Тест-план фичи 0151: Накопление диагностик внутри отдельной проверки `validate`

> Фича: [../features/0151-diagnostics-batch-within-check.md](../features/0151-diagnostics-batch-within-check.md) · ADR: [../adr/0151-diagnostics-batch-within-check.md](../adr/0151-diagnostics-batch-within-check.md) · анализ: [../analyze/0151-diagnostics-batch-within-check.md](../analyze/0151-diagnostics-batch-within-check.md)

## Область и цель

Проверяется **сколько** сообщений видит пользователь за прогон и **где проходит
граница** накопления. Наблюдается прогоном бинаря: предмет — вывод инструмента,
а не внутренний интерфейс проверок.

Файл: `takt-lang/tests/semantic/validate_batch_tests.rs`.

## Проверки (условие → ожидаемый результат)

| # | Проверка | Предусловие | Ожидаемый результат | Ссылка на R/A |
|---|---|---|---|---|
| T1 | два `ref` с неразрешённым условием | разные состояния | две `SE-025` | A1, R1 |
| T2 | два `cond` с неразрешённым условием | два объявления | две `SE-025` | A1, R1 |
| T3 | две переменные `bit` | недопустимые значения | две `SE-035` | A1, R1 |
| T4 | два массива | недопустимый размер | две `SE-038` | A1, R1 |
| T5 | два `address` | несуществующие порты | две `SE-048` | A1, R1 |
| T6 | два обращения к ячейке | в инициализаторах | две `SE-099` | A1, R1 |
| T7 | разные проверки | `SE-026` + `SE-035` + `SE-025` | все три | A2, R3 |

## Разбивка проверок по функциональности

Единые условия и ожидаемые результаты прогоняются против каждой задеваемой обратной функциональности
(правило 11); фиксируется статус.

| Функциональность | T1–T6 | T7–T8 | T9–T11 | Статус |
|---|---|---|---|---|
| `taktc compile` | ✅ | ✅ | ✅ | пройдено |
| LSP | — | — | — | тот же вход `validate_model_all`; отдельной проверки не требует |
| Стадии построения дерева | — | ✅ (T8) | — | терминальность сохранена |
| Цели генерации, симулятор, корпус | — | — | — | не применимо: при ошибке порождения нет |

## Тестовые данные и окружение

- Каждый класс — из **замера** анализа: тест заводится на то, что реально
  теряло сообщение, а не на воображаемый случай.
- ⚠️ Один код может рождаться в **двух** местах: `SE-025` — на ребре перехода и
  в объявлении `cond`. Тесты держат оба; мутация показала, что одного мало.
- Каталог теста уникален по имени потока (фича 0190).
