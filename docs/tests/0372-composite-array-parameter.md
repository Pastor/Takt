# Тест-план фичи 0372: Составной элемент массива в параметре функции

> Фича: [../features/0372-composite-array-parameter.md](../features/0372-composite-array-parameter.md) · ADR: [../adr/0372-composite-array-parameter.md](../adr/0372-composite-array-parameter.md) · анализ: [../analyze/0372-composite-array-parameter.md](../analyze/0372-composite-array-parameter.md)

## Область и цель

Проверяются требования R1…R6 анализа: вывод целей `sv` и `st` принимается их
инструментами, **значения** совпадают с эталоном, вывод корпуса не меняется, а
знание о раскладке и об имени формы живёт по одному носителю.

⚠️ Факт компиляции ничего не доказывает: перепутанный порядок конкатенации даёт
валидный RTL с зеркальными значениями, а `iec2c` принимает и перепутанные
индексы. Поэтому основной сторож — **потактовая сверка**, а инструменты
проверяются отдельно.

## Тестовые данные и окружение

- Фикстура — `takt-sim/tests/data/eval/conformance_composite_param.takt`: три
  вида составного элемента разом, наблюдаемые различают края массива, поля
  элемента и позиции внутреннего массива; четыре из шести меняются по тактам.
- Набор — `takt-sim/tests/conformance/conformance_composite_param_tests.rs`
  (тема `conformance`, правило 0244).
- Юнит-тесты носителей — `generator/sv/sv_array.rs` и `generator/st/st_type.rs`.
- Инструменты: `verilator` ≥ 5.050, `yosys` ≥ 0.68, `iec2c` (MatIEC) + `cc`.
  Нет инструмента → тест-**пропуск** с сообщением, а не красный: пакетом они не
  поставляются.
