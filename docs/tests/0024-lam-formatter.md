# Тест-план фичи 0024: Канонический форматтер .lam (lamc fmt)

> Фича: [../features/0024-lam-formatter.md](../features/0024-lam-formatter.md) · ADR: [../adr/0024-lam-formatter.md](../adr/0024-lam-formatter.md) · анализ: [../analyze/0024-lam-formatter.md](../analyze/0024-lam-formatter.md)

## Область и цель

Проверить требования R1–R7 и критерии A1–A7 анализа: печать от АСД, сохранность
комментариев, идемпотентность, семантическую нейтральность, канонический стиль,
единое ядро для трёх потребителей и контракт CLI.

## Главная проверка — корпус, а не отдельные примеры

Форматтер печатает **всё** дерево, поэтому парой фикстур его не проверить: любой
непокрытый узел молча испортил бы исходник. Основная проверка —
`grammar/tests/format_tests.rs`: прогон по **всему корпусу** `.lam` репозитория
(`examples/`, `grammar/tests/data/`, `simulation/tests/data/` — 158 файлов) с
двумя инвариантами на каждом файле и **сводкой покрытия**.

Гейт устроен так, чтобы «не отформатировано» не стало тихой нормой: тест **падает**
при появлении любого непокрытого узла.

## Проверки (условие → ожидаемый результат)

### Группа 1. Инварианты на корпусе

| # | Проверка | Предусловие | Ожидаемый результат | R/A |
|---|---|---|---|---|
| T1 | Идемпотентность | каждый разбираемый файл корпуса | `fmt(fmt(x)) == fmt(x)` | R3 / A1 |
| T2 | Семантическая нейтральность | то же | `parse(fmt(x))` структурно равен `parse(x)` (без учёта `Location`) | R4 / A3 |
| T3 | Полнота печати | то же | непокрытых узлов — **0**; новый узел валит тест | R1 |
| T4 | Стиль на большом файле | `elevator.lam`, `stacker.lam` | идемпотентно и парсится обратно | A7 |

### Группа 2. Комментарии (главный риск ADR)

| # | Проверка | Ожидаемый результат | R/A |
|---|---|---|---|
| T5 | Три вида комментариев | `//`, `///`, `/* */` сохраняются; ни один не теряется | R2 / A2 |
| T6 | Хвостовой комментарий | остаётся **на строке своего узла** (`var x: u8 := 0; // счётчик`) | R2 |
| T7 | Идемпотентность комментариев | при повторном прогоне не дублируются и не смещаются | R2, R3 |
| T8 | Пустая строка между группами комментариев | сохраняется (шапка файла не слипается с доком элемента) | R2, R5 |

### Группа 3. Канонический стиль

| # | Проверка | Ожидаемый результат | R/A |
|---|---|---|---|
| T9 | Нормализация объявления | `var   x :u8:=0;` → `var x: u8 := 0;` | R5 |
| T10 | Отступы тела | `state A { ref B: x > 1; }` → тело с отступом в 4 пробела | R5 |
| T11 | Финальный перевод строки | ровно один в конце файла | R5 |
| T12 | Пустые строки | восстанавливаются из исходника, **не более одной подряд** | R5 |
| T13 | Нет пустой строки после многострочной `fn` | она не появляется на ровном месте | R5 |

### Группа 4. Семантическая нейтральность в деталях

| # | Проверка | Ожидаемый результат | R/A |
|---|---|---|---|
| T14 | Операторы `:=` / `=` | не подменяются: `x: u8 := 1` и `ref B: x = 1` печатаются как есть (инвариант фичи 0021) | R4 / A5 |

## Тестовые данные и окружение

- **Корпус:** все `.lam` репозитория (158 файлов) — фикстуры не заводятся
  отдельно: форматтер обязан работать на **реальном** коде проекта.
- `grammar/tests/format_tests.rs` — корпус, стиль, комментарии, CLI (через
  настоящий бинарник `CARGO_BIN_EXE_lamc`).
- `grammar/tests/lsp_tests.rs` — `textDocument/formatting`, A6.
- `grammar/src/bin/lamc.rs` — юнит-тесты `parse_fmt_args`.
- `cargo test --all-features -- --test-threads=1`; `./scripts/precheck.sh`
  (включает `lamc fmt --check examples/`).

## Ограничение проверяемости: фикстуры не нормализуются

`lamc fmt --check` в `precheck.sh` покрывает **только** `examples/`. Фикстуры
`grammar/tests/data/` намеренно **не** приводятся к канону: часть тестов (в
первую очередь LSP) завязана на их раскладку и позиции, и нормализация сломала бы
проверки, ничего не улучшив. Это осознанное сужение области, а не пропуск.
