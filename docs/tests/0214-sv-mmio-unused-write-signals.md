# Тест-план фичи 0214: Регистровый интерфейс `sv-mmio`

> Фича: [../features/0214-sv-mmio-unused-write-signals.md](../features/0214-sv-mmio-unused-write-signals.md) · ADR: [../adr/0214-sv-mmio-unused-write-signals.md](../adr/0214-sv-mmio-unused-write-signals.md) · анализ: [../analyze/0214-sv-mmio-unused-write-signals.md](../analyze/0214-sv-mmio-unused-write-signals.md)

## Область и цель

Проверяется **состав** порождённого интерфейса и то, что все его потребители
следуют за ним. Линт и синтез состава не различают: модуль с лишним входом
валиден (урок ADR 0045), поэтому форма проверяется текстом, а поведение —
тестбенчем с настоящими циклами APB.

## Проверки (условие → ожидаемый результат)

| # | Проверка | Предусловие | Ожидаемый результат | Ссылка на R/A |
|---|---|---|---|---|
| T1 | Ядро без входных портов | все порты `out` | нет `reg_wdata`/`reg_wen`, `reg_rdata` на месте | R2 / A5 |
| T2 | Ядро с входным портом | есть `in` | все четыре сигнала | R3 / A5 |
| T3 | Адаптер APB следует за ядром | ядро без записи | нет `.reg_wdata(`/`.reg_wen(`, есть поглощение | R4 / A5 |
| T4 | Линт чист | `regulator` целью `sv-mmio` | 0 `UNUSEDSIGNAL` под `-Wall` | R2 / A1 |
| T5 | Вывод с записью не изменился | `stacker`, ядро и адаптер | байт-в-байт прежний | R3 / A2 |
| T6 | Пара «ядро + APB» синтезируется | `regulator` | verilator и yosys принимают | R4 / A3 |
| T7 | Поведение шины | тестбенч `regulator_apb_tb.sv` | 4 проверки пройдены | R5 / A4 |
| T8 | Потактовая сверка | `conformance_sv_mmio_tests` | тестбенч строится по интерфейсу ядра | R7 / A6 |
| T9 | Гейт видит класс | `SV_MMIO_TRANSLATABLE` | содержит модель без входных битов | R6 / A6 |
