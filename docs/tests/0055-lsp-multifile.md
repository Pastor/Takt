# Тест-план фичи 0055: Многофайловость LSP

> Фича: [../features/0055-lsp-multifile.md](../features/0055-lsp-multifile.md) · ADR: [../adr/0055-lsp-multifile.md](../adr/0055-lsp-multifile.md) · анализ: [../analyze/0055-lsp-multifile.md](../analyze/0055-lsp-multifile.md)

## Область и цель

Проверяется **что увидит автор в редакторе** (разрешился ли импорт, где легла
подсветка, что сказано в тексте) и **что не изменилось у компилятора** (сборки с
`-I` находят те же файлы).

**Ключевой принцип плана.** Фича добавляет неявный путь поиска — то есть трогает
разрешение импорта у **всех** инструментов. Поэтому каждая проверка «стало
работать» обязана иметь пару «прежнее поведение сохранено»: аддитивность —
обещание фичи (правило 11), а не побочность.

## Тестовые данные и окружение

**Фикстуры** `grammar/tests/data/lsp55/` (правило 16 — пара «работает / ошибка»):

| Фикстура | Роль |
|---|---|
| `lib_ok.lam` | библиотека без ошибок |
| `uses_ok.lam` | импорт рядом — обязан разрешиться |
| `lib_bad.lam` | библиотека с ошибкой (`ref Nowhere`) |
| `uses_bad.lam` | импортёр: чужая ошибка обязана быть показана и названа |

⚠️ **Тесты LSP живут под `#[cfg(feature = "lsp")]`** — обычная `cargo build` их
**не видит**; собирает только `precheck.sh` (`--all-features --all-targets`).

**Где живут проверки:** `grammar/tests/lsp_tests.rs::lsp_multifile` (T1, T5–T7);
пробы CLI (T3, T4, T8); регресс — `./scripts/precheck.sh` (T2, T10).

## Как воспроизвести

```sh
cargo test -p grammar --features lsp --test lsp_tests -- --test-threads=1
./scripts/precheck.sh

# Проба (T3, T8): импорт рядом без -I + цепочка импорта
lamc compile -t c top.lam -o /tmp/o.c
#   deep.lam:2:18: Ошибка компиляции [SE-002]: Ссылка 'Missing' не найдена
#     примечание: 'deep.lam' импортирован в 'mid.lam'
#     примечание: 'mid.lam' импортирован в 'top.lam'
```
