# Тест-план фичи 0037: Сбои тестов на Windows (пути include, ресурс viewport)

> Фича: [../features/0037-windows-test-failures.md](../features/0037-windows-test-failures.md) · ADR: [../adr/0037-windows-test-failures.md](../adr/0037-windows-test-failures.md) · анализ: [../analyze/0037-windows-test-failures.md](../analyze/0037-windows-test-failures.md)

## Область и цель

Проверяется, что шесть тестов, падавших **только на Windows**, зелены на обеих
платформах; что продуктовый код и CLI-контракт `lamc` при этом **не изменились**
(правило 11); что покрытие не уменьшилось; и что Windows появился в матрице CI.
Связь с анализом: требования **R1–R10**, критерии **A1–A12**.

**Правило 16 не порождает здесь языковых проверок.** Фича **не меняет** ни
синтаксис, ни семантику языка (правки — в `mod tests` двух файлов и в
`.github/workflows/ci.yml`), поэтому обязательный для языковых фич блок
«тесты корректности языка и компилятора + примеры и контрпримеры» — **не
применим**; версия языка остаётся 0.2.0 (правило 22). Тем не менее дух правила
16 соблюдается на уровне предмета фичи: для каждого разбираемого класса входа
ниже даны **пример** (что должно разбираться) и **контрпример** (что не должно) —
см. раздел «Примеры и контрпримеры».

## Главная методическая проблема: как проверить Windows, не имея Windows

**Проблема ставится честно: полноценно — никак.** Разработка ведётся на darwin.
Снят эталон **до** правки:

- `cargo test --bin lamc -- --test-threads=1` → **44 passed**;
- `cargo test -p simulation test_highlight -- --test-threads=1` → **1 passed**.

То есть **все шесть «падающих» тестов на darwin зелёные и до, и после
исправления**. Локальный прогон по этим тестам **не несёт информации** о
починке: он даст «зелено» в любом случае, включая случай, когда правка сделана
неверно. Любой отчёт, где A8/A9 закрыты локальным прогоном на macOS/Linux,
— **недостоверен**.

Отсюда — трёхуровневая стратегия; уровни 1–2 доступны локально и ловят
**большинство** ошибок реализации, уровень 3 — единственное настоящее
доказательство:

| Уровень | Что даёт | Что **не** даёт |
|---|---|---|
| **1. Статические проверки диффа** (T1–T4) | Ловит саму причину класса дефектов: зашитый `:`, обращение к ФС, выход диффа за `mod tests`. Не требует прогона вообще | Не доказывает, что тест на Windows **проходит** |
| **2. Косвенные проверки логики без Windows** (T5–T7) | Проверяет ветку `cfg(windows)` **на darwin**: (а) прогон тестов с принудительным разделителем; (б) `cargo check --target x86_64-pc-windows-msvc` — **компилирует** windows-ветки `cfg`, ловя опечатки в невидимом на Unix коде | Не исполняет код на Windows: ни ФС, ни рантайм не проверяются |
| **3. Job `windows` в CI** (T8–T12) | Единственная настоящая проверка A8/A9 | Требует, чтобы 0037-03 была сделана — поэтому она **в объёме фичи**, а не «на потом» |

**Уровень 2, приём (а) — как проверить платформенную ветку теста на darwin.**
Тесты 0037-01 параметризуются `cfg`-константой `SEP`. На darwin ветка
`#[cfg(windows)]` недостижима, но **сама проверяемая логика** доступна: контроль
даёт тест `split_semicolon_is_not_unix_separator` (`lamc.rs:776`, уже
существующий) — он фиксирует, что на Unix `;` **не** разделяет. Симметричный
факт для Windows (`:` не разделяет) на darwin непроверяем; ожидание фиксируется в
коде и проверяется уровнем 3.

**Уровень 2, приём (б) — кросс-компиляция.** `rustup target add
x86_64-pc-windows-msvc` + `cargo check --target x86_64-pc-windows-msvc
--all-targets` **собирает** ветки `#[cfg(windows)]`, включая тестовые. Это ловит
класс «Windows-код не компилируется» (опечатка в `#[cfg(windows)] const SEP`,
несобираемый тест) **без Windows**. Ограничение честное: `cargo check` не
линкует и **не исполняет** — падение `fs::write("/tmp/…")` таким способом
поймать нельзя в принципе, это рантайм.

## Примеры и контрпримеры (дух правила 16)

Предмет фичи — не язык, а разбор списка путей. Примеры даются для него:

**Примеры (разбирается корректно; ожидание одинаково на обеих платформах после
подстановки платформенного разделителя `SEP`):**

| Вход | Ожидаемый `include_dirs` |
|---|---|
| `-I /lib/lam{SEP}/usr/lam` | `["/lib/lam", "/usr/lam"]` |
| `--include-dirs /lib{SEP}/usr` | `["/lib", "/usr"]` |
| `-I/a{SEP}/b` (слитная форма) | `["/a", "/b"]` |
| `-I /a{SEP}{SEP}/b` (пустой сегмент) | `["/a", "/b"]` |
| `-I /a -I /b` (повторяемый флаг) | `["/a", "/b"]` — **единственная форма, не зависящая от платформы** |

**Контрпримеры (не должны разбираться как список — платформенно-специфичны):**

| Вход | Платформа | Ожидание | Существующий тест |
|---|---|---|---|
| `-I /a;/b` | Unix | **один** каталог `/a;/b` — `;` не разделитель | `split_semicolon_is_not_unix_separator` (776) |
| `-I C:\a:C:\b` | Windows | **один** каталог — `:` не разделитель; иначе буква диска отрезалась бы | покрывается T8 (ветка `cfg(windows)`) |
| `-I C:\lib;C:\usr` | Windows | **два** каталога — так и задумано | `split_semicolon_windows` (722) |

Контрпример второй строки — **суть кандидата в `FEATURES.md`** («конфликт с
буквами дисков»). Анализ показал, что продукт его уже обрабатывает; тест-план
фиксирует это как явное ожидание, чтобы утверждение перестало быть устным.

## Тестовые данные и окружение

**Тестовых данных нет.** Фикстуры `.lam` не заводятся: фича не трогает язык, а
входы тестов — строки аргументов, конструируемые в теле теста. Каталог
`grammar/tests/data/` не изменяется.

**Эталон «до» (снят на darwin 2026-07-15, ветка v2, коммит `6984471`):**

```sh
cargo test --bin lamc -- --test-threads=1                 # → 44 passed
cargo test -p simulation test_highlight -- --test-threads=1  # → 1 passed
```

Значение эталона — фиксация того, что локальный прогон **не различает**
исправленное и неисправленное состояние (см. «Главная методическая проблема»).

**Окружение проверок:**

| Уровень | Окружение | Команды |
|---|---|---|
| 1 (статика) | любое | `git diff`, `grep` |
| 2 (darwin) | macOS (Darwin 25.5.0), nightly | `cargo test --bin lamc -- --test-threads=1`; `cargo test --features lsp -- --test-threads=1`; `cargo check --target x86_64-pc-windows-msvc --all-targets` |
| 3 (Windows) | GitHub Actions, `windows-latest`, nightly, **MSVC** | `cargo build --all-features --all-targets --examples`; `cargo check`; `cargo test` |

**Расхождение окружений — фиксируется явно.** Отчёт 0021 (источник наблюдения)
писался на **Windows 11, nightly gnu + MinGW**; job `windows` даст **MSVC**
(ADR, Decision, условие 4). Совпадения окружений **нет**: MinGW-специфичные
падения матрица не поймает, MSVC может дать свои (риск Р4 анализа).

**Ограничение отчёта о тестировании (правило 20).** До первого прогона job
`windows` критерии **A8/A9 остаются ⬜ «не проверялось»** — их запрещено
закрывать локальным прогоном на darwin. Вердикт «ПРОЙДЕН» невозможен без лога
Windows-job с явными именами шести тестов.
