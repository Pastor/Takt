# Тест-план фичи 0290: Приложение «Ошибки» сверяется с реестром диагностик

> Фича: [../features/0290-book-diagnostics-codes-gate.md](../features/0290-book-diagnostics-codes-gate.md) · анализ: [../analyze/0290-book-diagnostics-codes-gate.md](../analyze/0290-book-diagnostics-codes-gate.md) · отчёт: [../reports/0290-book-diagnostics-codes-gate.md](../reports/0290-book-diagnostics-codes-gate.md)

## Предмет проверки

Гейт `scripts/check-book-diagnostics.py` и согласованность приложения
«Ошибки и предупреждения» с реестром диагностик. Язык не затронут, поэтому
примеров и контрпримеров на языке (правило 16) фича не требует: предметом
является **документ и его сторож**.

## Условия проверок

| # | Условие | Как проверяется | Ожидаемый результат |
|---|---|---|---|
| П1 | Согласованное дерево принимается (контроль) | `test-book-diagnostics.sh`, проверка 1; прогон гейта на рабочем дереве | код 0, «264 кодов сверены» |
| П2 | Код реестра, пропавший из приложения, ловится | сторож, проверка 2 (удаление `SE-115` в копии) | код ≠ 0, раздел «Нет в приложении», код назван |
| П3 | Код приложения вне реестра ловится | сторож, проверка 3 (вставка `SE-999` в копию) | код ≠ 0, раздел «Нет в реестре», код назван |
| П4 | Документ без сводной таблицы валит гейт | сторож, проверка 4 | код ≠ 0, сообщение про раздел «Сводная таблица кодов» |
| П5 | Реестр без строк таблиц валит гейт | сторож, проверка 5 | код ≠ 0, сообщение про строки таблицы |
| П6 | `SE-066` в документе отсутствует | `grep -rn 'SE-066' book/` | пусто |
| П7 | Документ собирается | `make -C book build` | PDF собран, код 0 |
| П8 | Символы новых записей покрыты шрифтом | `check-book-glyphs.py` | «символов вне шрифта нет» |
| П9 | Предкоммит зелёный | `./scripts/precheck.sh` | код 0 |

## Мутационные проверки (доказательство небутафорности)

- **М1.** Удалить из гейта сравнение `registry - appendix` → П2 обязана
  провалиться. Проверяет, что направление «нет в приложении» действительно
  считается, а не подразумевается.
- **М2.** Удалить сравнение `appendix - registry` → П3 обязана провалиться.
  Именно это направление кандидат не называл, и без него `SE-066` дожил бы.
- **М3.** Читать коды грепом по всему файлу приложения (а не по сводной
  таблице) → П2 перестанет ловить пропажу кода, у которого есть разбор: их
  четырнадцать, и именно так расхождение занижалось до 18.

## Границы

Верность **текста** записи гейт не проверяет — только наличие кода. Разбор
ошибок (вторая часть приложения) сверке не подлежит: он подмножество.
