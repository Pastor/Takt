# Тест-план фичи 0062: Цель `sv-mmio` — адреса портов как регистровый файл

> Фича: [../features/0062-sv-mmio-target.md](../features/0062-sv-mmio-target.md) · ADR: [../adr/0062-sv-mmio-target.md](../adr/0062-sv-mmio-target.md) · анализ: [../analyze/0062-sv-mmio-target.md](../analyze/0062-sv-mmio-target.md)

## Область и цель

Проверяется **новая цель** `-t sv-mmio`: адреса портов → регистровый файл без
шинного протокола. Язык **не меняется** → примеров/контрпримеров синтаксиса
правило 16 не требует.

⚠️ **Гейт не доказывает верность.** У цели `sv` дефект «`always_comb` читает
регистр вместо `_next`» приняли **оба** инструмента (verilator и yosys) — он
валиден и синтезируем, просто считает не то. Поэтому основной критерий — **T4:
потактовая сверка через регистры**, а гейт (T2) — необходимое условие.

## Тестовые данные и окружение

- **Опорные примеры корпуса:** `stacker.lam` (карта смещений `0x1xx`…`0x6xx` —
  уже фактически регистровая карта), `elevator.lam` (плоский физический
  `0x10000000`), `extend_complex.lam` (**смешанное** слово с битами 1, 2, 33).
- **Гейт — оба инструктора SV:** verilator **и** yosys (ловят непересекающиеся
  классы; `real`/`return` verilator принимает молча, петлю и узкую ширину yosys
  синтезирует молча).
- **Тестбенч без BFM:** регистровый интерфейс дёргается напрямую — это и есть
  причина, по которой ADR принял шинно-агностичный вариант.
- **Однопоточность:** `-- --test-threads=1` (`CLAUDE.md`).

## Блокировка объёма

⚠️ **T5 неисполним в полном виде, пока не закрыт
[фикс 0020-01](../fixes/0020-01-port-bit-out-of-range.md)**: язык не выражает
ширину адресуемого слова, поэтому `0x44533932:33` не интерпретируем. До закрытия
фикса ожидаемый результат T5 — **диагностика**, а не карта регистров.

## Что этот план сознательно НЕ проверяет

- **Шинные протоколы** (APB/AXI-Lite/Wishbone) — вне объёма по решению ADR:
  адаптеры заводятся отдельными фичами **по требованию**.
- **Сторону `c-hal`** («вторая половина шины») — она не компилируется ни одним
  гейтом (кандидат).
