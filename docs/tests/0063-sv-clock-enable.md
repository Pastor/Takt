# Тест-план фичи 0063: Порт `en` (clock enable) для цели `sv`

> Фича: [../features/0063-sv-clock-enable.md](../features/0063-sv-clock-enable.md) · ADR: [../adr/0063-sv-clock-enable.md](../adr/0063-sv-clock-enable.md) · анализ: [../analyze/0063-sv-clock-enable.md](../analyze/0063-sv-clock-enable.md)

## Область и цель

Проверяется служебный вход `en` цели `sv`. Язык **не меняется** (`en` — как
`clk`/`rst_n`, в `.lam` не выразим) → примеров/контрпримеров синтаксиса правило 16
не требует; контрпример нужен один — коллизия имени (T6).

⚠️ **Ключевая мысль: гейт не доказывает семантику.** «Принял» ≠ «значит `1`» —
урок 0045 (`real` verilator принимает молча; петлю yosys синтезирует молча).
Поэтому основа плана — **T2 (симуляция)** и **T3 (сверка)**, а гейт (T1) —
необходимое условие.

## Проверки (условие → ожидаемый результат)

| # | Проверка | Предусловие | Ожидаемый результат | Ссылка на R/A |
|---|---|---|---|---|
| T1 | Гейт | Порождённый модуль с `en = 1'b1` | **verilator `-Wall` И yosys** принимают | R1 / A1 |
| **T2** | **Семантика умолчания (симуляция)** | Три экземпляра: `en` не подключён / `en=1` / `en=0` | `не подключён` ≡ `en=1` **побитово**; при `en=0` автомат **стоит**. Проверено пробой проработки: `10 \| 10 \| 0` | R1, R2 / A2 |
| T2б | Семантика умолчания (синтез) | `yosys synth -flatten` | `не подключён` и `en=1` дают **одинаковые** ячейки (23, `$_DFF_PN0_` без разрешения); `en=0` → 1 ячейка. ⚠️ **Только с `-flatten`**: без него проба ничего не доказывает | R1 / A2 |
| **T3** | **Потактовая сверка (основная)** | `conformance_sv_tests`, `en` **не подключён** | Вердикты **не изменились** — то есть умолчание держится в том самом прогоне, которым проверяется цель | R5 / A3 |
| T4 | Сброс не загейчен | `en = 0`, затем `rst_n = 0` | Автомат **сбрасывается** (иначе его нельзя сбросить, пока он не разрешён) | R3 / A4 |
| T5 | Шаг по разрешению | `en` дёргается 1 такт из N | Автомат делает **ровно один** шаг на N тактов `clk` | R2 / A2 |
| T6 | **Контрпример: коллизия имени** | Модель с портом `en` | **`SV-007`** (как у `clk`/`rst_n`) | R4 / A5 |
| T7 | `is_done` независим от `en` | `en = 0` в конечном состоянии | `is_done` **держится** | R6 / A6 |
| T8 | Прочие цели не задеты | Перегенерация | `git diff --exit-code examples/generated` — пусто по `c`/`c-hal`/`st`/`st-at`/`rust`/`plantuml` | R7 / A7 |
| T9 | **Негативный сторож T4** (мутация) | Поставить `if (en)` **выше** проверки `rst_n` | T4 **падает** — иначе несбрасываемость прошла бы молча | R3 / A4 |

## Тестовые данные и окружение

- **Оба инструмента SV обязательны:** verilator **и** yosys — ловят
  непересекающиеся классы (проверено 4 раза при 0045).
- **Симуляция — `verilator --binary`**: именно им гоняет модуль
  `conformance_sv_tests`, поэтому семантику доказывать надо им.
- ⚠️ **Синтез — только `yosys synth -flatten`**: без уплощения константы не
  распространяются, и `en=0` неотличим от `en=1`.
- Корпус: имени `en` в `examples/` **нет** (греп) — T6 требует **новой** фикстуры.
- Однопоточность: `-- --test-threads=1` (`CLAUDE.md`).
