# Тест-план фичи 0054: Позиции в диагностиках симулятора

> Фича: [../features/0054-sim-diagnostics-positions.md](../features/0054-sim-diagnostics-positions.md) · ADR: [../adr/0054-sim-diagnostics-positions.md](../adr/0054-sim-diagnostics-positions.md) · анализ: [../analyze/0054-sim-diagnostics-positions.md](../analyze/0054-sim-diagnostics-positions.md)

## Область и цель

Проверяется **вывод симулятора**, который увидит пользователь. Тесты сквозные —
гоняют сам бинарник (`CARGO_BIN_EXE_simulation`): печать живёт в
`bin/simulation.rs`, и проверять надо её, а не внутренние функции.

**Ключевой принцип плана.** Проверка обязана различать **виновника и импортёра**:
до фичи оба случая давали дословно одинаковый вывод, поэтому тест, не проверяющий
имя файла, прошёл бы и на сломанной фиче. Плюс отдельный сторож против
расхождения печати с `lamc` (риск Р1).

## Тестовые данные и окружение

**Фикстуры** `simulation/tests/data/diag54/` (правило 16 — виновник и импортёр):

| Фикстура | Роль |
|---|---|
| `lib_bad.lam` | «чужая библиотека» с `ref Nowhere` — виновник |
| `importer.lam` | импортёр без своих ошибок: до фичи неотличим от виновника |
| `syntax_bad.lam` | несколько ошибок разбора — сторож «печатаются все» |

**Где живут проверки:** `simulation/tests/diagnostics_tests.rs` (T1–T4); пробы
CLI (T5, T6); регресс — `./scripts/precheck.sh` (T8).

## Как воспроизвести

```sh
cargo test -p simulation --test diagnostics_tests -- --test-threads=1
./scripts/precheck.sh

# Проба (T5): позиция в начале строки, назван виновник, а не импортёр
simulation -I tests/data/diag54 tests/data/diag54/importer.lam --steps 3
#   Ошибка: tests/data/diag54/lib_bad.lam:2:18: [SE-002] Ссылка 'Nowhere' не найдена
```
