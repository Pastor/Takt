# Тест-план 0335: разряд в позиции числового значения

> Фича: [../features/0335-bit-value-in-targets.md](../features/0335-bit-value-in-targets.md) · ADR: [../adr/0335-bit-value-in-targets.md](../adr/0335-bit-value-in-targets.md) · отчёт: [../reports/0335-bit-value-in-targets.md](../reports/0335-bit-value-in-targets.md)

## Условия

| # | Условие | Проверка |
|---|---|---|
| П1 | `rust`: приведение печатается, вывод собирается под `-D warnings` | `rust_bit_value_compiles` |
| П2 | `st`: `BOOL_TO_<тип>`, `iec2c` принимает | `st_bit_value_is_accepted_by_iec2c` |
| П3 | `sv`: размерная форма, `verilator -Wall` молчит | `sv_bit_value_has_no_width_warning` |
| П4 | Значения совпадают с эталоном | `bit_value_matches_generated_st` |
| П5 | Битовый приёмник не изменился | контрольные проверки в тех же тестах |
| П6 | Мутация ловится | снятие `BOOL_TO_` валит сверку |
| П7 | Предкоммит | `./scripts/precheck.sh` |

## Почему тесты именно такие

Текст вывода — не предмет: предмет в том, **принимает** ли его целевой
инструмент, поэтому все три теста запускают настоящие `rustc`, `iec2c`,
`verilator`. Значения сверяются там, где форма содержательна (`st`):
преобразование, дающее не тот разряд, компилируется прекрасно.

⚠️ Наблюдаются **два** разряда — старший и младший: обёртка, всегда дающая
единицу, прошла бы проверку по одному старшему.
