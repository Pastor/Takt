# Тест-план фичи 0198: место комментария при форматировании

> Фича: [../features/0198-formatter-comment-in-block.md](../features/0198-formatter-comment-in-block.md) · ADR: [../adr/0198-formatter-comment-in-block.md](../adr/0198-formatter-comment-in-block.md) · анализ: [../analyze/0198-formatter-comment-in-block.md](../analyze/0198-formatter-comment-in-block.md)

## Область и цель

Проверяется, что `taktc fmt` сохраняет **место** комментария, а не только его
текст. Инвариант «комментарий не теряется» (R2 фичи 0024) уже был зелёным — и
именно поэтому дефект жил незамеченным.

⚠️ Корпус класс не покрывает: гейт `fmt --check` регресс не поймает. Проверки
фикстурные, по одной на форму.

## Проверки (условие → ожидаемый результат)

| # | Проверка | Предусловие | Ожидаемый результат | Ссылка на R/A |
|---|---|---|---|---|
| T1 | первой строкой тела | комментарий в `always { … }` | остаётся в теле, отступ тела | R1 / A1 |
| T2 | между операторами | комментарий в середине тела | там же | R2 / A1 |
| T3 | последней строкой тела | комментарий перед `}` | остаётся внутри | R3 / A1 |
| T4 | вложенный `if` | комментарий внутри `if` в `always` | своя глубина, не всплывает | R4 / A1 |
| T5 | тело функции | комментарий перед `return` | внутри функции **и перед** `return` | R5 / A1 |
| T6 | хвостовой комментарий | `n := n + 1; // счёт` | остаётся на строке оператора | R6 / A2 |
| T7 | идемпотентность | повторный `fmt` | ничего не двигает | R7 / A3 |
| T8 | мутация роняет сторожей | печать в обход привязки | тесты краснеют | — / A4 |
| T9 | корпус не сдвинут | `fmt` по `examples/` и `book/` | пустой дифф | R8 / A5 |
| T10 | предкоммит | всё дерево | код возврата 0, `fmt --check` зелёный | A5 |

## Тестовые данные и окружение

Фикстуры заданы строками в `takt-lang/tests/syntax/format_comment_position_tests.rs`.

⚠️ **Проверяется отступ, а не факт наличия строки.** Мутационная проба показала,
что проверки одного лишь наличия недостаточно: при печати в обход привязки
комментарий остаётся внутри тела, но встаёт **после** своего оператора. Поэтому
у формы «тело функции» проверяется ещё и **порядок строк**.

Окружение: macOS (Darwin 25.5.0), толчейн `1.97.1`, `./scripts/precheck.sh`.
