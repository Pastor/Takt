# Тест-план фичи 0212: Диагностика цели c без кода

> Фича: [../features/0212-c-diagnostic-without-code.md](../features/0212-c-diagnostic-without-code.md) · ADR: [../adr/0212-c-diagnostic-without-code.md](../adr/0212-c-diagnostic-without-code.md) · анализ: [../analyze/0212-c-diagnostic-without-code.md](../analyze/0212-c-diagnostic-without-code.md)

## Область и цель

Проверяются требования R1–R8 анализа: код у каждого отказа цели `c`, русский
текст без имён вариантов АСД, позиция и путь файла, разделение `CC-022` /
`CC-023`, единственность знания о позиции выражения и неизменность поведения.

Фича **не меняет язык** (набор принимаемых программ прежний), поэтому примеры и
контрпримеры правила 16 здесь — это входы, на которых сравнивается **текст**
диагностики, а не принятие программы.

⚠️ **Прогоном покрываются две ветви из девятнадцати.** Остальные недостижимы из
корректного текста: их держат грамматика (`SY-008` на адресном литерале),
семантика (`SE-004` на неизвестной функции), отсутствие правил у мёртвых узлов
(класс 0201) и корректность самого понижения. Мера полноты для них — **исходный
текст генераторов** (греп-сторож) и **перечисление видов** в юнит-тестах воронок
(образец `CC-023`, фича 0236).

### Примеры и контрпримеры (правило 16)

**Примеры (отвергаются `CC-022`):** `model_expr.takt` (модель в выражении),
`array_slice.takt` (срез массива).

**Контрпример (поведение сохранено):** `debug_call.takt` — вызов `debug` в
позиции оператора компилируется молча, как и до фичи (решение 0189).
