# Тест-план фичи 0049: Верификация модели (Model Checking) на основе LTL

> Фича: [../features/0049-model-checking-ltl.md](../features/0049-model-checking-ltl.md) · ADR: [../adr/0049-model-checking-ltl.md](../adr/0049-model-checking-ltl.md) · анализ: [../analyze/0049-model-checking-ltl.md](../analyze/0049-model-checking-ltl.md)

## Область и цель

Проверяется **вердикт**, который увидит пользователь: держится / нарушено (с
контрпримером) / не проверено. Покрываются требования R1–R11 и критерии
приёмки A1–A10 анализа.

**Ключевой принцип плана (капкан 0025, риск Р7 анализа).** Тесты пишутся на
**принимаемый язык и вердикт**, а не на структуру автомата («states не пусто»,
«есть принимающие состояния»). Именно тесты-на-структуру позволили дефекту
[0010-01](../fixes/0010-01-buchi-acceptance.md) (вырожденное условие принятия:
`build_buchi(F p)` принимал слово, где `p` не наступает) прожить в зелёном CI до
появления первого потребителя. Ни одна проверка ниже не считается пройденной,
если она подтверждает форму, а не поведение.

Из области **исключено** (ADR 0049, осознанные границы): свойства над данными;
точность контрпримера по данным (over-approximation); минимальность
контрпримера.

## Тестовые данные и окружение

**Фикстуры** `grammar/tests/data/verify/` — примеры и контрпримеры парами
(правило 16); отличие внутри пары минимально, чтобы причина вердикта была видна
глазом:

| Фикстура | Свойство | Ожидаемый вердикт |
|---|---|---|
| `holds.lam` | `G (Fault -> F Idle)` | держится |
| `fails.lam` | `G (Fault -> F Idle)` | нарушено (`Idle -> [ Fault ]*`) — отличие от `holds.lam`: самопетля `ref Fault` |
| `reachable.lam` | `F Done` | держится |
| `unreachable.lam` | `F Done` | нарушено — отличие: в `Done` не ведёт ни один `ref` |
| `atom_not_state.lam` | `G temp` | не проверено (`temp` — переменная) |

**Где живут проверки:**

- юнит-тесты — `grammar/src/verification/{kripke,product,check,verify}.rs`
  (T1–T13, T22, T24–T25, T34–T35);
- интеграционные — `grammar/tests/verify_tests.rs` (T14–T21, T23, T26–T30,
  T36–T37, T40);
- CLI — `grammar/src/bin/lamc.rs::tests` (T31–T32); проба CLI (T33);
- регресс — `./scripts/precheck.sh` (T38–T39).

**Окружение:** `cargo test -p grammar -- --test-threads=1` (однопоточно —
правило проекта); внешних зависимостей верификация не требует.

## Как воспроизвести

```sh
cargo test -p grammar -- --test-threads=1          # юнит + интеграционные + CLI
cargo test -p grammar --test verify_tests -- --test-threads=1
cargo test -p grammar --doc -- --test-threads=1    # примеры в документации API
./scripts/precheck.sh                              # регресс целиком

# Проба CLI (T33): коды возврата
lamc verify grammar/tests/data/verify/holds.lam; echo $?   # 0
lamc verify grammar/tests/data/verify/fails.lam; echo $?   # 1
```
