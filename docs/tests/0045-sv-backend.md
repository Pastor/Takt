## Область и цель

Проверить, что цель `-t sv` порождает **синтезируемый** SystemVerilog, семантически
эквивалентный модели Lam, не задевая существующие цели. Покрываются требования
**R1..R12** и критерии **A1..A12** анализа.

Фича меняет **семантику порождаемого кода** (новая целевая платформа), но **не
синтаксис и не семантику языка** `.lam`. Тем не менее правило 16 применяется в
полном объёме: тесты корректности + **примеры и контрпримеры**, которые после
проверки попадают в документацию по языку (правило 15) — потому что границы цели
(`float`, `extern fn`, `inout`, `clk`) автор модели обязан знать из документации, а
не узнавать от yosys.

### Чем проверяем порождённый SV — вердикт (проверено фактически)

**Главный вопрос проверяемости решён до начала разработки** и не на догадках.

Исходно в среде **не было ни одного** SV-инструмента (`which verilator iverilog
yosys vvp sv2v` — пусто). Установлены через Homebrew и **опробованы**:

| Инструмент | Версия | Роль |
|---|---|---|
| **Verilator** | 5.050 | гейт 1 — линт; + тестбенч (`--binary --timing`) |
| **yosys** | 0.67+post | гейт 2 — **синтез** |
| Icarus Verilog | — | не ставился: роль покрыта Verilator |

**Гейтов должно быть два — это установлено пробами, а не выбрано из осторожности:**

| Класс дефекта | Verilator `--lint-only -Wall` | yosys `synth` |
|---|---|---|
| **Несинтезируемый тип (`real`)** | **пропускает (код 0)** | **ловит (код 1)** |
| **Комбинационная петля** | **ловит (код 1, `UNOPTFLAT`)** | **пропускает (код 0)** |
| Синтаксис SV | ловит | ловит |
| Защёлка (`LATCH`), ширины, неиспользуемые сигналы | ловит | не сообщает |
| Фактическая реализуемость в ячейках | не проверяет | **проверяет** |
| Поведение (потактовая трасса) | **`--binary`** | не умеет |

Расхожее «`verilator --lint-only` даёт проверку синтеза» — **неверно**: Verilator
принял `real` в `always_ff` молча. И наоборот: yosys молча синтезировал
комбинационную петлю — центральный риск отображения `M1 | M2`. **Инструменты
ловят непересекающиеся классы дефектов; ни один по отдельности не достаточен.**

> **Операциональное определение (ADR, вопрос 6).** «Валидный SV» =
> `verilator --lint-only -Wall` (код 0) **И** `yosys … synth` (код 0).
> «Поведенчески корректный» = тестбенч (`verilator --binary --timing`) сходится с
> трассой симулятора Lam.

Подробности проб — [анализ 0045-02](../analyze/0045-02-validation.md).

### Ограничение метода: побайтовые снапшоты невозможны

Находка фичи 0026: генерация **недетерминирована** — `states: HashMap<String,
StateNode>` (`semantic/mod.rs:101`) → порядок вариантов `enum` и веток `case`
плавает от запуска к запуску на одном входе. Следствия для всего плана:

- проверки вывода — **структурные** (подстроки, множества строк), **не побайтовые**;
- регресс существующих целей (T1) — тоже структурно;
- **это не слабость плана, а свойство кода**; настоящую защиту дают гейты синтеза
  и сверка значений с симулятором, которые к порядку веток нечувствительны.

### Контрпримеры (отвергаются диагностикой)

Каждый — **фикстура** `grammar/tests/data/sv/invalid/*.lam`; тест проверяет **код**
диагностики, а не текст сообщения.

| # | Контрпример | Ожидаемая диагностика | Почему это граница, а не дефект |
|---|---|---|---|
| К1 | `var x: float;` | **`SV-003`** | В синтезируемом RTL плавающей точки **не существует**: `real` — только симуляция; FP в железе — IP-ядро, а не тип. **Verilator это пропустит (проверено!), yosys — отвергнет** |
| К2 | `extern fn motor_up();` | **`SV-005`** | Аналога нет: DPI-C — только симуляция; «внешняя функция» на железе — модуль со своими портами и латентностью, которых `extern fn` не описывает. → `elevator.lam` (8 шт.), `comprehensive.lam` (2), `extend_complex.lam` (1) для `sv` **недоступны** |
| К3 | `inout p: bit;` | **`SV-006`** | `inout` в SV = трёхстабильная шина, требует `oe`; Lam его не выражает и вывести нельзя. Корпус `inout` не использует (проверено) → цена нулевая |
| К4 | `in clk: bit;` | **`SV-007`** | Коллизия со служебным портом. **`clk`/`rst_n` — не ключевые слова языка**: модель остаётся валидной для `c`/`c-hal`/`plantuml`/`st`, отвергается **только** целью `sv` |
| К5 | `start S { enter { v := f(in_port); } }` | **`SV-008`** | Ветвь сброса — цепь сброса триггеров, выражений не вычисляет. Обход: перенести в `always` (сдвиг всё равно 0) |
| К6 | `struct { data: [u8; 4] }` | **`SV-004`** | Распакованный массив не входит в `struct packed` |
| К7 | Непокрытый узел `TypeNode` | **`SV-002`** | **Никакого тихого пропуска** (класс дефектов 0025/0028/0029) |

**Общий принцип контрпримеров:** каждый — **честный отказ вместо молчания**. Ни
один не должен приводить к порождению несинтезируемого кода или к тихой потере
узла (R4).

- **Не побайтово:** генерация недетерминирована (0026) — только структурные
  проверки.
- **Тесты на значения, а не на факт перехода** (урок 0025: именно отсутствие
  этого слоя дало восемь дефектов при зелёных тестах).

## Команды прогона

```sh
# Сборка и генерация
cargo build --bin lamc
cargo run --bin lamc -- compile -t sv examples/stacker.lam -o out/sv

# Гейт 1 — линт (ловит петли; НЕ ловит real)
verilator --lint-only -Wall out/sv/stacker.sv

# Гейт 2 — синтез (ловит real; НЕ ловит петли)
yosys -p "read_verilog -sv out/sv/stacker.sv; synth -top stacker; stat"

# Тестбенч и потактовая трасса
verilator --binary --timing --top-module tb_stacker tb_stacker.sv out/sv/stacker.sv -o simtb
./obj_dir/simtb

# Тесты
cargo test -- --test-threads=1
cargo test --test sv_tests -- --test-threads=1
cargo test --test conformance_sv_tests -- --test-threads=1

# Предкоммит (включая оба гейта после 0045-02)
./scripts/precheck.sh
```
