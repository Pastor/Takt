# Тест-план фичи 0077: Реестр кодов диагностик

> Фича: [../features/0077-diagnostic-code-registry.md](../features/0077-diagnostic-code-registry.md) · ADR: [../adr/0077-diagnostic-code-registry.md](../adr/0077-diagnostic-code-registry.md) · анализ: [../analyze/0077-diagnostic-code-registry.md](../analyze/0077-diagnostic-code-registry.md)

## Область и цель

Проверяем реестр кодов (`docs/diagnostics/README.md`) и гейт
(`scripts/check-diagnostic-codes.sh`): полнота, четыре условия отказа, метка
`RESERVED`, печать «следующего свободного», аддитивность (вывод неизменен),
указатели на источник истины. Инструмент проверки — сам гейт (POSIX sh) + негативные
пробы + `precheck.sh`.

## Проверки (условие → ожидаемый результат)

| # | Проверка | Предусловие | Ожидаемый результат | Ссылка на R/A |
|---|---|---|---|---|
| T1 | Гейт на текущем дереве | реестр = 171 код | зелёный, «реестр согласован (171 кодов)» | R1 / A1 |
| T2 | Пустых значений в реестре нет | — | 0 строк с пустым столбцом «Значение» | R1 / A1 |

## Разбивка проверок по функциональности

Единые условия и ожидаемые результаты прогоняются против каждой задеваемой обратной функциональности
(правило 11); фиксируется статус.

| Функциональность | Задета? | Проверки | Статус |

| Гейт кодов (`check-diagnostic-codes.sh`) | да (ядро фичи) | T1–T8, T11 | ✅ |
| Реестр (`docs/diagnostics/README.md`) | да | T1, T2, T10 | ✅ |
| Диагностика (`with_code`) | комментарий | T9, T10 | ✅ (вывод неизменен) |
| Цели C/rust/st/sv/plantuml, симулятор | нет (поведение) | T9 (неизменность) | ✅ |
| README/CODE.md указатели | да (docs) | T10 | ✅ |

## Тестовые данные и окружение

- **Артефакты:** `docs/diagnostics/README.md` (реестр), `scripts/check-diagnostic-codes.sh`
  (гейт). Негативные пробы — временная правка src/реестра с откатом (в отчёте о
  тестировании; в дерево не коммитятся).
- **Команды:** `./scripts/check-diagnostic-codes.sh` (быстрый), `./scripts/precheck.sh`
  (итог: fmt/clippy/размер/**коды**/тесты/детерминизм/гейты целей).
- **Окружение:** POSIX sh + grep/sed/awk/comm (без внешних зависимостей, как
  `check-module-size.sh`).
