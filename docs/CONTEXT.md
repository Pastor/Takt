# Контекст Takt

Задачи и правила проекта находятся в aNaL (проект 22, мнемоника `TAKT`).
Перенесены 598 фич и 100 исправлений. Состояние задач и отчёты смотри в aNaL.
Восемь идей из прежней витрины перенесены в `TAKT-699`–`TAKT-706`.
В карточках выгрузки `tasks/` осталось 5150 битых относительных ссылок.
Полные исходники и цели ссылок доступны по архивным ссылкам ниже.
Состояние проверки описано в протоколе TAKT-707. Исправление ссылок
вынесено в [TAKT-710](https://pastor.axatel.ru/anal/#task/1840).

`TAKT-705` исправляет повтор префикса в диагностиках сценария `takt-sim`.
Формат сообщения `SIM-030` проверяется через CLI на русском и английском.

`TAKT-615` подтверждает исправление E0499 в цели Rust. Генератор вычисляет
читающее HAL значение во временной переменной перед записью в выходной порт.
Форму вывода, компиляцию и значения выходов проверяют тесты генератора
и сверка с эталонным симулятором.

Компилятор и LSP находятся в `takt-lang/`, эталонный симулятор — в
`takt-sim/`. Браузерный редактор использует эти компоненты через
`takt-wasm/`. В `book/` хранится пользовательское описание языка,
в `examples/` — модели и сценарии, в `docs/diagnostics/` — реестр
кодов диагностик.

Контракты ядра:

- Условия рёбер `ref` не разрешаются. `Condition` и `Expression` имеют разную
  семантику `=`. Присваивание записывается `:=`, сравнение — `=`.
- Адрес порта из внешней карты имеет приоритет над оператором `address`,
  а оператор — над адресом в объявлении.
- Вход в стартовое состояние не расходует такт. Блок `always` модели
  выполняется каждый такт перед диспетчеризацией состояния.
- `match` выбирает первое совпадение. `SE-131` предупреждает как о повторе
  образца из предыдущей ветви, так и о дубле внутри одной ветви.
- Поведение целей сверяют потактово с эталонным симулятором. Время внутри
  реализации состояния покрыто тестами для C и Rust. Расхождения ST и
  SystemVerilog на тех же фикстурах описаны в `TAKT-701`.
- Цель Rust приводит ветви тернарного оператора к `bool` при записи в
  битовый порт. Оба исхода условия сверяются с симулятором (TAKT-641).
- Для `(A + B) | C` цели C и Rust сохраняют порядок A → B и выполняют C
  параллельно. Потактовую сверку с симулятором выполняет набор
  [conformance_nested_composition_tests](../takt-sim/tests/conformance/conformance_nested_composition_tests.rs)
  (TAKT-596).
- Снимок симулятора хранит вложенные реализации состояний. При загрузке
  симулятор восстанавливает их и публикует состояния для условий `S(Модель)`.
- Тип результата `unit` описан в главе «Типы данных». Глава «Функции»
  ссылается на неё при объяснении опущенного типа результата (TAKT-704).
- Глава «Диагностики» показывает на модели лампы, как предупреждение
  `SE-036` и ошибка `SE-003` влияют на генерацию и вывод `--quiet` (TAKT-706).

Схема хранит адрес экземпляра в пути входа. У открытой вложенной композиции
подсветка следует этому адресу, а раскладка общая для всех экземпляров
листа (TAKT-700). Ресурсы панели IntelliJ собираются из веб-исходников
скриптом `scripts/build-plugin-webview.py`.

Панель Takt Scheme для IntelliJ реализована в рабочей ветке
`codex/TAKT-540`. Общий `precheck` доходит до проверки ссылок в
перенесённых карточках `tasks/` и останавливается на ней. Результаты
проверок панели зафиксированы в [протоколе](PROTOCOL.md) и карточке
`TAKT-540`.
