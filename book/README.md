# book/ — документ «Язык Takt — описание»

Справочное описание **языка** Takt (не инструментов и не процесса разработки).
Собирается [Typst](https://typst.app/) в **PDF** (шрифт текста — **Fira Code**).

## Сборка

Внешний инструмент **один**:

```sh
brew install typst          # либо cargo install typst-cli
# + шрифт Fira Code (https://github.com/tonsky/FiraCode), установленный в систему
```

Требуется `typst` версии **0.13** и выше (проверенная — **0.15.1**); версию
проверяет цель `deps` Makefile. Пин намеренный: до выпуска 1.0 Typst меняет язык
между минорными версиями, а документ опирается на `skew` (синтетический курсив
для Fira Code, у которой курсивного начертания нет).

Затем из корня репозитория:

```sh
make -C book build    # регенерация графов + PDF: book/book/pdf/takt-language.pdf
make -C book pdf      # только PDF (шаг предкоммита: файлы дерева не меняются)
make -C book check    # сборка «на прочность» (для CI)
make -C book graphs   # перерисовать SVG-графы верификации (taktc → dot)
make -C book clean    # удалить каталог сборки
```

Сборка входит в `./scripts/precheck.sh`: без `typst` шаг мягко пропускается, под
`PRECHECK_STRICT=1` отсутствие инструмента — ошибка.

## Структура

- `src/main.typ` — **состав и порядок** документа: части, разделы, приложения.
  Автонумерация глав идёт из порядка включений. Это управляющий файл структуры.
- `src/template.typ` — **шаблон**: метаданные (титульный лист), страница и поля,
  шрифты, колонтитулы, оглавление, оформление таблиц, врезок и блоков кода,
  функции `example()` / `code()` для вставки внешних файлов.
- `src/title.typ`, `src/introduction.typ`, `src/purpose.typ` — вводная часть
  (титул, введение, назначение документа).
- `src/NN-slug/` — **каждый раздел в своей папке**: `index.typ` (текст),
  подкаталог `examples/` (примеры кода на Takt), при необходимости `generated/`
  (порождённый код) и `images/` (диаграммы SVG).
- `src/appendix-*/` — приложения (ошибки и предупреждения, порождённый код,
  грамматика EBNF, литература, глоссарий).
- `takt.sublime-syntax` — определение **подсветки синтаксиса** Takt (формат
  Sublime Text; его понимает syntect — движок подсветки Typst).
- `takt.tmTheme` — палитра подсветки (повторяет `tango` skylighting, которым
  документ набирался прежде).
- `takt-keywords.txt` — слова, выделяемые в **инлайн-коде** прозы.
- `scripts/` — регенерация SVG-графов верификации (`taktc verify --emit-graph`).

Списки подсветки (`takt-keywords.txt` и `takt.sublime-syntax`) сверяются с
таблицей `KEYWORDS` лексера гейтом `scripts/check-book-keywords.py` — в обе
стороны. Правя набор ключевых слов языка, правьте оба файла: расходятся они
молча.

## Разметка разделов

Заголовок главы несёт метку для кросс-ссылок, пример вставляется чтением файла:

```typst
= Типы данных <sec-03-types>

Проза с инлайн-кодом `var` и ссылкой на #link(<sec-appendix-errors>)[приложение].

#example(read("examples/types.takt"))
```

⚠️ `read()` разрешает путь **относительно файла, где записан вызов**, поэтому
чтение примера стоит в файле раздела, а не внутри функции шаблона. Файлы
разделов импортируют нужные функции сами: `#import "../template.typ": example`.

Фрагмент на другом языке оформляется блоком с тегом (```` ```c ````, ```` ```rust ````,
```` ```systemverilog ````) или вставляется из файла: `#code(read("generated/c/lift.c"), "c")`.

## Что попадает в документ

Только **язык**: синтаксис, семантика, модель исполнения, примеры на Takt.
**Не** попадают: детали реализации компилятора/симулятора, номера задач и фич,
ссылки на архитектурные решения и отчёты, история процесса разработки (правило
проекта о документировании — см. `docs/RULE.md`).

Наполнение каждого раздела — отдельная фича; при изменении языка соответствующий
раздел правится в стадии «Документирование» этой фичи.
