# Модели и состояния

**Модель** — это конечный автомат: набор **состояний** и **переходов** между
ними. В каждый момент времени модель находится ровно в одном состоянии. Работа
идёт по тактам: на каждом такте проверяются условия переходов из текущего
состояния (подробно — в разделе «Модель исполнения»).

## Модель

Модель объявляется словом `model` и содержит состояния, а также — при
необходимости — переменные, порты ввода-вывода и функции:

```takt
model Motor {
    var speed: u8 := 0;
    // состояния…
}
```

Если модель в файле одна, обёртку `model` можно опустить — состояния и объявления
пишутся прямо на верхнем уровне файла, образуя **корневую** модель:

```takt
out led: bit;
start Off { ref On: true; }
state On { ref Off: true; }
```

## Состояния

Состояние объявляется словом `state`, а **стартовое** — словом `start`. Стартовое
состояние в модели ровно одно: с него начинается работа автомата.

```takt
start Idle { … }     // стартовое состояние
state Running { … }  // обычное состояние
state Done;          // состояние без тела (например, конечное)
```

Тело состояния в фигурных скобках содержит переходы и **именованные блоки**
(`enter`, `exit`, `always`) — их подробно описывает раздел «Именованные условия и
блоки»:

- `enter` — исполняется при входе в состояние;
- `exit` — при выходе из него;
- `always` — на каждом такте, пока автомат в этом состоянии.

## Переходы

Переход задаёт, в какое состояние перейти. Есть две формы.

**Условный переход** `ref` срабатывает, когда его условие истинно:

```takt
ref Running: start_btn = 1;
```

**Безусловный переход** `next` выполняется всегда (по завершении текущего шага):

```takt
next Done;
```

В теле состояния может быть несколько переходов `ref` — они проверяются в порядке
записи. Если условия двух переходов истинны одновременно, выбор недетерминирован;
компилятор предупреждает о таких состояниях (см. раздел «Диагностики»).

## Композиция моделей

Модели **композируются**: сложное поведение собирается из более простых моделей.
Точка сборки — `start` (или составное состояние), где через `=` указывается
композиция под-моделей.

**Параллельная композиция** `|` — под-модели работают **одновременно**, каждая на
своём такте:

```takt
model Cabin { … }
model Motor { … }
start Main = Cabin | Motor;
```

**Последовательная композиция** `+` — под-модели работают **по очереди**: когда
одна завершается, управление переходит к следующей, а после последней —
безусловным переходом `next` — к указанному состоянию:

```takt
model A { … }
model B { … }
start Main = A + B {
    next Done;
}
state Done;
```

Композиции можно **группировать** скобками и вкладывать, комбинируя `+` и `|`:

```takt
start Main = A + B + (C | D) + E {
    next Next;
}
```

Составным может быть не только стартовое, но и любое **состояние**:

```takt
state Middle = Engine + (Engine | Engine) {
    next End;
}
```

Общие для под-моделей данные объявляются в охватывающей (корневой) модели и видны
всем участникам композиции — так под-модели обмениваются значениями.

## Частые ошибки

Типичные ошибки при описании моделей и состояний:

- в модели нет стартового состояния `start` (или их несколько) — `SE-011`;
- переход `ref`/`next` указывает на несуществующее состояние — `SE-002`;
- композиция ссылается на необъявленную модель — `SE-001`;
- состояние недостижимо из стартового — `SE-046`;
- два перехода из состояния с одинаковым условием (недетерминизм) — `SE-042`;
- более одного `next` в одном состоянии — `SE-012`.
