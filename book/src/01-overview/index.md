# Обзор языка

Takt описывает поведение устройства как **конечный автомат**: набор состояний и
переходов между ними, исполняемых по **тактам**. Единица описания — **модель**
(`model`); модель содержит состояния (`state`), переменные, порты ввода-вывода и,
при необходимости, функции. Модели **композируются**: сложное устройство
собирается из более простых.

## Принцип «одна модель — много целей»

Модель на Takt самодостаточна и не привязана к платформе. Компилятор `taktc`
порождает из неё эквивалентный код для нескольких целей:

| Цель | Назначение |
|------|-----------|
| `c`, `c-hal` | Прошивка микроконтроллера (переносимый C; `c-hal` — с доступом к портам через адреса) |
| `st`, `st-at` | Программа ПЛК на Structured Text (IEC 61131-3) |
| `rust` | Встраиваемый Rust (`no_std`) |
| `sv`, `sv-mmio` | Синтезируемый SystemVerilog (FPGA/ASIC); `sv-mmio` — с регистровым файлом по адресам портов |
| `plantuml` | Диаграмма состояний |

**Поведение модели одинаково во всех целях и в симуляторе.** Оно задаётся
семантикой языка (моделью исполнения по тактам, см. раздел «Модель исполнения»), а
не выбором цели; расхождение поведения между целями — дефект инструмента, а не
свойство языка.

## Пример

Минимальная модель — подсветка, управляемая кнопкой:

```takt
{{#include examples/blinker.takt}}
```

Модель имеет два состояния (`Off`, `On`): пока кнопка `btn` нажата, автомат
находится в `On` и выход `led` включён; отпускание кнопки возвращает его в `Off`.
Тот же исходный текст даёт прошивку на C, программу ПЛК на ST, модуль
SystemVerilog и диаграмму — без правок модели.
