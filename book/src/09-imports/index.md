# Импорты и композиция моделей

Крупная система редко умещается в один файл и один автомат. **Импорты** позволяют
вынести переиспользуемые модели в отдельные файлы и подключать их, а **композиция**
— собирать сложную модель из простых, работающих вместе. Оба механизма служат
одной цели: строить большое из понятных частей.

## Импорт файла

Подключить другой файл `.takt` можно оператором `import`. Простейшая форма
подключает файл целиком:

```takt
import "sensors.takt";
```

Содержимое становится доступным под именем, образованным от имени файла
(`sensors.takt` → `Sensors`). Чтобы задать имя явно, используют `as`:

```takt
import "sensors.takt" as Io;
```

## Выборочный импорт

Чаще из файла нужны **конкретные** объявления — модели или псевдонимы типов. Их
перечисляют в фигурных скобках, при необходимости переименовывая через `as`:

```takt
import { Thermostat } from "thermostat.takt";
import { Pump, Valve as V } from "hydraulics.takt";
```

Так в текущий файл попадают именно `Thermostat`, `Pump` и `V` — остальное
содержимое подключённых файлов остаётся скрытым.

## Поиск подключаемых файлов

Путь в `import` — имя файла, а не абсолютный путь. Компилятор ищет файл **рядом с
импортирующим файлом**, а также в каталогах, заданных ключом `-I`:

```bash
taktc compile -t c -I lib room.takt -o out/
```

Так общие модели складывают в отдельный каталог (`lib/`), а конкретные проекты
подключают их, не дублируя.

## Композиция моделей

Отдельная **модель** объявляется словом `model` — это самостоятельный автомат со
своими состояниями и портами:

```takt
model Motor {
    start Idle { ref Run: on = 1; }
    state Run  { ref Idle: on = 0; }
}
```

Модели соединяются двумя операторами. **Параллельная** композиция `|` запускает
обе модели **одновременно** — каждый такт делают шаг обе:

```takt
start Main = Cabin | Motor;
```

**Последовательная** композиция `+` выполняет модели **по очереди**: закончив
работу, первая передаёт управление второй:

```takt
start Cycle = Fill + Drain;
```

Модель может реализовать и отдельное состояние — `state S = Model;`: пока автомат
в состоянии `S`, внутри работает вложенная модель.

## Общие переменные

Модели в композиции общаются через **переменные корня** — объявленные на верхнем
уровне файла. Они видны всем под-моделям: одна пишет, другая читает. Так параллельные
части согласуют работу, не обращаясь к портам друг друга.

## Что видит подключённая модель

Модель из подключённого файла видит объявления **своего** файла — и ничего из
файла, который её подключает. Это не ограничение реализации, а условие
переиспользуемости: библиотека не может зависеть от того, что объявит её
будущий потребитель.

Поэтому связь с моделями потребителя описывает **сама библиотека**: она
объявляет переменные связи у себя, а потребитель подключает их вместе с
моделью. Подключённое объявление становится обычной переменной корня — той же
самой для всех, кто её читает и пишет:

```takt
{{#include examples/pid_lib.takt}}
```

```takt
{{#include examples/pid_loop.takt}}
```

Регулятор поднимает воздействие, пока измерение ниже уставки, объект прибавляет
воздействие к уровню, и уровень возвращается регулятору тем же именем `meas` —
контур замкнулся, хотя модели живут в разных файлах:

```text
Шаг  1: [Control, Run]  level=4   ctrl=4  meas=4
Шаг  5: [Control, Run]  level=20  ctrl=4  meas=20
Шаг 10: [Control, Run]  level=40  ctrl=4  meas=40
Шаг 11: [Control, Run]  level=40  ctrl=0  meas=40
```

На одиннадцатом шаге измерение достигает уставки, регулятор снимает воздействие,
и уровень держится.

Подключить модель, **не** подключив объявления, на которые опирается её тело,
нельзя: компилятор перечислит недостающие имена (`SE-074`) и попросит добавить
их в список импорта. Молчаливой связи «сама подтянется» здесь нет — иначе
имена библиотеки появлялись бы в файле, где их никто не писал.

Подключение файла **целиком** (`import "pid_lib.takt";`) переносит все его
верхнеуровневые объявления к потребителю сразу, а сам файл становится
под-моделью. Такой файл должен быть автоматом — то есть объявлять стартовое
состояние; набор объявлений и моделей без стартового состояния подключают
выборочной формой.

Одно и то же имя, подключённое дважды, — это две **разные** переменные:

```takt
import { Pid as A, ctrl as ca, meas as ma } from "pid_lib.takt";
import { Pid as B, ctrl as cb, meas as mb } from "pid_lib.takt";
```

Здесь два независимых регулятора со своими переменными связи, и путать их
компилятор не даст.

## Пример

Рассмотрим **климат-контроль** помещения: термостат по датчику температуры
включает нагреватель, а вентилятор гонит воздух, пока идёт нагрев. Это две
независимые, но согласованные задачи — естественная **параллельная композиция**:

```takt
{{#include examples/climate.takt}}
```

Каждая задача — своя **под-модель** (1): `Thermostat` следит за температурой,
`Fan` управляет вентилятором. Они работают **параллельно** — `start Climate =
Thermostat | Fan;` (2) запускает обе, и каждый такт шаг делают обе. Согласуются
они через **общую переменную** `heating` (3), объявленную на уровне файла:
термостат поднимает флаг, входя в `Cold` (идёт нагрев), и опускает в `Warm`; а
`Fan` этот флаг только читает — включается, пока `heating = 1`. Так вентилятор
следует за нагревом, ничего не зная об устройстве термостата.

Прогон подтверждает связку (в состоянии показаны обе под-модели, `[Термостат,
Вентилятор]`):

```text
Шаг 1: [Cold, On]   temp=18  heater=1 fan=1  heating=1
Шаг 2: [Cold, On]   temp=20  heater=1 fan=1  heating=1
Шаг 3: [Warm, Off]  temp=22  heater=0 fan=0  heating=0
Шаг 4: [Warm, Off]  temp=23  heater=0 fan=0  heating=0
Шаг 5: [Cold, On]   temp=19  heater=1 fan=1  heating=1
```

Пока холодно (шаги 1–2), греет нагреватель и работает вентилятор; на пороге 22°
(шаг 3) термостат уходит в `Warm`, опускает `heating`, и вентилятор выключается
следом; остыв до 19° (шаг 5), система снова включается.

**Термостат как переиспользуемая модель.** Ту же `Thermostat` можно вынести в
отдельный файл и подключать в разные проекты. Файл `thermostat.takt` содержит
модель, а главный файл берёт её выборочным импортом:

```takt
{{#include examples/room.takt}}
```

Здесь `start Room = Thermostat(setpoint := 20);` реализует машину комнаты
импортированной моделью — термостат работает так же, как встроенный, но **порог
задан в месте подключения**: в библиотеке он объявлен параметром со значением по
умолчанию 22°, а комнате нужно 20°. Файл библиотеки при этом не правится.

Так один файл служит нескольким проектам с разной настройкой, а два экземпляра в
одной композиции могут быть настроены по-разному:
`Thermostat(setpoint := 22) | Thermostat(setpoint := 18)`. Подробно —
«Параметризация моделей» в разделе о моделях и состояниях.

## Частые ошибки

Типичные ошибки при работе с импортами и композицией:

- `SE-013` — подключаемый файл не найден (проверьте имя и пути `-I`) или
  импорты образуют цикл;
- `SE-017` — в выборочном импорте запрошен символ, которого в файле нет;
- `SE-001` — ссылка на неизвестную модель (например, имя не было импортировано);
- `SE-074` — подключённая модель опирается на объявления своего файла, не
  перечисленные в импорте;
- `SE-005` — имя из подключённого целиком файла уже занято у потребителя;
- `SE-106` — в реализации стоит модель без состояний; частый случай —
  подключение файла, где состояния объявлены у вложенной модели, а не на
  верхнем уровне.

Подробный разбор с примерами — в приложении
[«Ошибки и предупреждения»](../appendix-errors/index.md).
