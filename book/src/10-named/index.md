# Именованные условия и блоки

Логику состояния удобно раскладывать на понятные, переиспользуемые части:
**именованные условия** дают имя проверке, а **именованные блоки** задают, что
делать при входе в состояние, при выходе и на каждом такте. И то, и другое делает
модель короче и яснее — условие с осмысленным именем читается лучше, чем формула,
повторённая в нескольких переходах.

## Именованные условия

Условие можно объявить один раз, дав ему имя, и ссылаться на него по имени.
Объявляется оно словом `cond`:

```takt
cond Overheated = temperature >= MAX_TEMP;
cond Empty      = level <= LOW;
```

Дальше имя используется в переходах вместо самой формулы:

```takt
ref Cooling: Overheated;
```

Именованные условия **комбинируются** как обычные логические выражения — через
`&` (и), `|` (или), `!` (не):

```takt
ref Done: Cooled & CyclesDone;
ref Idle: Cooled & !CyclesDone;
```

Так одна и та же проверка не дублируется по всей модели, а сложное условие
собирается из простых с говорящими именами.

## Блоки состояния

Тело состояния описывается **именованными блоками**. Имён ровно три, и каждое
задаёт свой момент исполнения.

**`enter`** выполняется **один раз** при входе в состояние — здесь выставляют
начальные значения выходов и переменных:

```takt
enter { valve := 1; pump := 0; }
```

**`always`** выполняется **каждый такт**, пока автомат в этом состоянии — здесь
живёт повторяющаяся работа (счётчики, интегрирование, обновление выходов):

```takt
always { level := level + RATE; }
```

**`exit`** выполняется **один раз** при выходе из состояния — здесь завершают
дела: гасят сигнал, фиксируют результат, считают завершённый цикл:

```takt
exit { cycles := cycles + 1; }
```

Другого имени у блока быть не может: `enter`, `exit`, `always` — исчерпывающий
список.

## Пример

Рассмотрим **регулятор уровня в баке**: он наливает бак до верхней отметки, затем
откачивает до нижней и снова наливает, считая завершённые циклы откачки. Здесь
пригождаются и именованные условия, и все три блока:

```takt
{{#include examples/tank.takt}}
```

Две отметки уровня вынесены в **именованные условия** (1): `Full` — бак достиг
верхней границы, `Empty` — опустел до нижней. Ими и управляются переходы: `ref
Draining: Full;` и `ref Filling: Empty;` — вместо того чтобы писать `level >=
HIGH` прямо в переходе, мы даём проверке имя. В каждом состоянии свои блоки: при
**входе** (2) `Filling` открывает клапан и глушит насос, а `Draining` — наоборот;
**каждый такт** (3) уровень растёт или падает на `RATE`; при **выходе** (4) из
`Draining` счётчик `cycles` увеличивается — так фиксируется завершённый цикл
откачки.

Прогон показывает колебание уровня и счёт циклов:

```text
Шаг 1: [Filling]   valve=1 pump=0  level=70  cycles=0
Шаг 2: [Draining]  valve=0 pump=1  level=90  cycles=0
Шаг 3: [Draining]  valve=0 pump=1  level=70  cycles=0
...
Шаг 6: [Filling]   valve=1 pump=0  level=10  cycles=1
```

Уровень растёт до `HIGH` (90), затем модель переходит в `Draining` и качает вниз
до `LOW` (10); на этом переходе назад срабатывает `exit`, и `cycles` становится
равным 1. Дальше цикл повторяется.

## Частые ошибки

Типичные ошибки при работе с именованными условиями и блоками:

- `SE-025` — именованное условие ссылается на неизвестную переменную или имя
  (опечатка в формуле `cond`);
- `SE-045` — неизвестное имя блока: допустимы только `enter`, `exit`, `always`.
