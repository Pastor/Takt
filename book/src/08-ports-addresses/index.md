# Порты и адреса

**Порт** — это точка связи модели с окружением: физической аппаратурой, соседней
подсистемой или средой исполнения. Через порты в модель приходят показания
датчиков и команды, а из модели уходят управляющие сигналы. У порта есть имя, тип
и **направление**; при необходимости порту сопоставляется **адрес** — место в
пространстве ввода-вывода целевой платформы.

## Направления

Направление задаётся ключевым словом перед именем порта:

```takt
in  demand:  bit;     // вход: значение приходит извне, модель его читает
out running: bit;     // выход: значение задаёт модель, окружение его читает
inout bus:   u8;      // двунаправленный: и чтение, и запись
```

- `in` — **входной** порт. Модель только читает его; записывать во входной порт
  нельзя. Так подаются показания датчиков и внешние запросы.
- `out` — **выходной** порт. Модель только пишет в него; окружение читает
  результат. Так выдаются команды исполнительным механизмам.
- `inout` — **двунаправленный** порт: допускает и чтение, и запись (например,
  общая шина).

В теле состояний порт используется как обычная переменная — с учётом
направления: входной читается в условиях и выражениях, выходной получает значение
присваиванием `:=`.

## Адрес порта

Чтобы связать порт с конкретным регистром ввода-вывода, ему сопоставляют
**адрес**. Задать адрес можно тремя способами.

**Инлайн** — прямо в объявлении, через `:=`:

```takt
in button: bit := 0x40000000:0;
```

> **Осторожно.** Инициализатор порта задаёт **адрес**, а не начальное значение.
> Начального значения у порта и не бывает: он читается извне либо пишется
> наружу. Поэтому `out ready: bit := 0;` означает «порт лежит по адресу 0», а не
> «изначально ноль» — компилятор об этом предупреждает (`SE-091`). Если адрес
> задаётся не в модели, инициализатор просто опускают: `out ready: bit;`.

**Оператором `address`** — отдельной строкой, что удобно, когда объявления и
карту адресов хочется держать порознь:

```takt
in  temp: u8;
address temp = 0x40000002;
```

**Внешней картой** — файлом в формате, близком к `.ld` (`ИМЯ = 0xАДРЕС;`),
который подаётся ключом `--address-map` при генерации. Так одна и та же модель
переносится между платами без правки исходника.

Если один порт получает адрес сразу несколькими способами, действует приоритет:
**инлайн `:=` слабее оператора `address`, а он — слабее внешней карты**. Внешняя
карта перекрывает всё, оператор перекрывает инлайн.

## Бит адреса

Когда порт занимает не весь регистр, а отдельный разряд, к адресу через двоеточие
дописывают **номер бита**:

```takt
out alarm: bit := 0x40000004:5;   // бит 5 регистра выходов
```

Номер бита должен лежать в диапазоне **от 0 до 63**. Несколько битовых портов
могут делить один адрес, различаясь номерами бита, — так один регистр
раскладывается на независимые сигналы.

Если у однобитного порта позиция не написана (`in P: bit := 0x100;`),
принимается **бит 0** — и об этом сообщается (`SE-090`): для отдельного разряда
адрес без позиции неполон, а угадывать за автора компилятор не вправе молча.

## Связь с целями генерации

Адреса нужны там, где модель отображается прямо в память платы. Их используют цели
`c-hal` (прошивка микроконтроллера с доступом к регистрам), `st-at` (ПЛК с прямой
адресацией) и `sv-mmio` (аппаратный интерфейс). Для этих целей адрес превращается в
чтение и запись по указанному месту памяти.

Цель `c` адрес **не использует**: доступ к портам она выражает через колбэки
слоя аппаратной абстракции (HAL), а сопоставление имени порта с железом остаётся
за средой. Поэтому модель, написанная с адресами, годится и для `c` — адреса там
просто не участвуют.

Разрешённую карту адресов можно выгрузить наружу — командой
`taktc address-map --emit map` (или `--emit json`). Полезно, чтобы свериться,
какой адрес в итоге получил каждый порт после наложения всех трёх источников.

в состоянии `Off` всё обесточено, по нажатию кнопки модель переходит в `On`,
включает вентилятор и каждый такт сравнивает температуру с порогом `MAX_T`,
зажигая светодиод при перегреве.

## Частые ошибки

Типичные ошибки при работе с портами и адресами:

- `SE-048` — оператор `address` ссылается на несуществующий порт (опечатка в имени);
- `SE-049` — конфликт: у порта задан и инлайн-адрес, и оператор `address`;
- `SE-052` — используемый порт целевой платформы (`c-hal`/`st-at`) остался без адреса;
- `SE-060` — номер бита адреса вне диапазона [0, 63];
- `SE-090` — у однобитного порта не задана позиция бита: принят бит 0;
- `SE-091` — инициализатор порта задаёт адрес, а не начальное значение (адрес
  0 или 1 почти всегда написан по привычке).
