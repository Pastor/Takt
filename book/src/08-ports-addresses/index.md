# Порты и адреса

**Порт** — это точка связи модели с окружением: физической аппаратурой, соседней
подсистемой или средой исполнения. Через порты в модель приходят показания
датчиков и команды, а из модели уходят управляющие сигналы. У порта есть имя, тип
и **направление**; при необходимости порту сопоставляется **адрес** — место в
пространстве ввода-вывода целевой платформы.

## Направления

Направление задаётся ключевым словом перед именем порта:

```takt
in  demand:  bit;     // вход: значение приходит извне, модель его читает
out running: bit;     // выход: значение задаёт модель, окружение его читает
inout bus:   u8;      // двунаправленный: и чтение, и запись
```

- `in` — **входной** порт. Модель только читает его; записывать во входной порт
  нельзя. Так подаются показания датчиков и внешние запросы.
- `out` — **выходной** порт. Модель только пишет в него; окружение читает
  результат. Так выдаются команды исполнительным механизмам.
- `inout` — **двунаправленный** порт: допускает и чтение, и запись (например,
  общая шина).

В теле состояний порт используется как обычная переменная — с учётом
направления: входной читается в условиях и выражениях, выходной получает значение
присваиванием `:=`.

Направление проверяется **во всех местах программы** — в условиях переходов, в
телах блоков и функций, внутри `if`, `loop` и `for`, в инициализаторах. Запись
во входной порт даёт `SE-026`, чтение выходного — `SE-027`. Если выданное
значение нужно потом прочитать, заведите переменную и присваивайте её и порту:
переменная и хранит выданное.

## Адрес порта

Чтобы связать порт с конкретным регистром ввода-вывода, ему сопоставляют
**адрес**. Задать адрес можно тремя способами.

**В объявлении** — ключевым словом `at`:

```takt
in button: bit at 0x40000000:0;
```

Часть **необязательная**: если адрес задаётся не в модели, `at` просто не пишут —
`out ready: bit;`.

**Оператором `address`** — отдельной строкой, что удобно, когда объявления и
карту адресов хочется держать порознь:

```takt
in  temp: u8;
address temp = 0x40000002;
```

**Внешней картой** — файлом в формате, близком к `.ld` (`ИМЯ = 0xАДРЕС;`),
который подаётся ключом `--address-map` при генерации. Так одна и та же модель
переносится между платами без правки исходника.

Если один порт получает адрес сразу несколькими способами, действует приоритет:
**`at` слабее оператора `address`, а он — слабее внешней карты**. Внешняя карта
перекрывает всё, оператор перекрывает `at`.

## Начальное значение выходного порта

Знак `:=` в объявлении порта задаёт **начальное значение** — то, что выставится
на выход до первого такта:

```takt
out ready: bit at 0x40000004:0 := 0;   // адрес и начальное значение
out alarm: bit := 0;                   // только значение: адрес придёт извне
```

У **входного** порта начального значения не бывает: его значение приходит извне —
от датчика, регистра, соседнего устройства. Такая запись отвергается (`SE-092`).

Значение должно быть известно **при компиляции**: литерал, константа или
арифметика над ними. Оно выставляется до того, как автомат сделал хоть один шаг,
поэтому взять его из переменной неоткуда — такая запись отвергается (`SE-094`).

```takt
const IDLE: u8 := 4;
out mode: u8 at 0x40000010 := IDLE + 1;   // 5 — посчитано при сборке
```

Значение выставляется **до первого такта** — во всех целях и в симуляторе, но
каждая делает это своим способом: `c`, `c-hal` и `rust` пишут его в функции
инициализации, `sv` и `sv-mmio` — цепью сброса, `st` и `st-at` — инициализатором
объявления (у `st-at` — на размещённой переменной).

> **Осторожно, цель `c`.** Значение уходит наружу через тот же слой аппаратной
> абстракции, что и запись из тела автомата. Значит указатели HAL должны быть
> проставлены **до** вызова `<Root>_init` — в цели `c-hal` для этого сперва
> вызывают `<Root>_bind_default_hal`.

> **Осторожно.** Размещение и значение — разные вещи и пишутся по-разному:
> `at 0x40000004:0` говорит **где** порт лежит, `:= 0` — **чем** он начинается.
> Перепутать их нельзя: `out ready: bit := 0x40000004;` означает «начальное
> значение 0x40000004», а не адрес.

## Бит адреса

Когда порт занимает не весь регистр, а отдельный разряд, к адресу через двоеточие
дописывают **номер бита**:

```takt
out alarm: bit at 0x40000004:5;   // бит 5 регистра выходов
```

Номер бита должен лежать в диапазоне **от 0 до 63**. Несколько битовых портов
могут делить один адрес, различаясь номерами бита, — так один регистр
раскладывается на независимые сигналы.

Если у однобитного порта позиция не написана (`in P: bit at 0x100;`),
принимается **бит 0** — и об этом сообщается (`SE-090`): для отдельного разряда
адрес без позиции неполон, а угадывать за автора компилятор не вправе молча.

## Связь с целями генерации

Адреса нужны там, где модель отображается прямо в память платы. Их используют цели
`c-hal` (прошивка микроконтроллера с доступом к регистрам), `st-at` (ПЛК с прямой
адресацией) и `sv-mmio` (аппаратный интерфейс). Для этих целей адрес превращается в
чтение и запись по указанному месту памяти.

Цель `c` адрес **не использует**: доступ к портам она выражает через колбэки
слоя аппаратной абстракции (HAL), а сопоставление имени порта с железом остаётся
за средой. Поэтому модель, написанная с адресами, годится и для `c` — адреса там
просто не участвуют.

Разрешённую карту адресов можно выгрузить наружу — командой
`taktc address-map --emit map` (или `--emit json`). Полезно, чтобы свериться,
какой адрес в итоге получил каждый порт после наложения всех трёх источников.

## Обращение к ячейке без имени

Иногда порт заводить незачем: к регистру обращаются один раз — разблокировать
периферию, прочитать идентификатор чипа, взвести сторожевой таймер. Для этого
есть **обращение по адресу**, у которого имени нет вовсе:

```takt
flags := #0x40000010 as u32;      // прочитать слово по адресу
#0x40000010 as u32 := 1;          // записать слово по адресу
mode := #0x40000014:3 as u8;      // поле шириной 8 разрядов, начиная с бита 3
ready := #0x40000014.7;           // один бит
```

Читается так: `#` — «ячейка по адресу», `:N` — **начало поля**, `as ТИП` — его
разрядность, `.N` — один бит. Разрядность обязательна: `#0x40000010` без `as` и
без бита не означает ничего — по адресу может лежать и байт, и слово, и выбирать
за автора компилятор не станет.

Обращение — **операнд**, а не самостоятельный оператор: значение, которое
никуда не идёт, эффекта не имеет. Поэтому строка `#0x40000010 as u32;` незаконна,
а `x := #0x40000010 as u32;` и `if #0x40000014.7 { … }` — законны.

**Направления у ячейки нет**, поэтому проверить законность записи компилятор не
может: за адресом может стоять регистр только для чтения. Запись поэтому всегда
сопровождается предупреждением; чтобы его снять, объявите именованный порт с тем
же адресом — тогда направление объявлено и проверяемо.

Обращение без имени понимают только цели, знающие адресное пространство:
`c-hal`, `st-at` и `sv-mmio`. Цели `c`, `rust`, `st` и `sv` отказываются
транслировать такую модель, называя причину, — молча потерять доступ к железу
хуже, чем отказать.

> **Осторожно — ограничение симуляции.** В прогоне ячейка моделируется как
> отдельное значение, различаемое по адресу, биту и разрядности: `#0x100 as u8`
> и `#0x100 as u32` симулятор считает **разными** ячейками, тогда как на плате
> это одна и та же память. Если модель обращается к одной ячейке разной
> шириной, проверять её поведение симуляцией нельзя.


Кнопка `button` (1) получает адрес **инлайн** — бит 0 входного регистра
`0x40000000`. Датчик `temp` (2) объявлен без адреса, а адрес ему задан ниже
**оператором** `address temp = 0x40000002;` — объявление и адрес разнесены.
Выходы делят один регистр `0x40000004`: светодиод `alarm` сидит в бите 5, а
вентилятор `fan` — в бите 0 (два битовых порта на одном адресе). Логика проста:
в состоянии `Off` всё обесточено, по нажатию кнопки модель переходит в `On`,
включает вентилятор и каждый такт сравнивает температуру с порогом `MAX_T`,
зажигая светодиод при перегреве.

## Частые ошибки

Типичные ошибки при работе с портами и адресами:

- `SE-048` — оператор `address` ссылается на несуществующий порт (опечатка в имени);
- `SE-049` — конфликт: у порта задан и инлайн-адрес, и оператор `address`;
- `SE-052` — используемый порт целевой платформы (`c-hal`/`st-at`) остался без адреса;
- `SE-026` — запись во входной порт (его значение приходит извне);
- `SE-027` — чтение выходного порта (для «вспомнить выданное» заведите переменную);
- `SE-060` — номер бита адреса вне диапазона [0, 63];
- `SE-090` — у однобитного порта не задана позиция бита: принят бит 0;
- `SE-092` — начальное значение задано **входному** порту;
- `SE-096` — запись по адресу без объявленного направления (предупреждение);
- `SE-097` — у обращения по адресу не задана разрядность доступа;
- `SE-098` — позиция бита или разрядность поля выходит за слово доступа;
- `SE-099` — обращение по адресу в инициализаторе объявления;
- `SY-008` — адресный литерал написан там, где вычисляется значение.
