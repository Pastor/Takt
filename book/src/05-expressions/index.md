# Выражения и условия

В Takt различаются два контекста вычислений: **условия** и **выражения**.
Различие не только стилистическое — в этих контекстах **по-разному ведут себя
операторы `&` и `|`**, поэтому важно понимать, где какой контекст.

## Условия

**Условие** даёт логическое значение (истина/ложь) и используется там, где нужно
принять решение:

- на переходах — `ref Цель: условие;`;
- в управляющих конструкциях — `if условие { … }`, `while условие { … }`.

В условии `&` — это **логическое И**, `|` — **логическое ИЛИ**, `!` — **отрицание**
(все — одиночные знаки). Равенство сравнивается знаком `=`.

```takt
ref Working: start_btn = 1 & stop_btn = 0;   // И
ref Idle:    stop_btn = 1 | count >= LIMIT;  // ИЛИ
```

В условиях доступны сравнения (`=`, `!=`, `<`, `<=`, `>`, `>=`), сложение и
вычитание, обращение к полю/биту/элементу и проверка состояния под-модели
(`S(Модель)` — см. раздел «Импорты и композиция моделей»). Проверка состояния
записывается двумя равносильными способами — полным `S(Модель) = Состояние` и
кратким `Модель = Состояние`:

```takt
ref Done: S(Feeder) = Idle;   // полная запись
ref Done: Feeder = Idle;      // краткая — то же самое
```

## Выражения

**Выражение** вычисляет значение или выполняет присваивание. Выражения образуют
тела блоков `enter`/`exit`/`always` и тела функций:

```takt
count := count + 1;        // присваивание
doubled := count * 2;
m := a > b ? a : b;        // условное выражение (тернарное)
```

### Присваивание и сравнение

- **`:=`** — присваивание (записать значение в переменную/поле/порт);
- **`=`** — сравнение на равенство; **`!=`** — на неравенство.

Знака `==` в языке нет — равенство везде обозначается одним `=`. Тот же `=`
служит связкой в определениях (`type`, `enum`, `cond`).

```takt
count := 0        // присваивание
count = LIMIT     // сравнение (даёт истину/ложь)
```

**Присваивание — оператор, а не значение.** Записать что-то посреди вычисления
нельзя: присваивание стоит либо отдельным оператором тела, либо шагом цикла
`for`. Значение записи не «возвращается», поэтому её не подставить в
арифметику, условие или аргумент.

```takt
value := 3;                 // так: запись — отдельный оператор
seen := value + 1;          // и лишь потом использование

seen := (value := 3) + 1;   // ОШИБКА SY-006: запись внутри вычисления
```

Правило держит **синтаксис**: такая запись не разбирается вовсе, а не
отвергается позже. Оно одинаково для переменных и портов, и его действие видно в
каждой цели генерации: запись всегда порождает оператор, чтение — выражение.

> **Осторожно.** Форма `имя := значение` встречается ещё в одном месте — при
> **инстанцировании модели** (`Pid(kp := 0.25)`, см. раздел о параметрах). Это не
> запись в переменную, а задание параметра: слева там стоит имя параметра
> целевой модели.

### Операторы выражений

| Категория | Операторы |
|-----------|-----------|
| Арифметические | `+`  `-`  `*`  `/`  `%`  `**` |
| Побитовые | `&`  `\|`  `^`  `~`  `<<`  `>>` |
| Логические | `&&`  `\|\|`  `!` |
| Сравнения | `=`  `!=`  `<`  `<=`  `>`  `>=` |
| Присваивание | `:=` |
| Условное (тернарное) | `условие ? то : иначе` |
| Приведение типа | `значение as Тип` |

> **Важное различие с условиями.** В выражении `&` и `|` — **побитовые**
> операторы, а логические — это **`&&`** и **`||`**. В условии же `&`/`|` —
> логические. Одна и та же запись `a & b` в условии означает «И», а в выражении —
> побитовое И.

### Результат за границами типа

Что происходит, когда результат не помещается в тип, определяет **тип**, а не
операция:

| Тип операндов | Поведение |
|---|---|
| беззнаковое целое (`u8`…`u64`) | обёртка по модулю `2ⁿ` |
| знаковое целое (`i8`…`i64`) | **ошибка программы** (`SIM-003` при симуляции) |
| `q(m, n)` | перенос через границу ширины `W = m + n` |
| `q(m, n) sat` | прижатие к границе (насыщение) |

Обе семантики фикс-точки и выбор между ними описаны в разделе
[«Типы»](../03-types/index.md). Правило одно для эталона и всех целей генерации:
арифметика в порождённом коде обязана давать бит в бит те же значения, что
симулятор.

## Приоритет операторов

В выражении операторы применяются в следующем порядке (от **высшего** приоритета к
**низшему**):

| Приоритет | Операторы |
|-----------|-----------|
| высший | обращение `.` `[]`, вызов, скобки `( )` |
| | унарные `!` `~` `+` `-` |
| | `**` (степень) |
| | `*` `/` `%` |
| | `+` `-` |
| | `<<` `>>` |
| | `&`, `as` |
| | `^` |
| | `\|` |
| | `<` `<=` `>` `>=` |
| | `=` `!=` |
| | `&&` |
| | `\|\|` |
| низший | `:=`, `? :` |

Скобками `( )` порядок вычисления задаётся явно, когда приоритет по умолчанию не
подходит.

## Доступ к члену

К составным значениям обращаются постфиксными операторами:

| Запись | Смысл |
|--------|-------|
| `p.x` | поле `x` структуры `p` |
| `flags.3` | бит номер 3 значения `flags` |
| `a[i]` | элемент массива `a` по индексу `i` |
| `a[l:r]` | срез массива `a` |

```takt
p.x := 100;         // запись в поле
led := flags.3;     // чтение бита
a[0] := 42;         // запись элемента массива
```

## Обращение к ячейке по адресу

Выражением может быть и **ячейка памяти**, у которой нет имени, — форма `#`:

```takt
word := #0x40000010 as u32;   // слово по адресу
part := #0x40000014:3 as u8;  // поле шириной 8 разрядов с бита 3
flag := #0x40000014.7;        // один бит
```

Разрядность доступа задаётся явно — приведением `as ТИП` либо битовым доступом
`.N`; без них обращение незаконно. Такое выражение можно и записывать
(`#0x40000010 as u32 := 1;`), но само по себе, без потребителя значения, оно
оператором быть не может. Подробности и ограничения — в разделе
[«Порты и адреса»](../08-ports-addresses/index.md).

> **Осторожно.** Адрес **без** `#` в выражении незаконен: `x := 0x100:0;` —
> ошибка `SY-008`. Запись `0xАДРЕС:бит` означает размещение и живёт только
> там, где порт размещают (`at`, оператор `address`, внешняя карта).

## Оператор обязан иметь эффект

Оператором тела может быть **присваивание** либо **вызов функции** — то, что
что-то делает. Выражение, значение которого никуда не идёт, оператором не
является:

```takt
x := y + 1;     // корректно: присваивание
beep();         // корректно: вызов
y + 1;          // ОШИБКА SY-007: вычисленное значение некуда деть
#0x100.4;       // ОШИБКА SY-007: чтение без потребителя
```

## Пример

Рассмотрим модель **бойлера**. Он включает нагрев, когда вода остыла ниже нижнего
порога и давление в норме, и выключает его, когда температура достигает верхнего
порога либо давление падает.

```takt
{{#include examples/expr.takt}}
```

Модель — два состояния: `Idle` (нагрев выключен) и `Heating` (включён). Пороги
`MIN_TEMP`/`MAX_TEMP` заданы константами, `temp` и `pressure_ok` — входы с датчиков,
`heater` — выход на нагреватель, а `cycles` считает **циклы нагрева** (сколько раз
он включался).

Здесь наглядно видно различие двух контекстов. **Условия** переходов записываются
логическими операторами (одиночными знаками): нагрев включается, когда выполнены
**оба** условия — `temp < MIN_TEMP & pressure_ok = 1` (логическое И, (1)), а
выключается, когда истинно **хотя бы одно** — `temp >= MAX_TEMP | pressure_ok = 0`
(логическое ИЛИ, (3)); равенство здесь обозначается знаком `=`. В **теле** блока
`enter` работает уже выражение — присваивание с арифметикой `cycles := cycles + 1`
(2), исполняемое **при входе** в `Heating` (то есть на каждый цикл нагрева, а не на
каждый такт). Обратите внимание: попади те же `&`/`|` в тело блока, они означали бы
**побитовые** операции, а не логические.

## Частые ошибки

Типичные ошибки в выражениях и условиях:

- `SY-002` — запись равенства как `==` вместо `=`;
- `SE-003` — использование необъявленной переменной;
- `SE-059` — неявное смешение `q(m, n)` и `float` в арифметике (нужно `… as q(m, n)`);
- `SE-026` / `SE-027` — запись в входной порт или чтение из выходного;
- `SE-028` — индекс вне границ массива; `SE-030` — индексация не-массива;
- `SE-062` — вложенность выражения глубже предела (обычно признак забытой
  закрывающей скобки);
- `SY-007` — выражение в позиции оператора не имеет эффекта;
- `SY-008` — адресный литерал написан там, где вычисляется значение;
- `SE-097` — у обращения `#АДРЕС` не задана разрядность доступа.

Помните и о разной роли `&`/`|`: в условии — логические, в выражении — побитовые.
