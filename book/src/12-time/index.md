# Механизмы времени

Такт — шаг логики, а не единица времени: частота тактирования задаётся
платформой и к физике отношения не имеет (см.
[«Модель исполнения»](../11-execution/index.md)). Поэтому выдержку нельзя
записать «в тактах»: то же число тактов на другом устройстве означает другую
длительность. Язык даёт для времени отдельные средства — **литерал
длительности**, тип **`duration`** и выдержку **`after`** на переходе.

Источник времени, как и такт, — **внешний**: автомат его не порождает, а
спрашивает. Что именно его даёт (системные часы, таймер контроллера, счётчик
тактов известной частоты) — свойство платформы, а не модели.

## Литерал длительности

Длительность записывается числом с единицей **без пробела**:

```takt
500ms   // полсекунды
3s      // три секунды
2h      // два часа
```

Единицы: `ns` (наносекунды), `us` (микросекунды), `ms` (миллисекунды), `s`
(секунды), `m` (минуты), `h` (часы). Регистр значим: `m` — минута, а `MHz` —
мегагерц.

Слагаемые можно писать подряд, **от крупных к мелким**:

```takt
1m30s   // девяносто секунд
2h30m   // два с половиной часа
```

Дробная форма не допускается: вместо `1.5s` пишется `1500ms` — так у выдержки нет
скрытого округления. Порядок слагаемых обязателен: `1s30m` — ошибка, а не
«полторы минуты».

## Тип `duration`

Длительность — **самостоятельный тип**, а не число: единица входит в тип и
поэтому не теряется при присваивании.

```takt
var left: duration := 0s;
var pause: duration := 250ms;
```

Разрешены сложение и вычитание длительностей (результат — снова длительность) и
сравнения:

```takt
left := pause + 750ms;   // 1s
left := left - 250ms;    // 750ms
```

Смешивать длительность с числом **неявно** нельзя: `left + 1` — ошибка, потому
что неизвестно, что такое «единица» — такт, миллисекунда или час. Переход между
длительностью и числом делается **явным приведением**, и единица перехода —
**миллисекунда**:

```takt
var ms: u32 := 0;
ms := left as u32;          // 750  — число миллисекунд
left := 250 as duration;    // 250ms — число трактуется как миллисекунды
```

При приведении к числу остаток отбрасывается: `500us as u32` даёт `0`. Это
осознанная потеря — на то и нужно явное `as`.

## Частота тактирования

Модель может объявить частоту, с которой её тактирует платформа:

```takt
clock 1kHz;   // такт — одна миллисекунда
```

Единицы частоты — `Hz`, `kHz`, `MHz`. Объявление говорит компилятору, во сколько
тактов превращается длительность: при 1 кГц выдержка `3s` — это 3000 тактов.
Модель **без** объявления частоты остаётся полноценной: тогда длительность
сравнивается с показаниями внешнего источника времени, и от частоты она не
зависит вовсе — это и позволяет отлаживать автомат потактово, не привязываясь к
устройству.

Если длительность не выражается целым числом тактов заявленной частоты,
компилятор **отказывает**, а не округляет молча: `500ms` при частоте 3 Гц — это
полтора такта, и такую модель нужно исправить, а не «примерно собрать».

## Выдержка `after`

`after` — условие перехода: «прошло не меньше указанного».

```takt
state Overrun {
    ref Idle: after 3m;
}
```

Отсчёт начинается **с входа в состояние, где стоит переход**. Запись выше читается
так: «попав в `Overrun`, через три минуты перейти в `Idle`». Повторный вход в
состояние начинает отсчёт **заново** — выдержка привязана к входу, а не к началу
работы автомата.

`after` можно соединять с другими условиями:

```takt
ref Alarm: (after 10s) & (level = 0);   // держится больше 10 с и уровень не поднялся
```

Выдержка допустима **только** в условии перехода: в именованном условии (`cond`),
инварианте или формуле у неё нет состояния, от входа в которое вести отсчёт.

Из состояния может вести несколько переходов, и `after` соревнуется с ними на
общих правах: сработает **первый** годный по порядку записи. Это и есть штатный
способ **отменить** выдержку — уйти из состояния раньше по другому условию.

## Точность

Условия проверяются на такте, поэтому переход по выдержке происходит на **первом
такте, на котором интервал истёк**: выдержка никогда не короче заявленной, а её
точность — один такт. Чем реже такты, тем грубее приближение: при такте раз в
секунду выдержка `2500ms` фактически станет тремя секундами.

## Пример

Рассмотрим модель **вытяжного вентилятора с выбегом** — обычная автоматика
санузла или производственного помещения. Пока горит свет, вентилятор работает;
когда свет выключили, он крутится ещё три минуты, вытягивая остаточную влажность,
и только потом останавливается. Если свет включили снова — вентилятор продолжает
работать, а отсчёт выбега отменяется.

```takt
{{#include examples/fan.takt}}
```

Модель тактируется каждую миллисекунду — это сказано объявлением `clock 1kHz` (1),
и оно же позволяет компилятору перевести выдержку в такты для устройств без
собственных часов. Состояние света приходит **датчиком** `light`, а вентилятор
включается **выходным портом** `motor`: автомат командует приводом и читает
датчик, а не вычисляет физику сам.

Работа делится на три состояния. В `Idle` вентилятор стоит, и единственный
переход ждёт появления света. В `Working` вентилятор включён; переход из него
происходит, когда свет пропал. Самое интересное — `Overrun`: сюда автомат попадает
в момент выключения света, и **от этого момента** (2) идёт отсчёт выбега.

Из `Overrun` ведут два перехода, и порядок их записи значим. Первым проверяется
`ref Working: light = 1` (3) — если свет включили снова, автомат немедленно
возвращается в рабочий режим, и выдержка **отменяется**: при следующем выключении
света отсчёт начнётся с нуля. Только если света нет, дело доходит до второго
перехода `ref Idle: after 3m` (4), который и останавливает вентилятор через три
минуты.

Вот прогон со сценарием «свет горел, затем его выключили» (модельное время
показано в скобках):

```text
Шаг 1:           [Working]  light=1  motor=1
Шаг 2 (   1ms):  [Working]  light=1  motor=1
Шаг 3 ( 1m1ms):  [Overrun]  light=0  motor=1
Шаг 4 ( 2m1ms):  [Overrun]  light=0  motor=1
Шаг 5 ( 3m1ms):  [Overrun]  light=0  motor=1
Шаг 6 ( 4m1ms):  [Idle]     light=0  motor=0
Шаг 7 ( 5m1ms):  [Idle]     light=0  motor=0
```

На первом такте свет уже горит, поэтому автомат сразу оказывается в `Working` и
включает вентилятор — вход в стартовое состояние не стоит такта. На шаге 3 свет
выключили (`light=0`), и модель перешла в `Overrun`, **не выключая** вентилятор.
Дальше видно главное свойство выдержки: она считается от входа в `Overrun`
(момент `1m1ms`), а не от начала прогона, поэтому вентилятор останавливается на
шаге 6 в момент `4m1ms` — ровно через три минуты после того, как погас свет.

## Частые ошибки

Типичные ошибки, связанные со временем:

- `LE-011` — единица приписана недопустимой форме числа: `1.5s`, `1e3ms`,
  `0xFFms`, либо слагаемые идут не по убыванию (`1s30m`);
- `LE-010` — литерал длительности вне представимого диапазона;
- `SE-063` — длительность непредставима: мельче миллисекунды там, где время
  меряется миллисекундами, либо не кратна периоду такта заявленной частоты;
- `SE-064` — длительность не помещается в счётчик времени;
- `SE-065` — длительность смешана с числом без явного приведения (`left + 1`);
- `SE-067` — частота тактирования объявлена дважды и по-разному;
- `SE-068` — `after` стоит вне условия перехода (в `cond`, инварианте, формуле).

Подробный разбор с примерами — в приложении
[«Ошибки и предупреждения»](../appendix-errors/index.md).
