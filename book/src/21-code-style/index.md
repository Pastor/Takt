# Стиль кода

Единый стиль экономит внимание: чем меньше сил уходит на разбор написания, тем
больше остаётся на разбор смысла. Этот раздел описывает, как принято оформлять
код на Takt.

Стиль си-подобный и близок к K&R: открывающая скобка остаётся на строке
заголовка, тело блока — с отступом, оператор завершается точкой с запятой. Ниже
названы и те немногие места, где принятое в Takt оформление от K&R отходит.

## Форматирование выполняет компилятор

Большую часть правил ниже не нужно соблюдать вручную:

```bash
taktc fmt traffic.takt        # привести файл к канону
taktc fmt --check traffic.takt   # проверить, не меняя (для CI)
```

Поэтому спор об оформлении в Takt не имеет предмета: канон один, и он исполним
командой. Разумный порядок работы — писать как удобно и прогонять `fmt` перед
сохранением; редакторы с поддержкой языкового сервера делают это сами.

Часть правил инструмент проверить не может — он не знает, какое имя удачно и в
каком порядке читателю удобнее видеть объявления. Такие правила ниже
сформулированы как советы, и в тексте прямо сказано, что выбор остаётся за
автором.

## Отступы и скобки

Отступ — **четыре пробела** на уровень; знаки табуляции не используются. Каждый
вложенный блок добавляет один уровень. Это делает `taktc fmt`.

Открывающая скобка ставится **на строке заголовка**, через пробел; закрывающая —
на отдельной строке, на отступе заголовка:

```takt
model Heater {
    start Idle {
        always {
            ticks := ticks + 1;
        }
    }
}
```

Тело блока всегда занимает отдельные строки, даже когда оператор один:
`start S { always { v := 1; } }` форматтер развернёт. Компактная запись каноном
не является.

**`else` начинается с новой строки** — здесь Takt расходится с K&R, где принято
`} else {`:

```takt
if level > limit {
    valve := 0;
}
else {
    valve := 1;
}
```

Условие `if` и заголовок `while` в скобки не заключаются: `if a > 3 {`, а не
`if (a > 3) {`. Скобки в условии остаются допустимыми там, где они группируют
подвыражение по смыслу.

## Пробелы

Пробел ставится после двоеточия в объявлении (`var a: u8`), вокруг присваивания
`:=`, вокруг связки `=` в определениях имён, вокруг бинарных операторов и вокруг
стрелки возвращаемого типа:

```takt
var speed: u8 := 1 + 2 * 3;
const LIMIT: u8 := 4;
fn next(x: u8) -> u8 {
    return x + 1;
}
```

Пробел не ставится между именем функции и открывающей круглой скобкой
(`next(x)`), а также сразу за открывающей и перед закрывающей скобкой. Всё
перечисленное расставляет `taktc fmt`.

Перечисление, объявленное в одну строку, такой и остаётся, с пробелами внутри
скобок: `enum Cmd { Up, Down }`.

## Пустые строки

Пустая строка отделяет смысловые группы — объявления от состояний, одно
состояние от другого. Подряд идущих пустых строк не бывает: две и более
форматтер сводит к одной.

Где именно ставить пустую строку, решает автор: инструмент сохраняет её, если
она есть, но сам не расставляет.

## Порядок элементов модели

Форматтер порядок **не меняет** — он ваш. Принято располагать элементы от общего
к частному, чтобы читатель сначала узнал, чем модель оперирует, и лишь потом —
как она себя ведёт:

1. импорты;
2. типы: `type`, `enum`, `struct`;
3. константы и параметры: `const`, `parameter`;
4. порты: `in`, `out`, `inout`;
5. переменные: `var`;
6. именованные условия `cond` и инварианты;
7. функции `fn`;
8. стартовое состояние, затем остальные состояния.

Состояния удобно располагать в порядке прохождения: стартовое, затем те, куда из
него ведут переходы. Так текст читается в том же направлении, в каком работает
автомат.

## Именование

Инструмент имена не проверяет — они целиком на авторе. Приняты следующие формы:

| Что | Форма | Пример |
|---|---|---|
| Модели, состояния, типы, перечисления, структуры | `UpperCamelCase` | `Heater`, `Idle`, `Command` |
| Варианты перечисления | `UpperCamelCase` | `Up`, `Down`, `Stop` |
| Переменные, порты, функции, параметры | `snake_case` | `target_floor`, `read_sensor` |
| Константы | `UPPER_SNAKE_CASE` | `MAX_LEVEL`, `LIMIT` |

Имя состояния лучше называет **положение**, а не действие: `Heating`, `Settled`,
`DoorOpen` — а не `DoHeat`. Имя порта называет сигнал, а не его направление:
`ready`, а не `out_ready`, — направление уже написано рядом.

Не всякое имя языка стоит выбирать, даже когда язык его принимает: имена
встроенных типов (`bit`, `bool`, `u8`, `float`) переменной дать можно, но читать
такой код тяжело.

Буквы вне латиницы язык допускает, однако цели `sv` и `st` их не переводят. Если
модель предназначена для ПЛК или аппаратуры, именуйте латиницей.

## Комментарии

Комментарий объясняет **почему**, а не повторяет **что**: строка
`// увеличиваем счётчик` над `count := count + 1;` не сообщает ничего. Полезны
пояснения о происхождении величин, единицах измерения, ограничениях устройства.

Комментарий перед элементом ставится на его отступе и относится к нему;
короткое пояснение к объявлению можно оставить в конце той же строки:

```takt
// Порог из паспорта датчика: выше 80 C начинается дрейф.
const MAX_TEMP: u8 := 80;

var level: u8 := 0; // текущий уровень, 0..100
```

Хвостовые комментарии по колонке **не выравниваются**: между оператором и `//`
всегда один пробел. Выравнивание столбиком выглядит опрятно ровно до первой
правки — стоит удлиниться одной строке, и в обзоре различий меняются все
соседние. Форматтер поэтому сводит отступ перед `//` к одному пробелу.

Форматтер сохраняет комментарии и их место, но содержание — на авторе.

## Равноправные написания

Некоторые конструкции имеют два написания, и форматтер **не приводит их к
одному**: он сохраняет выбор автора, потому что выбор бывает осмысленным.

**`while` и `loop`** означают одно и то же. `while` уместен, когда условие —
главное в цикле; `loop` — когда главное тело, а условие лишь ограничивает
повторения:

```takt
while level < target {
    level := level + 1;
}
```

**Явный вид формулы.** Запись `: [Guard] ready = 1;` и краткая `: ready = 1;`
равносильны. Явная форма полезна там, где рядом соседствуют формулы разных
видов и вид стоит назвать; краткая — когда вид очевиден.

В пределах одного файла держитесь одного написания: чередование без причины
заставляет читателя искать различие, которого нет.

## Длина строки

Строку длиннее примерно ста символов читать неудобно, а в обзоре различий она
переносится и теряет вид. Форматтер длину не контролирует — длинное выражение
разбивает автор: именованным условием `cond`, промежуточной переменной или
функцией. Это к тому же обычно улучшает и смысл: имя объясняет выражение лучше,
чем само выражение.

## Пример

Модель обогревателя, оформленная по описанным правилам:

```takt
// Управление обогревателем: греем до уставки, дальше поддерживаем.
enum Mode { Heating, Holding }

model Heater {
    const TARGET: u8 := 60; // уставка, градусы Цельсия
    const STEP: u8 := 5; // прирост за такт при нагреве

    var mode: Mode := Heating;
    var temp: u8 := 20;

    cond reached = temp >= TARGET;

    start Warmup {
        always {
            temp := temp + STEP;
        }
        ref Hold: reached;
    }

    // Уставка достигнута: держим режим и не трогаем температуру.
    state Hold {
        always {
            mode := Holding;
        }
    }
}

start Main = Heater;
```

## Частые ошибки

**Компактная запись «в одну строку».** `start S { always { v := 1; } }` не
ошибка языка, но каноном не является: `taktc fmt` развернёт её, и в обзоре
различий появится правка, к смыслу отношения не имеющая. Прогоняйте `fmt` до
сохранения, а не после ревью.

**`} else {` по привычке из C.** Takt ставит `else` на новую строку. Написав
по-другому, вы получите ту же правку от форматтера.

**Скобки вокруг условия `if`.** `if (a > 3) {` язык принимает, и форматтер их
сохранит — он не переставляет скобки, поставленные автором. Но в каноническом
тексте их нет, и файл будет выглядеть чужеродно.

**Имя состояния как действие.** `DoHeat` читается как команда, тогда как
состояние есть положение, в котором автомат находится. `Heating` точнее.

**Комментарий, повторяющий код.** Он не бесполезен, а вреден: устаревая, он
начинает противоречить коду, и читатель верит комментарию.

**Чередование `while` и `loop` в одном файле** без причины. Разницы нет, а
читатель её ищет.
