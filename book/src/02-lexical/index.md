# Лексическая структура

Прежде чем разбирать программу на синтаксические конструкции, компилятор
разбивает исходный текст на **токены** (лексемы): идентификаторы, ключевые слова,
литералы, операторы и пунктуацию. Комментарии и пробельные символы служат
разделителями и в поток токенов не попадают. Этот раздел описывает правила такого
разбиения.

## Кодировка исходного текста

Исходный текст — это последовательность символов **Unicode** (кодировка UTF-8).
Unicode допускается не только в комментариях и строках, но и в **идентификаторах**:
имя состояния, переменной или модели может быть записано, например, кириллицей.

## Пробелы и переносы строк

Пробелы, табуляции и переносы строк **не значимы** — они лишь разделяют токены.
Отступы и переносы можно расставлять свободно, для читаемости; на смысл программы
они не влияют. Единственная роль перевода строки — завершение строчного
комментария.

## Комментарии

Поддерживаются три вида комментариев:

| Запись | Комментарий |
|--------|-------------|
| `//` | строчный — от `//` до конца строки |
| `///` | документационный — относится к следующему объявлению |
| `/* */` | блочный — от `/*` до `*/`, может занимать несколько строк |

Документационный комментарий (`///`) описывает идущее следом объявление и
предназначен для инструментов документирования. Последовательность из четырёх и
более слэшей (`//// …`) — это **обычный** строчный комментарий, а не
документационный. Блочные комментарии **не вкладываются**: первый же `*/`
закрывает комментарий, открытый ближайшим `/*`.

```takt
// обычный строчный комментарий
/// документационный комментарий к объявлению ниже
var count: u8 := 0;
/* блочный
   комментарий */
```

## Идентификаторы

Идентификатор именует модель, состояние, переменную, порт, функцию, тип и т. п.
Идентификатор начинается с буквы (в смысле Unicode), знака подчёркивания `_` или
знака доллара `$`, а продолжается буквами, цифрами, `_` или `$`. Регистр букв
**значим**: `Count` и `count` — разные идентификаторы.

```takt
counter        // латиница
счётчик        // кириллица допустима
_temp          // допустимо начинать с подчёркивания
$signal        // и со знака доллара
max_speed_2    // цифры и подчёркивания — в середине и в конце
```

## Ключевые слова

Ключевые слова зарезервированы и не могут использоваться как идентификаторы.

| Назначение | Ключевые слова |
|------------|----------------|
| Модели и состояния | `model`, `state`, `start`, `ref`, `next`, `cond`, `invariant` |
| Объявления | `var`, `const`, `type`, `enum`, `struct`, `fn`, `extern`, `template` |
| Импорт | `import`, `from`, `as` |
| Порты и адреса | `in`, `out`, `inout`, `address` |
| Управляющие конструкции | `if`, `else`, `match`, `while`, `loop`, `for`, `break`, `continue`, `return` |
| Логические литералы | `true`, `false` |
| Верификация | `formula`, `LTL`, `Guard`, `X`, `F`, `G`, `U`, `R` |
| Прочие | `string`, `assembly`, `_` |

> Обратите внимание: одиночные заглавные буквы `X`, `F`, `G`, `U`, `R`
> зарезервированы как операторы темпоральной логики (см. раздел «Верификация
> свойств») и не могут служить именами.

## Литералы

### Числовые литералы

**Целые** числа записываются в десятичной или шестнадцатеричной форме. Для
удобочитаемости в них допустим разделитель разрядов `_`, который на значение не
влияет. Знак `-` перед числом образует отрицательный литерал.

```takt
42
1_000          // разделитель разрядов
0xFF           // шестнадцатеричный
0x0100_0000    // разделитель допустим и в шестнадцатеричной записи
-5             // отрицательный литерал
```

**Дробные** числа (с плавающей точкой) записываются с десятичной точкой и, при
необходимости, с показателем степени `e`/`E`:

```takt
3.14
0.5
.5             // целая часть может отсутствовать
1e10
2.5E-3
```

### Адресные литералы

Адрес аппаратного порта задаётся шестнадцатеричным числом; за ним через двоеточие
может следовать номер бита. Такая запись — единый **адресный литерал** (подробнее
см. раздел «Порты и адреса»):

```takt
0x40020000     // адрес слова
0x40020000:3   // бит 3 по указанному адресу
```

### Логические литералы

Значения истинности — `true` и `false`.

### Строковые литералы

Строка заключается в двойные `"…"` или одинарные `'…'` кавычки. Внутри строки
символ `\` экранирует следующий за ним символ (в частности, саму кавычку).
Префикс `unicode` перед строкой (`unicode"…"`) обозначает строку с Unicode-
содержимым.

```takt
"привет"
'A'
"экранированная \" кавычка"
unicode"Unicode-строка"
```

## Операторы

| Категория | Операторы |
|-----------|-----------|
| Арифметические | `+`  `-`  `*`  `/`  `%`  `**` (степень) |
| Побитовые | `&`  `\|`  `^`  `~`  `<<`  `>>` |
| Логические | `&&`  `\|\|`  `!` |
| Сравнения | `=` (равенство)  `!=`  `<`  `<=`  `>`  `>=` |
| Присваивание | `:=` |
| Доступ и условие | `.` (член)  `?` (условное выражение) |

Ключевое различие: **`:=` — присваивание**, а **`=` — равенство**. Тот же знак
`=` служит связкой в определениях (`type`, `enum`, именованных условиях `cond`,
композиции состояний). Инициализаторы `var`, `const` и портов записываются через
`:=`.

```takt
count := count + 1     // присваивание
count = LIMIT          // сравнение на равенство
```

## Пунктуация

Остальные знаки — разделители и ограничители конструкций:

| Знак | Назначение |
|------|-----------|
| `;` | конец объявления или оператора |
| `,` | разделитель элементов (списки, аргументы, поля) |
| `( )` | группировка, аргументы функций |
| `{ }` | тела моделей, состояний, блоков |
| `[ ]` | типы-массивы и индексация |
| `:` | аннотация типа, метка |
| `->` | тип возвращаемого значения функции |
| `=>` | ветвь `match` |
| `#` | служебный знак |

## Частые ошибки

При наборе лексики легко ошибиться:

- незакрытая строка (нет второй кавычки) — `LE-002`;
- нет цифры после `0x` в шестнадцатеричном литерале — `LE-004`;
- посторонний символ, не входящий в алфавит языка — `LE-006`;
- запись равенства как `==` (в Takt равенство — один знак `=`) — `SY-002`.
