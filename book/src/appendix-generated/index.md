# Механизмы времени — что порождается

Раздел [«Механизмы времени»](../12-time/index.md) описывает конструкции; здесь —
код, который из них получается. Источник — пример вытяжного вентилятора того же
раздела (`fan.takt`): модель объявляет частоту `clock 1kHz` и выходит из состояния
выбега по `after 3m`.

Приведения `duration` ↔ число здесь не разбираются: единица перехода —
миллисекунда, и приведение сводится к обычной целочисленной арифметике.

### Что здесь стоит рассмотреть

**Длительности в коде нет — есть число тактов.** Выдержка `after 3m` при частоте
1 кГц превратилась в сравнение:

```c
if (model->takt_dwell >= 180000) {
```

Три минуты — это 180 000 тактов по миллисекунде, и пересчёт сделан **на
компиляции**. Поэтому на устройстве не нужны ни часы, ни деление — только
инкремент и сравнение. По той же причине компилятор отказывается собирать модель,
у которой длительность не выражается целым числом тактов: округлять он не имеет
права.

**Разрядность счётчика выбрана по самой длинной выдержке.** В структуре модели
объявлено `uint32_t takt_dwell;` — 180 000 не помещается в 16 бит. Будь самая
долгая выдержка короче 256 тактов, хватило бы `uint8_t`: разрядность подбирается
под модель, а не берётся «с запасом».

**Счётчик обновляется один раз — в конце такта:**

```c
if ((unsigned)model->state != model->takt_prev_state) {
    model->takt_dwell = 1;
    model->takt_prev_state = (unsigned)model->state;
} else {
    model->takt_dwell++;
}
```

Смена состояния в этом такте означает вход в новое состояние, поэтому счётчик
становится единицей: к следующему такту с момента входа пройдёт ровно один такт.
Обновление стоит в **одном** месте, а не рядом с каждым присваиванием
`model->state`.

Значение, которое видят условия на такте, оставлено предыдущим тактом. Отсюда
свойство, заявленное в разделе: на такте входа в состояние выдержка равна нулю.

**Поля появляются только там, где нужны.** Ни `takt_dwell`, ни `takt_prev_state`
не эмитируются, если модель не использует `after`: код модели без времени в
точности такой же, каким был бы без этих механизмов.

## Остальные цели

Порождение времени для целей `rust`, `st` и `sv` описывается здесь по мере того,
как каждая из них его получает. Сейчас модель с временем на них не транслируется,
и компилятор говорит об этом прямо — вместо кода, считающего не то.
