# Ошибки и предупреждения

Компилятор `taktc` и симулятор `takt-sim` сообщают о проблемах **диагностиками**.
У каждой диагностики есть **код** вида `XX-NNN`: две–четыре заглавные латинские
буквы (префикс — слой, где обнаружена проблема), дефис и три цифры. Диагностики
делятся на **ошибки** (компиляция/симуляция прекращается) и **предупреждения**
(работа продолжается).

Формат сообщения — `путь:строка:колонка: <вид> [<код>]: <текст>`, например:

```text
model.takt:1:8: Ошибка компиляции [SE-034]: Локальный тип 'u9' не найден
```

Это приложение — **справочник** по кодам: сперва сводная таблица всех кодов по
префиксам, затем подробный разбор основных ошибок с примерами. Ссылки на этот
справочник расставлены по тексту документа там, где ошибку уместно упомянуть, но
не раскрывать в основном изложении.

## Префиксы

| Префикс | Слой |
|---------|------|
| `LE` | лексический анализ (разбор текста на токены) |
| `SY` | синтаксический анализ (грамматика) |
| `SE` | семантика (типы, имена, модели, адреса) |
| `CC` | генерация цели C |
| `RS` | генерация цели Rust |
| `SV` | генерация цели SystemVerilog |
| `ST` | генерация цели Structured Text |
| `AM` | разбор внешней карты адресов |
| `DF` | флаг определения символа (`--define`) |
| `PU` | генерация цели PlantUML |
| `SIM` | вычисление в симуляторе |

## Подробный разбор основных ошибок

Ниже — легковоспроизводимые лексические (`LE`), синтаксические (`SY`) и
семантические (`SE`) ошибки, с которыми сталкиваются при написании моделей: для
каждой — пример кода, вызывающий проблему, и реальный вывод инструмента. Пути в
сообщениях приведены к условному `model.takt`. Коды целей генерации
(`CC`/`RS`/`SV`/`ST`) и симулятора (`SIM`) см. в сводной таблице выше.

### `LE-001` — незакрытый блочный комментарий

Блочный комментарий `/* … */` не закрыт до конца файла.

```takt
/* незакрытый комментарий
start S;
```

```text
model.takt:1:1: Ошибка компиляции [LE-001]: неожиданный конец файла внутри комментария
```

### `LE-002` — незакрытая строка

Строковый литерал не имеет закрывающей кавычки.

```takt
var s := "abc;
start S;
```

```text
model.takt:1:10: Ошибка компиляции [LE-002]: неожиданный конец файла внутри строкового литерала
```

### `LE-004` — нет числа после `0x`

После префикса `0x` не идёт шестнадцатеричная цифра.

```takt
var x := 0x;
out o: u8; start S { enter { o := 0; } }
```


### `LE-009` — числовой литерал вне диапазона

Числовой литерал не помещается в знаковое 64-битное целое. Граница —
свойство представления чисел в языке: значение литерала хранится как `i64`,
поэтому допустимый диапазон — от `-9223372036854775808` до
`9223372036854775807` (то же и для шестнадцатеричной записи: `0x7FFFFFFFFFFFFFFF`
принимается, `0x8000000000000000` — уже нет).

```takt

start S;
```

```text
model.takt:1:24: Ошибка компиляции [LE-009]: числовой литерал '0xFFFFFFFFFFFFFFFF' вне диапазона i64 [-9223372036854775808, 9223372036854775807]
```

Самый частый способ наткнуться — **полная маска 64-битного вектора**: у типа
`[bit;64]` значение «все единицы» записать литералом нельзя. Обходной путь —
задать маску по частям либо взять вектор меньшей ширины; ограничение
зафиксировано намеренно и будет снято отдельно.

### `SE-062` — превышен предел вложенности

Выражение, условие или оператор вложены глубже допустимого. Предел существует не
из экономии: разбор вложенной конструкции рекурсивен, и на достаточной глубине
у инструмента кончается стек — прежде это выглядело как аварийное завершение без
всякого сообщения.

```takt
var x: u8 := 0;
start S {
    ref S: ((((((( … ))))))) = 1;   // несколько десятков вложенных скобок
}
```

```text
model.takt:3:41: Ошибка компиляции [SE-062]: превышен предел вложенности (32): выражение, условие или оператор вложены слишком глубоко
```

Для написанной руками спецификации предел недостижим: вложенность глубже трёх
десятков означает либо забытую закрывающую скобку, либо порождённый текст. В
первом случае ищите несоответствие скобок, во втором — разбейте выражение на
именованные условия (`cond`) или промежуточные переменные.

### `SY-005` — превышен предел вложенности разбора

Вложенность настолько велика, что программа отвергается **ещё на разборе**, до
проверки имён и типов. Это второй, внешний предел вложенности: `SE-062` называет
границу, за которой конструкцию отказывается разбирать смысловой анализ, а
`SY-005` — границу, за которой дерево программы становится неподъёмным для
инструмента целиком, включая форматирование.

```takt
var x: u8 := 0;
start S {
    always { x := (((( … ))))1; }   // сотни вложенных скобок
}
```

```text
model.takt:3:3017: Ошибка компиляции [SY-005]: превышен предел вложенности разбора (96): дерево программы вложено слишком глубоко
```

Порядок такой: вложенность в несколько десятков даёт `SE-062` (программа
разобрана, но смысл слишком глубок), вложенность в сотни — `SY-005` (программу
не берётся разбирать даже форматтер). Практический смысл один и тот же:
**сократить вложенность** — разбить выражение именованными условиями (`cond`),
промежуточными переменными или функциями. Текст такой глубины пишется не
руками, поэтому чаще всего `SY-005` означает либо ошибку генератора, который
этот текст произвёл, либо потерянную закрывающую скобку в самом начале файла.

### `SE-026` / `SE-027` — нарушено направление порта

Входной порт (`in`) только читают, выходной (`out`) только пишут. Направление —
не пожелание: у входа физически нет источника записи, а чтение выхода в
порождённом коде означало бы обращение к чужому регистру либо невалидный модуль.

```takt
in A: u8 at 0x100;
out B: u8 at 0x104;
var t: u8 := 0;
start S {
    always {
        A := 5;      // ошибка: запись во входной порт
        t := B;      // ошибка: чтение выходного порта
    }
    ref S: t = 9;
}
```

```text
model.takt:1:1: Ошибка компиляции [SE-026]: Запись в входной порт 'A' запрещена
model.takt:2:1: Ошибка компиляции [SE-027]: Чтение из выходного порта 'B' запрещено
```

Правило действует **везде**: в условиях переходов, в телах блоков, внутри
`if`/`loop`/`for`, в телах функций и в инициализаторах.

Если значение, выданное наружу, нужно потом прочитать, заведите переменную и
пишите в обе стороны — она и хранит выданное:

```takt
out B: u8 at 0x104;
var last: u8 := 0;
start S {
    always { last := last + 1; B := last; }   // читаем `last`, а не `B`
    ref S: last = 9;
}
```

Порт `inout` свободен в обе стороны — и читается, и пишется.

Принимается бит 0, о чём и говорит предупреждение.

```takt
in P: bit at 0x100;
start S { ref S: P = 1; }
```

```text
Предупреждение [SE-090]: порт 'P' однобитный, но в адресе не задана позиция бита: принят бит 0. Если подразумевался другой бит, укажите его явно — `0xADDR:бит`
```

Чтобы предупреждение исчезло, позиция пишется явно — `in P: bit at 0x100:0;`
(или тот бит, который занимает порт на самом деле).

### `SE-061` — нет поля структуры

Обращение к несуществующему полю структуры.

```takt
struct P { x: u8 }
var p: P := {0}; out o: u8; start S { enter { p.y := 1; o := p.x; } }
```

```text
model.takt:2:49: Ошибка компиляции [SE-061]: структура 'P' не содержит поля 'y'
```

### `SE-072` — выдержка не сводится к константной длительности

`after` принимает литерал длительности, литерал тактов, имя константы типа
`duration` либо их сумму и разность в скобках. Значение выдержки нужно
компилятору, поэтому всё, что становится известно лишь во время работы автомата
(переменная, порт, вызов функции), негодно.

```takt
model M {
    var v: duration := 10s;
    start Wait { ref Done: after (v + 1s); }
    state Done;
}
```

```text
model.takt:3:35: Ошибка компиляции [SE-072]: выдержка 'after': 'v' — это переменная, а выдержке нужна константа типа duration (const v := 3m;); значение, известное только в такте, компилятор подставить не может
```

Второй частый случай — число без единицы времени: длительность сочетается только
с длительностью.

```takt
model M {
    const BASE := 10s;
    start Wait { ref Done: after (BASE + 1); }
    state Done;
}
```

```text
model.takt:3:42: Ошибка компиляции [SE-072]: выдержка 'after': число 1 без единицы времени — длительность сочетается только с длительностью (напишите 1s, 1ms или 1us)
```

Сообщение всегда называет причину: имя не объявлено, тип не `duration`, значение
не сводится к длительности, голое число, вызов функции, сравнение, отрицательный
результат или цикл в цепочке констант.

> **Осторожно.** Переменная и входной порт типа `duration` — **законны**: выдержка
> тогда вычисляется в такте (см. «Выдержка, заданная значением» в разделе о
> времени). Отказ остаётся там, где значение не длительность.

### `SE-073` — выдержка значением требует частоты, кратной 1000 Гц

Когда выдержка меряется тактами, миллисекунда обязана быть целым числом тактов:
иначе сравнение пришлось бы округлять, и выдержка вышла бы короче заявленной.

```takt
model Timer {
    var base: duration := 2s;
    out done: bit;
    start Waiting { ref Ready: after (base + 500ms); }
    state Ready { enter { done := 1; } }
}
```

Сборка с частотой 3 Гц:

```text
Ошибка компиляции [SE-073]: вычисляемая выдержка требует частоты, кратной 1000 Гц: при 3 Гц миллисекунда — не целое число тактов, и сравнение округлялось бы молча. Либо задайте кратную частоту, либо оставьте выдержку константной (её компилятор пересчитывает точно)
```

Лечится либо кратной частотой (1 кГц, 2 кГц, 1 МГц), либо константной выдержкой —
её компилятор пересчитывает точно и отказывает заранее, если пересчёт не целый
(`SE-063`).

### `SE-075` — параметр объявлен вне модели

`parameter` объявляет **настройку модели**, поэтому у объявления должно быть место
инстанцирования: где-то модель подставляется в композицию, и там задаются
значения. У верхнего уровня файла такого места нет.

```takt
parameter portion: u8 := 3;   // вне модели
start S { ref S; }
```

```text
model.takt:1:1: Ошибка компиляции [SE-075]: Параметр 'portion' объявлен вне модели: верхний уровень файла инстанцировать нечем — перенесите объявление в модель либо замените на 'var'
```

### `SE-078` — у модели нет такого параметра

Имя в аргументе инстанцирования обязано быть параметром целевой модели.
Сообщение перечисляет объявленные — обычно это опечатка.

```takt
model Feeder {
    parameter portion: u8 := 1;
    start Run { ref Run; }
}

start Line = Feeder(portions := 3);   // лишняя буква
```

```text
model.takt:6:21: Ошибка компиляции [SE-078]: Модель 'Feeder' не имеет параметра 'portions' (объявлены: portion)
```

Рядом стоят: `SE-077` — модель не объявляет параметров вовсе; `SE-079` — имя в
модели есть, но объявлено как `var`, `const` или порт (настройкой оно не является);
`SE-080` — один параметр задан в вызове дважды.

### `SE-083` — значение параметра не вычисляется при сборке

Аргумент инстанцирования — константное выражение: литералы, имена констант,
арифметика над ними и вызовы функций, вычислимых при сборке. Величина, известная
лишь в работе, настройкой быть не может.

```takt
var level: u8 := 5;

model Feeder {
    parameter portion: u8 := 1;
    start Run { ref Run; }
}

start Line = Feeder(portion := level);   // level — переменная
```

Сообщение называет причину: переменная, порт, неподдержанная форма, дробная
арифметика. Рядом: `SE-084` — функция непригодна для вычисления при сборке
(`extern`, встроенная, без `return`, не то число аргументов); `SE-085` — исчерпан
предел вычисления (взаимная рекурсия или незавершающееся тело).

### `SE-089` — литерал не помещается в тип

Числовой литерал записывается в переменную, тип которой его не вмещает.
Диапазон приёма у самого литерала широкий — это объединение диапазонов **всех**
целых типов языка (`[-9223372036854775808, 18446744073709551615]`), — поэтому
лексер такое значение пропускает: влезает ли оно в **конкретный** тип, видно
только по объявлению.

```takt
model M {
    var a: u8 := 300;
    start S { always { a := a; } }
}

start Root = M;
```

```text
model.takt:2:5: Ошибка компиляции [SE-089]: литерал 300 не помещается в тип 'u8' переменной 'a': допустимо [0, 255]
```

Сообщение всегда называет и значение, и границы. Лечится либо выбором типа
пошире (`u16`), либо исправлением значения. Проверка смотрит **литерал**:
значение выражения (`a := 200 + 200`) она не считает.

### `SE-088` — здесь нужна величина, известная при сборке

Выдержка `after` и адрес порта требуют значения на этапе генерации. Параметр им
становится **только** при сборке способом `--parameters=specialize` — тогда на
каждую настройку порождается своя копия модели, и неизменяемый параметр эмитируется
константой. В способе по умолчанию (`assign`) параметр — поле экземпляра, то есть
величина работы.

```takt
model Timer {
    parameter dwell: duration := 100ms;
    start Wait { ref Done: after dwell; }
    state Done;
}
```

```text
model.takt:3:34: Ошибка компиляции [SE-088]: выдержка 'after': 'dwell' — параметр модели, а здесь нужна величина, известная при генерации; параметр является константой только при сборке с '--parameters=specialize' (в режиме по умолчанию '--parameters=assign' параметр — поле экземпляра)
```

Лечится либо ключом сборки, либо константой (`const DWELL := 100ms;`), если
настройка одна на все экземпляры.

### `SE-087` — специализация модели с вложенными моделями

Способ `--parameters=specialize` порождает копию модели на каждую настройку. Модель
с **собственными вложенными моделями** так не копируется: уникальные имена
вложенных разошлись бы с их местом в дереве. Настройте вложенные модели в их
собственных инстанцированиях либо соберите способом `assign`.

Рядом стоит `SE-086` — имя специализации совпало с именем существующей модели;
переименуйте её (молчаливое переименование скрыло бы столкновение имён в
порождённом коде).
