# Переиспользуемая модель: библиотека и её применение

Одну и ту же управляющую логику применяют к разным установкам: ПИД-регулятор
одинаково годится для нагрева, давления и расхода — меняется лишь объект. Этот
раздел показывает, как оформить такую логику **библиотекой**, подключить её к
своей установке и замкнуть контур, ничего в библиотеке не меняя.

## Что выносят в библиотеку

Библиотечный файл описывает две вещи: **саму модель** и **протокол связи** — те
величины, через которые она общается с внешним миром. Всё остальное — настройка,
накопители, промежуточные величины — остаётся её внутренним устройством.

Граница проходит там, где проходит смысл: уставку, измерение и воздействие
задаёт тот, кто прикладывает регулятор к установке; коэффициенты — свойство
самого закона регулирования.

Рассмотрим модель, описывающую **ПИД-регулятор** — самый распространённый закон
управления. Регулятор считает рассогласование между уставкой и измерением и
складывает воздействие из трёх слагаемых: пропорционального рассогласованию,
накопленного (интегрального) и реагирующего на скорость изменения
(дифференциального).


Три переменные верхнего уровня (1) — это и есть протокол: `target`, `meas`,
`ctrl`. Их подключает к себе тот, кто применяет регулятор. Настройка и рабочие
величины (2) объявлены **внутри** модели, поэтому применение подключает три
имени, а не полтора десятка, и не может случайно испортить накопитель.

Накопитель ограничен условиями (3) — это защита от «раскрутки интеграла»: пока
объект далёк от уставки, сумма ошибок растёт, и без предела она увела бы
воздействие в насыщение (а в целочисленном представлении встраиваемых целей —
ещё и перевернулась бы через границу типа). Насыщающего оператора в языке нет,
поэтому предел записан двумя `if`.

Сойдясь (`err` стало меньше порога `eps`), регулятор снимает воздействие и
поднимает `ready`.

## Как её применяют

Применение подключает из библиотеки **модель и протокол** (4) и описывает свой
объект. Ниже — бак периодического действия: партию греют до уставки, затем
выдерживают, пока она не остынет до температуры выдачи.

```takt
{{#include examples/heater_loop.takt}}
```

Контур замыкает композиция (6): каждый такт работают обе модели — регулятор
считает воздействие по измерению, объект пересчитывает измерение по
воздействию. Ни одна из них не знает об устройстве другой; общее у них — только
три величины протокола.

Прогон показывает, как контур сходится:

```text
Шаг  1: [Control, Heating]  temperature=16.90  ready=0
Шаг  2: [Control, Heating]  temperature=21.62  ready=0
Шаг 18: [Control, Heating]  temperature=39.51  ready=0
Шаг 19: [Settled, Holding]  temperature=38.44  ready=1
Шаг 20: [Done, Done]        temperature=37.41  ready=1
```

Первый шаг даёт скачок мощности: рассогласование максимально, и все три
слагаемых работают в одну сторону. К восемнадцатому шагу температура подходит к
уставке 40°, рассогласование опускается ниже порога — регулятор переходит в
`Settled`, снимает мощность и поднимает `ready`. Объект видит снятое воздействие
и уходит на выдержку `Holding`, где остывает по тем же потерям; достигнув
температуры выдачи 38°, цикл завершается.

**Модель объекта (5) — стенд, а не часть системы управления.** Она нужна, чтобы
прогнать контур на столе: реальная установка измерения не вычисляет, а
**сообщает** его датчиком. В боевой сборке объект заменяется портами:

```takt
model Plant {
    in sensor: float;   // датчик установки
    out power: float;   // привод

    start Run {
        always {
            meas := sensor;   // измерение приходит извне
            power := ctrl;    // воздействие уходит на привод
        }
        ref Run: true;
    }
}
```

Такт здесь — шаг логики, а не единица времени: частоту опроса задаёт объявление
`clock` модели либо ключ сборки, и от неё зависит, во сколько реального времени
обходится один шаг контура.

## Границы механизма

Протокол связи объявляет **одна** сторона. Если бы объект жил в своём файле и
объявлял `meas`/`ctrl` у себя, применение получило бы две несвязанные пары
величин: подключение двух файлов строит два независимых дерева, и общей
переменной между ними не возникает. Поэтому объект либо описывают в файле
применения, либо берут протокол из той же библиотеки, что и модель.

Настройку регулятора нельзя задать «снаружи»: параметризации моделей в языке
нет, а коэффициенты объявлены внутри. Другая настройка — это либо правка
библиотеки, либо её отдельная копия под задачу.

## Частые ошибки

Типичные ошибки при вынесении модели в библиотеку:

- `SE-074` — подключена модель, но не подключены объявления, на которые
  опирается её тело (компилятор перечислит недостающие имена);
- `SE-005` — имя из подключённого целиком файла уже занято у потребителя;
- `SE-003` — библиотечная модель сослалась на объявление потребителя: подключённый
  файл видит только **свои** объявления;
- `SE-017` — в выборочном подключении запрошено имя, которого в файле нет.
